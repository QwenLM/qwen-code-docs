Qwen Code Hebdo : /learn transforme vos connaissances en Skill, Code Review monte en gamme, Web Shell fait peau neuve

Qwen Team
2026-07-16

Cette semaine, Qwen Code sort trois versions stables — v0.19.9, v0.19.10 et v0.19.11 — avec plus de 160 PR fusionnés.

La commande /learn fait son entrée. Vous créez des Skills à partir de n’importe quelle source de connaissances — répertoire, URL, historique de conversation, texte libre — et Qwen Code les organise automatiquement en SKILL.md, prêts à être réutilisés.

Code Review passe de « fonctionnel » à « fiable ». Les suggestions sont publiées directement en commentaires inline sur la PR. Le review intègre désormais des vérifications de correction procédurale, une validation pré-publication, un verifier à l’étape 4 et un reverse-audit à l’étape 5.

Web Shell fait peau neuve. Refonte complète avec shadcn comme bibliothèque de composants, panneau de revue Artifact, page de gestion des extensions, diagrammes Mermaid zoomables et déplaçables. Le multi-workspace est désormais intégré de bout en bout, avec des split panes colorés par workspace.

Voice Bridge connecte la voix à l’ACP. Même un modèle principal texte seul peut traiter des prompts vocaux — l’audio est d’abord transcrit en texte avant d’être transmis au modèle. Les modèles compatibles audio reçoivent le flux brut sans intermédiaire.

Les PDF scannés ne bloquent plus l’Agent. Quand l’extraction de texte dépasse la limite, les pages sont automatiquement rendues en images et confiées au modèle visuel.

Les workflows CLI se complètent. /update pour la mise à jour en un clic, Ctrl+O pour figer la conversation, Ctrl+S pour mettre en brouillon un prompt, Explore hérite du modèle principal, Alt+T pour le raisonnement complet en streaming.

✨ Nouvelles fonctionnalités

/learn : transformer vos connaissances en Skills réutilisables

/learn est une nouvelle commande slash qui vous permet de créer des Skills réutilisables à partir de sources de connaissances. Ces sources peuvent être un répertoire local, une URL, un historique de conversation ou un texte que vous rédigez directement. Le modèle principal collecte les connaissances et les organise automatiquement en un SKILL.md, enregistré sous .qwen/skills/learned-skill-<name>/, avec le marqueur source: learned — sans interférence avec vos Skills manuels ou auto-générés.

Quelques cas d’usage :

  • /learn Deploy process: ... transforme votre processus de déploiement en Skill, invocable en un clin d’œil la prochaine fois
  • Pointer vers un répertoire de documentation pour que Qwen Code apprenne les conventions de développement du projet et les applique automatiquement
  • Extraire les connaissances d’une conversation pour les capitaliser en templates d’instructions réutilisables

Voir le PR #6440 

Code Review : un bond qualitatif

Code Review a été renforcé cette semaine sur plusieurs fronts, des commentaires inline à la validation de la qualité du review lui-même.

/review publie désormais les suggestions directement sous forme de commentaires inline sur la PR — plus besoin de copier-coller manuellement les recommandations du review vers la PR. Le review lui-même intègre des vérificateurs de correction procédurale et un niveau d’effort ajustable, avec une validation par garde-fou avant publication pour s’assurer que chaque finding est fondé.

Les review de gros diff ne sont plus répartis de manière approximative — chaque ligne de diff a un reviewer clairement assigné, garantissant une couverture complète. L’agent de découpage du review reçoit un prompt complet, éliminant les exécutions à contexte vide. Les commentaires de triage PR ajoutent un score de confiance, des diagrammes de séquence, un aperçu des fichiers et un pied de page de review, offrant aux reviewers un contexte enrichi. Le délai d’expiration par défaut des reviews automatisés passe à 180 minutes, avec un override possible jusqu’à 240 minutes — les grosses PR ne sont plus interrompues par un timeout.

Ce que cela vous permet de faire :

  • /review publie automatiquement des suggestions inline sur la PR, sans étape manuelle
  • Le niveau d’effort ajustable s’adapte à l’ampleur du review
  • Le score de confiance du triage PR vous aide à identifier celles qui méritent une attention particulière

La v0.19.11 introduit en outre le verifier à l’étape 4 et le reverse-audit à l’étape 5 — le processus de review passe de « trouver un problème → publier un commentaire » à « trouver un problème → vérifier qu’il est fondé → auditer en sens inverse pour confirmer l’absence d’omission ». La liste des findings est repliée dans le prompt de vérification et de reverse-audit, réduisant la taille du prompt. La portée du build/test de l’Agent 7 est également restreinte aux workspaces concernés par le diff, évitant les builds intégrals sur les gros dépôts.

Voir les PR #6593 , #6711 , #6612 , #6789 , #6771 , #6840 , #6942 , #6965 , #6892 , #6955 

Web Shell : refonte majeure de l’interface

Le Web Shell reçoit cette semaine plus de 15 PR, couvrant tout, de la bibliothèque de composants de base à la barre latérale, en passant par la page de paramètres et le sélecteur de modèles.

shadcn est introduit comme bibliothèque de composants UI de base, unifiant les tokens de design et les normes de composants. La barre latérale multi-workspace est repensée avec une disposition plus claire. La page de paramètres adopte une bibliothèque de composants moderne — les paramètres utilisateur sont éditables directement dans le panneau, et la gestion des modèles y est intégrée. Le sélecteur de modèles est repensé avec des métadonnées plus claires et une commutation plus rapide. Voir les PR #6760 , #6804 , #6817 , #6758 

Le multi-workspace est désormais intégré de bout en bout. Les endpoints ACP du daemon supportent le scoping par workspace, les workers de canal sont regroupés et liés par workspace, le split view gère les sessions cross-workspace et les onglets workspace. Les workspaces ajoutés dynamiquement sont persistés — pas besoin de reconfiguration après redémarrage du daemon. Les workspaces peuvent être retirés à la volée sans redémarrer le serveur. Voir les PR #6621 , #6635 , #6746 , #6716 , #6745 

Nouveau panneau Artifact à droite — les fichiers modifiés s’affichent sous forme de cartes par tour, avec compteur de lignes et diff individuel dépliable par fichier. Le panneau droit propose une navigation en liste ou en arborescence et une largeur ajustable par glissement. Les Artifacts et les tâches planifiées disposent également de cartes de sortie par tour dédiées, et les artifacts HTML sont rendus dans une iframe sandbox. Voir le PR #6591 

La v0.19.11 introduit la page de gestion des extensions, permettant de consulter et gérer les extensions installées directement depuis le Web Shell. Les diagrammes Mermaid supportent le zoom, le panoramique et le glissement — les diagrammes de flux et de séquence ne sont plus de simples images statiques. Le split pane permet de maximiser un panneau individuel, chaque pane étant coloré par workspace. Les contrôles du Composer adoptent un format popover, et la liste des sessions affiche celles en attente d’action utilisateur. Voir les PR #6815 , #6881 , #6951 , #6971 , #6877 , #6956 

Autres améliorations : double-clic sur une cellule de tableau Markdown pour afficher le contenu complet dans une popup et faciliter la copie ; la barre d’outils de saisie affiche un chip avec la branche Git courante ; les groupes de sessions supportent les codes couleur Hex personnalisés ; les tâches planifiées de tous les workspaces sont rassemblées dans une vue unifiée ; le Composer accepte un texte de placeholder personnalisé ; les chemins de workspace sont verrouillés. Voir les PR #6530 , #6725 , #6752 , #6759 , #6765 , #6853 

Voice Bridge : l’entrée vocale connectée à l’ACP

Jusqu’ici, l’envoi d’un prompt vocal via l’ACP (Agent Communication Protocol) échouait si le modèle principal était un modèle texte seul — l’audio ne pouvait pas être traité. Un voice bridge a été ajouté : l’audio est d’abord transcrit en texte par le voice model configuré, puis transmis au modèle principal. Si le modèle principal prend lui-même en charge l’entrée audio, le flux brut est transmis directement, sans transcription. En cas d’indisponibilité ou d’échec de la transcription, le modèle principal reçoit un message sûr indiquant « audio non disponible », sans jamais transmettre d’audio brut.

Ce que cela vous permet de faire :

  • Envoyer des commandes vocales via un client ACP, même avec un modèle texte seul
  • Les modèles principaux compatibles audio (modèles multimodaux) conservent le flux audio brut, sans perte d’information
  • Dégradation sûre en cas d’échec de transcription — la conversation n’est jamais interrompue par un problème audio

Voir le PR #6576 

Conversion PDF en image : les scans ne bloquent plus l’Agent

Auparavant, face à un PDF scanné ou dense en texte, l’extraction dépassait le budget de 12 000 tokens et déclenchait une boucle FILE_TOO_LARGE — l’Agent réessayait avec des plages de pages plus petites, échouait à chaque fois, et le contexte gonflait jusqu’au crash de la session. Un repli page-vers-image a été ajouté : quand l’extraction de texte dépasse la limite ou échoue, pdftoppm rend automatiquement les pages en JPEG et les confie au modèle visuel. Le coût en tokens par page est fixe, indépendant de la densité textuelle. L’extraction de texte reste le chemin par défaut (recherchable, extraction précise) ; le rendu n’est déclenché qu’en cas de dépassement ou d’échec. Pour les modèles texte seuls couplés à un modèle visuel, les scans attachés via @ sont rendus en quelques pages et transmis au vision bridge pour transcription.

Ce que cela vous permet de faire :

  • Les PDF scannés ne provoquent plus de FILE_TOO_LARGE — le modèle visuel lit directement les images
  • Les PDF denses (dépassant le budget de tokens) basculent automatiquement en mode image, sans saturer le contexte
  • Les PDF texte conservent l’extraction textuelle, sans perte de précision

Voir le PR #6585 

Workflows CLI : mise à jour en un clic, conversations préservées

Jusqu’ici, la mise à jour de Qwen Code dépendait de la méthode d’installation — npm install pour npm, téléchargement manuel pour standalone. Les commandes qwen update (CLI) et /update (slash) ont été ajoutées, détectant automatiquement le type d’installation. L’installation standalone récupère la dernière version depuis le registre npm, avec vérification SHA256 + signature Ed25519 (optionnelle) + smoke test (le nouveau binaire doit passer --version) + remplacement atomique et rollback automatique en cas d’échec. L’installation npm affiche la commande npm install -g correspondante. Prise en charge i18n en 9 langues. Voir le PR #5780 

Ctrl+O fige la vue du transcript — un écran alternatif s’ouvre avec l’intégralité de la conversation, tous les résultats d’outils dépliés, navigable au scroll. Esc/q/Ctrl+C/Ctrl+O pour revenir à l’interface principale. Le rendu des résultats d’outils a également été repensé : les outils de lecture/recherche/liste sont repliés en un résumé d’une ligne, les outils de mutation restent dépliés. L’ancien paramètre compactMode est ignoré silencieusement. Voir le PR #5666 

Ctrl+S met le prompt en brouillon — quand le champ de saisie contient du texte, Ctrl+S enregistre le prompt dans un fichier de brouillon au niveau du projet, restauré automatiquement au prochain lancement depuis le même projet. Le brouillon est supprimé automatiquement après soumission. Les placeholders de collage volumineux sont développés avant sauvegarde — la restauration renvoie le contenu original. Chaque projet gère son propre brouillon indépendamment. Voir le PR #6709 

Le timeout des commandes Shell est configurable. Le nouveau paramètre tools.shell.defaultTimeoutMs ajuste le délai d’expiration par défaut des commandes foreground au niveau du projet ou de la session, sans avoir à le spécifier à chaque commande. La valeur par défaut reste 120 secondes, 0 pour désactiver le timeout. Voir le PR #6628 

Le sous-agent Explore hérite du modèle principal par défaut. Le sous-agent intégré Explore ne sélectionne plus automatiquement le fastModel — il hérite du modèle de la session principale. Si vous utilisez Claude Opus comme modèle principal, Explore utilise aussi Claude Opus, sans compromis sur le raisonnement. Pour conserver le modèle rapide, réglez agents.builtin.exploreModel sur fast ou sur un ID de modèle spécifique. Voir le PR #6807 

Alt+T déplie le raisonnement complet en streaming. Pendant la sortie streaming, Alt+T déplie le bloc de thinking — vous voyez désormais le contenu de raisonnement complet en temps réel, au lieu de l’aperçu codé en dur des 4 dernières lignes. Suivre la chaîne de pensée du modèle devient enfin possible. Les raisonnements très longs sont limités par la hauteur du viewport, sans expansion infinie. Voir le PR #6678
