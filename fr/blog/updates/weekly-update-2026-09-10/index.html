Qwen Code Hebdo : les workflows passés se consultent, Plan et YOLO peuvent coexister dans le Web Shell, et le bot de groupe traite plusieurs tâches à la fois

Qwen Team
2026-09-10

Qwen Code publie cette semaine deux versions stables — v0.23.1 et v0.23.2 — avec plus de 300 PR fusionnées.

Les workflows ont leur page de gestion. Dans le Web Shell, vous voyez où en est chaque exécution, combien d’agents elle a lancés et combien de tokens elle a consommés.

Le Web Shell gagne trois commodités. Vous repérez en un clic ce qui occupe le contexte, la remontée dans l’historique a sa barre de navigation, et Plan et YOLO peuvent être activés ensemble.

Les tâches d’un Channel ont un nom. Dans DingTalk, vous menez plusieurs choses de front, chacune avec son nom, basculable à tout moment, et chacune peut modifier les fichiers dans son propre espace de travail.

✨ Nouvelles fonctionnalités

Les workflows ont leur page de gestion

La semaine dernière, les workflows se mettaient en pause, reprenaient ou annulaient en tapant une commande dans le terminal. Cette semaine, ils ont leur page dans le Web Shell.

Cliquez sur Workflows dans la barre latérale, ou tapez /workflows dans la conversation. La page compte trois onglets — Enregistrés, En cours, Historique — et rassemble pour chaque exécution l’avancement des étapes, les agents lancés, les approbations en attente et les tokens consommés. Ouvrez un workflow enregistré : sa description, ses cas d’usage, le chemin de son script et son code source s’affichent directement.

Ce que vous pouvez en faire :

  • Suivre sur la page où en est un workflow et combien d’agents il a lancés
  • L’arrêter en cours de route, ou le relancer depuis le début
  • Ouvrir un workflow enregistré pour lire son script et sa description

Voir le PR #10594 

Web Shell : ce qui occupe le contexte se voit, Plan se combine avec YOLO

Ce qui occupe le contexte, en un clic. Une icône s’ajoute en tête de conversation et ouvre un onglet d’utilisation du contexte : la part consommée de la fenêtre, ce qu’il reste, puis la part de chaque poste — instructions système, outils intégrés, outils MCP, fichiers de mémoire, skills, messages. Chaque poste se déplie pour voir son contenu.

Une barre de navigation dans l’historique. Une réglette apparaît sur le bord gauche de la conversation : survolez un repère pour lire la question de ce tour, cliquez dessus pour y sauter.

Plan et les droits d’exécution sont dissociés. Plan sort du menu des droits pour devenir un interrupteur indépendant, cumulable avec Default, Auto Edit, Auto ou YOLO — avant, choisir Plan empêchait de choisir YOLO. Il se coupe tout seul une fois le plan approuvé. Toutes les commandes /plan sont prises en charge.

Une notification du navigateur en fin de tâche. Un interrupteur « Notifications de tâche du navigateur » s’ajoute dans la rubrique Interface des paramètres. Une fois activé et autorisé, si la page est en arrière-plan ou sans le focus, la conversation que vous suivez envoie une notification du navigateur lorsqu’elle termine ou échoue. Désactivé par défaut, et les notifications ne contiennent ni contenu de discussion ni chemin de répertoire.

On voit que les agents d’arrière-plan tournent encore. L’icône de la carte d’un agent d’arrière-plan porte un léger battement ; la ligne repliée d’un agent d’avant-plan affiche sa durée d’exécution et le sous-outil en cours.

Ce que vous pouvez en faire :

  • Cliquer l’icône en tête de conversation pour voir ce qui occupe le contexte
  • Sauter à n’importe quel tour de l’historique depuis la réglette de gauche
  • Activer Plan et YOLO en même temps

Voir les PR #11177 , #11208 , #11054 , #11423 , #11398 , #10939 

Channel : plusieurs tâches de front dans un même groupe, chacune dans son espace de travail

Le bot Channel, c’est le bot Qwen Code que vous ajoutez, après un scan de QR code, à DingTalk, Feishu ou un autre outil de messagerie. Avant, un bot dans un groupe ne pouvait faire qu’une chose à la fois : lui faire surveiller une PR tout en lui demandant une nouvelle fonctionnalité obligeait à entasser les deux dans la même conversation, avec des interruptions mutuelles. Les Channels ont désormais des tâches nommées, et plusieurs choses avancent en parallèle.

Plusieurs tâches dans une même conversation de groupe. /session new <nom> crée une tâche — jusqu’à 8 par personne et par groupe, chacune avec sa session et son historique. /session use <nom> bascule quand vous voulez, y compris pendant qu’une tâche tourne ; vous pouvez alors en créer d’autres ou en changer. /session cancel <nom> arrête celle que vous citez. Chaque réponse porte son origine : le nom de la tâche en privé, « qui · quelle tâche » en groupe. Une question sans rapport en plein milieu d’une tâche ? Envoyez /btw <question>, la tâche principale continue normalement.

Chaque tâche travaille dans son coin. Ajoutez --worktree à la création : la tâche travaille sur son propre répertoire et sa propre branche, et plusieurs tâches peuvent modifier des fichiers sans empiéter les unes sur les autres. /clear, /new et /reset ouvrent seulement une nouvelle conversation : les fichiers modifiés et la branche restent en place, et les tâches survivent à un redémarrage du bot. Quand vous supprimez la session, l’espace de travail et la branche que la tâche avait créés sont nettoyés avec elle ; s’il reste des modifications non commitées, tout est laissé tel quel.

Avant de l’utiliser, activez sessionScope: "user" et multiSession: true sur le Channel concerné dans les paramètres.

Ce que vous pouvez en faire :

  • Mener de front la review d’une PR et une nouvelle fonctionnalité, avec un historique chacun
  • Ajouter --worktree pour que les modifications de fichiers ne se gênent pas
  • Intervenir pendant qu’une tâche tourne, la tâche principale continue

Voir les PR #10198 , #10420 , #10574 , #10712 , #10713 , #10643 , #11015 , #11308 , #11309 

DingTalk : les confirmations de droit passent par une carte, la progression par des emojis

La confirmation des droits devient une carte. Quand l’IA veut exécuter une action soumise à approbation, vous recevez dans DingTalk une carte native interactive et il suffit d’appuyer sur un bouton : Autoriser une fois, Refuser, Autoriser définitivement.

La progression se lit dans les emojis. Pendant que l’IA travaille, le message que vous avez envoyé garde son 👀 et affiche en plus un emoji qui suit l’étape en cours : 🤔 réflexion, 📖 lecture, 🔎 recherche, 🖥️ exécution, 🛠️ édition, 🗑️ suppression, 🌐 récupération, etc. Une fois terminé, il ne reste qu’un emoji final.

Les agents d’arrière-plan signent leurs messages. Quand plusieurs agents d’arrière-plan tournent en parallèle, chaque réponse est précédée de Agent · nom : vous savez qui parle. Si les messages sont trop nombreux, activez aggregateBackgroundAgentResponses pour n’avoir qu’un récapitulatif par tour.

Ce que vous pouvez en faire :

  • Cliquer sur la carte quand l’IA demande un droit
  • Regarder l’emoji pour savoir où en est l’IA
  • Suivre plusieurs agents qui parlent en même temps, chacun identifié

Voir les PR #10457 , #10504 , #10899 

Un Qwen Code installé sur un serveur peut modifier les projets de votre ordinateur

Beaucoup font tourner Qwen Code sur un serveur cloud et le pilotent depuis le navigateur de leur ordinateur. Le problème : l’IA ne voyait que les fichiers du serveur, et pas le projet qui est sur votre ordinateur portable. Il fallait téléverser les fichiers, puis les récupérer une fois modifiés.

Vous pouvez désormais choisir dans le navigateur un dossier de votre ordinateur et le confier à la session courante. Cette session peut alors lister, lire, rechercher et écrire les fichiers du dossier, tous les chemins étant relatifs au dossier choisi. Le bas de la barre latérale affiche le dossier connecté et le nombre d’outils fournis.

Ce dossier n’est ouvert qu’à la session à laquelle vous êtes connecté, et se referme dès que vous fermez l’onglet, que la connexion tombe ou que la session se termine.

Ce que vous pouvez en faire :

  • Garder le serveur dans le cloud et lui faire modifier directement un projet de votre ordinateur
  • Confier un dossier sans rien téléverser avant ni rien télécharger après
  • Donner le projet A aujourd’hui et le projet B demain : l’IA ne voit que ce que vous lui donnez à cet instant

Voir le PR #10962 

📊 Autres nouvelles fonctionnalités

Les styles de sortie se rédigent vous-même. Les quatre styles intégrés se choisissaient depuis la semaine dernière ; cette semaine, vous définissez les vôtres. Un fichier Markdown dans ~/.qwen/output-styles/ devient un style global, un fichier dans .qwen/output-styles/ du projet devient un style de projet, et le contenu du fichier sert d’instruction pour ce style. Voir le PR #10761 

La recherche web intégrée est disponible toute seule. Avec une Standard API Key Bailian ou un Token Plan, web_search fonctionne sans rien configurer, et les frais sont imputés au compte que vous utilisez. Avec un Coding Plan, il faut désigner manuellement une configuration de fournisseur Bailian. Voir les PR #11348 , #11450 

Les conversations s’exportent en HTML. /export html suit le même pipeline dans le CLI, le Web et VS Code, et le fichier exporté permet la recherche plein texte, la sélection, la copie et l’impression. Ouvrir le fichier exporté demande une connexion internet. Voir le PR #10076 

Le budget consommé par un Goal est visible. Un Goal dispose d’un budget token : une fois épuisé, il s’arrête et vous rend la main, mais rien n’indiquait la consommation. Désormais, le bas du terminal, la carte d’état et le Web Shell affichent ce qui est utilisé et le plafond, et le chiffre reste affiché après l’arrêt. Un Goal qui n’obtient rien de décisivable pendant trois tours se met lui-même en pause ; une interruption de votre part n’est pas comptée comme un tour à vide. Voir les PR #11248 , #11254 , #11239 , #11257 

Deux options de plus pour les Channels. Dans un groupe bruyant, messagePrefix ne déclenche le bot que sur les messages commençant par ce préfixe. instructions attache à un Channel des exigences permanentes — le ton des réponses, vers qui orienter certains sujets — et se configure sur tous les types de Channel. Voir les PR #10817 , #11082 

Davantage de modèles règlent l’intensité de réflexion. GPT-6 Astra accepte cinq niveaux, de low à max, avec medium par défaut ; la série GPT-5 suit ses propres paliers. deepseek-v4-pro est pris en charge, avec high et max. Voir les PR #11295 , #10999 

Deux angles de plus pour la review. Quand la modification touche un fichier d’instructions comme SKILL.md ou QWEN.md, un agent exécute réellement les nouvelles instructions et cherche les écarts avec ce que le texte promet. Un autre angle écarte les sujets évoqués dans la description de la PR et juge l’ensemble du changement indépendamment. Voir le PR #10221 

L’outil de recherche de code local s’installe en une fois. Dites « installe-moi zvec-grep » ou tapez /zvec-grep-install : l’outil est installé et branché sur Qwen Code. C’est un outil local de recherche de code qui réunit recherche par mots-clés et recherche sémantique. Voir le PR #10723 

La liste de tâches s’active soi-même. Quand l’IA traite une tâche à plusieurs étapes, elle dresse une liste de tâches et coche chaque ligne terminée ; cette liste est l’outil todo_write. Il ne fait plus partie des outils par défaut : mettez tools.todoWrite.enabled à true dans les paramètres et relancez si vous en avez besoin. Voir le PR #10645 

Une commande suffit pour le QR code d’appairage. Auparavant, un --hostname choisi à la main exigeait de configurer aussi le token et les origines autorisées, et le serveur refusait de démarrer sans tout cela. qwen serve --hostname 0.0.0.0 suffit désormais : scannez depuis votre téléphone le QR code affiché dans le terminal pour entrer directement dans un Web Shell déjà connecté. Voir le PR #11172 

Plusieurs instances de service peuvent tourner ensemble. Plusieurs instances du service Qwen Code peuvent fonctionner sur la même machine ; en cas de conflit, le Web Shell affiche une proposition de réessai. Voir les PR #10924 , #11207 

La mémoire Mem0 s’écrit et s’efface. Mem0 branché, Qwen Code peut écrire et supprimer des souvenirs. Un Mem0 déployé par un administrateur peut aussi activer le rappel automatique : les souvenirs les plus pertinents accompagnent chaque question. Voir les PR #11311 , #11337 , #11246 , #11397 

👏 Améliorations de l’expérience

Les liens du terminal se cliquent. Un clic ouvre un lien présent dans la sortie ; le clic droit ouvre un menu pour l’ouvrir, copier son adresse ou copier la sélection. Voir le PR #10979 

Les paramètres d’appel d’outil s’affichent en ligne. Avec ui.showToolCallArgs activé dans les paramètres, chaque appel d’outil occupe sa ligne, suivie d’une ligne JSON contenant les paramètres réellement passés. Désactivé par défaut. Voir le PR #10565 

Les éditeurs compatibles ACP montrent ce que fait un sous-agent. Pendant qu’un sous-agent travaille, son activité s’affiche en temps réel sur la carte d’outil parente : l’outil en cours d’exécution, le droit attendu. Voir le PR #8729 

La configuration de Token Plan est documentée. Point d’entrée, région, nom de variable d’environnement et exemple de settings.json sont tous décrits. Voir les PR #10980 , #10993
