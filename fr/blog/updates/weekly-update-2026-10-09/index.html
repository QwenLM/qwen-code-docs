Qwen Code Hebdo : Qwen Live est lancé, Qwen Code travaille sur vos pages déjà connectées, un e-mail suffit pour confier une tâche

Qwen Team
2026-10-09

Qwen Code publie en deux semaines quatre versions stables — de v0.24.5 à v0.25.0 — avec 467 PR fusionnées.

Qwen Live est lancé. Vous lui parlez, il vous répond à voix haute. Pendant l’appel, vous pouvez partager votre écran : il voit ce qui s’y passe en ce moment.

Qwen Code travaille sur les pages où vous êtes déjà connecté. Il reprend le Chrome que vous utilisez tous les jours pour naviguer, remplir les formulaires et envoyer. Tout se fait en arrière-plan, vous gardez la main sur votre ordinateur.

Un e-mail suffit pour confier une tâche. Vous n’êtes pas devant la machine : une phrase depuis l’appli mail de votre téléphone, et Qwen Code s’en occupe sur cet ordinateur. Une fois fini, il vous écrit pour donner le résultat.

Un lot de tâches répétitives part en arrière-plan à moitié prix avec /batch-api. Vous dites quoi faire, il rend d’abord un plan qui n’est pas facturé, vous validez, puis quelques heures plus tard les résultats sont posés dans des fichiers.

Un tour vous paraît lent ou coûteux ? L’onglet Trajectory dit où ça coince. « Model requests », « Tool calls » et « Subagent requests » tiennent chacune leur piste : la portion anormalement longue saute aux yeux.

✨ Nouvelles fonctionnalités

Qwen Live est lancé

Qwen Live est disponible, dans le Web Shell comme dans la version desktop. Cliquez sur l’icône Live dans la barre latérale gauche : la carte Qwen Live s’ouvre à droite. Activez l’interrupteur, collez votre clé API DashScope Realtime d’Alibaba Cloud Model Studio, puis cliquez sur Save. Voir le PR #12529 

Une fois activé, cliquez sur « Open Live Voice » sur la page Live, ou sur le bouton vocal en bas à droite du champ de saisie : vous parlez, il vous répond à voix haute. Voir le PR #12189 

Pendant l’appel, vous pouvez aussi cliquer sur « Partager l’écran » : il voit ce qui se passe à l’écran, et vous lui demandez directement ce que veut dire l’erreur affichée. Voir les PR #12378 , #12623 

Ce que vous pouvez en faire :

  • Vos mains restent sur le clavier : vous dites oralement la prochaine étape à accomplir
  • Une erreur qu’on ne comprend pas s’affiche : partagez l’écran, il la lit lui-même puis donne son avis
  • Un échange qui demande beaucoup de phrases d’affilée se dicte en une fois

Qwen Code travaille sur les pages où vous êtes déjà connecté

Qwen Code passe par le Chrome que vous utilisez tous les jours : les onglets que vous avez ouverts, les comptes où vous êtes connecté, il les reprend tels quels. Il navigue, remplit les formulaires, envoie, puis vous laisse la page de résultat sous les yeux. Dites simplement « Lis le rapport que j’ai ouvert et récapitule les commandes du jour ». Voir le PR #11242 

Avant de l’utiliser, installez l’extension Qwen Code  depuis le Chrome Web Store ; ensuite, dites dans la conversation ce qu’il faut faire. Disponible sur Mac et Linux, Windows n’est pas encore pris en charge. Voir le PR #12510 

Tout cela se déroule en arrière-plan : Chrome ne passe pas au premier plan et votre ordinateur reste utilisable. Plusieurs conversations peuvent s’en servir en même temps, chacune avec son propre groupe d’onglets, sans se gêner. Voir le PR #12229 

Ce que vous pouvez en faire :

  • Lui faire lire le back-office où vous êtes connecté et relever les chiffres du jour pour les comparer à votre tableau
  • Des notes de frais ou des tickets éparpillés sur plusieurs pages : une phrase suffit pour qu’il les remplisse et les envoie un par un
  • Surveiller un flux visible uniquement sur le web — file d’approbation, liste de tâches — et en extraire ce qui demande une action

Un e-mail suffit pour confier une tâche

Une idée vous traverse l’esprit, mais l’ordinateur qui fait tourner Qwen Code n’est pas à portée de main. Voici Email Channel : envoyez un e-mail, c’est tout.

Depuis n’importe quelle appli mail de votre téléphone, donnez une consigne : Qwen Code l’exécute sur cet ordinateur et vous renvoie un e-mail avec le résultat. Si quelque chose cloche, répondez à ce message avec une précision — il sait déjà où il en est. L’e-mail d’erreur que quelqu’un vous envoie, comme l’alerte d’un système, peut être transféré dans cette boîte pour qu’il reprenne la main.

Pour l’utiliser, donnez d’abord une adresse mail à Qwen Code, puis ajoutez votre propre adresse dans sa liste : il n’agit que sur les messages que vous envoyez.

Ce que vous pouvez en faire :

  • Dans les transports, envoyer un e-mail pour lancer le travail et trouver le résultat en arrivant à votre bureau
  • Transféré tel quel, l’e-mail d’un utilisateur qui signale un problème : il lit les journaux en pièce jointe et donne une première analyse
  • Dès qu’une alerte part, Qwen Code s’en saisit, enquête, puis vous écrit pour dire la cause trouvée

Voir le PR #12939 

/batch-api : un lot de tâches en arrière-plan, à moitié prix

Vous avez des centaines de petites tâches indépendantes : traduire tout un répertoire de documents, extraire quelques champs de dizaines de tickets, rédiger un résumé pour chacun. Les envoyer une par une encombre la conversation d’attente, et l’argent part vite.

Écrivez /batch-api suivi de ce qu’il faut faire. Il examine quelques échantillons et vous remet un plan : combien d’éléments, dans quel répertoire, combien de tokens à peu près. Cette étape n’est pas facturée. Vous dites oui, et le lot est réellement soumis. Il tourne ensuite en arrière-plan à la moitié du tarif temps réel ; en général, entre quelques dizaines de minutes et quelques heures plus tard, les résultats se posent en fichiers à l’endroit que vous avez indiqué. Pendant ce temps, votre conversation travaille normalement.

/batch-api Traduis en anglais les documents Markdown du dossier docs/zh et écris-les sous le même nom dans docs/en

C’est fait pour les lots traitables en une seule passe, dont les éléments n’ont rien à voir entre eux. Ce qui demande plusieurs allers-retours reste une conversation classique.

Ce que vous pouvez en faire :

  • Tout un répertoire de documentation chinoise traduit en anglais, soumis en une fois et récupéré quelques heures plus tard
  • Des journaux ou des tickets à champs extraits élément par élément, regroupés en une seule exécution
  • Des centaines de retours utilisateurs classés et étiquetés un par un, soumis en une fois

Voir le PR #12492 

Onglet Trajectory : voir où part le temps d’un tour

Un tour se termine et vous le trouvez long. Vous savez seulement qu’il est « long » : impossible de dire si le modèle a mis du temps à répondre, s’il a trop parlé, ou si un outil est resté bloqué en route.

L’onglet Trajectory du panneau de droite étale le temps en trois pistes : « Model requests », « Tool calls » et « Subagent requests ». La portion anormalement longue se voit d’emblée ; quand les barres sont trop serrées, agrandissez une plage pour la détailler. Voir les PR #12524 , #12557 

Une plage vous semble suspecte ? Encadrez-la sur l’axe : il ne reste en dessous que ce qui s’est passé sur ce créneau. Sélectionnez une entrée : ce qu’elle a lu, ce qu’elle a renvoyé et les tokens consommés s’affichent, et vous pouvez les copier directement. Voir les PR #12543 , #12971 

L’axe propose aussi un rendu « Real time », qui compte le temps où vous attendez sans rien pouvoir faire et donne deux chiffres : la durée totale et le temps réellement en exécution. C’est là que se voit le temps que le tour vous a pris. Voir le PR #12607 

Les tours terminés se replient : inutile de remonter du début à la fin d’une longue session. Voir le PR #13081 

Ce que vous pouvez en faire :

  • Un doute sur la lenteur : l’axe dit sur quoi intervenir en premier, changer de modèle ou vérifier cet outil
  • Dans une longue session, encadrer la plage qui intéresse et replier les tours finis pour y revenir
  • Une opération semble mal tournée : consultez sur place son entrée, sa sortie et les tokens consommés

Channel : un bot mène plusieurs fils de front, privé et groupe réglés à part, longues sessions renouvelées

Un même bot peut mener plusieurs fils à la fois. Un préfixe en tête de message ouvre une conversation différente, avec ses propres exigences de transmission : faites-lui relire du code d’un côté, répondre aux questions du dépôt de l’autre. Les deux ne se mélangent pas et vous n’avez pas besoin d’ouvrir une connexion de plus. Dans un groupe, mentionnez-le puis ajoutez le préfixe. Voir le PR #12595 

Qui a droit au privé et qui peut l’employer dans le groupe sont deux réglages distincts. Vous pouvez ouvrir le groupe à tout le monde tout en réservant le privé aux quelques personnes de votre liste. Les deux côtés restent indépendants. Voir les PR #12547 , #12475 

Une longue conversation de groupe se renouvelle toute seule. Un fil s’allonge message après message ; à force, il ne peut plus rien envoyer et seule cette conversation est cassée. Un fil DingTalk en avait accumulé 8 577. Vous pouvez désormais lui fixer un plafond ; atteint, une nouvelle conversation démarre et le groupe est prévenu. Voir le PR #12616 

Web Shell : barre latérale réorganisée, recherche dans l’historique d’une longue session, plusieurs copies de travail pour un même dépôt

La barre latérale a été réorganisée. Une navigation fine s’ajoute à gauche : Channel, la voix et le reste ont chacun leur entrée ; le numéro de version et les actions rares partent dans « Plus ». Voir le PR #12943 

Une longue session retrouve ce qui a été dit. Retrouver une phrase déjà écrite ou un morceau de code déjà collé : la recherche par mot-clé saute directement au message. Inutile de faire défiler vers le haut pour atteindre les plus anciens, la recherche les trouve. Voir le PR #12234 

« Poser une question à côté » est maintenant visible. Une petite question à glisser pendant que la tâche principale tourne : le menu « + » du champ de saisie contient cette entrée et rédige la demande pour vous. La réponse arrive dans un panneau à côté, la tâche principale continue. Voir le PR #12775 

Un même dépôt peut accueillir plusieurs copies de travail. Dans la continuité du graphe de branches de la dernière livraison, la boîte Git a un onglet « Worktree » : chaque conversation utilise sa propre copie, les modifications ne se gênent pas. On voit quelle copie fait tourner une conversation et laquelle garde des modifications non commitées, et un clic y amène. Voir les PR #12154 , #11816 

📊 Autres nouvelles fonctionnalités

Le commit peut aussi lui revenir. Tapez /commit : il regarde quels fichiers ont changé, rédige un message de commit dans le style de l’historique du dépôt, et ne place que les fichiers qui appartiennent à ce commit. Un fichier comme .env, qui garde des secrets, il le refuse. Il crée le commit ; le push reste votre affaire. Pour limiter le périmètre, ajoutez une précision derrière, par exemple /commit only stage the parser changes. Voir le PR #10586 

Voir ce qu’une de vos phrases lui a fait faire. Dans le Web Shell, arrêtez la souris sur le message que vous avez envoyé : une icône clé anglaise apparaît à côté du bouton copier. Cliquez et l’onglet « Appels d’outils » s’ouvre : quels fichiers lus, quelles commandes lancées, quels endroits modifiés, listés un par un ; chacun se déplie pour montrer le résultat et le diff. Les tours d’avant sont consultables aussi. Voir le PR #12466 

/advisor passe de la relecture à la demande. Une fois activé, le modèle qui travaille va de lui-même consulter un conseiller avant de modifier quoi que ce soit, puis au moment de rendre son travail ; l’avis revient dans la conversation et il continue. Les sous-agents qu’il envoie peuvent consulter eux aussi. Chaque appel coûte des tokens en plus, et l’échange est soumis au modèle conseiller : choisissez-en un qui mérite votre confiance. Voir les PR #9636 , #12688 

Brancher un nouveau modèle demande moins de saisie. Taille de la fenêtre de contexte, longueur de sortie maximale, capacité à recevoir des images : il le sait désormais tout seul. Un catalogue de modèles intégré est rafraîchi en arrière-plan chaque jour et reste utilisable hors connexion. Les valeurs que vous avez saisies gardent la main. Voir le PR #11959 

Une mémoire externe se branche plus simplement. Pour qu’il retienne les choses d’une session à l’autre, une adresse et une clé suffisent : installer une extension ou enregistrer un service n’est plus nécessaire. La recherche marche par défaut ; pour qu’il écrive dehors, activez un interrupteur, et après cela tout ce qui est enregistré passe d’abord sous vos yeux. Voir le PR #12891 

Une mémoire fournie ne s’étale plus en entier. Une fois activé, il ne place dans le contexte que les entrées liées à votre question actuelle, et va chercher le reste si besoin. Quand la mémoire atteint des dizaines ou des centaines de fichiers, cela en économise pas mal. Voir le PR #10183 

Le bot QQ reçoit images et vidéos. Les photos et les courtes vidéos envoyées dans le groupe, il les regarde directement, sans que vous deviez les décrire par écrit. Voir le PR #12850 

👏 Améliorations de l’expérience

Prêt à taper deux fois plus vite. Sur une machine propre, entre la frappe de qwen et le premier caractère possible, il fallait environ 2,5 s, dont 2 s de terminal vide. Cette attente est réduite de moitié, et l’empreinte mémoire baisse d’environ 60 % par rapport aux 575 Mo de départ. Voir les PR #12622 , #12602 , #12603 

Le panneau de paramètres est entièrement en chinois. Quand la langue de l’interface est réglée sur le chinois, plus aucun libellé ne reste dans une autre langue. Voir le PR #12783 

Qui parle dans le groupe et qui administre les sessions se règlent dans une fenêtre. Ces deux listes d’un Channel se changent dans un dialogue : inutile d’ouvrir le fichier de configuration pour les saisir à la main. Voir le PR #12535 

L’interface respire un peu plus. Un paramètre vide ne prend plus une ligne entière, l’en-tête de la page de statistiques est aligné, et les données brutes partent dans le détail. Voir les PR #12601 , #13091 

Après avoir modifié un skill, un rafraîchissement suffit. Voir le PR #12182
