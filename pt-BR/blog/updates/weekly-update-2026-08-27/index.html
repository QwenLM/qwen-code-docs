Qwen Code Semanal: Goal encerra sozinho quando o orçamento estoura, modelo Qwen ganha botão de Thinking, use mais comandos “/” enquanto a IA responde

Qwen Team
2026-08-27

O Qwen Code lançou três versões oficiais esta semana — v0.21.15, v0.22.0 e v0.22.2 — com mais de 300 PRs integrados.

Goal sabe a hora de parar. O Goal autônomo agora vem com orçamento de token: quando estoura, escreve um relatório de entrega e para; quando percebe que o alvo é inalcançável, para por conta própria.

Modelo Qwen com botão de Thinking. Modelos híbridos como o qwen3.5-plus ganharam um botão simples de Thinking: desligado, a sessão atual não pensa; ligado, volta ao comportamento padrão do modelo.

Mais comandos de barra durante a resposta. Enquanto a IA está gerando, 10 comandos de barra como /theme e /tools funcionam na hora, sem esperar a rodada acabar.

✨ Novidades

Goal: orçamento de token e relatório de entrega antes de parar

O Goal autônomo esta semana ganhou “autoconsciência”: sabe quanto gastou, quando parar e o que deixar dito antes de parar.

Controle de gasto por Goal. Cada Goal agora registra individualmente quanto token gastou. Dá para ver no get_goal, lado a lado com o número de rodadas.

Orçamento definido. Novos Goals vêm com um orçamento de token padrão. Quando o Goal autônomo gasta tudo, entra em espera. Para continuar, basta recuperar ou editar o Goal — o orçamento ganha uma nova janela automaticamente.

Rodada de entrega antes de parar. Quando o orçamento acaba, o Goal ganha uma “rodada de entrega” extra: não abre novo trabalho, apenas explica o que fez, o que falta e qual é o próximo passo — e então para. Quem assumir depois lê esse relatório e retoma de onde parou.

Para sozinho quando trava. Se três verificações seguidas derem problema, o Goal para automaticamente; se houver evidência de que o alvo é impossível, para já na rodada atual.

/goal-draft transforma uma ideia vaga em um Goal executável. Ele primeiro faz algumas perguntas para esclarecer a ideia vaga, depois rascunha um Goal verificável e anexa um comando /goal set pronto para executar. Ele só rascunha, não executa o trabalho; usar ou não depende de você.

Veja os PRs #9583 , #9891 , #10132 , #9975 , #10125 , #10002 

Modelos Qwen ganham botão de Thinking

No web shell, os modelos qwen3.5-plus, qwen3.6-plus, qwen3.6-flash, qwen3.7-plus e qwen3.7-max agora têm um botão de Thinking: desligado, a resposta atual pula a etapa de raciocínio; ligado, pensa antes de responder.

O qwen3.8-max mantém os três níveis de intensidade de raciocínio: low / medium / extra high.

Veja o PR #9574 

Workflow com botão oficial e aprovação pré-execução

O workflow divide uma tarefa grande e distribui entre vários assistentes de IA. Esta semana ganhou três camadas de controle:

  • Botão oficial: ative tools.workflowsEnabled nas configurações e pronto — só você pode ligar, a configuração do projeto não mexe nisso
  • Aprovação antes de rodar: antes de rodar, o popup de aprovação mostra por inteiro o script de workflow que a IA acabou de escrever — o que ela vai pesquisar, como divide o trabalho, como junta os resultados. Você lê, confirma, e só então ele roda
  • Sob demanda: só inicia quando você quer delegar de verdade — dizendo “use o workflow”, nomeando um workflow específico ou mandando continuar de onde parou; se a IA acha que precisa mas você não mencionou, ela primeiro explica como pretende delegar e quantos assistentes vai usar, e espera seu aval

Veja os PRs #9098 , #9837 , #9806 

PR do GitHub vinculado à sessão que o criou

Depois de abrir um PR pelo Web Shell, encontrar “qual sessão abriu aquele PR” exigia fuçar no histórico. Agora, PRs criados pelo painel Git do Web Shell ficam vinculados à sessão de origem: um badge de PR aparece ao lado do nome da sessão na barra lateral, e buscar pelo número do PR leva direto à sessão correspondente. Cada sessão registra até 10 PRs; quando o mesmo PR recebe um novo push, o registro atualiza para o mais recente.

Veja o PR #9543 

Mais comandos de barra funcionam enquanto a IA responde

Antes, a maioria dos comandos de barra precisava esperar a IA terminar de gerar. Esta semana, 10 comandos entraram na lista de “não precisa esperar”: /theme, /editor, /vim, /voice, /terminal-setup (configuração de interface) e /tools, /tasks, /hooks, /docs, /bug (somente leitura) — use à vontade enquanto a IA fala, o resultado aparece na hora.

Veja o PR #9495 

📊 Mais funcionalidades

qwen3.8-max sai de preview e vira versão estável. O qwen3.8-max agora é versão estável; usuários do Token Plan podem selecioná-lo diretamente no /model. Veja o PR #9383 

Adicionar arquivos no meio da conversa. Semana passada dava para arrastar arquivos para a caixa de entrada do Web Shell; agora, mesmo com a conversa em andamento, dá para adicionar anexos — tanto pelo anexo na caixa de entrada quanto por @ referenciando arquivos do workspace. A IA recebe na hora. A entrada de upload também foi unificada: ou referencia um arquivo do workspace ou faz upload direto, e os anexos enviados ficam salvos permanentemente. Veja os PRs #9570 , #9477 

Modelo de conversa também gera imagem. O mesmo modelo agora cuida de conversa e geração de imagem integrada, sem precisar de um modelo separado só para imagens; a geração de imagem também passou a suportar a API do MiniMax. Veja os PRs #9650 , #8322 

Gerencie o Goal direto no Web Shell. O Goal não depende mais de mensagens de chat para ser gerenciado — o Web Shell ganhou uma barra compacta e dedicada só para isso. Veja o PR #9393 

Tarefas agendadas rodam dentro da sessão atual. Na criação de uma tarefa agendada, dá para escolher executá-la dentro da sessão atual. Veja os PRs #9838 , #9361 

Código desktop migrado para o OpenWork. O código desktop Electron foi movido para o projeto open-source independente OpenWork , onde segue em desenvolvimento. O repositório do Qwen Code mantém apenas a ponte de migração para a nova versão desktop. Veja o PR #9085 

Computer Use agora é orientado por habilidade. A IA agora opera o computador usando habilidades próprias: no primeiro uso, instala as dependências automaticamente e pede um reinício — depois funciona normalmente. O Node REPL deixou de ser uma ferramenta embutida e virou o pacote MCP independente @qwen-code/node-repl-mcp, desativado por padrão e que só entra em vigor quando configurado no mcpServers. Veja os PRs #9856 , #9587 , #9499 

Kimi como provedor embutido. No /auth, escolha o provedor de terceiros Kimi, insira a API key e está conectado — endpoint internacional ou doméstico à escolha. A lista de modelos já vem com o flagship K3, K2.6 e dois modelos especializados em código, e você pode editar a lista. O K3 vem com raciocínio ligado por padrão; os outros três podem ligar e desligar livremente. Veja o PR #9814 

👏 Melhorias de experiência

Painel de uso no Web Shell. O Web Shell agora tem um painel de consumo de token por sessão: total, divisão por modelo, chamadas de sub-agentes e estatísticas de uso de ferramentas — tudo numa página. Veja o PR #9988 

Modo compacto vira o único no Web Shell. Blocos de raciocínio e atividade de ferramentas agora vêm recolhidos em linhas de resumo por padrão; o atalho Ctrl+O foi removido. A conversa principal, o painel dividido e o painel de detalhes do sub-agente usam todos a mesma renderização compacta. Veja os PRs #9993 , #9657 

Cartão de aprovação dentro do fluxo de mensagens. Aprovações de ferramentas e perguntas não cobrem mais a lista inteira de mensagens — viraram um cartão fixado na parte inferior do fluxo de mensagens, com a mesma largura da área de chat. Veja o PR #9351 

Shell em segundo plano mantém a rodada aberta. Quando uma rodada dispara um shell em segundo plano, ela fica aberta até o processo terminar, para você acompanhar o progresso. Veja o PR #9632 

Plugin VS Code com a mesma renderização. A linha do tempo de sessões do plugin VS Code agora usa o mesmo renderizador do Web Shell, alinhando a experiência visual dos dois lados. Veja o PR #9719 

Terminal grande rola mais suave. A taxa de renderização da rolagem virtual do terminal subiu de 30 para 60 quadros por segundo — rolar o histórico em janelas grandes ficou visivelmente mais fluido. Veja o PR #9681 

Agora dá para ver quais arquivos de contexto foram carregados. Quando você adiciona arquivos de contexto personalizados nas configurações, a primeira mensagem da sessão agora lista quais arquivos foram carregados — antes, essa etapa era completamente invisível. Veja o PR #8855 

Sessão lembra o modelo escolhido. Depois de reiniciar ou reconectar uma sessão daemon, ela volta para o modelo que você selecionou por último naquela sessão; sessões novas ainda usam o padrão das configurações. Veja o PR #9687 

Canal DingTalk agora entende citações. Antes, ao citar uma imagem ou arquivo no DingTalk, a IA só via um placeholder; agora, imagens, arquivos, áudios e vídeos citados são baixados de verdade e entregues à IA, e mensagens encaminhadas de histórico têm título e resumo extraídos e incluídos no contexto. Veja os PRs #9347 , #9339 

Instale extensões de repositórios privados. A instalação de extensões via HTTPS Git agora suporta autenticação — dá para clonar de repositórios privados, com opção de salvar ou não as credenciais. Veja o PR #9458 

Git antigo também instala extensões públicas. Em sistemas com Git anterior à versão 2.37, a instalação de extensões públicas do GitHub usa o caminho de download de arquivo compactado. Veja os PRs #9680 , #9690 

Um comando abre o Web Shell com autenticação. qwen serve --open-with-auth abre um Web Shell local com autenticação por token; se nenhum token estiver configurado, gera um automaticamente e passa para o navegador. Veja o PR #9738 

Homebrew para de alertar atualização fantasma. Quando os metadados locais confirmam que não há versão nova, o aviso de atualização não aparece mais. Veja o PR #9502
