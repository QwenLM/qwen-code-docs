Qwen Code Semanal: redirecionamento em tempo real para corrigir o Agent a qualquer momento, sessões isoladas com Worktree sem conflitos, web_search integrado de volta

Qwen Team
2026-07-23

Esta semana o Qwen Code lançou três versões oficiais: v0.19.12, v0.20.0 e v0.20.1, com 220+ PRs integrados.

O Agent saiu do rumo? É só digitar para corrigir. Enquanto o modelo está gerando saída, pressione Enter e sua mensagem orienta o turno atual no próximo ponto de amostragem; pressione Ctrl+Q para adiar para o próximo turno. Mensagens digitadas durante a execução de ferramentas também funcionam. Não precisa mais esperar o Agent terminar para corrigir.

Tarefas paralelas finalmente não se atropelam mais. O Web Shell agora suporta criação de sessões isoladas com Worktree em um clique — múltiplas tarefas no mesmo repositório rodam em git worktrees independentes, sem interferência entre edições de arquivos, git add e git checkout. O identificador roxo ⑂ aparece no git chip, na lista de sessões e no menu dropdown do workspace.

A busca na web está de volta. A ferramenta integrada web_search é baseada na Responses API do Bailian — basta usar a chave de API Bailian que você já tem. A comunidade pedia o retorno desde que foi removida; desta vez foi reimplementada com busca no servidor + leitura de páginas, com links de referência Sources anexados automaticamente ao final da resposta. Desativada por padrão — é preciso ativar explicitamente.

web_fetch reconstruído do zero. Antes, ao buscar páginas web os links se perdiam, PDFs viravam texto corrompido e páginas grandes eram truncadas com perda de conteúdo. Agora o HTML é convertido para markdown antes do truncamento, PDFs têm texto extraído inline, arquivos binários são salvos corretamente, com timeout de 60 segundos e limite de 10 MB como proteção.

✨ Novidades

Redirecionamento em tempo real: corrija o Agent enquanto ele gera saída

Antes, se você digitasse algo enquanto o Agent estava gerando saída, tinha que esperar ele terminar para enviar — virava um novo prompt. Se o Agent saísse do rumo, só restava assistir até o fim e depois corrigir.

Agora Enter e Ctrl+Q têm funções bem definidas:

  • Enter: a mensagem entra na fila de redirecionamento e é aplicada no próximo ponto de amostragem do modelo, ainda dentro do turno atual. O Agent está escrevendo código e você digita “reescreve em TypeScript” — ele recebe essa orientação no próximo ponto de amostragem.
  • Ctrl+Q: a mensagem é adiada para depois do fim do turno atual, abrindo um novo turno de conversa.
  • Durante a execução de ferramentas: mensagens digitadas são consumidas após o retorno do resultado da ferramenta, dentro do mesmo turno.
  • Mudou de ideia? Pressione Up ou Escape e a mensagem enfileirada volta para o campo de entrada.

Anexos com @ também são preservados, sem prefixo sintético. Se a entrega falhar ou for cancelada, a mensagem não se perde.

O que você pode fazer com isso:

  • O Agent está escrevendo código na direção errada — digite para corrigir sem esperar ele terminar
  • Adicione informações de contexto enquanto uma ferramenta está em execução
  • Já sabe o que perguntar no próximo turno? Ctrl+Q enfileira e envia automaticamente quando o turno atual terminar

Veja o PR #7090 

Sessões isoladas com Worktree: tarefas paralelas cada uma no seu espaço

Ao trabalhar em duas tarefas ao mesmo tempo no mesmo repositório, uma sessão edita um arquivo e o git status da outra fica uma bagunça. Antes era preciso fazer git worktree add + cd manualmente; agora o Web Shell resolve em um clique.

Clique em “New Worktree Task” no menu dropdown do pill de branch do workspace, e o daemon cria automaticamente um git worktree em <repoRoot>/.qwen/worktrees/<slug>, com o diretório de trabalho da sessão apontando para o worktree. Toda a interface usa o identificador roxo ⑂ para diferenciar: o git chip fica roxo, a lista de sessões mostra o marcador ⑂ e o menu dropdown do workspace traz a indicação. Repositórios que não são git não mostram essa opção.

As informações do Worktree são persistidas em um arquivo sidecar e não se perdem após reinício do daemon. Ao restaurar a sessão, o isolamento do worktree é recriado automaticamente, e a barra de status mostra o nome do branch do worktree em vez do branch principal do workspace.

O que você pode fazer com isso:

  • Rodar dois desenvolvimentos de funcionalidade ao mesmo tempo, sem interferência
  • Corrigir um bug enquanto continua trabalhando em uma feature, sem ficar fazendo stash pra lá e pra cá
  • Deixar o Agent fazer alterações experimentais em um ambiente isolado, mantendo o workspace principal limpo

Veja os PRs #7221 , #7262 , #7365 , #7367 

web_search integrado: busca na web com sua chave Bailian

Antes o Qwen Code não tinha busca integrada — a documentação mandava configurar o MCP WebSearch do Bailian. Mas na prática, aquele MCP não entregava qualidade em consultas complexas: uma consulta de taxas do Medicare com resposta padrão retornava 0 de 5 resultados relevantes em múltiplas execuções.

Esta semana a ferramenta integrada web_search está de volta. Baseada na busca server-side da Responses API do Bailian, usa a chave de API Bailian que você já configurou — sem MCP adicional, sem provider adicional, sem chave adicional. O agente de busca abre as páginas dos resultados para respostas mais fundamentadas, diferenciando “páginas efetivamente lidas” de “links candidatos não abertos”, e o modelo deve incluir uma seção Sources com referências ao final da resposta.

Desativada por padrão — são necessárias duas configurações para ativar: tools.webSearch.enabled: true e o modelo de busca tools.webSearch.model. Se configurado mas incompleto, a ferramenta permanece desativada e informa na inicialização exatamente qual condição não foi atendida. Também suporta configuração por variáveis de ambiente (ENABLE_WEB_SEARCH, WEB_SEARCH_MODEL, etc.), ideal para ambientes onde não é possível editar o settings.json. Cada chamada de busca requer confirmação (exibe a consulta, com opção de “sempre permitir”).

O que você pode fazer com isso:

  • Consultar informações com prazo de validade: mudanças na versão mais recente de uma biblioteca, atualizações de documentação de API, avisos de segurança
  • Investigar problemas posteriores à data de corte de conhecimento do modelo: breaking changes em versões novas, bug reports recentes
  • Substituir o fluxo de sair do terminal e abrir o navegador para pesquisar

Veja o PR #7215 

web_fetch completamente reconstruído: PDFs sem texto corrompido, links sem perda

O web_fetch anterior tinha vários problemas reais: páginas de listagem grandes eram truncadas no HTML bruto antes da conversão, cortando a resposta; URLs de links se perdiam completamente, e o modelo confidently dizia que “o alvo não existe”. PDFs eram decodificados como texto, gerando dezenas de milhares de tokens de texto corrompido. Alguns sites governamentais retornavam 403 para User-Agent anônimo.

Esta semana o pipeline inteiro foi reconstruído do zero:

  • HTML é convertido para markdown antes do truncamento, preservando conteúdo no fundo de páginas grandes e mantendo URLs de todos os hiperlinks. O truncamento tem marcação explícita; scripts e estilos não consomem o orçamento de conteúdo.
  • Extração de texto de PDF inline — uma única chamada de web_fetch já responde sobre o conteúdo do PDF. Arquivos binários são identificados por magic bytes (não apenas Content-Type) e salvos com a extensão correta.
  • Timeout de 60 segundos + limite de 10 MB, com Esc para cancelar a transferência imediatamente — antes a UI podia congelar. Buscas repetidas da mesma URL dentro de 15 minutos usam cache.
  • Redirecionamentos entre hosts não são mais seguidos silenciosamente — o sistema sugere que você faça uma nova requisição, passando pelo fluxo normal de permissões.
  • Modelo de permissões: o primeiro acesso a cada host requer confirmação (GETs expõem o caminho completo e a query, sendo um canal potencial de exfiltração de dados). Após aprovação, a regra é persistida por host. URLs de blob do GitHub são automaticamente normalizadas para endereços raw antes da avaliação de permissões.

O que você pode fazer com isso:

  • Buscar um link de PDF e responder diretamente sobre o conteúdo
  • Buscar uma página de listagem longa e perguntar sobre itens no fundo da página, sem perda de links
  • Redirecionamentos entre hosts pedem confirmação para nova requisição, sem seguir silenciosamente para domínios desconhecidos

Veja o PR #7146 

Grande atualização do Web Shell esta semana

O Web Shell recebeu um volume enorme de mudanças esta semana — de integração git a gerenciamento de sessões e experiência de workspace. Vamos por partes.

Trio de integração Git. O comando /log abre um navegador de histórico de commits em popup gráfico, com lista de commits, clique para expandir e ver a mensagem completa e estatísticas de alterações de arquivos, cópia do SHA em um clique e carregamento paginado. O popup de /diff também ganhou uma aba History, sem precisar trocar de comando. O chip de git status aparece na barra de ferramentas do composer, a barra lateral mostra o estado git do workspace e o popup de Changes exibe o diff visual da working tree. Veja os PRs #7204 , #7054 

Página de gerenciamento de Skills e página de Goals. O Web Shell agora tem uma página dedicada para visualizar e gerenciar skills do workspace, sem precisar voltar ao terminal. A página de Goals torna os objetivos do /goal visíveis no Web Shell, e os objetivos não se perdem após reinício do daemon. Veja os PRs #7018 , #6561 

Melhorias no gerenciamento de sessões. Cmd+B / Ctrl+B alterna a barra lateral, o layout de split view persiste entre refreshes (independente por aba), sessões restauradas carregam histórico com paginação em vez de puxar tudo de uma vez, e sessões arquivadas suportam exportação. O popup de Add Workspace ganhou autocompletar de diretório. Veja os PRs #7135 , #7136 , #7064 , #6910 , #7125 

Experiência de Workspace. Suporte a nomes de exibição personalizados para workspaces — em cenários com múltiplos workspaces, não é mais preciso olhar só o caminho. Ações de comandos slash personalizados, API de personalização da sidebar (marca, navegação, operações de sessão, footer). Rascunhos de novo tópico sugerem abrir uma nova sessão em vez de continuar na antiga. Veja os PRs #7179 , #7267 , #7379 , #7098 

📊 Mais funcionalidades

Valores padrão e aviso de escrita para Artifacts. O Agent agora tem configuração padrão ao criar artifacts e pede confirmação antes de escrever, reduzindo escritas acidentais de arquivos. Veja o PR #7068 

Resumo de ferramentas mostra caminho ativo. O resumo compacto de ferramentas exibe o caminho do arquivo sendo operado — em operações com múltiplos arquivos, você vê de imediato qual arquivo está sendo alterado. Veja o PR #7043 

Valores padrão e proteções para delegação de subagentes. Configuração padrão e limites de segurança da delegação de subagentes aprimorados, tornando o comportamento dos subagentes mais previsível. Veja o PR #7048 

Roteamento de logs no VSCode. Logs são direcionados para um output channel dedicado do Qwen Code Companion — para diagnosticar problemas no VSCode, não é mais preciso vasculhar outros painéis. Veja o PR #7121 

Rotação de logs do Daemon. Rotação de logs com limite — não crescem mais indefinidamente, e o disco não é mais consumido por logs do daemon. Veja o PR #6969 

Replay de histórico somente leitura no WebShell. Reprodução de histórico de ChatRecord em WebShell somente leitura, facilitando o compartilhamento de registros de sessão com colegas. Veja o PR #6999 

Normalização de nomes de ferramentas MCP. Nomes de ferramentas MCP normalizados para providers estritos, reduzindo falhas em chamadas de ferramentas MCP. Veja o PR #6976 

Recall de memória em Channels. Cada mensagem aciona automaticamente o recall de memórias relevantes, confirma alterações de memória natural e salva com segurança memórias com múltiplos fatos — o Agent em conversas de Channel lembra do contexto anterior. Veja os PRs #7157 , #7066 , #7092 

Observação de nome de grupo em Channels. O nome do grupo é obtido automaticamente das mensagens recebidas — em cenários com múltiplos grupos, o Agent sabe em qual grupo está. Veja o PR #7155 

Caminhos formatados na descrição de ferramentas. Descrições de ferramentas como grep/glob exibem caminhos de arquivos formatados, com resultados mais claros e legíveis. Veja o PR #7050 

Autocompletar com tab aprimorado no /cd. Ao digitar um nome de diretório e pressionar tab, o diretório já digitado é incluído nas sugestões, tornando o autocompletar mais preciso. Veja o PR #7320 

👏 Melhorias de experiência

Seleção com mouse no VP mode está de volta. Antes, os eventos de mouse no VP mode eram consumidos pelo CLI, impossibilitando selecionar e copiar. Agora é possível selecionar arrastando, dar duplo clique para selecionar palavra, triplo clique para selecionar linha — ao soltar, o conteúdo é copiado automaticamente para a área de transferência. Veja o PR #6937 

Reforço de segurança no Plan mode. Sair do Plan mode agora requer sua aprovação explícita — não sai mais silenciosamente. Comandos Shell no Plan mode são classificados por segurança: comandos somente leitura executam normalmente, comandos que modificam estado são bloqueados diretamente, e comandos indeterminados requerem aprovação individual sem sair do Plan mode. A confirmação de saída mostra o conteúdo completo do plano. Veja os PRs #6967 , #7172 , #7060 

Idioma de saída segue automaticamente. Quando configurado como auto, o idioma de saída acompanha o idioma de entrada do usuário, sem necessidade de troca manual. Veja o PR #6953 

Proteção contra Ctrl+C acidental. Para sair da TUI é preciso pressionar Ctrl+C duas vezes dentro de 1 segundo — um único Ctrl+C não fecha mais diretamente. Veja o PR #7129 

Controle de concorrência de subagentes. Suporte a limite de concorrência de subagentes por modelo — modelos diferentes podem ter configurações de concorrência diferentes. Subagentes fork ganharam o parâmetro fork_turns, permitindo herdar apenas os últimos turnos da conversa em vez do histórico completo. Veja os PRs #6984 , #7346 

Adaptação de modelos. Limites de token do kimi-k3 (contexto de 1M, saída de 128K), qwen3.8-max-preview adicionado à lista de modelos do Token Plan, suporte à região de Singapura no Token Plan. Veja os PRs #7144 , #7199 , #7280 

Outras melhorias. Limite de chamadas de ferramentas por turno agora é adaptativo, modo headless suporta subagentes com herança de contexto, controle de goal disponível em loops ativos, indicador de modo exibido durante saída em streaming, atualização npm executada em segundo plano com segurança. Veja os PRs #7052 , #7378 , #7202 , #7219 , #7322
