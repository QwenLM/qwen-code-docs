Qwen Code Semanal: /learn transforma conhecimento em Skill, Code Review ganha verificação de qualidade, Web Shell passa por grande renovação

Qwen Team
2026-07-16

Esta semana o Qwen Code lançou três versões oficiais: v0.19.9, v0.19.10 e v0.19.11, com 160+ PRs integrados.

Comando /learn disponível. Crie skills de forma ativa — forneça uma fonte de conhecimento (diretório, URL, conversa, texto) e o Qwen Code organiza tudo em um SKILL.md, pronto para reutilização.

Code Review evoluiu de “funcional” para “eficiente”. Suggestions agora são publicadas diretamente como comentários inline no PR, e o review ganhou verificadores de correção procedural, validação pré-publicação, verifier no Step 4 e reverse-audit no Step 5.

Web Shell com grande renovação. Base de componentes shadcn, painel de revisão Artifact, página de gerenciamento de extensions, Mermaid com zoom e arraste. Suporte completo a múltiplos workspaces, split pane com cores por workspace.

Voice Bridge integra entrada de voz ao ACP. Modelos principais de texto puro agora também processam prompts de voz — o áudio é transcrito para texto antes de chegar ao modelo; modelos que suportam áudio recebem o sinal original diretamente.

PDFs escaneados não travam mais o Agent. Quando a extração de texto ultrapassa o limite, as páginas são automaticamente renderizadas como imagens e enviadas ao modelo de visão.

Fluxos de CLI mais completos. /update para atualização com um clique, Ctrl+O para congelar a conversa, Ctrl+S para salvar prompts temporariamente, Explore herda o modelo principal, Alt+T para ver o raciocínio completo.

✨ Novidades

/learn: transforme conhecimento em Skill reutilizável

/learn é um novo comando slash que permite criar skills a partir de fontes de conhecimento. A fonte pode ser um diretório local, uma URL, histórico de conversa ou um texto escrito por você. O modelo principal coleta o conhecimento e o organiza automaticamente em um SKILL.md, salvo em .qwen/skills/learned-skill-<name>/, com a marcação source: learned — sem interferir com skills escritas manualmente ou geradas automaticamente.

O que você pode fazer com isso:

  • /learn Deploy process: ... transforma seu processo de deploy em uma skill, pronta para usar na próxima vez
  • Aponte para um diretório de documentação e o Qwen Code aprende as convenções do projeto, seguindo-as automaticamente no código
  • Extraia conhecimento de uma conversa e transforme em um template de instruções reutilizável

Veja o PR #6440 

Code Review ganha verificação de qualidade

O Code Review foi reforçado em múltiplas dimensões esta semana, desde comentários inline até verificação de qualidade do review.

/review agora publica descobertas do tipo Suggestion diretamente como comentários inline no PR — sem precisar copiar sugestões da saída do review e colar manualmente no PR. O review também ganhou verificadores de correção procedural e níveis de effort ajustáveis, com validação de guardrail antes de publicar cada finding para garantir que realmente procede.

Reviews de diffs grandes não são mais distribuídos de forma genérica — cada linha do diff tem um reviewer responsável, garantindo cobertura completa. O agent de chunk de review recebe o prompt completo e contextualizado, eliminando execuções com contexto vazio. Os comentários de triage de PR agora incluem pontuação de confiança, diagramas de sequência, resumos de arquivos e rodapé de review, oferecendo mais contexto ao reviewer. O timeout padrão de review automático foi ajustado para 180 minutos, com override de até 240 minutos — PRs grandes não são mais interrompidos por timeout.

O que você pode fazer com isso:

  • /review publica automaticamente comentários de sugestão inline no PR, eliminando o trabalho manual
  • Níveis de effort ajustáveis se adaptam ao tamanho do review
  • A pontuação de confiança do triage ajuda a identificar quais PRs precisam de mais atenção

A v0.19.11 adicionou verifier no Step 4 e reverse-audit no Step 5 — o fluxo de review passou de “encontrar problema → publicar comentário” para “encontrar problema → verificar que o finding procede → auditoria reversa para confirmar que nada foi esquecido”. A lista de findings foi incorporada aos prompts de verify/reverse-audit, reduzindo o volume de prompt. O escopo de build/test do Agent 7 também foi reduzido para os workspaces efetivamente envolvidos no diff, evitando builds completos em repositórios grandes.

Veja os PRs #6593 , #6711 , #6612 , #6789 , #6771 , #6840 , #6942 , #6965 , #6892 , #6955 

Web Shell UI com grande renovação

O Web Shell recebeu 15+ PRs concentrados esta semana, desde a base de componentes UI até a barra lateral, página de configurações e seletor de modelos.

A base agora usa shadcn como biblioteca de componentes UI, unificando tokens de design e normas de componentes. A barra lateral de múltiplos workspaces foi redesenhada, com layout mais claro. A página de configurações passou a usar componentes modernos, configurações de nível de usuário podem ser editadas diretamente no painel, e o gerenciamento de modelos foi integrado ao painel de configurações. O seletor de modelos foi redesenhado, com metadados mais claros e troca mais rápida. Veja os PRs #6760 , #6804 , #6817 , #6758 

Suporte completo a múltiplos workspaces. Os endpoints ACP do Daemon agora suportam escopo de workspace, workers de canal são agrupados e vinculados por workspace, split view suporta sessões entre workspaces e abas de workspace. Workspaces adicionados dinamicamente são persistidos — não é preciso reconfigurar após reiniciar o daemon. Workspaces podem ser removidos em tempo de execução, sem reiniciar o server. Veja os PRs #6621 , #6635 , #6746 , #6716 , #6745 

Novo painel de revisão Artifact à direita — arquivos editados são exibidos como cards de turno, com contagem de linhas e diff expansível por arquivo. O painel direito suporta lista de arquivos/navegação em árvore e largura ajustável por arraste. Artifact e tarefas agendadas também têm cards próprios de saída de turno, e HTML artifacts são renderizados em sandbox iframe. Veja o PR #6591 

A v0.19.11 adicionou a página de gerenciamento de extensions, permitindo visualizar e gerenciar extensions instaladas diretamente no Web Shell. Diagramas Mermaid agora suportam zoom, pan e arraste — fluxogramas e diagramas de sequência não são mais apenas estáticos. O split pane permite maximizar um painel individual, e cada pane é colorido por workspace. Os controles do Composer passaram para o formato popover, e a lista de sessões mostra as que estão aguardando ação do usuário. Veja os PRs #6815 , #6881 , #6951 , #6971 , #6877 , #6956 

Outras melhorias: tabelas Markdown com duplo clique na célula para exibir conteúdo completo em popup, facilitando a cópia; barra de ferramentas do campo de entrada exibe chip com o branch Git atual; grupos de sessão suportam códigos de cor Hex personalizados; tarefas agendadas são consolidadas de todos os workspaces em uma única visão; Composer suporta texto de placeholder personalizado; caminhos de workspace são bloqueados. Veja os PRs #6530 , #6725 , #6752 , #6759 , #6765 , #6853 

Voice Bridge: entrada de voz integrada ao ACP

Antes, ao enviar prompts de voz via ACP (Agent Communication Protocol), se o modelo principal fosse de texto puro, o áudio não podia ser processado. Agora foi adicionado o voice bridge — o áudio é primeiro transcrito para texto pelo voice model configurado e depois enviado ao modelo principal. Se o modelo principal suportar entrada de áudio nativamente, o áudio original é repassado diretamente, sem transcrição. Quando a transcrição não está disponível ou falha, o modelo principal recebe uma mensagem segura de “áudio indisponível”, sem repassar áudio bruto.

O que você pode fazer com isso:

  • Enviar comandos de voz via cliente ACP — modelos de texto puro também entendem o conteúdo da sua fala
  • Modelos principais que suportam áudio (como modelos multimodais) mantêm o áudio original direto, sem perda de informação
  • Fallback seguro quando a transcrição falha — problemas de áudio não interrompem a conversa

Veja o PR #6576 

Conversão automática de PDF para imagem: scans não travam mais o Agent

Antes, ao lidar com PDFs escaneados ou muito densos em texto, a extração que ultrapassasse o orçamento de 12.000 tokens gerava um loop de FILE_TOO_LARGE — o Agent tentava novamente com intervalos de páginas menores, mas continuava ultrapassando o limite, estourando o contexto até a sessão travar. Agora foi adicionado o fallback de renderização de página para imagem: quando a extração de texto ultrapassa o limite ou falha, as páginas são automaticamente renderizadas como JPEG via pdftoppm e enviadas ao modelo de visão. O custo de tokens por página é fixo, independente da densidade de texto. A extração de texto continua sendo o caminho padrão (permite grep e extração precisa de texto); a renderização só é acionada em caso de excesso ou falha. Para modelos principais de texto puro com modelo de visão configurado, scans anexados via @ são renderizados em poucas páginas e enviados ao vision bridge para transcrição.

O que você pode fazer com isso:

  • PDFs escaneados não geram mais FILE_TOO_LARGE — o modelo de visão lê a imagem diretamente
  • PDFs densos (acima do orçamento de tokens) são automaticamente convertidos em imagens, sem estourar o contexto
  • PDFs de texto puro continuam seguindo a extração de texto, sem perda de precisão

Veja o PR #6585 

Fluxos de CLI: atualização com um clique, conversas não se perdem mais

Antes, para atualizar o Qwen Code era preciso lembrar como instalou — se foi via npm, rodar npm install; se foi standalone, baixar o pacote novamente. Esta semana foram adicionados o comando CLI qwen update e o comando slash /update, que detectam automaticamente o tipo de instalação e executam a atualização. Instalações standalone baixam a versão mais recente diretamente do npm registry, com verificação SHA256 + validação de assinatura Ed25519 (opcional) + smoke test (o binário novo precisa passar em --version) + substituição atômica, com rollback automático em caso de falha. Instalações npm exibem o comando npm install -g correspondente. Suporte a i18n em 9 idiomas. Veja o PR #5780 

Ctrl+O agora congela a visão do transcript — ao pressionar, abre uma tela alternativa com o histórico completo da conversa, todas as saídas de ferramentas expandidas, com rolagem para cima e para baixo. Esc/q/Ctrl+C/Ctrl+O fecha e volta à tela principal. A renderização de saída de ferramentas também foi reformulada: resultados de ferramentas de leitura/busca/listagem são recolhidos em um resumo de uma linha; ferramentas de mutação permanecem expandidas. A configuração compactMode anterior é silenciosamente ignorada. Veja o PR #5666 

Ctrl+S agora salva prompts temporariamente — com conteúdo no campo de entrada, pressione Ctrl+S para salvar o prompt em um arquivo temporário no nível do projeto; ao iniciar o mesmo projeto novamente, o prompt é restaurado automaticamente. Após o envio, o arquivo temporário é excluído. Placeholders de blocos grandes colados são expandidos antes de salvar, e a restauração traz o conteúdo original. Projetos diferentes não interferem entre si. Veja o PR #6709 

Timeout de comandos shell agora é configurável. Nova configuração tools.shell.defaultTimeoutMs para ajustar o timeout padrão de comandos em primeiro plano no nível do projeto ou da sessão, sem precisar especificar individualmente a cada comando. O padrão continua 120 segundos; defina como 0 para desabilitar o timeout. Veja o PR #6628 

Explore subagent agora herda o modelo principal. O subagent Explore integrado não seleciona mais automaticamente o fastModel — passa a herdar o modelo da sessão principal. Se você usa Claude Opus como modelo principal, o Explore também usa Claude Opus, sem perda na capacidade de raciocínio. Para continuar usando o modelo rápido, configure agents.builtin.exploreModel como fast ou um ID de modelo específico. Veja o PR #6807 

Alt+T expande o raciocínio completo em streaming. Durante a saída em streaming, pressione Alt+T para expandir o bloco de thinking — agora é possível ver o raciocínio completo em tempo real, não mais a prévia fixa de 4 linhas do final. Acompanhar a cadeia de raciocínio do modelo finalmente ficou viável. Raciocínios muito longos são limitados pela altura da viewport, sem expansão infinita. Veja o PR #6678
