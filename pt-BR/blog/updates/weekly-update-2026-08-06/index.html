Qwen Code Semanal: Qwen Code desktop lançado oficialmente, Session Workflow mostra o fluxo de execução das tarefas em um gráfico, sub-Agents com permissões sob medida

Qwen Team
2026-08-06

Esta semana o Qwen Code lançou cinco versões oficiais, da v0.21.2 à v0.21.6, com 300+ PRs integrados. E tem uma novidade grande: o Qwen Code desktop v0.1.0 saiu oficialmente.

O desktop chegou! Semana passada o Web Shell passou por uma grande atualização; esta semana ele virou um app desktop independente. O Qwen Code desktop v0.1.0 foi lançado com instaladores nativos para macOS, Windows e Linux, disponíveis direto no GitHub Releases.

Agora dá para “ver” a execução das tarefas. A nova visão Session Workflow desenha o plano e o progresso como um fluxograma: quantos passos o plano tem, qual está rodando, qual está esperando, qual subtarefa foi para qual IA — tudo numa tela só. Antes de começar, a IA mostra o gráfico para você aprovar; só roda depois do ok.

Terminal e controle de permissões também avançaram. Imagens geradas pela IA agora aparecem direto no terminal, sem precisar abrir arquivo. Sub-Agents recebem permissões por tarefa: trabalho só de leitura ganha permissão só de leitura, e combinações frequentes podem ser salvas como template. A compactação de conversas longas pode usar um modelo mais barato, deixando o custo sob controle.

✨ Novidades

Qwen Code desktop lançado oficialmente: app nativo nos três principais sistemas operacionais

Antes, a experiência desktop do Qwen Code ficava dividida em dois lugares: o app Electron e o Web Shell no navegador. Esta semana os dois se uniram: o Qwen Code desktop v0.1.0 foi lançado oficialmente, com a interface do Web Shell que recebeu a grande atualização da semana passada. Os instaladores para macOS, Windows e Linux já estão disponíveis no GitHub Releases .

Quem já usa a versão Electron no macOS não precisa migrar manualmente: a nova versão traz um assistente de migração único, e as atualizações futuras chegam automaticamente depois da troca.

O que você pode fazer com isso:

  • O Qwen Code desktop tem as mesmas capacidades da versão de terminal
  • Experiência consistente nos três sistemas operacionais
  • Verificação automática de atualizações — sem reinstalar manualmente a cada versão

Veja os PRs #8132 , #8392 , #8511 , #8518 

Session Workflow: plano, subtarefas e progresso em um único gráfico

Quando uma tarefa complexa está rodando, saber em que passo o plano está e o que cada subtarefa faz era coisa de garimpar o histórico da conversa.

A nova visão Session Workflow desenha tudo isso como um fluxograma: cada passo do plano é um bloco, as linhas mostram a ordem, e dá para ver em tempo real o que está rodando e o que travou. As subtarefas delegadas pela IA também ficam no gráfico — clique para ver o que cada uma fez. Antes de começar, a IA mostra o fluxograma para você; ela só inicia com a sua aprovação, e se você não aprovar ela volta a replanejar. Depois que a tarefa termina, dá para reabrir o gráfico e revisar: cada passo registra quem fez e o que foi feito.

A funcionalidade vem desativada por padrão: para ligar, defina experimental.sessionWorkflow como true no settings. Ligada, ela traz duas conveniências: quando uma subtarefa precisa de confirmação — rodar um comando, alterar um arquivo —, o pedido aparece direto na interface principal, sem precisar entrar na subtarefa para achar; e tarefas muito longas podem ir para segundo plano enquanto a conversa principal segue com outra coisa, com notificação ao terminar.

O que você pode fazer com isso:

  • Acompanhe o progresso de tarefas complexas em um relance — o gráfico mostra onde travou
  • Confirme o plano antes da execução e trabalhe com mais segurança
  • Mande tarefas longas para segundo plano e continue a conversa principal

Veja os PRs #7580 , #8391 , #8240 , #8303 

display_image: imagens geradas pela IA direto no terminal

Antes, quando a IA gerava uma imagem, ela entregava um caminho de arquivo e você abria por conta própria. Agora a imagem aparece direto no terminal, assim que é gerada. A capa desta edição do relatório semanal foi escolhida assim: a IA gerou algumas candidatas, exibiu todas no terminal e deu para comparar e escolher na hora, sem abrir arquivo por arquivo. Se o seu terminal não suportar imagens, ela avisa.

O que você pode fazer com isso:

  • Imagens geradas pela IA aparecem na hora, sem abrir arquivo
  • Gráficos desenhados a partir de dados e screenshots de páginas montadas também aparecem direto
  • Peça para a IA exibir designs e screenshots que já estão no repositório para ver junto

Veja o PR #8217 

Permissões de sub-Agents: chaves sob medida por tarefa, sem interferência entre trabalhos paralelos

Quando você dá uma tarefa grande ao Qwen Code, ele às vezes escala alguns “assistentes” (sub-Agents) para trabalhar em paralelo — um lendo código, outro rodando testes. Antes, cada um deles tinha o mesmo conjunto completo de capacidades do principal: ler arquivo, alterar arquivo, executar comando, tudo. Você queria só “ler o código e escrever um resumo”, mas ele podia muito bem alterar um arquivo no caminho. Inseguro.

Agora dá para configurar permissões por tarefa:

  • Chaves por tarefa: ao delegar, você pode limitar quais ferramentas o sub-Agent usa — basta uma frase, tipo “esse trabalho é só de leitura”, e a restrição vai junto; qualquer tentativa de alterar algo é bloqueada na hora
  • Templates de permissão: combinações frequentes ficam salvas como templates no diretório .qwen/fork-profiles/ do projeto; na próxima vez, um parâmetro reutiliza — sem reconfigurar
  • Instruções privadas: corrigimos uma falha — antes, sub-Agents em paralelo conseguiam ver as instruções uns dos outros; agora cada um vê só as suas e foca no próprio trabalho

O que você pode fazer com isso:

  • Tarefa só de leitura ganha permissão só de leitura — chega de alterações acidentais
  • Salve combinações frequentes como templates e reutilize com uma linha
  • Sub-Agents em paralelo trabalham isolados, sem interferência

Veja os PRs #8066 , #8148 , #8344 

Custo de compactação: agora dá para compactar com um modelo mais barato

Quando uma conversa longa dispara a compactação automática, antes só o modelo principal processava o contexto inteiro — caro e lento.

Esta semana vieram três melhorias. Primeira: /model --compaction permite especificar um modelo dedicado para a compactação — um modelo mais barato resume a conversa longa enquanto a conversa principal continua com o modelo bom, sem perder qualidade. Segunda: ao compactar com o modelo principal, o conteúdo já em cache é reaproveitado, a resposta sai mais rápida e históricos com imagens também são suportados. Terceira: com modelos da família Claude, dá para definir generationConfig.cacheRetention como "1h" — o cache fica retido por 1 hora em vez dos 5 minutos padrão, e sessões espaçadas param de desperdiçar cache a cada vez.

O que você pode fazer com isso:

  • Delegue a compactação a um modelo mais barato e economize em conversas longas
  • A compactação com o modelo principal reaproveita cache e responde mais rápido
  • Sessões espaçadas não pagam mais o preço de cache expirado toda vez

Veja os PRs #7818 , #8339 , #8419 , #8048 

Ecossistema de Channels: GitLab, cards interativos no DingTalk e gerenciamento de pareamento

Semana passada o GitHub Channel chegou; esta semana o ecossistema continua crescendo.

GitLab chegou. Todos do GitLab e comentários com @ para o bot viram mensagens recebidas. Dá para configurar quais ações a IA processa, e o que já foi processado não é processado de novo. Veja o PR #7862 

O DingTalk ganhou cards interativos. O Channel do DingTalk agora suporta cards interativos: o status da IA atualiza em tempo real no card, e quando precisa de algo de você aparece uma pergunta estruturada — nada de caçar resposta em textão. Outras plataformas não são afetadas. Veja o PR #6930 

A lista de quem pode acionar a IA agora pode ser vista e revogada. Ao conectar plataformas de chat, dá para ativar o modo de pareamento por segurança: quando um desconhecido menciona o bot com @ pela primeira vez, precisa da sua aprovação para usar. Antes, depois de aprovar não havia onde ver a lista nem como revogar — aprovou a pessoa errada, ou alguém saiu do time, e a pessoa continuava usando a sua IA. Agora o editor de Channels mostra quem foi aprovado e permite revogar pessoas individualmente, com listas separadas por workspace. Veja os PRs #8045 , #8081 

Chega de editar configuração na mão para GitHub/GitLab Channel. Antes, conectar a IA ao GitHub/GitLab exigia abrir o settings.json e escrever na mão: credenciais, escopos, quem pode usar — um caractere errado e nada funcionava. Agora o Web Shell tem uma interface de gerenciamento dedicada: tudo é preenchido em formulários e selecionado na tela; salvou, valendo, sem tocar em arquivo de configuração. Veja o PR #8310 

Ajustes finos no GitHub Channel. Se você já está logado no gh localmente, o GitHub Channel reaproveita esse login — sem criar outro token. As respostas também ficaram mais contidas: cada evento gera no máximo um comentário final; enquanto a IA processa, o comentário original recebe uma reação 👀 temporária, removida automaticamente no fim. Tarefas interrompidas podem ser retomadas após reinício. Veja os PRs #8461 , #8033 , #8061 , #8306 

📊 Mais funcionalidades

Auto Recall: recuperação automática de contexto. A recuperação de corpus externo da semana passada era “a IA consulta quando precisa”; o Auto Recall desta semana é “consulta automática a cada pergunta”: os resultados vão junto como referência para a IA, com filtragem automática de informações sensíveis comuns. É exclusivo com o modo sob demanda e é implantado pelo administrador. Veja o PR #7877 

Threshold de pré-carregamento de ferramentas. Nova configuração tools.toolSearch.threshold: quando há poucas ferramentas, todas são declaradas já no início da sessão, sem busca sob demanda no meio do caminho — resposta mais rápida. Defina 0 para voltar ao comportamento anterior. Veja o PR #7922 

/autofix agora suporta o workspace local. Antes o /autofix só rodava no GitHub Actions; agora ele roda direto e revisa e corrige alterações locais: encontra problemas, aplica correções mínimas, roda verificações e revisa de novo, até ficar limpo ou confirmar que não dá para corrigir. Antes de rodar, ele explica que as verificações acontecem em sandbox e pede que você confirme que confia no repositório. Veja o PR #8121 

Visão estruturada de resultados de review no Web Shell. Depois que o /review termina, os resultados ganham uma visão dedicada no Web Shell: quantos problemas, onde, como corrigir e qual é a evidência, tudo visível de relance — dá para filtrar por severidade e abrir o relatório completo. Veja o PR #8402 

Reasoning effort do Qwen 3.8 funcionando. Com modelos da família qwen3.8-max, os cinco níveis do /effort agora controlam de verdade a profundidade de raciocínio do modelo — não só um nível. Veja o PR #8472 

Goal v3 integrado ao CLI. O comando /goal e o modo interativo agora usam o mesmo runtime: cards de status e comandos de ciclo de vida alinhados nos dois lados, experiência consistente. Veja os PRs #8005 , #8324 

Ocultação de skills por nível. Nova configuração skills.disabledLevels: permite ocultar níveis inteiros de skills pela origem — útil quando há skills demais na lista. Veja o PR #8057 

Ciclo de vida de skills geradas automaticamente. Skills geradas automaticamente pelo /learn e afins agora têm rastreamento de uso: 30 dias sem uso, marcadas como expiradas; 90 dias, arquivadas automaticamente. Chega de acúmulo infinito. Veja o PR #7846 

memory.agentMaxTurns. Configuração unificada do limite de turnos do Agent de memória; 0 significa sem limite. Veja o PR #8171 

/summary com caminho personalizado. O /summary agora aceita um parâmetro de caminho para salvar o resumo do projeto onde você quiser — o diretório pai é criado automaticamente. Veja o PR #8116 

Capacidade e status do daemon. O limite de sessões por workspace subiu de 20 para 32 — mais difícil bater no teto com várias sessões em paralelo. O /daemon/status mostra o uso de memória para você saber quanto falta até o limite, e o limite de sub-sessões concorrentes também é configurável. Veja os PRs #8235 , #8245 , #8341 

Extensão do Chrome em alpha. A versão alpha da extensão do Chrome ganhou fluxo de onboarding, diagnóstico de runtime e aceitação automatizada em ambiente Chrome real. Veja o PR #6739 

👏 Melhorias de experiência

Status durante o streaming. Enquanto o modelo ainda está gerando, comandos somente leitura como /status, /settings e /help agora executam na hora, sem esperar o turno terminar. No Web Shell, /stats, /about e /context também rodam imediatamente no meio do turno — antes esses comandos eram engolidos em silêncio. Veja os PRs #8130 , #8496 

Saídas longas de ferramentas não são mais cortadas. Saídas de comandos e conteúdos longos de raciocínio eram truncados na marra acima de 500 caracteres. Agora viram uma visão completa recolhida por padrão e expansível — e o texto completo também aparece em sessões exportadas. Veja o PR #8251 

Turnos ficam expandidos enquanto Agents em segundo plano rodam. Antes, assim que a IA principal ficava ociosa, o Web Shell marcava o turno como concluído e recolhia — mesmo com sub-Agents ainda rodando em segundo plano, e as atualizações apareciam depois, com o status pulando de um lado para o outro. Agora, enquanto houver sub-Agents ativos, o turno fica expandido. Veja o PR #8413 

Blocos de Thinking sem oscilação, transcript agora inline. A altura dos blocos de raciocínio em streaming ficou estável, sem mais saltos. A sobreposição de registro em tela cheia foi substituída por um atalho inline com Ctrl+O. Veja o PR #8077 

Novos atalhos. Colar imagens da área de transferência no macOS agora tem o Option+V. Alternar categorias no autocompletar com @ ganhou Ctrl+Tab / Ctrl+Shift+Tab, evitando conflito com atalhos do próprio terminal. Veja os PRs #8120 , #8074 

Busca mais rápida e mais estável. A busca de arquivos está mais rápida. Quando a busca falha, ela tenta de novo automaticamente — sem mais falso negativo de “não há resultados” quando a busca não tinha terminado. Veja os PRs #8253 , #7888 

Detalhes de tabelas e diálogos. Fechar o diálogo de célula nas tabelas Markdown estendidas não faz mais a página pular. Eventos de scroll no momento em que um diálogo abre não rolam o fundo por engano. Veja os PRs #8407 , #8089 

Ctrl+Shift+C volta a copiar. Antes o Ctrl+Shift+C disparava sair ou limpar a tela; agora ele volta à função de sempre: copiar no terminal. Veja o PR #8011 

Menu de detalhes da sessão. O menu de detalhes da sessão não estoura mais em layouts estreitos, e ganhou uma ação de “copiar ID completo da sessão” acessível pelo teclado. Veja o PR #8127
