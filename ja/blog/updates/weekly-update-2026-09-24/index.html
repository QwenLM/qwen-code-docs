ブログ機能アップデート09-24 製品アップデート

Qwen Code 週報：コンテキストの消費元がファイルまで分かる、別のマシンのプロジェクトも編集できる、中断したワークフローは続きから

Qwen Team
2026-09-24

Qwen Code は今週、v0.24.1 ～ v0.24.4 の 4 つの安定版をリリースし、200 件の PR がマージされました。

コンテキストが満杯でも、どのファイル・どの拡張機能が食ったか分かります。 何を閉じればいいか分かり、空きが戻る。

SSH アドレス 1 行で、別のマシンのプロジェクトを編集できます。 コードがサーバーやビルド機、同僚のマシンにあっても、自分の席から向こうのファイルを書き換え、向こうのビルドを走らせられる。

ワークフローが途中で途切れても、再起動後に続きから走ります。 完了済みの部分はそのまま流用。数時間かかる長いフローでも、失敗した箇所だけ埋め合わせれば済みます。

✨ 新機能

コンテキストが満杯でも、どのファイル・どの拡張機能が食ったか分かる

/context はコンテキストを由来別に分解して並べます——システムプロンプト、内蔵ツール、MCP ツール、メモリファイル、スキル、拡張機能が抱えるファイル。今週はここに「起動時コンテキスト」とキャッシュプレフィックスの 2 行を増やしました。/context detail を掘ると個々のファイルまで見え、拡張機能が持ち込んだものは Extension: 拡張名 · ファイル名 と表記され、それぞれどれだけの容量を食っているかも分かります。ターミナルと Web Shell で表示は同期しています。

多すぎると一言お知らせします。 常駐コンテキスト（QWEN.md と自動メモリ）の合計が「ウィンドウの 15%」と「1 万 Token」のうち小さいほうを超えると、読み込み時に知らせてくれます。

拡張機能のルールは、該当ファイルに触れたときだけ効かせることもできます。 アクセスしたファイルにヒットしたときだけコンテキストを注入し、普段は場所を取りません。

こんなことに使えます：

  • コンテキストが埋まりかけたら、まずどのファイル・どの拡張機能が食っているか見極める
  • 拡張機能を入れたらコンテキストが一気に増えたとき、/context detail でどれか特定する
  • 超過の案内を受けたら、QWEN.md を絞るのか自動メモリを切るのかを判断できる

詳しくは PR #12119 、#12318 、#12034 

SSH アドレス 1 行で、別のマシンのプロジェクトを直接編集

プロジェクトがサーバーやビルド機、同僚のマシンに置いてあって、そこを Qwen Code に触らせたい。以前は向こうのマシンに Qwen Code を入れてサービスを起動し、そのうえでアドレスを打ち込む必要がありました。今は Web Shell でワークスペースを追加するとき、ディレクトリパスに SSH アドレスを 1 行書くだけです：

ssh://user@host/absolute/project

向こうのマシンに Qwen Code が未導入なら、このアドレスを入力して登録します。すでに Qwen Code サービスが動いているマシンなら、アドレスとトークンを 1 回保存しておけば、以後はワークスペース追加時にそれを選ぶだけ。登録してしまえば、向こうのファイルの読み書き、向こうでのコマンド実行、向こうの Git 状態の確認まで、すべて手元の 1 本の会話の中で完結します。追加したてのワークスペースは閲覧のみで、「信頼」を承認してから編集できるようになります。

こんなことに使えます：

  • コードも依存関係もビルド機にある。手元の会話から向こうのファイルを書き換え、向こうのビルドを走らせる
  • 人のマシンにある既存の環境を借りて一度検証する
  • ローカルとリモートのプロジェクトを同時にぶら下げ、1 本の会話を行き来しながら編集する

詳しくは PR #12255 、#12085 、#12412 

ワークフローが途中で途切れても、再起動後に続きから走れる

フローが途中まで進んだところで仕事を終えたい、あるいはマシンの再起動で途切れた——そんなとき、以前は最初からやり直すしかありませんでした。今は実行のたびに記録が残るので、次回はその続きから走れます。

再起動後は向こうから教えてくれます。 Qwen Code を開くと、起動時の案内に「どの実行が途切れたか、何ステップ目で止まったか、サブ Agent がいくつ完了していたか」が並び、/workflows へ誘導します。これらの実行は履歴リストにも残っています。

Web Shell の履歴実行カードにボタンが付きました。 「失敗した経路のみ再実行」は成功しなかった部分だけをやり直し、「すべて再実行」は最初からやり直します。

こんなことに使えます：

  • 途中まで走らせて終了。翌朝まず、どこで止まったかを確認できる
  • サブ Agent の 2 つだけ失敗した長いフローは、「失敗した経路のみ再実行」でその 2 箇所だけ埋め合わせる
  • 同じフローをもう一度最初から検証し直したいときは「すべて再実行」を押す

詳しくは PR #12159 、#12291 、#12097 

Web Shell：複数のアップデート

ファイルを承認する前に、変更を開いて見せます。 確認が必要なファイル変更は、承認カードに「今回どの行を足し、どこを消したか」を直接並べます。既存ファイルの編集、新規ファイルの作成、notebook の変更の 3 種に対応。詳しくは PR #12443 

長いログを貼るとカードに折りたたまれます。 貼り付けた内容が 200 行または 8000 文字を超えると自動で折りたたまれ、タイトルは冒頭の一部を採用。「入力欄に表示」を押すと入力欄に戻せます。/ や ! で始まる貼り付け、短い貼り付け、選択範囲を置き換える内容は折りたたまれません。詳しくは PR #12084 

右側パネルに Trajectory タブを追加できます。 1 ラウンド走らせて遅い・高いと感じたら、開けば時間がどこへ消えたか分かります——各ラウンドの所要時間、最初の文字が出るまでの待ち時間、食った Token 量、最も時間を食ったツール呼び出し。入口は右側の拡張エリアの「タブを追加」から Trajectory を選びます。詳しくは PR #12388 

Git の履歴が見つけやすくなりました。 Web Shell のコミット履歴はブランチのツリー図で表示し、全ブランチの切り替え、コミットメッセージ・作者・ハッシュでの検索も可能です。リモートリポジトリのアドレスも画面から追加・削除でき、ターミナルを開いてコマンドを打つ必要がありません。入口はいずれも入力欄の上にあるブランチタブです。詳しくは PR #12152 、#11163 

その他の改善。 計画モードのスイッチは入力欄のツールバーから「+」メニューに収納し、オンのあいだは入力欄の上に閉じられるタブを残します（#12218 ）。/export で書き出したファイルは、会話の中でプレビュー・ダウンロードできるカードになります（#12050 ）。

📊 その他の新機能

Web Shell を PC の独立アプリとしてインストールできます。 アドレスバーの右にインストールの入口が出て、押すと専用のアイコンと別ウィンドウが与えられ、ストアで入れたアプリのように使えます。条件は Chrome / Edge 111 以上、Firefox 128 以上、Safari 16.4 以上、アドレスがローカル（127.0.0.1 または localhost）か HTTPS であること。LAN の IP でアクセスしている場合はインストールできません。詳しくは PR #11722 

デスクトップ版でウィンドウ内の文字サイズを変えられます。 Cmd / Ctrl に - / = / 0 を添えるか、トラックパッドを 2 本指でつまむ。50% ～ 300% の範囲で自在で、次回開いても前回調整した比率のままです。詳しくは PR #12410 

Goal の枠が入力欄の上に表示されます。 あのステータス行は従来の Token 予算に加えて、ターン数と時間の上限も示すようになりました。たとえば 3 / 20 turns、12m 3s / 30m 0s のように。上限を設定していない Goal は従来どおりです。/export で書き出すセッション記録にも Goal の全工程が載ります。詳しくは PR #12201 、#12099 

Goal が「完了」と言っても、会話中の実際の経過で判定します。 /goal で目標を掲げて数ターン走らせるとき、本人が「終わった」と言うだけでは認められません。受け入れチェックが直近の会話で何が起きたかを見返し、合わなければ未完成と判定します。詳しくは PR #12105 

派遣するサブ Agent をコンテナの中で動かせるようにしました。 リポジトリ全体をスキャンさせたり大量のコマンドを走らせたりしても、home ディレクトリで SSH key や認証情報を探される心配はありません。実行するコマンドも読み書きも、すべて Docker か Podman のコンテナ内に閉じ込められ、変更できるのはワークスペースだけになります。この動かし方をするには起動前に QWEN_AGENT_EXECUTION_BACKEND=docker を設定します。代償としてワークフロー、Agent Team、MCP、LSP、スキルはまとめて停止し、Windows はまだ未対応です。詳しくは PR #11711 

1 つのプロバイダーの下で 2 種類のインターフェースを混ぜて置けます。 あるモデルだけ OpenAI の Responses プロトコルに通したいなら、そのモデルの項目に "wireApi": "responses" を 1 行足すだけ。残りのモデルは従来どおり Chat を通ります。/auth でカスタムプロバイダーを設定するときも、「API 形式を選択」というステップを選べます。詳しくは PR #11538 

👏 体験改善

スマホで Web Shell を使うのが滑らかになりました。 サービスを対外アドレスにバインドすると、Web Shell のセッションページの右上にもペアリングコードが出るようになり、スマホで読み込めば現在のセッションに入れます。トークンを手入力する必要はありません。スマホ側の画面も入力欄を作り直し、十数個のアクションを「メッセージに追加」のドロワーに収納しました。詳しくは PR #12322 、#12252 

入力欄まわりがすっきりしました。 セッションがまだ張られていないとき、ワークスペースの選択と Git ブランチのタブは入力欄のツールバーから下の独立した行へ移動。セッション開始後は、ワークスペースは上部にフォルダのアイコン 1 つだけ表示し、マウスを乗せると完全なパスが見えます。会話内のリンク系の成果物カードは、そのまま新しいページを開く方式に変わりました。詳しくは PR #12299 、#12317 

圧縮結果が読みやすい文章になりました。 /compress のあと「コンテキストを圧縮しました X → Y」と表示し、圧縮するものがないときは「圧縮は不要です。」と返します。セッションを開き直した後、コンテキストのリングに表示される数字も最新になります。詳しくは PR #12141 

主でないワークスペースでも Channel の自動接続が効きます。 1 つの qwen serve に複数のワークスペースをぶら下げ、それぞれ別の Channel ボットを繋いでいる場合、サービスの起動時に信頼済みワークスペースそれぞれの Channel を復元します。「Qwen Code 起動時に自動接続」のスイッチを押して保存すれば、本当に効くようになりました。詳しくは PR #12385 

Linux のサンドボックスはツール実行だけを閉じ込める方式に変更。 前回まで Qwen Code 全体を bwrap に入れる設定は、この版では直接エラーとなり、移行の案内が 1 行出ます。tools.executionSandbox に切り替えると、制約を受けるのはコマンドラインやファイル読み書きといったツール実行だけ。Qwen Code 本体・モデルへのリクエスト・ログイン状態はローカルに残ります。詳しくは PR #12267 

スクリプトからの 1 回きりの呼び出しが速くなりました。 qwen -p のように 1 文走らせて終わる使い方で、実測 7.7 秒 → 5.1 秒、メモリ 640 MiB → 421 MiB に短縮。プロセスを 1 つ減らしました。詳しくは PR #12340 

ターミナルにペアリングコードが出ないとき、理由を添えます。 対外アドレスにバインドしてスマホで読み込ませようとしたとき、ターミナルにコードが出なければ理由を説明し、代わりにアドレスだけを載せたコードを出します。読み込めばスマホで 1 回トークンを入力するだけで接続できます。トークン入りのコードを無理に出したい場合は qwen serve --token-qr を使ってください。詳しくは PR #12266
