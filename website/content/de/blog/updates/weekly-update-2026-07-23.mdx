Qwen Code hat diese Woche drei stabile Versionen (v0.19.12, v0.20.0 und v0.20.1) mit über 220 gemergten PRs veröffentlicht.

**Agent auf Abwegen? Einfach tippen und korrigieren.** Während das Modell ausgibt, leitet Enter die Nachricht an der nächsten Sampling-Grenze in die aktuelle Runde ein; Strg+Q verschiebt sie auf die nächste Runde. Nachrichten während der Tool-Ausführung werden ebenfalls verarbeitet. Kein Warten mehr, bis der Agent fertig ist.

**Parallele Aufgaben kommen sich nicht mehr in die Quere.** Die Web Shell unterstützt das Erstellen von Worktree-isolierten Sitzungen mit einem Klick — mehrere Aufgaben im selben Repository laufen jeweils in einem eigenen Git Worktree, ohne dass sich Dateiänderungen, `git add` oder `git checkout` gegenseitig stören. Das violette ⑂-Symbol zieht sich durch Git-Chip, Sitzungsliste und Workspace-Dropdown.

**Websuche ist zurück.** Das integrierte `web_search`-Tool basiert auf der Bailian Responses API — dein vorhandener Bailian-API-Key reicht aus. Nach der Entfernung wurde die Community nicht müde, die Rückkehr zu fordern. Diesmal mit serverseitiger Suche + Seitenlesen neu implementiert, mit automatischen Sources-Links am Ende der Antwort. Standardmäßig deaktiviert, muss explizit aktiviert werden.

**`web_fetch` komplett neu aufgebaut.** Bisher gingen beim Abrufen von Webseiten Links verloren, PDFs wurden zu Zeichensalat, und bei großen Seiten wurde die Antwort nach dem Abschneiden unbrauchbar. Jetzt wird HTML zuerst in Markdown konvertiert und dann abgeschnitten, PDF-Text inline extrahiert, Binärdateien korrekt gespeichert — dazu 60-Sekunden-Timeout und 10-MB-Limit als Schutz.

## ✨ Neue Features

### Echtzeit-Steering: Agent-Kurskorrektur während der Ausgabe

Bisher musste man warten, bis der Agent fertig war, wenn man während der Ausgabe etwas tippen wollte — die Nachricht wurde zu einem neuen Prompt in der nächsten Runde. Wenn der Agent in die falsche Richtung lief, konnte man nur zusehen und danach korrigieren.

Jetzt haben Enter und Strg+Q klare Aufgaben:

- **Enter**: Die Nachricht wird in die Steering-Warteschlange eingereiht und an der nächsten Modell-Sampling-Grenze wirksam — noch innerhalb der aktuellen Runde. Der Agent schreibt gerade Code, du tippst „In TypeScript umschreiben" — er erhält die Anweisung am nächsten Sampling-Punkt.
- **Strg+Q**: Die Nachricht wird auf das Ende der aktuellen Runde verschoben und beginnt eine neue Konversationsrunde.
- **Während der Tool-Ausführung**: Eingegebene Nachrichten werden nach Rückgabe des Tool-Ergebnisses innerhalb derselben Runde verarbeitet.
- **Rückgängig machen?** Up oder Escape stellt die wartende Nachricht im Eingabefeld wieder her.

@-Anhänge bleiben ebenfalls erhalten und erhalten kein synthetisches Präfix. Bei fehlgeschlagener Zustellung oder Abbruch geht keine Nachricht verloren.

Was du damit machen kannst:

- Agent schreibt Code in die falsche Richtung — tippen und korrigieren, ohne auf das Ende zu warten
- Während ein Tool läuft, zusätzlichen Kontext liefern
- Nächste Frage schon parat — Strg+Q reiht sie ein, sie wird automatisch nach Ende der aktuellen Runde gesendet

### Worktree-Isolation: Parallele Aufgaben ohne Konflikte

Zwei Aufgaben gleichzeitig im selben Repository — eine Sitzung ändert Dateien, und der `git status` der anderen ist durcheinander. Bisher musste man manuell `git worktree add` + `cd` ausführen, jetzt geht das in der Web Shell mit einem Klick.

Im Workspace-Branch-Pill-Dropdown auf „New Worktree Task" klicken — der Daemon erstellt automatisch einen Git Worktree unter `<repoRoot>/.qwen/worktrees/<slug>` und wechselt das Arbeitsverzeichnis der Sitzung dorthin. Die gesamte Oberfläche nutzt das violette ⑂-Symbol zur Unterscheidung: Git-Chip wird violett, Sitzungsliste zeigt ⑂, Workspace-Dropdown enthält eine Beschreibung. Bei Nicht-Git-Repositories wird diese Option nicht angezeigt.

Worktree-Informationen werden in einer Sidecar-Datei persistiert und überleben Daemon-Neustarts. Beim Wiederherstellen einer Sitzung wird die Worktree-Isolation automatisch wiederhergestellt, die Statusleiste zeigt den Worktree-Branch-Namen statt des Haupt-Workspace-Branches.

Was du damit machen kannst:

- Zwei Feature-Entwicklungen gleichzeitig laufen lassen, ohne gegenseitige Störung
- Bug fixen und parallel am Feature weiterarbeiten, ohne ständig zu stashen
- Den Agent experimentelle Änderungen in einer isolierten Umgebung machen lassen, während der Hauptarbeitsbereich sauber bleibt

### Integriertes web_search: Websuche mit Bailian-Key

Bisher hatte Qwen Code keine integrierte Suche — die Dokumentation verwies auf die Konfiguration des Bailian WebSearch MCP. In der Praxis lieferte dieser MCP bei komplexen Anfragen schlechte Qualität — eine Medicare-Gebührenabfrage mit eindeutiger Standardantwort ergab über mehrere MCP-Läufe 0/5 relevante Ergebnisse.

Diese Woche ist das integrierte `web_search`-Tool zurück. Es basiert auf der serverseitigen Suche der Bailian Responses API — dein bereits konfigurierter Bailian-API-Key reicht, kein zusätzlicher MCP-Dienst, kein zusätzlicher Provider, kein zusätzlicher Key nötig. Der Such-Agent öffnet die Ergebnisseiten für fundiertere Antworten, unterscheidet zwischen „tatsächlich gelesenen Seiten" und „nicht geöffneten Kandidatenlinks", und das Modell muss am Ende der Antwort einen Sources-Abschnitt anhängen.

**Standardmäßig deaktiviert** — zwei Konfigurationen sind zur Aktivierung nötig: `tools.webSearch.enabled: true` und das Suchmodell `tools.webSearch.model`. Wenn konfiguriert aber nicht korrekt, bleibt das Tool deaktiviert und beim Start wird angezeigt, welche Bedingung nicht erfüllt ist. Auch reine Umgebungsvariablen-Konfiguration wird unterstützt (`ENABLE_WEB_SEARCH`, `WEB_SEARCH_MODEL` etc.) — praktisch für Umgebungen ohne settings.json. Jede Suchanfrage erfordert eine Bestätigung (zeigt den Suchbegriff, optional „Immer erlauben").

Was du damit machen kannst:

- Zeitkritische Informationen abrufen: neueste Versionsänderungen von Bibliotheken, API-Dokumentationsupdates, Sicherheitshinweise
- Probleme nach dem Wissensstichtag des Modells untersuchen: Breaking Changes in neuen Versionen, aktuelle Bug Reports
- Den manuellen Workflow „Terminal verlassen → Browser öffnen → suchen" ersetzen

### web_fetch komplett neu aufgebaut: Keine PDF-Zeichensalate mehr, keine verlorenen Links

Bisher hatte `web_fetch` mehrere praxisrelevante Probleme: Große Listenseiten wurden vor der Konvertierung am rohen HTML abgeschnitten — Antworten wurden gekappt, alle Link-URLs gingen verloren, und das Modell behauptete selbstsicher „Ziel existiert nicht". PDFs wurden als Text dekodiert und zu zehntausenden Token Zeichensalat. Manche Regierungsseiten lieferten bei anonymem User-Agent ein 403.

Diese Woche wurde die gesamte Pipeline neu aufgebaut:

- **HTML wird zuerst in Markdown konvertiert, dann abgeschnitten** — Inhalte tief in großen Seiten bleiben erhalten, alle Hyperlinks behalten ihre URL. Das Abschneiden wird explizit markiert, Skripte und Styles verbrauchen kein Kontingent.
- **PDF-Text wird inline extrahiert** — ein einziger `web_fetch`-Aufruf beantwortet Fragen zum PDF-Inhalt. Binärdateien werden über Magic Bytes erkannt (nicht nur Content-Type) und mit der korrekten Erweiterung gespeichert.
- **60-Sekunden-Timeout + 10-MB-Limit** — Esc bricht die Übertragung sofort ab (bisher konnte die UI einfrieren). Wiederholtes Abrufen derselben URL innerhalb von 15 Minuten nutzt den Cache.
- **Cross-Host-Redirects werden nicht mehr stillschweigend gefolgt** — stattdessen wirst du aufgefordert, die Anfrage erneut zu stellen, mit normalem Berechtigungsablauf.
- **Berechtigungsmodell**: Erster Zugriff auf jeden Host erfordert Bestätigung (GET gibt den vollständigen Pfad und Query preis — ein potenzieller Datenexfiltrationskanal). Nach Genehmigung wird die Regel pro Host persistiert. GitHub-Blob-URLs werden automatisch in Raw-Adressen normalisiert, bevor die Berechtigung geprüft wird.

Was du damit machen kannst:

- PDF-Link abrufen und direkt den Inhalt beantworten lassen
- Lange Listenseite abrufen und nach Einträgen tief in der Seite fragen — Links gehen nicht mehr verloren
- Cross-Host-Redirects fordern zur erneuten Anfrage auf, statt stillschweigend zu einer fremden Domain zu folgen

Siehe PR [#7146](https://github.com/QwenLM/qwen-code/pull/7146)

### Web Shell: Großes Update diese Woche

Die Web Shell erhielt diese Woche umfangreiche Änderungen — von Git-Integration über Sitzungsverwaltung bis zur Workspace-Erfahrung. Hier die Zusammenfassung.

**Git-Integration im Dreierpack.** `/log` öffnet einen Commit-Verlaufs-Browser — ein grafisches Popup zeigt die Commit-Liste, Klick zeigt vollständige Message und Dateiänderungsstatistiken, SHA mit einem Klick kopieren, mit Seitenladung. Das `/diff`-Popup erhielt ebenfalls einen History-Tab, kein Befehlswechsel nötig. Der Git-Status-Chip wird in der Composer-Symbolleiste angezeigt, die Seitenleiste zeigt den Git-Status des Arbeitsbereichs, und das Changes-Popup zeigt einen visuellen Working-Tree-Diff. Siehe PRs [#7204](https://github.com/QwenLM/qwen-code/pull/7204), [#7054](https://github.com/QwenLM/qwen-code/pull/7054)

**Skill-Verwaltungsseite und Goals-Seite.** Die Web Shell hat jetzt eine eigene Skill-Verwaltungsseite — Workspace-Skills ansehen und verwalten, ohne zum Terminal zurückzukehren. Die Goals-Seite visualisiert `/goal`-Ziele in der Web Shell, Ziele überleben Daemon-Neustarts. Siehe PRs [#7018](https://github.com/QwenLM/qwen-code/pull/7018), [#6561](https://github.com/QwenLM/qwen-code/pull/6561)

**Sitzungsverwaltung verbessert.** Strg+B / Cmd+B schaltet die Seitenleiste um, Split-View-Layout bleibt über Aktualisierungen erhalten (pro Tab unabhängig), wiederhergestellte Sitzungsverläufe unterstützen Seitenladung statt alles auf einmal, archivierte Sitzungen können exportiert werden. Das Add-Workspace-Popup erhielt Verzeichnis-Autovervollständigung. Siehe PRs [#7135](https://github.com/QwenLM/qwen-code/pull/7135), [#7136](https://github.com/QwenLM/qwen-code/pull/7136), [#7064](https://github.com/QwenLM/qwen-code/pull/7064), [#6910](https://github.com/QwenLM/qwen-code/pull/6910), [#7125](https://github.com/QwenLM/qwen-code/pull/7125)

**Workspace-Erfahrung.** Benutzerdefinierte Workspace-Anzeigenamen — in Multi-Workspace-Szenarien nicht mehr nur Pfade. Benutzerdefinierte Slash-Befehlsaktionen, Sidebar-Anpassungs-API (Branding, Navigation, Sitzungsaktionen, Footer). Neue Themenentwürfe schlagen vor, eine neue Sitzung zu starten, statt in der alten fortzufahren. Siehe PRs [#7179](https://github.com/QwenLM/qwen-code/pull/7179), [#7267](https://github.com/QwenLM/qwen-code/pull/7267), [#7379](https://github.com/QwenLM/qwen-code/pull/7379), [#7098](https://github.com/QwenLM/qwen-code/pull/7098)

## 📊 Weitere neue Funktionen

**Artifact-Standardwerte und Schreibbestätigung.** Agent hat beim Erstellen von Artifacts eine Standardkonfiguration und fragt vor dem Schreiben nach Bestätigung — weniger versehentlich geschriebene Dateien. Siehe PR [#7068](https://github.com/QwenLM/qwen-code/pull/7068)

**Tool-Zusammenfassung zeigt aktiven Pfad.** Die kompakte Tool-Zusammenfassung zeigt den aktuell bearbeiteten Dateipfad — bei Multi-Datei-Operationen sofort erkennbar, welche Datei geändert wird. Siehe PR [#7043](https://github.com/QwenLM/qwen-code/pull/7043)

**Subagent-Delegierung: Standardwerte und Guardrails.** Verbesserte Standardkonfiguration und Sicherheitsgrenzen für die Subagent-Delegierung — vorhersehbareres Verhalten der Subagenten. Siehe PR [#7048](https://github.com/QwenLM/qwen-code/pull/7048)

**VSCode-Log-Routing.** Logs werden in einen dedizierten Qwen Code Companion Output Channel geleitet — Problemdiagnose in VSCode ohne andere Panels durchsuchen zu müssen. Siehe PR [#7121](https://github.com/QwenLM/qwen-code/pull/7121)

**Daemon-Log-Rotation.** Begrenzte Log-Rotation statt unbegrenztem Wachstum — die Festplatte wird nicht mehr von Daemon-Logs gefüllt. Siehe PR [#6969](https://github.com/QwenLM/qwen-code/pull/6969)

**WebShell Read-Only-Verlaufswiedergabe.** ChatRecord-Verlauf in einer Read-Only-WebShell wiedergeben — praktisch zum Teilen von Sitzungsverläufen mit Kollegen. Siehe PR [#6999](https://github.com/QwenLM/qwen-code/pull/6999)

**MCP-Toolnamen-Normalisierung.** MCP-Toolnamen werden für strikte Provider normalisiert — weniger fehlgeschlagene MCP-Tool-Aufrufe. Siehe PR [#6976](https://github.com/QwenLM/qwen-code/pull/6976)

**Channel-Memory-Abruf.** Jede Nachricht ruft automatisch relevante Erinnerungen ab, bestätigt natürliche Memory-Änderungen und speichert Multi-Fakten-Memories sicher — der Agent in Channel-Konversationen erinnert sich an früheren Kontext. Siehe PRs [#7157](https://github.com/QwenLM/qwen-code/pull/7157), [#7066](https://github.com/QwenLM/qwen-code/pull/7066), [#7092](https://github.com/QwenLM/qwen-code/pull/7092)

**Channel-Gruppennamen-Erkennung.** Gruppennamen werden automatisch aus eingehenden Nachrichten extrahiert — in Multi-Gruppen-Szenarien weiß der Agent, in welcher Gruppe er sich befindet. Siehe PR [#7155](https://github.com/QwenLM/qwen-code/pull/7155)

**Formatierte Pfade in Tool-Beschreibungen.** Tool-Beschreibungen von grep/glob etc. zeigen formatierte Dateipfade — Ergebnisse sind klarer und lesbarer. Siehe PR [#7050](https://github.com/QwenLM/qwen-code/pull/7050)

**`/cd` Tab-Vervollständigung verbessert.** Nach Eingabe eines Verzeichnisnamens enthält Tab auch das bereits eingegebene Verzeichnis — genauere Vervollständigung. Siehe PR [#7320](https://github.com/QwenLM/qwen-code/pull/7320)
