Qwen Code hat diese Woche drei stabile Versionen (v0.19.9, v0.19.10 und v0.19.11) mit über 160 gemergten PRs veröffentlicht.

**`/learn`-Befehl verfügbar.** Nutzer können jetzt gezielt Skills erstellen — eine Wissensquelle angeben (Verzeichnis, URL, Konversation, Text), und Qwen Code erstellt daraus automatisch eine SKILL.md zur direkten Wiederverwendung.

**Code Review: von „funktional" zu „hochwertig".** Suggestions werden direkt als PR-Inline-Kommentare gepostet, das Review enthält jetzt Korrektheitsprüfungen, Pre-Release-Validierung, einen Step-4-Verifier und Step-5-Reverse-Audit.

**Web Shell großflächig überarbeitet.** shadcn als UI-Basis, Artifact-Prüfpanel, Extension-Verwaltungsseite, Mermaid-Diagramme mit Zoom und Drag. Multi-Workspace-Unterstützung vollständig durchgängig, Split Pane farblich nach Workspace gekennzeichnet.

**Voice Bridge: Spracheingabe über ACP.** Auch reine Textmodelle können jetzt Sprach-Prompts verarbeiten — Audio wird zuerst in Text transkribiert und dann an das Modell weitergeleitet. Modelle mit Audio-Unterstützung erhalten den Originalton direkt.

**Gescannte PDFs blockieren den Agent nicht mehr.** Bei Überschreitung des Token-Limits für die Textextraktion werden die Seiten automatisch als Bilder gerendert und an das Vision-Modell übergeben.

**CLI-Workflows vervollständigt.** `/update` für Ein-Klick-Upgrades, Strg+O zum Einfrieren der Konversation, Strg+S zum Zwischenspeichern von Prompts, Explore erbt das Hauptmodell, Alt+T zeigt den vollständigen Denkprozess.

## ✨ Neue Features

### `/learn`: Wissen in wiederverwendbare Skills verwandeln

`/learn` ist ein neuer Slash-Befehl, mit dem du aus einer Wissensquelle einen wiederverwendbaren Skill erstellen kannst. Als Wissensquelle eignet sich ein lokales Verzeichnis, eine URL, der Konversationsverlauf oder ein selbst geschriebener Text. Das Hauptmodell sammelt das Wissen, fasst es automatisch in einer SKILL.md zusammen und speichert sie unter `.qwen/skills/learned-skill-<name>/` mit dem Marker `source: learned` — getrennt von manuell erstellten oder automatisch generierten Skills.

Was du damit machen kannst:

- `/learn Deploy process: ...` — den Deploy-Prozess als Skill festhalten und beim nächsten Mal direkt aufrufen
- Ein Dokumentationsverzeichnis angeben, damit Qwen Code die Projektkonventionen lernt und beim Codieren automatisch befolgt
- Wissen aus einer Konversation extrahieren und als wiederverwendbare Befehlsvorlage speichern

Siehe PR [#6440](https://github.com/QwenLM/qwen-code/pull/6440)

### Code Review: Qualitätssicherung deutlich verbessert

Das Code Review wurde diese Woche in mehreren Dimensionen aufgewertet — von Inline-Kommentaren bis zur Qualitätsprüfung der Review-Ergebnisse.

`/review` veröffentlicht jetzt **Suggestion-Ergebnisse direkt als PR-Inline-Kommentare** — kein manuelles Kopieren von Vorschlägen mehr. Das Review selbst enthält neue Finder für prozedurale Korrektheit und konfigurierbare Effort-Stufen, und vor dem Posten prüft ein Guardrail, ob jedes Finding tatsächlich zutrifft.

**Reviews großer Diffs werden nicht mehr pauschal zugewiesen — jede Diff-Zeile hat einen verantwortlichen Reviewer, was lückenlose Abdeckung sicherstellt.** Der Review-Chunk-Agent erhält vollständig aufgebaute Prompts, keine Ausführung mehr mit leerem Kontext. PR-Triage-Kommentare enthalten jetzt Konfidenzwerte, Sequenzdiagramme, Dateiüberblicke und einen Review-Footer für mehr Kontext. Die Standard-Zeitüberschreitung für automatische Reviews liegt bei 180 Minuten, mit Override bis 240 Minuten — große PRs werden nicht mehr durch Timeouts abgebrochen.

Was du damit machen kannst:

- `/review` postet automatisch Inline-Suggestion-Kommentare auf PRs, kein manuelles Einfügen nötig
- Konfigurierbare Effort-Stufen passen sich verschiedenen Review-Umfängen an
- Konfidenzwerte in der PR-Triage helfen bei der Priorisierung, welche PRs besondere Aufmerksamkeit brauchen

v0.19.11 fügt **Step-4-Verifier und Step-5-Reverse-Audit** hinzu — der Review-Prozess wird von „Problem finden → Kommentar posten" zu „Problem finden → validieren, dass das Finding zutrifft → Reverse-Audit zur Bestätigung der Vollständigkeit". Die Findings-Liste wird in den Verifier-/Reverse-Audit-Prompt eingebettet, was die Prompt-Größe reduziert. Der Build-/Test-Umfang von Agent 7 wird auf die tatsächlich im Diff betroffenen Workspaces beschränkt — große Repositories werden nicht mehr vollständig gebaut.

### Voice Bridge: Spracheingabe über ACP

Bisher konnten Sprach-Prompts über ACP (Agent Communication Protocol) nicht verarbeitet werden, wenn das Hauptmodell ein reines Textmodell war. Jetzt gibt es die Voice Bridge — Audio wird zuerst vom konfigurierten Voice-Modell in Text transkribiert und dann an das Hauptmodell weitergeleitet. Wenn das Hauptmodell selbst Audioeingaben unterstützt, wird der Originalton direkt durchgeschleust, ohne Transkription. Ist die Transkription nicht verfügbar oder schlägt fehl, erhält das Hauptmodell eine sichere „Audio nicht verfügbar"-Meldung, anstatt rohes Audio durchzureichen.

Was du damit machen kannst:

- Sprachbefehle über einen ACP-Client senden — auch reine Textmodelle verstehen deine Sprachinhalte
- Audiofähige Hauptmodelle (z. B. multimodale Modelle) behalten den Originalton, ohne Sprachinformationen zu verlieren
- Sichere Degradation bei Transkriptionsfehlern — keine Konversationsabbrüche durch Audioprobleme

Siehe PR [#6576](https://github.com/QwenLM/qwen-code/pull/6576)

### PDF-zu-Bild-Fallback: Gescannte Dokumente blockieren den Agent nicht mehr

Bei gescannten oder textintensiven PDFs führte die Textextraktion über dem Token-Budget von 12.000 zu einem `FILE_TOO_LARGE`-Fehler in einer Endlosschleife — der Agent versuchte es wiederholt mit kleineren Seitenbereichen, überschritt aber jedes Mal das Limit, bis der Kontext voll war und die Sitzung abbrach. Jetzt gibt es einen Seite-zu-Bild-Fallback: Wenn die Textextraktion das Limit überschreitet oder fehlschlägt, werden die Seiten automatisch mit `pdftoppm` als JPEG-Bilder gerendert und an das Vision-Modell übergeben. Die Token-Kosten pro Seite sind fest, unabhängig von der Textdichte. Die Textextraktion bleibt der Standardpfad (durchsuchbar, präzise Textentnahme), die Bildrenderung wird nur bei Überschreitung oder Fehler ausgelöst. Bei reinen Textmodellen mit konfiguriertem Vision-Modell werden per `@` angehängte Scans als wenige Seiten gerendert und über die Vision Bridge transkribiert.

Was du damit machen kannst:

- Gescannte PDFs lösen kein `FILE_TOO_LARGE` mehr aus — das Vision-Modell liest direkt aus den Bildern
- Textintensive PDFs (über dem Token-Budget) werden automatisch auf Bilder degradiert, ohne den Kontext zu sprengen
- Reine Text-PDFs behalten die Textextraktion, ohne Genauigkeit einzubüßen

Siehe PR [#6585](https://github.com/QwenLM/qwen-code/pull/6585)

### CLI-Workflows: Ein-Klick-Upgrade, Konversation bleibt erhalten

Bisher musste man sich merken, wie Qwen Code installiert wurde — bei npm mit `npm install`, bei Standalone-Installation durch erneutes Herunterladen. Diese Woche wurden der `qwen update`-CLI-Befehl und der `/update`-Slash-Befehl hinzugefügt, die automatisch den Installationstyp erkennen und das Upgrade ausführen. Standalone-Installationen laden die neueste Version direkt aus dem npm-Registry, mit SHA256-Prüfung + Ed25519-Signaturverifizierung (optional) + Smoke-Test (das neue Binary muss `--version` bestehen) + atomares Ersetzen mit automatischem Rollback bei Fehler. Bei npm-Installationen wird der passende `npm install -g`-Befehl angezeigt. i18n-Unterstützung für 9 Sprachen. Siehe PR [#5780](https://github.com/QwenLM/qwen-code/pull/5780)

**Strg+O: Transkript-Ansicht einfrieren** — ein Druck öffnet einen alternativen Bildschirm mit dem vollständigen Konversationsverlauf, alle Tool-Ausgaben aufgeklappt, frei scrollbar. Esc/q/Strg+C/Strg+O schließt die Ansicht. Gleichzeitig wurde die Tool-Output-Darstellung überarbeitet: Ergebnisse von Read-/Search-/List-Tools werden auf eine einzeilige Zusammenfassung reduziert, Mutation-Tools bleiben aufgeklappt. Die bisherige compactMode-Einstellung wird stillschweigend ignoriert. Siehe PR [#5666](https://github.com/QwenLM/qwen-code/pull/5666)

![](https://gw.alicdn.com/imgextra/i2/O1CN01b2Flxy1UBR05kJjrS_!!6000000002479-2-tps-3837-2160.png)

**Strg+S: Prompt zwischenspeichern** — bei Inhalt im Eingabefeld speichert Strg+S den Prompt in einer projektbezogenen Staging-Datei, beim nächsten Start aus demselben Projekt wird er automatisch wiederhergestellt. Nach dem Absenden wird die Staging-Datei automatisch gelöscht. Platzhalter aus großen Einfügungen werden vor dem Speichern aufgelöst, die Wiederherstellung liefert den Originalinhalt. Verschiedene Projekte stören sich nicht gegenseitig. Siehe PR [#6709](https://github.com/QwenLM/qwen-code/pull/6709)

**Shell-Befehl-Timeout konfigurierbar.** Neue Einstellung `tools.shell.defaultTimeoutMs` zum Anpassen des Standard-Timeouts für Vordergrundbefehle auf Projekt- oder Sitzungsebene, ohne jedes Mal den Timeout in den Befehlsparametern angeben zu müssen. Standard bleibt 120 Sekunden, auf 0 setzen deaktiviert den Timeout. Siehe PR [#6628](https://github.com/QwenLM/qwen-code/pull/6628)

**Explore-Subagent erbt jetzt das Hauptmodell.** Der integrierte Explore-Subagent wählt nicht mehr automatisch das fastModel, sondern erbt das Modell der Hauptsitzung. Wer Claude Opus als Hauptmodell nutzt, bekommt auch im Explore Claude Opus — volle Reasoning-Fähigkeit ohne Abstriche. Wer weiterhin das schnelle Modell nutzen möchte, setzt `agents.builtin.exploreModel` auf `fast` oder eine konkrete Modell-ID. Siehe PR [#6807](https://github.com/QwenLM/qwen-code/pull/6807)

**Alt+T zeigt den vollständigen Denkprozess.** Beim Streaming öffnet Alt+T den Thinking-Block und zeigt jetzt den vollständigen Reasoning-Inhalt als Live-Stream — statt der bisher hartcodierten 4-Zeilen-Vorschau. Der Denkkette des Modells endlich in Echtzeit folgen. Sehr lange Reasoning-Ausgaben werden durch die Viewport-Höhe begrenzt und nicht unbegrenzt aufgeklappt. Siehe PR [#6678](https://github.com/QwenLM/qwen-code/pull/6678)
