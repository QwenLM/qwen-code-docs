Qwen Code hat diese Woche zwei Stable-Releases ausgeliefert — v0.25.1 und v0.25.2 — mit 371 gemergten PRs.

**Agent Collaboration: Claude Code und Codex per @ ins Gespräch holen.** Die Antwort erscheint direkt in deinem aktuellen Gespräch, und laufen kann die Arbeit auch auf einem anderen Rechner.

**Mehrere Qwen Code hängen gleichzeitig an einem Browser-Tab.** In der Sidebar bildet jeder Qwen Code eine Gruppe, darunter seine aktuellen Sessions und Workspaces. Der Wechsel passiert im Tab.

**Einen bestimmten MCP-Server beim Start weglassen.** `qwen --disable-mcp-server <name>` gilt nur für diesen Start und ändert nichts an deiner Konfigurationsdatei.

## ✨ Neue Features

### Agent Collaboration: Claude Code und Codex per @ ins Gespräch holen

Eine Aufgabe, die sich aufteilen lässt: Qwen Code schreibt den Code um, ein anderes Programm macht den Review dazu. Bisher war ein @ auf einen Agent ein Abschieben — neues Thema, deine letzten Sätze hineinkopiert, dann der Sprung auf diese Seite. Die Antwort kam im Hauptgespräch nie an.

Heute antwortet er direkt in deinem aktuellen Gespräch: mit Namen, den Schritten, welche Werkzeuge er benutzt hat und wie vielen Token. Vor jedem Befehl holt er sich deine Freigabe. Der Agent muss kein Qwen Code sein — hast du Claude Code oder Codex installiert, holst du sie einfach per @ dazu. Siehe PR [#13467](https://github.com/QwenLM/qwen-code/pull/13467)

Er kann auch auf einem anderen Rechner arbeiten: Dort läuft `qwen serve`, du nimmst ihn als Helfer auf, schwere Aufgaben gehen an diese Maschine, und nach einem Neustart meldet er sich selbst zurück. Du kannst auch eine ganze Gruppe per @ ansprechen: Der Lead teilt die Arbeit auf, die Mitglieder liefern bei ihm ab. Siehe PR [#13583](https://github.com/QwenLM/qwen-code/pull/13583)

Der Unterschied zum Sub-Agent: Den schickt Qwen Code selbst los, eine kleine Aufgabe, und er berichtet nur an Qwen Code zurück. Der per @ geholte Kollege redet vor dir — er kann von einem anderen Anbieter stammen und auf einer anderen Maschine laufen.

Das ist noch experimentell und standardmäßig aus: Stell in den Einstellungen `Enable Agent Collaboration` an, dann wirkt es nach einem Neustart. Den Teamkollegen musst du vorher anlegen — auf der `Agents`-Seite links. Danach rufst du ihn in jedem Gespräch per @ beim Namen.

Was du damit machen kannst:

- Qwen Code den Code umschreiben und von einem anderen Agent den Review machen lassen — beide Linien bleiben in einem Gespräch lesbar
- Bauen und Testlauf an eine andere Maschine geben, während du hier weiterarbeitest
- Programme verschiedener Anbieter in einer Gruppe zusammenspannen, jeder übernimmt seinen Teil

![Ein Helfer namens reviewer auf der `Agents`-Seite angelegt und per @ zurück ins Gespräch geholt — die Antwort landet mit Namen und ReadFile-Schritten direkt in diesem Gespräch](https://img.alicdn.com/imgextra/i3/O1CN01nZHvJWBQd2I5qXns_!!6000000004221-1-tps-2880-1800.gif)

### Mehrere Qwen Code hängen gleichzeitig an einem Browser-Tab

Der eine hat ein Notebook, einen Build-Rechner und eine Maschine mit langen Jobs. Wieder ein anderer hat nur einen Rechner und für jedes Projekt eine eigene Qwen Code Web Shell — getrennt, damit sich nichts vermischt. Ein Browser-Tab kannte bisher genau einen davon. Wer einen anderen sehen wollte, musste den Tab komplett neu laden: einmal weißer Zwischenstand, und der halbfertige Text im Eingabefeld war weg.

Heute sind alle gespeicherten gleichzeitig verbunden. In der Sidebar bildet jeder Qwen Code eine Gruppe, darunter seine aktuellen Sessions und Workspaces; wählst du im Eingabefeld den Workspace aus, sind die Verzeichnisse nach Gruppen getrennt; der Wechsel zu einer anderen Gruppe passiert im Tab. Siehe PR [#13739](https://github.com/QwenLM/qwen-code/pull/13739), [#13677](https://github.com/QwenLM/qwen-code/pull/13677)

Damit das klappt, muss die verbundene Maschine diesen Tab ausdrücklich zulassen: Starte `qwen serve` mit `--allow-origin` und trag die Adresse ein, die du oben in der Browser-Adressleiste siehst.

Was du damit machen kannst:

- Der Build-Rechner arbeitet an einem langen Job, du siehst vom eigenen Rechner, wie weit er ist
- Mehrere Projekte auf einer Maschine, jedes für sich — ein Tab für alle
- Vom Notebook auf den Desktop-Rechner wechseln und dort weiterschicken

![Zwei Gruppen von Qwen Code untereinander in der Sidebar der Web Shell, die zweite mit 127.0.0.1:4171 und dem Status connected, darunter ihre aktuellen Sessions und Workspaces](https://img.alicdn.com/imgextra/i1/O1CN013gKPf9c85bL5qXns_!!6000000000032-0-tps-2880-1800.jpg)

### Einen bestimmten MCP-Server beim Start weglassen

Wer MCP-Server angebunden hat, kennt das: Einer macht heute Ärger — Werkzeuge liefern Fehler oder der Start zieht sich — und du willst ihn einfach diesmal weglassen. Bisher gab es nur das pauschale Abschalten: alle Server aus den Einstellungen mitsamt der lokalen Konfiguration.

Heute benennst du ihn beim Start:

```text
qwen --disable-mcp-server github
```

Mehrere auf einmal: Flag einfach wiederholen oder als `--disable-mcp-server github,postgres` schreiben. Es gilt nur für diesen Start, deine Konfigurationsdatei bleibt unangetastet. Siehe PR [#14003](https://github.com/QwenLM/qwen-code/pull/14003)

Was du damit machen kannst:

- Im Verdacht, dass ein Server die Störung verursacht: einmal ohne ihn starten und schauen
- Zieht ein Server den Start in die Länge, bleibt er diesmal draußen
- Dieselbe Codebasis, eine Runde nur Datenbank, eine nur Web — jeweils mit den passenden Servern

### Web Shell: Projektdateien direkt ansehen, Nachträge sofort senden, Benachrichtigung, wenn es auf dich wartet

**Der Dateibrowser sitzt im rechten Panel.** Hier liegt der komplette Verzeichnisbaum des Workspaces; ein Klick auf eine Datei zeigt den Inhalt daneben: Markdown, HTML, Bilder und Excel gehen direkt auf, dazu Pfad kopieren, herunterladen und referenzieren. Siehe PR [#13878](https://github.com/QwenLM/qwen-code/pull/13878), [#13664](https://github.com/QwenLM/qwen-code/pull/13664)

**Lokale Dateien einfach reinziehen.** Sie landen in dem Ordner, in den du sie ziehst — im Desktop-Build genauso. Siehe PR [#14145](https://github.com/QwenLM/qwen-code/pull/14145), [#14053](https://github.com/QwenLM/qwen-code/pull/14053)

**Nachrichten aus der Warteschlange sind sofort einschiebbar.** Was du schickst, während Qwen Code noch antwortet, steht erst mal in der Warteschlange. Mit `Send now` geht sie sofort raus. Bricht du ab, bevor das Modell etwas ausgegeben hat, kehrt der Text ins Eingabefeld zurück — nachbessern und erneut senden. Siehe PR [#13681](https://github.com/QwenLM/qwen-code/pull/13681), [#13488](https://github.com/QwenLM/qwen-code/pull/13488)

**Wenn es auf dich wartet, kommt eine Benachrichtigung.** Soll eine Aktion freigegeben oder eine Gegenfrage beantwortet werden, war davon bisher nichts zu merken. Jetzt geht in genau diesen beiden Fällen eine Benachrichtigung auf, sobald der Tab im Hintergrund liegt — ein Klick bringt dich zurück in die Session. Siehe PR [#13832](https://github.com/QwenLM/qwen-code/pull/13832)

**Laufen Sub-Agents oder Hintergrundjobs, bekommt das Listen-Icon über dem Chat einen blinkenden Punkt.** Du siehst es, ohne das Panel zu öffnen. Siehe PR [#14048](https://github.com/QwenLM/qwen-code/pull/14048)

## 📊 Weitere neue Features

**Viele Suchrunden ohne Ergebnis lösen einen Hinweis aus.** Nach einer bestimmten Anzahl nur lesender Aktionen — Dateien lesen, Code durchsuchen — bekommt das Modell in der nächsten Runde eine Erinnerung: Es soll das Gefundene benutzen, die Anforderung einen Schritt weiterbringen oder klar sagen, wo es festhängt. War das Erkunden selbst das Ziel, nennt es jetzt Ergebnis und offene Fragen. Siehe PR [#13601](https://github.com/QwenLM/qwen-code/pull/13601)

**Oberflächen von MCP-Servern brauchen deine Freigabe, bevor sie senden.** Manche MCP-Server bringen mehr als Werkzeuge — sie zeigen eine klickbare Fläche im Gespräch. Will so eine Fläche in deinem Namen eine Nachricht schicken, legt Qwen Code vorher alles offen: den kompletten Inhalt, woher er kommt und in welche Session er geht. Erst nach deinem Klick wird gesendet. Siehe PR [#13958](https://github.com/QwenLM/qwen-code/pull/13958)

**Was ein Agent im Workflow getan hat, zeigt ein Klick auf seinen Knoten.** In der Workflow-Karte im Gespräch, auf der `Tasks`-Seite oder auf der Workflow-Seite: Das rechte Panel öffnet den Ablauf dieses Laufs — seinen Prompt, die benutzten Werkzeuge, was er gerade ausgibt und wie weit er gekommen ist. Siehe PR [#14175](https://github.com/QwenLM/qwen-code/pull/14175)

**Die Prüfung vor der Ausführung darf die Parameter dieses Laufs ändern.** Solche Hooks konfigurierst du in den Einstellungen: Sie laufen, bevor Qwen Code ein Werkzeug benutzt. Kommen dabei neue Parameter zurück, werden sie erst neu validiert und gehen nochmal durch Berechtigung und Rückfrage — dann wird ausgeführt. Siehe PR [#13442](https://github.com/QwenLM/qwen-code/pull/13442)

**Nebenfragen gehen in einen anderen Workspace.** Während die Hauptaufgabe noch antwortet, legt `/btw side` in einem der anderen zugehörigen Workspaces ein eigenes Gespräch an — getrennt von der Hauptaufgabe. Siehe PR [#13468](https://github.com/QwenLM/qwen-code/pull/13468)

**Commands aus Plugins im Claude-Format laufen jetzt wirklich.** So eine Command ist Code, kein Prompt ans Modell: Früher war ihr Aufruf ein Satz ans Modell, heute führt das Plugin sie lokal aus und gibt das Ergebnis zurück — ohne Token. Dafür schaltest du `experimental.mods` in den Einstellungen an, der Workspace muss als vertraut markiert sein, und es wirkt nur in der Einmal-Aufruf-Form `qwen -p '…'`; die interaktive Oberfläche und die Web Shell unterstützen es noch nicht. Nur ein Teil der Mod-Schnittstelle ist umgesetzt, bei fertigen Mods ist nicht garantiert, dass sie alle laufen. Siehe PR [#13843](https://github.com/QwenLM/qwen-code/pull/13843), [#13890](https://github.com/QwenLM/qwen-code/pull/13890), [#13915](https://github.com/QwenLM/qwen-code/pull/13915), [#13950](https://github.com/QwenLM/qwen-code/pull/13950)

## 👏 Verbesserte Erfahrungen

**Auf der Seite für neue Aufgaben ist das rechte Panel schon vor dem ersten Satz da.** Oben sitzt jetzt eine schlanke Toolbar; jeder Workspace merkt sich diese Layout-Variante — Neuladen und Sessionwechsel lassen sie unberührt. Schickst du deinen ersten Satz, gehen Tabs, Reihenfolge, Panelbreiten und Vollbild auf die neu angelegte Session über. Siehe PR [#14159](https://github.com/QwenLM/qwen-code/pull/14159)

**Der Trajectory-Tab ist durchsuchbar, filterbar und blätterbar.** Ein Sprung zu einem Werkzeugnamen, einem Modellnamen oder einem Textstück aus dem Protokoll; außerdem nur eine Art von Einträgen, nur fehlgeschlagene oder nur erfolgreiche. Ältere Abschnitte lädst du Stück für Stück, und danach geht es zurück zum neuesten — Suche und Statistik zählen nur den Abschnitt, den du gerade geladen hast. Fällt die Verbindung weg und kommt sie zurück, bleiben Position, Auswahl, Filter und Scrollstand erhalten. Siehe PR [#13264](https://github.com/QwenLM/qwen-code/pull/13264), [#13716](https://github.com/QwenLM/qwen-code/pull/13716), [#13952](https://github.com/QwenLM/qwen-code/pull/13952)

**Auswahl in einer Antwort kopierst du so, wie du willst.** Markiere einen Abschnitt: Das Menü bietet reinen Text oder Markdown inklusive Originalformatierung — Überschriften, Listen, Code und Tabellen bleiben drin. Siehe PR [#13833](https://github.com/QwenLM/qwen-code/pull/13833)

**Der Klick auf den Kontext-Ring öffnet rechts, statt Karten im Gespräch zu stapeln.** Bisher legte der Ring im Eingabefeld eine `Context Usage`-Karte ins Gespräch, und das Detail darauf noch eine. Beide öffnen jetzt das rechte Panel, und jede Session behält ihr eigenes. Wer es im Gespräch haben will, tippt `/context`. Siehe PR [#14086](https://github.com/QwenLM/qwen-code/pull/14086)

**Breite und lange Tabellen gibt es im Vollbild.** Ein Klick auf `Fullscreen` über der Tabelle füllt das ganze Fenster; mit Esc oder dem Exit-Button gehst du zurück. Sortierung, Filter, Spalteneinstellungen und deine Leseposition bleiben stehen. Siehe PR [#13589](https://github.com/QwenLM/qwen-code/pull/13589)

**Nachrichten in der Warteschlange löschst du direkt dort.** Auch eine, deren Datei noch hochgeladen wird — die Zwischendatei wird mit beseitigt. Siehe PR [#13594](https://github.com/QwenLM/qwen-code/pull/13594)

**Klappst du eine Runde zu, verschwinden auch die Ergebnisse aus dem Hintergrund.** Output-Karten der Hintergrundjobs und ihre Fertig-Meldung gehen mit in die Falte. Siehe PR [#13825](https://github.com/QwenLM/qwen-code/pull/13825)

**Die Meldungen bei der Spracheingabe gibt es jetzt auch auf Chinesisch, und Fehler sind schließbar.** Fehler und Hinweise wie „keine Stimme gehört" folgen der eingestellten Sprache der Oberfläche; ein Klick auf Schließen oben rechts gibt das Mikrofon frei — der nächste Versuch startet sofort. Siehe PR [#13938](https://github.com/QwenLM/qwen-code/pull/13938)

**Eine eigene Arbeitskopie: Worktree auswählen, fertig.** Ein Klick im Git-Dialog wählt aus und klappt das Menü zu. Benannt und angelegt wird die Kopie erst, wenn die Session entsteht — also wenn du deinen ersten Satz schickst. Bis dahin kannst du jederzeit zurück. Siehe PR [#13607](https://github.com/QwenLM/qwen-code/pull/13607)

**Alle Icons laufen auf das aktuelle Markenlogo.** Getauscht sind das Favicon der Web Shell, das Sidebar-Zeichen, das Benachrichtigungs-Icon im Browser, das Startbild und das App-Icon des Desktop-Builds. Siehe PR [#14052](https://github.com/QwenLM/qwen-code/pull/14052)
