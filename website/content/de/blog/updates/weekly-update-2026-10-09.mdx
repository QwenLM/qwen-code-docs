Qwen Code hat in den beiden vergangenen Wochen vier Stable-Releases ausgeliefert — v0.24.5 bis v0.25.0 — mit 467 gemergten PRs.

**Qwen Live ist da.** Du sprichst direkt, und Qwen Code antwortet mit Sprache; während des Anrufs teilst du deinen Bildschirm, damit Qwen Code sieht, was gerade darauf passiert.

**Qwen Code bedient die Webseiten, bei denen du angemeldet bist.** Es blättert, füllt Formulare aus und sendet ab — in genau dem Chrome, das du täglich benutzt, alles im Hintergrund, während du deinen Rechner weiter nutzt.

**Eine E-Mail, und die Aufgabe ist raus.** Du bist nicht am Rechner, schickst vom Handy eine Mail, und Qwen Code auf diesem Rechner erledigt sie und schreibt dir das Ergebnis zurück.

**Eine Ladung immer gleicher Aufgaben läuft per `/batch-api` im Hintergrund — zum halben Preis.** Du beschreibst, was zu tun ist, bekommst zuerst einen Plan ohne Berechnung, und erst nach deinem Okay geht die Arbeit raus; Stunden später liegen die Ergebnisse als Dateien da.

**Kam dir eine Runde langsam oder teuer vor, zeigt der Trajectory-Tab, wo sie hängt.** Model requests, Tool calls und Subagent requests bekommen je eine Linie; welche Strecke abnormal lang ist, springt ins Auge.

## ✨ Neue Features

### Qwen Live: sprechen statt tippen, mit geteiltem Bildschirm

Qwen Live ist gestartet und läuft in der Web Shell wie im Desktop-Build. Klicke links in der Sidebar auf das Live-Symbol, rechts erscheinen die Karten für Qwen Live: Schalter an, deinen DashScope-Realtime-API-Key von Bailian hineinkopieren, Save. Siehe PR [#12529](https://github.com/QwenLM/qwen-code/pull/12529)

Ist er an, startest du den Anruf über „Open Live Voice" auf der Live-Seite oder über den Button für den Echtzeit-Sprachanruf unten rechts im Eingabefeld. Dann sprichst du, und Qwen Code antwortet mit Sprache. Siehe PR [#12189](https://github.com/QwenLM/qwen-code/pull/12189)

Während des Anrufs kannst du zusätzlich auf „Bildschirm teilen" klicken, damit Qwen Code sieht, was auf deinem Bildschirm passiert — du fragst dann einfach, was die Fehlermeldung da oben bedeutet. Siehe PR [#12378](https://github.com/QwenLM/qwen-code/pull/12378), [#12623](https://github.com/QwenLM/qwen-code/pull/12623)

Was du damit machen kannst:

- Die Hände sind an der Tastatur beschäftigt — den nächsten Schritt sagst du einfach
- Eine Fehlermeldung auf dem Bildschirm, die du nicht deuten kannst — Bildschirm teilen, Qwen Code schaut selbst und gibt eine Einschätzung
- Eine Klärung, die sonst viele Sätze hin und her braucht, redest du in einem Durchgang aus

### Qwen Code bedient die Webseiten, bei denen du angemeldet bist

Qwen Code geht in genau das Chrome, das du täglich benutzt: Deine offenen Tabs und Deine angemeldeten Konten gelten weiter — Qwen Code blättert, füllt Formulare aus, sendet ab und lässt dich die Ergebnisseite sehen. Sag einfach: „Lies den Report, den ich offen habe, und fass die Bestellungen von heute zusammen." Siehe PR [#11242](https://github.com/QwenLM/qwen-code/pull/11242)

Vorher holst du dir einmal die [Qwen Code Chrome-Extension](https://chromewebstore.google.com/detail/qwen-code/hdhmmjclhibojdddmancfgbkleahfaph) aus dem Chrome Web Store; danach beschreibst du im Gespräch einfach, was zu erledigen ist. Läuft auf Mac und Linux, Windows kommt noch. Siehe PR [#12510](https://github.com/QwenLM/qwen-code/pull/12510)

All das läuft im Hintergrund: Chrome kommt nicht in den Vordergrund, und du nutzt deinen Rechner normal weiter. Mehrere Sessions können Qwen Code gleichzeitig beschäftigen — jede bekommt ihre eigenen Tabs und stört die anderen nicht. Siehe PR [#12229](https://github.com/QwenLM/qwen-code/pull/12229)

Was du damit machen kannst:

- Qwen Code liest das Backend, in dem du angemeldet bist, und hält die Zahlen von heute gegen deine Tabelle
- Belege und Tickets liegen über mehrere Webseiten verteilt — ein Satz, und Qwen Code füllt und sendet sie der Reihe nach
- Ein Prozess, den du nur im Browser siehst — Freigabe-Queue, offene Aufgaben — Qwen Code sucht heraus, was als Erstes dran ist

### Eine E-Mail, und die Aufgabe ist raus

Manchmal fällt dir etwas ein, aber der Rechner mit Qwen Code steht nicht griffbereit — du kommst nicht dran. Dafür gibt es jetzt den Email Channel: schreib einfach eine Mail.

Du gibst im Mail-Programm auf dem Handy eine Anweisung, Qwen Code auf diesem Rechner erledigt sie und antwortet dir mit dem Ergebnis. Wenn dir etwas falsch vorkommt, antwortest du auf dieselbe Mail und schiebst einen Satz nach — Qwen Code weiß, wie weit es schon gekommen ist. Eine weitergeleitete Fehlermeldung eines Nutzers oder eine Systemwarnung kann ebenfalls in dieses Postfach laufen; Qwen Code übernimmt sie.

Damit es läuft, gibst du Qwen Code ein Mail-Konto und trägst deine eigene Adresse in die Liste ein — Qwen Code reagiert nur auf Mails von dir.

Was du damit machen kannst:

- Auf dem Weg ins Büro eine Mail losschicken, damit die Arbeit läuft, wenn du am Platz sitzt
- Eine Fehlermeldung eines Nutzers unverändert hineinleiten; Qwen Code liest zuerst die Logs im Anhang und gibt eine erste Einschätzung
- Sobald eine Warnung rausgeht, übernimmt Qwen Code die Untersuchung und schreibt dir den Grund zurück

Siehe PR [#12939](https://github.com/QwenLM/qwen-code/pull/12939)

### /batch-api: eine Ladung immer gleicher Aufgaben im Hintergrund — zum halben Preis

Du hast hunderte voneinander unabhängige Kleinigkeiten: ein ganzes Dokumentenverzeichnis übersetzen, aus Dutzenden Tickets jeweils ein paar Felder ziehen, für jeden Eintrag eine Zusammenfassung schreiben. Einzeln losschicken füllt das Gespräch mit Warten und kostet obendrauf.

Schreib hinter `/batch-api` in einem Satz, was zu tun ist. Qwen Code probiert ein paar Beispiele und legt dir einen Plan vor: wie viele Einträge, in welches Verzeichnis die Ergebnisse kommen und mit welchen Kosten zu rechnen ist — für diesen Schritt zahlst du nichts. Erst wenn du zustimmst, geht die Arbeit raus. Danach läuft die Ladung im Hintergrund zum halben Preis des Echtzeit-Tarifs; meist nach einigen Dutzend Minuten bis wenigen Stunden liegen die Ergebnisse als einzelne Dateien an dem Ort, den du angegeben hast. Dein Gespräch arbeitet in der Zeit ganz normal weiter.

```text
/batch-api Übersetze die Markdown-Dokumente unter docs/zh ins Englische und schreibe sie mit gleichem Namen unter docs/en
```

Passend ist das für Aufgaben, die in einem Durchgang fertig werden und nichts voneinander wollen. Was mehrere Runden Diskussion braucht, läuft weiterhin im Gespräch.

Was du damit machen kannst:

- Ein chinesisches Dokumentenverzeichnis komplett ins Englische — einmal übergeben, ein paar Stunden später einsammeln
- Aus einem Stapel Logs und Tickets pro Eintrag Felder ziehen und in einem Lauf bündeln
- Hunderte Nutzerfeedbacks der Reihe nach einsortieren und verschlagworten — einmal übergeben

Siehe PR [#12492](https://github.com/QwenLM/qwen-code/pull/12492)

### Trajectory-Tab: bei einer langsamen oder teuren Runde siehst du, woran es liegt

Du kommst aus einer Runde und weißt nur: sie war lang. Ob das Modell lange brauchte, ob es zu viel Text zurückgab oder ob ein Tool zwischendrin feststeckte, war bisher nicht zu sehen.

Der Trajectory-Tab im rechten Panel fächert die Zeit in drei Linien auf: Model requests, Tool calls und Subagent requests. Welche Strecke abnormal lang ist, springt ins Auge; stehen die Balken zu dicht, ziehst du einen Abschnitt einfach auseinander. Siehe PR [#12524](https://github.com/QwenLM/qwen-code/pull/12524), [#12557](https://github.com/QwenLM/qwen-code/pull/12557)

Ist dir ein Abschnitt verdächtig, markierst du ihn auf der Achse, und darunter bleiben nur die Ereignisse aus dieser Zeit. Wählst du einen einzelnen Balken, stehen darunter was er gelesen hat, was zurückkam und wie viele Tokens es kostete — zum Kopieren. Siehe PR [#12543](https://github.com/QwenLM/qwen-code/pull/12543), [#12971](https://github.com/QwenLM/qwen-code/pull/12971)

Auf der Achse gibt es außerdem die Ansicht Real time: Sie zählt auch die Zeit, in der du nur wartest, und nennt zwei Zahlen — wie lange die Runde dauerte und wie lange tatsächlich gearbeitet wurde. Wie viel Zeit eine Runde von dir fordert, steht hier. Siehe PR [#12607](https://github.com/QwenLM/qwen-code/pull/12607)

Fertige Runden lassen sich zusammenklappen; in einer langen Session musst du nicht von oben bis unten scrollen. Siehe PR [#13081](https://github.com/QwenLM/qwen-code/pull/13081)

Was du damit machen kannst:

- Langsam? Ein Blick auf die Achse sagt, was du als Nächstes angehst: das Modell wechseln oder das Tool untersuchen
- In einer langen Session zu einem Abschnitt zurück — markieren, fertige Runden zuklappen, nur diese Strecke sehen
- Der Verdacht, ein Vorgang sei schiefgelaufen: Eingabe, Rückgabe und Token-Kosten stehen direkt da

### Channel: ein Bot verteilt die Arbeit, private und Gruppen-Zugänge getrennt, lange Sessions wechseln von selbst

**Ein Bot kann die Arbeit aufteilen.** Ein Präfix vor der Nachricht entscheidet, in welche Session sie geht und welche Regeln dort gelten — die eine Linie lässt Code prüfen, die andere beantwortet Fragen zum Repository, und beide bleiben sauber getrennt. Dafür brauchst du keine zweite Verbindung. In der Gruppe setzt du das Präfix hinter das @. Siehe PR [#12595](https://github.com/QwenLM/qwen-code/pull/12595)

**Wer privat schreiben darf und wer in der Gruppe nutzen darf, sind zwei Einstellungen.** Die Gruppe kann komplett offen sein, während private Gespräche auf ein paar Namen auf der Liste beschränkt bleiben — die beiden Regler beeinflussen einander nicht. Siehe PR [#12547](https://github.com/QwenLM/qwen-code/pull/12547), [#12475](https://github.com/QwenLM/qwen-code/pull/12475)

**Lange Gruppen-Sessions wechseln von selbst.** Ein Thread wächst und wächst, bis am Ende keine Nachricht mehr durchkommt — kaputt war dann nur diese eine Session; ein DingTalk-Thread hatte 8.577 Nachrichten. Setzt du ihm ein Limit, nimmt Qwen Code rechtzeitig eine frische Session und sagt es in der Gruppe. Siehe PR [#12616](https://github.com/QwenLM/qwen-code/pull/12616)

### Web Shell: neue Sidebar, Suche im langen Verlauf, mehrere Worktrees pro Repository und mehr

**Die Sidebar ist neu gebaut.** Links sitzt eine schmale Navigation; Channel, Live und die anderen Bereiche haben eigene Einträge, Versionsnummer und selten benutzte Aktionen ziehen ins Menü „Mehr" um. Siehe PR [#12943](https://github.com/QwenLM/qwen-code/pull/12943)

**Der lange Verlauf ist durchsuchbar.** Suchst du einen Satz von früher oder einen eingefügten Code-Abschnitt, führt dich das Suchfeld direkt zu dieser Nachricht. Ältere Nachrichten musst du nicht erst heraufscrollen, die Suche findet sie. Siehe PR [#12234](https://github.com/QwenLM/qwen-code/pull/12234)

**Nebenfragen sind einen Klick entfernt.** Läuft die Hauptaufgabe und du willst kurz etwas anderes fragen, gibt es dafür einen Punkt im „+"-Menü des Eingabefelds, der die Anfrage für dich vorbereitet. Die Antwort erscheint im Panel daneben, die Hauptaufgabe läuft ungestört weiter. Siehe PR [#12775](https://github.com/QwenLM/qwen-code/pull/12775)

**Ein Repository kann mehrere Arbeitskopien haben.** Nach dem Branch-Graphen der letzten Ausgabe gibt es im Git-Dialog einen Worktree-Tab: Jede Session bekommt ihre eigene Kopie, Änderungen behindern einander nicht. Welche Kopie eine Session laufen hat und wo etwas uncommittet ist, steht sofort da; ein Klick switcht hinüber. Siehe PR [#12154](https://github.com/QwenLM/qwen-code/pull/12154), [#11816](https://github.com/QwenLM/qwen-code/pull/11816)

## 📊 Weitere neue Features

**Auch der Commit läuft auf Befehl.** `/commit` sieht, welche Dateien du geändert hast, schreibt einen Commit-Text im Stil deiner Repository-Geschichte und nimmt nur die Dateien auf, die in diesen Commit gehören. Dateien mit Secrets wie `.env` lehnt Qwen Code ab. Qwen Code erzeugt den Commit; das Pushen bleibt bei dir. Eingrenzen kannst du mit einem Zusatz, etwa `/commit only stage the parser changes`. Siehe PR [#10586](https://github.com/QwenLM/qwen-code/pull/10586)

**An einer Nachricht siehst du, was sie ausgelöst hat.** In der Web Shell legst du die Maus auf deine eigene Nachricht: neben dem Kopieren-Button erscheint ein Schraubenschlüssel-Icon, und dahinter liegt die Liste der Tool-Aufrufe — welche Dateien diese Runde gelesen hat, welche Befehle sie lieferte und was sie änderte, einzeln aufgelistet; aufklappen zeigt Ergebnis und Änderung. Auch Runden davor sind nachsehbar. Siehe PR [#12466](https://github.com/QwenLM/qwen-code/pull/12466)

**`/advisor` kommt von selbst.** Ist der Schalter an, holt sich das arbeitende Modell vor dem Eingriff und kurz vor der Abgabe die Meinung des Advisors; der Rat kommt im Gespräch an, dann macht Qwen Code weiter. Auch Subagents dürfen fragen. Jede Anfrage kostet zusätzliche Tokens, und der Verlauf geht an das Beratermodell — nimm eines, dem du traust. Siehe PR [#9636](https://github.com/QwenLM/qwen-code/pull/9636), [#12688](https://github.com/QwenLM/qwen-code/pull/12688)

**Neues Modell anschließen, weniger eintragen.** Wie groß sein Kontextfenster ist, wie viel es auf einmal ausgibt und ob es Bilder nimmt, erkennt Qwen Code jetzt selbst: Die eingebaute Modelliste wird im Hintergrund täglich aktualisiert und hilft auch ohne Netzverbindung. Was du selbst eingetragen hast, bleibt maßgeblich. Siehe PR [#11959](https://github.com/QwenLM/qwen-code/pull/11959)

**Externes Memory andocken wird einfach.** Soll Qwen Code über Sessions hinweg etwas wissen, gib ihm eine Adresse und einen Key — Extension installieren und Dienst registrieren entfällt. Suchen ist sofort dabei; fürs Schreiben nach extern schaltest du einen zusätzlichen Schalter an, und danach siehst du jeden Eintrag, bevor er abgelegt wird. Siehe PR [#12891](https://github.com/QwenLM/qwen-code/pull/12891)

**Viel Memory liegt nicht mehr komplett im Kontext.** Mit dem Schalter legt Qwen Code nur die Einträge bei, die zu deiner aktuellen Frage passen; den Rest holst du bei Bedarf. Ab Dutzenden Memory-Dateien ist das eine erhebliche Ersparnis. Siehe PR [#10183](https://github.com/QwenLM/qwen-code/pull/10183)

**Der QQ-Bot sieht Bilder und Videos.** Bilder und kurze Videos, die in der Gruppe an ihn gehen, schaut Qwen Code sich direkt an — du musst sie nicht mehr in Text beschreiben. Siehe PR [#12850](https://github.com/QwenLM/qwen-code/pull/12850)

## 👏 Verbesserte Erfahrungen

**Doppelt so schnell zum ersten Zeichen.** Auf einem sauberen Rechner vergingen vom Aufruf von `qwen` bis zum ersten getippten Zeichen rund 2,5 Sekunden, und die ersten 2 davon blieb der Terminal leer. Diese Wartezeit ist halbiert, und der Speicherbedarf sinkt von 575 MB um etwa 60 %. Siehe PR [#12622](https://github.com/QwenLM/qwen-code/pull/12622), [#12602](https://github.com/QwenLM/qwen-code/pull/12602), [#12603](https://github.com/QwenLM/qwen-code/pull/12603)

**Das Einstellungspanel ist durchgängig chinesisch.** Wer die Interface-Sprache auf Chinesisch stellt, sieht dort überall Chinesisch. Siehe PR [#12783](https://github.com/QwenLM/qwen-code/pull/12783)

**Channel-Einstellungen im Dialog.** Sprecher einer Gruppe und Session-Verwalter trägst du jetzt in einem Dialog ein, statt die Konfigurationsdatei von Hand zu bearbeiten. Siehe PR [#12535](https://github.com/QwenLM/qwen-code/pull/12535)

**Weniger Ballast im Interface.** Leere Parameter belegen keine Zeile mehr, die Kopfzeile der Statistikseite ist sortiert, und Rohdaten stecken im Detail. Siehe PR [#12601](https://github.com/QwenLM/qwen-code/pull/12601), [#13091](https://github.com/QwenLM/qwen-code/pull/13091)

**Skills geändert, neu geladen, wirkt es.** Hast du Skill-Inhalte geändert, sind sie nach dem Neuladen aktuell. Siehe PR [#12182](https://github.com/QwenLM/qwen-code/pull/12182)
