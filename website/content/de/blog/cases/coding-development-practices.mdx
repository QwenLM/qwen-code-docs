Softwareentwicklung besteht nicht nur aus dem Schreiben von Code. Jeder Schritt kostet Zeit – von der Klärung der Anforderungen bis zur Sicherstellung der Codequalität. Die folgenden drei Szenarien zeigen, wie Qwen Code den gesamten Prozess begleitet: Anforderungen klären, Code prüfen, Testfälle ergänzen.

## Von vagen Anforderungen zu einem interaktiven Prototyp

Sie haben eine Idee im Kopf, aber die Details sind noch unklar? Erzählen Sie Qwen Code einfach, was Sie machen möchten. Es fängt nicht sofort an, Code zu schreiben, sondern spricht erst mit Ihnen wie ein Product Manager – Kernfunktionen, Interaktionsweise, technische Umsetzung. Wenn Sie und die AI mit den Anforderungen zufrieden sind, entwickelt es das gesamte Tool. Von einem Satz zu einem lauffähigen Prototyp – ohne dass Sie eine Zeile Code selbst schreiben.

### Vorgehensweise

1. **Anforderungen ausarbeiten** — Erzählen Sie Qwen Code Ihre Idee, auch wenn es nur eine vage Beschreibung ist. Die AI stellt proaktiv Fragen zu den Details: Kernfunktionen, Interaktionsweise, technische Umsetzung und erstellt am Ende ein vollständiges Anforderungsdokument.
2. **Anforderungskonzept bestätigen** — Nachdem die AI das Konzept erstellt hat, können Sie es Punkt für Punkt prüfen und Anpassungen vornehmen. Wenn alles passt, geht es weiter.
3. **Entwicklung starten** — Sobald das Konzept bestätigt ist, lassen Sie Qwen Code mit der Entwicklung beginnen. Es erstellt das Tool Schritt für Schritt gemäß dem Anforderungsdokument – automatisch.

<Callout>
    **Tipp**: Je konkreter die Anforderungsphase, desto weniger Nachbesserungen in der Entwicklungsphase. Keine Eile beim Coden – zuerst klären.
</Callout>

## 9 AI-Reviewer prüfen gleichzeitig Ihren Code

Führen Sie vor dem Commit `/review` aus, und 9 Review-Agenten starten parallel: Sicherheit, Performance, Codequalität und weitere Dimensionen werden gescannt, gefundene Probleme direkt behoben. Ein Kollege hat einen PR eingereicht? Ein Befehl für das Review, Kommentare werden automatisch in die GitHub-Codezeilen geschrieben – wie ein echtes Review.

### Vorgehensweise

1. **Projekt-Code-Review** — Führen Sie `/review` aus, um den Projektcode zu prüfen. 9 Agenten scannen parallel und finden automatisch Sicherheits- und Performance-Probleme wie hartcodierte Secrets oder SQL-Injection.
2. **Probleme per Klick beheben** — Wählen Sie die automatische Reparatur. Qwen Code ändert den Code direkt und führt den Linter zur Verifikation aus, sodass keine neuen Probleme entstehen.
3. **PR prüfen und kommentieren** — Führen Sie `/review <PR number> --comment` aus, um einen Remote-PR zu prüfen. Wechseln Sie zu GitHub, um die Inline-Kommentare zu sehen – die Review-Hinweise stehen direkt in den Codezeilen.

```bash
/review <PR number> --comment
```

## Unit-Tests für das Projekt hinzufügen

Lassen Sie Qwen Code die Projektregeln verstehen und automatisch Unit-Tests generieren, die normale Szenarien, Randfälle und fehlerhafte Eingaben abdecken – mit automatischer Ausführung, Fehlerbehebung und Ergänzung der Testabdeckung.

### Vorgehensweise

1. **Projekt und Testziele verstehen** — Qwen Code liest die Projektdateien, versteht Geschäftsregeln, Kernfunktionen und Testziele und plant, welche Testszenarien priorisiert abgedeckt werden müssen.
2. **Tests generieren und ausführen** — Basierend auf den Geschäftsregeln werden Unit-Tests für Kernfunktionen generiert, die normale Szenarien, Randfälle und fehlerhafte Eingaben abdecken – z. B. Rabattschwellen, Versandkosten-Grenzwerte, leerer Warenkorb und ungültige Eingaben. Die Tests werden automatisch ausgeführt.
3. **Probleme beheben und Tests zum Laufen bringen** — Bei Testfehlern wird die Fehlerursache ermittelt. Wenn die Codeimplementierung nicht mit den Geschäftsregeln übereinstimmt, ändert Qwen Code den Code und führt die Tests neu aus, bis sie durchlaufen.
4. **Testabdeckung ergänzen** — Prüfen Sie den Coverage-Report, analysieren Sie nicht abgedeckte Dateien und Branches und ergänzen Sie weitere wertvolle Testfälle, um die Testabdeckung der Kernlogik zu verbessern.

<Callout type="error">
    **Hinweis**: Bei AI-generierten Testfällen müssen Sie selbst beurteilen, ob die Geschäftslogik korrekt ist. AI kann Tests schreiben, aber nicht beurteilen, was richtig ist.
</Callout>
