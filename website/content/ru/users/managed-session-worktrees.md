# Управляемые worktree сессий


В поддерживаемом локальном управляемом развертывании выберите Git-проект при создании сессии. Откройте кнопку Git-ветки рядом с рабочим пространством под композером и выберите **Worktree**. Пикер закроется; отправка первого сообщения автоматически создаст изолированный checkout из текущего HEAD на отдельной ветке. Нет формы для заполнения ветки или каталога. Незакоммиченные файлы, игнорируемая конфигурация и установленные зависимости остаются в исходном каталоге.

Перед отправкой выберите **Current branch** или очистите чип Worktree, чтобы работать непосредственно с исходной веткой. Чип отображает фактическую исходную ветку, например **main**, когда изоляция не выбрана.

Сессия сообщает о подготовке и может ожидать другие инструменты, использующие то же
хранилище. Ссылки на файлы и загрузки рабочего пространства становятся доступны после того,
как worktree готов. Инструкции проекта берутся из целевого каталога; настройки
управляемой модели, одобрения, навыков, MCP и расширений сохраняют свои пины сессии.

В чате Home информационная карточка сессии содержит статус worktree, ветку и базовый коммит. Детали готового worktree больше не занимают верхнюю часть
разговора; сообщения о подготовке и ошибках остаются видимыми там, когда это необходимо.

Закрытие, архивирование или удаление чата сохраняет checkout и ветку. Откройте
**Session worktrees** из попапа композера новой задачи того же рабочего пространства для проверки сохраненных каталогов. Закройте
сессию и завершите ее фоновую работу перед очисткой. Сначала закоммитьте или иначе
сохраните отслеживаемое/неотслеживаемое/игнорируемое содержимое. Очистка удаляет только чистый
checkout и сохраняет все ветки; она не объединяет изменения в источник.

Развертывания включают `qwen.managed-agent.runtime-broker.session-worktrees-enabled`.
По умолчанию выключено; `qwen serve --managed` включает подходящие локальные хосты. Эта версия
поддерживает ЛОКАЛЬНОЕ хранилище macOS/Linux, изолированные от сессий долговечные локальные процессы
и Git 2.40 или новее. Репозиторий и его общий каталог Git должны
находиться внутри зарегистрированного корневого каталога хранилища. Для существующего связанного checkout с метаданными Git
в другом месте выберите исходный checkout или попросите администратора
зарегистрировать корневой каталог, содержащий оба. SSH и CSI не поддерживаются в этой версии.

Перезапуск готовой сессии повторно использует ее исходный checkout. Отсутствующие или замененные
каталоги блокируют выполнение. Если сервер был принудительно остановлен, пока Git создавал или
удалял worktree, непроверенный исходный процесс Git оставляет операцию
заблокированной и ее служебное удержание нетронутым. Повторная проверка не принуждает восстановление;
автоматическое восстановление macOS для этого случая не входит в эту версию. Сохраните
каталог и ветку, пока исходное выполнение не может быть согласовано.

Публичный запрос создания сессии добавляет `worktree: {"base_ref":"main"}`;
`worktree: {}` выбирает HEAD, а пропуск использует текущий каталог. Отправьте
явный авторизованный `workspace` и сохраните тот же Idempotency-Key при повторе.
Запросите `worktree.state` возвращенной сессии перед отправкой последующего ввода.

Эта версия разработки обновляет общую baseline схемы V1. Используйте
каталог разработки, воссозданный из этой baseline; миграция обновления для
более старого каталога не включена.
