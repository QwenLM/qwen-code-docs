# Память

Каждая сессия Qwen Code начинается с нового контекстного окна. Два механизма переносят знания между сессиями, чтобы вам не приходилось каждый раз объяснять всё заново:

- **QWEN.md** — инструкции, которые _вы_ пишете один раз, и Qwen читает их в каждой сессии
- **Auto-memory** — заметки, которые Qwen создает сам на основе того, что узнает о вас
- **Внешняя память (`context_search`)** — опциональный MCP-инструмент, который Qwen вызывает по запросу для поиска в Mem0 или локальном индексе сессий

---

## QWEN.md: ваши инструкции для Qwen

QWEN.md — это обычный текстовый файл, в котором вы указываете то, что Qwen должен всегда знать о вашем проекте или ваших предпочтениях. Считайте его постоянным брифингом, который загружается в начале каждого диалога.

### Что включать в QWEN.md

Добавьте вещи, которые иначе пришлось бы повторять в каждой сессии:

- Команды для сборки и тестирования (`npm run test`, `make build`)
- Соглашения о стиле кода, которых придерживается ваша команда («все новые файлы должны иметь комментарии JSDoc»)
- Архитектурные решения («мы используем паттерн Repository, никогда не обращаемся к базе данных напрямую из контроллеров»)
- Личные предпочтения («всегда использовать pnpm, а не npm»)
- Политику верификации для ответственной работы — например, «проверяй по базе данных перед тем, как делать вывод» (см. [Enforce evidence-based conclusions](../common-workflow.md#enforce-evidence-based-conclusions) для готового шаблона)

Не включайте то, что Qwen может понять, просто прочитав ваш код. QWEN.md работает лучше всего, когда он короткий и конкретный — чем он длиннее, тем менее надежно Qwen ему следует.

### Где создавать QWEN.md

| Файл                          | Для кого применяется                            |
| ----------------------------- | ----------------------------------------------- |
| `~/.qwen/QWEN.md`             | Для вас, во всех ваших проектах                 |
| `QWEN.md` в корне проекта     | Для всей вашей команды (закоммитьте в git)      |
| `.qwen/QWEN.local.md`         | Только для вас, только в этом проекте (исключите из git) |

Вы можете использовать любую комбинацию этих файлов. Qwen загружает их все при запуске сессии.

Если в вашем репозитории уже есть файл `AGENTS.md` для других AI-инструментов, Qwen прочитает и его. Дублировать инструкции не нужно.

#### Когда использовать `.qwen/QWEN.local.md`

Используйте его для **специфичных для проекта, но личных** инструкций — вещей, которые относятся к этому проекту, но не должны передаваться команде:

- Ваш собственный ID кластера, пространство имен в реестре контейнеров или облачный аккаунт
- Личная команда для отладки, в которой захардкожены параметры вашего локального окружения
- Заметки о вашей текущей работе, которые вы хотите, чтобы Qwen знал, но не коммитил

Он загружается **после** общего `QWEN.md` проекта, поэтому ваши локальные инструкции могут дополнять или переопределять командные.

**Вам нужно самостоятельно добавить его в `.gitignore`.** Хотя каталог `.qwen/` часто считается локальным, qwen-code не создает `.gitignore` за вас, а некоторые проекты коммитят `.qwen/settings.json`. Добавьте эту строку в ваш `.gitignore` (или в глобальный gitignore):

```
.qwen/QWEN.local.md
```

### Автоматическая генерация с помощью `/init`

Запустите `/init`, и Qwen проанализирует вашу кодовую базу, чтобы создать начальный QWEN.md с командами сборки, инструкциями по тестированию и найденными соглашениями. Если файл уже существует, он предложит дополнения вместо перезаписи.

### Ссылки на другие файлы

Вы можете указать в QWEN.md на другие файлы, чтобы Qwen прочитал и их:

```markdown
См. @README.md для обзора проекта.

# Conventions

- Git workflow: @docs/git-workflow.md
```

Используйте `@path/to/file` в любом месте QWEN.md. Относительные пути разрешаются относительно самого файла QWEN.md.

## Auto-memory: что Qwen узнает о вас

Auto-memory работает в фоновом режиме. После каждого вашего диалога Qwen тихо сохраняет полезные вещи, которые он узнал — ваши предпочтения, оставленные отзывы, контекст проекта — чтобы использовать их в будущих сессиях без необходимости повторяться.

Это отличается от QWEN.md: вы его не пишете, это делает Qwen.

Когда ход, отвечающий на сообщение, переданное через [канал](./channels/overview) — GitHub, Telegram, DingTalk и другие — завершается, Qwen не выполняет извлечение и не планирует [периодическую очистку](#периодическая-очистка): отправитель часто не вы, и извлечение после каждого переданного сообщения добавляло бы вызовы модели к каждому из них. В сессии, которая также принимает ваши собственные промпты, например привязанной к pull request, извлечение после вашего следующего промпта всё ещё читает недавний разговор, поэтому переданные сообщения, всё ещё находящиеся в нём, могут быть изучены. Воспоминание памяти не затрагивается: ответ на сообщение канала может использовать то, что уже сохранено. Канал-чат хранит долговечный контекст в [памяти канала](./channels/overview#channel-memory) вместо этого.

### Что сохраняет Qwen

Qwen ищет четыре типа вещей, которые стоит запомнить:

| Что                     | Примеры                                                |
| ----------------------- | ------------------------------------------------------ |
| **О вас**               | Ваша роль, бэкграунд, как вы любите работать           |
| **Ваши отзывы**         | Внесенные вами исправления, подтвержденные подходы     |
| **Контекст проекта**    | Текущая работа, решения, цели, неочевидные из кода     |
| **Внешние ссылки**      | Дашборды, тикер-трекеры, ссылки на документацию, которые вы упоминали |

Qwen сохраняет не всё — только то, что действительно будет полезно в следующий раз.

### Где это хранится

Файлы Auto-memory находятся в `~/.qwen/projects/<project>/memory/`. Все ветки одного checkout используют одну и ту же папку памяти, поэтому то, что Qwen узнает в одной ветке, доступно и в других. Каждый привязанный git worktree получает собственную папку памяти, что соответствует изоляции чатов и другого состояния сессии по worktree — общепроектные соглашения, которые нужны в каждом worktree, следует помещать в [командную память](#командная-память-доступна-соавторам).

Всё сохраненное — это обычный markdown, вы можете открыть, отредактировать или удалить любой файл в любое время.

`MEMORY.md` — это компактный индекс, а не полное хранилище памяти. Его сгенерированное тело и часть, загружаемая в промпты, имеют лимит в 200 строк и 25 000 единиц UTF-16; уведомления об усечении добавляются отдельно. Концы строк нормализуются перед бюджетированием промпта. Под давлением размера полные обычные записи (до 150 единиц кода) получают пространство перед более длинными записями, а сохраненные записи сохраняют свой исходный порядок. Запись, которая не помещается, пропускается целиком, поэтому её Markdown-ссылка никогда не обрезается посередине. Держите детали в связанных файлах тем.

Когда перестройка опускает записи, сохраненное предупреждение сообщает отброшенное количество и до трех имен для каждого лимита: лимит сканирования файлов тем и бюджет тела индекса. Счетчики остаются разделенными, потому что одна группированная командная запись может представлять несколько файлов. Предупреждение остается видимым, когда индекс загружается в промпт, пока это последний параграф файла. Вставьте новые указатели индекса выше завершающего предупреждения, чтобы сохранить его. Пропуск из индекса не удаляет связанные файлы тем. Для давления тела индекса объедините файлы тем или удалите устаревшие, или сократите их имена и описания в frontmatter. Слишком длинная ссылка уже не имеет описания: сократите путь файла темы или имя frontmatter вместо этого. Редактирование только сгенерированного индекса не переживет следующую перестройку. Для лимита сканирования количества файлов объедините файлы тем или удалите устаревшие; редактирование только сгенерированного индекса не уменьшает количество просканированных файлов.

Предупреждение для частично загруженного индекса различает бюджеты строк и символов. Сокращение описаний может помочь с общим бюджетом символов, даже когда ни одна запись не превышает обычную длину строки. Для записей, соответствующих сгенерированному формату, этот совет учитывает имена и ссылки, включая группированные ссылки; сокращайте или объединяйте записи, когда эти ссылки alone потребляют бюджет. Форматы, отредактированные вручную, или группированные суффиксы, которые могли бы быть текстом описания, получают возможные исправления без обещания, что сокращение подойдет. Если лимит количества записей превышен, записи всё ещё должны быть сокращены или объединены: сокращение описания не уменьшает количество записей. Когда оба бюджета превышены, сокращение индекса до 200 записей может всё ещё требовать более коротких описаний или меньшего количества записей для соответствия бюджету символов; предупреждение сообщает фактическое количество кандидатов. Сокращение до 150 единиц на запись не всегда достаточно для соответствия общему количеству 25 000 единиц.

Ограниченное, одно-параграфное завершающее уведомление writer исключается из бюджетирования промпта. Когда все сохраненные записи помещаются, Qwen сохраняет это уведомление без утверждения, что больше записей было пропущено при загрузке. Регенерация насыщенного индекса может заполнить пространство, освобожденное более короткими описаниями, поэтому размер сохраненного файла не обязательно должен уменьшаться немедленно. Для проектной, пользовательской и командной памяти отредактируйте frontmatter `description` файлов тем и проверьте регенерированный индекс. Пустое описание может вернуться к типу памяти, поэтому сокращение frontmatter не гарантирует, что каждая запись поместится. Прямые редактирования строк индекса могут быть заменены следующей управляемой записью. Держите полные цели ссылок целыми, даже когда ссылка превышает 150 единиц; сократите метаданные отображения или сократите или объедините файлы тем вместо обрезки ссылок.

#### Закрепленная память

Поместите вручную составленные документы, которые автоматическое обслуживание памяти должно сохранять, в каталог `pinned/` внутри управляемого каталога памяти, например `~/.qwen/projects/<project>/memory/pinned/architecture.md` или `~/.qwen/memories/pinned/preferences.md`. Используйте тот же frontmatter, что и для остальных документов памяти. Валидные закрепленные файлы читаются Qwen и включаются при следующей перестройке `MEMORY.md`, в рамках тех же ограничений на размер и количество файлов, что и остальные документы памяти.

Защищен только каталог `pinned/` верхнего уровня, находящийся непосредственно внутри корня управляемой памяти; вложенные каталоги, такие как `memory/project/pinned/`, являются обычным записываемым хранилищем памяти. Автоматическое извлечение и воркеры Dream сопоставляют зарезервированное имя каталога без учета регистра.

Автоматическое извлечение получает инструкцию оставлять закрепленные записи и их валидные записи индекса без изменений, а Dream получает инструкцию пропускать `pinned/` во время консолидации. Как автоматическое извлечение, так и форкнутые воркеры Dream, включая фоновую очистку, соблюдают границу закрепленных файлов в своих инструментах записи и редактирования, включая пути, которые разрешаются через symlink в `pinned/`.
Удаление через командную строку также закрыто: только проектный воркер Dream держит shell, и его политика только для чтения, в то время как автоматическое извлечение и воркер Dream пользовательской памяти не держат shell вообще. Вы по-прежнему напрямую контролируете эти файлы и можете удалить их с помощью явного запроса `/forget`.

> **Примечание:** Видимая слеш-команда `/dream` выполняется на основном Agent. Она получает ту же инструкцию о пропуске, но пока не получает детерминированный поворотный инструментальный барьер форкнутого воркера.

### Периодическая очистка

Qwen периодически просматривает сохраненные воспоминания, чтобы удалять дубликаты и очищать устаревшие записи. Это запускается автоматически в фоновом режиме раз в день после накопления достаточного количества сессий. Вы можете запустить это вручную с помощью `/dream`, если хотите, чтобы это выполнилось сейчас.

Ваша сессия продолжается в обычном режиме, пока очистка работает в фоновом режиме.

### Включение и выключение

Auto-memory включена по умолчанию. Чтобы переключить её, откройте `/memory` и используйте переключатели вверху. Вы можете отключить только автоматическое сохранение, только периодическую очистку или и то, и другое.

Вы также можете настроить их в `~/.qwen/settings.json` (применяется ко всем проектам) или `.qwen/settings.json` (только для этого проекта):

```json
{
  "memory": {
    "enableManagedAutoMemory": true,
    "enableManagedAutoDream": true
  }
}
```

### Структурированный поиск (opt-in)

По умолчанию Qwen читает память как плоский индекс `MEMORY.md`. Структурированный протокол заменяет его иерархическим деревом памяти, инжектирует только поддерево, относящееся к вашему текущему запросу, и дает Qwen инструмент `search_memory` для извлечени�� полных записей по запросу — что стоит меньше токенов, когда коллекция памяти вырастает больше горстки файлов.

Он выключен по умолчанию. Включите его в `settings.json` (требуется перезапуск):

```json
{
  "memory": {
    "enableStructuredRecall": true
  }
}
```

или для одного запуска с `QWEN_CODE_MEMORY_STRUCTURED_RECALL=1`.

Включение запускает фоновую миграцию метаданных: каждый файл памяти получает frontmatter (категория, ключевые слова, сценарии использования), который нужен для поиска. Он запускается небольшими пакетами не более 10 файлов за ход и переписывает только frontmatter, никогда не тело заметки. Пока настройка выключена, миграция никогда не планируется, поэтому ничего не переписывается и фоновые вызовы модели не делаются.

### Командная память (доступна соавторам)

По умолчанию auto-memory **является вашей личной** — она находится в вашем домашнем каталоге и никогда не передается другим. Командная память — это опциональный уровень, которым вся команда делится **через git**.

При включении Qwen получает третий каталог памяти по пути `.qwen/team-memory/` **внутри репозитория**. Он использует ту же структуру «один файл на одно воспоминание» и индекс `MEMORY.md`, что и личные уровни. Поскольку он коммитится в репозиторий, он доступен каждому соавтору стандартным способом: вы делаете `git pull`, чтобы получить воспоминания коллег, и коммитите/пушите, чтобы поделиться своими. Qwen направляет сюда долговечные, общепроектные знания — соглашения, которые должен соблюдать каждый участник, общие указатели (трекеры, дашборды) — в то время как личные и быстро устаревающие заметки остаются приватными.

Включите её для конкретного проекта (или глобально) в `settings.json`:

```json
{
  "memory": {
    "enableTeamMemory": true
  }
}
```

По умолчанию она **выключена**. Учитывайте следующие нюансы:

- **Она контролируется системой версий и видна всем, у кого есть доступ к репозиторию.** Относитесь к командной памяти как к коммиту в репозиторий.
- **Секреты блокируются.** Записи в `.qwen/team-memory/` сканируются на наличие учетных данных (API-ключи, токены, приватные ключи); обнаруженный секрет отклоняется и никогда не записывается. Сканирование — это последняя линия обороны, а не гарантия — не помещайте туда конфиденциальные данные.
- **Изменения можно ревьюить.** Записи командной памяти появляются в `git status` / diff PR как любой другой файл, поэтому их можно проверить перед коммитом. В режиме подтверждения по умолчанию Qwen также спрашивает перед каждой командной записью; в режиме `AUTO_EDIT`/YOLO (где вы включили автоподтверждение) они применяются без запроса, но всё равно отображаются в diff.
- **Каталог должен отслеживаться в git.** Если `.gitignore` вашего проекта исключает `.qwen/*`, повторно включите этот путь, чтобы он мог быть общим:

  ```gitignore
  !.qwen/team-memory/
  !.qwen/team-memory/**
  ```

  Нюанс: используйте форму игнорирования файловых шаблонов (`.qwen/*`), а не форму каталога с косой чертой в конце (`.qwen/`). Игнорирование в форме каталога заставляет git полностью пропускать папку, поэтому повторное включение через `!` ниже по тексту не сработает, и командный уровень останется молча пустым в git. Qwen один раз предупреждает при запуске, если уровень включен, но его каталог игнорируется в git или находится вне любого git-репозитория, так что эта неправильная конфигурация не останется незамеченной.

`QWEN_CODE_MEMORY_TEAM=1` / `=0` переопределяет настройку для одного запуска.

### Автоматическая синхронизация git (опционально)

По умолчанию вы делитесь командной памятью через обычный git-воркфлоу (`pull` для получения, `commit`/`push` для отправки). Чтобы Qwen делал это за вас, включите синхронизацию:

```json
{
  "memory": {
    "enableTeamMemory": true,
    "enableTeamMemorySync": true
  }
}
```

При включении, в начале сессии Qwen синхронизирует каталог `.qwen/team-memory/` в режиме best-effort: он перестраивает общий индекс `MEMORY.md`, сначала делает fast-forward pull обновлений соавторов, затем коммитит ваши изменения командной памяти поверх и пушит **только этот коммит синхронизации** (через явный single-branch refspec) — так что загружаемый вами индекс отражает последние данные. Он только **индексирует (stages)** командный каталог (ваши другие рабочие изменения никогда не коммитятся) и никогда не блокирует сессию при сбое git. По умолчанию выключено. `QWEN_CODE_MEMORY_TEAM_SYNC=1` / `=0` переопределяет настройку для одного запуска.

Две вещи, которые нужно знать перед включением:

- **Fast-forward pull действует на всю вашу текущую ветку, а не только на `.qwen/team-memory/`** (в git нет pull с ограничением по пути). Поэтому синхронизация сделает fast-forward вашей ветки до удаленного кончика. Пуш, напротив, ограничен: он публикует **только тот коммит, который только что создала эта синхронизация**, поэтому он никогда не пушит другие ваши незапушенные коммиты — если ваша ветка уже опережает upstream, синхронизация коммитит локально и пропускает пуш. Включайте её на ветках, где fast-forward pull допустим, или запускайте её в отдельном checkout.
- **Расходящаяся ветка остается нетронутой** (`--ff-only` никогда не делает merge). Когда это происходит, синхронизация просто ничего не делает в этой сессии; разрешите расхождение (`git pull`), и она возобновит работу. Ветка без upstream (без конфигурации отслеживания) всё равно коммитит локально, но пропускает пуш — пушить некуда.

## Команды

### `/memory`

Открывает панель Memory. В Web Shell файлы остаются только для чтения, когда их полный текст недоступен, включая файлы, превышающие лимит содержимого, файлы, которые изменяются во время чтения, и файлы с маркером порядка байтов или недопустимым UTF-8. Если файл изменился во время чтения, выберите его вкладку памяти снова, чтобы повторить попытку.

Отсюда вы можете:

- Включать или выключать сохранение auto-memory
- Включать или выключать периодическую очистку (dream)
- Открывать ваш личный QWEN.md (`~/.qwen/QWEN.md`)
- Открывать проектный QWEN.md
- Просматривать папку auto-memory

### `/memory migrate-team`

Мигрирует уровень **командной памяти** (`.qwen/team-memory/`) в формат структурированных метаданных: каждый файл получает frontmatter (имя, описание, категория, ключевые слова, сценарии использования), который нужен для поиска памяти. Личная и проектная память мигрируются автоматически в фоновом режиме, когда включен [структурированный поиск](#структурированный-поиск-opt-in); командная память доступна через git, поэтому переписывание запускается только по явному запросу и появляется как ревьюимый коммит. Запустите один раз на репозиторий в доверенном рабочем пространстве с включенной командной памятью.

### `/init`

Генерирует начальный QWEN.md для вашего проекта. Qwen читает вашу кодовую базу и заполняет команды сборки, инструкции по тестированию и обнаруженные соглашения.

### `/remember <text>`

Немедленно сохраняет что-либо в auto-memory, не дожидаясь, пока Qwen подхватит это автоматически:

```
/remember always use snake_case for Python variable names
/remember the staging environment is at staging.example.com
```

### `/forget <text>`

Удаляет записи auto-memory, соответствующие вашему описанию:

```
/forget old workaround for the login bug
```

### `/dream`

Запускает очистку памяти прямо сейчас, вместо ожидания по автоматическому расписанию:

```
/dream
```

## Внешняя память (`context_search`)

В дополнение к `QWEN.md` и auto-memory, Qwen Code может запрашивать внешние сервисы памяти и локальные индексы сессий через MCP-инструмент `context_search`. В отличие от `QWEN.md` и auto-memory, `context_search` вызывается моделью по запросу — ничего не вспоминается и не отправляется автоматически на каждом ходу:

- **Mem0 (встроенный адаптер):** Настройте `memory.mem0` в `~/.qwen/settings.json` для подключения к Mem0 Platform V3, PolarDB или self-hosted Mem0 OSS. См. [Mem0](./mem0.md) для настройки и опционального подтверждения записи.
- **External Context MCP Profile v1 серверы:** Любой stdio или HTTP MCP-сервер, реализующий контракт `context_search({ query })`, может быть зарегистрирован с помощью `qwen mcp add` или `mcpServers` в `settings.json` (установите `"includeTools": ["context_search"]`, чтобы только `context_search` был доступен для Profile v1 сервера).

Каждая запись регистрирует свой собственный сервер, и более одного могут быть активны одновременно — Qwen предоставляет `context_search` каждого сервера отдельно (например, `mcp__external-context__context_search` и `mcp__deja-context__context_search`) и модель выбирает между ними, поэтому включайте только тот корпус, который вы хотите искать, или укажите бэкенд в вашем запросе.

Какой бы бэкенд вы ни использовали, совпадения, возвращаемые `context_search`, добавляются в контекст Qwen и отправляются провайдеру модели, настроенному для сессии, и вызовы требуют одобрения, если вы их не разрешите — локальный индекс держит поиск локальным, не результаты. В Auto Mode запрос и ограниченная копия аргументов также идут в модель классификатора.

### deja-vu

Локальный CLI и MCP-сервер, который индексирует транскрипты сессий, которые coding-агенты (Qwen Code, Claude Code, Codex, Cursor и другие) уже записывают на диск, используя локальный поиск BM25, без вызовов модели или API-ключей, необходимых для построения или запроса индекса.

- **Репозиторий:** https://github.com/vshulcz/deja-vu
- **Стоимость:** Бесплатно и открыто (MIT)
- **Лучше всего для:** Поиска прошлых сессий через Qwen Code и другие локальные coding-агенты на той же машине

#### Доступные инструменты

- `context_search` — Поиск по индексированным локальным транскриптам сессий (`deja mcp --context-search`)

#### Настройка

1. Установите бинарный файл `deja` (например, `brew install deja-vu`, `npm install -g @vshulcz/deja-vu` или из [GitHub releases](https://github.com/vshulcz/deja-vu/releases)) и постройте начальный индекс (`deja index`).
2. Зарегистрируйте сервер, используя один из методов ниже:

**Метод 1: CLI команда**

```bash
qwen mcp add deja-context deja mcp --context-search --timeout 8000 --include-tools context_search
```

**Метод 2: `settings.json`**

```json
{
  "mcpServers": {
    "deja-context": {
      "command": "deja",
      "args": ["mcp", "--context-search"],
      "timeout": 8000,
      "includeTools": ["context_search"]
    }
  }
}
```

3. Перезапустите Qwen Code, чтобы новый MCP-сервер загрузился при запуске сессии, затем запустите `/mcp`, чтобы подтвердить, что `deja-context` подключен (см. [MCP Servers](./mcp.md)).

Чтобы удалить сервер позже, запустите `qwen mcp remove deja-context` (или удалите запись `deja-context` из `mcpServers` в `~/.qwen/settings.json`) и перезапустите Qwen Code.

## Устранение неполадок

### Qwen не следует моему QWEN.md

Откройте `/memory`, чтобы увидеть, какие файлы загружены. Если вашего файла нет в списке, Qwen его не видит — убедитесь, что он находится в корне проекта или в `~/.qwen/`.

Инструкции работают лучше, когда они конкретны:

- ✓ `Use 2-space indentation for TypeScript files`
- ✗ `Format code nicely`

Если у вас есть несколько файлов QWEN.md с противоречащими друг другу инструкциями, Qwen может вести себя непоследовательно. Проверьте их и удалите любые противоречия.

### Я хочу посмотреть, что сохранил Qwen

Запустите `/memory` и выберите **Open auto-memory folder**. Все сохраненные воспоминания — это читаемые markdown-файлы, которые вы можете просматривать, редактировать или удалять.

### Qwen постоянно всё забывает

Если auto-memory включена, но Qwen, кажется, не запоминает вещи между сессиями, попробуйте запустить `/dream`, чтобы принудительно выполнить очистку. Также проверьте `/memory`, чтобы убедиться, что оба переключателя включены.

Для вещей, которые вы всегда хотите, чтобы Qwen помнил, лучше добавьте их в QWEN.md — auto-memory работает в режиме best-effort, а QWEN.md гарантирует результат.
