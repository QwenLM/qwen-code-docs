# Стили вывода

Стили вывода определяют, как Qwen Code формирует ответы — тон, объём пояснений, степень детализации — не меняя его возможностей. Стиль — это именованный блок инструкций, накладываемый на встроенный системный промпт; модель получает напоминание об активном стиле на каждом ходу, чтобы сохранять его на протяжении длинных сессий.

## Встроенные стили

| Стиль | Описание |
| --- | --- |
| **default** | Без дополнительного стиля — стандартный промпт. |
| **Concise** | Сначала ответ, без вступления, пояснений и итогового резюме. Работа остаётся такой же тщательной; отчёты об ошибках и подтверждения безопасности сохраняют полное содержимое. |
| **Proactive** | Сразу приступает к работе и предпочитает явно сформулированное предположение вопросу при низкорискованных решениях. Не меняет допустимых действий: режим одобрения и правила подтверждения продолжают действовать в полном объёме. |
| **Explanatory** | Добавляет короткие образовательные заметки «Insight» о кодовой базе и решениях по реализации прямо в ходе работы. |
| **Learning** | Совместное обучение на практике: выдаёт небольшие осмысленные фрагменты кода для написания (помеченные `TODO(human)`), затем ждёт. Пропускается в headless-режиме, где ожидание невозможно. |

## Выбор стиля

Выполните `/output-style` для открытия селектора или задайте стиль напрямую:

```
/output-style Concise
/output-style default   # back to no style
```

Изменение вступает в силу немедленно в текущей сессии — системный промпт перестраивается на месте, поэтому следующий ход уже выполняется в новом стиле — и сохраняется для будущих сессий. Если доверенная настройка проекта уже владеет `general.outputStyle`, команда обновляет эту настройку проекта; иначе обновляется пользовательская настройка. Имена стилей регистронезависимы.

Стиль можно задать и без команды:

- **Настройки**: `"general": { "outputStyle": "Concise" }` в `settings.json` (область действия: пользователь или проект). Значение — имя встроенного или [пользовательского](#custom-styles) стиля. Ручное изменение вступает в силу при следующем запуске.
- **Один запуск**: `qwen -p "..." --output-style Concise` переопределяет настройку для этого запуска. См. [Headless Mode](./headless).

## Пользовательские стили

Пользовательский стиль — это Markdown-файл, содержимое которого является инструкциями стиля. Разместите его в одном из двух каталогов:

| Расположение | Область действия |
| --- | --- |
| `~/.qwen/output-styles/<name>.md` | Ваши стили, доступны в каждом проекте |
| `<project>/.qwen/output-styles/*.md` | Стили проекта, читаются только при доверии к рабочему пространству |

Доверие проверяется при каждом использовании стиля, а не только при чтении файла, поэтому отзыв доверия в середине сессии прекращает влияние стиля проекта на разговор.

```markdown
---
name: Reviewer
description: Reviews code and reports findings without editing anything
keep-coding-instructions: false
---

You are reviewing, not implementing. Read the code the user points you at, list concrete findings ordered by severity, and never edit files unless the user asks for a fix.
```

Frontmatter необязателен. Каждое поле имеет значение по умолчанию:

- `name` — имя стиля, используется с `/output-style <name>` и в `general.outputStyle`. По умолчанию — имя файла без `.md`. Значение `default` зарезервировано.
- `description` — однострочное описание, отображаемое в селекторе. По умолчанию — первая строка содержимого.
- `keep-coding-instructions` — `true` сохраняет встроенные инструкции по инженерному рабочему процессу в промпте вместе с вашим стилем; `false` убирает этот раздел, если стиль не связан с написанием кода. Файл без явного указания наследует значение переопределяемого встроенного стиля, поэтому переписывание `concise.md` меняет формулировки, но не убирает эти инструкции; файл, не имеющий встроенного аналога, по умолчанию получает `false`. Всё остальное во встроенном промпте — идентичность, правила безопасности, инструкции по инструментам — действует при любом стиле.

Пользовательские стили отображаются в селекторе `/output-style` после встроенных, с указанием источника, и перечитываются при каждом открытии селектора или указании имени, поэтому новый файл не требует перезапуска. Имена сопоставляются регистронезависимо и должны быть уникальными: стиль проекта переопределяет пользовательский стиль с тем же именем, а любой из них переопределяет встроенный стиль с таким именем. Файл, который не может быть загружен, пропускается и фиксируется в отладочном логе, а остальные файлы продолжают загружаться — пустое содержимое, некорректное имя, файл размером более 25 КБ (стиль — это промпт, а не документ), файл не в кодировке UTF-8 или файл, всё содержимое которого является HTML-комментарием. HTML-комментарии удаляются из содержимого, поэтому заметки для коллег не передаются модели.

Файл стиля может ссылаться только на себя: файл проекта, являющийся символической ссылкой, пропускается; пользовательский файл может быть символической ссылкой на ваш домашний каталог (конфигурация dotfiles), но не за его пределы; жёсткая ссылка запрещена на любом уровне.

Пользовательские стили игнорируются в режимах `--bare` и `--safe-mode`, где используются только встроенные стили.

## Область действия и взаимодействия

- Стиль накладывается на встроенный промпт. Если `--system-prompt` или `QWEN_SYSTEM_MD` полностью заменяет промпт, стиль (и напоминание на каждом ходу) не применяется.
- Стили применяются только к основному разговору. Субагенты используют собственные системные промпты, а пир в арене наследует стиль сессии только если этот стиль сохраняет инструкции по написанию кода — пир оценивается по создаваемому диффу, поэтому он никогда не работает без инженерных инструкций.
- `--bare` и `--safe-mode` игнорируют настройку и не допускают изменений через `/output-style`.
- Смена стиля в середине сессии однократно инвалидирует кэшированный префикс промпта; далее кэширование работает как обычно.

Стили корректируют тон и рабочий процесс, а не знания или разрешения. Для соглашений проекта, которые модель должна знать всегда, используйте контекстные файлы (`QWEN.md`); для разового дополнения промпта используйте `--append-system-prompt`.
