# Доверенные папки

Функция «Доверенные папки» — это параметр безопасности, который даёт вам контроль над тем, какие проекты могут использовать полные возможности Qwen Code. Она предотвращает выполнение потенциально вредоносного кода, запрашивая ваше одобрение папки перед тем, как CLI загрузит из неё какие-либо конфигурации, специфичные для проекта.

## Включение функции

Функция «Доверенные папки» **отключена по умолчанию**. Чтобы использовать её, необходимо сначала включить её в настройках.

Добавьте следующее в файл `settings.json` пользователя:

```json
{
  "security": {
    "folderTrust": {
      "enabled": true
    }
  }
}
```

## Как это работает: диалог доверия

Когда функция включена, при первом запуске Qwen Code из папки автоматически появится диалоговое окно с предложением сделать выбор:

- **Доверять папке**: Предоставляет полное доверие текущей папке (например, `my-project`).
- **Доверять родительской папке**: Предоставляет доверие родительскому каталогу (например, `safe-projects`), что автоматически наделяет доверием все его подкаталоги. Это полезно, если все безопасные проекты хранятся в одном месте.
- **Не доверять**: Помечает папку как недоверенную. CLI будет работать в ограниченном «безопасном режиме».

Ваш выбор сохраняется в центральном файле (`~/.qwen/trustedFolders.json`), поэтому запрос появится только один раз для каждой папки.

Функция работает по принципу fail closed: пока вы не сделаете выбор, папка считается **недоверенной**, а не доверенной по умолчанию. Если этот файл отсутствует — новый компьютер, восстановленный домашний каталог, синхронизированная конфигурация dotfiles — каждая папка, для которой нет сигнала с более высоким приоритетом (см. «Процесс проверки доверия (расширенный)» ниже), начинает как недоверенная, включая папки, которым вы ранее доверяли. Когда проверка доверия доходит до правил файла, нечитаемый файл, некорректный синтаксис JSONC или документ, не являющийся объектом, являются жесткой ошибкой конфигурации. Неудачная загрузка из кэша заставляет CLI остановиться с сообщением «Please fix the configuration file and try again.», а проверки доверия v1 демона отвечают `500 trusted_folders_invalid`; предыдущее решение о доверии из IDE может обойти эти файловые проверки. Средство записи правил всё равно валидирует файл перед сохранением правила. Исправьте или удалите файл вручную, затем перезапустите демон, чтобы сбросить неудачную загрузку. Комментарии и висячие запятые допускаются. Некорректные значения уровня доверия обнаруживаются средством записи правил и читателем политик v2, но не валидируются устаревшим читателем v1; v2 сообщает об ошибках политик как `200` с `configured.state: "error"`. Файл, ставший некорректным после загрузки из кэша, может привести к ошибке при записи правила с `500 internal_error` или при проверке политики после записи с `409 trust_grant_ineffective`.

## Почему доверие важно: последствия работы в недоверенной рабочей области

Когда папка **не является доверенной**, Qwen Code работает в ограниченном «безопасном режиме» для вашей защиты. В этом режиме следующие функции отключены:

1.  **Настройки рабочей области игнорируются**: CLI **не** будет загружать файл `.qwen/settings.json` из проекта. Это предотвращает загрузку пользовательских инструментов и других потенциально опасных конфигураций.

2.  **Переменные окружения игнорируются**: CLI **не** будет загружать файлы `.env` из проекта.

3.  **Управление расширениями ограничено**: Вы **не можете** устанавливать, обновлять или удалять расширения.

4.  **Автопринятие инструментов отключено**: Перед запуском любого инструмента всегда будет появляться запрос, даже если глобально включено автопринятие.

5.  **Автоматическая загрузка памяти отключена**: CLI не будет автоматически загружать файлы в контекст из каталогов, указанных в локальных настройках.

Предоставление доверия папке разблокирует полную функциональность Qwen Code для этой рабочей области.

## Управление настройками доверия

Если вам нужно изменить решение или просмотреть все настройки, у вас есть несколько вариантов:

- **Изменить доверие к текущей папке**: выполните команду `/permissions` внутри CLI. Откроется тот же интерактивный диалог, позволяющий изменить уровень доверия для текущей папки.

- **Доверять рабочей области из веб-оболочки**: откройте обзор рабочих областей и используйте действие **Trust** для недоверенной рабочей области. Это фиксирует то же решение без необходимости в терминале, что является способом восстановления, если все рабочие области оказались недоверенными из-за отсутствия решающего правила. Действие появляется только тогда, когда подключенный демон анонсирует `workspace_trust_grant`, что происходит только там, где горячая перезагрузка доверия применяет решение к работающему runtime — демон, обслуживающий маршруты правил без горячей перезагрузки, скрывает это действие. Там, где действие недоступно, правило доверия, записанное через собственный API демона, обновляет файл доверия и статус доверия v1 немедленно, но гейты runtime, привязанные к запуску, требуют перезапуска. Решение, записанное отдельным процессом терминала или редактированием файла, не сразу видно кэшированному статусу v1 демона; перезапустите демон для его загрузки. Там, где действие доступно, рабочая область становится полностью доверенной после перестройки runtime демоном, что занимает некоторое время.

- **Просмотреть все правила доверия**: чтобы увидеть полный список всех правил для доверенных и недоверенных папок, вы можете просмотреть содержимое файла `~/.qwen/trustedFolders.json` в вашем домашнем каталоге.

## Процесс проверки доверия (расширенный)

Для опытных пользователей полезно знать точный порядок проверки доверия:

1.  **Сигнал доверия от IDE**: Если вы используете [интеграцию с IDE](../ide-integration/ide-integration), CLI сначала запрашивает у IDE, доверена ли рабочая область. Ответ IDE имеет наивысший приоритет.

2.  **Локальный файл доверия**: Если IDE не подключена, CLI проверяет центральный файл `~/.qwen/trustedFolders.json`.
