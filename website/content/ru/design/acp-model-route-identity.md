# Идентичность маршрута модели ACP

## Проблема

Qwen Code сейчас выставляет ID моделей ACP в виде `modelId(authType)`. Две настроенные модели с одним и тем же model ID и типом авторизации, но разными значениями `baseUrl` поэтому схлопываются в один селектор ACP. Клиенты не могут идентифицировать активную строку и вернуть выбор на предполагаемый эндпоинт.

Core уже трактует `(authType, modelId, configured baseUrl)` как идентичность реестра. Потеря происходит только когда эта идентичность пересекает границу ACP. Настроенное значение должно оставаться отдельным от резолвленного эндпоинта, потому что дефолты провайдера могут заполнить `baseUrl` уже после регистрации.

## Дизайн

Строить опции моделей ACP из существующего списка настроенных моделей:

- Сохранять `modelId(authType)`, когда он уникален. Это сохраняет существующие ID для обычного случая.
- Когда несколько опций получили бы такой ID, заменять каждую детерминированным селектором `qwen-route:v1:<digest>`, выводимым из несекретных метаданных модели и публичной идентичности эндпоинта (учетные данные, query и фрагмент удалены).
- Отклонять маршруты, остающиеся неразличимыми после санитизации, вместо использования порядка в массиве, который мог бы переназначить старый селектор после переупорядочивания конфигурации.
- Продолжать использовать `ModelInfo.name` и метаданные провайдера для отображения. ID маршрута — непрозрачный машинный селектор.

Core выставляет исходный опциональный `baseUrl` реестра наряду с резолвленным эндпоинтом для отображения. Один и тот же построитель опций снабжает модели сессий ACP, опции конфигурации, живой статус провайдера и статус провайдера рабочего пространства демона, так что каждый клиент видит один и тот же ID, а сервер сохраняет точный дискриминатор реестра.

На `session/set_model` Qwen Code резолвит селектор по текущему списку настроенных моделей перед переключением. Он передает резолвленный `baseUrl` в Core, затем персистит только канонические значения настроек:

- `model.name`: фактический model ID
- `model.baseUrl`: настроенный эндпоинт реестра, либо пустой tombstone для неявного дефолта
- `security.auth.selectedType`: фактический тип авторизации

Непрозрачный селектор никогда не пишется в `settings.json`.

## Совместимость

- Схема ACP не меняется; `modelId` остается строкой.
- Уникальные существующие model ID сохраняют текущее wire-представление.
- Легаси-запросы `modelId(authType)` остаются принимаемыми. Если такой ID неоднозначен, существующее поведение первого совпадения сохраняется для совместимости; вновь объявленные селекторы точны.
- Неизвестные или устаревшие непрозрачные селекторы отклоняются вместо трактовки их как буквальных model ID.
- Общим ACP-клиентам, включая Zed, достаточно лишь эхо-возвращать непрозрачный селектор.
- Настройки и поведение выбора в CLI TUI не меняются.

## Верификация

- Дублирующие маршруты получают различные, стабильные селекторы без утечки своих URL.
- Состояние модели сессии и опции конфигурации публикуют одни и те же селекторы и точный текущий маршрут.
- Выбор второго маршрута переключается с его `baseUrl`, персистит канонические настройки и уведомляет клиентов его непрозрачным селектором.
- Статус провайдера демона идентифицирует точный текущий маршрут для Web Shell.
- Уникальные и легаси-выборы моделей продолжают работать.
