# Channel Delivery V1

## Цель

Позволить запланированным задачам, промптам демона и прямому Notify API отправлять текст на явную цель IM через Channel Worker, который владеет выбранным рабочим пространством. Доставка немедленная и по мере возможности (best effort): нет долговечного outbox, воспроизведения, повторов или глобального хука финального ответа.

## Публичный контракт

```ts
interface ChannelDelivery {
  kind: 'channel';
  target: {
    channelName: string;
    type: 'user' | 'chat';
    id: string;
  };
}
```

Создание запланированных задач и `POST /session/:id/prompt` принимают опциональный верхнеуровневый `delivery`. Прямое уведомление использует:

```http
POST /workspace/notify
POST /workspaces/:workspace/notify

{
  "text": "alert text",
  "delivery": {
    "kind": "channel",
    "target": {
      "channelName": "dingtalk",
      "type": "user",
      "id": "platform-user-id"
    }
  }
}
```

Демон нормализует публичную цель на своей границе доверия во внутренний запрос воркера `{ deliveryId, channelName, target: { type, id }, text }`. Текст, отправляемый воркеру, должен быть непустым и ограничен 100 000 UTF-16 code units до IPC. Промпт и запланированное reverse-управление могут нести пустую строку только для сообщения об успешном ходе без финального ответа, подлежащего доставке, как `skipped`; этот путь никогда не достигает IPC воркера.

## Границы выполнения

Запланированные задачи и Prompt владеют своей семантикой финального ответа. Session фиксирует текст только когда текущий вызов несет метаданные доставки. Каждая отправка модели владеет одним блоком ответа: non-thought чанки стрима объединяются внутри этого блока, повтор без продолжения или фолбэк модели отбрасывает замещенные чанки, а любой блок, запрашивающий инструмент, является промежуточным и не может стать полезной нагрузкой доставки. Более позднее автоматическое продолжение заменяет более ранний терминальный кандидат. После того как полный ход достигает успешного `end_turn`, Session отправляет ровно один запрос reverse-управления, содержащий только последний свободный от инструментов блок ответа ассистента. Повествование между инструментами и все более ранние блоки ответа исключаются.

Успешный `end_turn` всегда отправляет запрос reverse-управления, в том числе когда финальный блок пуст или содержит только пробельные символы. Демон сначала потребляет закрепленную авторизацию, возвращает `skipped` без резолвинга воркера и публикует событие `channel_delivery_result`. Отмена, неудача агента и завершение по лимиту токенов не отправляют ничего. Пустой вывод поэтому отличим от хода, который никогда не был подлежащим доставке.

Допуск Prompt остается `202`; завершение агента остается `turn_complete` или `turn_error`. Завершение канала — это более позднее событие `channel_delivery_result`, и оно никогда не превращает успех агента в `turn_error`.

Notify обходит Session и агента. Он ждет одну попытку доставки воркером и мапит невалидный ввод в 400, недоступных или заполненных воркеров в 503, таймаут в 504 и сбой адаптера в 502. Таймаут имеет неизвестный исход доставки и не повторяется.

Webhook остается независимым асинхронным путем со своим секретом и контрактом допуска воркера `202`. Он может переиспользовать примитивы отправки и классификацию ошибок `ChannelBase`, но не управляющий поток Prompt/Notify. Фоновые промпты уведомлений остаются работой локального агента и не отправляются автоматически в IM.

## Владение рабочим пространством

Демон привязывает рабочее пространство при построении каждого ACP-бриджа. Допуск Prompt записывает delivery ID, выданный демоном, и закрепленную цель, тогда как запланированная доставка авторизуется из персистентной задачи. Колбэк дочернего процесса должен совпадать с этой авторизацией и не может выбирать `workspaceCwd` или заменять цель. Колбэк хоста потребляет авторизацию до решения между `skipped` и доставкой воркером, поэтому пустые финалы не могут подделать события или оставить состояние одноразовой/монотонной авторизации неизменным. Непустой текст маршрутизируется только в группу воркеров канонического рабочего пространства. Отсутствующие, находящиеся в начальной загрузке, дренируемые, остановленные или удаленные владельцы возвращают `channel_worker_unavailable`; фолбэка на основной рантайм нет, и ленивого запуска воркеров нет.

## Надежность и приватность

Авторизация потребляется до проверки доступности воркера, поэтому временный сбой воркера после потребления навсегда роняет эту единственную доставку; это согласуется с контрактом немедленной, best-effort, без повторов.

Эта V1 не имеет персистентности, воспроизведения при старте, сканирования истории, повторов или гарантий идемпотентности. Существующие задачи без delivery никогда не отправляют. Существующее поведение наверстывания планировщика не меняется. Обычные выполнения несут delivery только когда задача уже содержит его; синтетический батч исторических пропущенных one-shot явно очищает delivery, чтобы более позднее включение Channel не создавало всплеск старых алертов.

V1 наблюдает только Promise отправки канала. Отклонение санитизируется и мапится в `channel_delivery_failed`, за исключением адаптеров, которые уже предоставляют типизированный постоянный disposition — они мапятся в `channel_delivery_rejected`. Разбор ответов специфичных провайдеров и согласованная семантика причин ошибок между адаптерами IM — последующая работа; демон и воркер не содержат платформо-специфичной обработки ошибок.

События и логи результата доставки включают корреляционные идентификаторы, источник, статус и санитизированные данные ошибок. Они никогда не включают текст сообщения, ID целей, учетные данные или секреты webhook. `delivered` означает, что Promise отправки адаптера зарезолвился; это не утверждает, что провайдер принял сообщение или что пользователь получил или прочитал его.

## Возможность (capability)

Демон объявляет `channel_delivery`, когда поддерживает контракты и маршруты. Это поддержка протокола, а не утверждение о живой работоспособности какого-либо воркера или адаптера.
