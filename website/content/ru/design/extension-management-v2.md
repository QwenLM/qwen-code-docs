# Управление расширениями V2

## Статус

Этот дизайн расширяет протокол демона `v1` под аддитивной возможностью
(capability) `extension_management_v2`. Уже опубликованная возможность
`workspace_extensions` и маршруты `/workspace/extensions/*` остаются
доступными как адаптер совместимости основного рабочего пространства.

## Модель ресурсов

Установленное расширение — это один артефакт уровня пользователя в
`QWEN_HOME/extensions`. Активация — это политика, а не вторая копия этого
артефакта:

1. Точное переопределение рабочего пространства (`enabled` или `disabled`).
2. Внутренняя точная маска `inherit`, создаваемая при миграции legacy-правил
   путей.
3. Упорядоченное правило пути V1.
4. Глобальный дефолт.

Идентичность рабочего пространства использует канонический путь рабочего
пространства демона. Маршрут рабочего пространства сначала выбирает
существующий рантайм по id рабочего пространства, а затем по каноническому
cwd. Чтения разрешены для недоверенных рантаймов; изменения активации,
обновление и установка со скоупом рабочего пространства требуют доверенной
цели. Глобальная мутация использует обычную аутентификацию мутаций демона и
согласие на установку, а не состояние доверия того рабочего пространства,
которое инициировало запрос.

## Хранилище и граница транзакций

`ExtensionStore` — единственный писатель финальных каталогов расширений и
состояния активации V2. `ExtensionManager` остается фасадом, обращенным к
рабочему пространству, но CLI, TUI, автообновление, демон и операции на
базе SDK делегируют мутации хранилищу.

Раскладка такова:

```text
~/.qwen/
├── extensions/
└── extension-store/
    ├── lock
    ├── state.json
    ├── state.previous.json
    ├── staging/
    ├── rollback/
    └── transactions/
```

Хранилище и артефакты разделяют файловую систему, поэтому подмена артефактов
— это переименования каталогов. In-process мьютекс и блокировка
`proper-lockfile` сериализуют коммиты между всеми процессами, знающими о V2.
Каждая мутация перечитывает состояние, удерживая блокировку, и
инкрементирует монотонное поколение, предотвращая потерянные обновления.

Подготовка установки/обновления происходит вне финального каталога артефакта.
Коммит пишет журнал `prepared`, перемещает старый артефакт в rollback,
перемещает staging на место и атомарно пишет `state.json`. Это
переименование состояния и есть точка коммита. До него восстановление
откатывается; после него восстановление лишь завершает проекцию и очистку.
Зафиксированная политика никогда не откатывается из-за того, что одно
обновление рантайма не удалось. Если и операция до коммита, и ее rollback не
удаются, вызывающий получает обе ошибки, и журнал остается для fail-closed
восстановления; хранилище не продолжает запись сквозь неоднозначное
состояние артефакта.

Файлы хранилища используют разрешения только-для-владельца и атомарные
записи без следования симлинкам. ID расширений, пути артефактов прямых
потомков, пути транзакций и имена валидируются. Отказы сообщаются с
источниками, из которых удалены креденшалы.

## Миграция V1 и проекция понижения

Первый процесс, знающий о V2, импортирует упорядоченные правила из
`extension-enablement.json`, не материализуя текущее множество
зарегистрированных рабочих пространств как точные переопределения. V2 пишет
совместимую проекцию после каждого коммита состояния и хранит ее хэш в
`state.json`.

Если хэши различаются, порядок изменения определяет направление
восстановления: более старая проекция восстанавливается из авторитетного
состояния V2; проекция, измененная после состояния V2, трактуется как
последовательная запись бинарником пониженной версии и повторно импортируется
с новым поколением. Одновременные писатели V1 и V2, разделяющие один
`QWEN_HOME`, намеренно не поддерживаются.

Очистка публичного переопределения рабочего пространства обычно удаляет
точную запись. Если старое правило пути тогда изменило бы эффективное
значение, хранилище пишет внутреннюю маску `inherit`, чтобы DELETE по-прежнему
означал «наследовать глобальный дефолт».

## API демона

Глобальная поверхность:

```text
GET    /extensions
POST   /extensions/install
POST   /extensions/check-updates
POST   /extensions/:extensionId/update
DELETE /extensions/:extensionId
PUT    /extensions/:extensionId/activation
GET    /extensions/operations/:operationId
```

Установка требует явного согласия и начальной активации:

```ts
type InitialActivation =
  | { scope: 'user' }
  | { scope: 'workspace'; workspaceId: string };
```

Эндпоинт установки демона принимает источники HTTPS Git, GitHub Release и npm
под публичной сетевой политикой. SSH и локальные/link-источники остаются
функциями локального CLI. Обновление сохраняет id расширения, имя манифеста,
настройки и политику активации. «Уже актуально» — это успешный результат
`updated: false`. Удаление идемпотентно и удаляет и артефакт, и политику.

Проекция рабочего пространства:

```text
GET    /workspaces/:workspace/extensions
PUT    /workspaces/:workspace/extensions/:extensionId/activation
DELETE /workspaces/:workspace/extensions/:extensionId/activation
POST   /workspaces/:workspace/extensions/refresh
```

Она намеренно не имеет маршрутов мутации артефактов рабочего пространства.
Записи проекции включают дефолт, точное значение рабочего пространства,
эффективное значение и источник. Желаемое поколение и локально примененное
поколение — поля ответа верхнего уровня.

Потенциально медленные мутации возвращают `202`, `Location` и `Retry-After`.
Запись операции — это локальная память демона, она сохраняет не более 100
терминальных записей и может исчезнуть при перезапуске. Восстановление
каталога/хранилища авторитетно. Таймаут опроса SDK останавливает только
опрос; он никогда не отменяет принятую работу.

Демон допускает не более 10 незавершенных операций расширений. Общедемоновая
FIFO-очередь подготовки выполняет не более двух загрузок, распаковок,
конвертаций или проверок обновления одного расширения одновременно. Установка
и обновление используют явный жизненный цикл `prepare -> commit/dispose`:
подготовка владеет файлами staging и версионируемыми снимками креденшалов, но
не изменяет хранилище, кэш, рантайм или креденшалы, выбранные установленным
артефактом. Подготовленные мутации входят в отдельную FIFO-очередь коммитов с
одной конкурентностью в порядке завершения подготовки. Активация и удаление
входят только в очередь коммитов; check-updates входит только в очередь
подготовки. Ручное обновление сериализуется через очередь коммитов. Его
HTTP-таймаут освобождает эту полосу, чтобы застрявшее обновление рантайма не
могло навсегда заблокировать последующие мутации расширений; уже начатое
обновление все равно может урегулироваться позже. Чувствительные настройки
стейжатся как один атомарный секретный бандл под per-prepare ревизией.
Несекретный селектор записывает эту ревизию и бэкенд secure-хранилища внутри
стейжащегося артефакта, поэтому только коммит выигравшего артефакта
активирует полный бандл. Таким образом, коммит хранилища — это точка
долговечности, и она немедленно освобождает полосу коммитов. Перезагрузка
расширений, legacy-синхронизация настроек per-key, обновление рантайма
менеджера, очистка подготовленных файлов и согласование рантайма демона
выполняются вне нее. Эти post-commit шаги не занимают ни один из слотов,
поэтому последующие коммиты могут продвигаться, пока более раннее поколение
применяется или очищается.

Dispose подготовленной мутации удаляет ее невыбранный снимок креденшалов, а
успешный коммит удаляет ранее выбранный снимок по мере возможности. Жесткое
падение процесса до dispose может оставить недостижимую запись в secure-
бэкенде; ни один селектор артефакта не ссылается на нее, поэтому она не
может стать активной или быть принятой за зафиксированные креденшалы.

Дедлайн подготовки начинается, когда операция впервые получает слот
подготовки, а не пока она ждет. Прерывание распространяется на сетевые
операции и активные потоки сканирования и распаковки архивов. Начатая задача
продолжает занимать свой слот до урегулирования ее базового промиса, даже
если она игнорирует прерывание. Коммит не отменяем. Подготовленные обновления
несут поколение целевого артефакта: несвязанные изменения расширения или
активации безопасно перебазируются, тогда как устаревшее обновление того же
артефакта завершается с `extension_conflict`.

Удаленные npm-метаданные стримятся с лимитом ответа 10 MiB. Архивы npm и
GitHub имеют отдельные лимиты загрузки 100 MiB, дедлайны запросов, лимиты
редиректов и валидацию записей архива до распаковки.

## Согласование рантайма

Успешный коммит инвалидирует локальный статус и обновляет затронутые
рантаймы. Глобальные изменения артефактов/дефолтов согласуют все рантаймы в
этом демоне; точное переопределение рабочего пространства согласует только
свою цель. Согласование рантайма обновляет кэши расширений и навыков,
инструменты расширений, иерархическую память, активные системные инструкции
чата и доступные команды. Неудачный компонент не пропускает оставшиеся
компоненты обновления; RPC сессии сообщает комбинированный отказ после того,
как все компоненты были испробованы. Согласование поколения рантайма
использует общедемоновый FIFO, разделяемый мутациями и опрашивателем
поколений. Мутация резервирует свою позицию в долговечном колбэке коммита,
поэтому более поздние поколения не могут обновить рантайм первыми, даже когда
более ранняя post-commit работа завершается позже.
ACP-бридж ограничивает каждое обновление сессии 30 секундами. Если
агрегированное обновление все равно превышает дедлайн маршрута, контроллер
освобождает полосу коммитов без отмены базового RPC. Применение поколения N
также удовлетворяет ожидателей более старых поколений, поэтому позднее
обновление с низшим поколением не может сдвинуть примененное поколение
назад. Частичный отказ обновления или отказ post-commit перезагрузки/очистки
дает `succeeded_with_warnings` со специфичной для рабочего пространства или
коммитной диагностикой без отката артефакта.

Миграция legacy-рабочих пространств трактует зафиксированный артефакт как
неудачный, только когда его не удалось перезагрузить. Синхронизация
совместимости настроек, очистка или предупреждения обновления рантайма не
запускают повторную попытку для артефакта, который уже долговечно установлен.
Вызывающие обновление получают детали предупреждений; предупреждения
совместимости и очистки используют отдельное состояние `updated with
warnings`, тогда как отказы перезагрузки или обновления рантайма остаются
`updated, needs restart`.

Файловый вотчер расширений наблюдает только `extension-store/state.json` для
поколения политики и продолжает наблюдать содержимое установленных/связанных
расширений на предмет изменений команд, навыков, агентов, хуков и MCP.
30-секундный опрос поколения восстанавливает пропущенные события файловой
системы и ограничивает сходимость для других демонов, разделяющих хранилище.

## Совместимость

`workspace_extensions` остается возможностью для существующей единичной
поверхности. Ее обработчики вызывают тот же менеджер/координатор и
адаптируют ответы: активация проекта становится переопределением основного
рабочего пространства; активация пользователя сохраняет legacy-поведение
очистки правил; глобальная мутация согласует каждый локальный рантайм.
Legacy-эндпоинт операций отображает завершение V2 с предупреждениями обратно
на опубликованный legacy-статус ошибок обновления.

Клиенты должны проверять `extension_management_v2`; ни режим демона, ни
другая возможность рабочего пространства не подразумевают этот API.
Заброшенное предложение `workspace_qualified_extensions` не является частью
протокола.

## Не цели

- Копии артефактов per-workspace.
- Реестр демона или протокол удаленного подтверждения.
- Отмена принятых операций пользователем.
- Одновременные записи старого бинарника и знающего о V2 в один `QWEN_HOME`.
- Удаление адаптера V1 до будущей миграции протокола v2.
