# Профили форков

## Резюме

Добавить слой именованных профилей уровня проекта поверх allowlist исполнения
форков, введенного #8066. Вызывающий может передать `fork_profile: "<name>"`
вместо повторения `fork_tools`; рантайм разрешает
`.qwen/fork-profiles/<name>.md` один раз при запуске и подает полученный
список инструментов в существующий гейт исполнения.

Эта фаза не добавляет нового механизма авторизации. Разрешенный профиль
должен вести себя точно так же, как эквивалентный инлайн-вызов `fork_tools`.

## Формат файла

Профили находятся под корнем активного проекта:

```text
.qwen/fork-profiles/<name>.md
```

Каждый файл содержит YAML frontmatter:

```markdown
---
name: ro-research
tools:
  - read_file
  - grep_search
  - glob
  - mcp__search__*
promptHint: |
  Work read-only. Prefer targeted searches and report evidence.
---
```

`name` и `tools` обязательны. `promptHint` опционален и ограничен 200
символами. Запрошенное имя, имя файла и имя в frontmatter должны совпадать.
Имена имеют длину 2–50 символов и содержат только буквы, цифры, дефисы или
подчеркивания, без начального или конечного разделителя. Файлы профилей —
только frontmatter; непустое Markdown-тело отклоняется, чтобы руководство не
могло быть тихо отброшено. Профиль должен разрешаться в обычный файл внутри
каталога профилей проекта и не может превышать 64 KiB.

Поле `tools` использует точный контракт `fork_tools`. Пустой список остается
deny-all, голый `*` невалиден, а синтаксис wildcard MCP не изменяется.

Скоуп проекта — единственный скоуп поиска в этой фазе. Профили уровня
пользователя, приоритет скоупов, встроенные профили, перечисление профилей и
UI управления отложены. Safe mode и bare mode отклоняют профили проекта,
потому что это локальные кастомизации. Режим AUTO трактует записи в
`.qwen/fork-profiles/` как самомодификацию, поэтому они не могут
использовать обычный быстрый путь редактирования внутри рабочего
пространства.

## Разрешение при запуске

`fork_profile` валиден только с `subagent_type: "fork"` и не может
комбинироваться с `fork_tools` или именованным тиммейтом. Вызов Agent
разрешает профиль до конструирования рантайма форка:

1. Валидировать запрошенное логическое имя до построения пути файловой
   системы.
2. Прочитать соответствующий профиль проекта и строго распарсить его YAML
   frontmatter.
3. Валидировать идентичность имени файла/frontmatter и allowlist
   инструментов.
4. Привязать разобранный профиль к одному снимку запуска и выставить его
   эффективные инструменты и подсказку промпта классификации режима AUTO.
5. Передать клонированный список инструментов как
   `ToolConfig.executionAllowedTools`.
6. Добавить `promptHint`, если он присутствует, к директиве задачи форка
   после кэшируемого префикса, выведенного из родителя. Контролируемый
   проектом текст экранируется и оформляется как руководство после директивы,
   тогда как авторитетное ограничение исполнения остается последним.

Отсутствующие или невалидные профили валят запуск до создания рантайма
агента, хуков, записи фонового реестра или sidecar транскрипта.

## Рантайм и возрождение

Существующий гейт исполнения остается авторитетным. Разрешение профиля не
меняет видимые модели декларации и не обходит обычные разрешения для
разрешенного инструмента.

Разрешенный список инструментов, а не имя или путь профиля, является
политикой на момент запуска. Существующий sidecar
`AgentMeta.executionAllowedTools` хранит его, включая пустой список deny-all.
Холодное возрождение повторно применяет этот снимок к текущей живой
поверхности инструментов и не перечитывает профиль, который мог измениться с
момента запуска.

Промпт задачи запуска уже является частью транскрипта форка, поэтому
разрешенная подсказка промпта следует существующему пути
транскрипта/возрождения без второго поиска профиля.

## Границы

Эта фаза не добавляет паттерны аргументов shell, overlay-файловые системы,
интеграцию `/btw`, автоматическую рефлексию/оркестрацию роя, профили уровня
пользователя или UI CRUD профилей.

Профили форков — это удобство для вызывающего и контролируемый проектом слой
промпта, а не обеспечиваемая администратором песочница. Они могут только
сужать исполняемую поверхность, унаследованную от родителя.
