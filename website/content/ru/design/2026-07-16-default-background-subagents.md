# Субагенты в фоне по умолчанию

## Краткое описание

Одноразовые субагенты верхнего уровня должны по умолчанию выполняться в фоне. Вызывающие стороны, которым нужен инлайновый результат, могут отказаться от этого с помощью `run_in_background: false`. Запуски вложенных субагентов и запуски, привязанные к `working_dir`, принадлежащему вызывающей стороне, остаются операциями на переднем плане, поскольку текущий жизненный цикл фоновых задач не может безопасно вернуть результаты этим вызывающим. Форки и именованные участники Agent Teams сохраняют свое существующее поведение.

## Мотивация

Инструмент Agent уже поддерживает фоновое выполнение для интерактивных, headless и SDK-потребителей, но вызывающие стороны в настоящее время должны запрашивать его через `run_in_background: true` или выбирать агента, объявленного с `background: true`. Это заставляет обычное делегирование по умолчанию блокировать родителя, даже когда родитель мог бы продолжить независимую работу. Сделать фоновое выполнение значением по умолчанию верхнего уровня лучше соответствует рекомендациям инструмента по параллельному делегированию, сохраняя при этом явный аварийный выход на передний план для работы, зависящей от результата.

## Цели

- Запускать одноразовые субагенты верхнего уровня в фоне, когда `run_in_background` опущен.
- Сохранить `run_in_background: false` как явный отказ от фона.
- Сохранить существующие пути уведомления о завершении, отмены, параллельности, разрешений, транскриптов и ожидания в headless.
- Оставить небезопасные или неподдерживаемые формы запуска на их существующем пути на переднем плане.
- Задокументировать влияние на совместимость для навыков и вызывающих сторон, которым нужен инлайновый результат.

## Не цели

- Фоновое выполнение для запусков вложенных субагентов.
- Фоновое выполнение в `working_dir`, принадлежащем вызывающей стороне.
- Изменения наследования контекста форка или жизненного цикла форка.
- Изменения поведения именованных участников Agent Teams.
- Новая глобальная настройка для значения по умолчанию.
- Перепроектирование маршрутизации фоновых уведомлений или владения задачами.

## Поведение

Рантайм разрешает выполнение одноразового субагента в следующем порядке:

1. Именованный участник Agent Teams использует существующий путь участников.
2. Валидный форк верхнего уровня использует существующий отсоединенный путь форков.
3. Вложенный обычный субагент выполняется на переднем плане, даже если был запрошен фон, чтобы его результат вернулся вложенному вызывающему.
4. Обычный субагент с `working_dir` и без настроенного значения по умолчанию фона выполняется на переднем плане, поскольку вызывающий владеет жизненным циклом этого worktree. Явный или настроенный запрос фона остается невалидным.
5. Для любого другого обычного субагента верхнего уровня:
   - `run_in_background: false` выполняется на переднем плане.
   - `run_in_background: true` выполняется в фоне.
   - опущенный `run_in_background` выполняется в фоне.

Существующий frontmatter `background: true` уровня агента по-прежнему принимается для совместимости. Он больше не нужен для получения нового значения по умолчанию верхнего уровня. Явное значение вызова инструмента `run_in_background: false` имеет приоритет и выбирает путь на переднем плане.

## Реализация

Решение о диспетчеризации остается в инструменте Agent, чтобы каждый потребитель получал одно и то же поведение. Фоновое решение должно различать три понятия:

- отказался ли вызывающий явно;
- является ли запуск верхнеуровневым;
- может ли форма запуска безопасно отсоединиться.

Реализация должна переиспользовать существующую фоновую ветку, а не добавлять второй путь запуска. Текст схемы инструмента и рекомендации по использованию для модели должны описывать фон как значение по умолчанию и говорить вызывающим передавать `run_in_background: false`, когда им нужен результат инлайн.

Исключение `working_dir` должно разрешаться до существующего гейта несовместимости. Опущенный параметр фона не должен превращать ранее валидные привязанные запуски ревью в ошибки. Явный `run_in_background: true` или агент, настроенный с `background: true`, остается несовместимым с `working_dir`, сохраняя существующую проверку безопасности.

## Поток результатов

Запуск в фоне по умолчанию немедленно возвращает родителю существующий ответ фонового запуска. Отсоединенная задача остается зарегистрированной в существующем реестре фоновых задач. Когда она завершается, реестр выпускает существующее уведомление о завершении, сбое или отмене, и родитель обрабатывает результат в более позднем ходе. Новый формат сообщений или событие SDK не вводятся.

Отказы в пользу переднего плана продолжаются через существующую синхронную ветку и возвращают санированный результат субагента инлайн.

## Документация

Руководство пользователя субагентов должно указывать, что именованные одноразовые субагенты на верхнем уровне по умолчанию выполняются в фоне, и объяснять `run_in_background: false`. Сравнение с форками должно фокусироваться на наследовании контекста и семантике результатов, а не утверждать, что все именованные субагенты блокируют родителя.

## Тестирование

Юнит-покрытие должно проверить:

- обычный субагент верхнего уровня с опущенным флагом запускается в фоне;
- `run_in_background: false` возвращает результат инлайн;
- `run_in_background: true` сохраняет существующее фоновое поведение;
- вложенный запуск с опущенным или истинным флагом остается на переднем плане;
- запуск с `working_dir` и опущенным флагом остается на переднем плане;
- явный запрос фона с `working_dir` по-прежнему отклоняется;
- поведение форков и именованных участников остается неизменным;
- схема инструмента и рекомендации по использованию анонсируют новое значение по умолчанию и отказ.

Существующие тесты, намеренно проверяющие ветку переднего плана, должны передавать `run_in_background: false`, чтобы их ожидание было явным. Сфокусированный тестовый файл инструмента Agent, сборка и typecheck обязательны перед отправкой. Ручная интерактивная E2E-проверка должна подтвердить, что обычное делегирование немедленно возвращает управление и позже доставляет уведомление о завершении, тогда как явное делегирование на передний план блокирует и возвращает результат инлайн.

## Риски и совместимость

Изменение ломает поведение для промптов, навыков и программных вызывающих, которые опускают флаг и предполагают, что ответ инструмента Agent содержит результат субагента. Такие вызывающие должны передавать `run_in_background: false`.

Фоновое выполнение по умолчанию также может увеличить параллельную работу. Существующие глобальные лимиты параллельности и постановка в очередь остаются контролирующими гарантиями. Обработка разрешений, завершение работы и ожидание в headless уже используют устоявшийся жизненный цикл фоновых задач и этим дизайном не меняются.
