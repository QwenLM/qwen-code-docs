# Порог предзагрузки ToolSearch

## Проблема

Отложенные инструменты (`shouldDefer=true`) безоговорочно скрываются за
ToolSearch: каждый инструмент MCP (жёстко задано в `DiscoveredMCPTool`) плюс
набор встроенных бандл-инструментов (web_search, web_fetch, cron, monitor,
worktree, …). Откладывание экономит токены промпта, когда отложенный набор
велик, но это не бесплатно: каждое раскрытие посреди сессии переписывает
список деклараций функций, который находится в начале префикса
tools→system→messages, поэтому одна загрузка через ToolSearch инвалидирует
весь KV-кэш промпта. Для малого отложенного набора откладывание экономит
немного, а повреждение кэша плюс дополнительный round trip через ToolSearch
делают его чистым убытком.

Claude Code моделирует этот компромисс через `ENABLE_TOOL_SEARCH=auto` /
`auto:N`: «инструменты загружаются сразу, если помещаются в 10% окна
контекста, иначе откладываются»
(code.claude.com/docs/en/agent-sdk/tool-search). Это изменение добавляет
эквивалентный гейт.

## Дизайн

Новая настройка `tools.toolSearch.threshold` (число, проценты, по умолчанию
`10`).

На старте сессии (`GeminiClient.startChat`, до резолва напоминания об
отложенных инструментах), когда ToolSearch зарегистрирован и порог > 0:

- Оценить суммарный токен-объём схем всех отложенных инструментов — как
  бандл-встроенных, так и MCP
  (`JSON.stringify(tool.schema).length / CHARS_PER_TOKEN`).
- Если сумма помещается в `threshold`% окна контекста
  (`contentGeneratorConfig.contextWindowSize`, с фолбэком на
  `tokenLimit(model)`), раскрыть их все через существующий механизм
  `revealDeferredTool`. Всё или ничего — частичное раскрытие оставило бы
  произвольное подмножество за ToolSearch, а любой оставшийся отложенным
  инструмент всё равно может сломать кэш при первом использовании.
- Иначе всё остаётся отложенным (прежнее поведение). `threshold: 0`
  безоговорочно восстанавливает старое поведение.

Предзагруженные инструменты таким образом попадают в начальный список
деклараций, отфильтровываются из стартового напоминания об отложенных
инструментах, и список деклараций остаётся стабильным на всю сессию.

## Решения

- **Только на старте сессии, никогда в `setTools()`.** Раскрытие инструмента,
  уже объявленного стартовым напоминанием, заставило бы
  `queueAddedMcpToolsReminder` пометить его как «удалённый», а изменение
  деклараций посреди сессии ломает именно тот кэш, который предзагрузка
  призвана защищать. Инструменты серверов, подключающихся позже, остаются
  отложенными (объявляются напоминанием о добавленных инструментах, доступны
  через ToolSearch) до следующего старта сессии. `/clear` очищает раскрытый
  набор и перезапускает решение.
- **Один бюджет на весь отложенный набор, включая бандл.** Автоматический
  порог Claude Code покрывает только инструменты MCP/SDK (его встроенные
  управляются отдельно), но он может позволить себе такое разделение:
  отложенные инструменты вычищаются из префикса промпта до вычисления ключа
  кэша, а определение обнаруженного инструмента разворачивается инлайн через
  блок `tool_reference` — «префикс не трогается, поэтому кэширование промпта
  сохраняется»
  (platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool).
  Здесь каждое раскрытие — бандл или MCP — проходит через `setTools()` и
  переписывает список деклараций. Исключение ~14 бандл-отложенных
  инструментов (web_search, web_fetch, …) оставило бы префикс в одной
  обычной загрузке инструмента от полного сброса кэша, перечёркивая именно ту
  стабильность, которую покупает предзагрузка. Когда объединение превышает
  бюджет, всё остаётся отложенным, что соответствует допороговому baseline
  для бандл-инструментов.
- **Порог по умолчанию 10 (auto-режим включён), в отличие от Claude Code.**
  Не заданный по умолчанию порог Claude Code держит инструменты MCP всегда
  отложенными и делает `auto` включаемым явно — там это допустимо, поскольку
  первое использование отложенного инструмента не стоит инвалидации кэша.
  Здесь оно стоит полной пересборки префикса, поэтому гейт в auto-стиле
  включён по умолчанию; `threshold: 0` воспроизводит поведение Claude Code с
  постоянным откладыванием.
- **Уже раскрытые инструменты учитываются в бюджете**, чтобы повторные старты
  сессии (сжатие также проходит через `startChat`) не могли наращивать
  раскрытый набор за пределы бюджета по мере подключения и отключения
  серверов.
- **Без предзагрузки, когда ToolSearch недоступен** — существующая ветка
  немедленного раскрытия в `resolveDeferredToolsForReminder` уже показывает
  всё.
