# Метрики тайминга генерации в `/stats`

> Позднее выравнивание по GenAI добавляет независимый
> Span-атрибут `gen_ai.response.time_to_first_chunk` рядом с существующим
> приватным `ttft_ms`. Поток данных `ApiResponseEvent.ttft_ms` и семантика
> первого видимого пользователю вывода из этого документа остаются без изменений;
> `/stats` не потребляет стандартный атрибут первого чанка.

## Контекст

Issue #4252 просит `/stats` показывать тайминг генерации отдельно от
wall time сессии и end-to-end задержки API. Низкоуровневый тайминг уже существует:

- `LoggingContentGenerator` измеряет `ttftMs` от отправки запроса до первого
  видимого пользователю стримингового чанка.
- `endLLMRequestSpan` выводит `sampling_ms` и
  `output_tokens_per_second`.
- `ApiResponseEvent` уже несет длительность запроса, модель, prompt id и
  количество выходных токенов в `UiTelemetryService`.

Недостающее звено — сделать существующее значение TTFT доступным для
метрик сессии без учета контента, которые использует `/stats`.

## Область

Это изменение добавляет живые метрики генерации с областью действия сессии:

- интерактивная вкладка Session в `/stats`;
- неинтерактивный текстовый ответ `/stats`.

Оно не добавляет второй таймер, не сохраняет тайминг в ежедневных/ежемесячных
файлах использования токенов, не меняет экспорты и не меняет схему статистики
демона/Web Shell.

## Поток данных

```text
LoggingContentGenerator.loggingStreamWrapper
  -> ApiResponseEvent(ttft_ms)
  -> logApiResponse
  -> UiTelemetryService
  -> SessionMetrics.generation
  -> SessionContext
  -> /stats
```

`ttft_ms` опционален. Нестриминговые ответы и стримы, завершающиеся без
видимого пользователю контента, сохраняют текущее поведение и не создают
сэмпл генерации.

## Метрики и семантика

Для каждого успешного стримингового ответа с TTFT:

- **TTFT** — существующее измерение `ttftMs`.
- **Время генерации** — `max(0, duration_ms - ttft_ms)`, измеряется от
  первого видимого пользователю стримингового контента до завершения.
- **TPS** — `output_token_count / generation_time_seconds`. Недоступен,
  когда время генерации равно нулю.

`SessionMetrics.generation` создается лениво и содержит:

- модель, TTFT, время генерации и количество выходных токенов последнего
  завершенного запроса;
- общее количество запросов с таймингом и TTFT, а также время генерации и
  выходные токены для запросов, пригодных для учета пропускной способности.

Средний TTFT сессии — арифметическое среднее по запросам с таймингом. TPS
сессии — взвешенная пропускная способность: суммарные выходные токены,
деленные на суммарное время генерации. Запросы с нулевым временем генерации
вносят вклад в статистику TTFT, но не в обе стороны вычисления TPS сессии.
Это избегает деления на ноль и перевешивания коротких запросов.

Внутренние вспомогательные промпты исключаются из метрик генерации. Они не
записываются в возобновляемый транскрипт, и их включение одновременно удивило
бы пользователей и рассинхронизировало бы значения живой и возобновленной
сессии. Запросы основного разговора и субагентов остаются включенными,
соответствуя существующей статистике моделей на уровне сессии.

## Совместимость

- `ApiResponseEvent.ttft_ms` и `SessionMetrics.generation` аддитивны и
  опциональны.
- Существующие записанные события и вызывающие стороны остаются валидными.
- Существующие ежедневные/ежемесячные записи продолжают содержать только
  данные о токенах и длительности API, сохраняя границу владения,
  задокументированную в `issue-4479-token-usage-stats-coordination.md`.
- Логика клонирования/сравнения Session context копирует и сравнивает
  опциональный объект generation, чтобы интерактивный дашборд обновлялся при
  каждом завершенном запросе с таймингом.

## Верификация

- Основные тесты доказывают агрегацию, исключение внутренних промптов,
  обработку нулевой генерации, изоляцию сессий и поведение сброса.
- Тесты LoggingContentGenerator доказывают, что захваченный TTFT попадает в
  `ApiResponseEvent` и отсутствует для невидимых стримов.
- Тесты CLI доказывают неинтерактивный вывод и рендер интерактивной вкладки Session.
- Тесты i18n покрывают все встроенные локали для новых заметных лейблов.
