# Выравнивание полей GenAI и ARMS

## Область действия и baseline стандартов

Этот дизайн выравнивает первый набор атрибутов спанов Qwen Code, чьи имена,
типы и смысл совпадают между семантическими конвенциями OpenTelemetry GenAI и
Alibaba Cloud ARMS LLM Trace. Он не меняет имена спанов, виды спанов,
родительские связи или топологию повторных попыток.
Он также документирует включаемое явно расширение идентификации конечного
пользователя только для ARMS.

Конвенция OpenTelemetry GenAI все еще находится в статусе Development. Это
изменение привязано к коммиту
[`2e994c6d59a93bb4fc1752c5378eedb9b8e14d6b`](https://github.com/open-telemetry/semantic-conventions-genai/tree/2e994c6d59a93bb4fc1752c5378eedb9b8e14d6b):

- [Спаны инференса](https://raw.githubusercontent.com/open-telemetry/semantic-conventions-genai/2e994c6d59a93bb4fc1752c5378eedb9b8e14d6b/docs/gen-ai/gen-ai-spans.md)
- [Спаны агента](https://raw.githubusercontent.com/open-telemetry/semantic-conventions-genai/2e994c6d59a93bb4fc1752c5378eedb9b8e14d6b/docs/gen-ai/gen-ai-agent-spans.md)
- [Реестр GenAI](https://raw.githubusercontent.com/open-telemetry/semantic-conventions-genai/2e994c6d59a93bb4fc1752c5378eedb9b8e14d6b/model/gen-ai/registry.yaml)

Стриминговые атрибуты — узкое дополнение, привязанное к
[OpenTelemetry Semantic Conventions v1.41.0](https://github.com/open-telemetry/semantic-conventions/blob/v1.41.0/docs/gen-ai/gen-ai-spans.md).
Это дополнение принимает только `gen_ai.request.stream` и
`gen_ai.response.time_to_first_chunk`; это не полное обновление baseline,
описанного выше.

Baseline ARMS — [определения полей LLM Trace](https://help.aliyun.com/zh/arms/application-monitoring/developer-reference/llm-trace-field-definition-description).
Обновление любого из двух baseline требует повторной генерации и проверки этой
матрицы.

`gen_ai.response.finish_reasons` теперь сохраняет сырые строки провайдера для
всех кандидатов вместо прежних нормализованных для Gemini значений. Существующие
запросы, фильтрующие значения вроде `STOP` или `MAX_TOKENS`, должны мигрировать
на значения провайдера, такие как `stop`, `length`, `tool_calls` или `end_turn`.

`gen_ai.response.time_to_first_chunk` использует монотонный таймер от момента
непосредственно перед обернутым вызовом провайдера до первого нормализованного
`GenerateContentResponse`, наблюдаемого `LoggingContentGenerator`. Адаптеры
провайдера могут фильтровать или объединять сырые кадры протокола до того, как
они достигнут обертки логирования, поэтому кадры, отброшенные адаптером
(например, фильтр пустых ответов пайплайна OpenAI), исключаются из этого
измерения, и записанное значение может быть позже истинного первого сетевого
кадра. Нормализованные ответы только с метаданными и только с usage, прошедшие
фильтрацию адаптера, считаются чанками. Атрибут сохраняется, если стрим позже
падает, прерывается или истекает по таймауту, и пропускается, если ни один чанк
не прибыл.

Внутренний таймер `ttftMs` остается задержкой первого видимого пользователю
вывода и продолжает управлять `ApiResponseEvent.ttft_ms`, `sampling_ms`,
`output_tokens_per_second` и метрикой разбивки API-запросов. Поэтому
`duration_ms - gen_ai.response.time_to_first_chunk * 1000` не равно
`sampling_ms`.

Существующие запросы к стриминговым спанам должны заменить
`llm_request.stream=true` на `gen_ai.request.stream=true`; нестриминговые
спаны определяются отсутствием `gen_ai.request.stream` (старый фильтр
`llm_request.stream=false` теперь не находит ни одной строки). Спан `ttft_ms`
остается доступным для задержки первого видимого пользователю вывода;
`gen_ai.response.time_to_first_chunk` — независимый стандартный атрибут,
измеряющий задержку первого нормализованного чанка в секундах.

## Определение провайдера и операции

Определение — чистая функция над эффективной конфигурацией генератора контента.
Она никогда не возвращает URL, credential, произвольный hostname прокси или
значение, выведенное из имени модели.

1. Qwen OAuth и точное совпадение `DASHSCOPE_PROXY_BASE_URL` определяются как
   `dashscope`.
2. Безопасное к границам сравнение hostname распознает эндпоинты Alibaba Model
   Studio и внутренние шлюзы Alibaba, Azure OpenAI и поддерживаемые сторонние
   эндпоинты (DeepSeek, xAI, Mistral, MiniMax, Z.AI, ModelScope, MiMo,
   OpenRouter и Requesty).
3. Если host неизвестен, известный `apiKeyEnvKey` определяет настроенного
   провайдера. При конфликте побеждает идентичность host.
4. Неизвестные эндпоинты откатываются к провайдеру протокола: `openai`,
   `anthropic`, `gcp.gemini` или `gcp.vertex_ai`.

Запросы OpenAI-совместимого, Anthropic и Qwen OAuth используют операцию `chat`.
Запросы Gemini и Vertex AI используют `generate_content`.

## Параметры запроса

Атрибуты запроса собираются после того, как адаптеры провайдера применили
значения по умолчанию, переопределения, удаление неподдерживаемых полей и
ограничения окна вывода, непосредственно перед вызовом SDK провайдера. Это
финальный объект SDK-запроса, видимый Qwen Code, а не исходная логическая
конфигурация или сериализованное HTTP-тело. Логический спан LLM записывает
только первый такой снимок запроса.

| Стандартный атрибут                  | OpenAI-совместимый и Qwen OAuth                          | Anthropic          | Gemini и Vertex AI        |
| ---------------------------------- | ---------------------------------------------------------- | ------------------ | ------------------------- |
| `gen_ai.request.choice.count`      | `n`                                                        | Неприменимо     | `config.candidateCount`   |
| `gen_ai.request.max_tokens`        | `max_tokens`, `max_completion_tokens` или `max_new_tokens` | `max_tokens`       | `config.maxOutputTokens`  |
| `gen_ai.request.temperature`       | `temperature`                                              | `temperature`      | `config.temperature`      |
| `gen_ai.request.top_p`             | `top_p`                                                    | `top_p`            | `config.topP`             |
| `gen_ai.request.frequency_penalty` | `frequency_penalty`                                        | Сейчас не отправляется | `config.frequencyPenalty` |
| `gen_ai.request.presence_penalty`  | `presence_penalty`                                         | Сейчас не отправляется | `config.presencePenalty`  |
| `gen_ai.request.stop_sequences`    | `stop`                                                     | `stop_sequences`   | `config.stopSequences`    |

Конечные числа и безопасные целые сохраняются точно, включая ноль и
отрицательные значения на неудачных запросах к провайдеру. Choice count
пропускается, когда он равен единице. Stop sequences должны быть полным
массивом строк; однострочная форма OpenAI нормализуется в массив из одного
элемента. Пустые массивы сохраняются, а смешанные массивы пропускаются целиком
вместо фильтрации. Явные значения по умолчанию адаптера записываются, тогда как
неявные значения по умолчанию SDK или сервера не выводятся.

Когда присутствуют несколько алиасов бюджета вывода OpenAI-совместимого
провайдера, стандартный максимум выставляется только если все присутствующие
значения являются валидными безопасными целыми и равны. Конфликтующие значения
пропускаются, потому что совместимые эндпоинты не имеют общего правила
приоритета.

## Контент и payload инструментов

Чувствительный контент GenAI собирается только когда включен
`telemetry.includeSensitiveSpanAttributes`. Qwen Code не читает
`OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT`, поэтому существует
единственный переключатель захвата контента. Адаптеры OpenAI-совместимого,
Anthropic, Gemini и Vertex преобразуют свои финальные для провайдера объекты
SDK-запроса и структуры сырого ответа в JSON-схемы, привязанные этим дизайном.

Первая физическая попытка запроса предоставляет входные сообщения, системные
инструкции и определения инструментов. Ответы привязаны к генерации: фолбэк
провайдера или повторная попытка required-thinking начинает новый аккумулятор
ответа, а поздние чанки от более старой попытки игнорируются. Стриминговые
аккумуляторы сохраняют канонические части, а не сырые чанки. Частичные сбои
помечают незавершенных кандидатов как `error`; успешный ответ с кандидатом, у
которого нет явной причины завершения, пропускает полный атрибут выходных
сообщений.

Каждый JSON-атрибут компактно сериализуется и независимо ограничивается
`telemetry.sensitiveSpanAttributeMaxLength`. Невалидные, циклические, неполные
или превышающие размер значения атрибутов пропускаются целиком; JSON никогда не
усекается. Внутри `gen_ai.tool.definitions` `type` и `name` — обязательные
идентификаторы, поэтому невалидный идентификатор пропускает атрибут целиком.
`parameters` опционален в стандартной схеме; когда предоставленная провайдером
схема параметров не может быть нормализована в Draft-07, пропускается только
это опциональное свойство, а упорядоченный список идентификаторов инструментов
сохраняется. Пустые массивы и объекты сохраняются, когда провайдер явно
отправляет или возвращает их. При лимите по умолчанию 1 MiB теоретический
максимум на стороне приложения составляет около 4 MiB чувствительных атрибутов
на спан LLM и 2 MiB на спан Tool. Коллекторы и бэкенды могут налагать меньшие
лимиты.

Аргументы инструмента захватываются из параметров последней invocation
непосредственно перед исполнением, после хуков разрешения и редактирования.
Результат инструмента захватывается только после успешного вызова и успешной
постобработки, из финального объекта `FunctionResponse.response`, возвращаемого
модели. Оба корня должны быть JSON-объектами. `gen_ai.tool.description`
берется из статического описания реестра и не является чувствительным; оно
ограничено 4096 кодовыми единицами UTF-16, сохраняет суррогатные пары и
добавляет `…[truncated]` при укорачивании. Описания агента и ошибки спанов
сохраняют свои лимиты в 1024 единицы.

## Происхождение ответов и usage

Конвертеры провайдера прикрепляют внутреннее происхождение к нормализованным
объектам usage Gemini через `WeakMap`. Она записывает, действительно ли
присутствовало поле чтения кэша, и токены создания кэша Anthropic. Это
сохраняет публичную JSON-форму ответа и позволяет сборке мусора следовать за
нормализованным объектом usage.

Когда OpenAI-совместимый провайдер сообщает только `total_tokens`,
нормализованная сумма остается доступной существующим внутренним потребителям,
но разбиение на input/output не синтезируется и ни один стандартный атрибут
usage не выставляется.

OpenAI `response.model`/`chunk.model` и модель сообщения Anthropic сохраняются
как `modelVersion`. Отсутствующая модель провайдера остается отсутствующей для
трассировки; фолбэк на модель запроса остается ограниченным существующими
API-логами и поведением UI. Слияние стримов переносит последнюю известную
модель провайдера и происхождение usage в терминальный ответ. Вход и
использование кэша Anthropic `message_start` прикрепляются к первому
последующему выданному чанку, чтобы частичные сбои стрима сохраняли
сообщенный провайдером usage без синтеза количества вывода.

## Конфигурация ARMS

Автоматическое распознавание GenAI-приложений в ARMS требует этот ресурсный
атрибут:

```json
{
  "telemetry": {
    "resourceAttributes": {
      "acs.arms.service.feature": "genai_app"
    }
  }
}
```

Qwen Code не внедряет этот vendor-специфичный ресурсный атрибут или
`gen_ai.span.kind`. ARMS может выводить роли LLM, Tool и Agent из
`gen_ai.operation.name`.

### Расширение идентификации конечного пользователя ARMS

`gen_ai.user.id` — общий атрибут спана ARMS, не часть привязанного baseline
OpenTelemetry GenAI выше. Qwen Code выставляет его только когда оператор явно
настраивает `telemetry.userId` или `QWEN_TELEMETRY_USER_ID`. Значение
помещается на спан взаимодействия при создании и распространяется через
существующий внутрипроцессный контекст на спаны LLM, Tool и Agent, включая
форки/фоновые агенты с привязанным корнем. Продолжения результата инструмента
разрешают то же логическое взаимодействие по prompt ID без изменения
родительских связей спана; эта минимальная запись идентификации истекает вместе
с существующим 30-минутным TTL страховочной сети спанов.

Значение никогда не выводится, не генерируется, не записывается в
Resource/логи/метрики и не помещается в исходящий Baggage. Qwen Code не
использует двойную запись `enduser.id` или `user.id`. Прежний
`telemetry.resourceAttributes.user.id` остается общей ресурсной размерностью и
должен быть удален явно при миграции. Поскольку настройка действует на весь
процесс, она поддерживается только когда один процесс представляет одного
конечного пользователя; идентификация на уровне запроса для развертываний
общего демона и каналов отложена до тех пор, пока их доверенная идентичность
вызывающего не будет прошита сквозным образом.

## Отложенная работа

- `seed` и `top_k` имеют несовместимые типы ARMS и GenAI в baseline.
- Embedding требует корректного жизненного цикла запрошенной модели перед
  трассировкой.
- Time-to-first-token в ARMS и time-to-first-chunk в OpenTelemetry различаются
  именем, единицей и смыслом. Qwen Code выставляет стандартный
  `gen_ai.response.time_to_first_chunk` рядом с приватным `ttft_ms` и не
  обещает автоматическое заполнение дашборда первого токена ARMS.
- Полное именование спанов GenAI, вид спанов CLIENT и логическая топология
  повторных попыток — отдельный проект соответствия.
