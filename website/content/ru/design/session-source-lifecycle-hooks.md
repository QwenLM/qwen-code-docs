# Источник сессии в lifecycle-хуках

## Контекст

Создание сессии демона уже передаёт опциональные значения `sourceType` и
`sourceId` в ACP через `_meta['qwen.session.source']`. ACP-рантайм сейчас
использует тип источника, чтобы отключать нативный cron для сессий каналов, но
payload'ы lifecycle-хуков не могут наблюдать ни одно из этих значений. Поэтому
получатели не могут атрибутировать новую сессию, когда `SessionStart`
срабатывает раньше, чем бридж сохраняет её источник.

## Дизайн

Один раз разобрать существующие метаданные источника на границе ACP-сессии.
Сохранить две опциональные строки в `Config` сессии рядом с id сессии и другим
состоянием сессионного уровня, и предоставить read-only геттеры.

Обработчик событий хуков добавляет присутствующие значения источника в свой
общий входной объект:

- `sourceType` становится `source_type`.
- `sourceId` становится `source_id`.

Условные object spread'ы опускают отсутствующие значения вместо сериализации
пустых или undefined полей. Поскольку каждое lifecycle-событие использует общий
конструктор входного объекта, `SessionStart`, `UserPromptSubmit`, `Stop` и
`SessionEnd` получают одинаковую атрибуцию без специфичной для события
обвязки.

## Границы

Это сквозное чтение существующих метаданных создания. Не меняются REST-запрос
создания, ключ метаданных ACP-бриджа, согласование возможностей (capability),
персистентность сессии или поведение resume. Сессия, созданная без метаданных
источника, сохраняет прежнюю форму payload'а хуков.

## Проверка

- Тесты обработчика хуков покрывают присутствующие и отсутствующие поля
  источника в payload'ах `SessionStart`.
- Тесты ACP-сессии покрывают проброс метаданных источника канала в `Config`
  сессии.
- Существующие тесты channel worker продолжают покрывать метаданные создания,
  включая имя экземпляра канала как `sourceId`.
