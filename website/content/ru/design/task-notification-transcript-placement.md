# Размещение уведомлений задач в транскрипте

Завершения фоновых задач — это входные данные модели, а не промпты, созданные
пользователем. Живой путь демона уже идентифицирует их через
`_meta.source = "background_notification"`, но воспроизведение истории ранее
проецировало персистентные записи уведомлений как немаркированные сообщения
пользователя.

Воспроизведение истории сохраняет персистентную роль входа модели, добавляя при
этом тот же маркер источника, который используется живыми уведомлениями.
Адаптер транскриптов Web Shell отображает этот источник — из чанка user или
assistant — в информационное системное сообщение. Новые записи также сохраняют
существующий структурированный статус задачи, чтобы живые и воспроизведённые
сообщения использовали одну и ту же метку completed, failed или cancelled;
более старые записи откатываются к общей метке уведомления. Содержимое
уведомления отображается без изменений рядом с семантической иконкой статуса.
Это оставляет и живые, и воспроизведённые уведомления видимыми слева, не меняя
общую семантику воспроизведения для других потребителей.
