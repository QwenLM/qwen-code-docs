# Контракт публикации канала GitHub

## Цель

Сделать ответы канала GitHub безопасными для автоматической публикации и
трассируемыми постфактум. Канал публикует только финальный ответ агента через
адаптер; промежуточные рассуждения, вывод инструментов и стриминговые чанки
никогда не становятся комментариями GitHub.

## Контракт

- Адаптер GitHub отключает блочный стриминг, поэтому каждое принятое входящее
  событие порождает максимум одну попытку доставки финального ответа.
- Финальная доставка использует тред issue/PR активного промпта вместо
  потенциально устаревшей цели общей сессии.
- Инструкции канала говорят агенту не использовать `gh` или GitHub API для
  создания комментариев или ревью. Публичной доставкой владеет адаптер.
- Финальный ответ, чей обрезанный контент состоит только из sentinel
  `<no-reply/>`, намеренно подавляется. Пробельные символы, регистр, пробел
  перед `/>` и единственная оборачивающая код-ограда нормализуются; любой
  другой контент публикуется без изменений.
- Подавление и публикация записываются в локальный append-only JSONL-файл
  аудита в `~/.qwen/channels/<workspace-scope>/<channel>-<name-hash>-github-audit.jsonl`.
  Записи содержат время, канал, сессию, исходное сообщение, тред, исход,
  идентичность/URL комментария GitHub, когда присутствуют, и SHA-256 плюс
  количество символов ответа. Они никогда не содержат текст ответа,
  учетные данные или токен GitHub.
- Записи аудита выполняются по мере возможности (best effort). Сбой аудита
  логируется без изменения результата публикации. Неоднозначный сбой GitHub
  API остается сбоем доставки и не повторяется; определенные ответы без
  записи записываются в приватный файл ожидающих доставок и повторяются при
  следующем старте канала.

## Поток

1. Адаптер GitHub диспетчеризует принятое событие в `ChannelBase`.
2. Активный промпт держит входящее сообщение и тред issue/PR доступными до
  завершения финальной доставки.
3. Агент возвращает один финальный ответ.
4. Адаптер либо подавляет точный sentinel, либо создает один комментарий
   issue.
5. Адаптер добавляет запись аудита публикации. Терминальным жизненным циклом
   задачи по-прежнему владеет `ChannelBase`.
6. Если финальная доставка не удалась с определенным ответом без записи,
   адаптер сохраняет финальный текст в
   `~/.qwen/channels/<workspace-scope>/<channel>-<name-hash>-github-pending-deliveries.json`
   с приватными правами файла и повторяет его после перезапуска, не перезапуская
   агента.

## Не цели

- Это не повторяет неоднозначные сбои публикации, не создает комментарии
  статуса и не включает стриминг ответов. Это отдельные части issue #8012.
- Инструкция против прямой публикации через `gh`/API — операционная граница
  для агента, а не обеспечение песочницы. Обеспечение ограничений записи
  GitHub на уровне инструментов принадлежит рантайм-модели разрешений.
- Политика хранения ожидающих доставок, включая максимум попыток, максимальный
  возраст, лимиты размера, обработку устаревших ответов и очистку осиротевших
  временных файлов, отслеживается отдельно в #8142.

## Верификация

Сфокусированные тесты адаптера GitHub покрывают подавление sentinel, обычную
доставку финального комментария, поля аудита без текста ответа и неблокирующие
сбои записи аудита. Существующие тесты маршрутизации и доставки остаются без
изменений.
