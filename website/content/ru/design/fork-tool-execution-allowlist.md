# Allowlist исполнения инструментов форка

## Резюме

Добавить опциональный параметр `fork_tools` к существующему рантайму
`subagent_type: "fork"` инструмента Agent. Параметр сужает, какие инструменты
форк может исполнять, не меняя декларации инструментов, отправляемые модели.

Это первая фаза #7625. Именованные файлы профилей, паттерны аргументов shell,
overlay-файловые системы и интеграция `/btw` вне области. Подсказка в
промпте запуска сообщает форку, какие видимые инструменты разрешает allowlist.

## Цели

- Сохранить унаследованную поверхность исполнения форка, когда `fork_tools`
  опущен, за исключением инструментов взаимодействия, которые форки никогда
  не должны исполнять.
- Трактать пустой список как deny-all, а не как существующее поведение
  wildcard `tools: []`.
- Оставить текущие видимые модели декларации форка неизменными, чтобы
  добавление ограничения исполнения не изменяло его префикс промпт-кэша.
- Отклонять неразрешенные вызовы до построения инструмента, хуков
  инструмента, классификации разрешений, планирования или одобрения.
- Сохранять ограничение при возрождении фонового форка из его
  персистентного sidecar.

## Параметр и сопоставление

`fork_tools` валиден только с явным `subagent_type: "fork"` и не может
комбинироваться с именованным тиммейтом. Каждая запись должна быть непустой
строкой без окружающего пробельного пространства. Неизвестные точные имена
остаются в allowlist и не сопоставляются ничему; они не отфильтровываются,
потому что превращение невалидного непустого списка в опущенное ограничение
завершилось бы fail open.

Встроенные инструменты используют точные канонические имена функций из
видимых модели деклараций. Записи MCP поддерживают точные канонические имена,
а также паттерны сервера и завершающего wildcard. Паттерны сопоставляются с
сырой идентичностью MCP-сервер/инструмент зарегистрированного инструмента, а
не только с его санитизированным провайдером именем, поэтому различные имена
серверов, санитизирующиеся в один и тот же префикс, не могут
перекрестно совпасть. Голый `*` отклоняется; опускание уже разрешает все
иначе исполняемые унаследованные инструменты.
Записи wildcard ограничены `mcp__*` или паттерном завершающего префикса
инструмента MCP, таким как `mcp__github__read_*`. `mcp__*` намеренно
сопоставляется со всеми инструментами MCP, не сопоставляясь со встроенными
инструментами.

Паттерны аргументов shell не являются частью этой фазы. Перечисление
`run_shell_command` позволяет вызову инструмента продолжиться через обычный
конвейер разрешений, но не одобряет заранее его команду.

## Разделение рантайма

`ToolConfig.tools` остается источником для `AgentCore.prepareTools()` и
деклараций функций на каждом запросе модели. Отдельное поле
`executionAllowedTools` снимается при создании `AgentCore`. Точные записи и
записи wildcard MCP предвычисляются отдельно, чтобы промах инструмента не
аллоцировал и не пересканировывал несвязанные встроенные имена.

`processFunctionCalls()` сначала проверяет, что запрошенное имя присутствует
в наборе деклараций. Затем он применяет опциональный allowlist исполнения.
Неразрешенный вызов дает один синтетический ответ ошибки с исходными ID и
именем вызова, тогда как другие вызовы в том же батче продолжаются в
планировщик. Поскольку эта проверка предшествует построению планировщика,
отклоненный вызов не может открыть промпт одобрения или исполнить пред-
инструментальный хук.

Allowlist только сужает существующую поверхность. Он не может повторно
включить инструменты, удаленные исключениями субагентов, обойти обычные
разрешения для разрешенного инструмента или добавить декларации.

Каждый форк получает in-memory allowlist исполнения, даже когда `fork_tools`
опущен. Пол рантайма удаляет `ask_user_question` после применения списка,
предоставленного вызывающим, поэтому вызывающий не может повторно включить
его. Инструмент остается в списке деклараций, выведенном из родителя, для
разделения промпт-кэша, но вызов отклоняется до планирования или одобрения.
Заблокированный форк сообщает об отсутствии ввода своему родителю вместо
того, чтобы пытаться взаимодействовать с пользователем напрямую.

Форк получает уведомление об ограничении в промпте задачи после
унаследованного кэшируемого префикса. Это избегает вызовов методом проб и
ошибок без изменения системной инструкции, выведенной из родителя, префикса
истории или деклараций инструментов.

## Фоновое возрождение

Фоновые форки персистят унаследованную историю в записи транскрипта
`agent_bootstrap` и промпт задачи запуска в отдельной записи. Системная
инструкция и декларации инструментов — это возможности (capability), поэтому
холодное возрождение перепривязывает их из текущего рантайма родителя и
разрешает текущие имена инструментов через живой реестр.

Предоставленное вызывающим `executionAllowedTools` — вместо этого политика на
момент запуска. Ограниченные форки хранят его в sidecar `AgentMeta`, включая
пустой список deny-all, и холодное возрождение повторно применяет его к
живому `ToolConfig`. Форки, запущенные без `fork_tools`, не персистят
выведенный список, позволяя возрождению пересчитать его из текущей
поверхности инструментов родителя. Результирующая исполняемая поверхность —
это текущая поверхность инструментов, выведенная из родителя, суженная
персистентной политикой и обязательным исключением инструментов
взаимодействия.

Поле остается опциональным для совместимости. Старые транскрипты и форки,
запущенные без `fork_tools`, восстанавливаются с текущей поверхностью
инструментов, выведенной из родителя, минус обязательное исключение
инструментов взаимодействия.

## Граница

`fork_tools` предоставляется родительской моделью или вызывающим на каждом
вызове инструмента Agent. Поэтому это ограничение возможностей потомка, а не
обеспечиваемая пользователем или администратором песочница безопасности.
Будущий слой профилей может предоставить короткое, контролируемое проектом
имя политики поверх этого механизма исполнения.

Ограничение не может быть отмыто через другого потомка: исполнение форка
выполняется внутри контекста рантайма форка, чей авторитетный гейт
инструмента Agent отклоняет любое порождение субагентов. Более общо,
`fork_tools` не может сделать исключенный или необъявленный инструмент
исполняемым.
