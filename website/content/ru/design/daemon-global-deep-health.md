# Глобальная deep-проверка здоровья демона

## Проблема

`GET /health?deep=1` был введен, когда демон владел одним рантаймом рабочего
пространства. Маршрут оставался подключен к primary-бриджу после появления
поддержки нескольких рабочих пространств, поэтому его счетчики могли сообщать
о простое демона, пока во вторичном рабочем пространстве были сессии,
промпты или ожидающие разрешения.

Поверхностный эндпоинт намеренно отличается: `GET /health` только доказывает,
что слушатель может ответить. Он должен оставаться дешевым и не должен
обращаться к состоянию рантайма.

## Решение

Deep-проверка здоровья — это информационный снимок всего демона. Она
агрегирует каждый рантайм, возвращаемый `WorkspaceRegistry.listManaged()`,
включая рабочие пространства, которые дренируются, но еще не завершили
очистку бриджа.

| Поле                 | Агрегация                                                |
| -------------------- | -------------------------------------------------------- |
| `workspaceCount`     | Число управляемых рантаймов в снимке                     |
| `sessions`           | Сумма                                                    |
| `pendingPermissions` | Сумма                                                    |
| `activePrompts`      | Сумма                                                    |
| `connectedClients`   | Существующий общедомоновый счетчик REST SSE              |
| `channelAlive`       | True, когда жив любой канал любого управляемого рантайма |
| `lastActivityAt`     | Последнее ненулевое время активности бриджа              |
| `idleSinceMs`        | Один снимок `Date.now()` минус последнее время активности |
| `rateLimitHits`      | Существующие опциональные общедемоновые счетчики rate-limit |

Маршрут читает обязательные геттеры каждого рантайма перед объединением
значений. Он не короткозамыкает чтения каналов. Если реестр или любой геттер
бросает исключение, вся deep-проверка завершается ошибкой
`503 {"status":"degraded","reason":"aggregation_failed"}`, а не возвращает
частичный снимок. Ошибки геттеров идентифицируют рантайм рабочего пространства
в stderr-логе демона, не раскрывая этот идентификатор в HTTP-ответе.

Пока слушатель bootstrap поднят, но реестр рантаймов не готов, deep-запрос
возвращает degraded-тело с `reason: "bootstrap"` и `Retry-After: 1`. В режиме
запуска health-first завершение этого ответа все равно запускает старт
рантайма. Поверхностный ответ bootstrap остается
`200 {"status":"ok"}`.

## Совместимость и границы

- `deep=1`, `deep=true` и просто `deep` включают снимок; все остальные значения
  используют поверхностную проверку.
- Deep-ответы с одним рабочим пространством сохраняют свои существующие
  значения и добавляют `workspaceCount: 1`.
- Аутентификация, allowlist хостов, CORS и поведение rate-limit не меняются.
- Ответ не раскрывает ID рабочих пространств, пути, состояние доверия или
  детали по рабочим пространствам.
- Никаких изменений возможностей (capabilities) или SDK не требуется.
  `workspaceCount` позволяет потребителям опознать общедемоновый контракт.

Deep-проверка — это не проверка готовности всех рабочих пространств и не
атомарная аренда возврата. Аксессоры счетчиков не пингуют дочерние процессы,
а `connectedClients` представляет только REST SSE. Возвращатель должен
требовать повторяющихся idle-выборок и graceful-завершения; операторам,
которым нужна диагностика транспорта или по рабочим пространствам, следует
использовать аутентифицированный эндпоинт `/daemon/status`.

## Отклоненные альтернативы

- Агрегация только `WorkspaceRegistry.list()` скрыла бы дренирующиеся
  рантаймы до завершения их очистки бриджа и могла бы сообщить о простое
  слишком рано.
- Переиспользование `/daemon/status` сделало бы проверку здоровья зависимой от
  более тяжелого снимка с другой областью активных рабочих пространств и
  контрактом ошибок.
- Добавление селектора рабочего пространства сохранило бы проблему fan-out на
  стороне вызывающего и не удовлетворило бы обнаружение простоя на уровне
  демона.
- Определение `channelAlive` как «все каналы живы» молча изменило бы его
  существующее значение, совместимое с daemon-status. Ошибки по рабочим
  пространствам принадлежат `/daemon/status`.
