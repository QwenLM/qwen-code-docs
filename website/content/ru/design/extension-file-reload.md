# Дизайн перезагрузки файлов расширений

## Фон

Изменения расширений сейчас входят в рантайм с двух разных направлений.
Мутации UI, инициированные пользователем, такие как включение, отключение,
установка, удаление и обновление, уже проходят через `ExtensionManager` и
могут обновить состояние рантайма напрямую. Изменения файловой системы вне
полосы, такие как редактирование `skills/`, `commands/`, `hooks/` или
`qwen-extension.json` установленного расширения, не принадлежат одному
действию UI и поэтому нуждаются в пути, управляемом вотчером.

Этот дизайн добавляет этот отсутствующий путь вотчера, сохраняя путь прямых
мутаций. Он следует той же слоистости, что и дизайны горячей перезагрузки MCP
и LSP:

- CLI решает, когда изменения файловой системы должны вызвать перезагрузку
  или уведомление пользователя;
- Core владеет тем, как обновляется состояние рантайма расширений;
- UI-компоненты потребляют небольшой объект события/состояния вместо опроса
  файлов расширений напрямую.

Ключевое ограничение в том, что не каждый файл расширения можно безопасно
горячо применить одинаковым образом. Файлы возможностей (capability), похожие
на содержимое, можно обновлять автоматически, но изменения уровня пакета
должны просить пользователя выполнить `/reload-plugins`, чтобы кэш
расширений, runtime-инструменты, хуки, файлы контекста и список
слеш-команд пересобирались из одного связного снимка.

## Оценка текущего кода

- `ExtensionManager` уже загружает манифесты расширений, каталоги
  соглашений, метаданные установки, состояние включенности, состояние
  источников маркетплейса, команды, навыки, агентов, хуки, декларации MCP и
  декларации LSP.
- Операции расширений UI уже вызывают `ExtensionManager.refreshTools()` после
  изменения релевантного рантайму состояния. Этот путь обновляет MCP, навыки,
  субагентов, хуки и иерархическую память через Core.
- Дополнение слеш-команд строится `CommandService.create()` из загрузчиков.
  Команды расширений и слеш-команды на основе навыков не появляются
  автоматически, пока `reloadCommands()` не пересоберет этот сервис команд.
- Менеджеры навыков и субагентов имеют API обновления кэша, но эти кэши
  отделены от дополнения слеш-команд.
- Хуки принадлежат `HookSystem` и `HookRegistry`. Пересоздание всей системы
  хуков потеряло бы временные хуки со скоупом агента, поэтому перезагрузка
  должна целиться только в настроенные хуки.
- `SettingsWatcher` и существующие вотчеры MCP/LSP не покрывают содержимое
  установленных пакетов расширений. Файлы, специфичные для расширений,
  требуют своего вотчера.
- Связанные расширения могут находиться вне пользовательского каталога
  расширений, поэтому наблюдение только за `~/.qwen/extensions` пропускает
  активные workflow разработки.

## Цели

Сделать так, чтобы изменения расширений вступали в силу в текущей
интерактивной сессии без полного перезапуска CLI:

- сохранить немедленную вступаемость в силу мутаций расширений из UI;
- обнаруживать ручные правки, добавления и удаления расширений под
  пользовательским каталогом расширений;
- обнаруживать правки в исходных каталогах связанных расширений;
- автоматически обновлять файлы возможностей уровня содержимого под
  `commands/`, `skills/` и `agents/`;
- предлагать пользователю выполнить `/reload-plugins` для изменений уровня
  пакета;
- обновлять хуки как часть перезагрузки рантайма без потери хуков со скоупом
  агента;
- держать дополнение слеш-команд в синхронизации с изменениями команд и
  навыков;
- подавлять уведомления вотчера об изменениях, записанных собственными
  мутациями расширений Qwen;
- выносить наружу отказы перезагрузки MCP и хуков вместо сообщения вводящей
  в заблуждение сводки об успешной перезагрузке.

## Не цели

- Не делать правки файлов хуков автоматически обновляемыми как содержимое.
  Поведение хуков может влиять на исполнение команд и чувствительные к
  безопасности workflow, поэтому правки хуков трактуются как изменения
  уровня пакета.
- Не горячо перезагружать произвольные файлы расширений. Неизвестные файлы
  игнорируются, если они не являются разрешенными файлами контекста.
- Не добавлять per-extension инкрементальный перезапуск MCP. Этот дизайн
  продолжает использовать существующую точку входа реинициализации MCP.
- Не менять обнаружение расширений, конвертацию, парсинг источников установки
  или семантику маркетплейса.
- Не поддерживать переключение bare mode в рантайме. Вотчер просто не
  запускается в bare mode.

## Структура кода

Реализация намеренно разделена по слоям.

```text
packages/core/src/extension/
  extensionManager.ts
    Extension mutation lifecycle events.
    UI mutation methods still own direct runtime refresh.

  extension-runtime-refresh.ts
    Core runtime refresh contract for extension mutations.

packages/core/src/hooks/
  hookRegistry.ts
    Reload configured hooks while preserving agent-scoped hooks.

  hookSystem.ts
    Public hook reload facade used by extension runtime refresh.

packages/cli/src/config/
  extension-refresh-state.ts
    Shared event/state object for watcher, slash processor, and reload command.

  extension-file-watcher.ts
    Filesystem watcher and path classifier.

  extension-runtime-reload.ts
    CLI reload helpers for /reload-plugins and content auto-refresh.

packages/cli/src/ui/commands/
  reload-plugins-command.ts
    Interactive slash command for package-level extension reload.

packages/cli/src/ui/hooks/
  slashCommandProcessor.ts
    Event consumers for stale notifications and content auto-refresh.

packages/cli/src/
  gemini.tsx
  ui/AppContainer.tsx
  ui/startInteractiveUI.tsx
    Startup and dependency injection for ExtensionRefreshState and watcher.
```

## Дизайн

### 1. Классификация изменений файловой системы

`ExtensionFileWatcher` отображает событие chokidar на один из трех исходов:

```ts
type RefreshAction = 'auto' | 'stale' | false;
```

Классификация намеренно консервативна.

| Класс пути                        | Действие  | Причина                                                                                        |
| --------------------------------- | --------- | ---------------------------------------------------------------------------------------------- |
| `commands/**`                     | `auto`    | Загрузчики слеш-команд могут пересобраться из существующего кэша расширений.                   |
| `skills/**`                       | `auto`    | Кэш навыков и загрузчики слеш-команд могут пересобраться без изменения идентичности пакета.    |
| `agents/**`                       | `auto`    | Кэш субагентов может пересобраться без изменения идентичности пакета.                          |
| `hooks/**`                        | `stale`   | Поведение исполнения хуков должно перезагружаться из связного снимка пакета.                   |
| `qwen-extension.json`             | `stale`   | Манифест может менять команды, навыки, агентов, хуки, MCP, LSP, имена файлов контекста и метаданные. |
| `.qwen-extension-install.json`    | `stale`   | Метаданные установки влияют на связанные исходные корни и идентичность пакета.                 |
| настроенные файлы контекста       | `stale`   | Контекст модели может измениться и должен перезагружаться явно.                                |
| добавление/удаление каталога расширения | `stale` | Топология установленных расширений изменилась.                                            |
| конфигурационные файлы расширения верхнего уровня | `stale` | Включенность, предпочтения или маркетплейсы изменились вне пути мутаций UI.        |
| неизвестные файлы                 | игнорируется | Избегать перезагрузки для артефактов сборки или несвязанных данных.                        |

Тот же классификатор используется для установленных пользователем расширений
и исходных корней связанных расширений. Для связанных корней вотчер сначала
находит владеющее связанное расширение, а затем классифицирует путь
относительно этого исходного корня.

### 2. Наблюдение пользовательских и связанных корней расширений

`ExtensionFileWatcher.startWatching()` строит корни наблюдения из:

1. `Storage.getUserExtensionsDir()`, когда он существует;
2. активных исходных путей связанных расширений из метаданных установки;
3. родителя каталога расширений пользователя, только когда каталог
   расширений еще не существует.

Bootstrap-вотчер родителя покрывает установку первого расширения или ручное
создание каталога расширений после старта. Когда каталог появляется, вотчер
помечает состояние расширений как устаревшее и планирует `restartWatching()`
в микрозадаче. Планирование перезапуска избегает закрытия bootstrap-вотчера,
пока chokidar все еще диспетчеризует событие.

Опции вотчера:

```ts
watchFs(roots, {
  ignoreInitial: true,
  followSymlinks: false,
  awaitWriteFinish: {
    stabilityThreshold: 200,
    pollInterval: 50,
  },
  ignored: (filePath) => this.isIgnored(filePath),
});
```

`followSymlinks: false` не дает расширению заставить Qwen наблюдать
произвольные внешние пути через симлинки. Фильтр игнорирования пропускает
`node_modules`, `.git`, обычные файлы резервных копий редакторов, swap-файлы,
временные файлы и `.DS_Store`.

### 3. Разделение состояния перезагрузки через ExtensionRefreshState

`ExtensionRefreshState` — это небольшая примитивная сущность события/
состояния, разделяемая вотчером, процессором слеш-команд и
`/reload-plugins`.

Ключевые методы:

```ts
markExtensionsChanged(reason?: string): boolean;
markExtensionContentChanged(reason?: string): boolean;
clearExtensionsChanged(): void;
notifyExtensionsReloadStarted(): void;
needsExtensionRefresh(): boolean;
beginSuppression(onSettle?: () => void): () => void;
suppressNotifications<T>(fn: () => T, onSettle?: () => void): T;
```

События:

| Событие                   | Производитель                             | Потребитель                 | Значение                                                                   |
| ------------------------- | ----------------------------------------- | --------------------------- | -------------------------------------------------------------------------- |
| `ExtensionContentChanged` | `ExtensionFileWatcher`                    | `useSlashCommandProcessor`  | Изменились файлы уровня содержимого; запланировать автообновление.          |
| `ExtensionRefreshNeeded`  | `ExtensionFileWatcher`                    | `useSlashCommandProcessor`  | Изменилось состояние уровня пакета; сказать пользователю выполнить `/reload-plugins`. |
| `ExtensionsReloadStarted` | `/reload-plugins`                         | `useSlashCommandProcessor`  | Отменить ожидающие таймеры обновления содержимого перед ручной перезагрузкой. |
| `ExtensionsReloaded`      | `/reload-plugins`, путь перезапуска вотчера | вотчер и процессор слеш-команд | Очистить флаги устаревания и перезапустить/отменить ожидающую работу.   |

`markExtensionsChanged()` дедуплицирует уведомления об устаревании, пока
состояние не очищено. Уведомления об изменении содержимого не
дедуплицируются этим объектом состояния, потому что процессор слеш-команд
владеет дебаунсом и сериализацией.

### 4. Подавление шума вотчера во время программных мутаций

`ExtensionManager` выставляет:

```ts
interface ExtensionMutationEvent {
  id: number;
  phase: 'start' | 'end';
  operation: string;
}

addMutationListener(listener: ExtensionMutationListener): () => void;
```

Релевантные рантайму методы мутаций вызывают `beginMutation()` и всегда
эмиттят соответствующее конечное событие в `finally`.

Методы, которые эмиттят события мутаций:

- `enableExtension()`
- `disableExtension()`
- `installExtension()`
- `uninstallExtension()`
- `updateExtension()`
- `addSource()`
- `removeSource()`
- `setExtensionScope()`
- `setMcpServerDisabled()`

Методы, которые не эмиттят события мутаций:

- `toggleFavorite()`
- `markSourceUpdated()`

Вотчер хранит `mutation id -> колбэк подавления завершения` в `Map`. Это
важно, потому что установка может внутренне вызвать включение, а отдельные
мутации могут перекрываться. Спаривание по id избегает зависимости от
порядка стека.

Когда внешняя глубина подавления достигает нуля, вотчер перезапускается. Это
обновляет связанные исходные корни, имена файлов контекста и метаданные
активных расширений после урегулирования мутации.

### 5. Обновление состояния рантайма из Core

`refreshExtensionRuntime()` — это точка входа обновления рантайма на стороне
Core, используемая мутациями расширений UI.

Он обновляет в следующем порядке:

1. `config.reinitializeMcpServers(config.getSettingsMcpServers())`
2. `config.getSkillManager()?.refreshCache()`
3. `config.getSubagentManager().refreshCache()`
4. `config.getHookSystem()?.reload()`
5. `config.refreshHierarchicalMemory()`

Реинициализация MCP выполняется первой, потому что описания инструментов
навыков и субагентов могут зависеть от обновленного списка инструментов MCP.

Навыки, субагенты и хуки выполняются через `Promise.allSettled()`, чтобы
одна отклоненная ветвь не препятствовала применению остальных. Отказ
перезагрузки хуков сохраняется и перебрасывается после того, как
иерархическая память получила возможность обновиться. Это держит отказы хуков
видимыми, все еще применяя обновления кэша по мере возможности.

Контракт отказов:

- Отказ MCP распространяется немедленно, и последующие ветви рантайма не
  выполняются.
- Отказ перезагрузки хуков распространяется после урегулирования
  параллельных ветвей обновления и обновления памяти.
- Отказ обновления навыков логируется и является best-effort.
- Отказ обновления субагентов логируется и является best-effort.
- Отказ обновления иерархической памяти логируется и является best-effort.

### 6. Перезагрузка изменений уровня пакета через /reload-plugins

`reloadPluginsRuntime()` — это помощник перезагрузки рантайма на стороне
CLI, используемый слеш-командой:

```ts
async function reloadPluginsRuntime(options: {
  config: Config;
  reloadCommands?: () => void | Promise<void>;
}): Promise<ReloadPluginsSummary>;
```

Поток:

1. `config.getExtensionManager().refreshCache()`
2. `config.getExtensionManager().refreshTools()`
3. `reloadCommands()`
4. свести возможности (capability) активных расширений

Сводка подсчитывает декларации активных расширений для:

- расширений;
- команд;
- навыков;
- агентов;
- хуков;
- MCP-серверов расширений;
- LSP-серверов расширений.

`/reload-plugins` владеет видимым пользователю поведением команды:

1. требовать `config`;
2. эмиттить `ExtensionsReloadStarted`;
3. вызывать `reloadPluginsRuntime()`;
4. вызывать `clearExtensionsChanged()` при успехе или отказе;
5. возвращать либо локализованную информационную сводку, либо сообщение об
   ошибке.

Очистка устаревшего состояния при отказе намеренна. Если бы неудачная
перезагрузка оставляла `extensionRefreshNeeded = true`, будущие уведомления
файлового вотчера дедуплицировались бы, и автообновление содержимого
продолжало бы обходить само себя.

### 7. Автообновление изменений уровня содержимого

`refreshExtensionContentRuntime()` используется для изменений файловой
системы только уровня содержимого.

Поток:

1. обновить кэш расширений;
2. обновить кэш навыков;
3. обновить кэш субагентов;
4. перезагрузить слеш-команды;
5. агрегировать ошибки и бросить одно сообщение, если любая ветвь не
   удалась.

Процессор слеш-команд слушает `ExtensionContentChanged` и дебаунсит
обновление на 250 мс. Он сериализует обновления через:

```ts
extensionContentRefreshRunningRef;
extensionContentRefreshPendingRef;
```

Если событие содержимого прибывает во время выполнения обновления, процессор
помечает другой проход как ожидающий и выполняет этот проход после
завершения текущего. Небольшой верхний предел не дает шумному редактору или
процессу сборки держать одну и ту же задачу обновления живой бесконечно.

Если `ExtensionRefreshState.needsExtensionRefresh()` истинно, автообновление
содержимого выходит рано. Перезагрузка уровня пакета должна выполниться
первой, чтобы состояние команд, навыков, агентов, хуков, MCP, LSP и
контекста было пересобрано из одного снимка кэша расширений.

### 8. Перезагрузка хуков без сброса хуков со скоупом агента

`HookRegistry.reloadConfiguredHooks()` заменяет только записи настроенных
хуков. Она сохраняет записи с `agentScope !== undefined`, потому что это
временные хуки, зарегистрированные для исполнения субагентов.

Поток:

1. сохранить `previousEntries`;
2. сохранить `agentEntries`;
3. установить записи реестра в `agentEntries`;
4. выполнить `processHooksFromConfig()`;
5. при отказе восстановить `previousEntries` и перебросить.

`HookSystem.reload()` — это узкий фасад, который делегирует
`hookRegistry.reloadConfiguredHooks()`. Поэтому перезагрузке рантайма не
нужно пересоздавать всю систему хуков.

Этот путь перезагрузки не перечитывает файлы настроек пользователя или
проекта с диска. `processHooksFromConfig()` повторно обрабатывает текущие
значения `Config` для хуков пользователя/проекта и обновленные значения
конфигурации расширений. Перезагрузка файлов настроек остается за путем
перезагрузки настроек; `/reload-plugins` ограничен состоянием рантайма
расширений.

### 9. Подключение состояния к интерактивному UI

Интерактивный старт создает один разделяемый `ExtensionRefreshState`:

```ts
const extensionRefreshState = new ExtensionRefreshState();
const extensionFileWatcher = isBareMode(argv.bare)
  ? undefined
  : new ExtensionFileWatcher(config, undefined, extensionRefreshState);
```

Это состояние передается через:

```text
gemini.tsx
  -> startInteractiveUI(...)
    -> AppContainer
      -> useSlashCommandProcessor
      -> CommandContext.services.extensionRefreshState
```

`AppContainer` создает фолбэк `ExtensionRefreshState`, только когда он не был
предоставлен. Это держит тесты и альтернативные точки входа UI простыми,
погда основной интерактивный путь разделяет состояние между вотчером и
обработкой слеш-команд.

Очистка отрегистрирует слушателя перезагрузки и останавливает вотчер.

## Потоки событий

### Правка файла содержимого

```text
edit extension commands/skills/agents file
  -> ExtensionFileWatcher classifies as auto
  -> ExtensionRefreshState.markExtensionContentChanged()
  -> useSlashCommandProcessor schedules debounced refresh
  -> refreshExtensionContentRuntime()
      -> ExtensionManager.refreshCache()
      -> SkillManager.refreshCache()
      -> SubagentManager.refreshCache()
      -> reloadCommands()
```

### Правка файла уровня пакета

```text
edit qwen-extension.json/hooks/context/install metadata/topology
  -> ExtensionFileWatcher classifies as stale
  -> ExtensionRefreshState.markExtensionsChanged()
  -> useSlashCommandProcessor prints:
       "Extensions changed on disk. Run /reload-plugins to apply updates."
  -> user runs /reload-plugins
  -> reloadPluginsRuntime()
      -> ExtensionManager.refreshCache()
      -> ExtensionManager.refreshTools()
      -> reloadCommands()
```

### Мутация UI

```text
user enables/disables/installs/uninstalls/updates extension
  -> ExtensionManager emits mutation start
  -> ExtensionRefreshState begins suppression
  -> ExtensionManager writes disk/runtime state
  -> ExtensionManager.refreshTools()
      -> refreshExtensionRuntime()
  -> ExtensionManager emits mutation end
  -> suppression settles
  -> ExtensionFileWatcher restarts with fresh roots/context files
```

## Конкурентность и упорядочивание

- Перезапуски вотчера защищены поколением. События из старого инстанса
  вотчера игнорируются после изменения `watchGeneration`.
- Подавление мутаций спаривается по id мутации, а не по порядку стека.
- `stopWatching()` завершает все ожидающие подавления до сброса ссылок
  вотчера, поэтому глубина подавления не может утечь, когда вотчер
  останавливается во время мутации в полете.
- Автообновление содержимого сериализовано в процессоре слеш-команд.
  Одновременные события коалесцируются не более чем в один ожидающий
  повторный запуск.
- `/reload-plugins` эмиттит `ExtensionsReloadStarted` и `ExtensionsReloaded`,
  чтобы ожидающие таймеры обновления содержимого отменялись вокруг ручной
  перезагрузки.
- Устаревшее состояние уровня пакета выигрывает у автообновления содержимого.
  Если нужна перезагрузка устаревшего, автообновление содержимого выходит и
  ждет `/reload-plugins`.

## Семантика отказов

| Путь                                                  | Поведение                                                                                                                                  |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Реинициализация MCP при мутации или `/reload-plugins` | Распространяется. Сообщение об успехе вводило бы в заблуждение, потому что инструменты MCP расширений могут быть недоступны.              |
| Перезагрузка хуков при мутации или `/reload-plugins`  | Распространяется после урегулирования других параллельных ветвей обновления. Сводка об успехе вводила бы в заблуждение, потому что настроенные хуки могут быть не зарегистрированы. |
| Обновление кэша навыков во время мутации              | Логируется и является best-effort.                                                                                                         |
| Обновление кэша субагентов во время мутации           | Логируется и является best-effort.                                                                                                         |
| Обновление иерархической памяти во время мутации      | Логируется и является best-effort. Оно не должно откатывать уже записанное состояние расширений.                                           |
| Отказ автообновления содержимого                      | Агрегируется и показывается в UI с фолбэком `/reload-plugins`.                                                                             |
| Отказ `/reload-plugins`                               | Возвращает сообщение об ошибке и очищает устаревшее состояние, чтобы будущие уведомления вотчера могли снова срабатывать.                   |
| Отказ перезагрузки реестра хуков                      | Восстанавливает предыдущие записи хуков и перебрасывает.                                                                                   |
| Ошибка вотчера                                        | Логируется через debug-логгер; сессия продолжается.                                                                                        |

### Ручная верификация

Ручная верификация должна покрывать:

1. Включить расширение из UI и подтвердить, что команды, навыки, агенты, MCP,
   хуки и контекст обновились без перезапуска.
2. Отключить то же расширение и подтвердить, что возможности рантайма
   удалены или больше не предлагаются.
3. Отредактировать файл команды под `commands/` и подтвердить, что
   дополнение слеш-команд обновляется автоматически.
4. Отредактировать файл навыка под `skills/` и подтвердить, что дополнение
   слеш-команд на основе навыков обновляется автоматически.
5. Отредактировать файл агента под `agents/` и подтвердить, что поведение
   кэша агентов отражает изменение.
6. Отредактировать `hooks/hooks.json`, `qwen-extension.json`, метаданные
   установки, файлы контекста или топологию каталога расширений и
   подтвердить, что UI запрашивает `/reload-plugins`.
7. Выполнить `/reload-plugins` и подтвердить, что сводка сообщает
   расширения, команды, навыки, агентов, хуки, MCP-серверы расширений и
   LSP-серверы расширений.
8. Принудительно вызвать отказ перезагрузки и подтвердить, что UI сообщает
   ошибку, а последующее изменение файловой системы все еще может вызвать
   другое уведомление.

## Компромиссы

- Хуки трактуются как устаревшие изменения уровня пакета, хотя API
  перезагрузки настроенных хуков существует. Это избегает тихого изменения
  поведения исполнения хуков из фонового события файловой системы.
- Обновление MCP остается полной реинициализацией рантайма. Per-extension
  инкрементальный перезапуск MCP снизил бы стоимость, но расширил бы этот PR
  на владение MCP и логику согласования.
- Вотчер классифицирует неизвестные файлы как игнорируемые вместо устаревших.
  Это снижает шум от артефактов сборки, но означает, что авторы расширений
  должны помещать файлы возможностей рантайма в поддерживаемые каталоги
  соглашений.
- Корни связанных расширений наблюдаются напрямую. Это улучшает эргономику
  разработки, но может увеличить число вотчеров для пользователей с большим
  числом связанных расширений.

## Будущая работа

- Добавить per-extension инкрементальное согласование MCP.
- Добавить видимую пользователю диагностику для фатальных ошибок вотчера,
  таких как `ENOSPC` или `EMFILE`.
- Рассмотреть типизированный результат перезагрузки из
  `refreshExtensionRuntime()`, если вызывающим нужны сводки частичного
  успеха.
- Оптимизировать поиск источников связанных расширений предварительно
  вычисленной картой корней, если связанные расширения станут распространенными.
- Пересмотреть автообновление содержимого хуков, только если перезагрузку
  хуков можно сделать явной, наблюдаемой и достаточно безопасной для фонового
  применения.
