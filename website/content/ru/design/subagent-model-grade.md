# Выбор грейда модели субагента

## Цель

Позволить модели выбирать пользовательский грейд модели при запуске обычного
субагента, не раскрывая специфичные для провайдера ID моделей в схеме
инструмента Agent.

```json
{
  "agents": {
    "modelGrades": {
      "small": "fast",
      "high": "qwen-max"
    },
    "allowedGrades": ["small", "high"]
  }
}
```

Инструмент Agent объявляет `model: "small" | "high"` и резолвит выбранный
грейд сразу после загрузки конфигурации субагента.

## Резолвинг

Действующий селектор модели использует такой приоритет:

1. Явная, не-`inherit` модель не-встроенного агента
2. Разрешённый грейд, отображённый через `agents.modelGrades`
3. Настройка модели встроенного Explore
4. Наследуемая родительская модель

Неизвестные или неразрешённые грейды отклоняются. Форки отклоняют параметр,
поскольку должны наследовать модель и кэш промпта родителя. Именованные
тиммейты команды также отклоняют его, поскольку переопределение их backend-модели принимает конкретные ID моделей, а не селекторы грейдов.

В динамическую схему инструмента включаются только сконфигурированные,
разрешённые имена грейдов. Конкретные селекторы моделей остаются приватными
для пользовательских настроек.

## Проверка

- Схема настроек и проброс конфигурации CLI-to-core
- Резолвинг грейдов, фильтрация allowlist и приоритет пользовательских агентов
- Динамическая схема инструмента Agent без конкретных ID моделей
- Обычная foreground- и background-диспетчеризация с использованием
  зарезолвленной модели
- Валидация форков
