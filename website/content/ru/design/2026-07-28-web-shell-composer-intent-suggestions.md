# Предложения намерений композера Web Shell

## Резюме

Расширить существующее предложение новой темы Web Shell так, чтобы одна
консервативная классификация могла рекомендовать либо задать побочный вопрос
через `/btw`, либо отправить существенную новую тему в свежей сессии.

Композер продолжает показывать максимум одно неблокирующее действие. Валидное
решение `none` не рендерит ничего. Невалидные, неуспешные или отмененные
классификации также не рендерят ничего.

## Контракт решения

```ts
type SuggestionKind = 'btw' | 'new_session' | 'none';

interface SuggestionDecision {
  suggestion: SuggestionKind;
  confidence: number;
}
```

Только решения `btw` и `new_session` на уровне существующего порога
уверенности или выше становятся активными. Активное состояние записывает
точный классифицированный черновик и исходную сессию, чтобы при клике
пользователя можно было проверить оба снова.

## Поведение

- `btw` — для быстрого, самодостаточного побочного вопроса, который не должен
  тревожить основную задачу.
- `new_session` — для явно другой, существенной задачи или темы.
- `none` покрывает продолжения, неопределенность и черновики, не подходящие
  ни под одно действие.
- Классификация BTW начинается после одного предшествующего обмена
  пользователь/ассистент. Предложения новой сессии сохраняют свои более
  строгие существующие пороги контекста.
- Формулировки, похожие на follow-up, могут классифицироваться для BTW, но
  никогда не могут использовать ослабленный порог BTW для показа действия
  новой сессии.
- Клик по предложению `btw` отправляет `/btw <draft>` через существующий путь
  редактора, что сохраняет текущую историю команды и семантику очистки
  композера.
- Черновик с изображением или тегом композера никогда не пригоден для `btw`.
- `new_session` сохраняет существующую последовательность очистки, открепления,
  создания и автоотправки, включая сохранение изображений и отмену гонки
  сессий.

## Безопасность

Классификатор остается консервативным и fail-closed:

- некорректный вывод, неизвестные действия, невалидная уверенность, ошибки и
  отмены не порождают действия;
- смена сессии прерывает ожидающую классификацию и инвалидирует видимое
  предложение;
- изменение черновика или вложения инвалидирует видимое предложение;
- обработка клика проверяет текущий черновик, исходную сессию и состояние
  вложений непосредственно перед выполнением;
- вложения трактуются как присутствующие, пока ChatEditor не сообщит обратное,
  поэтому переходное неизвестное состояние не может раскрыть действие `/btw`.

## Область

Изменение остается внутри Web Shell. Оно переиспользует существующую генерацию
сессий демона, отправку редактора и поведение `/btw`. Оно не добавляет
маршрутов демона или SDK, не меняет стилизацию и не вводит обобщенный
фреймворк предложений.

## Производительность композера

Изменения черновика попадают в классификатор через стабильный колбэк. Они
обновляют refs классификатора, состояние отмены и таймер debounce без
обновления состояния React. Приложение Web Shell перерендеривается только
когда появляется активное предложение или существующее предложение
инвалидируется.

Это держит классификацию намерений вне пути рендера композера, сохраняя при
этом немедленную отмену при изменении черновика.

## Стратегия тестирования

- Тесты хука покрывают три значения решения, строгий парсинг, уверенность,
  гейтинг по вложениям и результаты устаревшей сессии.
- Тесты приложения покрывают выполнение `/btw` и очистку композера, отклонение
  устаревшего черновика/сессии, отклонение вложений, существующие гонки новой
  сессии и отсутствие перерендера приложения, пока классификация ожидает.
- Тесты ChatEditor покрывают сообщение о наличии вложений.
