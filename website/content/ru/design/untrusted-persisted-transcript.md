# Читатель недоверенных персистентных транскриптов

## Контекст

Демон уже предоставляет каталоги сессий и групп только из персистентных
данных для зарегистрированных недоверенных вторичных рабочих пространств.
Постраничное чтение транскриптов остаётся недоступным, поскольку легаси-маршрут
`GET /session/:id/transcript` резолвит владельца сессии через живое состояние
бриджа и делегирует воспроизведение дочернему процессу ACP. Этот путь может
запускать процесс, загружать настройки рабочего пространства и определённые
проектом возможности (capabilities), а также создавать или чинить
персистентный ключ подписи курсора.

Этот дизайн добавляет отдельный REST-контракт с квалификатором рабочего
пространства, который читает только активный персистентный транскрипт.
Легаси-маршрут и его поведение на базе ACP остаются без изменений.

## Контракт

Демон объявляет безусловную возможность
`workspace_persisted_transcript` и обслуживает:

`GET /workspaces/:workspace/session/:id/transcript?cursor=<opaque>&limit=<1..500>`

Селектор рабочего пространства сначала резолвит точный id зарегистрированного
рабочего пространства, затем URL-декодированный портативный абсолютный cwd.
Неизвестные или незарегистрированные селекторы завершаются fail closed с
`workspace_mismatch`. Доверенные первичные и вторичные рабочие пространства и
недоверенные вторичные рабочие пространства могут читать. Недоверенное
первичное по-прежнему отклоняется, чтобы сохранить существующую границу
safe-режима маршрута в единственном числе.

Читается только активный персистентный JSONL. Архивированные сессии
возвращают `session_archived`; конфликты active/archive возвращают
`session_conflict`; отсутствующие сессии возвращают 404. Ответ
переиспользует `DaemonSessionTranscriptPage` и содержит фреймы
`session_update` без id, созданные существующей проекцией видимой истории.
Сырой JSONL и скрытые системные записи никогда не возвращаются.

## Граница безопасности

Маршрут не должен вызывать методы бриджа, запускать или прогревать ACP,
загружать настройки, разбирать агентов или навыки, обнаруживать инструменты,
выполнять внешние команды, создавать персистентный ключ курсора или писать
специфичный для маршрута daemon/debug-лог. Существующие общедоступные
логирование HTTP-доступа и телеметрия демона остаются вне этой гарантии
отсутствия записи для маршрута.

Прямые чтения персистентного транскрипта выполняются с подавленным debug-логом
сессии. Координатор архива удерживает общий сессионный лок на время проверок
расположения, построения индекса, чтения записей, валидации session-id и
воспроизведения. Каждая возвращённая запись должна нести запрошенный id
сессии; несовпадение завершается fail closed как конфликт снимка.

Контекст прямого воспроизведения содержит только id сессии, приёмник
обновлений, опциональную перепись сообщений и опциональное накопительное
использование. Метаданные отображения инструментов откатываются к
персистентным имени и описанию инструмента, когда полного `Config` нет.
Никакой управляемый проектом реестр инструментов не запрашивается.

## Жизненный цикл курсора

Основной читатель принимает явный кодек курсора. Существующие вызывающие
стороны продолжают использовать кодек на файловой основе. Демон создаёт один
случайный мастер-ключ на процесс, выводит отдельный 32-байтовый HMAC-ключ из
id рабочего пространства и канонического cwd и кэширует кодек в памяти на
каждый зарегистрированный рантайм. Курсоры нового маршрута поэтому истекают
при перезапуске демона и не могут быть воспроизведены в других рабочих
пространствах.

Курсор замораживает идентичность файла, размер в байтах, активный лист,
позицию воспроизведения и состояние воспроизведения. Добавления после первой
страницы не меняют снимок. Удаление, архивирование, усечение, замена, смена
листа или несовпадение session-id возвращают
`transcript_snapshot_unavailable`.

## Обработка сбоев и гонок

Для первой страницы маршрут проверяет расположение active/archive, но всё
равно пробует активный читатель, когда расположение неизвестно, чтобы
некорректное активное хранилище молча не сообщалось как отсутствующее. Для
страниц по курсору валидируется только замороженный активный снимок. При
`ENOENT` страница по курсору возвращает недоступность снимка; первая страница
перепроверяет расположение, чтобы обнаружить гонку с архивацией, прежде чем
вернуть отсутствие.

Воспроизведение постранично-транзакционно на границе протокола: обновления,
выпущенные до сбоя конвертации воспроизведения, возвращаются с
`partial: true`, общей ошибкой воспроизведения и без следующего курсора.
Ожидающие вызовы инструментов и накопительное использование переносятся в
подписанном курсоре только после успешного воспроизведения.

## Совместимость и лимиты

Старый маршрут в единственном числе, персистентный ключ курсора и отображение
ошибок ACP остаются нетронутыми. Новый маршрут сохраняет существующий размер
страницы по умолчанию 100, максимум 500, лимит снимка 256 МиБ, кэш индекса
32 записи/64 МиБ и время жизни кэша пять минут. Маршрут с квалификатором
рабочего пространства дополнительно ограничивает каждую страницу 4 МиБ
персистентных исходных записей, 32 МиБ сериализованного JSON ответа и 64 КиБ
состояния курсора. `limit` поэтому является потолком числа записей, а не
обещанием, что каждая успешная страница содержит столько записей. Одна
агрегатная запись сверх бюджета источника возвращает
`transcript_page_too_large`; раздувшийся курсор воспроизведения завершает
иначе успешную страницу как частичную, не выдавая курсор продолжения.
Первое сканирование индекса остаётся линейным по размеру замороженного
снимка.

TypeScript SDK предоставляет метод в `WorkspaceDaemonClient`. Он форсирует
нативный REST-транспорт и не имеет отображения на маршрут ACP. Более старые
демоны могут быть обнаружены через новую возможность и продолжают возвращать
404 для этого маршрута.

## Отложенная работа

Чтение архивированных транскриптов, обратная/хвостовая пагинация, живое
следование, автоматическая загрузка полной истории, индексирование в
worker-потоках, курсоры между перезапусками и просмотрщик Web Shell — это
отдельные follow-up'ы.
