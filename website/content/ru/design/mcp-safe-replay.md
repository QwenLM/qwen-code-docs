# Безопасное воспроизведение после потери соединения MCP

## Проблема

Инструмент MCP может завершить побочный эффект до того, как его соединение
для ответа упадет. Поэтому переподключение и повторная отправка того же
`tools/call` могут повторить запись, в то время как пользователь видит только
второй результат. Аннотации инструментов MCP опциональны и по умолчанию
означают неидемпотентное поведение, поэтому отсутствующие аннотации не могут
оправдать автоматическое воспроизведение.

## Политика воспроизведения

Qwen Code автоматически воспроизводит неудачный вызов только когда все из
следующего истинно:

- Сбой классифицируется как потеря соединения существующими проверками
  соединения MCP.
- MCP-сервер имеет `trust: true`.
- Текущее рабочее пространство проходит гейт доверия рабочего пространства.
- Инструмент объявляет `idempotentHint: true`, либо объявляет
  `readOnlyHint: true` без `destructiveHint: true` или `idempotentHint: false`.

Конфликтующие аннотации не трактуются как безопасные. В частности, инструмент,
объявляющий себя read-only и одновременно объявляющий деструктивное или
неидемпотентное поведение, не воспроизводится. Явное объявление идемпотентности
может покрыть мутирующую операцию, но не переопределяет противоречащие
аннотации read-only.

То же решение применяется к обоим путям исполнения: прямому клиенту MCP,
используемому для вызовов с awareness прогресса, и вызываемому фолбэку.
Ошибки отмены, ошибки не-соединения и результаты протокола MCP `isError: true`
сохраняют свое существующее поведение.

После переподключения Qwen Code применяет те же проверки доверия и аннотаций к
заново обнаруженному инструменту перед отправкой воспроизведения. Он не
переносит доверие или аннотации предыдущего процесса сервера в новый вызов.

## Поведение при сбое

Когда воспроизведение сбоя соединения небезопасно, текущий вызов не
переподключается и не конструирует второй вызов. Он возвращает стабильную
ошибку, объясняющую, что операция могла завершиться и не должна повторяться
автоматически. Ошибка не включает аргументы инструмента или вышестоящую
транспортную ошибку.

Восстановление соединения для последующих независимых вызовов остается
ответственностью существующего монитора здоровья, явного переподключения или
обычного жизненного цикла обнаружения. Безопасные вызовы сохраняют
существующее ограниченное поведение переподключения.

## Совместимость

Это намеренно консервативное изменение. Инструменты без аннотаций больше не
получают прозрачного воспроизведения потери соединения, даже когда более
старый выпуск Qwen Code повторял их. Серверы, которые хотят воспроизведения,
должны предоставлять точные аннотации, а администраторы должны явно включать
доверие серверу в доверенном рабочем пространстве.

Аннотации MCP — подсказки поведения, предоставляемые сервером, а не граница
авторизации. Qwen Code использует их для воспроизведения только после того,
как пройдены оба гейта доверия сервера и рабочего пространства.

## Верификация

Тесты покрывают прямой клиент и вызываемый фолбэк, безопасные объявления
идемпотентности и read-only, отсутствующие и противоречивые аннотации, оба
гейта доверия, повторно обнаруженные инструменты, потерявшие доверие или
аннотации, классификацию ошибок соединения, отмены, ошибки протокола, сбой
переподключения и лимит повторов. Отдельная локальная запись E2E проходит
сервер, который фиксирует побочный эффект до разрыва соединения для ответа, и
проверяет, что небезопасный вызов достигает сервера только один раз.
