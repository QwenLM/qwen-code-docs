# Ленивая загрузка при первом использовании для зависимостей кодирования, терминала и Git

## Контекст

Issue #7264 отслеживает зависимости, присутствующие в замыкании жадных
статических импортов ACP-child процесса, хотя большинство сессий никогда их не
использует. Кандидат 5 группирует три пакета с разными границами первого
использования:

| Пакет                    | Baseline замыкания ACP | Первое использование                                                |
| ------------------------ | -------------------: | ----------------------------------------------------------------- |
| `iconv-lite`             |        551 713 байт | Чтение или запись не-UTF-8 текста без BOM                   |
| `@xterm/headless`        |        213 071 байт | Запуск shell через PTY-путь                             |
| `simple-git`             |        146 526 байт | Выполнение Git-операций worktree, cleanup или GitHub-расширения |
| **Итого по пакетам напрямую** |    **911 310 байт** |                                                                   |

Прямая сумма составляет примерно 890 KiB. Полное статическое замыкание ACP
также содержит модули, которые становятся недостижимыми, когда эти пакеты
уходят с жадного пути, поэтому измеренное уменьшение на уровне бандла может
быть больше.

## Цели

- Убрать все три пакета из замыкания статических импортов ACP-child.
- Сохранить текущие синхронные публичные помощники кодирования.
- Загружать каждый пакет один раз, при первом реальном использовании, без
  новой конфигурации.
- Сохранить поведение фолбэка shell, поведение Git, метаданные кодирования
  файлов, обработку BOM и атомарные записи.
- Добавить защиту бандла, чтобы будущие импорты не могли тихо вернуть эти
  пакеты в жадное замыкание.
- Валидировать изменение с той же приемочной дисциплиной 2-vCPU, 4-GiB, что и
  другие кандидаты в #7264.

## Не-цели

- Изменение публичных API кодирования с синхронных на асинхронные.
- Замена `iconv-lite`, `@xterm/headless` или `simple-git`.
- Изменение выбора PTY, семантики worktree, определения кодирования или
  политики ошибок.
- Оптимизация кода, который выполняется после того, как эти зависимости уже
  загружены.

## Наблюдения по замыканию импортов

Baseline-бандл, собранный из `febb43bc9266cc7a3363539df87d90d752ad782c`, имеет
статическое замыкание ACP в 13 405 027 байт по 144 выходам. Обход metafile
esbuild приписывает 551 713 байт `iconv-lite`, 213 071 байт `@xterm/headless`
и 146 526 байт `simple-git`.

Первоначальных ленивых импортов на уровне пакетов было недостаточно. CLI
содержал динамические импорты корня пакета Core в производственном
пространстве имен. В сборке esbuild с code-splitting запрос всего пространства
имен сохраняет каждый экспорт корня достижимым, включая экспорт совместимости
синхронного кодирования. Поэтому дизайн требует и локальных для зависимости
загрузчиков, и узких runtime-входных модулей CLI, которые реэкспортируют
только символы, потребляемые каждым отложенным путем.

## Дизайн

### Свойства общего загрузчика

Каждый пакет имеет локальный для пакета загрузчик, опирающийся на промис
скоупа модуля. Конкурентные первые пользователи разделяют один и тот же
импорт, а последующие пользователи переиспользуют разрешенный модуль.
Загрузчики нормализуют формы CommonJS-интероперабельности, испускаемые Node и
esbuild, и выставляют только члены рантайма, нужные их потребителям.

Загрузчики намеренно используют `import()`, а не `createRequire()`.
Производственный бандл самодостаточен и не должен зависеть от отдельно
установленного дерева `node_modules`. Динамические импорты позволяют esbuild
испускать автономные чанки, удерживая эти чанки вне статического замыкания
ACP.

### `@xterm/headless`

`ShellExecutionService.execute()` уже асинхронен. Сервис сначала получает
реализацию PTY, затем загружает `@xterm/headless` непосредственно перед
входом в путь исполнения PTY. Он повторно проверяет сигнал отмены после
асинхронного импорта и передает разрешенный конструктор `Terminal` в
существующие синхронные помощники PTY и воспроизведения.

Если чанк терминала не загружается, ошибка остается внутри существующей
границы сбоев PTY, и исполнение откатывается на `child_process`, соответствуя
текущей политике фолбэка. Загрузка пакета не происходит, когда поддержка PTY
недоступна или выбран путь child-process.

### `simple-git`

Все реальные Git-операции в аудированных потребителях асинхронны.
`GitWorktreeService` сохраняет конструирование без побочных эффектов и
разрешает промис `SimpleGit` на экземпляр только при вызове его первого
Git-метода. Другие потребители Core используют тот же локальный для пакета
загрузчик напрямую.

Очистка при старте сначала использует существующее легковесное обнаружение
корня репозитория. Она загружает `simple-git`, только когда присутствует
реальный репозиторий и необходим осмотр устаревших worktree. Неудачный импорт
отклоняет операцию на той же асинхронной границе, где уже сообщалось о сбое
инициализации Git.

### `iconv-lite`

Этот пакет имеет главный ограничитель совместимости:
`decodeBufferWithEncodingInfo()` и `encodeTextFileContent()` — публичные
синхронные API. Динамический импорт в JavaScript асинхронен, поэтому прямое
объявление этих функций ленивыми стало бы нарушением API.

Синхронные API остаются доступными через модуль совместимости, который
статически импортирует `iconv-lite`. Только край реэкспорта корня Core
помечен для бандла как свободный от побочных эффектов, позволяя esbuild
отбрасывать модуль совместимости, когда конкретный вход не использует эти
экспорты. Другие импорты модуля сохраняют обычную обработку побочных
эффектов.

Внутренние асинхронные пути file-service используют ленивые варианты:

- Записи пустого, помеченного BOM, валидного UTF-8, ASCII и UTF-8 завершаются
  без загрузки `iconv-lite`.
- Обнаруженное не-UTF-8 чтение загружает кодек перед декодированием.
- Запись, сохраняющая не-UTF-8 метаданные, загружает кодек перед кодированием.
- Сбой загрузки или декодирования на стороне чтения сохраняет текущее
  предупреждение и фолбэк замены на UTF-8.
- Сбой загрузки или кодирования на стороне записи отклоняет запись вместо
  повреждения байтов.

Отложенные импорты пространства имен Core в CLI заменяются узкими локальными
runtime-входными модулями. Это избегает удержания каждого экспорта корня Core,
сохраняя тот же экземпляр бандла Core и идентичность классов.

## Защита бандла

Защита быстрого пути ACP трактует `iconv-lite`, `@xterm/headless` и
`simple-git` как запрещенные статические пакеты. Статический путь от входа ACP
проваливает проверку; пути только с динамическими импортами разрешены. Тесты
покрывают и отклонение, и разрешенные динамические границы.

Эта защита вычисляет граф импортов metafile, а не текст бандла, поэтому
переименованный чанк или минифицированный символ не может ее обойти.

## Аудит совместимости и сбоев

| Область                         | Сохраненное поведение                                        | Новая граница                                                             |
| ------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Исполнение shell                 | Обработка вывода PTY, воспроизведение, отмена, фолбэк child-process     | Чанк терминала загружается после выбора PTY                            |
| Worktree и GitHub-расширения | Существующие опции `simple-git` и распространение ошибок            | Модуль Git загружается при первой асинхронной Git-операции            |
| Чтение текста                      | Быстрые пути BOM и UTF-8, метаданные кодирования, фолбэк-декодирование | Кодек загружается только для обнаруженного не-UTF-8 фолбэка                  |
| Запись текста                     | Сохранение BOM, не-UTF-8 кодирование, поведение атомарной записи    | Кодек загружается только когда не-UTF-8 метаданные требуют этого                |
| Публичный API Core                 | Сигнатуры и поведение синхронных помощников кодирования            | Экспорт совместимости может быть tree-shaken из входов, которые его не используют |

Дизайн не вносит процесс-глобальной мутируемой конфигурации. Промисы
загрузчиков локальны для процесса и идемпотентны. Отклоненные импорты
остаются отклоненными, что уместно, потому что отсутствующий или поврежденный
чанк бандла не может восстановиться в течение того же времени жизни процесса.

## Рассмотренные альтернативы

### Преобразовать синхронные API кодирования в промисы

Отклонено, потому что это ломает публичных вызывающих и расширяет внутреннюю
по своей сути оптимизацию запуска.

### Использовать `createRequire()` при первом использовании

Отклонено, потому что это сделало бы бандл CLI зависимым от установки
`node_modules` в рантайме и не дало бы самодостаточный артефакт релиза.

### Переписать таблицы кодирования или поведение терминала

Отклонено как существенно более рискованное, чем откладывание существующих
пакетов.

### Внедрить только `@xterm/headless` и `simple-git`

Это было бы проще, но оставило бы самый большой пакет группы на жадном пути и
не удовлетворило бы кандидата 5. Фасад совместимости и узкие runtime-входные
модули убирают `iconv-lite` без изменения его публичного API.

## План верификации

1. Собрать производственные артефакты только для CLI и забандлить их с
   code splitting esbuild.
2. Обойти статическое замыкание metafile входа ACP и требовать нулевых
   приписанных байтов для всех трех пакетов.
3. Запустить сфокусированные unit-тесты для чтения и записи кодирования,
   исполнения shell и фолбэка, поведения Git worktree, очистки, операций
   GitHub-расширения, каждого загрузчика и защиты бандла.
4. Запустить затронутые тесты CLI, сборку и полный typecheck.
5. На референсном хосте 2-vCPU, 4-GiB запустить один парный smoke-тест, затем
   30 чередующихся последовательных холодных пар и 30 прогретых пар. Сообщить
   `channel.initialize`, задержку от процесса до первой сессии, пиковый RSS
   дерева процессов, конкурентность, поведение с отключенной телеметрией,
   легаси-поведение одной сессии и остаточные процессы.

## Измеренный результат на 2C4G

Удаленный хост имел 2 vCPU, 3,5 GiB общего RAM, без swap, и Node.js 22.23.1.
Отдельный smoke-прогон на одной паре и его функциональные сценарии прошли до
формального прогона. Затем формальный прогон завершил 30 чередующихся
последовательных холодных пар и 30 чередующихся прогретых пар, после чего еще
один набор функциональных сценариев, без сбойных сессий или остаточных
процессов.

Формальным кандидатом был скопированный артефакт прототипа с SHA-256
`f0ac7edc7665752efac7b7bfbb4fb055ce2d8ef1a8ae5dd1af630305a2c84d28`, помеченный
харнессом как `febb43bc9266cc7a3363539df87d90d752ad782c+candidate5`. Результат
применим к этому точному артефакту, а не к будущему SHA коммита; PR должен
сохранить хеш артефакта или перезапустить гейт, если его производственный код
меняется.

Кандидат также прошел конкурентные первые сессии, запуск с отключенной
телеметрией и легаси-запуск одной сессии. Проба первого использования с
производственной конфигурацией прошла GBK-кодирование/декодирование,
конструирование и запись headless-терминала, идентичность single-flight
загрузчика и инициализацию реального локального репозитория `simple-git`. На
удаленном хосте нет исполняемого файла `git`, поэтому удаленная проба
`simple-git` проверила загрузку модуля и конструирование фабрики, но не могла
выполнить реальную Git-команду; полные локальные сьюты сервиса Git покрывают
эти операции.

Приемочный гейт удовлетворен: победы на холодном пути консистентны во всех 30
парах задержки, остаются видимыми в метрике прогретой инициализации канала и
не обменивают задержку на повышенную память.

## Риски и раскатка

Главный риск — сбой только при первом использовании, который жадные импорты
раньше выставляли при старте. Сфокусированные тесты проходят пути первого
использования, а защита производственного бандла проверяет, что импорты
остаются динамическими. Удаленные smoke- и приемочные прогоны проходят
реальные забандленные ACP-сессии и проверяют остаточные процессы.

Этот кандидат должен оставаться отдельным PR, как требует #7264, чтобы его
поверхность регрессий и эффект производительности оставались приписываемыми.
Если гейт 2C4G не покажет воспроизводимого преимущества при старте или
покажет заметный регресс первого использования, реализацию не следует
внедрять только ради уменьшения размера бандла.
