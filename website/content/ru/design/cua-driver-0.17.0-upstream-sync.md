# Синхронизация CUA Driver 0.17.0 с upstream

## Цель

Перевести вендоренные исходники CUA Driver с upstream
`cua-driver-rs-v0.7.0` на релизный тег `cua-driver-rs-v0.17.0`, сохранив
рантайм и контракт дистрибуции, специфичные для Qwen.

Релизный тег, коммит `10279552e2bbe479e367a082f78b1b98ee85a697`, является
источником истины. Локальный checkout `/Users/mochi/code/cua`, старые проектные заметки
и сгенерированные артефакты — это только входы для сравнения.

## Область действия

Импорт из upstream ограничен `trycua/cua:libs/cua-driver` и мапится в
`packages/cua-driver`. Воркфлоу upstream-монорепо, корневые скрипты, документация
и несвязанные библиотеки не импортируются автоматически. Любая новая зависимость от
этих файлов должна быть либо сделана локальной для пакета, либо явно замаплена на
существующую функциональность Qwen Code.

Принадлежащий Qwen релизный воркфлоу остается `.github/workflows/cd-cua-driver.yml`.
Он может получить минимальные изменения, требуемые новым контрактом сборки и релиза
драйвера, но должен продолжать публиковать принадлежащие Qwen артефакты.

## Требуемые дельты Qwen

Синхронизация неполна, если все из следующего не остается в силе:

1. Установленный исполняемый файл, процесс, app bundle, идентификатор бандла, пути,
   запланированные сервисы, документация и релизные ассеты используют принадлежащую Qwen
   идентичность, ожидаемую текущей релизной линейкой Qwen. Домашний каталог релизного состояния
   остается `~/.cua-driver` для совместимости обновлений; изолированный домашний каталог
   локальной сборки остается `~/.qwen-cua-driver-local`.
2. `CUA_DRIVER_RS_COORDINATE_SPACE=1` продолжает предоставлять явно включаемый (opt-in) контракт координат 0-1000
   на общей границе вызова. Он должен покрывать каждый новый несущий координаты
   desktop-инструмент и инструмент, смежный с браузером, либо завершаться fail closed.
3. `MCP_MODEL_PAYLOAD_FILTER=1` продолжает фильтровать видимый модели брендинг как в
   текстовом содержимом MCP, так и в структурированном содержимом, не изменяя бинарные медиа.
4. Все еще не слитое поведение верхнеуровневых окон Windows с пустым/null заголовком из
   trycua/cua#2021 остается на месте и адаптировано к текущей модели окон.
5. Патч записи в сокет при EAGAIN из trycua/cua#2036 выводится из локального
   инвентаря патчей, потому что он является частью базы 0.17.0.

## Изменения контракта upstream

Импорт включает принадлежащий SDK рантайм, Python и TypeScript UniFFI SDK,
типизированную автоматизацию браузера, режимы разрешений рантайма, область захвата per-session,
токены элементов, привязанные к снимку, закрытый контракт `ActionResult`,
`verify_state`, вызов нативных меню, инструменты буфера обмена, обрамление окон и
семантические темы курсора.

Это архитектурные замены, а не независимые листовые функции.
Преобразования координат и полезной нагрузки Qwen должны быть повторно прикреплены к
канонической границе SDK/инструмента, чтобы выполнение в CLI, MCP, прямом SDK, приватном воркере и демоне
не могло разойтись.

## Стратегия импорта

1. Запустить поддерживаемый репозиторием скрипт upstream-дельты от текущего
   ref в `.vendored-from` до `cua-driver-rs-v0.17.0`.
2. Проинвентаризировать каждый reject, удаление, новый сгенерированный файл, путь относительно корня,
   идентичность пакета, релизную версию и внешние зависимости сборки.
3. Разрешать перекрытия upstream/локальных, сохраняя архитектуру upstream и
   повторно выражая каждую дельту Qwen на ее новой канонической границе.
4. Обновить `.vendored-from`, `.vendored-patches.md`, ссылки на версии, установщики Qwen
   и релизный воркфлоу Qwen вместе.
5. Аудировать исходники, тесты, документацию, сгенерированные биндинги, установщики, метаданные
   бандла, имена процессов, имена сервисов и релизные архивы на согласованность
   идентичности.

## Верификация

Верификация многоуровневая, чтобы зеленый узкий юнит-тест не мог скрыть сломанный
дистрибутив или границу доверия:

- Rust-форматирование, проверки пакетов, юнит-тесты core/контракта/SDK и сгенерированная
  согласованность контракта.
- Сфокусированные тесты нормализации координат, фильтра полезной нагрузки, перечисления окон Windows,
  установщика и версий.
- Проверки генерации/пакетов Python и TypeScript SDK, когда их локальная для пакета
  тулчейн доступна.
- Статические проверки релизного воркфлоу Qwen на имена исполняемых файлов, раскладку app bundle,
  идентификаторы бандла, ассеты и зашитые версии.
- `npm run build && npm run typecheck` для объемлющего репозитория.
- Полный аудит diff и неотслеживаемых файлов, повторяемый, пока два последовательных прохода не будут
  чистыми.

Создание подписанных/нотаризованных релизов и физическая сертификация GUI на Windows/Linux/macOS
выходят за пределы локальной верификации и должны оставаться явными релизными
гейтами.
