# Экспорт сессий с квалификацией по рабочему пространству

## Резюме

Задача #6378 требует, чтобы клиенты могли экспортировать персистентную сессию
из явно выбранного зарегистрированного рабочего пространства. Существующий
маршрут `GET /session/:id/export` намеренно привязан к primary-рабочему
пространству, поэтому его переиспользование для вторичной сессии либо
возвращает `404`, либо может выбрать не тот транскрипт, когда один и тот же
id сессии существует в нескольких рабочих пространствах.

Это изменение добавляет
`GET /workspaces/:workspace/session/:id/export?format=html|md|json|jsonl`,
возможность (capability) `workspace_session_export`, соответствующий метод
`WorkspaceDaemonClient` и сопроводительную документацию. Legacy-маршрут
остается привязанным к primary.

## Контракт

Селектор рабочего пространства следует существующему правилу множественных
маршрутов: сначала точный id зарегистрированного рабочего пространства, затем
URL-кодированный абсолютный cwd после канонизации. Выбранный рантайм должен
быть доверенным. Разрешение и проверки доверия выполняются до валидации
сессии или формата.

Маршрут читает только активный персистентный JSONL выбранного рабочего
пространства. Он не ищет в другом рабочем пространстве, не откатывается на
primary, не разрешает живого владельца, не запускает ACP, не присоединяет
клиента и не загружает настройки рабочего пространства. Архивные сессии
остаются недоступными. Успех использует тот же форматтер, санитизацию имени
файла, MIME-тип, политику кэширования и заголовки вложения, что и legacy-маршрут
экспорта.

Ошибки сохраняют существующие формы экспорта/хранилища, с
`400 workspace_mismatch`, `403 untrusted_workspace`,
`400 invalid_export_format`, `404 session_not_found` и существующими
контрактами `409 session_archived`, `session_archiving` и
`session_conflict`.

## Возможность и совместимость

`workspace_session_export` — безусловная возможность v1, поскольку
множественный маршрут полезен для доверенного primary одного рабочего
пространства, выбранного по id или cwd. Доверие по-прежнему оценивается на
каждый запрос. Новый тег независим от `multi_workspace_sessions` и не может
быть выведен из `session_export` или `workspace_qualified_rest_core`;
выпущенные демоны объявляют оба старых тега, но не реализуют этот маршрут.

Прямые вызывающие стороны SDK получают обычную HTTP-ошибку, когда вызывают
новый метод против старого демона. Интеграция Web Shell выходит за рамки
этого изменения, поэтому его существующее поведение экспорта только для
primary остается без изменений.

## Конкурентность и безопасность

Экспорт сохраняет существующую общую блокировку координатора архива с ключом
по id сессии, поэтому архивация и удаление не могут переместить или удалить
файл во время воспроизведения. Координатор остается консервативно глобальным:
идентичные id в разных рабочих пространствах могут сериализоваться, хотя их
файлы независимы. Переименование всех ключей блокировок архива/удаления
выходит за рамки этого изменения.

В отличие от ограниченного пейджера персистентных транскриптов, полный экспорт
материализует транскрипт целиком и недоступен недоверенному вторичному
рабочему пространству. Существующий доверенный экспорт не получает нового
бюджета размера ответа; добавление специфичного для рабочего пространства
лимита привело бы к расхождению контрактов формата множественного и legacy
маршрутов. Bearer-аутентификация демона, дефолтный уровень rate для чтения
GET и проверки доверия к рабочему пространству на каждый запрос продолжают
применяться.

Гонки удаления рантайма используют рантайм, выбранный при разрешении запроса.
Удаление не удаляет хранилище транскриптов, поэтому экспорту не нужна аренда
рантайма, и он не держит ACP-потомка живым.

## SDK и наблюдаемость

`WorkspaceDaemonClient.exportSession` переиспользует существующие типы
результата экспорта и формата и всегда использует нативный REST, в том числе
когда у родительского клиента есть транспорт ACP. Общий помощник запросов
сохраняет токен, идентичность клиента, таймаут, разбор ошибок, тип контента и
поведение имени файла вложения.

Телеметрия демона нормализует новый путь как
`GET /workspaces/:workspace/session/:id/export`, декодирует id сессии и
использует разрешение рабочего пространства middleware для хэша выбранного
рабочего пространства.

## Отклоненные альтернативы

- Маршрутизация экспорта в единственном числе по живому владельцу не работает
  для неактивных персистентных сессий и делает владение неоднозначным после
  перезапуска.
- Добавление query-параметра `cwd` к legacy-маршруту меняет контракт
  совместимости только для primary и менее консистентно, чем существующие
  множественные маршруты рабочего пространства.
- Откат на primary при промахе может экспортировать сессию другого рабочего
  пространства при коллизии id.
- Разрешение полного экспорта для недоверенных обошло бы политику
  ограниченного чтения, разработанную для пейджера персистентных
  транскриптов.

## Верификация

Тесты покрывают объявление возможности, селекторы id/cwd, изоляцию одинаковых
id, каждый формат, заголовки ответа, границы доверия и архива,
отсутствующие/неизвестные цели, отсутствие активности бриджа, атрибуцию
телеметрии, транспорт и кодирование SDK, а также координацию архива/удаления.
Сквозная верификация использует изолированные каталоги рантайма и рабочего
пространства с детерминированными персистентными транскриптами.
