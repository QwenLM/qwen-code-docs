# Совместимость имен инструментов MCP с провайдерами

## Проблема

Qwen Code сейчас принимает имена инструментов MCP, используя набор символов
Gemini. Имена вроде `literature.search_pubmed` становятся
`mcp__server__literature.search_pubmed`, что Gemini принимает, но более
строгие OpenAI-совместимые и Anthropic-совместимые эндпоинты могут отклонить
до того, как инструмент сможет выполниться.

То же сырое имя независимо реконструируется для регистрации, персистентности
разрешений, поиска при переподключении, усечения вывода и восстановленной
истории. Поэтому изменение только запроса к провайдеру сделало бы видимое
модели имя отличным от ключа реестра.

## Дизайн

Использовать одно детерминированное безопасное для провайдера правило
нормализации для имен инструментов MCP:

- Сохранять имена, уже соответствующие `^[A-Za-z][A-Za-z0-9_-]*$` и длине не
  более 63 символов.
- Заменять неподдерживаемые символы, обеспечивать первый символ-букву и
  добавлять стабильный короткий хеш всякий раз, когда требуется нормализация
  или усечение.
- Держать финальное имя в пределах 63 символов, что принимается Gemini и
  более строгими OpenAI-совместимыми и Anthropic-совместимыми провайдерами.
- Использовать зарегистрированное имя на протяжении всего вызова MCP вместо
  пересборки его из сырых имени сервера и инструмента.
- Нормализовать имена MCP в восстановленной истории запросов OpenAI и
  Anthropic, чтобы сессии, созданные до изменения, оставались отправляемыми.
- Продолжать сопоставлять легаси-записи разрешений и отключенных инструментов
  MCP, перенося точный пре-нормализационный алиас, выведенный из сырых имен
  сервера и инструмента. Это также сохраняет имена, усеченные предыдущим
  алгоритмом усечения середины, без расширения совпадений wildcard.

Никакая специфичная для провайдера таблица алиасов не вводится. Законные
существующие имена остаются неизменными байт в байт, поэтому поведение Gemini
и обычные встроенные инструменты не затрагиваются.

Восстановленные имена, созданные предыдущим алгоритмом усечения середины, уже
безопасны для провайдера и остаются неизменными в исторических сообщениях.
Их удаленная середина не может быть достоверно реконструирована, поэтому
конвертеры не угадывают новое имя на основе хеша; точная совместимость
разрешений и отключенных инструментов вместо этого использует алиас сырого
имени, доступный при регистрации MCP.

## Верификация

- Unit-тесты для валидных, невалидных, конфликтующих, длинных, стабильных и
  идемпотентных имен.
- Тесты инструментов MCP для регистрации, правил разрешений, поиска при
  переподключении и отключенных инструментов.
- Тесты конвертеров OpenAI и Anthropic для восстановленной истории,
  содержащей имена MCP с точками.
- Сборка и typecheck пакета core.
