# Семантика ошибок тайм-аута Shell

## Проблема

Foreground-команды Shell сейчас описывают тайм-аут в тексте, но возвращают успешный `ToolResult`. Нижестоящий код поэтому записывает вызов как успешный, отправляет ответ функции с полем `output` и может отрисовать индикатор успеха, хотя команда не завершилась. Отмена, приходящая после тайм-аута, также может перезаписать исходную причину. Во время обнаружения PTY уже прерванный вызов всё ещё может запустить процесс, поскольку сервис выполнения не наблюдает сигнал до старта.

## Контракт результата

Тайм-аут foreground, принадлежащий Shell, возвращает `ToolErrorType.EXECUTION_TIMEOUT`. Результат использует три намеренно разделённых канала:

| Канал           | Аудитория                               | Содержимое при тайм-ауте                                                                     |
| --------------- | --------------------------------------- | -------------------------------------------------------------------------------------------- |
| `error.message` | Хуки, телеметрия, спаны, логи, алертинг | Только краткая сводка тайм-аута                                                              |
| `llmContent`    | Ответ функции модели                    | Сводка тайм-аута, частичный вывод или явное заявление об отсутствии вывода, и любой указатель усечения |
| `returnDisplay` | Интерактивная история и клиенты ACP     | Сводка тайм-аута, частичный вывод или заявление об отсутствии вывода, и любой указатель усечения |

Планировщик преобразует `llmContent` тайм-аута в ответ функции, чей `response` имеет поле `error` и не имеет поля `output`. Дополнительный контекст хука сбоя добавляется к этой面向енной модели ошибке один раз. Верхнеуровневый `ToolCallResponseInfo.error` остаётся краткой операционной сводкой, чтобы вывод команды не копировался в телеметрию или аргументы ошибок хуков.

Остальные мягкие ошибки инструментов сохраняют существующее поведение планировщика Core. ACP и спекулятивное выполнение последовательно кодируют все мягкие ошибки Envelope'ом ошибки, поскольку эти пути вызывают инструменты напрямую и иначе не имеют шага классификации планировщика.

## Правила первопричины

`AbortSignal.any()` сохраняет причину первого сигнала, который прерывает. Классификация Shell читает только комбинированную причину сигнала после выполнения:

- `TimeoutError` плюс прерванное выполнение — это тайм-аут.
- Причина background-promote плюс прерванное, не продвинутое выполнение — существующая гонка отказа promote.
- Любое другое прерванное выполнение — отмена.
- Тайм-аут, случившийся первым, не меняется более поздней отменой пользователя или запросом promote.
- Отмена или запрос promote, случившиеся первыми, не меняются более поздним тайм-аутом.

Планировщик Core имеет второй, опциональный глобальный таймер выполнения. Структурированный тайм-аут, возвращённый инструментом, остаётся тайм-аутом, даже если родительский сигнал прерван до того, как планировщик потребит результат. Когда тайм-аут поставляет собственный таймер планировщика, он побеждает только если родительский сигнал ещё не был прёрван в момент срабатывания таймера. Отмена родителя с последующим срабатыванием таймера против несотрудничающего инструмента остаётся отменой.

ACP применяет то же правило для структурированных тайм-аутов инструментов: тайм-аут является ошибкой, а не прерыванием, даже если его родительский сигнал наблюдается прёрванным впоследствии. Брошенные исключения продолжают использовать живое состояние прерывания.

## Поведение при старте

`ShellExecutionService.execute()` немедленно возвращает прёрванный дескриптор без процесса, когда его сигнал уже прёрван. Обнаружение PTY устраивает гонку сигнала с `getPty()` и удаляет свой временный слушатель после гонки. Если прерывание побеждает, более поздний резолв или отклонение PTY потребляется без запуска PTY или отката на `child_process`. Возвращаемый результат использует `executionMethod: 'none'` и не имеет pid.

Это поведение затрагивает всех потребителей сервиса в репозитории: обвязку foreground и background Shell, пользовательский `!` Shell, инъекцию команд из промпта, обработку shell бриджа ACP и зонды атрибуции git. Единственное изменение поведения — уже прёрванный запрос больше не запускает процесс.

## Поведение потребителей

| Потребитель                         | Поведение при тайм-ауте                                                                                          |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Планировщик Core                    | `status: error`, краткая верхнеуровневая ошибка, детальный `response.error`, тип сбоя timeout                    |
| ACP-сессия                          | обновление failed tool, детальный Envelope ошибки в истории модели и записи, краткие операционные метаданные      |
| Спекулятивное выполнение            | детальный Envelope ошибки; принятая спекулятивная история отображает Error                                        |
| Anthropic-адаптер                   | `tool_result.is_error: true`                                                                                     |
| OpenAI-совместимые адаптеры         | явный детальный текст ошибки; протокольный бит ошибки отсутствует                                                 |
| JSON и stream-json                  | `is_error: true`, детальный вложенный контент ошибки предпочтительнее краткой сводки                              |
| Оценка контекста и бюджет батча     | учитываются и `response.output`, и текст `response.error`; слишком большие ошибки сохраняют ключ error при выгрузке |

Микросжатие по-прежнему не трогает неудачные результаты инструментов. Полное сжатие чата теперь видит детальный размер ошибки и может срабатывать при корректном бюджете.

## Сравнение с Claude Code

Claude Code трактует тайм-аут команды как неудачный результат инструмента, сохраняет вывод, произведённый до завершения, для модели и пользователя, и помечает результат инструмента как ошибку в протоколе Anthropic. Этот дизайн принимает эти наблюдаемые свойства, сохраняя существующую форму `ToolResult` и конвенции телеметрии qwen-code. Он не копирует вывод команды в краткий операционный канал ошибок.

## Совместимость и наблюдаемость

Это намеренная коррекция на уровне wire. Мягкие сбои ACP и спекуляции меняются с `{ output }` на `{ error }`; Core меняет эту форму только для `EXECUTION_TIMEOUT`. Счётчики тайм-аутов переходят из метрик успеха в метрики ошибок/тайм-аутов, и хуки сбоя заменяют хуки успеха. Схема, enum ошибок, тайм-аут по умолчанию, миграция или флаг раскатки не меняются.

Частичный вывод команды может содержать чувствительные данные. Он остаётся доступным модели, интерактивному результату, записи чата и явному JSON-выводу, как и до коррекции классификации. Он не добавляется в аргументы ошибок хуков, верхнеуровневые ошибки, атрибуты результатов спанов или сводки операционных логов. Существующие лимиты усечения и выгрузки на диск применяются к детальному каналу модели.

## Вне области действия

- Heartbeat'ы или периодическая отчётность о прогрессе
- Stop-guard'ы todo или изменения промпта
- Семантика ненулевого кода выхода
- Семантика завершения внешним сигналом
- Тайм-ауты background Shell
- Ожидание частичного вывода после победы глобального таймера планировщика
- Новые настройки тайм-аута или поля протокола

## Проверка

Покрытие модульными тестами отрабатывает гонки предварительного прерывания и обнаружения PTY, порядок timeout/cancel/promote в Shell, симуляцию sed, краткий и детальный каналы планировщика, порядок глобального тайм-аута Core, прямой вызов ACP и спекуляции, конвертацию Anthropic, выбор контента JSON, оценку размера ошибок и выгрузку батча. План E2E записан в `.qwen/e2e-tests/shell-timeout-semantics.md`.
