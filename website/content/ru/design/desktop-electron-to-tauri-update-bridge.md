# Бридж обновления десктопа с Electron на Tauri

## Контекст

Последний опубликованный десктопный релиз, `desktop-v0.0.5`, — это
Electron-приложение с именем `Qwen Code Desktop` и идентификатором бандла
`com.alibaba.qwen-code`. Его macOS-апдейтер читает `latest-mac.yml` из
фиксированного релиза `desktop-latest` и устанавливает ZIP-архив.

Новая десктопная оболочка — это Tauri-приложение. Сейчас оно использует
другое имя продукта и идентификатор бандла и публикует
`desktop-latest.json`, поэтому существующее Electron-приложение не может его
обнаружить или заменить.

## Цели

- Позволить подписанным macOS Electron-установкам `0.0.5` обновляться
  напрямую на первый стабильный Tauri-релиз.
- Сохранить существующую идентичность macOS-приложения, чтобы апдейтер
  заменил установленный бандл приложения.
- Сохранить подписанный фид апдейтера Tauri для всех релизов после миграции.
- Сделать бридж включаемым явно и одноразовым; последующим релизам не должны
  требоваться инструменты сборки Electron.

## Не цели

- Миграция настроек, сессий или состояния рабочих пространств Electron.
  Tauri-приложение может запросить рабочее пространство при первом запуске.
- Бриджинг Windows- или Linux-установок Electron.
- Генерация дифференциальных blockmap Electron. Апдейтер Electron
  откатывается на полный ZIP с проверкой контрольной суммы.

## Контракт совместимости

Tauri-бандл использует legacy-идентичность macOS:

- имя продукта: `Qwen Code Desktop`
- идентификатор бандла: `com.alibaba.qwen-code`
- префикс артефактов: `Qwen-Code-Desktop`
- идентичность подписи: существующий сертификат Developer ID Application

Бридж-релиз должен быть новее `0.0.5`. Он публикует два представления
апдейтера поверх одних и тех же подписанных бандлов приложения:

1. `latest-mac.yml` направляет legacy-клиенты Electron на
   `Qwen-Code-Desktop-arm64.zip` или `Qwen-Code-Desktop-x64.zip`.
2. `desktop-latest.json` направляет Tauri-клиенты на подписанные архивы
   апдейтера Tauri.

ZIP создается из уже подписанного и нотариально заверенного `.app`; он не
пересобирается инструментами Electron.

## Поток релиза

`Desktop Release` получает вход `electron_bridge`, отключенный по умолчанию.

- Все macOS-сборки продолжают собирать Tauri-приложение, DMG, архив апдейтера
  и подпись апдейтера.
- Когда `electron_bridge` включен, каждая macOS-сборка также создает
  legacy-совместимый ZIP.
- Задача публикации генерирует `latest-mac.yml` из двух ZIP и двух DMG.
- Стабильный бридж-релиз загружает legacy-метаданные и полезные нагрузки в
  `desktop-latest` вместе с `desktop-latest.json`.
- Последующие стабильные релизы оставляют `electron_bridge` отключенным.
  Обновление `desktop-latest.json` не удаляет файлы бриджа, поэтому установки
  Electron, вернувшиеся позже, все равно могут перейти на Tauri.

Запуски draft и prerelease могут собирать и публиковать бридж-артефакты для
инспекции, но они никогда не обновляют стабильный фид.

## Учетные данные подписи

Репозиторий уже хранит сертификат Apple эпохи Electron и ключ API App Store
Connect под именами секретов `MAC_CSC_*` и `APPLE_NOTARY_*`. Workflow
принимает эти имена как фолбэки для более новых имен Tauri, поэтому
идентичность Developer ID остается неизменной.

Артефакты апдейтера Tauri дополнительно требуют
`TAURI_SIGNING_PRIVATE_KEY`; `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` нужен
только для зашифрованного приватного ключа. Приватный ключ должен
соответствовать публичному ключу в конфигурации Tauri до первого
опубликованного Tauri-релиза.

## Валидация

Автоматизированные тесты release-helper проверяют:

- идентичность legacy-приложения,
- точный выбор бридж-артефактов,
- значения SHA-512 и размера в `latest-mac.yml`,
- отказ при отсутствии требуемого бридж-артефакта,
- существующее поведение манифеста апдейтера Tauri и синхронизации версий.

Перед стабильным релизом установите подписанные сборки `desktop-v0.0.5`
arm64 и x64, направьте их на изолированный фид бриджа и проверьте оба
обновления `0.0.5 -> Tauri bridge` и `Tauri bridge -> более новый Tauri`.
