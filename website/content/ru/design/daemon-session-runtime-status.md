# Runtime-статус сессий демона

## Проблема

Клиенты демона могут опрашивать живую сессию через `GET /session/:id/status`
и перечислять сессии через `GET /workspace/:id/sessions`, но единственным
сигналом runtime-активности сегодня является `hasActivePrompt`. Клиенты не
могут отличить ход, ожидающий обычного разрешения, ответ на
`ask_user_question` или неудачный ход, чья ошибка должна оставаться видимой
до возобновления работы.

## Дизайн

ACP-бридж владеет небольшим in-memory расширением статуса на каждой живой
`SessionEntry`:

- `hasTurnError` и `turnError` хранят терминальную ошибку самого последнего
  неудачного хода.
- `pendingInteractions` отображает id ожидающих запросов разрешения на
  нормализованные, готовые к рендерингу действия разрешения или вопросы
  пользователя.

Существующий жизненный цикл промпта остается источником для
`hasActivePrompt`. Неудачный ход записывает свои санитизированные `message`,
опциональный `code` и опциональный `errorKind`, когда эмиттирует существующее
SSE-событие `turn_error`. Ошибка остается видимой, пока следующий
поставленный в очередь промпт не достигнет диспетчеризации и фактически не
начнется; принятый, но поставленный в очередь промпт не очищает ее.

ACP-потомок явно помечает запросы разрешения `ask_user_question` в метаданных
вызова инструмента. Бридж читает только этот стабильный маркер, а не выводит
категорию из текста UI или имени инструмента.

## API

Существующая live-сводка получает опциональные аддитивные поля:

- `isWaitingForPermission`
- `isWaitingForUserQuestion`
- `pendingInteractionCount`
- `hasTurnError`
- `turnError` (`message`, опциональный `code`, опциональный `errorKind`)
- `pendingInteractions`: заголовок/содержимое/вход действия и выбираемые
  опции для разрешений; вопросы и выбираемые опции для `ask_user_question`.
  Каждый вопрос несет `answerKey` для полезной нагрузки голосования
  разрешения `answers: Record<string, string>`.

`GET /session/:id/status` возвращает все поля для живой сессии. Список сессий
рабочего пространства несет те же runtime-поля, включая `turnError` и
`pendingInteractions`, для живых записей, чтобы вызывающие стороны могли
рендерить и одобрять взаимодействия напрямую при пакетном опросе.
Персистентные сессии, которые не являются живыми, опускают новые поля, чтобы
вызывающие стороны не приняли недоступное runtime-состояние за известное
состояние покоя.

## Область

Это не персистит runtime-состояние через перезапуски демона, не добавляет
новый эндпоинт и не заменяет SSE для детального потребления событий.
Существующий маршрут голосования
`POST /session/:id/permission/:requestId` разрешает ожидающий элемент;
ответы на вопросы используют его существующее расширение `answers`.
