# Статус и детали фоновых агентов

## Проблема

Вызов инструмента Agent возвращается, как только фоновый агент запущен. Поэтому его блок транскрипта имеет терминальное событие инструмента, чья полезная нагрузка говорит `status: background`. Web Shell намеренно мапит этот результат запуска обратно на ожидающую карточку инструмента, но позже ничто не сверяет карточку с живым реестром фоновых задач. Список задач в футере достигает терминального состояния, тогда как исходная карточка Agent остается running.

Foreground-агенты уже открываются в общей панели деталей субагентов. Фоновые агенты имеют тот же `toolUseId`, запись реестра задач, JSONL-транскрипт и резолвер виртуальных сессий, но этот путь не имеет явного покрытия.

## Дизайн

Оставить проекцию запуска без изменений: результат запуска с `status: background` остается ожидающим, пока не придет авторитетное состояние задачи. Демон уже выпускает терминальные уведомления фоновых агентов через SSE-поток сессии со `status` задачи и `toolUseId`. Web Shell потребляет эти скрытые метаданные уведомлений и сверяет их обратно со спроецированной карточкой инструмента Agent.

- `completed` и `cancelled` завершают карточку.
- `failed` валит карточку.
- Таймстамп уведомления становится временем окончания карточки.
- Уведомления без `toolUseId`, уведомления не от агентов и несвязанные вызовы инструментов не меняют сообщения напрямую.

Существующий провайдер деталей субагентов остается единственным UI-путем. Карточки фоновых агентов остаются кликабельными, пока ожидаются и после терминальной сверки. Резолвер виртуальных сессий продолжает стримить JSONL задачи и получать живой статус из реестра задач без фильтрации по foreground/фоновому режиму. Для легаси-задач без `toolUseId` он сопоставляет запись запуска с персистентным sidecar и сохраняет терминальный статус sidecar, когда исходный результат фонового запуска все еще говорит `running`.

Пока отсоединенная работа активна, ее карточка в основном списке использует выделенный статический лейбл `background task` вместо foreground-лейбла `running`. Карточка не использует бегущий шиммер или тикающий таймер прошедшего времени. Терминальные уведомления заменяют этот лейбл обычным представлением completed, failed или cancelled.

Фоновые агенты исключаются из нижней строки статуса, потому что их прогресс доступен из кликабельной карточки и панели деталей. Они остаются в полной панели Tasks. Другие виды фоновых задач, включая shell-команды, остаются в нижней строке статуса и сохраняют свой существующий опрос. Сам по себе фоновый Agent не активирует опрос задач нижней панели.

Персистентные записи уведомлений не всегда сохраняют `toolUseId`. Поэтому, когда загруженный транскрипт содержит активную карточку фонового Agent, Web Shell резолвит каждую ожидающую карточку через существующий эндпоинт субагентов после догона транскрипта. Он повторяет эту одноразовую проверку после переподключения и когда приходит любое терминальное уведомление Agent, даже если это уведомление не может идентифицировать карточку напрямую. Он никогда не запускает интервал. Фокус ввода и обычный стриминг не меняют ID ожидающих вызовов Agent или ключ терминальных уведомлений и поэтому не инициируют новый запрос.

Прикрепленная панель деталей раскрывается от правого края, так что чат непрерывно выталкивается влево, вместо того чтобы менять размер перед отдельным движением панели. Настройки уменьшенного движения отключают анимацию прикрепления. Вкладки панели имеют фиксированную ширину, обрезают длинные заголовки и прокручиваются горизонтально, когда список вкладок превышает доступное место.

## Область действия

Это изменение обновляет проекцию Web Shell и резолвер статуса виртуальных субагентов демона. Оно не переписывает персистентные родительские транскрипты, не изменяет жизненный цикл задач, не добавляет опрос задач для фоновых агентов, не убирает агентов из полной панели Tasks и не добавляет второй просмотрщик субагентов.
