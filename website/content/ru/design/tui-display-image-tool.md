# Инструмент отображения изображений в TUI

## Цель

Добавить вызываемый моделью инструмент `display_image`, который показывает
предпросмотр существующего PNG в интерактивном терминальном UI. Инструмент
только отображает: он не предоставляет пиксели изображения модели и недоступен
в реестрах headless-режима, SDK, screen-reader и субагентов.

## Дизайн

Основной инструмент валидирует абсолютный путь рабочего пространства, статус
обычного файла, сигнатуру PNG и лимит размера 8 МиБ. При успехе он возвращает
небольшое структурированное значение отображения:

```ts
{
  type: 'terminal_image',
  filePath: '/absolute/workspace/path/image.png',
  mimeType: 'image/png',
}
```

Перед возвратом успеха инструмент спрашивает у инжектируемого CLI
провайдера, есть ли в текущем терминале доступный рендерер. Нативные
протоколы проходят сразу; фолбэк проверяет доступность `chafa` в `PATH`, не
рендеря выбранный файл. Если рендерер недоступен, инструмент возвращает
ошибку выполнения, чтобы и TUI, и модель знали, что изображение не было
показано. `llmContent` сообщает модели использовать `read_file`, если ей нужно
изучить изображение. Байты изображения и escape-последовательности терминала
никогда не попадают в историю модели или персистентное значение отображения.

`ToolMessage` распознаёт структурированное значение и делегирует его
TUI-компоненту. Компонент повторно валидирует путь относительно текущего
рабочего пространства перед чтением. Рендеринг готовится во время первого
рендера компонента, поскольку завершённые строки инструментов сразу попадают
в append-only область Ink `Static`; асинхронное обновление состояния было бы
там отброшено. Kitty-совместимые терминалы используют существующий подход с
виртуальным изображением и Unicode-placeholder'ами, уже применяемый для
диаграмм Mermaid. Другие терминалы пробуют `chafa` с символьным выводом.
`chafa` получает только тот же allowlist'нутый набор окружения, что и рендерер
Mermaid, поэтому API-учётные данные не пробрасываются. Если ни один путь
недоступен, TUI показывает ограниченный текстовый фолбэк с именем
изображения.

Предпросмотры ограничены 72 колонками и 24 строками, затем дополнительно
уменьшаются, чтобы поместиться в доступное пространство терминала. Оценка
терминальной ячейки 8 на 16 пикселей даёт консервативный естественный размер,
чтобы маленькие изображения намеренно не увеличивались. И нативный рендеринг,
и рендеринг через `chafa` используют одни и те же размеры с сохранением
пропорций.

Инструмент регистрируется только когда все следующие условия истинны:

- основная конфигурация интерактивна;
- режим SDK отключён;
- режим screen-reader отключён;
- реестр создаётся не для субагента.

Bare-режим сохраняет существующий минимальный набор инструментов.

## Совместимость

Первая версия поддерживает только PNG. Kitty и Ghostty используют нативное
размещение изображений. Warp намеренно исключён, поскольку его поддержка Kitty
не включает расширение Unicode-placeholder, используемое этим рендерером, а
прямое размещение дрейфует от контента Ink при прокрутке и перекомпоновке
терминала. Прямое размещение iTerm2 также исключено, поскольку его протокол
инлайн-изображений позиционируется по курсору, а существующий асинхронный
путь Ink уже трактует его как небезопасный. Warp, iTerm2, tmux, SSH и
терминалы без нативного пути по-прежнему могут рендерить через `chafa`, когда
он установлен.

## Безопасность и персистентность

И инструмент, и рендерер используют `WorkspaceContext.isPathWithinWorkspace`,
который резолвит симлинки и предотвращает выход за пределы зарегистрированных
корней рабочего пространства. Рендерер трактует восстановленные данные
`resultDisplay` как недоверенные и повторяет эту проверку. Персистентные
сессии содержат только путь и MIME-тип; если файл больше не существует,
восстановление деградирует до текстового уведомления.

Сырой вывод терминала генерируется только доверенным рендерером. Управляемые
моделью строки и содержимое файлов никогда не пишутся в терминал напрямую.
