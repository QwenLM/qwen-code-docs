# Переключатель изоляции worktree в пустом состоянии Web Shell

## Контекст

Единственная текущая точка входа для сессий с изоляцией worktree (см.
[2026-07-19-webshell-worktree-sessions.md](./2026-07-19-webshell-worktree-sessions.md)) —
это **выпадающее меню капсулы git-ветки** в шапке workspace сайдбара
(`WorkspaceSection.tsx`), который рендерится только при одновременном
выполнении трех условий: `onOpenGitDiff`, `workspace.trusted` и
`gitStatus?.branch`. Пользователю трудно догадаться, что git-pill кликабелен —
функция спрятана слишком глубоко.

У Web Shell нет отдельной «страницы создания сессии» — после нажатия «новая
сессия» показывается пустое состояние чата (WelcomeHeader + поле ввода),
которое и является фактической страницей создания сессии. В пустом состоянии
уже есть готовый UI бейджа worktree pending (`worktreeWelcomeBadge` в
`App.tsx`) и полная машина состояний pending (`pendingWorktreeRef` /
`worktreePending`), а сессия действительно создается только при отправке
первого сообщения (ленивое создание), поэтому «переключатель» лишь задает
намерение pending.

## Цели

- Предоставить в пустом состоянии чата видимый переключатель изоляции worktree,
  клик по которому переиспользует существующую машину состояний pending и
  цепочку ленивого создания.
- После включения показывать существующий бейдж pending и предоставить способ
  отмены.
- Сохранить без изменений точку входа в меню git-pill сайдбара (быстрый вход
  для каждого workspace).

## Не цели

- Не менять SDK, маршрутизацию демона, `GitWorktreeService` — цепочка создания
  полностью переиспользуется.
- Не менять существующую семантику «намерение следует за workspace»: намерение
  pending всегда применяется к workspace, разрешаемому при следующем создании
  сессии (`lockedWorkspaceCwd ?? selectedWorkspaceCwd ?? primary`), что
  соответствует текущему поведению точки входа сайдбара.
- Не обрабатывать сбойное сообщение «pending включен, затем выполнен переход
  на не-git workspace» (это и сейчас вызывает ошибку, выходит за рамки этого
  изменения).

## Дизайн

### Видимость переключателя (eligibility)

Переключатель отображается в пустом состоянии только когда все следующие
условия выполнены:

| Условие                            | Сигнал                                                          | Обоснование                                                            |
| ---------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Пустое состояние чата              | `welcomeHeader` рендерится только при `isChatEmptyState`        | Выполняется естественным образом, дополнительных проверок не нужно     |
| Текущий workspace доверен          | `workspaces.find(e => e.cwd === activeWorkspaceCwd)?.trusted`   | Согласуется с точкой входа сайдбара: недоверенный workspace не меняет git |
| Текущий workspace — git-репозиторий | `selectedWorkspaceGitStatus?.branch`                           | Демон жестко падает на не-git репозиториях (`worktree_not_git_repo`), поэтому скрываем заранее |

`activeWorkspaceCwd` переиспользует существующий memo (`connection.sessionId ?
connection.workspaceCwd : (locked ?? selected ?? primary)`),
`selectedWorkspaceGitStatus` переиспользует существующий эффект выборки. Оба —
существующее состояние, новых сетевых запросов нет. Пока git status не
загружен, переключатель не отображается, что соответствует гейтингу
`gitStatus?.branch` сайдбара.

### Взаимодействие

- **Выключенное состояние**: на месте бейджа рендерится неброская ghost-кнопка
  (иконка fork + текст `worktree.welcomeTitle`). Клик →
  `pendingWorktreeRef.current = {}` + `setWorktreePending(true)`.
- **Включенное состояние**: рендерится существующий `worktreeWelcomeBadge`
  (иконка + заголовок + описание), в правом верхнем углу добавляется кнопка
  отмены X (`aria-label` использует новый i18n-ключ). Клик →
  `pendingWorktreeRef.current = undefined` + `setWorktreePending(false)`.
- Отправка первого сообщения → `ensureSessionForPrompt` по существующей логике
  несет `worktree: {}`, после успеха pending автоматически очищается; при сбое
  бейдж сохраняется для повторной попытки (поведение не меняется).
- Существующие пути, такие как клик «новая сессия» в сайдбаре или загрузка
  существующей сессии, не меняют свою логику очистки pending.
