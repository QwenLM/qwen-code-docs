# Runtime-управление каналами демона

## Резюме

Добавляет управление желаемым состоянием в рантайме для воркеров каналов,
управляемых демоном. Демон может стартовать без `--channel`, а затем включать,
заменять, инспектировать, перезагружать и останавливать свой выбор каналов без
перезапуска демона. Изменения в рантайме не персистируются; следующая загрузка
демона по-прежнему следует `--channel`.

Слой управления находится над реализацией воркеров, сгруппированных по
рабочим пространствам. Он владеет зафиксированным выбором, сериализует мутации
жизненного цикла, сохраняет аренду channel-сервиса, принадлежащую serve, и
согласует только те группы рабочих пространств, чей упорядоченный выбор
изменился.

## Публичный контракт

`GET /workspace/channel` возвращает зафиксированный выбор, необязательный
ожидающий выбор, текущий переход и снимки воркеров с аннотацией рабочих
пространств.

`PUT /workspace/channel` принимает:

```json
{ "selection": { "mode": "names", "names": ["telegram", "feishu"] } }
```

или `{ "selection": { "mode": "all" } }`. Именованные выборы обрезаются и
дедуплицируются без сортировки. Пустой выбор невалиден. `all` остается
доступным только для primary-рабочего пространства в мульти-воркспейсном
режиме.

`DELETE /workspace/channel` идемпотентно отключает runtime-выбор.
`POST /workspace/channel/reload` остается доступным и перечитывает настройки
для зафиксированного выбора. Мутации используют строгий гейт bearer-токена.

Возможность (capability) `channel_control` объявляет ресурс.
`channel_reload` продолжает объявляться только пока у менеджера есть
зафиксированный перезагружаемый выбор.

## Жизненный цикл

Менеджер предоставляет неизменяемые снимки и проводит все мутации через одну
FIFO-полосу. Обновление выбора выполняет предполетную проверку владения и
доверия к рабочему пространству до остановки воркеров. Неизмененные записи
рабочих пространств сохраняются. Измененные и удаленные записи останавливаются
до запуска замен, при этом демон сохраняет глобальную аренду channel-сервиса.

Если замена не удается, менеджер пытается остановить недавно запущенные записи
и перезапустить предыдущие. Клиенты инспектируют `rolledBack`,
`rollbackError` и `state`, поскольку очистка или восстановление тоже могут не
удаться. Неудача наблюдения за выходом дочернего процесса после SIGKILL — это
жесткая ошибка остановки: супервизор сохраняет ссылку на дочерний процесс,
менеджер сохраняет аренду сервиса, и замена не запускается.

Колбэки воркеров несут поколение. Колбэки от замененных записей могут
логировать, но не могут обновлять текущий pidfile или состояние маршрутизации.
Успешный коммит обменивает выбор, конфигурацию вебхуков и карту воркеров
вместе, а затем перезаписывает полный снимок pidfile.

Частичное подключение адаптера сохраняет существующее поведение: воркер ready,
когда подключается хотя бы один запрошенный канал. Результаты управления
сообщают `partial`, а статус демона продолжает испускать
`channel_worker_partial_connect`.

## Совместимость

`--channel` при загрузке использует тот же менеджер, сохраняя резервирование
аренды до прослушивания и поведение ready-до-успеха. Без `--channel` демон не
резервирует channel-сервис и не загружает тяжелый runtime каналов до первой
runtime-мутации.

Legacy `runtime.channelWorker`, сгруппированный `runtime.channelWorkers`, поля
pidfile, отдельный `qwen channel start` и `qwen channel reload` остаются
совместимыми. Новое CLI-управление предоставляется через `qwen channel set`,
плюс удаленные варианты остановки каналов и статуса.
