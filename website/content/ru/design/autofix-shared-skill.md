# Один навык Autofix для локальных и CI-запусков

## Контекст

В Qwen Code уже есть принадлежащий репозиторию навык Autofix, используемый GitHub Actions.
Он содержит триаж фидбэка ревью и правила верификации, тогда как воркфлоу
владеет планированием, фильтрацией доверия, учетными данными, записями в GitHub и бюджетами
раундов.

Локальный Autofix должен переиспользовать этот навык вместо добавления бандленного навыка или
второго движка сопровождения. Его вход — текущее рабочее дерево, а не удаленный
pull request: staged, unstaged и untracked изменения ревьюятся вместе.

## Дизайн

Существующий `.qwen/skills/autofix/SKILL.md` остается единственным навыком Autofix. У него
две точки входа:

- Прямой вызов `/autofix` синхронно ревьюит и исправляет текущее
  рабочее дерево.
- Существующий раннер Actions предоставляет одно из `assess-candidates`,
  `develop-issue` или `address-review` плюс доверенные файлы, подготовленные воркфлоу.

Локальный путь многократно запускает существующую машиночитаемую команду ревью:

```bash
env -u SANDBOX QWEN_SANDBOX=true "${QWEN_CODE_CLI:-qwen}" review run --approval-mode auto --effort high --json --quiet
```

Команда выполняется как управляемый фоновый shell, так что ее собственный таймаут, а не
более короткий лимит foreground-инструмента, остается авторитетным. Autofix все равно ждет
ее синхронно: интерактивный TUI возобновляется из уведомления терминальной задачи,
тогда как сессии ACP, stream-json и headless-режим инспектируют sidecar статуса
с ограниченной нарастающей частотой. Отпечатки рабочего дерева вокруг
ревью и непосредственно перед сходимостью делают любой побочный эффект ревью или
параллельное редактирование видимым исходом `BLOCKED`.

Вложенное headless-ревью использует режим одобрения Auto внутри песочницы Qwen.
Autofix очищает унаследованный маркер `SANDBOX` перед запуском, чтобы тот не мог обойти
изоляцию; недоступный классификатор одобрений или песочница приводит к
неполному ревью и fail closed. Перед запуском Autofix объясняет, что ревью
может выполнять определенные репозиторием проверки в изолированном процессе, который сохраняет учетные данные
модели и доступ к сети, затем требует явного подтверждения того, что
пользователь доверяет репозиторию. Если существуют untracked, не игнорируемые файлы, Autofix также
выводит их список до того, как их содержимое попадет в контекст модели ревью. Неинтерактивные
запуски останавливаются с `BLOCKED`, когда подтверждение недоступно. На Windows локальный Autofix
требует Git Bash/MSYS, поскольку бандленный воркфлоу ревью использует синтаксис POSIX shell;
нативные cmd.exe и PowerShell завершаются fail closed до начала ревью.

После каждого полного ревью Autofix читает выпущенный отчет, проверяет каждую
находку по коду, применяет один минимальный связный батч фиксов, запускает
наиболее узкие релевантные проверки и снова ревьюит результирующее рабочее дерево. Он
не опрашивает GitHub и не использует `/loop`.

Фиксированного числа локальных раундов нет. Процесс останавливается по свидетельству:

- `NO_CHANGES`: рабочее дерево было чистым до ревью.
- `CONVERGED`: полное безлимитное ревью не имеет находок, по которым можно действовать, и все
  требуемые проверки проходят.
- `BLOCKED`: свидетельства ревью неполны, требуемая проверка не имеет безопасного
  фикса в рамках области действия, либо требуется решение мейнтейнера/продакта.
- `STALLED`: одна и та же находка, по которой можно действовать, выживает без новой гипотезы,
  прогресса по рабочему дереву нет, либо изменения осциллируют.

Локальный Autofix никогда не делает stage, commit, push, не переписывает историю, не меняет
индекс и не пишет в GitHub. Существующее staged-состояние пользователя остается нетронутым;
фиксы остаются изменениями рабочего дерева для инспекции.

## Граница воркфлоу

GitHub Actions сохраняет за собой всю детерминированную политику: триггеры, авторизацию,
checkout, выбор доверенного фидбэка, бюджеты повторов и раундов, watermark'и,
коммиты, пуши, комментарии и финальные гейты. Только политика решений модели принадлежит
навыку. В частности, воркфлоу может пометить фидбэк как отложенный, тогда как
навык решает, как агент должен обрабатывать эту секцию.

## Отклоненные альтернативы

- Бандленный навык Autofix конфликтовал бы с навыком репозитория и разделил бы
  контракт модели.
- `on`, `off` или `status` управляли бы удаленным воркфлоу вместо исправления
  локальных изменений.
- Новый вотчер, планировщик или рантайм-машина состояний дублирует существующую инфраструктуру
  ревью и Actions.
- Фиксированный лимит локальных раундов может остановить продвигающийся ремонт; условия остановки
  на основе прогресса ограничивают несходящиеся запуски, не навязывая произвольный общий лимит.
