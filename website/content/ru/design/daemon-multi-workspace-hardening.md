# Базовый уровень ужесточения мульти-воркспейсного демона

Статус: базовый уровень текущей реализации и контракт ревью для issue
[#6378](https://github.com/QwenLM/qwen-code/issues/6378). Этот документ
закрывает фазу ужесточения; это не дорожная карта добавления новых функций
демона.

## Модель владения

Каждый маршрут демона и каждая нижестоящая операция принадлежит ровно одному
из этих классов владения:

| Владение              | Значение                                                                                                                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Процесс-глобальное    | Один ресурс слушателя/процесса, разделяемый всеми рантаймами: аутентификация, HTTP rate-limit, лимиты соединений, метрики и завершение.                                                |
| Legacy-primary        | Маршрут совместимости, чей контракт намеренно нацелен на primary-рантайм. Отсутствие селектора рабочего пространства — не разрешение угадывать другого владельца.                       |
| С квалификацией по рабочему пространству | Маршрут сначала разрешает явный id рабочего пространства, затем кодированный канонический абсолютный cwd, и диспетчеризует только в выбранный рантайм.                |
| Владелец живой сессии | Маршрут живой сессии в единственном числе сканирует зарегистрированные рантаймы в поисках уникального бриджа, владеющего сессией, и диспетчеризует только туда.                         |
| Персистентное рабочее пространство | Маршрут разрешает рабочее пространство до чтения его персистентного хранилища сессий или организации; он может предоставлять объявленную read-only поверхность для недоверенного secondary без запуска ACP. |

Primary-рабочее пространство — это первый рантайм при старте и дефолт
совместимости для маршрутов, которые явно документируют этот фолбэк. Это не
общий фолбэк при неудаче разрешения.

## Семантика ошибок

| Состояние                     | Требуемое поведение                                                                                                                                                                                                                                                                                |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Неизвестное рабочее пространство или сессия | Fail closed со стабильным ответом mismatch/not-found маршрута. Не зондировать и не выполнять на primary.                                                                                                                                                                     |
| Недоверенное рабочее пространство | Отклонять выполнение и мутации с опорой на рантайм. Недоверенный secondary может использовать только явно документированные read-only поверхности, включая ограниченную файловую систему и чтения персистентного каталога/транскриптов, без запуска ACP или записи состояния ремонта. Прогрев legacy-primary не авторизует запросы. |
| Неоднозначный владелец живой сессии | Вернуть ошибку сервера, поскольку диспетчеризация не может быть выполнена безопасно. Не выполнять ни на одном бридже.                                                                                                                                                    |
| Бутстрэп рантайма             | Сохранять отзывчивость процесс-глобальной живости; работа с опорой на рантайм ждет или сообщает объявленную ошибку старта. Deep-проверка здоровья возвращает `503` с причиной, пока агрегация недоступна.                                                                                          |
| Дренирующийся рантайм         | Отказывать в новой работе стабильным ответом draining. Нефорсированное удаление откатывается с `workspace_busy`, если есть активность; форсированное удаление запрашивает завершение и ограниченную очистку активных ресурсов. Рантайм остается в общедемоновом учете до завершения удаления.      |
| Удаленный рантайм             | Обращаться с ним как с неизвестным. Он должен исчезнуть из возможностей (capabilities), маршрутизации и агрегации здоровья до того, как то же рабочее пространство может быть добавлено снова. Очистка после точки фиксации персистентности — по мере возможности; ошибки логируются и не восстанавливают маршрутизацию. |

## Инварианты

- Разрешение рабочего пространства никогда не откатывается на primary после
  результата unknown, untrusted, ambiguous, draining или removed.
- Id рабочих пространств имеют приоритет над кодированными cwd-селекторами.
  Cwd-селекторы должны быть абсолютными и канонизироваться в
  зарегистрированный рантайм.
- Каждый активный рантайм рабочего пространства владеет своим снимком
  окружения, бриджем, сервисами рабочего пространства, границей файловой
  системы/доверия, состоянием Voice и границей ресурсов ACP/MCP. Продакшен
  пытается прогреть primary-бридж для совместимости и повторяет попытку при
  первом использовании после неудачи прогрева. Доверенный secondary запускает
  своего ACP-потомка по требованию и, когда включен `mcp_workspace_pool`,
  владеет пулом внутри этого потомка; недоверенный secondary не должен
  запускать ни одного. Прогрев primary не обходит гейты доверия маршрутов.
  Процесс-глобальный координатор Voice обеспечивает соблюдение общего лимита
  допуска, отслеживая аренды по владеющему рантайму. Одноименные ключи
  окружения не должны пересекать рантаймы, и оверлей рабочего пространства не
  должен мутировать окружение родительского процесса.
- Единый токен демона аутентифицирует процесс; это не ACL по рабочим
  пространствам. HTTP rate-limit, лимиты слушателя, допуск по общему числу
  сессий, метрики, завершение и радиус отказов процесса также
  общедемоновые.
- Когда объявлен `mcp_workspace_pool`, транспорты MCP и учет бюджета
  разделяются сессиями внутри одного рантайма рабочего пространства, никогда
  между рантаймами. Без тега клиенты должны принимать legacy-менеджер на
  сессию и статус `scope: 'session'`.
- Явные рантаймы запуска/статические рантаймы, включая primary, не подлежат
  удалению. Динамические или персистентные вторичные рантаймы следуют
  правилам жизненного цикла add, drain, remove и re-add. Дренирующиеся
  рантаймы остаются видимыми для общедемоновой проверки здоровья до
  завершения логического удаления. Форсированное удаление прерывает активные
  ресурсы и выполняет ограниченную очистку по мере возможности; таймаут
  очистки логируется вместо отката логического удаления.
- Поверхностный `GET /health` остается ровно `200 {"status":"ok"}`.
  Deep-проверка здоровья агрегирует активные и дренирующиеся рантаймы,
  возвращает `503` с причиной при ошибке bootstrap или агрегации и никогда не
  раскрывает пути рабочих пространств. См.
  [daemon-global deep health](./daemon-global-deep-health.md), реализовано в
  [PR #6961](https://github.com/QwenLM/qwen-code/pull/6961).

## Контракт ревью

Для каждого нового или измененного маршрута демона ревьюер должен назвать
класс владения и проследить запрос через окружение, бридж, сервис, файловую
систему, доверие и обработку ошибок. Маршрут неполон, если любой нижестоящий
потребитель может молча использовать состояние primary после неудачи
разрешения владения.

Находки ревью классифицируются так:

- Корректность, безопасность, потеря данных, изоляция или регрессии с
  fail-open относятся к ужесточению и блокируют соответствующее изменение.
- Новая возможность (capability) или миграция намеренного primary-only
  контракта получает отдельный issue и дизайн; она не расширяет это
  закрытие.
- Рефакторинг без конкретного дефекта не входит в область ужесточения.

Примерно после пяти раундов ревью активный PR ужесточения должны расширять
только исправления корректности, безопасности, потери данных и регрессий.
Другие валидные предложения записываются как follow-up, чтобы зонтичная
задача не оставалась открытой неопределенно долго.

## Явные текущие ограничения

- `POST /session/:id/branch`, `POST /session/:id/fork` и
  `POST /session/:id/cd` остаются legacy-primary для живой сессии,
  принадлежащей secondary, и возвращают
  `non_primary_session_route_not_supported`.
- Именованные каналы, управляемые демоном, группируются по владеющему
  рабочему пространству и запускают один воркер на владеющий рантайм.
  `--channel all` намеренно остается только для primary.
- Демон не предоставляет аутентификацию, rate-limit или изоляцию отказов
  процесса по рабочим пространствам. Когда нужны такие границы,
  разворачивайте отдельные демоны.

## Правило выхода

Этот базовый уровень, его контрактные тесты, охранники маршрутов/окружения и
общедемоновая deep-проверка здоровья — фиксированное закрытие #6378.
Маршрутизация branch/fork и семантика `cd` остаются независимой feature-работой.
После слияния PR закрытия будущие находки ревью следует оформлять как
фокусированные issue вместо повторного открытия неограниченного ведра
ужесточения.
