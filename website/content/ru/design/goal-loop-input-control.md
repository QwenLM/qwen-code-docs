# Управление вводом в goal-цикле

## Проблема

Активный `/goal` реализован как блокирующий хук Stop. Пока модель работает,
интерактивная очередь обычно откладывает слеш-команды до тех пор, пока стрим
не станет idle. Goal-цикл может никогда не достичь этой границы idle, поэтому
`/goal clear` и заменяющие команды `/goal` не могут вступить в силу.

Ответ Stop также может агрегировать хук goal с несвязанными настроенными
хуками. Очистка goal не должна отбрасывать блокирующее решение, принадлежащее
другому хуку.

## Дизайн

Во время активного хода очередь сообщений дренирует команды `/goal` наряду с
обычными текстовыми steering-сообщениями. Остальные слеш-команды остаются в
очереди для обычной обработки в idle.

CLI исполняет дренированные goal-команды через существующий обработчик
слеш-команд:

- Команды clear применяют свой побочный эффект без создания входа для модели.
- Заменяющие команды заменяют отложенную инструкцию goal.
- Когда несколько goal-команд дренируются вместе, отправляется только
  инструкция для последней активной goal.
- Выжившая инструкция сохраняет свою позицию относительно текстовых
  steering-сообщений.
- Исполненные goal-команды не восстанавливаются, если последующая подготовка
  steering отменена; неисполненные текстовые сообщения восстанавливаются.

Core сэмплирует очередь перед хуками Stop и снова после возврата блокирующего
хука Stop. Блокирующий вывод goal несет ID своего хука goal и держит свою
причину продолжения отдельно от обычных причин хуков. Бридж хуков также
сообщает, блокирует ли другой вывод Stop. Если goal меняется на второй
границе, core удаляет только продолжение старой goal; независимая блокирующая
причина по-прежнему соблюдается. Неблокирующие выводы хуков не вызывают
дополнительную итерацию goal.

## Верификация

- Тесты очереди покрывают дренирование goal в активном ходе и откладывание на
  границе idle.
- Тесты стрима CLI покрывают clear, замену, пакетные команды, порядок и
  поведение восстановления.
- Тесты core покрывают clear и замену во время вычисления хука Stop, включая
  агрегированный независимый блокатор.
- Локальная tmux-сессия проверяет clear и замену на собранном интерактивном
  CLI.
