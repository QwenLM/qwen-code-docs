# Провайдер внешнего Guard инструментов для управляемого ACP

Статус: дизайн реализации
Tracking issue: https://github.com/QwenLM/qwen-code/issues/8102
Зависит от: https://github.com/QwenLM/qwen-code/pull/8032

## Проблема и область

Qwen Code уже поддерживает правила разрешений и хуки, но эти механизмы не
дают управляемому развертыванию `qwen serve` обязательного, внешнего,
машинопроверяемого решения непосредственно перед каждым исполнителем
инструмента. PR #8032 добавляет этот колбэк на границе исполнителя. Это
изменение подключает колбэк к небольшому внешнему провайдеру для управляемых
развертываний ACP.

Область намеренно сводится к одному решению:

> Даны идентичность сессии и промпта, принадлежащие рантайму,
> принятая рантаймом корреляционная метка вызова инструмента, каноническое
> имя инструмента и финальные аргументы — может ли этот вызов выполниться
> сейчас?

Это изменение не добавляет протокол задач, колбэк результатов, сервис
наблюдения/воспроизведения, обобщенную замену хуков или слой авторизации для
явных контрольных/управляющих API демона. Оно также не делает реализацию
разрешенного инструмента детерминированной и не помещает в песочницу
поведение команды, которую провайдер решил разрешить.

## Контракт безопасности

- Активация только при старте процесса: `off` (по умолчанию) или `required`.
- В `off` провайдер не конструируется, RPC провайдера не выполняется и
  возможность не анонсируется. При отсутствии любых новых входных данных
  поведение автономного CLI / обычного ACP не меняется. Зарезервированная
  переменная окружения токена по-прежнему вычищается из окружений выполнения
  потомков, если задана.
- В `required` запуск демона выполняет аутентифицированное версионированное
  рукопожатие. Отсутствующая или невалидная конфигурация и недоступный или
  несовместимый провайдер валят запуск демона.
- Каждый поддерживаемый верхнеуровневый вызов, прошедший существующие гейты
  разрешений и `PreToolUse` и достигший финальной границы выполнения,
  выполняет ровно один ограниченный запрос `prepare`. Более ранний отказ
  разрешения/хука не выполняет запроса к провайдеру. Повторов нет. Таймаут,
  отмена, сбой транспорта, некорректный ответ, несовпадение идентичности или
  явный отказ мешают исполнителю выполниться.
- Унаследованный из PR #8032 порядок: обработка разрешений, хуки `PreToolUse`,
  затем этот Guard, затем целевой исполнитель. Guard авторизует только целевой
  исполнитель инструмента; он не авторизует и не помещает в песочницу
  поведение хуков. Управляемые развертывания, которым нужна граница всех
  эффектов, должны отключить хуки или доверять им и управлять ими независимо.
- Действия слеш-команд разрешаются до планирования модели/инструментов и не
  являются вызовами Tool Guard. Некоторые встроенные могут напрямую мутировать
  файлы или настройки. За исключением явно отклоненных входов вложенных
  агентов ниже, это изменение не классифицирует слеш-команды; управляемые
  хосты должны отклонять ввод слеш-команд или отключать не одобренные команды
  через `slashCommands.disabled` / `--disabled-slash-commands`.
- Учетные данные провайдера остаются в процессе `qwen serve`. Они никогда не
  копируются в окружение дочернего ACP, воркера канала, подпроцесса
  инструмента, MCP-сервера, хука или субагента. CLI захватывает и удаляет
  окружающий токен до заморозки снимков окружения рантайма.
- Запрос Guard от потомка к родителю использует существующий приватный канал
  ACP. Бридж принимает его только для сессии, принадлежащей этому каналу, и
  только когда ее prompt ID равен активному prompt ID бриджа.
- Каждый канал ACP должен подтвердить `required-v1` в своем ответе initialize,
  доказывая, что потомок потребил приватный маркер и установил колбэк
  исполнителя. Отсутствующее или несовпадающее подтверждение отклоняет канал
  до создания любой Session.
- Управляемый ACP не запускает интерактивный рантайм спекуляции предложений.
  Если встраивание независимо достигает пути спекуляции PR #8032, тот же
  колбэк по-прежнему требуется перед apply.
- V1 поддерживает только верхнеуровневые вызовы инструментов, сделанные во
  время активного foreground управляемого Prompt. `agent`, `workflow`,
  `create_sub_session`, `send_message`, прямая точка входа `/fork` и
  поддерживаемые агентом управляющие remember/dream памяти рабочего
  пространства отклоняются до того, как они смогут стартовать, возобновить или
  делегировать независимому AgentCore/Session. Автоматические/cron ходы и
  восстановленные фоновые агенты не несут активного управляемого контекста
  Prompt, поэтому их охраняемые инструменты завершаются fail closed.
- Верхнеуровневый вызов shell с `is_background=true` или вызов `monitor` — это
  все равно один охраняемый вызов: провайдер видит его финальные аргументы и
  может отклонить его. Guard не авторизует непрерывно запущенный процесс и не
  добавляет новый протокол аудита завершения процесса. Управляемые политики,
  которым нужно завершение в foreground, должны отклонять эти формы
  аргументов/инструментов.
- Охраняемая ошибка транспорта MCP трактуется как неоднозначный результат и
  автоматически не переподключается/не воспроизводится. Предыдущее разрешение
  не может авторизовать вторую попытку выполнения.
- Существующие события жизненного цикла инструментов ACP `session/update`
  остаются источником наблюдения выполнения. Запрос провайдера и эти события
  коррелируют по `sessionId`, `promptId` и `toolCallId`.

Сила идентичности намеренно явная:

- `sessionId` генерируется и принадлежит Session демона/ACP;
- `promptId` генерируется демоном и перепривязывается после снятия метаданных
  вызывающего;
- `toolCallId` — принятая рантаймом корреляционная метка. Она может
  происходить из вызова инструмента модели, поэтому не является субъектом
  аутентификации или самостоятельным ключом идемпотентности;
- `requestId` генерируется `qwen serve` для одного RPC провайдера. Это
  идентификатор операции решения провайдера, но существующие события
  жизненного цикла коррелируют по полному кортежу
  `(sessionId, promptId, toolCallId)`.

## Конфигурация

```bash
export QWEN_CODE_EXTERNAL_TOOL_GUARD_TOKEN='replace-with-local-secret'

qwen serve \
  --external-tool-guard-mode=required \
  --external-tool-guard-endpoint=http://127.0.0.1:8787 \
  --external-tool-guard-timeout-ms=3000
```

Правила:

- `--external-tool-guard-mode` принимает `off|required` и по умолчанию `off`.
- `required` требует endpoint loopback HTTP(S) только с origin и непустой
  токен не более 8192 кодовых единиц UTF-16 без управляющих символов из
  `QWEN_CODE_EXTERNAL_TOOL_GUARD_TOKEN`.
- Userinfo endpoint, query, fragment и пути, отличные от корневого,
  отклоняются.
- `localhost` закреплен клиентом за `127.0.0.1` (с SNI `localhost` для
  HTTPS); он никогда не разрешается через окружающий DNS или конфигурацию
  прокси.
- Таймаут — целое число от 100 до 30000 мс. По умолчанию 3000 мс.
- Endpoint и токен без `mode=required` не активируют провайдер.
  Зарезервированный токен по-прежнему потребляется и вычищается, а не
  раскрывается инструментам.

## Поток данных рантайма

```mermaid
sequenceDiagram
    participant Host as "DataAgent / operator"
    participant Serve as "qwen serve"
    participant Guard as "External Guard"
    participant ACP as "private qwen --acp"
    participant Exec as "Tool executor"

    Host->>Serve: "start with mode=required"
    Serve->>Guard: "POST /v1/handshake (Bearer token)"
    Guard-->>Serve: "version + nonce + prepare capability"
    Serve->>ACP: "spawn; private ACP capability + required marker"
    ACP-->>Serve: "initialize acknowledgement: required-v1"
    Host->>Serve: "prompt"
    Serve->>ACP: "prompt + runtime-owned sessionId/promptId"
    ACP->>ACP: "permission + PreToolUse gates"
    ACP->>Serve: "private extMethod prepare(sessionId,promptId,toolCallId,name,args)"
    Serve->>Serve: "verify owned session + active prompt"
    Serve->>Guard: "POST /v1/prepare (exactly once)"
    Guard-->>Serve: "allow or deny"
    Serve-->>ACP: "decision"
    alt "allow"
        ACP->>Exec: "execute final invocation"
        ACP-->>Serve: "existing tool_call_update terminal event"
    else "deny / unknown / timeout / cancel"
        ACP-->>Serve: "existing EXECUTION_DENIED/cancelled terminal event"
    end
```

## Проводной контракт

Все тела используют UTF-8 JSON и `Content-Type: application/json`. Запросы
используют `Authorization: Bearer <token>`. Редиректы не следуются. Тела
ответов ограничиваются до парсинга JSON. Сериализованный запрос не может
превышать 1 МиБ, ответ не может превышать 64 КиБ, а причина отказа не может
превышать 500 кодовых единиц UTF-16 или содержать управляющие символы.

Финальные аргументы инструмента — данные приложения и могут содержать
исходный код, пути, запросы или учетные данные, предоставленные инструменту.
Провайдер должен трактовать их как чувствительные и не должен сохранять их
без разбора лишь потому, что транспорт loopback.

Запрос рукопожатия:

```json
{
  "protocolVersion": 1,
  "nonce": "runtime-random-value",
  "client": "qwen-code"
}
```

Ответ рукопожатия:

```json
{
  "protocolVersion": 1,
  "nonce": "same-runtime-random-value",
  "capabilities": { "prepare": true }
}
```

Запрос prepare:

```json
{
  "protocolVersion": 1,
  "requestId": "runtime-random-value",
  "sessionId": "runtime-owned-session-id",
  "promptId": "runtime-owned-prompt-id",
  "toolCallId": "runtime-accepted-tool-call-correlation-id",
  "toolName": "canonical_tool_name",
  "arguments": { "final": "tool arguments" }
}
```

Ответ разрешения:

```json
{
  "protocolVersion": 1,
  "requestId": "same-runtime-random-value",
  "allowed": true
}
```

Ответ отказа:

```json
{
  "protocolVersion": 1,
  "requestId": "same-runtime-random-value",
  "allowed": false,
  "reason": "Safe user-visible policy reason"
}
```

Неизвестные поля, неверные версии/nonce/ID запросов, невалидные булевы,
чрезмерные тела и небезопасные причины отказа — сбои протокола и поэтому
отказ.

## Совместимость и поведение при сбоях

| Развертывание                                            | Ожидаемое поведение                                                        |
| -------------------------------------------------------- | --------------------------------------------------------------------------- |
| Интерактивный/headless `qwen`                            | Существующее поведение выполнения не меняется при отсутствии новых входных данных |
| `qwen --acp`, запущенный IDE                              | Нет провайдера; приватный маркер отсутствует                                 |
| `qwen serve` без новых флагов                            | Нет провайдера, нет возможности, текущее поведение прогрева/повторов          |
| `qwen serve`, endpoint/токен есть, mode опущен/off       | Нет провайдера/возможности; зарезервированный токен вычищается из потомков    |
| `qwen serve`, required, валидный провайдер               | Возможность анонсируется; каждый поддерживаемый верхнеуровневый инструмент охраняется |
| `qwen serve`, required, невалидная конфигурация/рукопожатие | Слушатель не стартует                                                     |
| Required, потомок не подтвердил установленный Guard        | Канал ACP отклоняется до создания Session                                    |
| Required-провайдер сбоит во время хода                     | Вызов становится отклоненным; счетчик исполнителей остается нулевым            |
| Required, неподдерживаемый вложенный/скрытый вход AgentCore | Отклоняется локально до начала вложенного выполнения                        |
| Required, ответ MCP потерян/соединение закрыто             | Первая попытка не удается; без автоматического переподключения или воспроизведения |

Возможность — `external_tool_guard`, и она анонсируется только когда
required-режим завершил свое стартовое рукопожатие.

## План верификации

Юнит- и контрактные тесты должны доказать:

1. строгую валидацию endpoint/конфигурации;
2. аутентифицированное рукопожатие, валидацию nonce/версии/схемы и лимиты тел;
3. разрешение, явный отказ, таймаут, прерывание, сбой соединения и некорректный
   ответ, без повторов;
4. BridgeClient отклоняет неизвестную сессию и устаревшую идентичность промпта
   до вызова провайдера;
5. off по умолчанию не создает провайдера и не анонсирует возможность;
6. токен никогда не попадает в эффективное окружение потомка ACP;
7. required-маркер переживает существующий путь перезапуска, но удаляется до
   того, как инструменты смогут унаследовать окружение процесса ACP;
8. required-режим инъектирует колбэк в Config каждой живой сессии ACP;
9. каждый required-канал ACP должен подтвердить установленный колбэк до
   создания Session;
10. управляемый ACP не запускает спекуляцию предложений, а отдельно вызванный
    путь спекуляции по-прежнему требует колбэк перед apply;
11. вложенные/делегирующие `agent`, `workflow`, `create_sub_session`,
    `send_message`, прямой `/fork` и поддерживаемые агентом управляющие памяти
    рабочего пространства отклоняются, тогда как автоматические/фоновые ходы
    без активного контекста Prompt завершаются fail closed;
12. охраняемая ошибка соединения MCP выполняет один вызов без
    переподключения/воспроизведения;
13. end-to-end кейс управляемого ACP сопоставляет
    `sessionId/promptId/toolCallId` провайдера с существующими стартовыми/терминальными
    событиями и доказывает, что счетчик исполнителей равен один для разрешения
    и ноль для отказа/сбоя.

Запустить сфокусированные тесты пакетов, сборку/typecheck/lint репозитория и
E2E-набор демона. Отчет PR записывает команды и точные результаты.

## Не цели и follow-up

- Транспорт Unix-domain socket; v1 использует endpoint loopback HTTP(S) только
  с origin.
- Повтор решений на стороне провайдера или идемпотентная повторная отправка;
  Qwen Code не отправляет повторов.
- Родословная вложенного/делегированного выполнения (`agent`, `workflow`,
  `create_sub_session`, `send_message`, `/fork`), поддерживаемые агентом
  управляющие памяти рабочего пространства и будущий протокол Guard с учетом
  попыток. V1 отклоняет эти вложенные/скрытые точки входа агентов вместо
  заявления неподдерживаемой корреляции.
- Отчет о результатах или хранение аудита в Qwen Code. Провайдер и DataAgent
  владеют своими записями аудита; Qwen Code предоставляет стабильные
  корреляционные ключи и существующие события жизненного цикла.
- Непрерывная авторизация или новый контракт терминальных результатов для
  фонового процесса shell/monitor после его охраняемого старта. Провайдеры
  могут отклонять эти вызовы по их финальному имени инструмента и аргументам.
- Бизнес-Task API, одобрение планов, гранты или специфичные политики
  DataAgent.
- Авторизация или песочница реализаций хуков. `PreToolUse` выполняется перед
  этим Guard исполнителя по контракту PR #8032.
- Авторизация действий слеш-команд. Они выполняются до планировщика
  инструментов; управляемые хосты, которым нужна граница всех эффектов, должны
  отклонять ввод слеш-команд или поддерживать строгий denylist развертывания
  вне этой функции.
- Семантическая инспекция или песочница реализации разрешенного инструмента
  или команды shell. Провайдер решает по каноническому имени и финальным
  аргументам; управляемое развертывание должно сочетать это решение со своей
  существующей политикой инструментов и границей изоляции.
- Авторизация явных контрольных операций REST/ACP демона; они по-прежнему
  управляются существующей аутентификацией демона и контрактами API.
