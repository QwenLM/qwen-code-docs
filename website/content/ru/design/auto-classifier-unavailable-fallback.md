# Фолбэк при недоступности авто-классификатора

## Проблема

Auto Mode сейчас преобразует каждый инфраструктурный сбой классификатора в отказ выполнения. Сетевая ошибка, таймаут, невалидный структурированный ответ, недоступная быстрая модель или переполнение контекста поэтому валят ожидающий вызов инструмента до того, как стандартный поток подтверждения сможет спросить пользователя, что делать.

Это поведение смешивает два разных исхода:

- Блокировка политикой классификатора — это вердикт безопасности, и он должен продолжать отклонять действие.
- Результат недоступности классификатора означает, что вердикт не был выработан, и должен позволить пользователю принять решение вручную.

Существующий фолбэк по последовательным недоступностям открывает подтверждение только после двух неудачных вызовов классификатора. Первые сбои по-прежнему завершают свои вызовы инструментов, и промпт не объясняет инфраструктурную проблему и не предлагает прямой путь восстановления.

## Цели

- Направлять первый результат недоступности классификатора в стандартный поток ручного подтверждения.
- Объяснять в подтверждении, что Auto Mode не смог классифицировать действие.
- Предлагать явную опцию, которая одобряет текущее действие один раз и переключает сессию на Default Mode.
- Держать поведение разрешений CLI и ACP согласованным.
- Сохранять блокировки политикой, явные правила отклонения, детерминированные гварды деструктивных команд и поведение отмены пользователем.

## Не-цели

- Персистить Default Mode в настройки пользователя или рабочего пространства.
- Автоматически переключать режимы без выбора пользователя.
- Менять правила allow/block классификатора политики.
- Делать неинтерактивные или фоновые сессии способными представить промпт, когда у них нет поверхности одобрения.

## Предлагаемое поведение

Когда классификатор возвращает `unavailable: true`, слой разрешений по-прежнему будет записывать событие недоступности, но будет возвращать исход manual-fallback вместо исхода blocked. Ожидающий вызов продолжится через существующие пути PermissionRequest и подтверждения.

Сгенерированное подтверждение будет нести метаданные фолбэка Auto Mode и подавлять постоянные варианты «всегда разрешать». Подтверждение будет показывать, что классификатор недоступен, и рекомендовать Default Mode, если сбои продолжаются. Его варианты будут включать:

- Разрешить один раз.
- Переключиться на Default Mode и разрешить один раз.
- Отклонить.

Вариант переключения намеренно объединен с явным одноразовым одобрением. Лейбл только с режимом оставил бы disposition уже ожидающего действия неоднозначным.

| Результат классификатора | Текущее поведение       | Новое поведение         |
| ------------------------ | ----------------------- | ----------------------- |
| Allow                    | Выполняется автоматически | Без изменений         |
| Блокировка политикой     | Отклонение с причиной политики | Без изменений   |
| Unavailable              | Отклонение вызова инструмента | Запрос ручного одобрения |

## Основной поток разрешений

`applyAutoModeDecision` будет записывать счетчики недоступности и возвращать причину фолбэка, выделенную для недоступности классификатора. Поскольку исход больше не blocked, хуки PermissionDenied не будут срабатывать на инфраструктурные сбои; вместо этого перед промптом будет выполняться обычный хук PermissionRequest.

Счетчики недоступности остаются полезными. Одобрение фолбэка сбрасывает последовательные счетчики, тогда как отклонение сохраняет их. Если повторяющиеся сбои достигают существующего порога, последующие вызовы, подлежащие классификации, могут обходить заведомо сломанный классификатор и переходить прямо к ручному подтверждению.

Детали подтверждения получат опциональные метаданные фолбэка Auto Mode, общие для форм подтверждения edit, execute, info, MCP и других. Новый исход одобрения будет представлять «продолжить один раз и переключиться на Default». Планировщик CLI будет переключать режим рантайм-сессии и нормализовать этот исход в обычный `ProceedOnce` перед вызовом специфичных для инструмента колбэков подтверждения или записи решения по инструменту.

`Config.setApprovalMode` уже обеспечивает требуемый переход сессии: он восстанавливает правила, временно снятые при входе в Auto Mode, сбрасывает счетчики отклонений и инкрементирует ревизию режима одобрения. Файл настроек не меняется.

## Представление в CLI

Компонент подтверждения TUI будет рендерить уведомление о фолбэке перед деталями действия и добавит опцию переключения перед Reject. Полные и компактные раскладки подтверждения обе будут выставлять эту опцию. Учет высоты должен резервировать место для добавленного предупреждения и опции, чтобы маленькие терминалы продолжали показывать варианты, по которым можно действовать.

## Представление в ACP

Запросы разрешений ACP будут включать уведомление о фолбэке как текстовый контент и выставлять ту же опцию переключения-и-одноразового-разрешения. При выборе сессия будет нормализовать одобрение инструмента в `ProceedOnce`, переключать рантайм-режим на Default и публиковать существующее уведомление об обновлении текущего режима.

ACP-клиенты, которые выбирают только Allow или Reject, продолжают использовать существующее поведение протокола.

## Границы сбоев

- Отмена пользователем запроса классификатора остается прерыванием и не становится промптом одобрения.
- Явные отклонения разрешений и детерминированные блокировки деструктивных команд остаются ошибками.
- Неинтерактивные вызовы без транспорта разрешений и фоновые агенты, которые не могут выдать промпт, по-прежнему отклоняют через свою существующую обработку фолбэка ручного подтверждения.
- Неудачный разбор политики на стадии 2 классификатора считается недоступностью и поэтому спрашивает пользователя; завершенная блокировка политикой стадии 2 остается отклоненной.

## Затронутые файлы

- `packages/core/src/permissions/autoMode.ts` и тесты: маппинг unavailable-в-fallback, метаданные и гейтинг хуков.
- `packages/core/src/tools/tools.ts`: метаданные подтверждения фолбэка и исход одобрения переключения.
- `packages/core/src/core/coreToolScheduler.ts` и тесты: декорирование подтверждений, отслеживание резолвинга фолбэка, переключение режимов и нормализация одобрения.
- `packages/core/src/telemetry/tool-call-decision.ts` и тесты: классификация нового исхода в форме одобрения.
- `packages/cli/src/ui/components/messages/ToolConfirmationMessage.tsx` и тесты: рендеринг уведомления и опции.
- `packages/cli/src/acp-integration/session/permissionUtils.ts` и тесты: контент ACP и маппинг опций.
- `packages/cli/src/acp-integration/session/Session.ts` и тесты: фолбэк ACP, переход режима и уведомление.
- `docs/users/features/auto-mode.md`: документирование немедленного ручного фолбэка и опции восстановления Default Mode.
