# Release-пайплайн DSW SWE-bench Verified

Этот пайплайн — изолированная реализация следующего:

`GitHub Release -> self-hosted DSW runner -> отправка короткого запуска -> постоянные Coordinator + 10 Executors -> Publisher -> результат Release`

Он не использует и не изменяет workflow, сервис, состояние или маркеры
результатов из PR #7584.

## Продакшн-поведение

- Стабильный Release `vX.Y.0` запускает workflow от целевого коммита тега
  Release. Патч-релизы, пререлизы и несвязанные семейства тегов пропускаются.
- Тег Release разрешается в его неизменяемый Git-коммит.
- Полный манифест SWE-bench Verified из 500 инстансов замораживается до
  диспетчеризации.
- Self-hosted раннер получает задачу Actions через свое исходящее соединение
  с GitHub. Одноразовый скрипт диспетчеризации замораживает манифест и
  вызывает `qwen-benchmark-pool submit` для создания запуска и начальных
  задач.
- Action записывает `run_id` пула и завершается, не ожидая бенчмарк.
- Постоянный координатор (Coordinator) и десять постоянных исполнителей
  (Executors) обрабатывают запуск. Каждый исполнитель атомарно захватывает
  одну задачу и выполняет одно испытание Harbor/Docker за раз.
- Живые каталоги испытаний Harbor остаются на локальном NVMe. Завершенные
  артефакты попыток копируются в OSS без зависимости от POSIX-операций
  разрешений OSS.
- Исполнители посылают heartbeat по своим аренам и атомарно отправляют
  результаты. Повторяемые ошибки инфраструктуры получают до четырех попыток
  с backoff 60, 120 и 240 секунд.
- Координатор восстанавливает истекшие аренды, сверяет счетчики запуска и
  применяет гейты завершения манифеста и публикации. Изолированные
  терминальные отказы не отменяют оставшиеся задачи.
- Постоянный DSW-издатель (publisher) наблюдает терминальные запуски и
  активно обновляет инициировавший Release публичным JSON результата и
  per-case архивом траекторий.
- Оценка записывается только после того, как все 500 инстансов достигнут
  уникального терминального состояния, ни одна задача не отменена и
  `EXECUTION_ERROR + INFRA_FAILED < 10`. Оценка равна
  `RESOLVED / (RESOLVED + UNRESOLVED)` с использованием только валидных
  результатов грейдера в качестве знаменателя.
- Десять или более терминальных ошибок, отмененная задача, отсутствующий
  результат или отсутствующая траектория для оцениваемого случая делают
  запуск `QUARANTINED`; статус и счетчики записываются без оценки.

## Границы изоляции

- Метка раннера: `qwen-benchmark-dsw`
- Workflow: `.github/workflows/dsw-swe-verified-release.yml`
- Сьют: `dsw_release_swe_verified_v1`
- База данных PostgreSQL: `qwen_benchmark_dsw_release_v1`
- Рантайм: `/mnt/workspace/qwen-benchmark-dsw-release-v1`
- Креденшалы модели: `/mnt/workspace/qwen-benchmark-dsw-release-v1/config/model.key`
  (`root:github-runner`, режим `0640`)
- OSS: `/mnt/data/qwen-benchmark/dsw-release-v1`
- Маркеры релиза: `qwen-code-dsw-swe-verified`

Слои Docker-образов могут использовать кэш хоста DSW, но состояние
экспериментов и артефакты не разделяют пути или таблицы с другим
бенчмарк-пайплайном.

## Валидация ветки

Используйте `workflow_dispatch` из этой ветки и нацеливайтесь на изолированный
пререлиз. Автоматические запуски `release.published` намеренно ограничены
стабильными релизами `vX.Y.0`.

Для вручную диспетчеризованного тестового пререлиза одна строка тела, такая
как `Benchmark-Qwen-Ref: v0.20.0-nightly.20260722.b98306b7e`, выбирает
существующую опубликованную npm-версию Qwen, сохраняя результат в
изолированном POC-релизе. Это переопределение принимается только для
пререлизов. Обычный Release всегда вычисляет свой собственный тег.

`workflow_dispatch` остается доступным для явной диагностики и повторных
запусков. Ручная валидация по умолчанию использует один инстанс, чтобы
ограничить время и стоимость модели; запуски с 5 и 500 инстансами не
передают single-case `instance_id`. Оба триггера асинхронны: Actions
записывает квитанцию диспетчеризации, но не остается живым на время
бенчмарка.

## Границы компонентов

- Self-hosted раннер GitHub: долгоживущий приемник задач GitHub.
- Диспетчеризация / отправка в пул: одноразовый создатель запуска и задач.
- PostgreSQL: общее персистентное хранилище состояния, а не планировщик.
- Координатор: восстановление истекших аренд, сверка запусков и гейт
  завершения.
- Исполнители: захват задач, исполнение Harbor/Qwen Code/грейдера,
  heartbeat и отправка результатов.
- Издатель: валидация терминальных запусков, генерация публичного бандла
  результата и траекторий и активная обратная запись в GitHub Release.

Реализация DSW поддерживается отдельно во внутреннем репозитории
`qwen-code-benchmark-dsw`. Этот PR содержит только триггер GitHub, манифест,
адаптер диспетчеризации и публичный контракт дизайна.
