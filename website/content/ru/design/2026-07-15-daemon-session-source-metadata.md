# Метаданные источника сессий демона

## Мотивация

Клиентам демона нужно определять, какая интеграция создала сессию, после перезапуска демона. Метаданные бриджа, существующие только в live, недостаточны, поскольку live-записи перестраиваются из персистентного транскрипта при загрузке или возобновлении.

## API

`POST /session` принимает два опциональных неизменяемых поля:

- `sourceType`: токен источника в нижнем регистре (`[a-z][a-z0-9_-]{0,63}`).
- `sourceId`: непустой идентификатор не более 256 символов. Он валиден только при наличии `sourceType`.

Поля возвращаются в ответах создания сессии, статуса и списка сессий рабочего пространства. Существующие сессии опускают оба поля. При `sessionScope: single` подключение возвращает источник существующей сессии и никогда не перенимает источник подключающегося запроса.

Списки сессий рабочего пространства принимают параметры запроса `sourceType` и опциональный `sourceId`. `sourceId` требует `sourceType`; при наличии обоих они сопоставляются вместе. Фильтры источника не комбинируются с организованным видом.

Запланированные задачи демона помечают свою выделенную сессию `sourceType: "scheduled_task"` и долговременным идентификатором задачи как `sourceId`.

Воркеры каналов демона помечают создаваемые ими сессии `sourceType: "channel"` и настроенным именем экземпляра канала (например, `feishu-main`) как `sourceId`, чтобы экземпляр канала — а через конфигурацию канала и тип канала (dingtalk/feishu/...) — был атрибутируем на плоскости данных демона. Загрузка или подключение существующей сессии никогда не перештамповывает ее источник создания.

## Персистентность

Новая сессия хранит одну системную запись `session_source` вблизи начала своего JSONL-транскрипта:

```json
{
  "type": "system",
  "subtype": "session_source",
  "systemPayload": {
    "sourceType": "web_shell",
    "sourceId": "window-1"
  }
}
```

Бридж просит дочерний процесс сессии добавить эту запись через ожидаемый управляющий метод ACP, соответствуя существующей границе персистентности `parent_session`. Ответ создания раскрывает `sourcePersisted`, чтобы вызывающая сторона могла обнаружить деградированный источник только для live, если запись не удалась.

`SessionService` читает эту запись при сканировании начала транскрипта для ответов списков и перед загрузкой/возобновлением, чтобы восстановленные live-сводки сохраняли источник.

## Ветвление

Форкнутые транскрипты не должны копировать `session_source`; иначе новая ветка приписывала бы себе создателя исходной сессии. Ветка не имеет источника, пока ее путь создания явно не назначит его.

## Совместимость

Оба поля опциональны. Старые транскрипты и клиенты остаются валидными. REST, ACP-over-HTTP и TypeScript SDK пробрасывают поля создания и фильтров списков. Демоны, реализующие эти поля, анонсируют `session_source_metadata`; SDK проверяет эту возможность перед отправкой метаданных источника или фильтров источника, чтобы старый демон не мог молча проигнорировать их и вернуть неотфильтрованные результаты. Значения предназначены только для атрибуции и не должны использоваться как сигнал авторизации, поскольку клиенты могут их предоставлять.

Если клиент отключается до получения новой созданной сессии, демон удаляет и live-сессию, и ее свежезаписанный транскрипт. Параллельное подключение предотвращает обе операции, сохраняя сессию для подключившегося клиента.
