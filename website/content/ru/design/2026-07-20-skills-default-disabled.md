# Переопределяемые навыки, отключенные по умолчанию

## Проблема

`skills.disabled` — это объединение без учета регистра по всем уровням настроек. Это делает его жестким denylist'ом: проект не может включить навык, отключенный настройками пользователя или системы. Это правильно для политики, но не может представить навык, который должен быть выключен изначально и при этом оставаться доступным для явного включения проектом.

## Настройки

Добавить два списка-объединения без учета регистра, оставив `skills.disabled` без изменений:

| Настройка                | Значение                                                                  |
| ------------------------ | ------------------------------------------------------------------------- |
| `skills.disabled`        | Жесткое отключение. Всегда побеждает и сохраняет существующие блокировки. |
| `skills.defaultDisabled` | Отключено, если не включено явно.                                         |
| `skills.enabled`         | Явное включение (opt-in); не может переопределить `skills.disabled`.      |

Эффективные отключения — это `disabled + (defaultDisabled - enabled)`. Используется явный список `enabled` вместо семантики замены, чтобы включение одного унаследованного значения по умолчанию не заменяло несвязанные значения по умолчанию.

## Рантайм и персистентность

Один локальный для CLI резолвер вычисляет эффективные отключенные имена и то, является ли каждый отключенный навык `hard` или `default`. Существующие потребители в рантайме продолжают читать эффективное множество через `Config.getDisabledSkillNames()`; API обнаружения и выполнения навыков в core не меняются.

Пикер `/skills` и переключатель демона применяют те же правила:

- включение удаляет жесткое отключение рабочего пространства и добавляет каноническое имя в `skills.enabled` рабочего пространства только при необходимости;
- отключение удаляет явное включение рабочего пространства и добавляет каноническое имя в `skills.disabled` рабочего пространства;
- записи `skills.disabled` более высоких уровней остаются заблокированными;
- несвязанные и недоступные записи навыков сохраняются.

Статус навыков рабочего пространства получает причину отключения и опциональный уровень блокировки, чтобы клиенты могли отличить жесткую блокировку от переопределяемого значения по умолчанию. Пути статуса, локальные для демона и для ACP, оба читают один и тот же локальный для CLI резолвер.

## Область применения

- Это изменение не добавляет ни одного навыка в `defaultDisabled`.
- `disable-model-invocation` и ACP-операции с управляемыми навыками не меняются.
- Существующая конфигурация `skills.disabled` остается совместимой.
- Изменения ограничены настройками, двумя существующими поверхностями переключения, статусом навыков рабочего пространства, их wire-типами, документацией и целевыми тестами.
