Разработка — это не только написание кода. От понимания, что нужно сделать, до обеспечения качества кода — каждый шаг занимает время. Ниже три сценария, в которых Qwen Code участвует на всём пути — помогает разобрать требования, review-ит код и дополняет тесты.

## От смутных требований к интерактивному прототипу

В голове есть идея, но детали ещё не ясны? Просто расскажите Qwen Code, что вы хотите сделать — он не спешит писать код, а сначала общается с вами как продакт-менеджер: какие ключевые функции нужны, как определить взаимодействие, какой технический подход использовать. Когда вы оба довольны требованиями, он приступает к разработке всего инструмента. От одной фразы до работающего прототипа продукта — без единой строки кода с вашей стороны.

### Шаги

1. **Проработка требований** — расскажите Qwen Code свою идею, даже если это одно смутное предложение. AI задаст вам ряд вопросов для уточнения деталей — ключевые функции, способы взаимодействия, техническая реализация — и в итоге поможет составить полный документ требований.
2. **Подтверждение плана требований** — после генерации плана вы можете проверить каждый пункт, внести изменения или дополнения. Убедившись, что всё верно, переходите к следующему шагу.
3. **Начало разработки** — план требований подтверждён, пусть Qwen Code приступает к разработке. Он будет шаг за шагом собирать весь инструмент согласно документу требований, полностью автоматически.

<Callout>
    **Подсказка**: чем конкретнее этап требований, тем меньше переделок на этапе разработки. Не спешите писать код — сначала разберитесь.
</Callout>

## 9 AI-ревьюеров одновременно проверяют ваш код

После написания кода перед коммитом запустите `/review` — 9 ревью-агентов одновременно приступают к работе, параллельно сканируя по безопасности, производительности, качеству кода. Найденные проблемы исправляются автоматически. Коллега отправил PR — одна команда для review, комментарии автоматически пишутся прямо в строки кода на GitHub, как при настоящем review.

### Шаги

1. **Review кода проекта** — запустите `/review` для проверки кода проекта, 9 агентов параллельно сканируют, автоматически обнаруживая хардкод ключей, SQL-инъекции и другие проблемы безопасности и производительности.
2. **Одно нажатие для исправления** — выберите автоисправление, Qwen Code напрямую изменяет код и запускает linter для проверки, чтобы исправление не вносило новых проблем.
3. **Review PR и комментарии** — запустите `/review <PR number> --comment` для проверки удалённого PR, перейдите на GitHub для просмотра inline-аннотаций — комментарии пишутся прямо в строки кода.

```bash
/review <PR number> --comment
```

## Добавление unit-тестов в проект

Пусть Qwen Code прочитает правила проекта, автоматически сгенерирует unit-тесты, покрывающие нормальные, граничные и аномальные сценарии, запустит проверку, исправит проблемы и дополнит покрытие тестами.

### Шаги

1. **Понимание проекта и целей тестирования** — Qwen Code читает файлы проекта, понимает бизнес-правила, ключевые функции и цели тестирования, планирует приоритетные сценарии для покрытия.
2. **Генерация тестов и запуск проверки** — на основе бизнес-правил для ключевых функций генерируются unit-тесты, покрывающие нормальные, граничные и аномальные сценарии — например, порог купона, граница бесплатной доставки, пустая корзина и невалидный ввод — и автоматически запускаются.
3. **Исправление проблем и прохождение тестов** — по результатам провалов тестов определяется источник проблемы. Если реализация кода не соответствует бизнес-правилам, Qwen Code изменяет код и перезапускает тесты до их прохождения.
4. **Дополнение покрытия тестами** — просмотрите отчёт о покрытии, проанализируйте непокрытые файлы и ветви, добавьте ценные тестовые случаи, повысьте покрытие ключевой логики.

<Callout type="error">
    **Внимание**: AI-сгенерированные тестовые случаи требуют вашего подтверждения правильности бизнес-логики. AI может написать тесты, но не может решить за вас, что правильно.
</Callout>
