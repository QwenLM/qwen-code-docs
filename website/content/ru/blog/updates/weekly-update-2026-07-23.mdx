На этой неделе Qwen Code выпустил 3 стабильные версии v0.19.12, v0.20.0 и v0.20.1, принято более 220 PR.

**Agent свернул не туда? Просто напишите.** Нажмите Enter во время вывода модели — сообщение направит текущий turn на следующем sampling boundary. Ctrl+Q откладывает сообщение до следующего turn. Сообщения, введённые во время выполнения инструмента, тоже работают. Больше не нужно ждать, пока Agent закончит, чтобы скорректировать направление.

**Параллельные задачи больше не конфликтуют.** Web Shell поддерживает создание изолированных сессий Worktree в один клик — несколько задач в одном репозитории работают в независимых git worktree, правки файлов, `git add`, `git checkout` не мешают друг другу. Фиолетовый символ ⑂ присутствует в git chip, списке сессий и выпадающем меню workspace.

**Поиск в интернете вернулся.** Встроенный инструмент `web_search` работает на Bailian Responses API — достаточно уже настроенного ключа Bailian API. После удаления сообщество постоянно просило вернуть; теперь поиск реализован через серверный поиск + чтение страниц, в конце ответа автоматически добавляется секция Sources со ссылками. По умолчанию выключен, включается явно.

**`web_fetch` перестроен с нуля.** Раньше при захвате страниц терялись ссылки, PDF превращался в мусор, большие страницы обрезались и ответ пропадал. Теперь HTML сначала конвертируется в markdown, потом обрезается; PDF извлекает текст инлайн; бинарные файлы сохраняются корректно; добавлены таймаут 60 секунд и лимит 10 МБ.

## ✨ Новые возможности

### Steering в реальном времени: корректировка Agent прямо во время вывода

Раньше, если вы писали сообщение во время вывода Agent, приходилось ждать окончания — оно становилось новым prompt. Agent свернул не туда, а вы могли только наблюдать, пока он не закончит.

Теперь Enter и Ctrl+Q чётко разделены:

- **Enter**: сообщение попадает в очередь steering и применяется на следующем sampling boundary модели, оставаясь в текущем turn. Agent пишет код, вы вводите «перепиши на TypeScript» — он получит это указание на следующей точке sampling.
- **Ctrl+Q**: сообщение откладывается до завершения текущего turn и становится началом нового turn.
- **Во время выполнения инструмента**: введённое сообщение потребляется после возврата результата инструмента, в том же turn.
- **Передумали?** Нажмите Up или Escape — сообщение из очереди вернётся в поле ввода.

Вложения через @ тоже сохраняются, без добавления синтетического префикса. При сбое доставки или отмене сообщение не теряется.

Что это даёт:

- Agent пишет код не в том направлении — исправьте на лету, не дожидаясь завершения
- Добавьте контекст, пока выполняется инструмент
- Запланируйте вопрос на следующий turn через Ctrl+Q — он отправится автоматически по завершении текущего

### Изоляция сессий через Worktree: параллельные задачи без конфликтов

Две задачи в одном репозитории — одна сессия изменила файл, и `git status` другой тут же «поплыл». Раньше приходилось вручную делать `git worktree add` + `cd`, теперь в Web Shell это один клик.

В выпадающем меню ветки workspace выберите «New Worktree Task» — daemon автоматически создаёт git worktree в `<repoRoot>/.qwen/worktrees/<slug>`, рабочая директория сессии переключается на worktree. Фиолетовый символ ⑂ маркирует всё: git chip становится фиолетовым, в списке сессий появляется ⑂, в меню workspace есть пояснение. Для репозиториев без git эта опция не отображается.

Информация о Worktree сохраняется в sidecar-файл и не теряется при перезапуске daemon. При восстановлении сессии изоляция worktree восстанавливается автоматически, статусная строка показывает ветку worktree, а не основную ветку workspace.

Что это даёт:

- Два feature параллельно, без взаимных помех
- Исправляйте bug, продолжая работу над feature — без бесконечных stash
- Экспериментальные правки Agent в изолированной среде, основная рабочая зона остаётся чистой

### Встроенный web_search: поиск в интернете по ключу Bailian

Раньше в Qwen Code не было встроенного поиска — документация предлагала настроить Bailian WebSearch MCP. Но на практике этот MCP не справлялся со сложными запросами: запрос тарифов Medicare с однозначным ответом возвращал 0 из 5 релевантных результатов при нескольких попытках.

На этой неделе встроенный `web_search` вернулся. Серверный поиск на Bailian Responses API — достаточно уже настроенного ключа Bailian API, без дополнительных MCP-сервисов, провайдеров и ключей. Поисковый агент открывает страницы результатов для более обоснованных ответов; результаты разделяют «фактически прочитанные страницы» и «кандидаты, которые не открывались»; модель обязана добавить секцию Sources в конце ответа.

**По умолчанию выключен**, для включения нужны два параметра: `tools.webSearch.enabled: true` и модель поиска `tools.webSearch.model`. Если параметры заданы, но некорректно, инструмент остаётся выключенным, а при запуске сообщается, какое условие не выполнено. Поддерживается конфигурация через переменные окружения (`ENABLE_WEB_SEARCH`, `WEB_SEARCH_MODEL` и др.) — для сред, где settings.json недоступен. Каждый вызов поиска требует подтверждения (показывается запрос, можно выбрать «Всегда разрешать»).

Что это даёт:

- Актуальная информация: изменения в новых версиях библиотек, обновления API-документации, security advisory
- Проблемы после cutoff знаний модели: breaking change в новых версиях, недавние bug report
- Замена ручному уходу из терминала в браузер

### Полная переработка web_fetch: PDF без мусора, ссылки без потерь

Ранее `web_fetch` имел ряд реальных проблем: большие страницы-списки обрезались по исходному HTML до конвертации — ответ терялся, все URL ссылок пропадали, и модель уверенно сообщала «цель не существует». PDF декодировался как текст, превращаясь в десятки тысяч token мусора. Некоторые государственные сайты возвращали 403 для анонимного User-Agent.

На этой неделе весь пайплайн перестроен с нуля:

- **HTML сначала конвертируется в markdown, затем обрезается** — содержимое в глубине больших страниц сохраняется, все гиперссылки сохраняют URL. Обрезка помечена явно, скрипты и стили не расходуют контентный бюджет.
- **PDF извлекает текст инлайн** — один вызов `web_fetch` отвечает на вопросы по содержимому PDF. Бинарные файлы определяются по magic bytes (не только Content-Type) и сохраняются с правильным расширением.
- **Таймаут 60 секунд + лимит 10 МБ**, Esc мгновенно отменяет передачу — раньше UI мог зависнуть. Повторный захват того же URL в течение 15 минут идёт из кэша.
- **Межхостовые редиректы больше не следуют молча** — предлагается повторный запрос через стандартный процесс разрешений.
- **Модель разрешений**: первый доступ к каждому хосту требует подтверждения (GET раскрывает полный путь и query — канал утечки данных). После одобрения правило сохраняется по хосту. GitHub blob URL автоматически нормализуются в raw-адрес перед оценкой разрешений.

Что это даёт:

- Захватите ссылку на PDF — получите ответ по содержимому
- Захватите длинную страницу-список — спросите об элементе в глубине страницы, ссылки больше не теряются
- Межхостовые редиректы предлагают повторный запрос, не следуя молча на незнакомый домен

### Крупное обновление Web Shell на этой неделе

Web Shell получил большой объём изменений — от git-интеграции до управления сессиями и опыта workspace.

**Git-интеграция: три в одном.** Команда `/log` открывает браузер истории коммитов — графическое всплывающее окно со списком commit, клик разворачивает полное сообщение и статистику изменений файлов, копирование SHA в один клик, пагинация. В окно `/diff` добавлена вкладка History — не нужно переключать команды. Git status chip отображается на панели инструментов composer, боковая панель показывает git-состояние workspace, окно Changes показывает визуальный working-tree diff. Подробнее в PR [#7204](https://github.com/QwenLM/qwen-code/pull/7204), [#7054](https://github.com/QwenLM/qwen-code/pull/7054)

**Страница управления Skill и страница Goals.** В Web Shell появилась отдельная страница управления skill — просмотр и управление skill workspace без возврата в терминал. Страница Goals визуализирует цели `/goal` в Web Shell, цели не теряются при перезапуске daemon. Подробнее в PR [#7018](https://github.com/QwenLM/qwen-code/pull/7018), [#6561](https://github.com/QwenLM/qwen-code/pull/6561)

**Улучшения управления сессиями.** Cmd+B / Ctrl+B переключает боковую панель, раскладка split view сохраняется между обновлениями (по вкладкам независимо), восстановленные сессии поддерживают пагинацию истории вместо полной загрузки, архивные сессии можно экспортировать. В окне Add Workspace добавлено автодополнение каталогов. Подробнее в PR [#7135](https://github.com/QwenLM/qwen-code/pull/7135), [#7136](https://github.com/QwenLM/qwen-code/pull/7136), [#7064](https://github.com/QwenLM/qwen-code/pull/7064), [#6910](https://github.com/QwenLM/qwen-code/pull/6910), [#7125](https://github.com/QwenLM/qwen-code/pull/7125)

**Опыт Workspace.** Поддержка пользовательских отображаемых имён workspace — в мульти-workspace сценариях больше не нужно смотреть на пути. Пользовательские slash-команды, API кастомизации sidebar (брендирование, навигация, действия сессий, footer). Черновик новой темы предлагает открыть новую сессию, а не продолжать в старой. Подробнее в PR [#7179](https://github.com/QwenLM/qwen-code/pull/7179), [#7267](https://github.com/QwenLM/qwen-code/pull/7267), [#7379](https://github.com/QwenLM/qwen-code/pull/7379), [#7098](https://github.com/QwenLM/qwen-code/pull/7098)

## 📊 Другие новые возможности

**Значения по умолчанию и напоминание при записи Artifact.** При создании artifact Agent использует конфигурацию по умолчанию и запрашивает подтверждение перед записью — меньше случайных записей файлов. Подробнее в PR [#7068](https://github.com/QwenLM/qwen-code/pull/7068)

**Значения по умолчанию и guardrail для делегирования субагентам.** Улучшены конфигурация по умолчанию и границы безопасности делегирования субагентам — поведение субагентов стало предсказуемее. Подробнее в PR [#7048](https://github.com/QwenLM/qwen-code/pull/7048)

**Маршрутизация логов VSCode.** Логи выводятся в отдельный output channel Qwen Code Companion — при диагностике в VSCode не нужно искать в других панелях. Подробнее в PR [#7121](https://github.com/QwenLM/qwen-code/pull/7121)

**Ротация логов Daemon.** Логи с ограничением размера, больше не растут бесконечно — диск не заполняется логами daemon. Подробнее в PR [#6969](https://github.com/QwenLM/qwen-code/pull/6969)

**Воспроизведение истории в read-only WebShell.** Воспроизведение истории ChatRecord в read-only WebShell — удобно делиться записями сессий с коллегами. Подробнее в PR [#6999](https://github.com/QwenLM/qwen-code/pull/6999)

**Нормализация имён MCP-инструментов.** Нормализация имён MCP-инструментов для строгих провайдеров — меньше сбоев при вызовах MCP-инструментов. Подробнее в PR [#6976](https://github.com/QwenLM/qwen-code/pull/6976)

**Воспроизведение памяти Channel.** Каждое сообщение автоматически вызывает релевантные воспоминания, подтверждает изменения естественной памяти, безопасно сохраняет многофактную память — Agent в Channel помнит предыдущий контекст. **Форматированные пути в описаниях инструментов.** Описания инструментов grep/glob показывают форматированные пути файлов — результаты чище и читаемее. Подробнее в PR [#7050](https://github.com/QwenLM/qwen-code/pull/7050)

## 👏 Улучшения опыта

**Выбор мышью в VP mode вернулся.** Раньше события мыши в VP mode перехватывались CLI — выделить и скопировать было нельзя. **Защита от случайного Ctrl+C.** Для выхода из TUI нужно нажать Ctrl+C дважды в течение 1 секунды — одиночное нажатие больше не завершает сессию. Подробнее в PR [#7129](https://github.com/QwenLM/qwen-code/pull/7129)
