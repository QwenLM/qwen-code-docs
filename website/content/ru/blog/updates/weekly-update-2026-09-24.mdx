На этой неделе Qwen Code выпустил четыре официальных релиза — с v0.24.1 по v0.24.4 — и принял 200 pull-реквестов.

**Когда контекст заполнен, видно, какой файл и какое расширение его заняли.** Понятно, что отключать, чтобы освободить место.

**Один SSH-адрес — и проект на другой машине правится отсюда.** Код лежит на сервере, в сборочной машине или у коллеги: вы остаётесь за своим компьютером, а Qwen Code меняет файлы там и запускает там же сборку.

**Прерванный на середине рабочий процесс продолжается после перезапуска.** Завершённая часть не теряется: в многочасовом процессе доделываете только то, что упало.

## ✨ Новые возможности

### Контекст разложен по источникам: видно, какой файл и какое расширение его заняли

`/context` разводит контекст по источникам: системный промпт, встроенные инструменты, инструменты MCP, файлы памяти, навыки, файлы расширений; на этой неделе добавились ещё две строки — «Стартовый контекст» и «Префикс кэша». Через `/context detail` видно конкретные файлы: всё, что пришло из расширений, помечено `Extension: имя расширения · имя файла`, и для каждого указано, сколько он занимает. Терминал и Web Shell показывают одно и то же.

**Перерасход помечается сразу.** Если постоянный контекст (`QWEN.md` и автопамять) вместе превышает меньшее из двух значений — 15% окна или 10 000 токенов, — при загрузке появляется предупреждение.

**Правила из расширения можно включать только по попаданию в файл.** Контекст подмешивается, когда вы открываете именно тот файл, к которому правило привязано; в остальное время место не занимает.

Что это даёт:

- Контекст на исходе — сначала смотрите, какие файлы и какое расширение его съедают
- Поставили расширение и контекст подрос — `/context detail` покажет, из-за чего именно
- Предупреждение о перерасходе сразу отвечает, что сокращать: `QWEN.md` или автопамять

Подробнее: PR [#12119](https://github.com/QwenLM/qwen-code/pull/12119), [#12318](https://github.com/QwenLM/qwen-code/pull/12318), [#12034](https://github.com/QwenLM/qwen-code/pull/12034)

[📸 Скриншот: экран `/context detail` с помеченным источником из расширения]

### Проект на другой машине подключается по одному SSH-адресу

Проект лежит на сервере, в сборочной машине или у коллеги, а менять его нужно вам. Раньше для этого на той машине сначала ставили Qwen Code, поднимали сервис и только потом вписывали адрес. Теперь в Web Shell при добавлении рабочей области вместо пути каталога пишете SSH-адрес:

```text
ssh://user@host/absolute/project
```

Если Qwen Code там не установлен, регистрируете рабочую область этим адресом; если сервис уже запущен, один раз сохраняете адрес и токен — и дальше просто выбираете её при добавлении. После регистрации всё идёт через один ваш локальный диалог: чтение и запись файлов там, команды там же, состояние Git тоже там. Свежедобавленная рабочая область доступна только на чтение — менять в ней документы можно после того, как выдадите разрешение «Доверять».

Что это даёт:

- Код и зависимости на сборочной машине — правки и сборку заказываете из локального диалога
- Проверяете что-то в готовом окружении на чужой машине
- Локальный и удалённый проекты открыты одновременно, и вы ходите между ними в одном диалоге

Подробнее: PR [#12255](https://github.com/QwenLM/qwen-code/pull/12255), [#12085](https://github.com/QwenLM/qwen-code/pull/12085), [#12412](https://github.com/QwenLM/qwen-code/pull/12412)

### Прерванный рабочий процесс продолжается с того же места

Процесс не успел добежать до конца — вы ушли домой, машина ушла в перезагрузку. Раньше это означало запускать всё заново; теперь каждый запуск оставляет запись, и следующий старт начинает с того места, где всё оборвалось.

**После перезапуска напоминание приходит само.** Запуская Qwen Code, вы видите в стартовом сообщении, какой запуск прервался, на каком шаге он остановился и сколько дочерних агентов уже отработали, плюс подсказку заглянуть в `/workflows`. Эти запуски попадают и в историю.

**На карточке запуска в истории Web Shell есть кнопки.** «Повторить сбойную ветку» перезапускает только то, что не удалось, «Перезапустить всё» начинает с нуля.

Что это даёт:

- Уходите посреди длинного процесса — завтра посмотрите, на каком шаге он остановился
- В многочасовом процессе упали два дочерних агента — «Повторить сбойную ветку» доделывает только эти места
- Нужно ещё раз пройти весь процесс с начала — нажимаете «Перезапустить всё»

Подробнее: PR [#12159](https://github.com/QwenLM/qwen-code/pull/12159), [#12291](https://github.com/QwenLM/qwen-code/pull/12291), [#12097](https://github.com/QwenLM/qwen-code/pull/12097)

### Web Shell: сразу несколько обновлений

**Перед одобрением правка видна целиком.** Карточка подтверждения сама перечисляет, какие строки добавлены и какие удалены; это работает для изменения файла, создания нового и правки notebook. Подробнее: PR [#12443](https://github.com/QwenLM/qwen-code/pull/12443)

**Большая вставка сворачивается в карточку.** Всё, что длиннее 200 строк или 8000 символов, сворачивается автоматически; заголовок берётся из начала текста, а кнопка «Показать в поле ввода» возвращает содержимое обратно. Не сворачиваются вставки, начинающиеся с `/` или `!`, короткие вставки и замена выделения. Подробнее: PR [#12084](https://github.com/QwenLM/qwen-code/pull/12084)

**В правую панель добавляется вкладка Trajectory.** Раунд показался медленным или дорогим — открываете вкладку Trajectory и видите, куда ушло время: сколько длился каждый раунд, когда появился первый символ, сколько токенов потрачено и какой вызов инструмента стоил дороже всего. Вход — в правой области расширений через «Добавить вкладку», где и выбирается Trajectory. Подробнее: PR [#12388](https://github.com/QwenLM/qwen-code/pull/12388)

**История Git стала обозримее.** Коммиты в Web Shell показываются графом веток, можно переключаться между всеми ветками и искать по сообщению коммита, автору или хешу. Адреса удалённых репозиториев добавляются и удаляются там же, в интерфейсе, — терминал с командами не нужен. Вход — на метке ветки над полем ввода. Подробнее: PR [#12152](https://github.com/QwenLM/qwen-code/pull/12152), [#11163](https://github.com/QwenLM/qwen-code/pull/11163)

**Прочие улучшения.** Переключатель режима планирования убран из панели инструментов поля ввода в меню «+», а пока режим включён, над полем ввода остаётся снимаемая метка ([#12218](https://github.com/QwenLM/qwen-code/pull/12218)); файл, экспортированный через `/export`, виден в диалоге карточкой с предпросмотром и скачиванием ([#12050](https://github.com/QwenLM/qwen-code/pull/12050)).

## 📊 Прочие новинки

**Web Shell устанавливается как обычное приложение.** Справа в адресной строке появилась кнопка установки: один клик — и у сервиса свой значок и отдельное окно, как у приложения из магазина. Нужен Chrome / Edge 111 и выше, Firefox 128 и выше или Safari 16.4 и выше, а адрес должен быть локальным (`127.0.0.1` или `localhost`) либо отдаваться по HTTPS; по IP из локальной сети установить не выйдет. Подробнее: PR [#11722](https://github.com/QwenLM/qwen-code/pull/11722)

**В десктопной версии масштабируется текст окна.** `Cmd` / `Ctrl` с `-`, `=` или `0`, либо щипок двумя пальцами на тачпаде — от 50% до 300%; при следующем запуске остаётся тот масштаб, который вы выставили. Подробнее: PR [#12410](https://github.com/QwenLM/qwen-code/pull/12410)

**Квота Goal видна над полем ввода.** Строка состояния, кроме прежнего бюджета токенов, показывает ещё лимиты раундов и времени — например `3 / 20 turns` или `12m 3s / 30m 0s`; у Goal без лимитов всё по-прежнему. Экспорт через `/export` теперь содержит и весь путь Goal. Подробнее: PR [#12201](https://github.com/QwenLM/qwen-code/pull/12201), [#12099](https://github.com/QwenLM/qwen-code/pull/12099)

**Goal засчитывает выполнение по фактическому ходу диалога.** Даёте цель через `/goal`, она отрабатывает несколько раундов, но собственное «готово» из реплики Goal ничего не доказывает: приёмка перечитывает последние раунды и смотрит, что действительно произошло. Не сходится — цель считается невыполненной. Подробнее: PR [#12105](https://github.com/QwenLM/qwen-code/pull/12105)

**Дочернего агента можно запереть в контейнере.** Поручаете ему просмотреть весь репозиторий и гоняете кучу команд — и не боитесь, что он доберётся до SSH-ключей и учётных данных в домашнем каталоге: каждая команда и каждый ввод-вывод остаются внутри контейнера Docker или Podman, и доступна для записи только рабочая область. Включается это до запуска, через `QWEN_AGENT_EXECUTION_BACKEND=docker`; цена — при таком запуске отключаются рабочие процессы, Agent Team, MCP, LSP и навыки, а Windows пока не поддерживается. Подробнее: PR [#11711](https://github.com/QwenLM/qwen-code/pull/11711)

**У одного провайдера можно смешать два протокола.** Хотите, чтобы отдельная модель работала по протоколу OpenAI Responses, — добавляете в её запись строку `"wireApi": "responses"`; остальные модели идут по-прежнему через Chat. В `/auth` при настройке своего провайдера появился необязательный шаг «Выбор формата API». Подробнее: PR [#11538](https://github.com/QwenLM/qwen-code/pull/11538)

## 👏 Улучшения UX

**Web Shell на телефоне стал удобнее.** Если сервис слушает внешний адрес, QR-код для сопряжения появляется и в правом верхнем углу страницы сессии: навели камеру телефона — и вы в текущей сессии, вводить токен вручную не нужно. Поле ввода на мобильной странице переверстано: с десяток действий убраны в выдвижной ящик «Добавить к сообщению». Подробнее: PR [#12322](https://github.com/QwenLM/qwen-code/pull/12322), [#12252](https://github.com/QwenLM/qwen-code/pull/12252)

**Вокруг поля ввода стало чище.** Пока сессия не создана, выбор рабочей области и метка ветки Git уехали из панели инструментов поля ввода в отдельную строку ниже; после создания сессии от рабочей области остаётся только значок папки наверху, а полный путь виден по наведению мыши. Карточки-артефакты со ссылками в диалоге теперь открываются на новой странице. Подробнее: PR [#12299](https://github.com/QwenLM/qwen-code/pull/12299), [#12317](https://github.com/QwenLM/qwen-code/pull/12317)

**Сводка после `/compress` стала внятной.** После сжатия появляется «Контекст сжат: X → Y», а если сжимать нечего — «Сжатие не требуется.»; после перезапуска сессии число в кольце контекста тоже обновляется. Подробнее: PR [#12141](https://github.com/QwenLM/qwen-code/pull/12141)

**Автоподключение Channel в неосновных рабочих областях заработало.** Когда один `qwen serve` держит несколько рабочих областей со своими ботами Channel, при старте сервиса восстанавливаются Channel каждой доверенной области — переключатель «Подключать автоматически при запуске Qwen Code» после сохранения действительно применяется. Подробнее: PR [#12385](https://github.com/QwenLM/qwen-code/pull/12385)

**На Linux в песочницу теперь садится только выполнение инструментов.** Конфигурация прошлого выпуска, где весь Qwen Code запирался внутри bwrap, теперь завершается ошибкой с подсказкой по миграции. После перехода на `tools.executionSandbox` ограничения касаются только выполнения инструментов — командной строки и чтения-записи файлов, а сам Qwen Code, запросы к модели и ваш вход остаются на машине. Подробнее: PR [#12267](https://github.com/QwenLM/qwen-code/pull/12267)

**Одиночный вызов из скриптов стал быстрее.** Режим `qwen -p` — выполнил строку и вышел — ускорился с 7,7 до 5,1 секунды, а потребление памяти упало с 640 до 421 MiB: один процесс меньше поднимается. Подробнее: PR [#12340](https://github.com/QwenLM/qwen-code/pull/12340)

**Если QR-код не показался в терминале, причина объясняется.** Поднимаете сервис на внешнем адресе, чтобы подключиться с телефона, и кода нет — Qwen Code говорит, почему, и выдаёт отдельный код только с адресом: отсканировали, один раз ввели токен на телефоне, соединились. Принудительно вывести код вместе с токеном можно через `qwen serve --token-qr`. Подробнее: PR [#12266](https://github.com/QwenLM/qwen-code/pull/12266)
