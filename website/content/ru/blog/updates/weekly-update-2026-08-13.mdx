На этой неделе Qwen Code выпустил пять стабильных версий — с v0.21.7 по v0.21.11, принято более 220 PR. Десктоп-приложение обновилось до v0.2.1.

**Телефон теперь управляет Qwen Code на компьютере.** Local Control показывает QR-код: отсканируйте его телефоном в той же сети — и перехватите сессию, которая выполняется на компьютере.

**Длинные задачи теперь доходят до конца.** Goal больше не обрывается на 50 ходах — он сжимает доказательства в архив и продолжает работу. В Review появились правила ревью под конкретный репозиторий.

**Экосистема плагинов открыта.** Пакеты Agent Plugins v1 и плагины Qoder устанавливаются как есть, без конвертации. Web Shell умеет устанавливать расширения из архивов.

**Несколько AI работают в команде.** На прошлой неделе субагенты получили управление правами, на этой `/coordinate` пошёл дальше — он ведёт целую команду: исследователи по умолчанию только читают, код меняет только один, результаты сами уходят лидеру.

## ✨ Новые возможности

### Local Control: телефон по QR-коду перехватывает сессии компьютера

На прошлой неделе официально вышло десктоп-приложение Qwen Code, на этой у него появился новый сценарий: включите Local Control на компьютере — на экране появится QR-код. Отсканируйте его телефоном и перехватите сессию, которая выполняется на компьютере. На телефоне открывается та же самая сессия: продолжайте диалог, подтверждайте действия. Одно ограничение: телефон и компьютер должны быть в одной локальной сети, удалённый доступ через интернет пока не поддерживается; корпоративные локальные сети тоже работают.

Работает и в терминале, и в десктоп-приложении: в терминале выполните `qwen serve --local-control`, в десктоп-приложении выберите в меню Control → Local Control…. Каждое включение создаёт новый токен сопряжения; пока функция включена, компьютер не засыпает, а текущая сессия работает как раньше. Выключили функцию или закрыли окно управления — соединение сразу разрывается, токен сразу перестаёт действовать.

Что это даёт:

- Отсканировали — и работаете: на телефон ничего не нужно скачивать и настраивать
- Отошли от компьютера — на телефоне видно, на каком этапе задача и что ждёт вашего подтверждения
- Закрыли окно управления — соединение сразу разорвано

### Goal: лимит в 50 ходов убрали, длинные задачи доходят до конца

В режиме длинных задач Goal на этой неделе два важных обновления.

**Фиксированный лимит в 50 ходов убрали.** Раньше Goal останавливался на 50 ходах независимо от того, выполнена задача или нет, а после возобновления счётчик ходов сбрасывался. Теперь Goal движется самой задачей: задача не выполнена, вы не ставили паузу и не очищали — он продолжает работать, а ходы накапливаются между паузой и возобновлением.

**У длинных задач появился архив доказательств.** Когда собранные Goal доказательства приближаются к лимиту, runtime ставит автопродолжение на паузу: отдельный валидатор без доступа к инструментам сжимает накопленные доказательства в набор кратких выводов, проверяет источник каждой цитаты, сохраняет в архив — и работа продолжается. Архив переживает даже неожиданное завершение процесса. Если проверка при сжатии не проходит, Goal останавливается и ждёт вас — не рвётся вперёд с ошибками.

Goal теперь не только в терминале. Goal в Web Shell работает на том же runtime, что и терминал: создание, редактирование, пауза, возобновление, очистка — всё на месте. Сторонние инструменты, подключённые через ACP, тоже могут вызывать те же возможности Goal на уровне протокола.

Подробнее в PR [#8421](https://github.com/QwenLM/qwen-code/pull/8421), [#8465](https://github.com/QwenLM/qwen-code/pull/8465), [#8732](https://github.com/QwenLM/qwen-code/pull/8732)

### Экосистема плагинов: Agent Plugins v1 и плагины Qoder устанавливаются как есть

Раньше, чтобы установить стороннее расширение, его приходилось конвертировать в формат Qwen Code. На этой неделе оба стандартных формата плагинов работают как есть:

**Agent Plugins v1.** Это открытый формат плагинов, и Qwen Code на этой неделе его поддержал: пакеты, соответствующие стандарту `plugin.json`, устанавливаются в Qwen Code как есть — после установки их можно обновлять, включать и выключать, а skill и MCP-серверы внутри доступны сразу.

**Плагины Qoder.** Устанавливаются из пяти источников: локальный каталог, архив, Git-репозиторий, URL архива, npm-пакет. Команды, агенты, skill и MCP-серверы из пакета автоматически конвертируются в расширения Qwen Code; если в корне пакета есть `system-prompt.md`, он автоматически загружается как контекст.

Менеджер расширений Web Shell умеет устанавливать расширения из локальных архивов `.zip` / `.tar.gz`.

Подробнее в PR [#8834](https://github.com/QwenLM/qwen-code/pull/8834), [#8661](https://github.com/QwenLM/qwen-code/pull/8661), [#8621](https://github.com/QwenLM/qwen-code/pull/8621)

### Review: правила ревью под репозиторий, большие PR больше не таймаутятся

Review на этой неделе обновился в двух направлениях.

**Правила ревью настраиваются под репозиторий.** Положите в репозиторий файл `.qwen/review-context.json`: какие модули есть в репозитории, на какие связанные пути смотреть при изменении определённого пути, какие тесты запускать — `/review` использует эти правила при составлении плана ревью. При ревью PR файл читается из базовой версии проверяемой ветки — ветка не может поменять собственные правила ревью.

**Быстрее и стабильнее.** Весь процесс ревью ускорился: изменения больше 3000 строк больше не падают по таймауту, мелкие изменения в несколько десятков строк получают результат быстрее, на финальный отчёт теперь всегда остаётся время — работа не уходит в пустоту без итогового слова. `/review submit` после выполнения сразу печатает ссылку на ревью.

### /coordinate: несколько AI делят работу — исследователи только читают, меняет один, итоги подводятся автоматически

На прошлой неделе мы сделали управление правами субагентов — «ключи под задачу». На этой пошли дальше: `/coordinate` теперь по-настоящему ведёт команду AI с разделением труда. Раньше `/coordinate` просто описывал командный процесс в промпте, и действительно ли напарники «только смотрят и не меняют», зависело от сознательности модели. Теперь это обеспечивает runtime:

- **Исследователи по умолчанию только читают**: отправленные на разведку напарники могут только смотреть репозиторий, обмениваться сообщениями и обновлять список задач — попытки изменить файлы или выполнить команду блокируются на уровне исполнения
- **Код меняет только один**: лидер создаёт Git worktree и отправляет туда единственного писателя — основной checkout остаётся нетронутым
- **Результаты приходят сами**: напарник закончил работу — выводы автоматически уходят лидеру, не нужно ждать отдельного сообщения, лидер не простаивает

Функция пока экспериментальная: чтобы пользоваться, установите переменную окружения `QWEN_CODE_ENABLE_AGENT_TEAM` в `1` — это включает Agent Team.

Что это даёт:

- Сложный вопрос несколько AI разбирают параллельно — быстрее, чем один агент копается в коде
- Исследователи — только чтение, руки только у одного, права под контролем
- Изменения попадают в отдельный worktree — основная ветка чиста

Подробнее в PR [#8804](https://github.com/QwenLM/qwen-code/pull/8804)

### Экосистема Channel: одно одобрение на всю группу, карточки с вариантами в Feishu

**Одно одобрение — и вся группа может пользоваться.** Раньше режим сопряжения был персональным: подключаете группу — и каждого участника нужно одобрять отдельно. Теперь сопряжение работает по группам: одобрите группу один раз по её ID — пользоваться могут все участники; личные чаты по-прежнему одобряются по человеку. Одобрение группы можно отозвать отдельно, списки каждого workspace управляются отдельно.

**В Feishu появились карточки с вариантами.** AI в работе иногда задаёт вопросы с выбором — например, «какой из двух вариантов берём». Раньше в Feishu такие вопросы показывались просто текстом: видно, но ответить нельзя, задача стоит. Теперь вопрос превращается в карточку с вариантами: выбрали, отправили — задача продолжается. Люди и группы в сессиях Feishu больше не показываются непонятными ID — вместо них настоящие имена.

**Карточки статуса DingTalk стали лучше.** Раньше, когда AI работал в DingTalk, вывод разлетался на несколько карточек. Теперь на всю задачу одна карточка: с самого начала виден статус выполнения, вывод обновляется на карточке в реальном времени, а когда работа закончена, финальный ответ заменяет процесс целиком. При упоминании человека в финальной карточке только один @. Когда в группе DingTalk упоминают бота и заодно кого-то ещё, AI понимает, кого именно упомянули.

**Сессии Channel теперь видны в Web Shell.** Сессии из DingTalk, Feishu и WeCom показываются в боковой панели Web Shell, сгруппированные по платформам, рядом с обычными задачами. Для каждого Channel настраивается гранулярность разделения сессий: по пользователю, по теме, по чату — или одна общая сессия на весь канал.

## 📊 Больше новых возможностей

**Сжатие стало дешевле и быстрее.** Когда диалог слишком длинный, Qwen Code сжимает его в короткую версию — но само сжатие отправляло весь длинный диалог модели ещё раз. Теперь контент, который модель уже обработала в основном диалоге, при сжатии переиспользуется, а не обрабатывается с нуля. Поддерживаются OpenAI-совместимые сервисы, Gemini и Vertex AI. Если переиспользовать не получается, автоматически включается прежний способ. Подробнее в PR [#8418](https://github.com/QwenLM/qwen-code/pull/8418), [#8425](https://github.com/QwenLM/qwen-code/pull/8425)

**Управление глубиной размышлений Qwen 3.8 пришло в Web Shell и ACP.** В меню моделей Web Shell можно прямо включать и выключать Thinking и выбирать уровень усилий low/medium/xhigh (пока поддерживается qwen3.8-max). ACP-клиенты (например, JetBrains) получили стандартные варианты глубины размышлений — шесть уровней от Default до Max. Подробнее в PR [#8974](https://github.com/QwenLM/qwen-code/pull/8974), [#8526](https://github.com/QwenLM/qwen-code/pull/8526)

**Workflows можно ставить на паузу и возобновлять.** Динамические workflows поддерживают кооперативные паузу и возобновление: в фоновых задачах — клавиша `p`, в терминале — `/workflows p <runId>`. Пауза не прерывает выполняющиеся подзадачи: новые задачи больше не выдаются, готовые результаты придерживаются, после возобновления работа продолжается с того же места. Подробнее в PR [#8320](https://github.com/QwenLM/qwen-code/pull/8320)

**Появился пакетный интерфейс включения и выключения skill.** daemon предоставляет пакетный интерфейс: до 100 skill включается или выключается за один раз — инструментам управления, подключённым к Qwen Code, больше не нужно слать запросы по одному. Подробнее в PR [#8664](https://github.com/QwenLM/qwen-code/pull/8664)

**Логи OpenAI API очищаются автоматически.** Если включён `model.enableOpenAILogging`, логи запросов автоматически удаляются по истечении срока — по умолчанию 7 дней, настраивается через `model.openAILogRetentionDays`. Подробнее в PR [#8862](https://github.com/QwenLM/qwen-code/pull/8862), [#8893](https://github.com/QwenLM/qwen-code/pull/8893)

**Внешний корпус умеет писать в Mem0.** Интеграция внешнего корпуса может записывать одобренный контент обратно в Mem0 как память — включается явно в конфигурации. Подробнее в PR [#8507](https://github.com/QwenLM/qwen-code/pull/8507)

**Для голосовой транскрипции можно указать доверенный шлюз.** Новая настройка `security.allowedInsecureVoiceBaseUrls`: управляемые развёртывания могут направлять голосовую транскрипцию на указанный HTTP- или внутренний ASR-сервис. Подробнее в PR [#8350](https://github.com/QwenLM/qwen-code/pull/8350)

**`/doctor memory` показывает долю результатов инструментов.** Новая статистика: сколько результатов инструментов держит текущая сессия, сколько всего символов, какой самый крупный. Если больше 30 тысяч символов — предложит выполнить `/compress`. Подробнее в PR [#8875](https://github.com/QwenLM/qwen-code/pull/8875)

## 👏 Улучшения опыта

**Изображения, которые модель возвращает напрямую, тоже показываются.** На прошлой неделе в терминале научились показываться изображения, сохранённые в файлы. На этой добавились изображения, которые модель возвращает прямо в ответе, и изображения в результатах инструментов — всё рендерится вместе с текстом в порядке вывода. Подробнее в PR [#8305](https://github.com/QwenLM/qwen-code/pull/8305)

**В Web Shell изображения отправляются перетаскиванием.** Перетащите PNG, JPEG, GIF, WebP или BMP прямо в поле ввода — несколько изображений сохраняют порядок, можно отправить и только изображения, без текста. Подробнее в PR [#8696](https://github.com/QwenLM/qwen-code/pull/8696)

**Клик по изображению открывает его целиком.** Кликните по загруженному или вставленному изображению — в правой панели откроется вкладка предпросмотра, при наведении появляется кнопка скачивания. Подробнее в PR [#8930](https://github.com/QwenLM/qwen-code/pull/8930)

**Правая панель раскрывается на весь экран одним кликом.** Панели артефактов, субагентов, diff и другие разворачиваются на весь экран одной кнопкой. Подробнее в PR [#8614](https://github.com/QwenLM/qwen-code/pull/8614)

**Заполнение контекста видно с одного взгляда.** Рядом с полем ввода появилось кольцо прогресса: сколько занято окно контекста. При 60% и 80% оно меняет цвет на предупреждающий, при наведении видны точные цифры, по клику открывается панель `/context`. Подробнее в PR [#8794](https://github.com/QwenLM/qwen-code/pull/8794)

**Статус субагентов стал понятнее.** Когда работают параллельные субагенты, блок статуса постоянно висит внизу диалога: во время работы он раскрывается сам, после завершения сворачивается. Строку любого субагента можно раскрыть в любой момент — тип и метрики видны сразу. Подробнее в PR [#8559](https://github.com/QwenLM/qwen-code/pull/8559), [#8780](https://github.com/QwenLM/qwen-code/pull/8780)

**Одно нажатие Esc — и всё остановилось.** Раньше, когда в очереди были сообщения, приходилось жать Esc трижды, чтобы AI прекратил вывод. Теперь первое же нажатие отменяет текущую работу. Подробнее в PR [#8353](https://github.com/QwenLM/qwen-code/pull/8353)

**Выделение мышью стало удобнее.** В терминале: дважды кликните по слову и, удерживая, тяните — выделение расширяется по словам; трижды кликните по строке и тяните — выделение расширяется по строкам. Подробнее в PR [#8739](https://github.com/QwenLM/qwen-code/pull/8739)

**Статус задачи виден в заголовке окна.** Когда AI выводит ответ или ждёт подтверждения, перед заголовком окна или вкладки терминала появляются символы ◐ и ✳ — в мультиплексорах вроде tmux сразу видно, в каком окне что происходит. Подробнее в PR [#8970](https://github.com/QwenLM/qwen-code/pull/8970)

**Категории автодополнения переключаются стрелками.** Переключение категорий автодополнения `@` переехало с Ctrl+Tab на стрелки влево и вправо. Подробнее в PR [#8576](https://github.com/QwenLM/qwen-code/pull/8576)

**Копирование в Wayland и ссылки в китайском тексте.** В Linux на Wayland копирование текста теперь предпочитает `wl-copy`; простые ссылки в китайском тексте больше не захватывают идущие следом полноширинные знаки препинания. Подробнее в PR [#8481](https://github.com/QwenLM/qwen-code/pull/8481), [#8755](https://github.com/QwenLM/qwen-code/pull/8755)

**Стриминг стал плавнее.** Парсинг Markdown во время стриминга теперь идёт с фиксированным интервалом — длинные ответы не подвисают; внутренний вывод hook больше не примешивается к отображению диалога. Подробнее в PR [#7904](https://github.com/QwenLM/qwen-code/pull/7904), [#7948](https://github.com/QwenLM/qwen-code/pull/7948)

**Статус в узких окнах.** В узком терминале имена слэш-команд больше не обрезаются; когда стриминг мешает показать очередь, в строке статуса постоянно висит бейдж «N queued». Подробнее в PR [#8657](https://github.com/QwenLM/qwen-code/pull/8657), [#8667](https://github.com/QwenLM/qwen-code/pull/8667)

**Вызовы инструментов ACP выполняются параллельно.** Вызовы инструментов, которые раздаёт ACP-агент, теперь выполняются параллельно в пределах настроенного лимита — раньше они шли по очереди. Подробнее в PR [#8631](https://github.com/QwenLM/qwen-code/pull/8631)

**Десктоп-версия скачивается быстрее.** Раньше установщики десктоп-приложения скачивались с GitHub — в Китае это медленно и нестабильно. Теперь копия лежит на Alibaba Cloud OSS: при проверке обновлений скачивание идёт сначала оттуда, а на GitHub возвращается только если не получилось. Подробнее в PR [#8976](https://github.com/QwenLM/qwen-code/pull/8976)

**Мелочи десктоп-версии.** При первом запуске автоматически создаётся workspace по умолчанию — открыли и работаете, выбирать каталог не нужно. На macOS закрытие главного окна теперь прячет его — клик по Dock возвращает обратно. При неудачном автообновлении показывается конкретная причина. Если в напоминании об обновлении провайдера выбрать «позже», следующее появится через 24 часа. Подробнее в PR [#8814](https://github.com/QwenLM/qwen-code/pull/8814), [#8802](https://github.com/QwenLM/qwen-code/pull/8802), [#8807](https://github.com/QwenLM/qwen-code/pull/8807), [#8829](https://github.com/QwenLM/qwen-code/pull/8829)

**Ошибки переключения сессий говорят, что именно мешает.** Если сессию не удаётся переключить из-за работающих фоновых задач, в ошибке видны их ID и статус. Подробнее в PR [#8742](https://github.com/QwenLM/qwen-code/pull/8742)
