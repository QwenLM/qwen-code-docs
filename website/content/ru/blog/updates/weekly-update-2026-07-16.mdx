На этой неделе Qwen Code выпустил 3 стабильные версии v0.19.9, v0.19.10 и v0.19.11, принято более 160 PR.

**Команда `/learn`.** Пользователь создаёт skill вручную — указывает источник знаний (каталог, URL, диалог, текст), Qwen Code автоматически формирует SKILL.md для повторного использования.

**Code Review вышел на новый уровень качества.** Suggestion публикуется как inline-комментарий в PR, добавлены проверка корректности программы, предиктивная валидация, Step 4 verifier и Step 5 reverse-audit.

**Масштабная переработка Web Shell.** Библиотека shadcn в основе UI, панель ревью Artifact, страница управления extension, масштабирование и перетаскивание Mermaid-диаграмм. Полная поддержка мульти-workspace, split pane с цветовой маркировкой по workspace.

**Voice Bridge: голосовой ввод через ACP.** Даже текстовая основная модель обрабатывает голосовые prompt — аудио сначала транскрибируется в текст, модели с поддержкой аудио получают оригинальный поток без преобразования.

**Сканированные PDF больше не блокируют Agent.** При превышении лимита извлечения текста страницы автоматически рендерятся в изображения, визуальная модель анализирует картинку.

**CLI-рабочие процессы дополнены.** `/update` для обновления в один клик, Ctrl+O для заморозки диалога, Ctrl+S для временного сохранения prompt, Explore наследует основную модель, Alt+T разворачивает полный ход рассуждений.

## ✨ Новые возможности

### `/learn`: превращение знаний в переиспользуемый Skill

`/learn` — новая slash-команда для создания переиспользуемых skill из источников знаний. Источником может быть локальный каталог, URL, история диалога или произвольный текст. Основная модель собирает знания и автоматически формирует SKILL.md, сохраняя его в `.qwen/skills/learned-skill-<name>/` с меткой `source: learned` — отдельно от skill, написанных вручную или сгенерированных автоматически.

Что это даёт:

- `/learn Deploy process: ...` — оформление процесса деплоя в skill для повторного использования
- Указание каталога документации позволяет Qwen Code изучить стандарты разработки проекта и следовать им в дальнейшем
- Извлечение знаний из диалога и сохранение их в виде переиспользуемого шаблона команд

### Масштабное обновление контроля качества Code Review

На этой неделе Code Review усилен по нескольким направлениям — от inline-комментариев до верификации качества самого review.

`/review` теперь **публикует находки типа Suggestion напрямую как inline-комментарии в PR** — больше не нужно вручную копировать рекомендации из вывода review и вставлять их в PR. В сам review добавлены проверки процедурной корректности (procedural correctness finders), настраиваемый уровень effort, а перед публикацией guardrail-валидация подтверждает обоснованность каждой находки.

**Review больших diff больше не распределяется оптом — каждая строка diff закреплена за конкретным reviewer, что обеспечивает полное покрытие**. Review chunk agent получает полностью сформированный prompt, запуски с пустым контекстом исключены. PR triage-комментарии дополнены оценкой уверенности, диаграммами последовательности, обзором файлов и review footer — reviewer получает более богатый контекст. Таймаут автоматического review по умолчанию увеличен до 180 минут с возможностью override до 240 минут, большие PR больше не прерываются по таймауту.

Что это даёт:

- `/review` автоматически публикует inline suggestion в PR, избавляя от ручной вставки комментариев
- Настраиваемый уровень effort адаптируется к объёму review
- Оценка уверенности PR triage помогает определить, какие PR требуют повышенного внимания

В v0.19.11 добавлены **Step 4 verifier и Step 5 reverse-audit** — процесс review превратился из «найти проблему → опубликовать комментарий» в полный цикл «найти проблему → подтвердить обоснованность находки → провести обратный аудит на предмет пропусков». Список findings свёрнут в prompt верификации и обратного аудита, что уменьшает объём prompt. Область build/test агента 7 также сужена до workspace, реально затронутых diff, большие репозитории больше не собираются целиком.

### Voice Bridge: голосовой ввод через ACP

Ранее при отправке голосового prompt через ACP (Agent Communication Protocol), если основная модель была текстовой, аудио не обрабатывалось. Теперь добавлен voice bridge — аудио сначала транскрибируется настроенной voice model в текст, затем передаётся основной модели. Если основная модель сама поддерживает аудиовход, оригинальное аудио передаётся напрямую, без транскрипции. При недоступности или сбое транскрипции основная модель получает безопасное сообщение «аудио недоступно», сырое аудио не передаётся.

Что это даёт:

- Отправка голосовых команд через ACP-клиент — текстовые модели тоже понимают голос
- Основные модели с поддержкой аудио (мультимодальные) получают оригинальный аудиопоток без потери информации
- Безопасная деградация при сбое транскрипции — проблемы с аудио не прерывают диалог

Подробнее в PR [#6576](https://github.com/QwenLM/qwen-code/pull/6576)

### Автоконвертация PDF в изображения: сканированные документы больше не блокируют Agent

Ранее при работе со сканированными или насыщёнными текстом PDF извлечение текста превышало бюджет в 12000 token и вызывало зацикливание `FILE_TOO_LARGE` — Agent повторял попытки с меньшим диапазоном страниц, каждый раз превышая лимит, контекст переполнялся до сбоя сессии. Теперь добавлен fallback с рендерингом страниц в изображения: при превышении лимита или сбое извлечения текста страницы автоматически рендерятся через `pdftoppm` в JPEG и передаются визуальной модели. Стоимость в token на страницу фиксирована и не зависит от плотности текста. Извлечение текста остаётся основным путём (grep, точное цитирование), рендеринг включается только при превышении лимита или сбое. Для текстовых основных моделей с подключённой визуальной моделью сканированные документы, прикреплённые через `@`, рендерятся в небольшом количестве страниц и передаются vision bridge для транскрипции.

Что это даёт:

- Сканированные PDF больше не вызывают `FILE_TOO_LARGE`, визуальная модель анализирует изображения
- Насыщённые PDF (превышающие бюджет token) автоматически деградируют до изображений, контекст не переполняется
- Текстовые PDF по-прежнему обрабатываются через извлечение текста, точность не теряется

### Обновление CLI-процессов: обновление в один клик, диалог не теряется

Раньше для обновления Qwen Code нужно было помнить способ установки — `npm install` для npm, повторная загрузка установщика для standalone. На этой неделе добавлены команда `qwen update` и slash-команда `/update`, автоматически определяющие тип установки. Standalone-установка загружает последнюю версию из npm registry с проверкой SHA256 + верификацией подписи Ed25519 (опционально) + smoke test (новый двоичный файл должен пройти `--version`) + атомарная замена, автоматический откат при сбое. Для npm-установки отображается соответствующая команда `npm install -g`. Поддержка i18n для 9 языков. Подробнее в PR [#5780](https://github.com/QwenLM/qwen-code/pull/5780)

**Ctrl+O — заморозка представления transcript** — нажатие открывает альтернативный экран с полной записью диалога, все выводы инструментов развёрнуты, доступна прокрутка. Esc/q/Ctrl+C/Ctrl+O для возврата. Одновременно переработан рендеринг выводов инструментов: результаты read/search/list свёрнуты в однострочные сводки, mutating-инструменты остаются развёрнутыми. Настройка compactMode молча игнорируется. Подробнее в PR [#5666](https://github.com/QwenLM/qwen-code/pull/5666)

![](https://gw.alicdn.com/imgextra/i2/O1CN01b2Flxy1UBR05kJjrS_!!6000000002479-2-tps-3837-2160.png)

**Ctrl+O — временное сохранение prompt** — при нажатии Ctrl+S с содержимым в поле ввода prompt сохраняется в файл временного хранения на уровне проекта, при следующем запуске из того же проекта автоматически восстанавливается. После отправки временный файл удаляется. Заполнители больших вставок разворачиваются перед сохранением, восстанавливается оригинальное содержимое. Разные проекты не мешают друг другу. Подробнее в PR [#6709](https://github.com/QwenLM/qwen-code/pull/6709)

**Настраиваемый таймаут shell-команд**. Добавлена настройка `tools.shell.defaultTimeoutMs` для изменения таймаута по умолчанию на уровне проекта или сессии, без необходимости каждый раз указывать таймаут в параметрах команды. Значение по умолчанию — 120 секунд, 0 отключает таймаут. Подробнее в PR [#6628](https://github.com/QwenLM/qwen-code/pull/6628)

**Explore subagent теперь наследует основную модель**. Встроенный Explore subagent больше не выбирает fastModel автоматически, а наследует модель основной сессии. Если основная модель — Claude Opus, Explore тоже использует Claude Opus, без потери качества рассуждений. Для возврата к быстрой модели установите `agents.builtin.exploreModel` в `fast` или конкретный ID модели. Подробнее в PR [#6807](https://github.com/QwenLM/qwen-code/pull/6807)

**Alt+T разворачивает полный ход рассуждений**. При потоковом выводе нажатие Alt+T разворачивает thinking block — теперь виден полный поток рассуждений в реальном времени, а не захардкоженные 4 строки хвоста. Отслеживание цепочки рассуждений модели наконец-то полноценное. Длинные рассуждения ограничены высотой области просмотра, бесконечного разворачивания нет. Подробнее в PR [#6678](https://github.com/QwenLM/qwen-code/pull/6678)
