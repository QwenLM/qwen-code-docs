На этой неделе Qwen Code выпустил пять стабильных версий — с v0.21.2 по v0.21.6, принято более 300 PR. И ещё одно крупное событие: официально вышло десктоп-приложение Qwen Code v0.1.0.

**Десктоп-версия вышла!** Ещё на прошлой неделе Web Shell получил большое обновление, а на этой превратился в полноценное десктоп-приложение: Qwen Code Desktop v0.1.0 вышел с нативными установщиками для macOS, Windows и Linux — скачать можно прямо из GitHub Releases.

**Выполнение задач теперь видно.** Новый вид Session Workflow рисует план и прогресс выполнения в виде блок-схемы: сколько шагов в плане, какой выполняется, какой ждёт, какая подзадача какому AI поручена — всё на одном экране. Перед стартом AI показывает эту схему вам и приступает только после подтверждения.

**Терминал и управление правами тоже подтянулись.** Изображения, которые рисует AI, теперь показываются прямо в терминале — не нужно открывать файл вручную. Права субагентов выдаются под задачу: задача только на чтение получает права только на чтение, а часто используемые наборы прав сохраняются в шаблоны. Для сжатия длинных сессий можно отдельно указать недорогую модель — расходы под контролем.

## ✨ Новые возможности

### Десктоп-приложение Qwen Code официально вышло: нативные приложения для трёх ОС

Раньше десктопный опыт Qwen Code был разрознен: Electron-приложение и Web Shell в браузере. На этой неделе они объединились: официально вышло десктоп-приложение Qwen Code v0.1.0 с интерфейсом обновлённого на прошлой неделе Web Shell. Установщики для macOS, Windows и Linux уже доступны — скачивайте прямо из [GitHub Releases](https://github.com/QwenLM/qwen-code/releases#release-desktop-v0.1.0).

Пользователям macOS с Electron-версией не нужно мигрировать вручную: в новой версии есть одноразовый мастер миграции, а после перехода обновления устанавливаются автоматически.

Что это даёт:

- Десктопный Qwen Code умеет всё то же, что и терминальная версия
- Единый опыт на трёх основных операционных системах
- Автоматическая проверка обновлений — новые версии не нужно устанавливать вручную

### Session Workflow: план, подзадачи и прогресс — на одной схеме

Когда запускается сложная задача, раньше приходилось листать историю диалога, чтобы понять, на каком шаге план и что делает каждая подзадача.

Новый вид Session Workflow рисует всё это в виде блок-схемы: каждый шаг плана — отдельный блок, порядок шагов соединён линиями, в реальном времени видно, какой шаг выполняется, а какой застрял. Подзадачи, которые раздаёт AI, тоже висят на схеме — кликните, чтобы посмотреть, что именно сделала каждая. Перед стартом AI показывает схему вам: подтвердили — начинается работа, нет — AI возвращается и перестраивает план. После завершения задачи схему можно открыть снова: для каждого шага записано, кто его выполнил и что сделал.

Функция выключена по умолчанию — чтобы включить, установите `experimental.sessionWorkflow` в true в settings. После включения есть ещё два удобства: когда подзадаче нужно ваше подтверждение — например, на запуск команды или изменение файла, — запрос всплывает прямо в главном интерфейсе, не нужно нырять в подзадачу; особо долгие задачи можно отправить в фон, а основной диалог продолжает другую работу — по завершении придёт уведомление.

Что это даёт:

- Прогресс сложной задачи виден с одного взгляда — какой шаг застрял, понятно по схеме
- Сначала подтверждаете план, потом AI приступает — спокойнее
- Долгие задачи — в фон, основной диалог занимается другим

### display_image: изображения от AI показываются прямо в терминале

Раньше AI генерировал изображение и выдавал путь к файлу — открывать приходилось самому. Теперь изображение показывается прямо в терминале сразу после генерации. Так выбрали и обложку этого выпуска: AI сгенерировал несколько вариантов, они отобразились в терминале, и можно было сравнить и выбрать, не открывая каждый файл по отдельности. Если терминал не поддерживает показ изображений, Qwen Code прямо об этом скажет.

Что это даёт:

- Изображения от AI видны сразу после генерации — не нужно открывать файл вручную
- Графики по вашим данным и скриншоты собранной веб-страницы тоже отображаются напрямую
- Дизайн-макеты и скриншоты из репозитория AI покажет тут же, рядом

### Права субагентов: ключи выдаются под задачу, параллельные задачи не мешают друг другу

Когда вы даёте Qwen Code большую задачу, он иногда отправляет несколько «клонов» (субагентов) работать параллельно — один читает код, другой запускает тесты. Раньше любой клон получал полный набор возможностей основного агента: чтение файлов, изменение файлов, запуск команд. Вы хотите, чтобы он «просто посмотрел код и написал сводку», а он может попутно изменить файлы — тревожно.

Теперь права настраиваются под задачу:

- **Ключи по задаче**: при создании клона можно ограничить набор доступных инструментов — достаточно одной фразы, например «эта задача только на чтение», и ограничение передаётся вместе с задачей: попытка что-то изменить отклоняется на месте
- **Шаблоны прав**: часто используемые наборы прав сохраняются в шаблоны в каталоге `.qwen/fork-profiles/` проекта — дальше они применяются одним параметром, без повторной настройки
- **Изоляция задач**: закрыли дыру — раньше несколько клонов при параллельной работе видели инструкции друг друга, теперь каждый видит только свои и сосредоточен на своей задаче

Что это даёт:

- Задачи только на чтение получают права только на чтение — никаких попутных изменений файлов
- Частые наборы прав — в шаблоны, повторное использование одной строкой
- Параллельные клоны работают каждый над своим, не мешая друг другу

Подробнее в PR [#8066](https://github.com/QwenLM/qwen-code/pull/8066), [#8148](https://github.com/QwenLM/qwen-code/pull/8148), [#8344](https://github.com/QwenLM/qwen-code/pull/8344)

### Оптимизация стоимости сжатия: для сжатия можно указать недорогую модель

Когда длинная сессия запускает автосжатие, раньше полный контекст прогонялся только основной моделью — дорого и медленно.

На этой неделе три улучшения. Первое: `/model --compaction` позволяет указать отдельную модель для сжатия — шаг «суммировать длинный диалог» выполняет недорогая модель, а основной диалог продолжает работать на хорошей, качество не страдает. Второе: при сжатии основной моделью переиспользуется ранее закэшированный контент — ответы быстрее, поддерживается и история с изображениями. Третье: для моделей семейства Claude можно установить `generationConfig.cacheRetention` в `"1h"` — время жизни кэша вырастет с 5 минут по умолчанию до 1 часа, и сессии с большими интервалами перестанут каждый раз терять кэш.

Что это даёт:

- Сжатие — недорогой модели, длинные сессии обходятся дешевле
- Сжатие основной моделью переиспользует кэш — ответы быстрее
- Редкие сессии больше не платят за протухший кэш каждый раз

Подробнее в PR [#7818](https://github.com/QwenLM/qwen-code/pull/7818), [#8339](https://github.com/QwenLM/qwen-code/pull/8339), [#8419](https://github.com/QwenLM/qwen-code/pull/8419), [#8048](https://github.com/QwenLM/qwen-code/pull/8048)

### Экосистема Channel: GitLab, интерактивные карточки DingTalk, управление сопряжением

На прошлой неделе вышел GitHub Channel, на этой экосистема Channel продолжает расти.

**GitLab на связи.** Todo в GitLab и комментарии с @ботом превращаются во входящие сообщения; какие действия обрабатывает AI — настраивается, уже обработанные не обрабатываются повторно. Подробнее в PR [#7862](https://github.com/QwenLM/qwen-code/pull/7862)

**У DingTalk появились интерактивные карточки.** Channel DingTalk поддерживает интерактивные карточки: статус работы AI обновляется на карточке в реальном времени, а когда нужен ваш ввод, всплывает структурированный вопрос — не нужно читать простыню текста. На другие платформы это не влияет. Подробнее в PR [#6930](https://github.com/QwenLM/qwen-code/pull/6930)

![Интерактивные карточки DingTalk](https://img.alicdn.com/imgextra/i3/O1CN01rlQ42T6JklK3OTaQ_!!6000000002748-2-tps-1672-942.png)

**Список «кто может командовать AI» теперь можно смотреть и отзывать.** При подключении чат-платформ из соображений безопасности можно включить режим сопряжения: когда незнакомец впервые упоминает бота, ему нужно ваше одобрение. Раньше после одобрения посмотреть список было негде, а отозвать — невозможно: ошибочно одобренный человек или ушедший сотрудник продолжал пользоваться вашим AI. Теперь в редакторе Channel видно, кто одобрен, доступ отдельному человеку можно отозвать, а списки каждого workspace управляются отдельно. Подробнее в PR [#8045](https://github.com/QwenLM/qwen-code/pull/8045), [#8081](https://github.com/QwenLM/qwen-code/pull/8081)

**GitHub/GitLab Channel больше не требуют ручной правки конфигов.** Раньше, чтобы подключить AI к GitHub/GitLab, приходилось вручную писать в `settings.json`: credential, scope, кому можно пользоваться — одна неверная строчка, и всё не работает. Теперь в Web Shell есть отдельный интерфейс управления: всё это заполняется в формах и выбирается в интерфейсе, сохранили — и заработало, без правки конфигов. Подробнее в PR [#8310](https://github.com/QwenLM/qwen-code/pull/8310)

**GitHub Channel отполировали.** Если локально выполнен вход в `gh`, GitHub Channel переиспользует эту сессию — отдельный token создавать не нужно. Поведение ответов стало собраннее: на каждое событие — не больше одного финального комментария; пока AI обрабатывает, на исходном комментарии висит временная реакция 👀, после завершения она снимается. Прерванные задачи восстанавливаются после перезапуска. Подробнее в PR [#8461](https://github.com/QwenLM/qwen-code/pull/8461), [#8033](https://github.com/QwenLM/qwen-code/pull/8033), [#8061](https://github.com/QwenLM/qwen-code/pull/8061), [#8306](https://github.com/QwenLM/qwen-code/pull/8306)

## 📊 Больше новых возможностей

**Auto Recall: автоматический поиск контекста.** Поиск по внешнему корпусу на прошлой неделе работал «по запросу AI», а Auto Recall на этой неделе — «автоматически при каждом вопросе»: результаты поиска прилагаются AI как справка, типичные конфиденциальные данные фильтруются автоматически. Взаимоисключающий с режимом поиска по запросу, разворачивается администратором. Подробнее в PR [#7877](https://github.com/QwenLM/qwen-code/pull/7877)

**Порог предзагрузки инструментов.** Новая настройка `tools.toolSearch.threshold`: когда инструментов немного, все они объявляются сразу при старте сессии — не нужно искать их по ходу, ответы быстрее; 0 возвращает прежнее поведение. Подробнее в PR [#7922](https://github.com/QwenLM/qwen-code/pull/7922)

**/autofix работает с локальным workspace.** Раньше `/autofix` запускался только в GitHub Actions, теперь при прямом запуске он проверяет и исправляет локальные изменения: находит проблему, применяет минимальное исправление, запускает проверки и повторяет, пока не станет чисто или не станет ясно, что исправить нельзя. Перед запуском он предупредит, что проверки идут в sandbox, и попросит подтвердить, что вы доверяете репозиторию. Подробнее в PR [#8121](https://github.com/QwenLM/qwen-code/pull/8121)

**Структурированный просмотр результатов review в Web Shell.** После выполнения `/review` результаты получают отдельный вид в Web Shell: сколько проблем, где они, как исправить, какие доказательства — всё видно сразу; можно фильтровать по серьёзности и открыть полный отчёт. Подробнее в PR [#8402](https://github.com/QwenLM/qwen-code/pull/8402)

**Qwen 3.8 reasoning effort работает.** Для моделей семейства qwen3.8-max пять уровней `/effort` реально управляют глубиной размышлений модели — работает не только один уровень. Подробнее в PR [#8472](https://github.com/QwenLM/qwen-code/pull/8472)

**Goal v3 подключён к CLI.** Команда `/goal` и интерактивный режим теперь работают на одном runtime — карточки статуса и команды жизненного цикла одинаковы с обеих сторон, опыт единообразный. Подробнее в PR [#8005](https://github.com/QwenLM/qwen-code/pull/8005), [#8324](https://github.com/QwenLM/qwen-code/pull/8324)

**Скрытие уровней skill.** Новая настройка `skills.disabledLevels` позволяет скрыть целый уровень skill по источнику — полезно, когда skill стало слишком много и они путают. Подробнее в PR [#8057](https://github.com/QwenLM/qwen-code/pull/8057)

**Управление жизненным циклом автосгенерированных skill.** Для skill, сгенерированных автоматически (`/learn` и другие), теперь отслеживается использование: 30 дней без использования — помечаются устаревшими, 90 дней — автоматически архивируются, больше не копятся бесконечно. Подробнее в PR [#7846](https://github.com/QwenLM/qwen-code/pull/7846)

**memory.agentMaxTurns.** Единая настройка лимита ходов memory Agent, 0 — без ограничений. Подробнее в PR [#8171](https://github.com/QwenLM/qwen-code/pull/8171)

**/summary поддерживает пользовательский путь.** В `/summary` теперь можно передать путь — сводка проекта сохранится в указанное место, родительские каталоги создаются автоматически. Подробнее в PR [#8116](https://github.com/QwenLM/qwen-code/pull/8116)

**Ёмкость и статус daemon.** Лимит сессий на workspace поднят с 20 до 32 — параллельные сессии реже упираются в потолок; `/daemon/status` показывает использование памяти и запас до лимита; лимит одновременных субсессий тоже настраивается. Подробнее в PR [#8235](https://github.com/QwenLM/qwen-code/pull/8235), [#8245](https://github.com/QwenLM/qwen-code/pull/8245), [#8341](https://github.com/QwenLM/qwen-code/pull/8341)

**Chrome-расширение alpha.** В alpha-версии Chrome-расширения появились онбординг, диагностика во время выполнения и автоматическая приёмка в реальном Chrome. Подробнее в PR [#6739](https://github.com/QwenLM/qwen-code/pull/6739)

## 👏 Улучшения опыта

**Статус можно проверять прямо во время стриминга.** Пока модель ещё отвечает, read-only команды вроде `/status`, `/settings`, `/help` выполняются сразу, не дожидаясь конца хода; в Web Shell то же самое для `/stats`, `/about`, `/context` — раньше эти команды молча проглатывались. Подробнее в PR [#8130](https://github.com/QwenLM/qwen-code/pull/8130), [#8496](https://github.com/QwenLM/qwen-code/pull/8496)

**Длинный вывод инструментов больше не обрезается.** Вывод команд и длинные размышления раньше жёстко обрезались после 500 символов — теперь они сворачиваются по умолчанию, полный текст раскрывается по клику, а в экспортированных сессиях виден целиком. Подробнее в PR [#8251](https://github.com/QwenLM/qwen-code/pull/8251)

**Ход остаётся раскрытым, пока работают фоновые Agent.** Раньше, стоило основному AI освободиться, Web Shell считал ход завершённым и сворачивал его — даже если фоновый субагент ещё работал, и через некоторое время всплывало новое обновление, статус прыгал туда-сюда. Теперь, пока есть активные субагенты, ход остаётся раскрытым. Подробнее в PR [#8413](https://github.com/QwenLM/qwen-code/pull/8413)

**Thinking-блоки больше не дёргаются, transcript стал inline.** Высота стриминговых блоков Thinking стабилизировалась — больше не скачет; полноэкранный слой записи заменён inline-переключателем по Ctrl+O. Подробнее в PR [#8077](https://github.com/QwenLM/qwen-code/pull/8077)

**Дополнения горячих клавиш.** Вставка изображения из буфера на macOS — Option+V; переключение категорий автодополнения `@` — Ctrl+Tab / Ctrl+Shift+Tab, чтобы не конфликтовать со встроенными клавишами терминала. Подробнее в PR [#8120](https://github.com/QwenLM/qwen-code/pull/8120), [#8074](https://github.com/QwenLM/qwen-code/pull/8074)

**Поиск стал быстрее и стабильнее.** Поиск по файлам стал быстрее; при сбое поиска выполняется автоматический повтор — незаконченный поиск больше не выдаётся за «ничего не найдено». Подробнее в PR [#8253](https://github.com/QwenLM/qwen-code/pull/8253), [#7888](https://github.com/QwenLM/qwen-code/pull/7888)

**Таблицы и диалоги: мелочи.** При закрытии диалога ячейки в расширенных Markdown-таблицах страница больше не дёргается; события колеса прокрутки в момент открытия диалога больше не прокручивают фон. Подробнее в PR [#8407](https://github.com/QwenLM/qwen-code/pull/8407), [#8089](https://github.com/QwenLM/qwen-code/pull/8089)

**Ctrl+Shift+C снова копирует.** Раньше Ctrl+Shift+C запускал выход или очистку экрана — теперь ему возвращена основная функция копирования в терминале. Подробнее в PR [#8011](https://github.com/QwenLM/qwen-code/pull/8011)

**Меню деталей сессии.** Меню деталей сессии больше не вылезает за границы в узкой раскладке, добавлено доступное с клавиатуры действие «скопировать полный ID сессии». Подробнее в PR [#8127](https://github.com/QwenLM/qwen-code/pull/8127)
