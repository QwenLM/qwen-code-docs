На этой неделе Qwen Code выпустил v0.19.4 — более 80 объединенных PR по трем направлениям:

**`/loop` работает, даже когда вас нет.** Простой `/loop` запускает автономный режим — agent продолжает начатую работу, пока вы отсутствуете, не придумывая новых задач и не выполняя необратимых операций. Добавьте файл задач `.qwen/loop.md`, и цикл будет перечитывать редактируемый список; удалите его — цикл перейдет в режим no-op tick, оставаясь живым. Claude Code на прошлой неделе опубликовал [руководство по агентским циклам](https://claude.com/blog/getting-started-with-loops), где описывается agent, многократно выполняющий заданный план. Автономный режим `/loop` делает то же самое, но с одним отличием: список задач можно редактировать в любой момент, и цикл автоматически отслеживает изменения.

**Голосовой ввод на десктопе.** Голосовой ввод уже работал в CLI и Web Shell, но десктопное приложение отставало. Эта версия закрывает последний пробел — теперь все три интерфейса предлагают единый опыт.

**Терминал становится удобнее.** `/settings` превратился из плоского списка во вкладочный вид — поиск, статус и статистика на одном экране; в режиме Virtualized History меню, автодополнение и поле ввода теперь поддерживают клики и наведение мыши.

## ✨ Новые функции

### Автономный режим `/loop` + файл задач loop.md

`/loop` теперь поддерживает два новых режима:

**Автономный режим**: простой `/loop` (без prompt и интервала) больше не выводит подсказку по использованию, а запускает автономный цикл с самоопределяемым шагом. Agent продолжает начатую работу, пока вы отсутствуете — поддерживает открытые PR, доделывает незавершенные задачи, выполняет обещания — но только то, что уже определено в transcript, не придумывая новых задач и не выполняя необратимых действий (push/delete/send) без явного разрешения. Замолчал — останавливается. Автономная преамбула отправляется один раз, далее каждый tick посылает короткое напоминание, сохраняя низкую стоимость токенов.

**Файл задач loop.md**: создайте `.qwen/loop.md` в корне проекта или в `~/.qwen/`, установите prompt wakeup/cron на sentinel (`<<loop.md-dynamic>>` или `<<loop.md>>`), и цикл будет перечитывать файл при каждом срабатывании. Первый раз отправляется полный текст, далее при отсутствии изменений — короткое напоминание; после редактирования файла — снова полный текст. Если файл исчезает, цикл переходит в режим no-op tick (agent ничего не делает, только re-arm для поддержания цикла), возвращаясь к базовому поведению автономного режима. После восстановления loop.md следующий tick автоматически обнаруживает изменения и снова отправляет полный текст.

**Циклы в каналах**: `/loop` не ограничивается терминалом — каналы DingTalk и Feishu тоже поддерживаются. В групповом чате используйте `/loop add "0 9 * * 1-5" проверить статус CI` для создания циклов по расписанию, `/loop list` для просмотра всех циклов текущего канала, `/loop inspect <id>` для просмотра количества запусков и последних результатов, `/loop cancel <id>` для остановки. Циклы выполняются через channel session router, дожидаясь завершения текущего активного turn, результаты записываются обратно через канал. Одноразовые циклы автоматически отключаются после успешного выполнения или ошибки.

**Что вы можете сделать с этим:**

- Простой `/loop` позволяет agent'у продолжать работу, пока вы отсутствуете
- Используйте `.qwen/loop.md` для постоянного редактируемого списка задач без повторного описания каждый tick
- Удалите loop.md — цикл перейдет в режим no-op, восстановите — seamlessly продолжит работу
- В группах DingTalk/Feishu используйте `/loop add` для циклов по расписанию

### Голосовой ввод на десктопе: единый опыт на всех платформах

Голосовой ввод уже был доступен в CLI и Web Shell, но отсутствовал в десктопном приложении — пользователи, настроившие голос, теряли эту функциональность при переключении на десктоп. Эта версия закрывает последний пробел.

На панели инструментов composer добавлена кнопка микрофона. Во время записи панель инструментов превращается в индикатор записи (пунктирная направляющая → живая форма волны → таймер), после остановки результат транскрипции вставляется в поле ввода для проверки. Транскрипция выполняется на стороне сервера, повторно используя голосовой конвейер CLI (пакетный `qwen3-asr-flash` и потоковый `*-realtime` модели), учетные данные provider не попадают в renderer. Голосовой ввод можно включить и выбрать модель в Settings → Input и в выпадающем списке моделей composer.

**Что вы можете сделать с этим:**

- Нажмите на микрофон и говорите — в реальном времени видите форму волны и таймер
- Выберите модель realtime (например, `qwen3-asr-flash-realtime`) и видите промежуточный текст по мере произнесения
- Свободные руки для ввода на планшете или при работе с несколькими мониторами

### Mobile Sidebar Drawer + улучшение `qwen serve`

Ранее при доступе к `qwen serve` с мобильного браузера боковая панель (список сессий, поиск, создание новой сессии) просто скрывалась через `display: none` при ширине менее 760px — переключить сессию было невозможно. Теперь используется overlay drawer: в заголовке чата появляется кнопка меню, по нажатию боковая панель выезжает слева с полупрозрачным затемнением. Выбор сессии, создание новой сессии или нажатие на затемнение закрывают drawer. Верстка десктопа не затрагивается.

За этим стоит серия изменений, превращающих `qwen serve` из «работающего» в «удобный»:

- **Отложенное создание сессии** ([#6066](https://github.com/QwenLM/qwen-code/pull/6066)): сессия создается только при первом prompt, снижая накладные расходы на пустые сессии — Web Shell запускается быстрее
- **workspace remember** ([#5884](https://github.com/QwenLM/qwen-code/pull/5884)): режим serve запоминает рабочую область, после перезапуска не нужно указывать заново
- **session archive** ([#6058](https://github.com/QwenLM/qwen-code/pull/6058)): daemon поддерживает архивирование сессий — долгосрочные сессии теперь можно управлять

**Что вы можете сделать с этим:**

- На мобильном браузере откройте `qwen serve` и переключайте сессии через меню
- При переключении между проектами serve автоматически запоминает рабочую область
- Долгосрочные сессии можно архивировать вместо удаления

### Клики и наведение мыши в TUI

Ранее CLI в режиме Virtualized History поддерживал только колесо мыши и полосу прокрутки, но не взаимодействие указателем. Теперь при включенном Virtualized History (`ui.useTerminalBuffer`) доступны три типа взаимодействия:

- **Меню выбора и диалоги** (подтверждение разрешений, `/model`, `/config`, темы и т.д.): наведение подсвечивает строку под указателем, клик выбирает
- **Списки автодополнения `/` команд и `@` файлов**: наведение подсвечивает элемент, клик принимает
- **Поле ввода**: левый клик позиционирует текстовый курсор (поддержка многострочного переноса, смещения прокрутки, широких символов)

**Что вы можете сделать с этим:**

- В диалоге `/model` выбирайте модель кликом мыши, не стрелками
- После ввода `/` кликайте по элементу автодополнения
- В многострочном вводе кликайте для перемещения курсора

Смотрите PR [#6011](https://github.com/QwenLM/qwen-code/pull/6011)

### Вкладочный диалог Settings: поиск, статус и статистика на одном экране

`/settings` переработан из плоского списка во вкладочный вид по образцу `/config` в Claude Code. Верхняя панель вкладок делит интерфейс на три страницы: Settings / Status / Stats. На странице Settings добавлено поле поиска — вводите текст для фильтрации.

Страница Status показывает ту же системную информацию, что и `/status`; страница Stats содержит полный дашборд `/stats` (вложенные вкладки Session / Activity / Efficiency). Фокус клавиатуры перемещается вертикально между панелью вкладок → полем поиска → списком настроек, подсветка появляется только в области, действительно имеющей фокус.

**Что вы можете сделать с этим:**

- Откройте `/settings` и сразу вводите ключевое слово для фильтрации настроек
- Переключайтесь ←/→ на вкладку Status для просмотра информации о среде выполнения без отдельного запуска `/status`
- На вкладке Stats переключайтесь Tab между Session / Activity / Efficiency; если таблица Efficiency превышает высоту диалога, она автоматически сворачивается в "+N еще"

### Расширение Chrome: диалог и управление страницей прямо из браузера

Расширение Chrome возрождено на архитектуре daemon-direct — расширение больше не является хостом Native Messaging, а выступает тонким клиентом локального daemon `qwen serve`.

Чат в боковой панели подключается напрямую к `qwen serve` через `DaemonSessionProvider` (HTTP+SSE, тот же путь, что и web shell); при недоступности daemon предлагает запустить `qwen serve`. Инструменты браузера (чтение страницы, скриншот, консоль, навигация, клик, заполнение форм) реализованы как MCP server, управляемый клиентом, и доступны agent через WebSocket daemon — оба пути (чат и инструменты) обходятся без Native Messaging.

> [!caution]
>
> Внимание: обратный канал инструментов в настоящее время включается через переменную окружения `QWEN_SERVE_CLIENT_MCP_OVER_WS` и по умолчанию выключен — необходимо явно установить этот флаг при запуске `qwen serve`.

**Что вы можете сделать с этим:**

- Общайтесь с Qwen Code в боковой панели Chrome без установки нативного хоста на уровне ОС
- Позвольте agent'у читать текущую страницу, делать скриншоты, управлять элементами браузера
- Используйте общий UI web shell — единый опыт
