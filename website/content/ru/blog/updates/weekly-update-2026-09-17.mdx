На этой неделе Qwen Code выпустил три официальных релиза — v0.23.3, v0.23.4 и v0.24.0 — и принял 267 pull-реквестов.

**Часть работы можно отдать Claude Code и Codex.** Внутри есть два дочерних агента: они работают под вашим аккаунтом и моделью, а Qwen Code раздаёт им задачи, следит за правами и собирает результаты.

**Рабочие процессы запускаются по имени.** Подходят и сохранённые, и те, что принесли расширения; добавьте в конце сообщения `+500k` — и лимит токенов на этот раунд задан.

**У Goal появились лимиты раундов и времени.** Задаёте потолок — и Goal останавливается сам, а на карточке состояния видно `3/20 turns`.

**Web Shell показывает веб-страницы.** Локальный сервис разработки видно прямо на месте, настольная и мобильная ширина переключаются как угодно; каждый переданный в диалоге HTML автоматически сохраняется отдельной версией, и через неделю открывается ровно тот вариант.

## ✨ Новые возможности

### Работу можно отдать Claude Code или Codex

Если Claude Code или Codex у вас уже установлены, часть работы передаёте им прямо из Qwen Code: скажите в диалоге «проверь этот модуль через дочернего агента claude-code» — и подзадача уйдёт Claude Code, под вашим аккаунтом и моделью. Готовые результаты и запросы на подтверждение прав остаются в одной сессии Qwen Code, перед вами по-прежнему единая лента диалога.

Оба дочерних агента по умолчанию выполняются на переднем плане. Codex по умолчанию работает только на чтение: смотрит код и даёт замечания, а чтобы менять файлы, включите в сессии auto-edit или YOLO либо явно выдайте права на запись в определении дочернего агента. С Claude Code можно переписываться несколько раз прямо во время выполнения задачи; Codex пока принимает одну задачу и возвращает один ответ. На macOS и Linux всё работает напрямую, на Windows используйте WSL.

Хотите подключить другого внешнего агента — объявите блок `executor` в файле определения дочернего агента в `.qwen/agents/` и укажите команду запуска.

Что это даёт:

- Ревью кода или переработку решения отдаёте Claude Code или Codex — под вашим аккаунтом и моделью
- Codex читает репозиторий и комментирует, а менять файлы или нет — решаете вы
- В определении дочернего агента подключаете любых внешних агентов с протоколом ACP

Подробнее: PR [#11003](https://github.com/QwenLM/qwen-code/pull/11003), [#11474](https://github.com/QwenLM/qwen-code/pull/11474)

### Рабочие процессы: запуск одной фразой, с понятным расходом токенов

На прошлой неделе рабочие процессы получили страницу управления, на этой — стало проще их запускать.

**Сохранённый рабочий процесс запускается одной фразой.** Скажите в диалоге «запусти рабочий процесс audit» или наберите `/audit` в поле ввода — и он начнёт работу.

**Лимит токенов на раунд указывается прямо в сообщении.** Добавьте в конце `+500k` — запущенный процесс получит этот лимит и сам начнёт сворачивать работу, подойдя к нему. В окне подтверждения появилось превью структуры: какой шаг вызовет дочернего агента, где ветки развернутся параллельно, а где пойдут циклы — всё видно до запуска. Если процесс окажется больше ожидаемого, на строке задачи загорится предупреждение о крупном рабочем процессе.

**Рабочие процессы можно распространять в составе расширения.** После установки расширения его процессы сразу появляются на странице управления с пометкой, из какого они расширения; ещё до установки видно, какие процессы расширение принесёт.

**Для каждого дочернего агента задаётся глубина размышления.** Настройка отдельная для каждого вызванного дочернего агента, плюс можно ограничить доступные ему инструменты. Сбору и структурированию информации ставьте глубину поменьше, решениям и ревью — побольше.

**Подтверждение прав действует только на одобренную версию.** Измените в процессе хотя бы символ — при следующем запуске права спросят заново.

Что это даёт:

- Один и тот же процесс запускаете напрямую и на этой неделе, и на следующей
- До запуска видно, сколько работы он раздаст, и заодно можно задать лимит токенов
- Процессы коллег достаются установкой расширения

### У Goal появились лимиты раундов и времени

На прошлой неделе Goal показывал, сколько токенов потрачено, на этой добавились два более ходовых лимита.

**Ограничить можно и раунды, и время.** Задайте в настройках `model.goalMaxTurns` и `model.goalMaxActiveMinutes` — и скажете «не больше 20 раундов» или «не больше 30 минут»; по умолчанию оба параметра выключены. После исчерпания лимита Goal получает ещё один раунд на завершение, чтобы внятно рассказать о результатах, и только потом останавливается. `/goal resume` открывает новое окно поверх уже израсходованной квоты и продлевает только ту норму, которая оказалась исчерпана ([#11457](https://github.com/QwenLM/qwen-code/pull/11457)).

**Остаток лимита на виду.** На карточке состояния прямо показано `3/20 turns` и `12m 3s/30m` ([#11999](https://github.com/QwenLM/qwen-code/pull/11999)). Время считает только активную работу. Токены, которые ушли на дочерних агентов на переднем плане и на проверки результата по запросу Goal, тоже записываются на счёт этого Goal ([#11998](https://github.com/QwenLM/qwen-code/pull/11998)). Когда проверяемого слишком много, проверки автоматически разбиваются на небольшие партии и доходят до конца, а зависшая партия повторяется в уменьшенном объёме ([#11365](https://github.com/QwenLM/qwen-code/pull/11365), [#11690](https://github.com/QwenLM/qwen-code/pull/11690)).

**Одобрение в Web Shell сразу запускает работу.** Одобрите предложение Goal — и Goal начнёт работать автоматически, как только этот раунд ответа штатно завершится ([#11360](https://github.com/QwenLM/qwen-code/pull/11360)).

Что это даёт:

- Поручаете Goal разбор проблемы, заранее задаёте лимиты, а после их исчерпания продолжаете
- Один взгляд на карточку состояния — сколько раундов и времени осталось
- Одобрили предложение в Web Shell — Goal стартует сам

### Channel: бот сам выбирает, как докладывать, и его ответы стало легко разбирать

Три изменения в боте Channel на этой неделе: можно выбрать формат уведомлений о фоновых задачах, убрали фильтр по префиксу сообщения, сессии Channel теперь видны как есть.

**Выбор формата уведомлений о фоновых задачах.** Настраивается в параметрах Channel, первым поддерживает DingTalk. По умолчанию сначала приходит основной результат, а после завершения фоновой задачи — отдельное уведомление. Можно слать каждый полный ответ либо дождаться, пока вся связанная фоновая работа закончится, и прислать только итог — так в чате спокойно, видно лишь последнее сообщение.

**Фильтр по префиксу убран.** Раньше можно было задать обязательное начало сообщения: без префикса бот на реплику не реагировал. Эта настройка удалена — теперь любое сообщение, пропущенное правилами по отправителю, группе и упоминанию, сразу вызывает бота.

**Сессия Channel открывается как есть.** Перезагрузите сессию Channel в CLI или Web Shell — каждый раунд покажет ровно то, что на самом деле дошло до модели: постоянные инструкции, историю группы, кто автор реплики. Так на вопрос «почему бот ответил именно так» находится ответ за один шаг.

Что это даёт:

- Долгие задачи докладывают по завершении — без потока сообщений в чате
- Не нужно начинать сообщение с обязательного слова: упомяните бота или напишите лично
- Если ответ странный, в CLI или Web Shell видно всё, что бот получил в тот момент

Подробнее: PR [#11822](https://github.com/QwenLM/qwen-code/pull/11822), [#11571](https://github.com/QwenLM/qwen-code/pull/11571), [#11646](https://github.com/QwenLM/qwen-code/pull/11646)

### Web Shell: сразу несколько обновлений

**Предпросмотр по адресу разработки, HTML сохраняется сам.** Справа в Web Shell появилась панель предпросмотра веб-страниц: введите локальный адрес разработки — и страница видна, ширину можно переключать между настольной и мобильной. Каждый переданный в диалоге HTML сохраняется отдельной версией: через неделю откроется ровно тот вариант, и несколько версий можно сравнивать между собой ([#11276](https://github.com/QwenLM/qwen-code/pull/11276)).

**Сообщение можно исправить и отправить снова, прерванная сессия продолжается на месте.** Последнее своё сообщение редактируется прямо в диалоге, ответ на этом раунде генерируется заново, а перенесённые изображения и файлы остаются без изменений ([#11650](https://github.com/QwenLM/qwen-code/pull/11650)). Диалог, оборвавшийся на середине, при повторном открытии предлагает продолжить выполнение — работа идёт дальше ровно с того же места ([#11545](https://github.com/QwenLM/qwen-code/pull/11545)).

**Уведомления браузера понимают, к какой сессии относятся.** Уведомления, добавленные на прошлой неделе, теперь указывают сессию и содержат фрагменты вопроса и ответа, а клик по уведомлению приводит прямо в нужный диалог ([#11447](https://github.com/QwenLM/qwen-code/pull/11447)). На встроенной странице они включены по умолчанию — достаточно один раз разрешить уведомления в браузере.

**Расход контекста виден точно, сжатие — в одно нажатие.** Панель контекста показывает точное занятое количество, общий объём, остаток и доли по категориям, и кнопка сжатия размещена прямо там; она есть и в карточке при наведении у поля ввода — сжатие запускается по клику ([#11700](https://github.com/QwenLM/qwen-code/pull/11700), [#11782](https://github.com/QwenLM/qwen-code/pull/11782)).

**Прочие улучшения.** Страница обзора сессий разбита по состояниям и умеет искать по ветке и номеру PR ([#11238](https://github.com/QwenLM/qwen-code/pull/11238)); загруженные файлы, файлы проекта и веб-ссылки собраны в один список Sources ([#11262](https://github.com/QwenLM/qwen-code/pull/11262)); для задачи по расписанию теперь выбираются модель и группа ([#11396](https://github.com/QwenLM/qwen-code/pull/11396)); по адресу можно подключиться к Qwen Code на другой машине ([#11548](https://github.com/QwenLM/qwen-code/pull/11548)).

## 📊 Прочие новинки

**У веб-поиска есть лимит вызовов на раунд.** По умолчанию не больше 200 вызовов `web_search` на сессию, настраивается через `tools.webSearch.maxPerSession`. После исчерпания AI продолжает работу с уже собранной информацией и сообщает, что лимит можно попросить увеличить. Подробнее: PR [#11852](https://github.com/QwenLM/qwen-code/pull/11852), [#11692](https://github.com/QwenLM/qwen-code/pull/11692)

**Межсессионные сообщения включены по умолчанию.** Несколько сессий Qwen Code на одной машине теперь видят друг друга, `/peers` перечисляет активные сессии, а между ними AI может пересылать сообщения о ходе работы. Не нужно — выставьте `agents.crossSessionMessaging` в `false`. Подробнее: PR [#11840](https://github.com/QwenLM/qwen-code/pull/11840)

**Моделей с настраиваемой интенсивностью размышления стало больше.** Moonshot K3 поддерживает три ступени — low, high и max, K2.6 — встроенный переключатель размышления, Qwen 3.8 — low, medium и xhigh, DeepSeek V4 Pro и Flash — low, high и max; новые модели добавлены и в процесс настройки Standard API Key, а в Token Plan появились Qwen 3.8 Flash и DeepSeek V4 Pro-0813. Подробнее: PR [#11349](https://github.com/QwenLM/qwen-code/pull/11349)

**История сессий VS Code объединена с остальной.** Диалоги, созданные в терминале, браузере и VS Code, оказываются в одном списке истории и открываются прямо оттуда. Подробнее: PR [#11713](https://github.com/QwenLM/qwen-code/pull/11713)

**Хуки теперь просматриваются прямо в терминале.** `/hooks` из одной строки состояния вырос в поуровневый просмотр событий, правил совпадения и деталей каждого хука; недавно изменённые настройки перечитываются при открытии, а при общем отключении показывается причина; во время выполнения хук тоже сообщает о прогрессе. Подробнее: PR [#11903](https://github.com/QwenLM/qwen-code/pull/11903), [#11904](https://github.com/QwenLM/qwen-code/pull/11904), [#11906](https://github.com/QwenLM/qwen-code/pull/11906)

**Появилось подключение моделей по протоколу OpenAI Responses.** В списке типов провайдеров добавлен `openai-responses` — работа через интерфейс OpenAI `/v1/responses` с поддержкой потоковой выдачи, вызовов инструментов и сводок размышлений. Подробнее: PR [#8169](https://github.com/QwenLM/qwen-code/pull/8169)

**Для Linux добавили ещё одну песочницу на уровне ядра.** После выбора бэкенда bwrap в настройках запись разрешена только в рабочую область, временные каталоги и необходимые кэши, остальная файловая система — только на чтение. Ни контейнерных инструментов, ни root не требуется; отдельная подкоманда показывает текущие границы и выполняет самотестирование. Подробнее: PR [#11614](https://github.com/QwenLM/qwen-code/pull/11614)

**Один фоновый сервис обслуживает больше рабочих областей.** `qwen serve` по умолчанию принимает с 25 до 256 рабочих областей; меняется через `QWEN_SERVE_MAX_WORKSPACES`. Подробнее: PR [#11515](https://github.com/QwenLM/qwen-code/pull/11515)

## 👏 Улучшения UX

**Большие сессии открываются заметно быстрее.** Ускорились повторное открытие старых длинных диалогов и раскрытие панелей Web Shell. Подробнее: PR [#11595](https://github.com/QwenLM/qwen-code/pull/11595), [#11644](https://github.com/QwenLM/qwen-code/pull/11644)

**Ссылки в ваших сообщениях кликабельны.** Адреса в ваших собственных репликах Web Shell теперь оформляются как кликабельные ссылки. Подробнее: PR [#11464](https://github.com/QwenLM/qwen-code/pull/11464)

**Во время чтения интерфейс не дёргается.** Панель подтверждения прав не меняет размеры, пока вы читаете; сводка раунда появляется ровно один раз — в конце вывода. Подробнее: PR [#11930](https://github.com/QwenLM/qwen-code/pull/11930), [#11986](https://github.com/QwenLM/qwen-code/pull/11986)

**Источники ответа листаются.** Сноски в ответе сгруппированы по источникам, при наведении раскрывается многостраничное превью; под каждым раундом перечислены все использованные источники, включая вложения без сносок. Подробнее: PR [#11480](https://github.com/QwenLM/qwen-code/pull/11480)

**Заданные вопросы остаются в диалоге.** После подведения итогов в конце раунда ваши вопросы и ответы продолжают отображаться в ленте, их можно перечитать. Подробнее: PR [#11461](https://github.com/QwenLM/qwen-code/pull/11461)

**Навигация по раундам следует за чтением.** Шкала раундов справа в Web Shell подсвечивает позицию чтения: до какого раунда дочитали, тот и подсвечен. Подробнее: PR [#11801](https://github.com/QwenLM/qwen-code/pull/11801)

**Новые модели — в начале списка.** В настройках провайдера вновь обнаруженные модели встают в начало списка, чтобы их было легко найти. Подробнее: PR [#11449](https://github.com/QwenLM/qwen-code/pull/11449)

**Отдельная страница Web Shell тоже учитывает настройки.** Тема и язык работают и на отдельной странице Web Shell. Подробнее: PR [#11961](https://github.com/QwenLM/qwen-code/pull/11961)
