Qwen Code publie cette semaine trois versions stables — v0.21.15, v0.22.0, v0.22.2 — avec plus de 300 PR fusionnées.

**Le Goal sait passer la main.** Le mode autonome du Goal dispose d'un budget token : une fois atteint, il rédige un bilan d'étape puis s'arrête ; s'il estime que l'objectif est hors d'atteinte, il s'interrompt de lui-même.

**Un bouton Thinking pour les modèles Qwen.** Les modèles à réflexion mixte comme qwen3.5-plus ont maintenant un interrupteur Thinking simple : désactivé, la réponse actuelle saute l'étape de réflexion ; réactivé, le modèle retrouve son comportement par défaut.

**Des commandes « / » qui ne font pas la queue.** Pendant que l'IA est en train d'écrire, 10 commandes comme `/theme`, `/tools` et d'autres s'exécutent immédiatement, sans attendre la fin du tour.

## ✨ Nouvelles fonctionnalités

### Goal : un budget token et un bilan avant de s'arrêter

Le mode autonome du Goal gagne cette semaine plusieurs formes de « conscience de soi » : il sait ce qu'il a dépensé, quand s'arrêter, et fait un bilan clair avant de se couper.

**La dépense est tracée.** Chaque Goal cumule désormais son coût en token dans un compteur dédié, visible dans `get_goal` à côté du nombre de tours.

**Un budget pour le mode autonome.** Tout nouveau Goal reçoit un budget token par défaut. Une fois ce budget consommé, le Goal se met en pause. Pour le relancer, il suffit de le restaurer ou de le modifier — un nouveau quota est automatiquement alloué.

**Un tour de bilan avant la pause.** Quand le budget est atteint, un « tour de bilan » est accordé : pas de nouveau travail, uniquement un résumé de ce qui a été accompli, ce qui reste à faire, et la prochaine étape. Ainsi, quelqu'un qui reprend la main peut continuer directement.

**Il s'arrête quand il est bloqué.** Trois échecs consécutifs au point de contrôle entraînent un arrêt automatique ; si des preuves indiquent que l'objectif est intrinsèquement irréaliste, le Goal s'interrompt dès le tour en cours.

**`/goal-draft` transforme une idée vague en Goal exécutable.** Il commence par poser quelques questions pour clarifier l'idée vague, puis rédige un Goal vérifiable et fournit une commande `/goal set` prête à exécuter. Il ne fait que rédiger, sans exécuter le travail ; à vous de décider de l'utiliser ou non.

Voir les PR [#9583](https://github.com/QwenLM/qwen-code/pull/9583), [#9891](https://github.com/QwenLM/qwen-code/pull/9891), [#10132](https://github.com/QwenLM/qwen-code/pull/10132), [#9975](https://github.com/QwenLM/qwen-code/pull/9975), [#10125](https://github.com/QwenLM/qwen-code/pull/10125), [#10002](https://github.com/QwenLM/qwen-code/pull/10002)

### Les modèles Qwen ont un bouton Thinking

Dans le web shell, les modèles qwen3.5-plus, qwen3.6-plus, qwen3.6-flash, qwen3.7-plus et qwen3.7-max disposent désormais d'un interrupteur Thinking : désactivé, le modèle répond sans réfléchir ; activé, il réfléchit avant de répondre.

qwen3.8-max conserve ses trois niveaux d'intensité de réflexion : low / medium / extra high.

Voir le PR [#9574](https://github.com/QwenLM/qwen-code/pull/9574)

![L'interrupteur Thinking dans le panneau de sélection du modèle](https://img.alicdn.com/imgextra/i4/O1CN01BtvdvUAuKfH7nOLI_!!6000000007210-2-tps-3840-2160.png)

### Les workflows ont un interrupteur officiel et une approbation avant exécution

Le workflow permet de décomposer une grosse tâche et de la distribuer à plusieurs assistants IA en parallèle. Trois garde-fous ont été ajoutés cette semaine :

- **Interrupteur officiel** : activez `tools.workflowsEnabled` dans les paramètres pour y avoir accès ; ce paramètre est strictement personnel et ne peut pas être modifié par la configuration du projet
- **Approbation avant exécution** : avant de lancer quoi que ce soit, la boîte de dialogue vous montre en entier le script de workflow que l'IA vient d'écrire — ce qu'elle recherche, comment elle répartit le travail, comment elle assemble les résultats. Vous lisez, vous confirmez, et seulement alors il s'exécute
- **Lancement sur demande explicite** : le workflow ne se déclenche que quand vous le demandez clairement, par exemple en disant « utilise un workflow », en nommant un workflow précis, ou en lui demandant de reprendre là où il s'était arrêté ; si l'IA estime qu'un workflow serait utile mais que vous n'en avez pas parlé, elle vous propose d'abord son plan de répartition et le nombre d'assistants, en attendant votre feu vert

Voir les PR [#9098](https://github.com/QwenLM/qwen-code/pull/9098), [#9837](https://github.com/QwenLM/qwen-code/pull/9837), [#9806](https://github.com/QwenLM/qwen-code/pull/9806)

### Les PR GitHub sont rattachées à la session qui les a créées

Après avoir créé une PR depuis le Web Shell, retrouver « quelle session l'a créée » demandait auparavant de fouiller dans l'historique. Désormais, toute PR créée depuis le panneau Git du Web Shell est enregistrée sous la session qui l'a initiée : un badge PR apparaît à côté du nom de la session dans la barre latérale, et une recherche par numéro de PR retrouve la session correspondante. Une session peut enregistrer jusqu'à 10 PR ; si la même PR est repoussée, l'enregistrement est actualisé.

Voir le PR [#9543](https://github.com/QwenLM/qwen-code/pull/9543)

![Badge PR dans la barre latérale et recherche par numéro](https://img.alicdn.com/imgextra/i3/O1CN01J2dzfeTpIxI2b88O_!!6000000004996-2-tps-1280-800.png)

### Des commandes « / » qui s'exécutent même pendant que l'IA écrit

Jusqu'ici, utiliser une commande slash pendant que l'IA était en train de répondre signifiait attendre la fin du tour pour la plupart d'entre elles. Cette semaine, 10 commandes rejoignent la liste des « sans attente » : `/theme`, `/editor`, `/vim`, `/voice`, `/terminal-setup` pour les paramètres d'interface, ainsi que `/tools`, `/tasks`, `/hooks`, `/docs`, `/bug` en lecture seule — l'IA continue d'écrire, vous utilisez vos commandes, le résultat apparaît immédiatement.

Voir le PR [#9495](https://github.com/QwenLM/qwen-code/pull/9495)

![Plus de commandes slash sans attente](https://img.alicdn.com/imgextra/i1/O1CN01wGzoSzEuAJK7nOLI_!!6000000003046-2-tps-3840-2160.png)

## 📊 Autres nouvelles fonctionnalités

**qwen3.8-max passe en version stable.** qwen3.8-max quitte le statut de preview et devient une version stable ; les utilisateurs Token Plan le trouvent directement dans `/model`. Voir le PR [#9383](https://github.com/QwenLM/qwen-code/pull/9383)

**Ajouter des fichiers en plein milieu d'une conversation.** La semaine dernière, on pouvait glisser des fichiers dans la zone de saisie du Web Shell ; cette semaine, on peut aussi en ajouter en cours de conversation : les fichiers joints depuis la zone de saisie et les fichiers du workspace référencés par @ sont tous deux pris en charge, et l'IA les reçoit en temps réel. Le point d'upload est unifié : deux options au choix, référencer un fichier du workspace ou uploader directement, et les fichiers uploadés sont conservés de manière persistante. Voir les PR [#9570](https://github.com/QwenLM/qwen-code/pull/9570), [#9477](https://github.com/QwenLM/qwen-code/pull/9477)

**Un même modèle pour la conversation et la génération d'images.** Un modèle peut désormais assumer simultanément la conversation et la génération d'images intégrée, sans avoir besoin d'un modèle séparé pour les images ; la génération d'images prend aussi en charge l'API de MiniMax. Voir les PR [#9650](https://github.com/QwenLM/qwen-code/pull/9650), [#8322](https://github.com/QwenLM/qwen-code/pull/8322)

**Gérer les Goals directement depuis le Web Shell.** Les Goals ne se mélangent plus aux messages de la conversation : le Web Shell leur réserve une ligne dédiée et compacte dans la zone de gestion. Voir le PR [#9393](https://github.com/QwenLM/qwen-code/pull/9393)

**Les tâches planifiées peuvent s'exécuter dans une session existante.** Lors de la création d'une tâche planifiée, vous pouvez choisir de l'exécuter dans la session en cours. Voir les PR [#9838](https://github.com/QwenLM/qwen-code/pull/9838), [#9361](https://github.com/QwenLM/qwen-code/pull/9361)

**Le code desktop migre vers OpenWork.** Le code de l'app desktop Electron est déplacé vers le projet open source indépendant [OpenWork](https://github.com/modelstudioai/openwork) pour y être développé en continu ; le repo Qwen Code conserve un pont de migration vers la nouvelle version desktop. Voir le PR [#9085](https://github.com/QwenLM/qwen-code/pull/9085)

**Computer Use passe au pilotage par compétences.** L'IA qui opère sur l'ordinateur fonctionne désormais avec des compétences intégrées : au premier usage, les dépendances s'installent automatiquement, un redémarrage unique est demandé, puis tout fonctionne normalement ; le Node REPL passe d'un outil intégré à un package MCP indépendant `@qwen-code/node-repl-mcp`, désactivé par défaut — il faut le configurer dans `mcpServers` pour qu'il soit actif. Voir les PR [#9856](https://github.com/QwenLM/qwen-code/pull/9856), [#9587](https://github.com/QwenLM/qwen-code/pull/9587), [#9499](https://github.com/QwenLM/qwen-code/pull/9499)

**Kimi devient un fournisseur intégré.** Dans `/auth`, sélectionnez Kimi comme fournisseur tiers, renseignez votre clé API et c'est branché — les points d'accès internationaux ou chinois sont au choix ; la liste de modèles inclut déjà le flagship K3, K2.6 et deux modèles spécialisés code, et cette liste est elle aussi éditable. K3 réfléchit en permanence, les trois autres peuvent activer ou désactiver la réflexion librement. Voir le PR [#9814](https://github.com/QwenLM/qwen-code/pull/9814)

## 👏 Améliorations de l'expérience

**Un panneau de consommation token dans le Web Shell.** Le Web Shell peut désormais afficher un panneau détaillé de l'utilisation des tokens au niveau de la session : consommation totale, répartition par modèle, appels de sous-agents, statistiques d'usage des outils — tout sur une seule page. Voir le PR [#9988](https://github.com/QwenLM/qwen-code/pull/9988)

**Le mode compact devient le seul mode du Web Shell.** Les blocs de réflexion et l'activité des outils sont repliés dans une ligne résumé par défaut ; le raccourci Ctrl+O est supprimé, et le rendu compact est unifié pour la conversation principale, le panneau partagé et les détails des sous-agents. Voir les PR [#9993](https://github.com/QwenLM/qwen-code/pull/9993), [#9657](https://github.com/QwenLM/qwen-code/pull/9657)

**Les cartes d'approbation s'intègrent dans le fil de messages.** Les demandes d'approbation d'outils et les questions ne recouvrent plus toute la liste de messages : elles apparaissent désormais sous forme de carte ancrée en bas du fil de messages, alignée sur la largeur de la zone de chat. Voir le PR [#9351](https://github.com/QwenLM/qwen-code/pull/9351)

**Un shell en arrière-plan maintient le tour ouvert.** Quand un tour lance un shell en arrière-plan, ce tour reste déplié jusqu'à la fin de l'exécution, ce qui permet de suivre l'avancement sans que le panneau ne se replie prématurément. Voir le PR [#9632](https://github.com/QwenLM/qwen-code/pull/9632)

**Le plugin VS Code adopte le même rendu.** La timeline de conversation du plugin VS Code utilise désormais le même moteur de rendu que le Web Shell, alignant l'expérience des deux interfaces. Voir le PR [#9719](https://github.com/QwenLM/qwen-code/pull/9719)

**Le terminal grande fenêtre scroll plus fluidement.** Le virtual scrolling du terminal passe de 30 à 60 images par seconde, rendant la navigation dans l'historique nettement plus fluide sur les grandes fenêtres. Voir le PR [#9681](https://github.com/QwenLM/qwen-code/pull/9681)

**On peut voir quels fichiers de contexte ont été chargés.** Quand des fichiers de contexte personnalisés sont ajoutés via les paramètres, le premier message de la conversation affiche désormais la liste des fichiers chargés — auparavant, cette étape était totalement invisible. Voir le PR [#8855](https://github.com/QwenLM/qwen-code/pull/8855)

**La session se souvient du dernier modèle sélectionné.** Après un redémarrage ou une reconnexion du daemon, la session retrouve le modèle que vous aviez choisi pour elle ; les nouvelles sessions utilisent toujours le modèle par défaut des paramètres. Voir le PR [#9687](https://github.com/QwenLM/qwen-code/pull/9687)

**Le channel DingTalk comprend les citations.** Auparavant, citer une image ou un fichier dans DingTalk ne transmettait à l'IA qu'un espace réservé ; désormais, les images, fichiers, audio et vidéo cités sont réellement téléchargés et transmis à l'IA, et les messages transférés depuis un historique de conversation sont analysés pour en extraire le titre et le résumé. Voir les PR [#9347](https://github.com/QwenLM/qwen-code/pull/9347), [#9339](https://github.com/QwenLM/qwen-code/pull/9339)

**Les extensions depuis des repos privés peuvent s'installer.** L'installation d'extensions via Git HTTPS prend maintenant en charge l'authentification, y compris pour le clonage depuis un repo privé, avec une option pour conserver ou non les identifiants de manière persistante. Voir le PR [#9458](https://github.com/QwenLM/qwen-code/pull/9458)

**Les anciennes versions de Git peuvent aussi installer des extensions publiques.** Pour les systèmes avec une version de Git antérieure à 2.37, l'installation d'extensions GitHub publiques passe par le téléchargement d'archive. Voir les PR [#9680](https://github.com/QwenLM/qwen-code/pull/9680), [#9690](https://github.com/QwenLM/qwen-code/pull/9690)

**Une commande ouvre un Web Shell avec verrouillage.** `qwen serve --open-with-auth` lance un Web Shell local protégé par un token d'authentification ; si aucun token n'est configuré, un est généré automatiquement et transmis au navigateur. Voir le PR [#9738](https://github.com/QwenLM/qwen-code/pull/9738)

**Homebrew ne signale plus de fausses mises à jour.** Quand les métadonnées locales confirment qu'aucune nouvelle version n'est disponible, la notification de mise à jour n'apparaît plus. Voir le PR [#9502](https://github.com/QwenLM/qwen-code/pull/9502)
