Cette semaine, Qwen Code sort trois versions stables — de v0.21.12 à v0.21.14 — avec plus de 140 PR fusionnés.

**Un deuxième avis indépendant.** `/advisor` fait une revue indépendante de la conversation en cours et rend quatre points : conclusion, risques, preuves manquantes, recommandations. Strictement en lecture seule — la conversation principale n'est pas touchée.

**Une commande pour voir les sessions qui tournent.** La nouvelle commande `qwen sessions ps` liste les sessions actives sur la machine : dans quel répertoire, depuis combien de temps, avec quel PID.

**Une revue interrompue ne repart plus de zéro.** Une revue de PR interrompue reprend avec `--resume` : si l'état sur le disque correspond, elle continue là où elle s'était arrêtée.

## ✨ Nouvelles fonctionnalités

### /advisor : un modèle indépendant passe la conversation en revue

Quand une conversation s'étire, on finit enfermé dans une seule ligne de raisonnement, et les angles morts de son propre contexte sont difficiles à voir. `/advisor` apporte un deuxième avis indépendant sur la conversation en cours : une session parallèle en lecture seule relit tout le contexte et rend quatre points — conclusion, risques, preuves manquantes, recommandations. Ce deuxième avis est strictement en lecture seule : il ne modifie pas la conversation principale, n'exécute aucune action, et la suite de la conversation n'est pas affectée.

Vous pouvez poser une question ciblée, par exemple `/advisor ce plan est-il sûr` ; le réglage `advisorModel` permet de désigner un modèle dédié à la revue — par défaut, c'est le modèle en cours qui est utilisé.

Voir le PR [#7567](https://github.com/QwenLM/qwen-code/pull/7567)

![La revue en quatre points renvoyée par /advisor](https://img.alicdn.com/imgextra/i4/O1CN01x6UkJeTG4kD7nOLI_!!6000000004249-2-tps-3840-2160.png)

### qwen sessions ps : une commande pour voir les sessions qui tournent

Plusieurs sessions Qwen Code ouvertes en même temps, et on perd vite le fil. La nouvelle commande `qwen sessions ps` liste toutes les sessions interactives en cours sur la machine, une par ligne : nom de session, PID, durée d'exécution, répertoire. Pour l'intégrer dans un script, ajoutez `--json` pour une sortie JSON.

La liste ne montre que ce qui tourne réellement : fermez une session, elle disparaît aussitôt de la liste.

Voir le PR [#8969](https://github.com/QwenLM/qwen-code/pull/8969)

![qwen sessions ps liste les sessions qui tournent](https://img.alicdn.com/imgextra/i1/O1CN01edM2ef0oKxI7nOLI_!!6000000005536-2-tps-3840-2160.png)

### Review : la revue de PR interrompue reprend, les commentaires parlent clairement

`/review` reçoit plusieurs améliorations pratiques cette semaine.

**Une revue interrompue reprend où elle s'était arrêtée.** Pour la revue d'une grosse PR, une interruption obligeait avant à tout recommencer. `qwen review fetch-pr` gagne maintenant `--resume` : la commande vérifie d'abord l'état sur le disque — le rapport de revue précédent, le worktree, le contenu du diff n'ont pas changé, et la PR n'a pas été mise à jour — si tout correspond, elle reprend où elle en était ; si un seul élément diffère, elle repart de zéro automatiquement.

**Les commentaires de revue en langage clair.** Quand `/review` analyse une PR et publie des commentaires, ceux-ci sonnaient avant très « template » ; ils sont désormais rédigés dans un langage naturel de revue : où est le problème, quand il se manifeste, comment le corriger. Pour les commentaires publiés sur la PR, tout se règle dans les paramètres : avec ou sans marque de sévérité et signature, profondeur d'analyse, publication ou non.

**La revue des scripts tient compte de leur environnement d'exécution.** Pour les scripts shell et les configurations CI, le problème « ça marche sur cette machine, ça casse ailleurs » est difficile à repérer. La revue commence par identifier les environnements où ces fichiers s'exécutent réellement, puis vérifie en fonction de leurs particularités.

Voir les PR [#9092](https://github.com/QwenLM/qwen-code/pull/9092), [#9027](https://github.com/QwenLM/qwen-code/pull/9027), [#8994](https://github.com/QwenLM/qwen-code/pull/8994), [#9263](https://github.com/QwenLM/qwen-code/pull/9263)

### Web Shell : glissez vos fichiers locaux directement dans la conversation

Une fois le jeton de connexion à distance configuré (`QWEN_SERVER_TOKEN` ou `--token`), glissez un fichier dans la zone de saisie du Web Shell ou collez-le : il est transmis à Qwen Code. Tout fichier atterrit dans son workspace, avec une référence ajoutée automatiquement dans la conversation — l'IA peut l'utiliser immédiatement. Les fichiers texte peuvent aussi être joints en ligne dans la conversation : l'IA les lit sur place, sans avoir à les ouvrir.

Vous pouvez aussi choisir le dossier de destination ; s'il n'existe pas, il est créé automatiquement. Sans jeton configuré, le glisser-déposer ou le collage de fichiers dans la conversation n'est pas encore pris en charge.

Voir les PR [#8874](https://github.com/QwenLM/qwen-code/pull/8874), [#9180](https://github.com/QwenLM/qwen-code/pull/9180), [#9382](https://github.com/QwenLM/qwen-code/pull/9382)

## 📊 Autres nouvelles fonctionnalités

**L'agent de workflow s'ancre dans un répertoire précis.** Dans un workflow, `agent({workingDir})` fixe un agent dans le répertoire de votre choix, sans rester limité à la portée du répertoire par défaut. Voir le PR [#8972](https://github.com/QwenLM/qwen-code/pull/8972)

**Les notes de version gagnent des résumés bilingues.** Les notes de version ne sont plus un simple empilement de PR : regroupées par thème fonctionnel, chaque groupe reçoit un résumé en langage clair, en deux langues, et les captures avant/après incluses dans les PR sont reprises elles aussi. Voir le PR [#9216](https://github.com/QwenLM/qwen-code/pull/9216)

**Une spécification unique pour brancher des bases de connaissances externes.** Les éditeurs de services de recherche peuvent développer des plugins Qwen Code conformes à la spécification : une fois branchés, l'IA peut interroger leurs corpus. Ce qui est interrogeable dépend des plugins que vous installez — l'IA ne cherche que dans ce périmètre. Voir le PR [#9068](https://github.com/QwenLM/qwen-code/pull/9068)

## 👏 Améliorations de l'expérience

**La gestion des Channels refaite en page complète.** La gestion des Channels du Web Shell adopte la même mise en page pleine page que les tâches planifiées : qui peut utiliser chaque canal, approbation ou liste blanche, découpage des sessions, rattachement à un workspace — tout se règle sur une seule page. Voir le PR [#8848](https://github.com/QwenLM/qwen-code/pull/8848)

**L'indicateur « en train d'écrire » de WeChat ne lâche plus les longues tâches.** Sur WeChat, l'état « en train d'écrire » expire ; avant, pendant une longue tâche, l'indicateur disparaissait en cours de route, comme une connexion coupée. Il est désormais rafraîchi toutes les 4 secondes pendant l'exécution et ne se retire qu'une fois la tâche terminée. Voir le PR [#9358](https://github.com/QwenLM/qwen-code/pull/9358)

**Le mode compact laisse voir la réflexion de l'IA.** Le mode compact du Web Shell (Ctrl+O) masquait complètement le contenu de réflexion. Désormais, pendant que le modèle réfléchit, un résumé affiche « en train de réfléchir » ; une fois terminé, la réflexion se replie dans le résumé de l'outil, dépliable d'un clic. Voir le PR [#9148](https://github.com/QwenLM/qwen-code/pull/9148)

**Changer de session même avec la barre latérale repliée.** Une fois la barre latérale du Web Shell repliée, survoler l'icône du projet ouvre le navigateur de sessions complet ; les états en attente d'approbation, de question ou de validation sont signalés par couleur sur l'icône. Voir le PR [#9311](https://github.com/QwenLM/qwen-code/pull/9311)

**Les prévisualisations d'images survivent au rafraîchissement.** Dans le Web Shell, les images envoyées gardent leur prévisualisation après un rafraîchissement de la page — qu'elles soient en file d'attente ou déjà injectées dans une tâche en cours ; plusieurs images ne sont ni fusionnées ni perdues. Voir le PR [#9310](https://github.com/QwenLM/qwen-code/pull/9310)

**Envoyer une question même en cas de déconnexion.** La zone de saisie du Web Shell est découplée de l'état de la connexion : même si le flux est coupé, vous pouvez envoyer votre question ; la zone de saisie n'est plus verrouillée. Voir le PR [#9323](https://github.com/QwenLM/qwen-code/pull/9323)

**La page HTML exportée se déplie et se replie en un clic.** La page HTML exportée par `/export` gagne deux boutons en haut : « Tout déplier / Tout replier », pour basculer d'un coup les blocs de réflexion et les sorties d'outils. Voir le PR [#9367](https://github.com/QwenLM/qwen-code/pull/9367)

**Les grosses sessions se restaurent plus vite.** La restauration de session par le daemon lit désormais à la demande : seuls les enregistrements nécessaires à la reconstruction de l'état sont chargés — le gain est net sur les grosses sessions. Voir le PR [#9055](https://github.com/QwenLM/qwen-code/pull/9055)

**Les shells en arrière-plan ne sont plus nettoyés par erreur.** Les shells en arrière-plan comptent désormais comme tâches actives : un shell en activité n'est plus nettoyé automatiquement. Voir le PR [#9042](https://github.com/QwenLM/qwen-code/pull/9042)
