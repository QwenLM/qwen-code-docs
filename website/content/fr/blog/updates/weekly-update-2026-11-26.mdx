Qwen Code publie cette semaine trois versions stables : v0.28.3, v0.28.4 et v0.28.6.

**Déléguez du travail à une autre session.** Dans le Web Shell, `/send` confie une tâche à une autre session : elle prend le relais, travaille, puis vous rapporte le résultat.

**Les résultats des tâches planifiées partent vers l'adresse de votre choix.** Ajoutez une connexion Generic Webhook dans la gestion des canaux et renseignez une adresse de réception : la tâche planifiée terminée, son résultat y part automatiquement.

**Les fichiers générés se consultent sur une seule page.** Rapports et fichiers exportés de toutes les sessions se rassemblent sur la page Artifacts, à prévisualiser et télécharger directement.

## ✨ Nouvelles fonctionnalités

### Confiez une tâche à une autre session avec /send

Vous déléguez vous-même du travail à une autre session. Tapez `/send vérifie le test qui vient d'échouer` dans le Web Shell : une nouvelle session du même workspace prend le relais. `--workspace` choisit le workspace, `--session-id` vise une session existante. La tâche terminée, la session courante vous rapporte le résultat.

L'IA délègue aussi elle-même : elle confie du travail à vos sessions ouvertes à la main autant qu'aux siennes. En mode YOLO, la délégation vers un autre dossier de projet part sans demande de confirmation.

Ce que vous pouvez en faire :

- La session A rassemble la documentation, la session B reçoit le relais et rédige la solution
- Vous codez dans la session principale, le diagnostic des tests part dans une autre session
- Suivez la progression dans le panneau de droite et traitez directement les demandes de confirmation et les questions de l'autre session

Voir les PR [#17539](https://github.com/QwenLM/qwen-code/pull/17539), [#17818](https://github.com/QwenLM/qwen-code/pull/17818)

### Canaux : les résultats des tâches planifiées partent vers l'adresse de votre choix, une session qui dérive se corrige en cours de route

**Les résultats des tâches planifiées partent vers l'adresse de votre choix.** Les groupes Feishu, WeCom et DingTalk reçoivent déjà les résultats ; le Generic Webhook ajoute une connexion compatible avec toutes les plateformes : renseignez une adresse de réception HTTPS dans la gestion des canaux, et les notifications comme les résultats des tâches planifiées y partent. Voir cette PR [#17405](https://github.com/QwenLM/qwen-code/pull/17405)

**Un message de canal corrige la trajectoire en cours de tâche.** Le mode de livraison inject est réservé aux canaux autonomes lancés depuis le terminal : les messages reçus pendant que l'IA travaille entrent directement dans le tour en cours, elle les lit et ajuste sa direction. Une tâche part mal : une phrase suffit pour la remettre sur les rails. Voir cette PR [#15634](https://github.com/QwenLM/qwen-code/pull/15634)

**Le bot QQ envoie des fichiers dans la conversation.** Réglez `fileTools` sur `true` dans la configuration du canal QQ (désactivé par défaut) et redémarrez le canal : l'IA envoie directement dans le chat les fichiers, images, vidéos et messages vocaux générés dans le workspace. Voir cette PR [#15450](https://github.com/QwenLM/qwen-code/pull/15450)

Ce que vous pouvez en faire :

- Une tâche planifiée se termine, son résultat part automatiquement dans votre propre système
- Une tâche dérive : ajoutez une phrase dans le groupe, l'IA change de direction sur-le-champ
- Déléguez directement depuis QQ, les fichiers générés reviennent dans la conversation

### Web Shell : les Artifacts de session sur une page, l'historique de saisie partagé entre appareils

**Les Artifacts de session se parcourent et se téléchargent sur une page.** Le Web Shell déployé en local gagne une page Artifacts : rapports, exports et instantanés d'aperçu web produits par toutes les sessions du workspace tiennent sur une page, à prévisualiser ou télécharger directement. Voir les PR [#18071](https://github.com/QwenLM/qwen-code/pull/18071), [#17689](https://github.com/QwenLM/qwen-code/pull/17689)

**L'historique de saisie se partage entre appareils.** Les prompts et commandes tapés sur l'ordinateur se retrouvent dans l'historique de saisie quand vous ouvrez le même workspace sur le téléphone, et inversement. Voir cette PR [#18120](https://github.com/QwenLM/qwen-code/pull/18120)

**La barre latérale affiche l'état de chaque session.** Les sessions avec objectif portent un marqueur d'objectif, aux mêmes couleurs que la page Goals : bleu en cours d'exécution, ambre quand votre action est attendue. Les sessions dont le dernier tour a été interrompu portent un badge Continue : après un redémarrage, un coup d'œil suffit pour savoir lesquelles reprendre. Voir les PR [#17515](https://github.com/QwenLM/qwen-code/pull/17515), [#18044](https://github.com/QwenLM/qwen-code/pull/18044)

**Les suggestions de suivi se tapent du doigt sur mobile.** Les suggestions deviennent des puces cliquables au-dessus du champ de saisie : un tap remplit le champ, vous ajustez puis envoyez. Voir cette PR [#17918](https://github.com/QwenLM/qwen-code/pull/17918)

**Autres améliorations.** Les boutons des cartes Generated UI copient directement du texte ou téléchargent de petits fichiers ([#18158](https://github.com/QwenLM/qwen-code/pull/18158)) ; la barre d'édition tactile reste sur une ligne sur téléphone et iPad ([#18126](https://github.com/QwenLM/qwen-code/pull/18126)).

## 📊 Autres nouvelles fonctionnalités

**Interface en chinois traditionnel.** Le Web Shell et l'extension compagnon VS Code ajoutent le chinois traditionnel : choisissez «繁體中文 [zh-TW]» dans le sélecteur de langue. Voir cette PR [#17421](https://github.com/QwenLM/qwen-code/pull/17421)

**Traduction à l'affichage.** Activez `general.displayLanguage` dans les paramètres et choisissez le chinois simplifié : les réponses et la réflexion dépliée écrites en anglais par le modèle s'affichent en chinois dans le terminal et le Web Shell. L'archivage, la copie et la suite de la conversation gardent le texte original. Désactivé par défaut : activez-le via `/settings` dans le terminal ou la page des paramètres du Web Shell. Voir cette PR [#18175](https://github.com/QwenLM/qwen-code/pull/18175)

**Extension de canal Microsoft Teams.** Installez séparément l'extension `@qwen-code/channel-msteams` et configurez un bot Azure : vous déléguez ensuite au bot par @mention dans les conversations privées et les groupes Teams, et chaque sujet garde sa propre conversation. Voir cette PR [#15620](https://github.com/QwenLM/qwen-code/pull/15620)

**Mode lecteur d'écran pour le CLI.** Le terminal gagne un mode lecteur d'écran (expérimental) : lancez avec `--screen-reader`, la réponse est lue une fois terminée, l'historique se parcourt au clavier, l'élément sélectionné et les opérations en attente d'approbation sont lus à voix haute. L'interface graphique par défaut reste inchangée. Voir cette PR [#17500](https://github.com/QwenLM/qwen-code/pull/17500)

## 👏 Améliorations de l'expérience

**Le Web Shell s'ouvre plus vite.** Le terminal ne se charge qu'à l'usage et les longs historiques de session voyagent compressés : entre l'ouverture d'une session passée et l'affichage du contenu, le temps mesuré passe d'environ 1,3 seconde à 0,8 seconde. Voir les PR [#17840](https://github.com/QwenLM/qwen-code/pull/17840), [#11220](https://github.com/QwenLM/qwen-code/pull/11220), [#18223](https://github.com/QwenLM/qwen-code/pull/18223)

**Les badges de tâches d'arrière-plan répondent à « que fait cette tâche ? ».** Chaque badge au-dessus du champ de saisie gagne un point d'interrogation : un clic, et l'IA explique en langage simple ce que fait la tâche et pourquoi elle a été lancée. La réponse s'affiche dans le panneau de questions-réponses à côté, la conversation et la tâche continuent normalement. Voir cette PR [#17398](https://github.com/QwenLM/qwen-code/pull/17398)

**La commande en cours continue quand vous envoyez un message.** Vous ajoutez une phrase pendant que l'IA exécute une commande : la commande passe en arrière-plan et continue, votre message reçoit une réponse immédiate. Voir cette PR [#17926](https://github.com/QwenLM/qwen-code/pull/17926)

**Les changements de configuration MCP s'appliquent immédiatement.** Ajoutez ou retirez des serveurs MCP dans les paramètres : les sessions en cours les prennent en compte automatiquement, sans redémarrage. Voir cette PR [#17743](https://github.com/QwenLM/qwen-code/pull/17743)

**Les suggestions de suivi arrivent plus vite.** Leur génération ne consulte qu'un court extrait de la conversation. Voir cette PR [#17532](https://github.com/QwenLM/qwen-code/pull/17532)

**Les réécritures des Mods s'affichent dans le Web Shell.** Le Web Shell affiche les réponses et la réflexion dépliée telles que les plugins Mods les réécrivent, comme le terminal ; l'historique, la copie, la recherche et les branches gardent le texte original. Activez `experimental.mods` pour en profiter. Voir les PR [#17718](https://github.com/QwenLM/qwen-code/pull/17718), [#17920](https://github.com/QwenLM/qwen-code/pull/17920)

**Les étapes d'un workflow se voient dès le départ.** Toutes les étapes sont listées dès le lancement : celles qui n'ont pas encore tourné sont marquées, la progression réelle s'affiche au fil de l'exécution, l'avancement global se lit d'un coup d'œil. Activez d'abord les workflows avec la variable d'environnement `QWEN_CODE_ENABLE_WORKFLOWS=1`. Voir cette PR [#17782](https://github.com/QwenLM/qwen-code/pull/17782)

**Gemini 4 et Kimi K3 adaptent automatiquement leurs paliers de réflexion.** Connectez l'un de ces deux modèles : les paliers de profondeur de réflexion sont disponibles automatiquement. Voir les PR [#18039](https://github.com/QwenLM/qwen-code/pull/18039), [#18095](https://github.com/QwenLM/qwen-code/pull/18095)

**Le basculement vers les modèles de secours gagne du temps.** Avec `experimental.modelAvailabilityTracking` activé, un modèle qui vient d'échouer par manque de capacité dans le tour en cours est sauté : le modèle de secours suivant prend le relais, et le modèle échoué est réessayé au tour suivant. Désactivé par défaut. Voir cette PR [#17377](https://github.com/QwenLM/qwen-code/pull/17377)
