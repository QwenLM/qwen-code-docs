Qwen Code publie cette semaine trois versions stables, v0.26.1, v0.26.2 et v0.26.3, avec 357 PR fusionnées.

**`/autofix-pr` prend le relais après votre soumission.** Sur votre machine, il fait le point toutes les deux minutes : un job CI tombé, une remarque d'un collègue, un conflit avec la branche principale, il corrige, vérifie, pousse, puis répond ligne à ligne dans le PR.

**Une tâche planifiée commence par jeter un œil.** Un contrôle préalable décide s'il y a du nouveau ; quand rien ne bouge, le tour saute d'un bloc, et ce qu'il ne consomme pas est autant de tokens économisés.

**Une session d'arrière-plan se reprend au terminal avec `qwen attach`.** Le matin, vous l'envoyez corriger un gros projet ; en cours de route, vous fermez la fenêtre. Le service tourne toujours : l'après-midi, un autre terminal, vous reprenez la conversation.

## ✨ Nouvelles fonctionnalités

### Suivi des PR : checks CI corrigés, retours de revue traités

Une fois le PR soumis, il faut revenir guetter le CI, lire les remarques des collègues et régler les conflits avec la branche principale. Lancez `/autofix-pr <numéro du PR>` : Qwen Code garde le PR en local et corrige ce qui casse.

Un lint tombe : il lit les journaux du job, corrige, relance les checks du dépôt, ne commite et ne pousse qu'après vérification, puis écrit dans le PR ce qu'il a changé. Tout part dans un worktree séparé, votre dossier de travail reste intact. Il fait le point toutes les deux minutes, uniquement sur les nouveautés. Voir le PR [#15385](https://github.com/QwenLM/qwen-code/pull/15385), [#15057](https://github.com/QwenLM/qwen-code/pull/15057)

Le suivi sur la durée est complété : `/autofix-pr status` donne l'état, `/autofix-pr resume <numéro du PR>` reprend le suivi plus tard, dans une autre session. Un watch choisi en exécution automatique corrige en arrière-plan ; un lancement ordinaire respecte vos réglages d'approbation. Voir les PR [#15510](https://github.com/QwenLM/qwen-code/pull/15510), [#15548](https://github.com/QwenLM/qwen-code/pull/15548), [#15578](https://github.com/QwenLM/qwen-code/pull/15578)

Le Web Shell ajoute une page « PR watch » : état du suivi par projet, nombre de poussées, points qui attendent une décision humaine. Pour un suivi lancé depuis la session Web Shell courante, la page ouvre la conversation d'origine ou permet de l'arrêter. Avant le départ, si la branche du PR garde des modifications non commitées ou des commits non poussés, il s'arrête là et l'explique. Voir les PR [#15668](https://github.com/QwenLM/qwen-code/pull/15668), [#15736](https://github.com/QwenLM/qwen-code/pull/15736)

Ce que vous pouvez en faire :

- Soumettez un PR avant de partir : au matin, le check tombé est corrigé et poussé
- Chaque remarque de revue reçoit une réponse ; ce qui ne s'autocorrige pas est marqué pour qu'un humain tranche
- Une mise à jour de la branche principale crée un conflit : il fusionne d'abord le travail des autres, puis relance les checks du dépôt

### Tâches planifiées : un contrôle préalable, et le modèle ne parle qu'en cas de nouveauté

Vous lui demandez peut-être de guetter toutes les quelques minutes : un build de PR est-il tombé, une nouvelle issue est-elle arrivée ? L'heure sonne, mais huit fois sur dix il ne s'est rien passé, et le tour tourne quand même pour finir sur « rien à signaler ».

Une tâche récurrente accepte désormais un contrôle préalable : une petite vérification choisie par vous, exécutée à chaque échéance, et ce n'est rien de plus qu'une commande ordinaire. Rien trouvé, le tour s'arrête là. Quelque chose trouvé, il enchaîne avec ce que la vérification a vu. Par exemple surveiller un build toutes les deux minutes avec un script qui ne lit que son résultat : le build tient, il ne se passe rien ; il tombe, la ligne remontée part au modèle, qui lit les journaux et corrige. Voir le PR [#15069](https://github.com/QwenLM/qwen-code/pull/15069)

La commande du contrôle vient de vous, avec une règle : pas de bruit quand tout va bien, une sortie seulement en cas de nouveauté. C'est souvent un petit script — et vous pouvez très bien demander à Qwen Code de l'écrire, puis le brancher sur la tâche.

Le formulaire des tâches planifiées du Web Shell contient ce contrôle, et la carte de la tâche affiche son dernier résultat. « Run now » exécute d'abord le contrôle, puis la tâche s'il y a une sortie. La surveillance de PR décrite plus haut repose dessus. Voir le PR [#15211](https://github.com/QwenLM/qwen-code/pull/15211)

Ce que vous pouvez en faire :

- Lire le résultat d'un build toutes les dix minutes, et n'envoyer la correction que le tour où il tombe
- Guetter les nouvelles issues, les lui faire lire et trier seulement quand il en arrive
- Branchez tout ce qui reste silencieux huit fois sur dix : la facture en tokens baisse d'autant

### qwen attach : reprendre au terminal une session qui tourne en arrière-plan

La semaine dernière, la famille `qwen daemon` installait les services locaux en arrière-plan durable. Les sessions du service suivent le mouvement : vous fermez la fenêtre qui les a vues naître, vous faites autre chose, elles restent en place. Pour leur reparler, il ne restait que le Web Shell dans le navigateur.

Un `qwen attach --session <identifiant de session>` dans un terminal vous remet dans la session : l'échange d'avant s'affiche normalement, chaque ligne tapée ici part comme une phrase neuve, la réponse rend ensuite un nouveau point de saisie. Le service lancé le matin se rejoint l'après-midi dans un autre terminal. Voir le PR [#15209](https://github.com/QwenLM/qwen-code/pull/15209)

L'identifiant de session est dans l'adresse Web Shell de cette session, après `/session/`. Vous retrouvez son flux de sortie et un champ de saisie, rien d'autre : complétion, historique des commandes et cartes d'approbation de votre terminal habituel ne suivent pas.

Ce que vous pouvez en faire :

- Un gros chantier interrompu par une fenêtre fermée : vous rebranchez, vous demandez où en sont les modifications
- Une longue tâche lancée depuis le Web Shell et une phrase à glisser — « pense à mettre la doc à jour » : vous repassez par le terminal
- Le service tourne sur une machine de dev : en SSH, vous reprenez la session dans son terminal pour suivre l'avancement et donner la suite

### Web Shell : sessions et workspaces, plus faciles à trouver dans la barre latérale

**La barre latérale gagne une section « Recent sessions ».** Conversations d'un projet et conversations sans workspace sont mélangées par activité récente. Plusieurs projets en parallèle, tout se retrouve au même endroit. Voir le PR [#14904](https://github.com/QwenLM/qwen-code/pull/14904)

**Le travail des Agent se replie sous la conversation qui les a envoyés.** Agent d'arrière-plan, tâche secondaire ouverte au passage, tâche planifiée avec sa propre session : tout s'accroche à la conversation d'origine. Les fils d'un même sujet sont groupés, la session principale et ses branches se distinguent d'un coup d'œil. Voir le PR [#15714](https://github.com/QwenLM/qwen-code/pull/15714)

**Les workspaces se trient, et se créent par une adresse Git.** « Move up » et « Move down » font remonter les projets du quotidien en tête de liste. Pour ajouter un projet, choisissez Dépôt Git et collez l'adresse : le code est récupéré et vous entrez dans ce workspace. Voir les PR [#15360](https://github.com/QwenLM/qwen-code/pull/15360), [#15361](https://github.com/QwenLM/qwen-code/pull/15361)

**Un workspace peut emporter d'autres dossiers, et cela se règle dans les paramètres.** La section « Workspace directories » liste, ajoute et retire des chemins. Un chemin ajouté vaut aussitôt pour toutes les sessions en cours de ce workspace. Voir le PR [#15393](https://github.com/QwenLM/qwen-code/pull/15393)

**Autres améliorations.** Une nouvelle session prend pour nom votre première question à l'IA ([#15689](https://github.com/QwenLM/qwen-code/pull/15689)) ; les conversations archivées ont leur place dans les paramètres, groupées par workspace et filtrables par origine ([#15557](https://github.com/QwenLM/qwen-code/pull/15557)) ; une réponse se copie en entier dans deux formats, « Copy content » pour le texte brut, « Copy Markdown » pour la source ([#15345](https://github.com/QwenLM/qwen-code/pull/15345)) ; la langue des réponses se voit et se choisit dans le panneau de paramètres, juste à côté de la langue de l'interface ([#15363](https://github.com/QwenLM/qwen-code/pull/15363)).

## 📊 Autres nouvelles fonctionnalités

**Les réglages d'une carte interactive repartent dans la conversation.** Une carte s'arrête après le calcul ; pour poursuivre avec ces chiffres, il fallait les recopier et les renvoyer. Une action de plus sur la carte rend le jeu de paramètres appliqué à la conversation d'origine, précédé d'une liste figée que vous validez avant l'envoi. Voir le PR [#15333](https://github.com/QwenLM/qwen-code/pull/15333)

**La mémoire accumulée par Codex s'importe.** D'abord un aperçu, puis le choix des blocs et du périmètre où les poser. La remise en forme tourne en arrière-plan avec le modèle réglé pour ce workspace, et le résultat entre dans la mémoire de Qwen Code : elle se consulte, s'utilise et s'oublie comme d'habitude. En ligne de commande, `qwen memory import codex`, avec `--dry-run` devant. Voir le PR [#14281](https://github.com/QwenLM/qwen-code/pull/14281)

**Une commande pour lever le service local et l'Agent géré.** Lancez `qwen serve --managed --open` : sessions ordinaires et sessions gérées dans la même interface, base de données incluse. Il faut Node.js 22 ou plus et Java 21. Ce chemin reste expérimental, et uniquement sur votre machine. Voir le PR [#14928](https://github.com/QwenLM/qwen-code/pull/14928)

**Dans une session d'Agent géré, vous pouvez intervenir en cours de route, et les droits se règlent session par session.** Ce que vous tapez et les fichiers cités pendant qu'il travaille partent en file, puis au modèle au prochain point sûr ; la file reste modifiable et annulable. À l'arrêt, vous pouvez écrire pour cette seule session des règles d'autorisation, de question et de refus, ou choisir l'approbation Auto. Voir les PR [#15449](https://github.com/QwenLM/qwen-code/pull/15449), [#15448](https://github.com/QwenLM/qwen-code/pull/15448)

**Les sessions gérées téléversent un fichier, récupèrent une page et tiennent leur liste de tâches ; les nouvelles délèguent par défaut à des sous-agents.** Un fichier envoyé depuis le navigateur atterrit dans le workspace choisi (8 Mo au plus) et son chemin s'insère dans la session. Il sait aussi récupérer une page web publique et maintenir ses propres tâches. Voir les PR [#15586](https://github.com/QwenLM/qwen-code/pull/15586), [#15313](https://github.com/QwenLM/qwen-code/pull/15313), [#15089](https://github.com/QwenLM/qwen-code/pull/15089), [#15171](https://github.com/QwenLM/qwen-code/pull/15171)

**La recherche sur le web accepte le domaine de votre passerelle.** Une équipe qui fait passer tout son trafic modèle par une passerelle montée chez elle était bloquée : la recherche ne reconnaissait pas son domaine, et sans toucher au code il n'y avait pas d'autre voie. Une ligne de configuration suffit, le domaine et tous ses sous-domaines correspondent. Voir le PR [#15638](https://github.com/QwenLM/qwen-code/pull/15638)

## 👏 Améliorations de l'expérience

**Le mode Workflow reste actif pour la session.** Ouvert par `--workflow-mode on` ou `/workflows mode on`, il accompagne chaque tour suivant ; reprise, bifurcation, retour en arrière et effacement ont chacun leur comportement, et un changement qui échoue rend l'état de départ. Les deux interfaces terminal affichent le mode courant, et l'interrupteur suit dans un bac à sable Docker. Voir les PR [#15422](https://github.com/QwenLM/qwen-code/pull/15422), [#15743](https://github.com/QwenLM/qwen-code/pull/15743)

**L'autre interface terminal (OpenTUI) a fait le plein ce tour-ci.** Champ de saisie vide, une touche Espace lance la dictée : transcription, annulation, demande d'accès au micro et état d'enregistrement sont branchés. Après un arrêt puis un relancement, vous retrouvez les textes, images et résultats d'outils déjà enregistrés ; un retour en arrière remet à ce point la conversation, la requête suivante et le brouillon. Le checkpoint s'écrit à l'instant où la modification est vraiment approuvée. Les volets « Discover » et « Sources » des extensions vont jusqu'au bout de l'installation. Le faire tourner ne demande plus d'installer Bun vous-même. Voir les PR [#15617](https://github.com/QwenLM/qwen-code/pull/15617), [#15384](https://github.com/QwenLM/qwen-code/pull/15384), [#15389](https://github.com/QwenLM/qwen-code/pull/15389), [#15671](https://github.com/QwenLM/qwen-code/pull/15671), [#14959](https://github.com/QwenLM/qwen-code/pull/14959)

**Contexte presque plein : un lot de résultats d'outils se partage l'espace restant.** Le lot entier repartit ce qu'il reste, en retirant d'abord les textes, images et structures à protéger ; le contenu complet reste écrit et récupérable. Quand la place ne suffit plus pour une vraie mention de troncature, le lot passe par la compression habituelle. Voir le PR [#13599](https://github.com/QwenLM/qwen-code/pull/13599)

**Les modèles à un million de tokens de contexte sont reconnus.** qwen4 et qwen-latest-series, sur invitation, partent désormais sur une fenêtre d'un million au lieu de retomber sur la fenêtre par défaut, plus petite. Voir les PR [#15758](https://github.com/QwenLM/qwen-code/pull/15758), [#15762](https://github.com/QwenLM/qwen-code/pull/15762)

**La liste des modèles des paramètres ne montre que ce que le fournisseur sert vraiment.** Elle gardait des noms retirés du catalogue, des modèles où l'option « désactiver la réflexion » ne désactivait rien, et une image collée à DeepSeek passait pour non prise en charge. Ces trois points sont corrigés. Avec une clé API standard vers Alibaba ModelStudio, la clé et la région suffisent pour choisir un modèle de votre compte. Voir les PR [#15184](https://github.com/QwenLM/qwen-code/pull/15184), [#15189](https://github.com/QwenLM/qwen-code/pull/15189), [#15164](https://github.com/QwenLM/qwen-code/pull/15164)
