Qwen Code publie cette semaine quatre versions stables, v0.26.4 à v0.26.7.

**La connexion à distance gagne un interrupteur indépendant, bien plus pratique.** Allez dans **Paramètres → Connexion**, activez **Autoriser la connexion à distance** : une autre machine sur le même réseau peut se connecter.

**Les événements GitHub font avancer vos sessions.** Un canal relié à un dépôt : nouveau commit, nouvelle revue, CI cassé — tout arrive directement dans la session liée au PR.

**L'état des sessions Web Shell se voit d'un coup d'œil.** Les événements du canal se consultent au même endroit, et dans la barre latérale, une session en cours, une session en attente de votre réponse, une session en erreur se distinguent immédiatement.

## ✨ Nouvelles fonctionnalités

### Connexion à distance : continuez votre travail depuis une autre machine sur le même réseau

Relier plusieurs instances de Qwen Code à une même interface demandait jusqu'ici de lancer la machine cible avec `--hostname 0.0.0.0`. Désormais, quand les deux machines sont sur le même réseau, il suffit de saisir l'adresse et le Bearer token dans **Paramètres → Connexion** pour établir la liaison.

Cette semaine, un interrupteur **Autoriser la connexion à distance** fait son apparition dans **Paramètres → Connexion**. Activez-le : une adresse et un Bearer token sont générés. Saisissez-les sur l'autre machine, la connexion se fait sans redémarrage. Vous pouvez le désactiver à tout moment. Voir les PR [#15887](https://github.com/QwenLM/qwen-code/pull/15887), [#16199](https://github.com/QwenLM/qwen-code/pull/16199)

Ce que vous pouvez en faire :

- Changer de machine et reprendre la conversation là où vous l'avez laissée
- Quitter votre poste, répondre à une question ou traiter une approbation à distance
- Ouvrir l'accès à distance temporairement, puis le refermer dans les paramètres une fois terminé




![Connexions à distance](https://img.alicdn.com/imgextra/i4/O1CN01WL5kej9I8kI4s7XG_!!6000000004481-2-tps-2400-1626.png)

### Les événements de votre dépôt GitHub font avancer vos sessions

Un canal relié à un dépôt GitHub : nouveau commit, nouvelle revue, CI cassé, tout est poussé automatiquement vers la session du canal liée à ce PR. Qwen Code voit l'événement et enchaîne — par exemple, un build cassé, il lit les journaux et corrige. Les réponses sont privées par défaut ; elles ne partent sous le PR qu'après votre confirmation. Voir les PR [#16117](https://github.com/QwenLM/qwen-code/pull/16117), [#16258](https://github.com/QwenLM/qwen-code/pull/16258)

Dans l'éditeur de canal, vous réglez directement les droits d'accès au dépôt GitHub, le comportement des @mentions et la fréquence des notifications — plus besoin d'écrire dans un fichier de configuration. Les numéros de PR et d'Issue mentionnés dans les événements deviennent automatiquement des liens cliquables. Voir les PR [#16149](https://github.com/QwenLM/qwen-code/pull/16149), [#16096](https://github.com/QwenLM/qwen-code/pull/16096), [#16226](https://github.com/QwenLM/qwen-code/pull/16226)

Ce que vous pouvez en faire :

- Le CI d'un PR tombe : les journaux d'échec arrivent dans la session, pas besoin d'aller les chercher
- Un collègue révise votre PR : ses remarques apparaissent dans l'interface de chat
- Un nouveau dépôt à suivre : collez son adresse dans l'éditeur, c'est tout

### Web Shell : événements des canaux et état des sessions, bien plus lisibles dans l'interface

**Les événements des canaux se consultent au même endroit.** Un canal vit au quotidien : un commit GitHub, une tâche planifiée qui se termine, une session qui répond. La page du canal affiche désormais un volet « Événements » : toutes les activités y sont classées par ordre chronologique, filtrables par canal, avec une chronologie qui se rafraîchit automatiquement. Voir cette PR [#16106](https://github.com/QwenLM/qwen-code/pull/16106)

**Le panneau de consommation de tokens se décompose requête par requête.** Avant, seule la consommation par catégorie s'affichait. Maintenant, chaque requête est détaillée : vitesse de sortie, délai de première réponse, succès ou échec, avec une couleur par modèle. Ouvrez une requête pour voir la cause précise d'un échec. Voir les PR [#16108](https://github.com/QwenLM/qwen-code/pull/16108), [#16111](https://github.com/QwenLM/qwen-code/pull/16111)

**Les sessions de la barre latérale portent un indicateur d'état.** Avant, la liste des sessions n'était qu'une suite de noms, sans qu'on sache ce qui s'y passait. Chaque session affiche maintenant un marqueur : une icône tournante pour celles en cours, un repère orange pour celles qui attendent votre approbation, une barre rouge pour celles en erreur. Ouvrez le marqueur : vous voyez qui attend, quelle instruction vient de recevoir sa réponse. Le nombre de messages non lus est indiqué, et vous pouvez tout marquer comme lu ou archiver en un clic. Voir cette PR [#16022](https://github.com/QwenLM/qwen-code/pull/16022)

**Les sessions côte à côte.** Le menu contextuel d'une session propose désormais « Ajouter à l'écran partagé » : deux sessions se placent en vis-à-vis pour les comparer. Voir cette PR [#15956](https://github.com/QwenLM/qwen-code/pull/15956)

**Autres améliorations.** L'interrupteur du mode Workflow rejoint le menu « + » à côté du champ de saisie ; une fois ouvert, une étiquette permet de le refermer ([#16107](https://github.com/QwenLM/qwen-code/pull/16107), [#15779](https://github.com/QwenLM/qwen-code/pull/15779)). Copiez l'adresse d'une image dans le champ de saisie, elle devient automatiquement une pièce jointe ; une capture d'écran se colle aussi directement ([#16179](https://github.com/QwenLM/qwen-code/pull/16179)).

## 📊 Autres nouvelles fonctionnalités

**Les cartes interactives sont actives par défaut.** Avant, il fallait les activer dans les paramètres. Maintenant, elles sont disponibles dès l'installation — demandez-lui de calculer un prêt, de comparer des options, et glissez les curseurs dans la conversation pour voir le résultat. Une fois les paramètres réglés, « Conserver » renvoie les valeurs dans la conversation pour continuer. Voir cette PR [#15856](https://github.com/QwenLM/qwen-code/pull/15856)

**Un projet téléchargé demande votre confiance avant d'exécuter ses hooks.** Les hooks, règles de permissions et serveurs de langage fournis par un projet inconnu ne prennent effet qu'après une boîte de confirmation et votre clic sur « Faire confiance ». Les projets créés localement sur votre machine ne sont pas concernés. Voir les PR [#16182](https://github.com/QwenLM/qwen-code/pull/16182), [#16196](https://github.com/QwenLM/qwen-code/pull/16196)

**`/verify-pr` exécute le code non fiable dans Docker.** Une commande lance un conteneur en local, y place le code du PR et exécute la vérification, sans que la clé de modèle ne quitte votre machine. Voir cette PR [#16077](https://github.com/QwenLM/qwen-code/pull/16077)

**Le bureau prend en charge Fedora 44 et RHEL 10.** Pour ces deux systèmes, téléchargez directement le paquet rpm depuis GitHub Releases. Voir cette PR [#16060](https://github.com/QwenLM/qwen-code/pull/16060)

**La modération de groupe QQ peut être confiée à l'IA.** Un canal expose ses outils de modération aux sessions qu'il héberge : retrait de message, expulsion, approbation d'adhésion, l'IA peut les exécuter pour vous. Contrôlez quels outils sont disponibles via `moderationTools` dans les paramètres du canal. Voir cette PR [#14348](https://github.com/QwenLM/qwen-code/pull/14348)

**L'Agent géré se déploie de zéro avec une seule commande Helm.** Configurez le chart Helm : MySQL et la passerelle sont embarqués. Voir cette PR [#15492](https://github.com/QwenLM/qwen-code/pull/15492)

**Les conversations archivées se restaurent depuis les paramètres.** Allez dans Paramètres → Archive : chaque entrée affiche désormais « Restaurer » et « Exporter », sans avoir à retrouver la session puis à la restaurer. Voir cette PR [#15872](https://github.com/QwenLM/qwen-code/pull/15872)

**Les skills affichent les paramètres restants pendant la saisie.** Tapez `/qwencode-weekly` : les paramètres à remplir flottent en permanence ; remplissez-en un, l'invite se réduit au suivant. Voir cette PR [#15930](https://github.com/QwenLM/qwen-code/pull/15930)

**La commande de mise à jour accepte une version cible.** Lancez `qwen update --target-version <version>` pour installer directement la version voulue, sans interroger le registre npm au préalable. Fonctionne aussi pour rétrograder ou réinstaller la même version. Voir cette PR [#11486](https://github.com/QwenLM/qwen-code/pull/11486)

## 👏 Améliorations de l'expérience

**`/autofix-pr` plus robuste : fusion automatique du tronc, travail dans la copie de travail, nombre de tours réglable.** Quand la branche est en retard sur le tronc et que le CI casse, il fusionne d'abord le tronc avant de relancer les vérifications — plus de rebase manuel. Ajoutez `--in-place` pour qu'il travaille dans votre copie de travail, vous suivez et modifiez en parallèle. Écrivez `@qwen-code /takeover for N` dans un PR pour fixer le nombre de tours, il rend la main une fois terminé. Voir les PR [#15922](https://github.com/QwenLM/qwen-code/pull/15922), [#15929](https://github.com/QwenLM/qwen-code/pull/15929), [#15388](https://github.com/QwenLM/qwen-code/pull/15388)

**Les réponses longues sont déroulables.** Quand `/btw` répond longuement, le contenu s'affiche dans un cadre avec barre de défilement : molette, flèches haut/bas ou PageUp/PageDown pour naviguer. Voir cette PR [#15982](https://github.com/QwenLM/qwen-code/pull/15982)

**DeepSeek V4, qwen4 et les modèles latest-series peuvent aussi définir une profondeur de réflexion.** Ces générations n'avaient aucune profondeur de réflexion sélectionnable, et DeepSeek V4.1 Flash derrière le proxy Alibaba n'avait pas non plus de valeur par défaut ; chaque palier est désormais attribué par modèle, et désactiver la réflexion passe toujours par l'interrupteur existant. Voir les PR [#15987](https://github.com/QwenLM/qwen-code/pull/15987), [#15828](https://github.com/QwenLM/qwen-code/pull/15828)

**La mise à jour en un clic du Web Shell prend en charge pnpm, yarn et bun.** Avant, seul npm bénéficiait du bouton de mise à jour. Désormais, tous ces gestionnaires de paquets sont couverts ; si le vôtre n'est pas détecté, les étapes manuelles s'affichent. Voir cette PR [#15849](https://github.com/QwenLM/qwen-code/pull/15849)

**La barre d'état affiche le nombre d'agents d'arrière-plan en cours.** Le bureau et le Web Shell indiquent en temps réel, dans le repère des tâches en bas, combien d'agents tournent actuellement. Voir cette PR [#14002](https://github.com/QwenLM/qwen-code/pull/14002)

**La navigation de code explique pourquoi elle échoue.** Sans serveur de langage disponible, elle renvoyait silencieusement un résultat vide. Elle vous indique maintenant qu'aucun serveur de langage n'est disponible. Voir cette PR [#15946](https://github.com/QwenLM/qwen-code/pull/15946)

**Les fichiers de contexte mémoire s'ouvrent en aperçu dans le panneau.** Un fichier comme AGENTS.md se lit d'un clic. Voir cette PR [#15932](https://github.com/QwenLM/qwen-code/pull/15932)

**La liste des sessions sans workspace disparaît quand elle est vide.** Avant, une colonne vide occupait de la place. Maintenant, comme pour les éléments épinglés, la colonne entière se masque quand il n'y a rien. Voir cette PR [#15916](https://github.com/QwenLM/qwen-code/pull/15916)
