Qwen Code publie cette semaine deux versions stables — v0.22.3 et v0.23.0 — avec plus de 320 PR fusionnées.

**Le style de réponse, c'est vous qui le choisissez.** Quatre styles de sortie intégrés — Concise (concis), Proactive (proactif), Explanatory (explicatif), Learning (pédagogique) — à choisir librement, et modifiables à tout moment en pleine conversation.

**Le bot DingTalk envoie des fichiers.** Les rapports et documents rédigés par l'IA partent en pièce jointe directement dans la conversation : vous les ouvrez depuis votre téléphone.

**Le Web Shell intègre un terminal.** Vous pouvez lancer des commandes juste à côté de la conversation ; chaque onglet est indépendant et travaille pour son compte.

## ✨ Nouvelles fonctionnalités

### Style de sortie : choisissez comment l'IA vous parle

Chacun attend autre chose des réponses de l'IA : certains veulent un résultat direct sans blabla, d'autres préfèrent que l'IA explique en travaillant, voire qu'elle leur apprenne. Cette semaine, le style de sortie devient configurable, avec quatre styles intégrés :

- **Concise** (concis) : la conclusion d'abord, sans préambule ni récit du processus
- **Proactive** (proactif) : démarre directement ; en cas de doute, énonce ses hypothèses et continue au lieu de vous redemander
- **Explanatory** (explicatif) : vous explique le code concerné pendant qu'il le modifie
- **Learning** (pédagogique) : travaille tout en vous guidant, et vous laisse prendre vous-même certaines petites décisions

Trois façons de le choisir : définissez `general.outputStyle` dans `settings.json` pour un effet permanent, passez `--output-style` au lancement pour une seule session, ou utilisez `/output-style` en pleine conversation pour basculer immédiatement — la réponse suivante adopte le nouveau style.

Ce que vous pouvez en faire :

- Vous ne voulez que le résultat ? Passez en Concise, l'IA va droit à la conclusion
- Vous voulez apprendre ? Passez en Explanatory ou Learning, l'IA explique pendant qu'elle modifie
- Envie de changer de style en cours de conversation ? `/output-style` bascule à tout moment

Voir les PR [#9565](https://github.com/QwenLM/qwen-code/pull/9565), [#10283](https://github.com/QwenLM/qwen-code/pull/10283), [#10683](https://github.com/QwenLM/qwen-code/pull/10683)

### Goal : l'IA rédige l'objectif, vous n'avez qu'à confirmer

La semaine dernière, `/goal-draft` permettait à l'IA de rédiger l'objectif pour vous. Cette semaine, une fois la rédaction terminée, l'IA vous présente l'objectif complet dans une boîte de confirmation, et dès votre confirmation le Goal démarre immédiatement.

Pour les tâches qui demandent plusieurs tours et dont les critères de réussite sont clairs, l'IA juge elle-même que le travail mérite d'être suivi jusqu'au bout : elle rédige l'objectif et vous demande confirmation. Si ce comportement ne vous plaît pas, vous pouvez le désactiver entièrement dans les paramètres. La fonction est disponible dans les sessions interactives du terminal ; la prise en charge dans le Web Shell arrive bientôt.

La semaine dernière, le Goal a gagné un budget token ; cette semaine, vous en décidez le montant : modifiez `model.goalTokenBudget` dans les paramètres, à la hausse comme à la baisse — mettez -1 pour n'avoir aucune limite.

Ce que vous pouvez en faire :

- L'IA rédige l'objectif ; vous confirmez, elle s'y met
- Pour les tâches longues aux critères de réussite clairs, l'IA propose d'elle-même de suivre le travail jusqu'au bout
- Le budget se règle librement, à la hausse comme à la baisse

Voir les PR [#10171](https://github.com/QwenLM/qwen-code/pull/10171), [#10543](https://github.com/QwenLM/qwen-code/pull/10543)

### Review de code : les tours de correction ne revoient que les changements, la profondeur est mémorisée

**Les tours de correction ne revoient que les changements.** Dans la boucle où l'IA review, corrige, puis re-review, chaque tour suivant n'examine que les fichiers modifiés : ce qui a déjà été revu et n'a pas bougé garde la conclusion du tour précédent. Moins de tokens, moins de temps.

**La profondeur de review est mémorisée.** Une fois que vous avez explicitement fixé la profondeur avec `--effort`, il suffit de lancer `/review` dans le même projet pour qu'elle soit réutilisée.

**Les exécutions longues donnent des nouvelles.** Quand un tour de correction automatique s'éternise, le commentaire de statut sur la page de la PR se met à jour environ toutes les 10 minutes avec la durée écoulée et l'heure de la dernière activité : vous savez d'un coup d'œil si ça travaille.

**Les problèmes récurrents sont signalés.** Si un problème grave réapparaît dans le même fichier après correction, la conclusion de la review marque explicitement cette chaîne de récurrences et vous invite à changer d'approche.

Ce que vous pouvez en faire :

- Vous modifiez localement, vous reviewez à chaque version : seuls les fichiers modifiés sont re-revus, et même après plusieurs tours la consommation de tokens reste faible
- Un `/review --effort high` dans un projet, et ensuite un simple `/review` reprend la même profondeur
- Une correction automatique laissée plusieurs heures sur une PR : le commentaire de statut se met à jour toutes les 10 minutes, impossible de louper si ça tourne toujours

Voir les PR [#9659](https://github.com/QwenLM/qwen-code/pull/9659), [#9883](https://github.com/QwenLM/qwen-code/pull/9883), [#9771](https://github.com/QwenLM/qwen-code/pull/9771), [#10010](https://github.com/QwenLM/qwen-code/pull/10010)

### Le bot DingTalk envoie des fichiers

Le bot Channel dans DingTalk ne savait auparavant envoyer que du texte et des images : les rapports et documents rédigés par l'IA devaient être collés dans le message, et pour récupérer le fichier lui-même il fallait revenir sur l'ordinateur. Désormais, le bot envoie les fichiers en pièce jointe : l'IA termine un rapport et l'envoie directement dans la conversation DingTalk, où vous pouvez l'ouvrir et le télécharger depuis votre téléphone. Quand le bot vous écrit de sa propre initiative, il peut aussi joindre des fichiers.

Ce que vous pouvez en faire :

- Les rapports et documents rédigés par l'IA partent en pièce jointe directement dans DingTalk
- Vous les ouvrez, les lisez et les téléchargez depuis votre téléphone
- Le bot peut aussi joindre des fichiers quand il fait un compte rendu spontané

Voir le PR [#10893](https://github.com/QwenLM/qwen-code/pull/10893)

![Le bot envoie un fichier en pièce jointe dans une conversation DingTalk](https://img.alicdn.com/imgextra/i4/O1CN01SuHINQRUN9G3OTaQ_!!6000000004652-2-tps-1672-942.png)

### Web Shell : terminal intégré, gestion des sessions et du poste de travail plus complète

**Un terminal juste à côté de la conversation.** Quand vous travaillez dans le Web Shell, vous avez souvent envie de lancer quelques commandes vous-même : démarrer un serveur pour vérifier le rendu, confirmer un résultat de build. Désormais, le panneau de droite permet d'ouvrir un terminal et de lancer vos commandes juste à côté de la conversation. Chaque onglet est un terminal indépendant, ouvert dans le répertoire de l'espace de travail courant : un onglet peut faire tourner un service en tâche de fond pendant que vous tapez vos commandes dans un autre, sans se gêner.

![Terminal intégré du Web Shell](https://img.alicdn.com/imgextra/i2/O1CN01gLcBvJPyiWE7nW9B_!!6000000004154-2-tps-3841-2160.png)

**Des tâches même sans projet.** La création de tâche permet désormais de créer une session qui n'appartient à aucun espace de travail : poser une question rapide, traiter quelque chose sans rapport avec un projet précis. Ces sessions ont leur propre liste, avec renommage, export et archivage.

**Retrouver une session par son contenu.** Un titre de session oublié ? Cherchez directement un passage de la discussion d'alors : les sessions correspondantes s'affichent avec un extrait du message trouvé.

**Les tâches planifiées ont un contexte propre.** Quand une tâche planifiée s'exécute plusieurs fois, vous pouvez créer une nouvelle session à chaque exécution : chaque contexte reste indépendant. Les sessions issues d'une même tâche sont automatiquement regroupées, et la liste reste claire.

**L'état de tous les espaces de travail d'un coup d'œil.** Le nouveau panneau de vue d'ensemble liste tous les espaces de travail sur une page : combien de sessions tournent, l'état des connexions MCP, la branche courante, la présence de modifications non commitées — et chaque ligne permet de créer directement une tâche.

![Panneau de vue d'ensemble des espaces de travail](https://img.alicdn.com/imgextra/i3/O1CN01bu5Xi34eXdD7nW9B_!!6000000001080-2-tps-3841-2160.png)

**La vue d'ensemble des sessions gagne en confort.** La page devient un tableau avec tri, filtres et pagination ; quand la fenêtre est étroite, le défilement horizontal laisse les colonnes clés fixes. L'entrée se trouve parmi les petites icônes en bas de la barre latérale : survolez la grille, l'infobulle indique « Vue d'ensemble des sessions ».

**L'appairage du téléphone passe en haut à droite.** Une petite icône de QR code en haut à droite de la conversation affiche le code d'appairage : scannez-le avec votre téléphone pour vous connecter à cette session sur l'ordinateur et confier des tâches à l'IA depuis votre mobile (la fonction s'appelle Local Control). Si la fonction n'est pas activée, un clic vous emmène directement sur la page de réglages pour l'activer.

**L'état de Git avant d'agir.** Update Project, Commit et Push affichent désormais une indication d'état : combien de commits de retard ou d'avance, combien de modifications non commitées. Si vous mettez à jour le projet avec des modifications en attente, vous pouvez les mettre de côté avant la mise à jour, ou les abandonner.

Ce que vous pouvez en faire :

- Lancer des commandes directement à côté de la conversation
- Chercher un passage discuté pour retrouver une ancienne session
- L'état de tous les espaces de travail d'un seul coup d'œil

Voir les PR [#9984](https://github.com/QwenLM/qwen-code/pull/9984), [#10514](https://github.com/QwenLM/qwen-code/pull/10514), [#10612](https://github.com/QwenLM/qwen-code/pull/10612), [#10233](https://github.com/QwenLM/qwen-code/pull/10233), [#10611](https://github.com/QwenLM/qwen-code/pull/10611), [#10589](https://github.com/QwenLM/qwen-code/pull/10589), [#10115](https://github.com/QwenLM/qwen-code/pull/10115), [#10432](https://github.com/QwenLM/qwen-code/pull/10432), [#10397](https://github.com/QwenLM/qwen-code/pull/10397), [#10390](https://github.com/QwenLM/qwen-code/pull/10390)

## 📊 Autres nouvelles fonctionnalités

**Les workflows se pilotent en cours de route.** Vous pouvez consulter la progression d'un workflow en cours, le mettre en pause, le reprendre, l'annuler ou le relancer ; l'annulation prend effet immédiatement. Voir les PR [#10411](https://github.com/QwenLM/qwen-code/pull/10411), [#10468](https://github.com/QwenLM/qwen-code/pull/10468)

**La mémoire se range par projet ou en personnel.** Quand vous demandez à l'IA de retenir quelque chose, vous pouvez choisir entre le projet courant et votre mémoire globale personnelle ; les deux côtés ont une frontière stricte et ne se mélangent jamais. Voir le PR [#9895](https://github.com/QwenLM/qwen-code/pull/9895)

**Le lien entre sessions et PR se complète.** La semaine dernière, les PR créées depuis le panneau Git du Web Shell étaient rattachées à leur session ; cette semaine, plusieurs manques sont comblés : les statuts de PR ont des icônes colorées — vert pour en cours, violet pour fusionnée, rouge pour fermée ; une recherche par numéro d'issue retrouve la session correspondante ; et une PR créée par l'IA avec `gh pr create` en pleine conversation est également enregistrée. Voir les PR [#9729](https://github.com/QwenLM/qwen-code/pull/9729), [#10258](https://github.com/QwenLM/qwen-code/pull/10258), [#10425](https://github.com/QwenLM/qwen-code/pull/10425), [#9739](https://github.com/QwenLM/qwen-code/pull/9739)

**La mémoire externe Mem0 est officiellement disponible.** Pour brancher Qwen Code sur le service de mémoire Mem0, installez le paquet d'extension officiel, configurez, et c'est prêt. Voir les PR [#10653](https://github.com/QwenLM/qwen-code/pull/10653), [#10634](https://github.com/QwenLM/qwen-code/pull/10634)

**Les sessions d'une même machine s'écrivent par leur nom.** Quand plusieurs sessions se répartissent le travail, une session peut en retrouver une autre par son nom et lui envoyer directement un message. Voir le PR [#10158](https://github.com/QwenLM/qwen-code/pull/10158)

**Les emojis de statut des tâches sont personnalisables.** Dans le Channel DingTalk, vous pouvez remplacer les emojis affichés pendant et après l'exécution d'une tâche par ceux de votre choix. Voir le PR [#10610](https://github.com/QwenLM/qwen-code/pull/10610)

**La configuration des fournisseurs prend effet immédiatement.** Après modification de `modelProviders` dans `settings.json`, la session en cours utilise la nouvelle configuration sans redémarrage. Voir les PR [#10582](https://github.com/QwenLM/qwen-code/pull/10582), [#10269](https://github.com/QwenLM/qwen-code/pull/10269)

## 👏 Améliorations de l'expérience

**Le champ de saisie du Web Shell a un menu « + » unifié.** Pièces jointes, fichiers, extensions, services MCP, skills : tout est regroupé dedans, un clic sur le plus pour ajouter. Voir le PR [#10379](https://github.com/QwenLM/qwen-code/pull/10379)

**Le gras s'affiche à nouveau, les noms de session sont complets.** Le texte en gras dans les réponses de l'IA est de nouveau rendu, et les noms de session de la barre latérale s'affichent en entier. Voir le PR [#10157](https://github.com/QwenLM/qwen-code/pull/10157)

**Tous les résumés d'outils sont repliables.** Chaque ligne de résumé d'outil peut se replier, les sous-outils restent repliés, et le contenu des MCP Apps est affiché séparément des autres agrégations. Voir le PR [#10231](https://github.com/QwenLM/qwen-code/pull/10231)

**L'erreur du terminal se copie en un clic.** Quand une erreur survient dans le terminal du Web Shell, un clic suffit pour copier le message d'erreur. Voir le PR [#10001](https://github.com/QwenLM/qwen-code/pull/10001)

**L'objectif est visible dans la liste de reprise.** Dans la liste et la recherche de reprise de session, les sessions Goal affichent directement leur objectif. Voir le PR [#10295](https://github.com/QwenLM/qwen-code/pull/10295)

**Les longs tours restent dépliés.** Les longs tours chargés par pagination restent dépliés ; à vous de les replier quand vous avez fini de lire. Voir le PR [#10086](https://github.com/QwenLM/qwen-code/pull/10086)

**Plus de façons d'installer des extensions.** L'installation depuis un chemin local est prise en charge, tout comme l'installation depuis un dépôt Git d'entreprise. Voir les PR [#10131](https://github.com/QwenLM/qwen-code/pull/10131), [#10156](https://github.com/QwenLM/qwen-code/pull/10156)

**Les artefacts se mettent à jour en direct.** Quand le contenu d'un artefact change, l'heure et la taille se mettent à jour immédiatement ; l'aperçu montre toujours la dernière version. Voir le PR [#9929](https://github.com/QwenLM/qwen-code/pull/9929)
