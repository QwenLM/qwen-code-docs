Qwen Code publie cette semaine trois versions stables — v0.23.3, v0.23.4 et v0.24.0 — avec 267 PR fusionnées.

**Les tâches partent chez Claude Code et Codex.** Deux sous-agents sont intégrés : ils travaillent avec le compte où vous êtes connecté et leur propre modèle, et Qwen Code distribue le travail, gère les droits et récupère les résultats.

**Un workflow se lance par son nom.** Ceux que vous avez enregistrés comme ceux livrés par une extension sont appelables directement ; écrivez `+500k` à la fin d'un message et le plafond de tokens du tour est fixé.

**Goal se limite en tours et en durée.** Réglez les plafonds : il s'arrête de lui-même une fois la limite atteinte, et la carte d'état affiche `3/20 turns`.

**Le Web Shell prévisualise les pages web.** Le service lancé en local se regarde en direct, en largeur bureau ou mobile au choix ; chaque HTML livré dans la conversation est archivé en version séparée, et vous rouvrez exactement celle du moment.

## ✨ Nouvelles fonctionnalités

### Confier une tâche à Claude Code ou à Codex

Si Claude Code ou Codex est installé chez vous, vous pouvez désormais leur remettre une portion de travail depuis Qwen Code : dites dans la conversation « fais relire ce module par le sous-agent claude-code », et la sous-tâche part chez Claude Code, avec le compte où vous êtes connecté et son modèle. Le travail rendu comme les demandes de droit reviennent dans cette seule session Qwen Code : vous ne voyez toujours qu'un seul fil de conversation.

Ces deux sous-agents s'exécutent par défaut au premier plan. Codex est en lecture seule par défaut : il lit le code et donne son avis, mais modifier des fichiers demande d'activer auto-edit ou YOLO dans la session, ou de lui accorder explicitement l'écriture dans sa définition. Claude Code accepte plusieurs échanges pendant qu'une tâche avance ; Codex, pour l'instant, reçoit une tâche et rend une réponse. Sur macOS et Linux, c'est utilisable directement ; sur Windows, passez par WSL.

Pour brancher d'autres agents, déclarez un bloc `executor` avec la commande qui les démarre dans leur fichier de définition de sous-agent, dans `.qwen/agents/`.

Ce que vous pouvez en faire :

- Confier une review de code ou une nouvelle version d'un plan à Claude Code ou Codex, avec votre compte et leur modèle
- Laisser Codex lire le dépôt et donner son avis sans toucher aux fichiers tant que vous ne l'autorisez pas
- Brancher d'autres agents externes parlant le protocole ACP dans une définition de sous-agent

Voir les PR [#11003](https://github.com/QwenLM/qwen-code/pull/11003), [#11474](https://github.com/QwenLM/qwen-code/pull/11474)

### Workflows : on les lance par leur nom, et l'effort comme les tokens se voient avant de démarrer

La semaine dernière, les workflows avaient eu leur page de gestion. Cette semaine, ils se lancent plus facilement.

**Un workflow enregistré se lance en une phrase.** Dites « lance le workflow audit » dans la conversation, ou tapez `/audit` dans le champ de saisie : le travail démarre.

**Le plafond de tokens du tour s'écrit dans le message.** Ajoutez `+500k` à la fin, et le workflow qui démarre s'organise avec ce plafond : il s'arrête de lui-même à l'approche de la limite. La fenêtre de confirmation ajoute une prévisualisation de la structure : à quelle étape des sous-agents sont lancés, où tout se déploie en parallèle, où la boucle tourne — vous voyez tout cela avant de démarrer. Si l'exécution dépasse vraiment les attentes, une alerte de flux surdimensionné s'allume sur la barre de tâche.

**Les workflows se packagent dans une extension.** Une fois l'extension installée, ses workflows apparaissent directement dans la page de gestion des workflows, avec leur extension d'origine indiquée ; avant l'installation, on vous liste quels workflows elle apporte.

**L'intensité de réflexion se règle par sous-agent.** Chaque sous-agent lancé peut avoir la sienne, ainsi qu'une restriction des outils qu'il a le droit d'utiliser. Réglez-la bas pour la recherche documentaire ou le tri, haut pour le jugement et la review.

**La confirmation des droits ne vaut que pour la version approuvée.** Changez un seul caractère du flux, et l'exécution suivante redemande la confirmation des droits.

Ce que vous pouvez en faire :

- Lancer le même flux cette semaine et la suivante sans rien reprendre
- Voir combien de travail il va distribuer avant de démarrer, et fixer un plafond de tokens au passage
- Récupérer en installant une extension les workflows qu'un collègue a construits

Voir les PR [#11943](https://github.com/QwenLM/qwen-code/pull/11943), [#11917](https://github.com/QwenLM/qwen-code/pull/11917), [#11939](https://github.com/QwenLM/qwen-code/pull/11939), [#11805](https://github.com/QwenLM/qwen-code/pull/11805), [#11691](https://github.com/QwenLM/qwen-code/pull/11691)

### Goal se limite en tours et en durée

La semaine dernière, un Goal affichait les tokens dépensés. Cette semaine, deux plafonds plus courants s'ajoutent.

**Les tours et la durée ont chacun un plafond.** Réglez `model.goalMaxTurns` et `model.goalMaxActiveMinutes` dans les paramètres pour dire « 20 tours maximum » ou « 30 minutes de travail maximum » ; les deux options sont désactivées par défaut. Une fois la limite atteinte, une durée de clôture est d'abord accordée pour rendre compte du travail en cours avant de s'arrêter. `/goal resume` ouvre une nouvelle fenêtre sur les mêmes plafonds, en ne rechargeant que la dimension consommée ([#11457](https://github.com/QwenLM/qwen-code/pull/11457)).

**Le reste disponible se voit.** La carte d'état affiche directement `3/20 turns` et `12m 3s/30m` ([#11999](https://github.com/QwenLM/qwen-code/pull/11999)). La durée ne compte que le temps de travail réel. Les tokens dépensés par les sous-agents d'avant-plan lancés par un Goal et par ses vérifications d'acceptation sont eux aussi portés au compte de ce Goal ([#11998](https://github.com/QwenLM/qwen-code/pull/11998)). Quand il y a trop de points à vérifier, les vérifications se découpent automatiquement en petits lots, et un lot bloqué est relancé avec un périmètre réduit ([#11365](https://github.com/QwenLM/qwen-code/pull/11365), [#11690](https://github.com/QwenLM/qwen-code/pull/11690)).

**Dans le Web Shell, approuver suffit à démarrer.** Approuvez une proposition de Goal : le Goal démarre de lui-même une fois la réponse du tour en cours terminée normalement ([#11360](https://github.com/QwenLM/qwen-code/pull/11360)).

Ce que vous pouvez en faire :

- Charger un Goal de diagnostiquer un problème après avoir fixé les plafonds, et prolonger s'il les atteint
- Lire sur la carte d'état combien de tours et de minutes restent
- Approuver une proposition dans le Web Shell et le laisser démarrer seul

![Avec une limite de 3 tours, le Goal s'arrête seul une fois la limite atteinte et indique que la fenêtre peut être prolongée](https://img.alicdn.com/imgextra/i2/O1CN01VsCGz0wiVsK1wazs_!!6000000002597-2-tps-958-622.png)

### Channel : le mode de notification du bot se choisit, et ses réponses se retracent

Trois changements sur le bot Channel cette semaine : le mode de notification des tâches d'arrière-plan se choisit, le filtrage par préfixe de message disparaît, et les sessions Channel se consultent telles quelles.

**Le mode de notification des tâches d'arrière-plan se choisit.** Réglez-le dans les paramètres du Channel, DingTalk est pris en charge en premier. Le réglage par défaut, Per turn, envoie d'abord le résultat principal, puis chaque tâche d'arrière-plan terminée ajoute sa propre notification. Per response envoie chaque réponse complète dès qu'elle est prête. Per task attend que tout le travail lié soit terminé et n'envoie qu'un seul résultat final — c'est le choix qui tient le groupe au calme.

![Choix du mode de notification dans les réglages du Channel : Per task, Per response, Per turn (par défaut)](https://img.alicdn.com/imgextra/i1/O1CN01D3zn0QE4IaE5cC36_!!6000000004834-0-tps-2766-1698.jpg)

**Le filtrage par préfixe de message disparaît.** On pouvait imposer un mot d'ouverture : sans ce préfixe, le bot ignorait le message. Cette configuration est retirée : désormais, tout message accepté par les règles d'expéditeur, de groupe ou de mention déclenche le bot, quel que soit son contenu.

**Les sessions Channel se consultent telles quelles.** Rouvrez une session Channel dans le CLI ou le Web Shell : chaque tour affiche exactement ce que le modèle a reçu, consignes permanentes, historique du groupe et auteur du message compris. Pour comprendre « pourquoi le bot a répondu comme ça », vous avez tout en une fois.

Ce que vous pouvez en faire :

- Faire travailler une longue tâche et ne rendre compte qu'à la fin, sans inonder le groupe de messages
- Ne plus préfixer vos messages : mentionnez-le ou parlez-lui en privé, directement
- Retrouver, dans le CLI ou le Web Shell, ce qu'il avait reçu au moment d'une réponse douteuse

Voir les PR [#11822](https://github.com/QwenLM/qwen-code/pull/11822), [#11571](https://github.com/QwenLM/qwen-code/pull/11571), [#11646](https://github.com/QwenLM/qwen-code/pull/11646)

### Web Shell : plusieurs nouveautés d'un coup

**Aperçu direct de l'adresse de développement, HTML archivé automatiquement.** Un panneau d'aperçu web s'ajoute à droite du Web Shell : saisissez l'adresse de votre serveur de développement local et regardez la page, en largeur bureau ou mobile au choix. À chaque HTML livré dans la conversation, une version distincte est archivée ; rouvert une semaine plus tard, il reste exactement la version du moment, et plusieurs versions se comparent côte à côte ([#11276](https://github.com/QwenLM/qwen-code/pull/11276)).

![Aperçu d'une page de développement local à droite, les deux cartes de versions enregistrées à gauche dans la conversation](https://img.alicdn.com/imgextra/i3/O1CN01Eku0NKR0GfI3FPgI_!!6000000002241-2-tps-1600-1050.png)

**Un message modifié se relance, une session interrompue reprend sur place.** Votre dernier message envoyé peut être édité sur place puis renvoyé : la réponse du tour est régénérée, et les images et fichiers déjà joints sont conservés tels quels ([#11650](https://github.com/QwenLM/qwen-code/pull/11650)). Une conversation interrompue en cours de route propose une action de reprise à la réouverture et repart là où elle s'était arrêtée ([#11545](https://github.com/QwenLM/qwen-code/pull/11545)).

**Les notifications du navigateur savent de quelle session il s'agit.** Ajoutées la semaine dernière, elles précisent désormais la session concernée et citent un extrait de la question et de la réponse ; un clic sur la notification ouvre cette conversation ([#11447](https://github.com/QwenLM/qwen-code/pull/11447)).

**La consommation de contexte est exacte, et un clic la comprime.** Le panneau de contexte affiche avec précision ce qui est utilisé, le total, le reste et la part de chaque catégorie, et embarque directement le bouton de compression ; la carte survolée à côté du champ de saisie l'a aussi, et un clic termine la compression ([#11700](https://github.com/QwenLM/qwen-code/pull/11700), [#11782](https://github.com/QwenLM/qwen-code/pull/11782)).

**Autres améliorations.** La page de synthèse des sessions se range par état et se recherche par branche ou numéro de PR ([#11238](https://github.com/QwenLM/qwen-code/pull/11238)) ; fichiers téléversés, fichiers du projet et liens web rejoignent une seule liste Sources ([#11262](https://github.com/QwenLM/qwen-code/pull/11262)) ; une tâche planifiée peut désigner le modèle à utiliser et son groupe ([#11396](https://github.com/QwenLM/qwen-code/pull/11396)) ; une adresse saisie à la main permet de rejoindre le Qwen Code d'une autre machine ([#11548](https://github.com/QwenLM/qwen-code/pull/11548)).

## 📊 Autres nouvelles fonctionnalités

**La recherche web a un plafond par session.** Jusqu'à 200 appels `web_search` par session par défaut, réglable via `tools.webSearch.maxPerSession`. Une fois le quota épuisé, l'IA continue de rédiger avec les informations déjà collectées et vous signale que vous pouvez demander plus. Voir les PR [#11852](https://github.com/QwenLM/qwen-code/pull/11852), [#11692](https://github.com/QwenLM/qwen-code/pull/11692)

**Les messages inter-sessions sont activés par défaut.** Plusieurs sessions Qwen Code sur la même machine se détectent désormais par défaut ; `/peers` liste les sessions en ligne, et les IA peuvent s'envoyer des messages d'une session à l'autre pour rendre compte de l'avancement. Pour revenir en arrière, passez `agents.crossSessionMessaging` à `false`. Voir le PR [#11840](https://github.com/QwenLM/qwen-code/pull/11840)

**Davantage de modèles règlent l'intensité de réflexion.** Moonshot K3 accepte les trois paliers low/high/max, K2.6 utilise l'interrupteur de réflexion natif, Qwen 3.8 accepte low/medium/xhigh, et DeepSeek V4 Pro comme Flash acceptent low/high/max ; le parcours de configuration d'une Standard API Key a été complété pour ces nouveaux modèles, et le Token Plan accueille Qwen 3.8 Flash et DeepSeek V4 Pro-0813. Voir le PR [#11349](https://github.com/QwenLM/qwen-code/pull/11349)

**L'historique des sessions de VS Code est fusionné.** Les conversations créées dans le terminal, le navigateur ou VS Code apparaissent dans une seule liste d'historique, ouvrables d'un clic. Voir le PR [#11713](https://github.com/QwenLM/qwen-code/pull/11713)

**Vos hooks se parcourent dans le terminal.** `/hooks` n'est plus une simple ligne d'état : l'outil déroule les événements, les règles de correspondance et le détail de chaque hook, couche par couche. Une configuration que vous venez de modifier est relue à l'ouverture, et une désactivation globale en explique la raison. La progression d'un hook qui s'exécute s'affiche aussi. Voir les PR [#11903](https://github.com/QwenLM/qwen-code/pull/11903), [#11904](https://github.com/QwenLM/qwen-code/pull/11904), [#11906](https://github.com/QwenLM/qwen-code/pull/11906)

**Les modèles se branchent aussi via le protocole OpenAI Responses.** Le type `openai-responses` rejoint la liste des fournisseurs : il passe par l'interface `/v1/responses` d'OpenAI, avec la sortie en flux, les appels d'outils et les résumés de réflexion. Voir le PR [#8169](https://github.com/QwenLM/qwen-code/pull/8169)

**Linux gagne un second type de bac à sable noyau.** Après avoir choisi le backend bwrap dans les paramètres, le périmètre inscriptible de l'IA se limite au workspace, aux répertoires temporaires et aux caches nécessaires, et le reste du système de fichiers passe en lecture seule. Aucun outil de conteneur, aucun droit root. Une sous-commande affiche les limites en vigueur et lance une auto-vérification. Voir le PR [#11614](https://github.com/QwenLM/qwen-code/pull/11614)

**Un service en arrière-plan porte plus de workspaces.** `qwen serve` accepte par défaut 256 workspaces au lieu de 25 ; utilisez `QWEN_SERVE_MAX_WORKSPACES` pour changer ce plafond. Voir le PR [#11515](https://github.com/QwenLM/qwen-code/pull/11515)

## 👏 Améliorations de l'expérience

**Rouvrir une grosse session va nettement plus vite.** La réouverture des longues conversations comme l'ouverture des panneaux du Web Shell ont été accélérées. Voir les PR [#11595](https://github.com/QwenLM/qwen-code/pull/11595), [#11644](https://github.com/QwenLM/qwen-code/pull/11644)

**Les liens que vous envoyez se cliquent.** Dans le Web Shell, les URL présentes dans vos propres messages sont rendues comme des liens cliquables. Voir le PR [#11464](https://github.com/QwenLM/qwen-code/pull/11464)

**L'interface ne bouge plus pendant que vous lisez.** Le panneau d'approbation ne change plus de taille en cours de lecture ; le résumé du tour s'affiche une seule fois, fixé en fin de sortie. Voir les PR [#11930](https://github.com/QwenLM/qwen-code/pull/11930), [#11986](https://github.com/QwenLM/qwen-code/pull/11986)

**Les sources d'une réponse s'ouvrent en pagination.** Les notes de bas de page d'une réponse sont groupées par source commune et se déplient au survol en aperçu paginé ; sous chaque tour, la liste complète des sources utilisées est affichée, annexes sans note comprises. Voir le PR [#11480](https://github.com/QwenLM/qwen-code/pull/11480)

**Les questions posées restent dans la conversation.** Après la synthèse de fin de tour, vos questions et leurs réponses restent visibles et relisables dans la conversation. Voir le PR [#11461](https://github.com/QwenLM/qwen-code/pull/11461)

**La navigation par tour suit votre lecture.** La barre de navigation par tour à droite du Web Shell s'illumine selon votre position : le tour lu est celui marqué. Voir le PR [#11801](https://github.com/QwenLM/qwen-code/pull/11801)

**Les nouveaux modèles passent en tête.** Dans la configuration d'un fournisseur, les modèles nouvellement découverts sont placés en tête de liste. Voir le PR [#11449](https://github.com/QwenLM/qwen-code/pull/11449)

**Le Web Shell autonome connaît aussi vos paramètres.** Les réglages de thème et de langue s'appliquent également dans la page autonome. Voir le PR [#11961](https://github.com/QwenLM/qwen-code/pull/11961)
