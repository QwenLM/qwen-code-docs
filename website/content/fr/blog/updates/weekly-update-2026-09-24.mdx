Qwen Code publie cette semaine quatre versions stables — de v0.24.1 à v0.24.4 — avec 200 PR fusionnées.

**Le contexte est plein, on sait quel fichier ou quelle extension l'a rempli.** Vous savez lequel fermer pour rendre de la place.

**Une adresse SSH suffit pour modifier un projet sur une autre machine.** Le code est sur un serveur, une machine de compilation ou le poste d'un collègue : depuis votre machine, vous lui demandez d'y modifier les fichiers et d'y lancer les builds.

**Un workflow coupé en route reprend après un redémarrage.** Ce qui est déjà exécuté est conservé ; sur un flux de plusieurs heures, vous ne reprenez que les points qui ont échoué.

## ✨ Nouvelles fonctionnalités

### Le contexte est plein, on sait quel fichier ou quelle extension l'a rempli

`/context` détaille le contexte par origine : la consigne système, les outils intégrés, les outils MCP, les fichiers de mémoire, les skills et les fichiers apportés par les extensions. Deux lignes s'ajoutent cette semaine, le contexte de démarrage et le préfixe mis en cache. `/context detail` descend jusqu'aux fichiers précis ; ce qu'une extension apporte est marqué `Extension: nom de l'extension · nom de fichier`, avec la part consommée pour chacun. Le terminal et le Web Shell affichent la même chose.

**Un rappel quand ça déborde.** Dès que le contexte permanent (`QWEN.md` et mémoire automatique) dépasse le plus petit des deux seuils, 15 % de la fenêtre ou 10 000 tokens, le chargement vous avertit.

**Les règles d'une extension peuvent ne s'activer que sur les fichiers concernés.** Le contexte est injecté seulement quand vous touchez un fichier visé ; le reste du temps, il ne consomme rien.

Ce que vous pouvez en faire :

- Le contexte est presque plein : vous voyez d'abord quels fichiers et quelle extension le consomment
- Vous installez une extension et le contexte grimpe : `/context detail` pointe celle qui est en cause
- Face à l'avertissement de dépassement, vous savez s'il faut alléger `QWEN.md` ou couper la mémoire automatique

Voir les PR [#12119](https://github.com/QwenLM/qwen-code/pull/12119), [#12318](https://github.com/QwenLM/qwen-code/pull/12318), [#12034](https://github.com/QwenLM/qwen-code/pull/12034)

### Une adresse SSH et vous modifiez un projet sur une autre machine

Votre projet est sur un serveur, dans une machine de compilation ou sur le poste d'un collègue, et vous voulez que Qwen Code y travaille. Avant, il fallait installer Qwen Code là-bas, y démarrer le service, puis recopier l'adresse. Maintenant, quand vous ajoutez un workspace dans le Web Shell, vous écrivez directement une adresse SSH dans le champ de chemin :

```text
ssh://user@host/absolute/project
```

Si Qwen Code n'est pas installé sur cette machine, cette adresse suffit à l'enregistrer. Si le service Qwen Code y tourne déjà, vous enregistrez une fois l'adresse et le jeton, puis vous sélectionnez ce workspace directement en l'ajoutant. Une fois enregistré, lire et écrire les fichiers là-bas, y exécuter des commandes et consulter son état Git se font dans votre conversation, sur votre machine. Un workspace tout juste ajouté est en lecture seule : il faut l'approuver par « Faire confiance » pour qu'il modifie des fichiers.

Ce que vous pouvez en faire :

- Le code et les dépendances sont sur la machine de compilation : depuis votre conversation locale, vous lui demandez d'y modifier les fichiers et d'y lancer le build
- Vérifier une fois dans l'environnement déjà prêt de quelqu'un d'autre
- Garder en parallèle un projet local et un projet distant, et aller de l'un à l'autre dans la même conversation

Voir les PR [#12255](https://github.com/QwenLM/qwen-code/pull/12255), [#12085](https://github.com/QwenLM/qwen-code/pull/12085), [#12412](https://github.com/QwenLM/qwen-code/pull/12412)

### Un workflow coupé en route reprend après un redémarrage

Un flux lancé que vous arrêtez pour la journée, ou coupé par un redémarrage de machine : avant, il fallait tout reprendre depuis le début. Chaque exécution laisse maintenant un point de reprise, et la suivante repart là où elle s'était arrêtée.

**Le redémarrage vous le signale de lui-même.** À l'ouverture de Qwen Code, le message de démarrage liste quelle exécution a été coupée, à quelle étape elle s'est arrêtée et combien de sous-agents avaient déjà terminé, et vous renvoie à `/workflows`. Ces exécutions rejoignent toutes l'historique.

**Des boutons sur les cartes d'exécutions passées du Web Shell.** « Réessayer le chemin échoué » ne rejoue que la partie qui a échoué, « Tout relancer » reprend depuis le début.

Ce que vous pouvez en faire :

- Vous coupez en fin de journée : au démarrage du lendemain, vous regardez d'abord où le flux s'est arrêté
- Un long flux où seuls deux sous-agents ont échoué : « Réessayer le chemin échoué » ne rattrape que ces deux points
- Vous voulez revérifier le même flux depuis le début : cliquez sur « Tout relancer »

Voir les PR [#12159](https://github.com/QwenLM/qwen-code/pull/12159), [#12291](https://github.com/QwenLM/qwen-code/pull/12291), [#12097](https://github.com/QwenLM/qwen-code/pull/12097)

### Web Shell : plusieurs nouveautés d'un coup

**Le diff s'affiche avant que vous approuviez une modification.** Pour toute modification de fichier qui demande votre accord, la carte d'approbation liste directement les lignes ajoutées et supprimées ; les trois cas sont couverts, écraser un fichier, écrire un nouveau fichier, éditer un notebook. Voir le PR [#12443](https://github.com/QwenLM/qwen-code/pull/12443)

**Un long collage se replie en carte.** Au-delà de 200 lignes ou 8 000 caractères, ce que vous collez est replié, avec un titre pris sur le début du contenu ; « Afficher dans le champ de saisie » le remet tel quel dans le champ. Les collages qui commencent par `/` ou `!`, les collages courts et le remplacement d'une sélection ne sont jamais repliés. Voir le PR [#12084](https://github.com/QwenLM/qwen-code/pull/12084)

**Un onglet Trajectory dans le panneau de droite.** Après un tour qui vous paraît lent ou coûteux, ouvrez-le pour voir où est passé le temps : la durée de chaque tour, le délai avant le premier caractère, les tokens consommés, l'appel d'outil le plus long. Il s'ajoute depuis « Ajouter un onglet » dans la zone d'extension de droite. Voir le PR [#12388](https://github.com/QwenLM/qwen-code/pull/12388)

**L'historique Git se retrouve plus vite.** Dans le Web Shell, l'historique des commits s'affiche en graphe de branches, avec bascule sur toutes les branches et recherche par message de commit, par auteur ou par hash. Les adresses de dépôt distant s'ajoutent et se retirent aussi depuis l'interface, sans retourner au terminal. Tout cela se trouve dans l'onglet de branche au-dessus du champ de saisie. Voir les PR [#12152](https://github.com/QwenLM/qwen-code/pull/12152), [#11163](https://github.com/QwenLM/qwen-code/pull/11163)

**Autres améliorations.** L'interrupteur du mode plan quitte la barre d'outils du champ de saisie pour le menu « + » ; quand il est actif, un onglet supprimable reste au-dessus du champ ([#12218](https://github.com/QwenLM/qwen-code/pull/12218)). Les fichiers produits par `/export` deviennent une carte prévisualisable et téléchargeable dans la conversation ([#12050](https://github.com/QwenLM/qwen-code/pull/12050)).

## 📊 Autres nouvelles fonctionnalités

**Le Web Shell s'installe comme une application à part entière.** Un bouton d'installation apparaît à droite de la barre d'adresse : vous obtenez votre propre icône et une fenêtre autonome, comme une application du store. Il faut Chrome / Edge 111 ou plus récent, Firefox 128 ou plus récent, Safari 16.4 ou plus récent, et une adresse locale (`127.0.0.1` ou `localhost`) ou en HTTPS ; en accès par IP de réseau local, l'installation n'est pas possible. Voir le PR [#11722](https://github.com/QwenLM/qwen-code/pull/11722)

**La taille du texte se règle dans la version desktop.** `Cmd` / `Ctrl` avec `-`, `=` ou `0`, ou un pincement à deux doigts sur le pavé tactile : entre 50 % et 300 %, et la fenêtre suivante s'ouvre encore au réglage que vous aviez choisi. Voir le PR [#12410](https://github.com/QwenLM/qwen-code/pull/12410)

**Les quotas du Goal s'affichent au-dessus du champ de saisie.** La carte d'état ne montre plus seulement le budget de tokens : elle ajoute les plafonds de tours et de durée, par exemple `3 / 20 turns` ou `12m 3s / 30m 0s` ; un Goal sans plafond reste comme avant. L'historique exporté par `/export` contient lui aussi le déroulé complet du Goal. Voir les PR [#12201](https://github.com/QwenLM/qwen-code/pull/12201), [#12099](https://github.com/QwenLM/qwen-code/pull/12099)

**Un Goal qui se déclare fini est vérifié sur le déroulé réel de la conversation.** Lancez-le avec `/goal` sur plusieurs tours : son « c'est terminé » ne suffit pas. La vérification relit ce qui s'est réellement passé dans les derniers tours et juge le Goal inachevé si les faits ne correspondent pas. Voir le PR [#12105](https://github.com/QwenLM/qwen-code/pull/12105)

**Un sous-agent peut travailler enfermé dans un conteneur.** Vous lui demandez de balayer tout le dépôt et d'enchaîner les commandes, sans craindre qu'il aille chercher votre clé SSH et vos identifiants dans le répertoire personnel : chaque commande exécutée et chaque lecture ou écriture restent dans un conteneur Docker ou Podman, et seul le workspace est modifiable. Pour ce mode, posez `QWEN_AGENT_EXECUTION_BACKEND=docker` avant le démarrage ; en contrepartie, les workflows, Agent Team, MCP, LSP et skills sont coupés, et Windows n'est pas encore pris en charge. Voir le PR [#11711](https://github.com/QwenLM/qwen-code/pull/11711)

**Deux formats d'API sous un seul fournisseur.** Pour faire passer un modèle par le protocole OpenAI Responses, ajoutez une ligne `"wireApi": "responses"` sur son entrée de modèle ; les autres modèles continuent sur Chat. La configuration d'un fournisseur personnalisé via `/auth` propose aussi une étape « Choisir le format d'API ». Voir le PR [#11538](https://github.com/QwenLM/qwen-code/pull/11538)

## 👏 Améliorations de l'expérience

**Le Web Shell sur mobile est plus agréable.** Quand le service est bindé sur une adresse accessible depuis l'extérieur, le code d'appairage apparaît aussi en haut à droite de la page de session : scannez-le depuis le téléphone pour entrer dans la session en cours, sans saisir le jeton à la main. Une fois sur la page mobile, le champ de saisie a été réorganisé et une dizaine d'actions sont regroupées dans le tiroir « Ajouter au message ». Voir les PR [#12322](https://github.com/QwenLM/qwen-code/pull/12322), [#12252](https://github.com/QwenLM/qwen-code/pull/12252)

**Le champ de saisie respire mieux.** Avant qu'une session existe, le sélecteur de workspace et l'onglet de branche Git quittent la barre d'outils pour une ligne dédiée en dessous ; une fois la session créée, le workspace n'apparaît plus qu'en icône dossier en haut, avec le chemin complet au survol. Les cartes de produit de type lien ouvrent désormais une page dans un nouvel onglet. Voir les PR [#12299](https://github.com/QwenLM/qwen-code/pull/12299), [#12317](https://github.com/QwenLM/qwen-code/pull/12317)

**Le résultat de la compression est écrit dans votre langue.** Après `/compress`, vous lisez « Contexte compressé : X → Y », et « Rien à compresser. » quand il n'y a rien à compresser ; après une reprise de session, le chiffre de l'anneau de contexte est à jour lui aussi. Voir le PR [#12141](https://github.com/QwenLM/qwen-code/pull/12141)

**La connexion automatique du Channel fonctionne aussi hors du workspace principal.** Quand un seul `qwen serve` porte plusieurs workspaces, chacun avec ses propres robots Channel, le démarrage du service rétablit désormais le Channel de chaque workspace approuvé : l'interrupteur « Se connecter automatiquement au démarrage de Qwen Code » produit vraiment son effet après l'enregistrement. Voir le PR [#12385](https://github.com/QwenLM/qwen-code/pull/12385)

**Sous Linux, le bac à sable ne confine plus que l'exécution des outils.** La configuration de la semaine dernière, qui enfermait Qwen Code entier dans bwrap, renvoie maintenant une erreur avec une indication de migration. Avec `tools.executionSandbox`, seules l'exécution des commandes et les lectures ou écritures de fichiers sont confinées ; Qwen Code lui-même, les requêtes au modèle et votre session de connexion restent sur la machine. Voir le PR [#12267](https://github.com/QwenLM/qwen-code/pull/12267)

**Les appels ponctuels depuis un script sont plus rapides.** Sur un usage du type `qwen -p`, qui lance une phrase puis quitte, le temps mesuré passe de 7,7 secondes à 5,1 secondes et la mémoire de 640 MiB à 421 MiB, grâce à un processus en moins. Voir le PR [#12340](https://github.com/QwenLM/qwen-code/pull/12340)

**Quand le terminal n'affiche pas de code d'appairage, il l'explique.** Vous bindez le service sur une adresse externe pour scanner depuis le téléphone : si aucun code ne sort dans le terminal, la raison est affichée, et un second code contenant seulement l'adresse est proposé — scannez-le, puis saisissez une fois le jeton sur le téléphone. Pour forcer un code contenant le jeton, utilisez `qwen serve --token-qr`. Voir le PR [#12266](https://github.com/QwenLM/qwen-code/pull/12266)
