Cette semaine, Qwen Code sort deux versions stables — v0.21.0 et v0.21.1 — avec plus de 290 PR fusionnés.

**Deux lacunes comblées dans le cycle de vie des sessions et des Agents.** Avant, pour réutiliser le contexte d'une conversation antérieure, il fallait faire resume ou fork — la conversation en cours était interrompue. Désormais, tapez `@` et la liste de complétion affiche l'historique des sessions du projet : sélectionnez-en une, un résumé en lecture seule est injecté, et votre conversation en cours reste indépendante. Côté Agent en arrière-plan, avant il était détruit après complétion — la moindre question de suivi exigeait une reconstruction complète. Désormais, le runtime d'un Agent terminé reste résident dans la session parente : `send_message` reprend la conversation, et même après un redémarrage du processus, le roster permet de le restaurer.

**Le système de skills passe en semi-automatique.** `/learn` ne traitait que du texte, des documents et des pages web — une vidéo tutorielle, il fallait la regarder soi-même puis rédiger le skill à la main. Désormais, déposez un MP4 et l'Agent le visionne, puis le distille automatiquement en un Skill réutilisable. Plus besoin de dupliquer vos répertoires de skills non plus — configurez un chemin dans settings, et Claude Code, Codex, Qwen Code partagent la même bibliothèque.

**L'observabilité et les intégrations se complètent.** `/stats` affiche enfin le TTFT, la durée de génération et le TPS — comparer les performances streaming entre modèles ne repose plus sur l'impression. L'adaptateur GitHub Channel est en ligne : mentionnez le bot dans une Issue ou un PR et l'Agent répond en commentaire. Le Web Shell a reçu plus de 40 PR cette semaine : sélecteur de branche Git, boîte de dialogue de commit, création de PR, page de gestion des Channels, aperçu de fichiers, saisie vocale — tout d'un coup.

## ✨ Nouvelles fonctionnalités

### /learn supporte les vidéos : un tutoriel vidéo devient une compétence réutilisable

Avant, `/learn` traitait le texte, les documents, les répertoires et les pages web, mais pas les vidéos. Vous avez un enregistrement d'écran de 15 minutes et vous voulez le transformer en skill utilisable par l'Agent ? Il fallait le regarder en entier puis rédiger le SKILL.md à la main.

Désormais, `/learn` accepte les fichiers MP4, WebM, MOV, M4V locaux et les liens directs HTTP(S) vers des vidéos. La commande vérifie d'abord si le modèle actuel supporte l'entrée vidéo, puis confie la vidéo à l'Agent pour distillation. Le résultat est un répertoire `learned-skill-*` contenant un `SKILL.md` et un fichier `references/source.md` horodaté. Les URL de pages YouTube sont détectées et rejetées, avec une invitation à télécharger la vidéo en local. Les entrées non-vidéo conservent le comportement existant.

Ce que cela vous permet de faire :

- Transformer l'enregistrement d'écran d'un collègue en skill réutilisable pour l'équipe
- Regarder un tutoriel vidéo, puis `/learn tutorial.mp4` pour extraire les étapes en un clic
- Le fichier source indique « source-grounded, not execution-verified » — distinction claire entre « vu » et « vérifié »

Voir le PR [#7497](https://github.com/QwenLM/qwen-code/pull/7497)

### @ pour référencer l'historique de conversation : sans resume ni fork, le contexte passé dans la conversation en cours

Avant, pour réutiliser le contexte d'une session antérieure, il fallait faire resume ou fork. Resume quitte la conversation en cours, fork crée une nouvelle branche — pour « juste référencer une conclusion précédente », les deux sont disproportionnés.

Désormais, tapez `@` dans le champ de saisie : la liste déroulante de complétion affiche les résultats par catégorie (Tout, Fichiers, Sessions, MCP, Extensions), les flèches gauche/droite basculent entre catégories. Sélectionnez une session passée et Qwen Code injecte un résumé en lecture seule généré de manière déterministe : le texte visible de l'utilisateur et de l'assistant est conservé, les résultats d'outils sont compressés en une ligne d'état, le tout dans un budget de 8k tokens avec priorité au contenu le plus récent. La conversation en cours n'est pas affectée, l'ancienne session n'est ni restaurée ni forkée.

Ce que cela vous permet de faire :

- Référencer les conclusions d'une session de débogage antérieure dans la tâche en cours, sans changer de contexte
- Transmettre le feedback d'une revue de code précédente comme contexte à une nouvelle tâche
- Accumuler la connaissance du projet entre sessions, sans réexpliquer le contexte à chaque fois

Voir le PR [#7302](https://github.com/QwenLM/qwen-code/pull/7302)

### Agent en arrière-plan résident et restauration cross-session : plus de reconstruction après complétion

Avant, un Agent en arrière-plan terminé voyait son runtime détruit. Une question de suivi ? Il fallait reconstruire intégralement le chat, les outils, le registry et le cache provider depuis le transcript JSONL — lent, et tout l'état in-process était perdu. Pire : après un redémarrage du processus, la reprise de la session parente transformait les Agents terminés en `Task not found`.

Deux PR cette semaine résolvent le problème. D'abord, le runtime d'un Agent en arrière-plan terminé reste résident dans la session parente : un `send_message` vers le même `task_id` réutilise le chat actif, les outils préparés, le cache provider et le modèle de démarrage — plus de reconstruction depuis le transcript. Ensuite, lors d'un redémarrage du processus et de la reprise de la session parente, les Agents interrompus reviennent en état `paused`, les terminés en état `completed`, avec le même identifiant de tâche. Le nouvel outil `list_agents` permet de consulter tous les Agents en arrière-plan adressables de la session.

Ce que cela vous permet de faire :

- L'Agent termine une revue de code en arrière-plan, vous demandez « développe le troisième point » — sans reconstruction
- Vous quittez le terminal, revenez le lendemain, `list_agents` montre que l'Agent de la veille est toujours là — vous reprenez
- En itération, l'Agent conserve son modèle de démarrage, indépendamment des changements de modèle de la session parente

Voir les PR [#7426](https://github.com/QwenLM/qwen-code/pull/7426), [#7459](https://github.com/QwenLM/qwen-code/pull/7459)

### Répertoires de skills personnalisés : une bibliothèque partagée entre plusieurs Agents

Avant, les skills ne pouvaient vivre que dans `~/.qwen/skills/`. Si vous utilisez Claude Code et Qwen Code simultanément, il fallait dupliquer la bibliothèque — et oublier de synchroniser l'une des copies était la norme.

Désormais, ajoutez un tableau `skills.directories` dans settings.json pour spécifier des chemins de scan supplémentaires. Les chemins supportent l'expansion `~`, le scan est récursif sur les fichiers SKILL.md. Le répertoire par défaut a priorité : en cas de nom identique, c'est la version du répertoire par défaut qui l'emporte.

Ce que cela vous permet de faire :

- Une bibliothèque dans `~/.agent/skills`, partagée entre Claude Code, Codex et Qwen Code
- Une bibliothèque d'équipe dans `/shared/team-skills`, synchronisée automatiquement pour tous
- Organiser les skills par projet, sans tout entasser dans un seul répertoire

Voir le PR [#7395](https://github.com/QwenLM/qwen-code/pull/7395)

### /stats affiche les métriques de génération : TTFT et TPS en un coup d'œil

Avant, `/stats` affichait la durée de session, le nombre total de requêtes, les appels d'outils et les modifications de fichiers. Comparer la vitesse de réponse streaming entre deux modèles ? Pas de TTFT, pas de TPS — uniquement l'impression.

Désormais, `/stats` et l'onglet Session incluent une section Generation Metrics : le nom du modèle de la dernière requête, le TTFT (latence du premier token), la durée de génération, le nombre de tokens en sortie et le TPS, ainsi que les métriques au niveau session (requêtes chronométrées, TTFT moyen, TPS pondéré). La durée de génération est calculée par `api_duration - ttft`, le dénominateur du TPS couvre l'intervalle entre le premier token visible et la fin de la génération. Les prompts auxiliaires internes sont exclus, les relevés d'utilisation quotidiens/mensuels restent inchangés.

Ce que cela vous permet de faire :

- Changer de modèle, lancer `/stats`, et voir directement l'écart de TTFT et de TPS
- Comparer les performances streaming entre un backend local et une API cloud
- Le TPS pondéré au niveau session reflète le débit réel de l'ensemble de la conversation

Voir le PR [#7677](https://github.com/QwenLM/qwen-code/pull/7677)

### Adaptateur GitHub Channel : mentionnez le bot dans une Issue ou un PR pour déclencher l'Agent

Avant, les Channels de Qwen Code supportaient Feishu, WeChat, QQ et Telegram, mais pas GitHub. Mentionner le bot dans une Issue pour qu'il examine un problème ? Impossible.

L'adaptateur GitHub Channel est désormais en ligne. Configurez un PAT classique, lancez le Channel, et il interroge l'API de notifications GitHub par polling. Mentionnez le bot dans un commentaire d'Issue ou de PR : l'Agent lit le contenu et répond dans le même fil. Mentionner le bot dans le corps d'une nouvelle Issue fonctionne aussi (premier contact). Le dédoublonnage repose sur une fenêtre de commentaires par cursor plutôt que sur le `markNotificationsAsRead` asynchrone de GitHub, et les auto-commentaires du bot sont filtrés pour éviter les boucles. GitHub Enterprise (via `baseUrl`) et les proxys sont supportés.

Ce que cela vous permet de faire :

- Mentionner le bot dans une Issue : « regarde cette erreur » — l'Agent répond directement en commentaire
- Pendant une revue de PR, mentionner le bot pour ajouter du contexte, sans quitter GitHub
- L'intervalle de polling est configurable (60 s par défaut), ajustez la réactivité selon vos besoins

Voir le PR [#7632](https://github.com/QwenLM/qwen-code/pull/7632)

### Web Shell : mise à jour massive — Git, gestion des Channels, aperçu de fichiers, saisie vocale

Le Web Shell a reçu plus de 40 PR cette semaine — du workflow Git à la gestion des Channels en passant par l'expérience de saisie, pratiquement tout a bougé.

**Le workflow Git est complet.** Avant, le Web Shell permettait de voir les branches, mais pas de basculer, de commiter ou de créer un PR. Désormais, un sélecteur de mode Git apparaît à la création de session ([#7471](https://github.com/QwenLM/qwen-code/pull/7471)), vous pouvez changer de branche en session, ouvrir la boîte de dialogue de commit et créer un PR directement ([#7731](https://github.com/QwenLM/qwen-code/pull/7731)). Les sessions Worktree accèdent aussi aux boîtes de dialogue Changes et History ([#7695](https://github.com/QwenLM/qwen-code/pull/7695)). Un panneau GitHub PR en lecture seule a été ajouté à la barre latérale ([#7683](https://github.com/QwenLM/qwen-code/pull/7683)) — consultez l'état d'un PR sans ouvrir le navigateur.

**La gestion des Channels a sa page.** Avant, configurer un Channel exigeait d'éditer settings.json à la main. Le Web Shell dispose désormais d'une page complète de gestion des Channels ([#7793](https://github.com/QwenLM/qwen-code/pull/7793)), avec flux de configuration ([#7893](https://github.com/QwenLM/qwen-code/pull/7893)) et gestion des demandes de pairing ([#7909](https://github.com/QwenLM/qwen-code/pull/7909)).

**Aperçu de fichiers et gestion des Agents.** La liste de fichiers supporte le rendu d'aperçu ([#7467](https://github.com/QwenLM/qwen-code/pull/7467)) — plus besoin d'ouvrir pour voir le contenu brut. Les sessions de sous-Agents sont visibles dans le panneau de détails ([#7380](https://github.com/QwenLM/qwen-code/pull/7380)), l'état des Agents en arrière-plan se synchronise en temps réel ([#7561](https://github.com/QwenLM/qwen-code/pull/7561)). Le sélecteur de Workspace ([#7390](https://github.com/QwenLM/qwen-code/pull/7390)) et le sélecteur de dossiers natif ([#7849](https://github.com/QwenLM/qwen-code/pull/7849)) facilitent le passage d'un projet à l'autre.

**Expérience de saisie.** La saisie vocale est limitée au composer workspace en cours ([#7754](https://github.com/QwenLM/qwen-code/pull/7754)), le mode push-to-talk est supporté ([#7839](https://github.com/QwenLM/qwen-code/pull/7839)), et la stabilité mobile est corrigée ([#7806](https://github.com/QwenLM/qwen-code/pull/7806)). Les appareils tactiles basculent sur un composer textarea pur ([#7587](https://github.com/QwenLM/qwen-code/pull/7587)). Le contenu collé n'est plus perdu ([#7824](https://github.com/QwenLM/qwen-code/pull/7824)). Le terminal supporte le parsing des séquences SGR 256 couleurs et truecolor ([#7620](https://github.com/QwenLM/qwen-code/pull/7620)).

**Autres améliorations.** La barre latérale peut s'étendre jusqu'à la moitié de la fenêtre ([#7778](https://github.com/QwenLM/qwen-code/pull/7778)), le nom de session s'affiche en entier au survol ([#7662](https://github.com/QwenLM/qwen-code/pull/7662)), les tâches Monitor ont un panneau de détails ([#7817](https://github.com/QwenLM/qwen-code/pull/7817)), et le rendu des longues sessions est optimisé ([#7408](https://github.com/QwenLM/qwen-code/pull/7408)). L'isolation Shadow DOM empêche le CSS hôte de polluer les styles des composants ([#7551](https://github.com/QwenLM/qwen-code/pull/7551)). Taper « BTW » suggère d'ouvrir une question latérale ([#7935](https://github.com/QwenLM/qwen-code/pull/7935)).

## 📊 Autres nouvelles fonctionnalités

**Outil de zoom d'image.** Les grandes images sont réduites avant envoi au modèle — les petits textes et les étiquettes de graphiques deviennent illisibles. Désormais, les modèles supportant l'entrée image disposent de l'outil `zoom_image` qui recadre une région du fichier original en pleine résolution et retourne une vue JPEG agrandie. Supporte PNG, JPEG, WebP, avec gestion automatique de l'orientation EXIF. Voir le PR [#7809](https://github.com/QwenLM/qwen-code/pull/7809)

**Niveaux de modèle pour les sous-Agents.** Différentes tâches nécessitent des modèles de coût différent, mais l'appelant ne devrait pas manipuler d'identifiants de modèle concrets. Vous pouvez désormais mapper des niveaux sémantiques (`small`, `high`, etc.) à des sélecteurs de modèle dans settings — le schéma de l'outil Agent n'expose que les noms de niveaux. Les forks et les teammates nommés n'acceptent pas ce paramètre. Voir le PR [#7702](https://github.com/QwenLM/qwen-code/pull/7702)

**Modèle de génération d'images configurable.** La génération d'images n'est plus liée au modèle par défaut — vous pouvez spécifier un modèle dédié dans la configuration. Voir le PR [#7607](https://github.com/QwenLM/qwen-code/pull/7607)

**Outil de recherche de corpus externe.** Nouvel outil MCP `context_search` pour récupérer du contexte à la demande depuis une base de connaissances externe ou un service RAG. Lecture seule, pas de rappel automatique, pas d'écriture — le provider et le corpus sont configurés par l'administrateur. Inclut deux adaptateurs : Mem0 et HTTP générique. Voir le PR [#7586](https://github.com/QwenLM/qwen-code/pull/7586)

**Override d'identité système.** La variable d'environnement `QWEN_SYSTEM_IDENTITY_MD` permet de remplacer le prompt d'identité principal. Voir le PR [#7478](https://github.com/QwenLM/qwen-code/pull/7478)

**Reconnexion forcée MCP.** `qwen serve` supporte la reconnexion forcée d'un serveur MCP sans redémarrer le processus entier. Voir le PR [#7488](https://github.com/QwenLM/qwen-code/pull/7488)

**Rechargement à chaud du workspace trust.** Après modification de la configuration de workspace trust, le daemon en cours applique immédiatement la nouvelle politique, sans redémarrage. Voir le PR [#7268](https://github.com/QwenLM/qwen-code/pull/7268)

**État désactivé par défaut des Skills.** Un skill peut être désactivé par défaut tout en permettant une activation explicite (soft default), ou désactivé de manière irréversible (hard). Voir le PR [#7357](https://github.com/QwenLM/qwen-code/pull/7357)

**MCP runtime par session.** Les sessions ACP supportent une configuration MCP runtime au niveau session. Voir le PR [#7847](https://github.com/QwenLM/qwen-code/pull/7847)

**Envoi d'images DingTalk.** Le Channel DingTalk supporte l'envoi de messages image. Voir le PR [#7698](https://github.com/QwenLM/qwen-code/pull/7698)

**Routage des forum topics Telegram.** Les réponses du Channel Telegram sont désormais correctement routées vers le forum topic. Voir le PR [#7612](https://github.com/QwenLM/qwen-code/pull/7612)

**Commentaires bilingues pour /review.** Quand la description d'un PR est en chinois, les commentaires de revue publiés par `/review` sont automatiquement en chinois et en anglais. Voir le PR [#7564](https://github.com/QwenLM/qwen-code/pull/7564)

**Lien de connexion OAuth optimisé.** L'URL de connexion OAuth est désormais émise au format hyperlien OSC 8 — cliquez directement dans le terminal pour ouvrir. Voir le PR [#7255](https://github.com/QwenLM/qwen-code/pull/7255)

**Copie en mode VP : texte sémantique préservé.** La sélection et copie en mode VP préserve le texte sémantique plutôt que le formatage rendu. Voir le PR [#7286](https://github.com/QwenLM/qwen-code/pull/7286)

## 👏 Améliorations de l'expérience

**Shift+Enter fonctionne enfin pour les retours à la ligne.** Dans les terminaux comme Ghostty, quand le protocole Kitty n'est pas activé, Shift+Enter était interprété à tort comme Escape, déclenchant l'invite de retour en arrière. Le parsing CSI-u est corrigé : Shift/Ctrl/Alt+Enter produisent un retour à la ligne en mode VP et non-VP. La hauteur des blocs Thinking en streaming ne tremble plus — la fenêtre ne fait que croître, sans suivre les fluctuations de hauteur du terminal. Voir le PR [#7397](https://github.com/QwenLM/qwen-code/pull/7397)

**Les gros collages ne figent plus.** Avant, coller 260K caractères déclenchait 260K événements keypress caractère par caractère, bloquant pendant environ 1,7 seconde. Désormais, les marqueurs de bracketed paste sont interceptés au niveau stdin et traités en bloc — latence réduite à environ 8 ms. Le Footer affiche une barre de progression pendant le collage (`Pasting… ████████░░░░░░░░ 42% (128 KB)`), Ctrl+C interrompt. Voir le PR [#6506](https://github.com/QwenLM/qwen-code/pull/6506)

**Délai de retry streaming configurable.** Nouveaux paramètres `retryInitialDelayMs` et `retryMaxDelayMs` pour ajuster le délai de retry SSE selon la fenêtre de quota d'un provider spécifique. Voir les PR [#7674](https://github.com/QwenLM/qwen-code/pull/7674), [#7666](https://github.com/QwenLM/qwen-code/pull/7666)

**Alignement des colonnes d'icônes TUI.** Toutes les colonnes d'icônes du TUI sont uniformisées à 2 caractères de large — fini l'alignement irrégulier. Voir le PR [#7633](https://github.com/QwenLM/qwen-code/pull/7633)

**Affichage des messages en file corrigé.** Le style et l'ordre des messages en file d'attente sont corrigés. Voir le PR [#7381](https://github.com/QwenLM/qwen-code/pull/7381)

**/copy corrigé.** `/copy` avec un index simple et `/copy <message> <index>` pour sélectionner un bloc de code fonctionnent correctement. Voir les PR [#7789](https://github.com/QwenLM/qwen-code/pull/7789), [#7883](https://github.com/QwenLM/qwen-code/pull/7883)

**Vérification de mise à jour via npm view.** La vérification de version passe de update-notifier à `npm view` — plus fiable. Voir le PR [#7528](https://github.com/QwenLM/qwen-code/pull/7528)

**Alignement du curseur IME.** Le curseur de l'éditeur de méthode de saisie n'est plus décalé après la mise à jour du Footer. Voir le PR [#7711](https://github.com/QwenLM/qwen-code/pull/7711)
