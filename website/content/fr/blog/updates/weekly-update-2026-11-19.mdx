Qwen Code publie cette semaine trois versions stables, v0.27.3 à v0.28.0.

**Le nouveau flagship Qwen4-Max est disponible.** C'est le nouveau modèle phare de Qwen, déjà connecté au dernier Qwen Code.

**Les nouvelles sessions travaillent dans une copie isolée.** Ouvrez plusieurs sessions en parallèle sur le même projet : chacune modifie son propre worktree, votre branche et vos fichiers restent intacts.

**Les résultats des tâches partent directement dans les groupes Feishu, WeCom et DingTalk.** Ajoutez un bot personnalisé dans le groupe, collez son adresse webhook dans le Web Shell : les notifications et les résultats des tâches planifiées arrivent dans le groupe.

## ✨ Nouvelles fonctionnalités

### Le nouveau flagship Qwen4-Max est disponible

Qwen4-Max est le nouveau modèle phare de Qwen : la version stable est sortie le 16 novembre. Il traite le texte, les images et la vidéo, pour le raisonnement complexe, la programmation et les tâches d'agent.

Qwen Code l'a connecté cette semaine. Bailian, plateforme IA Qwen ou abonnement Qwen : Qwen4-Max est utilisable quel que soit votre canal. La profondeur de réflexion compte trois paliers, low, high et xhigh, avec high par défaut ; la réflexion peut aussi se désactiver.

Les images et les vidéos s'envoient directement dans la conversation pour qu'il les comprenne. Sur les canaux Bailian et plateforme IA Qwen, deux réglages économisent des tokens : la durée de rétention du cache passe de 5 minutes par défaut à 1 heure, et le niveau de détail des images peut être réduit.

Ce que vous pouvez en faire :

- Envoyez une capture de votre maquette, il construit la page
- Envoyez un enregistrement d'écran, il démêle les étapes de reproduction d'un bug
- Pour un échec de test difficile à localiser, montez l'intensité de réflexion

Voir cette PR [#17513](https://github.com/QwenLM/qwen-code/pull/17513)

### Les nouvelles sessions travaillent dans un worktree indépendant, les tâches parallèles ne se gênent pas

Plusieurs sessions Web Shell sur le même projet travaillent chacune dans leur propre worktree. Dans un workspace Git de confiance, toute nouvelle session démarre par défaut dans un worktree indépendant — une autre copie de travail du même dépôt : l'historique des commits est partagé, les fichiers se modifient chacun de leur côté. Les modifications des IA restent entre elles, vos fichiers en cours d'édition restent intacts.

Le travail terminé, deux façons de récupérer le résultat : « Créer une branche ici » dans le menu de branche transforme le travail en branche à part entière ; « Transférer en local » ramène les modifications dans votre répertoire d'origine.

Le mode worktree par défaut se désactive : réglez `worktree.defaultForNewSessions` sur false, et les sessions travaillent directement sur la branche courante.

Ce que vous pouvez en faire :

- Ouvrez une session par demande et faites-les avancer en parallèle, sans écrasement
- Vous codez en local pendant que l'IA travaille dans sa copie, sans conflit entre les deux
- Deux sessions essaient chacune une approche de refactorisation, et vous comparez

Voir cette PR [#17228](https://github.com/QwenLM/qwen-code/pull/17228)

### Les résultats des tâches partent directement dans les groupes Feishu, WeCom et DingTalk

Après WeChat, QQ et l'e-mail la semaine dernière, la livraison en groupe arrive : Feishu, WeCom et DingTalk gagnent chacun une connexion « Webhook (envoi uniquement) ». Ajoutez un bot personnalisé dans le groupe, collez son adresse webhook dans la gestion des canaux du Web Shell : les notifications, les résultats d'exécution et les résultats des tâches planifiées arrivent dans le groupe en messages Markdown.

Cette méthode envoie uniquement, sans recevoir les messages du groupe. Pour converser avec l'IA dans le groupe, la connexion bot classique de chaque plateforme reste disponible.

Ce que vous pouvez en faire :

- Programmez « chaque matin à 9 h, résume les PR fusionnées hier » : le résultat part tout seul dans le groupe Feishu du projet
- L'IA lance les tests de régression chaque soir et envoie le résultat dans le groupe WeCom : vous le lisez en arrivant au bureau
- Une tâche longue : posez une notification de fin, le groupe DingTalk la reçoit et vos collègues suivent l'avancement

Voir les PR [#16804](https://github.com/QwenLM/qwen-code/pull/16804), [#17013](https://github.com/QwenLM/qwen-code/pull/17013), [#17224](https://github.com/QwenLM/qwen-code/pull/17224)

### Web Shell : le volume des modifications avant livraison, la progression des tâches en arrière-plan

**Le total des modifications d'une session se voit.** Avant de livrer, vous voulez savoir combien de fichiers ont changé et combien de lignes ont été ajoutées ou supprimées : le panneau de droite gagne une « Vue d'ensemble des modifications ». Les modifications non commitées, celles de chaque PR liée et les autres commits listent chacun leurs fichiers et leurs lignes. Voir cette PR [#17378](https://github.com/QwenLM/qwen-code/pull/17378)

**Les tâches d'arrière-plan s'ouvrent d'un clic sur leur badge.** Au-dessus du champ de saisie, de petits badges apparaissent : un par catégorie — workflows, shell, Monitor et agents d'arrière-plan en cours d'exécution. Un clic saute à la vue d'exécution correspondante. Voir cette PR [#16813](https://github.com/QwenLM/qwen-code/pull/16813)

**La barre latérale filtre les sessions par workspace et par date.** Avec plusieurs workspaces, filtrez par workspace ; les sessions se groupent par date d'activité : vous réduisez le périmètre avant de chercher. Voir les PR [#17244](https://github.com/QwenLM/qwen-code/pull/17244), [#17447](https://github.com/QwenLM/qwen-code/pull/17447)

**Autres améliorations.** Chaque réponse affiche le nombre de hooks déclenchés, le nombre de blocages et le temps passé ([#17015](https://github.com/QwenLM/qwen-code/pull/17015), [#17327](https://github.com/QwenLM/qwen-code/pull/17327)) ; la traduction russe de l'interface est complète ([#17414](https://github.com/QwenLM/qwen-code/pull/17414)) ; les résultats de recherche de sessions sont plus clairs et se parcourent au clavier avec les flèches haut/bas ([#16779](https://github.com/QwenLM/qwen-code/pull/16779)).

## 📊 Autres nouvelles fonctionnalités

**Une session peut déléguer du travail à un autre workspace.** Quand le Web Shell gère plusieurs workspaces, une session confie une tâche à un autre workspace : elle s'exécute avec les instructions et les paramètres de là-bas, le résultat revient, et vous pouvez relancer. La première délégation demande votre confirmation. Voir les PR [#17454](https://github.com/QwenLM/qwen-code/pull/17454), [#17484](https://github.com/QwenLM/qwen-code/pull/17484)

**La liaison de PR se complète à la main, les commentaires hors ligne fusionnent en résumé.** Si la liaison automatique a manqué une PR, tapez `/pr <numéro ou lien de la PR>` pour la lier ; un bouton « Lier une PR » existe aussi dans la vue d'ensemble des sessions et le menu de la barre latérale du Web Shell. Après un arrêt du service, les commentaires accumulés sur la PR liée fusionnent en un seul résumé envoyé dans la session. Voir les PR [#16877](https://github.com/QwenLM/qwen-code/pull/16877), [#17199](https://github.com/QwenLM/qwen-code/pull/17199)

**Le panneau `/memory` règle la mémoire.** Dans le terminal, le panneau `/memory` active ou désactive directement la sauvegarde automatique et le nettoyage périodique ; les fichiers de mémoire au niveau utilisateur et au niveau projet s'ouvrent pour édition. Voir cette PR [#17213](https://github.com/QwenLM/qwen-code/pull/17213)

**La page Goals rassemble tous les workspaces.** Avec plusieurs workspaces enregistrés, les objectifs de tous les workspaces de confiance tiennent sur une page, classés par date ; chaque carte indique son workspace. À la création, vous choisissez le workspace du nouvel objectif. Voir cette PR [#17230](https://github.com/QwenLM/qwen-code/pull/17230)

**Les plugins Mods réécrivent aussi la réflexion.** Après le texte de réponse affiché dans le terminal, les blocs de réflexion dépliés peuvent aussi être réécrits — par exemple, un plugin traduit la réflexion en chinois. Les deux interfaces terminal sont prises en charge. Voir les PR [#16873](https://github.com/QwenLM/qwen-code/pull/16873), [#17443](https://github.com/QwenLM/qwen-code/pull/17443)

**Le Web Shell fonctionne en HTTP simple.** Depuis un autre ordinateur, accédez au Web Shell via `http://<IP de l'ordinateur>:<port>` : les onglets terminal, l'aperçu web et les commandes locales fonctionnent. Voir cette PR [#17196](https://github.com/QwenLM/qwen-code/pull/17196)

**Le canal GitLab se configure dans le Web Shell.** La liste blanche de dépôts accepte les chemins de projet à plusieurs niveaux comme `group/subgroup/project`. Voir cette PR [#16845](https://github.com/QwenLM/qwen-code/pull/16845)

## 👏 Améliorations de l'expérience

**Après compression du contexte, la dernière opération complète reste intacte.** Quand une conversation trop longue déclenche la compression, l'opération la plus récente et son résultat sont conservés tels quels ; seul l'historique plus ancien est résumé. Voir cette PR [#17141](https://github.com/QwenLM/qwen-code/pull/17141)

**Un changement de branche bloqué par des modifications non commitées se règle dans la page.** Choisissez de mettre les modifications de côté ou de les abandonner, puis changez de branche, directement dans l'interface. Voir cette PR [#17364](https://github.com/QwenLM/qwen-code/pull/17364)

**L'état des cartes Goals se lit d'un coup d'œil.** En cours : bleu ; en attente de votre action : ambre. Les objectifs plafonnés affichent des barres de progression pour les tours, les tokens et la durée ; dans une session, le texte long d'un objectif tient sur une ligne. Voir les PR [#17349](https://github.com/QwenLM/qwen-code/pull/17349), [#17133](https://github.com/QwenLM/qwen-code/pull/17133)

**Le tableau de bord de consommation s'ouvre plus vite.** Celui de la page Status du Web Shell. Voir cette PR [#17239](https://github.com/QwenLM/qwen-code/pull/17239)

**Le palier actif est en surbrillance dans les menus de sélection.** Dans la fenêtre de profondeur de réflexion, le palier sélectionné se voit immédiatement ; même affichage pour la liste des modèles et le choix du mode d'exécution. Voir cette PR [#16622](https://github.com/QwenLM/qwen-code/pull/16622)

**Le renommage d'une session s'applique immédiatement.** Le nouveau titre s'affiche dès la confirmation. Voir cette PR [#17006](https://github.com/QwenLM/qwen-code/pull/17006)
