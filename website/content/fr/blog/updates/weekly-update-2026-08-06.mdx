Cette semaine, Qwen Code sort cinq versions stables — de v0.21.2 à v0.21.6 — avec plus de 300 PR fusionnés. Et une grosse annonce : l'app desktop Qwen Code v0.1.0 est officiellement lancée.

**L'app desktop est là !** La semaine dernière, le Web Shell recevait une grosse mise à jour. Cette semaine, il devient une application desktop à part entière : Qwen Code desktop v0.1.0 est lancé, avec des installateurs natifs pour macOS, Windows et Linux, en téléchargement direct sur GitHub Releases.

**L'exécution des tâches devient visible.** La nouvelle vue Session Workflow transforme le plan et la progression en un diagramme : nombre d'étapes, étape en cours, étape en attente, sous-tâche déléguée à quelle IA — tout est là. L'IA vous montre le diagramme avant de démarrer, et elle ne commence qu'avec votre accord.

**Le terminal et le contrôle des permissions se complètent.** Les images générées par l'IA s'affichent directement dans le terminal — plus besoin d'ouvrir le fichier soi-même. Les sous-Agents reçoivent désormais des permissions adaptées à leur tâche : une tâche en lecture seule n'obtient que la lecture, et les combinaisons de permissions courantes se gardent en modèles réutilisables. La compression des longues sessions peut utiliser un modèle dédié moins cher, pour un coût mieux maîtrisé.

## ✨ Nouvelles fonctionnalités

### Qwen Code desktop officiellement lancé : une app native sur les trois grands systèmes d'exploitation

Jusqu'ici, l'expérience desktop de Qwen Code était éparpillée entre deux endroits : l'app desktop Electron et le Web Shell dans le navigateur. Cette semaine, les deux fusionnent : Qwen Code desktop v0.1.0 est officiellement lancé, avec l'interface du Web Shell après sa grosse mise à jour de la semaine dernière. Les installateurs pour macOS, Windows et Linux sont en ligne, en téléchargement direct sur [GitHub Releases](https://github.com/QwenLM/qwen-code/releases#release-desktop-v0.1.0).

Les utilisateurs macOS déjà sur la version Electron n'ont pas de migration manuelle à faire : la nouvelle version inclut un assistant de migration unique, et les mises à jour suivantes suivent automatiquement.

Ce que cela vous permet de faire :

- L'app desktop Qwen Code a les mêmes capacités que la version terminal
- Une expérience cohérente sur les trois grands systèmes d'exploitation
- Vérification automatique des mises à jour — pas de réinstallation manuelle pour les versions suivantes

Voir les PR [#8132](https://github.com/QwenLM/qwen-code/pull/8132), [#8392](https://github.com/QwenLM/qwen-code/pull/8392), [#8511](https://github.com/QwenLM/qwen-code/pull/8511), [#8518](https://github.com/QwenLM/qwen-code/pull/8518)

### Session Workflow : le plan, les sous-tâches et la progression dans un seul diagramme

Une fois une tâche complexe lancée, savoir où en est le plan et ce que fait chaque sous-tâche voulait dire éplucher l'historique de la conversation pour tout reconstituer soi-même.

La nouvelle vue Session Workflow dessine tout cela en un diagramme : chaque étape du plan devient une boîte, les flèches montrent l'ordre, et l'état de chaque étape — en cours ou bloquée — s'affiche en temps réel. Les sous-tâches déléguées par l'IA sont aussi accrochées au diagramme ; un clic montre ce qu'elles ont fait concrètement. Avant de démarrer, l'IA vous montre le diagramme : vous validez, elle commence ; vous refusez, elle repart planifier. Une fois la tâche terminée, le diagramme reste consultable — chaque étape garde la trace de qui l'a faite et de ce qui a été fait.

La fonctionnalité est désactivée par défaut : passez `experimental.sessionWorkflow` à true dans settings pour l'activer. Deux bonus une fois activée : quand une sous-tâche attend votre validation — exécuter une commande, modifier un fichier — la demande remonte directement dans l'interface principale, pas besoin d'aller la chercher dans la sous-tâche ; et les très longues tâches peuvent partir en arrière-plan pendant que la conversation principale continue autre chose, avec une notification à la fin.

Ce que cela vous permet de faire :

- Suivre d'un coup d'œil la progression d'une tâche complexe — une étape bloquée se voit sur le diagramme
- Valider le plan avant le démarrage, pour travailler plus sereinement
- Envoyer les longues tâches en arrière-plan et continuer autre chose dans la conversation principale

Voir les PR [#7580](https://github.com/QwenLM/qwen-code/pull/7580), [#8391](https://github.com/QwenLM/qwen-code/pull/8391), [#8240](https://github.com/QwenLM/qwen-code/pull/8240), [#8303](https://github.com/QwenLM/qwen-code/pull/8303)

### display_image : les images générées par l'IA s'affichent directement dans le terminal

Avant, quand l'IA générait une image, elle vous laissait un chemin de fichier — à vous de l'ouvrir. Désormais, l'image s'affiche directement dans le terminal, visible dès la génération terminée. La couverture de ce numéro a été choisie exactement comme ça : l'IA génère quelques candidates, toutes affichées dans le terminal, et la comparaison se fait directement, sans ouvrir les fichiers une par une. Si le terminal ne supporte pas l'affichage d'images, il vous le dit clairement.

Ce que cela vous permet de faire :

- Une image générée par l'IA se voit aussitôt terminée, sans ouvrir de fichier
- Les graphiques dessinés à partir de données ou les captures d'une page web construite s'affichent aussi directement
- Demander à l'IA de sortir des maquettes ou des captures déjà présentes dans le repo pour les regarder ensemble

Voir le PR [#8217](https://github.com/QwenLM/qwen-code/pull/8217)

### Permissions des sous-Agents : des clés selon la tâche, sans interférence entre tâches parallèles

Quand vous confiez une grosse tâche à Qwen Code, il délègue parfois à quelques « clones » (sous-Agents) qui travaillent en parallèle — l'un lit le code, l'autre lance les tests. Avant, chaque clone avait les mêmes capacités complètes que l'original : lire des fichiers, les modifier, exécuter des commandes. Vous vouliez juste « lire le code et rédiger un résumé », mais il pouvait très bien modifier des fichiers au passage — pas rassurant.

Désormais, les permissions se règlent par tâche :

- **Des clés selon la tâche** : au moment de déléguer, vous pouvez limiter les outils disponibles — une phrase suffit, par exemple « cette tâche est en lecture seule », et la délégation part avec cette contrainte ; toute tentative de modification est refusée sur-le-champ
- **Modèles de permissions** : les combinaisons de permissions courantes se gardent en modèles, dans le répertoire `.qwen/fork-profiles/` du projet ; la fois suivante, un paramètre suffit pour les réutiliser — plus besoin de tout reconfigurer
- **Instructions confidentielles** : une faille corrigée — avant, quand plusieurs clones travaillaient en parallèle, ils pouvaient voir les instructions des autres ; désormais chacun ne voit que les siennes et reste concentré sur sa tâche

Ce que cela vous permet de faire :

- Une tâche en lecture seule n'obtient que la lecture — impossible de modifier des fichiers au passage
- Les combinaisons de permissions courantes deviennent des modèles, réutilisables en une ligne
- Les clones en parallèle travaillent chacun de leur côté, sans interférence

Voir les PR [#8066](https://github.com/QwenLM/qwen-code/pull/8066), [#8148](https://github.com/QwenLM/qwen-code/pull/8148), [#8344](https://github.com/QwenLM/qwen-code/pull/8344)

### Coût de compression : un modèle moins cher peut s'en charger

Quand une longue session déclenchait la compression automatique, seul le modèle principal pouvait relire tout le contexte — cher et lent.

Trois améliorations cette semaine. D'abord, `/model --compaction` permet de dédier un modèle à la compression : un modèle moins cher s'occupe de « résumer la longue conversation », pendant que la conversation principale garde le bon modèle — la qualité ne bouge pas. Ensuite, quand la compression utilise le modèle principal, elle réutilise le contenu déjà mis en cache : réponse plus rapide, historique avec images compris. Enfin, avec les modèles de la famille Claude, passez `generationConfig.cacheRetention` à `"1h"` : la rétention du cache passe de 5 minutes par défaut à 1 heure, et les sessions très espacées ne gaspillent plus leur cache à chaque fois.

Ce que cela vous permet de faire :

- Confier la compression à un modèle moins cher pour des longues sessions plus économiques
- Le modèle principal réutilise le cache pendant la compression — réponse plus rapide
- Les sessions peu fréquentes ne paient plus l'expiration du cache à chaque reprise

Voir les PR [#7818](https://github.com/QwenLM/qwen-code/pull/7818), [#8339](https://github.com/QwenLM/qwen-code/pull/8339), [#8419](https://github.com/QwenLM/qwen-code/pull/8419), [#8048](https://github.com/QwenLM/qwen-code/pull/8048)

### Écosystème Channel : GitLab arrive, cartes interactives DingTalk, gestion du pairing

La semaine dernière, le GitHub Channel arrivait. Cette semaine, l'écosystème Channel continue de s'élargir.

**GitLab est là.** Les todos GitLab et les commentaires @bot deviennent des messages entrants ; vous configurez quelles actions sont confiées à l'IA, et ce qui a déjà été traité ne l'est pas deux fois. Voir le PR [#7862](https://github.com/QwenLM/qwen-code/pull/7862)

**DingTalk a ses cartes interactives.** Le Channel DingTalk supporte les cartes interactives : l'état de l'IA se met à jour sur la carte en temps réel, et quand votre saisie est nécessaire, une question structurée apparaît — plus besoin de lire un long bloc de texte. Les autres plateformes ne changent pas. Voir le PR [#6930](https://github.com/QwenLM/qwen-code/pull/6930)

![Carte interactive DingTalk](https://img.alicdn.com/imgextra/i3/O1CN01rlQ42T6JklK3OTaQ_!!6000000002748-2-tps-1672-942.png)

**La liste de ceux qui peuvent utiliser l'IA se consulte et se révoque.** En connectant une plateforme de chat, on peut activer le mode pairing pour la sécurité : un inconnu qui @ le bot pour la première fois doit d'abord être approuvé par vous. Mais avant, une fois approuvé, aucune liste visible, aucune révocation possible — une mauvaise approbation, ou quelqu'un qui quitte l'équipe, et il continuait d'utiliser votre IA. Désormais, l'éditeur de Channel montre qui est approuvé, permet de révoquer quelqu'un individuellement, et chaque workspace garde sa propre liste. Voir les PR [#8045](https://github.com/QwenLM/qwen-code/pull/8045), [#8081](https://github.com/QwenLM/qwen-code/pull/8081)

**Les Channels GitHub/GitLab se configurent sans mettre les mains dans les fichiers.** Avant, connecter GitHub/GitLab à l'IA voulait dire ouvrir `settings.json` et écrire à la main : identifiants, périmètres, personnes autorisées — un symbole de travers et rien ne marchait. Désormais, le Web Shell a une interface de gestion dédiée : tout se remplit dans des formulaires et se choisit à l'écran, enregistrer suffit, sans toucher au fichier de configuration. Voir le PR [#8310](https://github.com/QwenLM/qwen-code/pull/8310)

**Le GitHub Channel peaufiné.** Si `gh` est déjà connecté en local, le GitHub Channel réutilise directement cette session — pas besoin de créer un token séparé. Les réponses sont aussi plus disciplinées : au plus un commentaire final par événement ; pendant le traitement de l'IA, le commentaire d'origine porte un emoji 👀 temporaire, retiré automatiquement à la fin. Une tâche interrompue peut reprendre après redémarrage. Voir les PR [#8461](https://github.com/QwenLM/qwen-code/pull/8461), [#8033](https://github.com/QwenLM/qwen-code/pull/8033), [#8061](https://github.com/QwenLM/qwen-code/pull/8061), [#8306](https://github.com/QwenLM/qwen-code/pull/8306)

## 📊 Autres nouvelles fonctionnalités

**Auto Recall : recherche automatique de contexte.** La semaine dernière, la recherche de corpus externe était « l'IA consulte à la demande ». Cette semaine, Auto Recall est « une recherche automatique à chaque question » : les résultats sont joints à l'IA comme référence, et les informations sensibles courantes sont filtrées automatiquement. Mutuellement exclusif avec le mode à la demande, déployé par l'administrateur. Voir le PR [#7877](https://github.com/QwenLM/qwen-code/pull/7877)

**Seuil de préchargement des outils.** Nouveau réglage `tools.toolSearch.threshold` : quand il y a peu d'outils, tous sont déclarés dès le démarrage de la session — plus de recherche à la demande en cours de route, réponse plus rapide ; 0 pour revenir au comportement précédent. Voir le PR [#7922](https://github.com/QwenLM/qwen-code/pull/7922)

**/autofix supporte le workspace local.** Avant, `/autofix` ne tournait que dans GitHub Actions. Désormais, lancé directement, il examine et corrige les changements locaux : détecte les problèmes, applique des corrections minimales, lance les vérifications, puis revérifie, jusqu'à ce que tout soit propre ou qu'il soit confirmé que ce n'est pas réparable. Avant de lancer, il précise que les vérifications tournent dans un sandbox et vous demande de confirmer que vous faites confiance au repo. Voir le PR [#8121](https://github.com/QwenLM/qwen-code/pull/8121)

**Vue structurée des résultats de revue dans le Web Shell.** Après un `/review`, les résultats ont une vue dédiée dans le Web Shell : nombre de problèmes, où, comment corriger, avec quelles preuves — tout est là, filtrable par sévérité, avec le rapport complet accessible. Voir le PR [#8402](https://github.com/QwenLM/qwen-code/pull/8402)

**Le reasoning effort de Qwen 3.8 prend effet.** Avec les modèles de la famille qwen3.8-max, les cinq niveaux de `/effort` contrôlent réellement la profondeur de réflexion du modèle — plus un seul niveau actif. Voir le PR [#8472](https://github.com/QwenLM/qwen-code/pull/8472)

**Goal v3 arrive dans le CLI.** La commande `/goal` et le mode interactif utilisent désormais le même runtime : cartes d'état et commandes de cycle de vie sont alignées des deux côtés, l'expérience est cohérente. Voir les PR [#8005](https://github.com/QwenLM/qwen-code/pull/8005), [#8324](https://github.com/QwenLM/qwen-code/pull/8324)

**Masquage des niveaux de skills.** Nouveau réglage `skills.disabledLevels` : masque des niveaux entiers de skills selon leur origine — pratique quand il y a trop de skills et que ça devient le chaos. Voir le PR [#8057](https://github.com/QwenLM/qwen-code/pull/8057)

**Cycle de vie des skills générés automatiquement.** Les skills générés automatiquement, par `/learn` notamment, ont désormais un suivi d'utilisation : inutilisés pendant 30 jours, marqués expirés ; à 90 jours, archivés automatiquement — plus d'accumulation sans fin. Voir le PR [#7846](https://github.com/QwenLM/qwen-code/pull/7846)

**memory.agentMaxTurns.** Un réglage unique pour la limite de tours de l'Agent de mémoire ; 0 pour illimité. Voir le PR [#8171](https://github.com/QwenLM/qwen-code/pull/8171)

**/summary supporte un chemin personnalisé.** `/summary` accepte désormais un paramètre de chemin pour enregistrer le résumé du projet où vous voulez ; le répertoire parent est créé automatiquement. Voir le PR [#8116](https://github.com/QwenLM/qwen-code/pull/8116)

**Capacité et état du daemon.** La limite de sessions par workspace passe de 20 à 32 — plusieurs sessions en parallèle sans toucher la limite ; `/daemon/status` montre l'usage mémoire et la marge restante ; la limite de sous-sessions concurrentes est aussi configurable. Voir les PR [#8235](https://github.com/QwenLM/qwen-code/pull/8235), [#8245](https://github.com/QwenLM/qwen-code/pull/8245), [#8341](https://github.com/QwenLM/qwen-code/pull/8341)

**Extension Chrome en alpha.** L'alpha de l'extension Chrome complète son parcours d'installation, son diagnostic d'exécution et sa validation automatisée dans un environnement Chrome réel. Voir le PR [#6739](https://github.com/QwenLM/qwen-code/pull/6739)

## 👏 Améliorations de l'expérience

**Consulter l'état pendant le streaming.** Pendant que le modèle répond encore, les commandes en lecture seule comme `/status`, `/settings`, `/help` s'exécutent immédiatement — pas besoin d'attendre la fin du tour ; dans le Web Shell, `/stats`, `/about`, `/context` sont aussi exécutables en cours de tour, alors qu'avant ces commandes étaient avalées en silence. Voir les PR [#8130](https://github.com/QwenLM/qwen-code/pull/8130), [#8496](https://github.com/QwenLM/qwen-code/pull/8496)

**Les longues sorties d'outils ne sont plus tronquées.** Les sorties de commandes et les longues réflexions étaient coupées d'office au-delà de 500 caractères ; désormais elles sont repliées par défaut, avec une vue complète dépliable, et le texte intégral est visible aussi dans les sessions exportées. Voir le PR [#8251](https://github.com/QwenLM/qwen-code/pull/8251)

**Le tour reste ouvert quand un Agent en arrière-plan tourne.** Avant, dès que l'IA principale était libre, le Web Shell marquait le tour comme terminé et le repliait — même si un sous-Agent en arrière-plan tournait encore et que des mises à jour arrivaient ensuite, l'état sautait sans arrêt. Désormais, tant qu'un sous-Agent est actif, le tour reste ouvert. Voir le PR [#8413](https://github.com/QwenLM/qwen-code/pull/8413)

**Les blocs Thinking ne tremblent plus, le transcript passe en ligne.** La hauteur des blocs de réflexion en streaming est stable — plus de sauts ; le calque plein écran de transcription est remplacé par un toggle en ligne sur Ctrl+O. Voir le PR [#8077](https://github.com/QwenLM/qwen-code/pull/8077)

**Raccourcis clavier en plus.** Sur macOS, Option+V permet aussi de coller une image du presse-papiers ; le changement de catégorie de la complétion @ utilise Ctrl+Tab / Ctrl+Shift+Tab, pour éviter les conflits avec les raccourcis natifs du terminal. Voir les PR [#8120](https://github.com/QwenLM/qwen-code/pull/8120), [#8074](https://github.com/QwenLM/qwen-code/pull/8074)

**Recherche plus rapide et plus fiable.** La recherche de fichiers est plus rapide ; quand elle échoue, elle retente automatiquement — plus de « aucun résultat » alors que la recherche n'était pas terminée. Voir les PR [#8253](https://github.com/QwenLM/qwen-code/pull/8253), [#7888](https://github.com/QwenLM/qwen-code/pull/7888)

**Détails des tableaux et des boîtes de dialogue.** Fermer la boîte de dialogue d'une cellule de tableau Markdown amélioré ne fait plus sauter la page ; un coup de molette à l'ouverture d'une boîte de dialogue ne fait plus défiler l'arrière-plan par accident. Voir les PR [#8407](https://github.com/QwenLM/qwen-code/pull/8407), [#8089](https://github.com/QwenLM/qwen-code/pull/8089)

**Ctrl+Shift+C rend la copie.** Avant, Ctrl+Shift+C déclenchait la sortie ou l'effacement de l'écran ; le raccourci retrouve désormais son rôle de copie du terminal. Voir le PR [#8011](https://github.com/QwenLM/qwen-code/pull/8011)

**Menu des détails de session.** Dans les mises en page étroites, le menu des détails de session ne déborde plus, et une action « copier l'ID complet de la session » accessible au clavier a été ajoutée. Voir le PR [#8127](https://github.com/QwenLM/qwen-code/pull/8127)
