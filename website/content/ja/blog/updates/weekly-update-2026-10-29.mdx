Qwen Code は今週、v0.26.1、v0.26.2、v0.26.3 の 3 つの正式版をリリースし、357 件の PR がマージされました。

**PR を出したあとは、`/autofix-pr` が引き継ぎます。** あなたのパソコン上で 2 分に 1 回見ます。ビルドが落ちた、同僚からレビューコメントが来た、main とコンフリクトした——直して、検証して、push して、PR にも 1 件ずつ返します。

**定期ジョブは毎回、まずゲートが確認します。** 新しい動きがあるかどうかを、ゲートが先に判定します。変化がなければその回まるごとスキップ。節約の中身はトークンです。

**裏で動いているセッションは、もう 1 つターミナルを開いて `qwen attach` で繋ぎ直せます。** 午前に大きなプロジェクトの修正を頼み、途中でそのウィンドウを閉じた——サービスは動き続けています。午後に別のターミナルから入り直せば、会話はそのまま続きます。

## ✨ 新機能

### PR の自動フォロー：落ちたチェックを直し、レビューコメントに返す

PR を出したあと、CI が落ちていないか、同僚から何かが言われていないか、main とコンフリクトしていないか——戻ってきて自分で見て処理する必要がありました。いま `/autofix-pr <PR 番号>` を実行すると、Qwen Code がローカルでこの PR につき、問題が出たら自分で直します。

たとえば lint が落ちれば、その job のログを読み、直してからリポジトリ自身のチェックで検証し、通ったあとでコミットして push、最後に PR 内で「何を直したか」に 1 行返します。変更はすべて別の worktree で行い、あなたが書いているディレクトリには触りません。2 分に 1 回チェックし、新しく出たものだけ処理します。詳しくは PR [#15385](https://github.com/QwenLM/qwen-code/pull/15385)、[#15057](https://github.com/QwenLM/qwen-code/pull/15057)

使い続けるための操作も今回揃いました。`/autofix-pr status` で状態を確認し、`/autofix-pr resume <PR 番号>` であとから開いたセッションにフォローを再開できます。自動実行を選ぶ監視なら、修復はバックグラウンドで走ります。通常の起動は、これまでどおり承認設定に従います。詳しくは PR [#15510](https://github.com/QwenLM/qwen-code/pull/15510)、[#15548](https://github.com/QwenLM/qwen-code/pull/15548)、[#15578](https://github.com/QwenLM/qwen-code/pull/15578)

Web Shell に `PR watch`（PR 監視）ページが増えました。プロジェクトごとの監視状態、push した回数、人が判断すべき項目を一覧できます。現在の Web Shell セッションから動かした監視は、このページから元の会話へ入ったり、停止をかけたりできます。起動の前に、PR ブランチへ未コミットの変更や未 push のコミットが残っていると、一度止いて状況を説明します。詳しくは PR [#15668](https://github.com/QwenLM/qwen-code/pull/15668)、[#15736](https://github.com/QwenLM/qwen-code/pull/15736)

こんなことに使えます：

- 終業前に PR を出しておき、翌朝開くと、落ちたチェックが直されて push まで終わっている
- 同僚のレビューコメント 1 件ごとに返りがつき、直せないものは判断待ちとして残る
- main の更新でコンフリクトが起きたときは、他の人の作業を先に取り込み、そのあとリポジトリのチェックをもう 1 度回す

### 定期ジョブのゲート：確認コマンドを 1 本おいて、変化があったときだけモデルが動く

数分に 1 回、新しい動きの有無を見ておいてほしくなることがあります。PR のビルドが落ちていないか、新しい issue が届いていないか。決めどきは必ず来るのに、10 回に 8 回は中身がなく、会話はその回まるごと走って「特にありません」で終わっていました。

こうした繰り返しタスクには、ゲートを 1 つ置けるようになりました。自分で決める小さな確認で、毎回まずこれを実行します。この段階はただのコマンド 1 本です。確認で何も出なければ、そこで終わり。何か出てはじめてモデルが先へ進み、確認が見たものをそのまま受け取ります。たとえばビルドを 2 分に 1 回チェックさせるなら、ビルド結果だけを返すスクリプトを 1 本入れます。ビルドが無事なら、その回はゲートだけで済みます。落ちていれば、その 1 行を渡されてモデルがログを読み、直しにいきます。詳しくは PR [#15069](https://github.com/QwenLM/qwen-code/pull/15069)

ゲートのコマンドはあなたが用意するもので、決まりは「何もないときは静かに、あるときだけ出す」です。たいてい小さなスクリプトになります。スクリプト自体を Qwen Code に書かせてから、タスクに載せてもかまいません。

Web Shell の定期ジョブのフォームで入力するのが、このゲートです。ジョブのカードにはゲートの最新結果が出ます。`Run now`（今すぐ実行）を押すとゲートが先に走り、出力があったときだけジョブが動きます。先に書いた PR 監視の機能は、このゲートの上に乗っています。詳しくは PR [#15211](https://github.com/QwenLM/qwen-code/pull/15211)

こんなことに使えます：

- ビルド結果を 10 分に 1 回確認し、落ちた回だけモデルが動く
- 新しい issue が届いたかを見張り、届いてから中を読ませ、分類させる
- 10 回に 8 回が空振りになる作業をここに乗せて、トークンを節約する

### qwen attach：裏で動いているセッションを、ターミナルから取り戻して続ける

先週 `qwen daemon` の管理コマンドが揃って、ローカルサービスは裏で動き続けられるようになりました。サービスの中のセッションも同じです。作ったターミナルのウィンドウを閉じて別の用に回しても、そのセッションはそのまま残っています。当時の戻り道は、ブラウザの Web Shell を開くことだけでした。

いまではターミナルで `qwen attach --session <セッション ID>` を実行すると、そのセッションに再加入できます。これまでのやり取りは普通に表示され、ターミナルで打った 1 行は新しい発言として送られ、返事が終わると入力欄がまた出ます。たとえば午前に起動したサービスへ、午後に別のターミナルから入り直して続きを聞けます。詳しくは PR [#15209](https://github.com/QwenLM/qwen-code/pull/15209)

セッション ID は Web Shell のそのセッションの URL にあります。`/session/` のうしろの文字列です。入り直して見えるのは、出力の流れと、入力する場所の 2 つです。補完、履歴を辿る、承認カード——ターミナルで慣れた機能は、この窓の対象外です。

こんなことに使えます：

- 大きなプロジェクトの修正を頼んで途中でターミナルのウィンドウを閉じ、戻って入り直し、「どこまで進んだ」と 1 回聞く
- Web Shell から出した長いジョブに「ドキュメントも更新しておいて」と 1 行足したくなり、ターミナルに戻って言い足す
- サービスを開発サーバーで動かしているなら、SSH で入り、そのターミナルからセッションに繋ぎ直して進捗を見、ひとこと送る

### Web Shell：セッションとワークスペースが、サイドバーで見つけやすく、まとめやすい

**サイドバーに `Recent sessions`（最近のセッション）が 1 欄増えました。** プロジェクト内の会話と、ワークスペースに紐づいていない会話が、直近の活動順に並んで一緒に見られます。複数プロジェクトを同時に回しているとき、セッションは `Recent sessions` でまとめて確認できます。詳しくは PR [#14904](https://github.com/QwenLM/qwen-code/pull/14904)

**会話が派生させた Agent の作業を、その会話の下にたためます。** バックグラウンドで走る Agent、ついでに開いた分岐タスク、別セッションで走る定期ジョブ——これらのセッションは、派生元の会話の下に付きます。同じ用件の何本かが並び、メインの会話と派生した枝がひと目で分かれます。詳しくは PR [#15714](https://github.com/QwenLM/qwen-code/pull/15714)

**ワークスペースは並べ替えも、Git の URL を貼っての新規作成もできます。** ワークスペースメニューに `Move up` と `Move down` が増え、毎日使うプロジェクトを一番上に固定できます。プロジェクトの追加では Git リポジトリを選べ、URL を貼れば、コードを取得してそのままそのワークスペースに入ります。詳しくは PR [#15360](https://github.com/QwenLM/qwen-code/pull/15360)、[#15361](https://github.com/QwenLM/qwen-code/pull/15361)

**ワークスペースに別のディレクトリも足したいときは、`Settings`（設定）で直せます。** `Settings` に `Workspace directories` が増え、一覧・追加・削除ができます。足したパスは、そのワークスペースで動いているすべてのセッションに即反映されます。詳しくは PR [#15393](https://github.com/QwenLM/qwen-code/pull/15393)

**その他の改善。** 新しい会話の名前は、AI に聞いた最初の 1 文がそのまま使われます（[#15689](https://github.com/QwenLM/qwen-code/pull/15689)）。アーカイブした会話は `Settings` 内の独立した 1 箇所に移り、ワークスペース別のグループ化と由来での絞り込みができます（[#15557](https://github.com/QwenLM/qwen-code/pull/15557)）。返信 1 件をまるごと 2 種類の形でコピーでき、`Copy content` はプレーンテキスト、`Copy Markdown` は元のソースです（[#15345](https://github.com/QwenLM/qwen-code/pull/15345)）。回答に使う言語は、`Settings` の中で界面言語の横に出て、そこから選べます（[#15363](https://github.com/QwenLM/qwen-code/pull/15363)）。

## 📊 その他の新機能

**インタラクティブカードで調整した値を、会話に戻してそのまま続けられます。** カードは計算を終えるとそこで止まり、その値のセットでモデルに追加で質問したければ、自分で書き写して送っていました。カードにもう 1 つ操作が増え、確定中の値のセットを元の会話へ返せます。送る前に凍結済みの一覧を見せて、確認がすんでから送ります。詳しくは PR [#15333](https://github.com/QwenLM/qwen-code/pull/15333)

**Codex に貯めたメモリを取り込めるようになりました。** まずプレビューを見て、どの部分を取り、どのスコープに書き出すかを決めます。裏ではそのワークスペースで決まっているモデルが整理し、整理が終われば Qwen Code 自身のメモリに入ります。これまでどおり検索、利用、忘却ができます。コマンドラインでは `qwen memory import codex` を実行します。先に `--dry-run` を付けてもよいです。詳しくは PR [#14281](https://github.com/QwenLM/qwen-code/pull/14281)

**自分のパソコンで、ローカルサービスと Managed Agent を 1 本の起動コマンドでまとめられます。** `qwen serve --managed --open` を実行すると、通常のセッションとマネージドセッションが同じ画面に並び、データベースも一式ついてきます。Node.js 22 以上と Java 21 が必要です。まだ実験的な段階で、対象はあなたのパソコン 1 台だけにかぎります。詳しくは PR [#14928](https://github.com/QwenLM/qwen-code/pull/14928)

**マネージドセッションは、実行中に割り込めて、権限もセッション単位で設定できます。** 作業中に打ち込んだ発言と呼び出したファイルはキューに入り、安全な節目でモデルへ渡されます。並んでいるものは書き換えも取り消しもできます。アイドル時は、そのセッションだけに向けて allow・ask・deny のルールを書けます。承認モードを Auto に選ぶこともできます。詳しくは PR [#15449](https://github.com/QwenLM/qwen-code/pull/15449)、[#15448](https://github.com/QwenLM/qwen-code/pull/15448)

**マネージドセッションにファイル送信、Web ページ取得、TODO 管理が増え、新規セッションは既定で作業をサブ Agent に任せます。** ブラウザから 1 つのファイルを指定ワークスペースへ送ると（8 MB まで）、パスがそのままセッションに入ります。公開されている Web ページの取得や、自身の TODO リストの管理もできます。詳しくは PR [#15586](https://github.com/QwenLM/qwen-code/pull/15586)、[#15313](https://github.com/QwenLM/qwen-code/pull/15313)、[#15089](https://github.com/QwenLM/qwen-code/pull/15089)、[#15171](https://github.com/QwenLM/qwen-code/pull/15171)

**Web 検索に、自社ゲートウェイのドメインを足せます。** モデルへの通信をすべて自社で建てたゲートウェイに通しているチームでは、検索だけが自社のドメインを判別できず、選べるのはソースを直すことだけでした。いまは設定を 1 行足すだけで、そのドメインと配下のサブドメインが認識されます。詳しくは PR [#15638](https://github.com/QwenLM/qwen-code/pull/15638)

## 👏 体験改善

**Workflow モードをセッションに覚えさせられます。** `--workflow-mode on` または `/workflows mode on` で開くと、そのセッションの以降の 1 回ごとにこの指針が付きます。復元、分岐、巻き戻し、消去はそれぞれ決まった挙動があり、切り替えが失敗したら元の状態に戻ります。2 種類のターミナル画面どちらも現在のモードを表示し、Docker サンドボックスで走る場合もこのスイッチが追随します。詳しくは PR [#15422](https://github.com/QwenLM/qwen-code/pull/15422)、[#15743](https://github.com/QwenLM/qwen-code/pull/15743)

**もう 1 つのターミナル画面（OpenTUI）も、今回かなり追いつきました。** 入力欄が空のときにスペースキーで発話でき、文字起こし、取り消し、マイクの許可確認、録音状態までつながりました。いったん抜けて入り直すと、録った文字・画像・ツールの結果が見え、巻き戻しは会話・次のリクエスト・下書きがその時点へ一緒に戻ります。チェックポイントは、変更が実際に承認された瞬間に書き出されます。拡張の「Discover」と「Sources」の 2 欄が、インストール完了まで通りました。実行の準備としてパソコンに Bun を用意しておく必要はなくなりました。詳しくは PR [#15617](https://github.com/QwenLM/qwen-code/pull/15617)、[#15384](https://github.com/QwenLM/qwen-code/pull/15384)、[#15389](https://github.com/QwenLM/qwen-code/pull/15389)、[#15671](https://github.com/QwenLM/qwen-code/pull/15671)、[#14959](https://github.com/QwenLM/qwen-code/pull/14959)

**コンテキストが埋まりかけたとき、1 バッチのツール結果は残量にあわせて割り振ります。** バッチ全体で残り容量を分け合い、守るべき文字・画像・構造は先に確保します。完全な原文はこれまでどおり書き出されて、あとから取り出せます。切り捨ての 1 文が確保できないほど残量が少ないバッチは、通常の圧縮に任せます。詳しくは PR [#13599](https://github.com/QwenLM/qwen-code/pull/13599)

**100 万トークンのコンテキストを持つモデルを見分けられるようになりました。** qwen4 系と、招待制の qwen-latest-series は、以前は既定の小さいウィンドウに落ちていましたが、いまは 100 万トークンのウィンドウで計算します。詳しくは PR [#15758](https://github.com/QwenLM/qwen-code/pull/15758)、[#15762](https://github.com/QwenLM/qwen-code/pull/15762)

**`Settings` の一覧に出るモデルは、プロバイダーがいま実際に提供しているものだけになりました。** 一覧に提供終了の名前が残ること、思考オフを選んでも切れないモデルがあること、DeepSeek に貼った画像が非対応扱いになること——この 3 つが直りました。標準の API Key で Alibaba ModelStudio に接続すれば、キーとリージョンを入れるだけで、自分のアカウントで使えるモデルを直接選べます。詳しくは PR [#15184](https://github.com/QwenLM/qwen-code/pull/15184)、[#15189](https://github.com/QwenLM/qwen-code/pull/15189)、[#15164](https://github.com/QwenLM/qwen-code/pull/15164)
