Qwen Code は今週、v0.28.3、v0.28.4、v0.28.6 の 3 つの正式版をリリースしました。

**別の会話に作業を任せられます。** Web Shell の `/send` で作業を別の会話へ渡すと、相手が続きを引き受け、完了後にあなたへ報告します。

**定期ジョブの結果を指定アドレスへ送れます。** チャンネル管理で Generic Webhook を追加して受信アドレスを入力すると、定期ジョブの実行結果が自動で届きます。

**生成ファイルは Artifacts ページに集まります。** すべての会話が生成したレポートやエクスポートファイルが Artifacts ページに集まり、会話を 1 つずつ開かずにその場でプレビュー・ダウンロードできます。

## ✨ 新機能

### /send でタスクを別の会話へ送る

あなた自身も `/send` で作業を送れます。Web Shell で `/send さっき失敗したテストを調べて` と入力すると、同じワークスペースに新しい会話が立ち上がり、タスクを引き継ぎます。`--workspace` でワークスペースを選べます。`--session-id` で既存の会話を指定することもできます。タスクが完了すると、現在の会話が結果を伝えてくれます。

AI も同じように作業を渡せます。AI が自分で開いた会話に加えて、あなたが手動で開いた会話にも作業を渡せます。YOLO モードをオンにしていれば、別のプロジェクトフォルダへの派遣も確認ダイアログなしで進みます。

こんなことに使えます：

- 会話 A で資料を調べ終えたら、会話 B へ送って企画書の続きを書いてもらう
- メイン会話でコードを書き続け、テストの調査は別の会話に任せる
- 右側パネルで進捗を見ながら、相手会話の確認リクエストや質問にその場で対応する

詳しくは PR [#17539](https://github.com/QwenLM/qwen-code/pull/17539)、[#17818](https://github.com/QwenLM/qwen-code/pull/17818)

### チャンネル：定期ジョブの結果を指定アドレスへ送信、実行中の軌道修正もその場で

**定期ジョブの結果を指定アドレスへ送れます。** Feishu、WeCom、DingTalk グループへの結果送信に加え、今週はプラットフォームを問わず使える Generic Webhook が加わりました。チャンネル管理に HTTPS の受信アドレスを入力すると、通知と定期ジョブの結果がそのアドレスへ届きます。詳しくは PR [#17405](https://github.com/QwenLM/qwen-code/pull/17405)

**チャンネルメッセージで実行中のタスクを軌道修正できます。** inject 配信モードを使えるのは、ターミナルで独立起動したチャンネルです。AI の作業中に届いたメッセージは現在のターンへ直接渡され、AI が途中で読んで方向を調整します。タスクの途中で気づいたことがあれば、一言送るだけで修正できます。詳しくは PR [#15634](https://github.com/QwenLM/qwen-code/pull/15634)

**QQ ボットがファイルをチャットへ送れます。** QQ チャンネル設定で `fileTools` を `true` にして（デフォルトはオフ）チャンネルを再起動すると、AI がワークスペースで生成したファイル・画像・動画・音声をそのままチャットへ送れます。詳しくは PR [#15450](https://github.com/QwenLM/qwen-code/pull/15450)

こんなことに使えます：

- 定期ジョブの実行結果を、自分のシステムへ自動送信
- タスクがずれたらグループで一言追加。AI がその場で方向を修正
- QQ でそのまま作業を指示し、生成ファイルはそのチャットへ返してもらう

### Web Shell：Artifacts ページで成果物を一括確認、入力履歴はデバイス間で共有

**会話の成果物を 1 ページで閲覧・ダウンロードできます。** ローカルデプロイの Web Shell に Artifacts ページが加わりました。ワークスペース内のすべての会話が生成したレポート、エクスポート、Web ページプレビューのスナップショットが 1 ページに集まり、そのままプレビュー・ダウンロードできます。詳しくは PR [#18071](https://github.com/QwenLM/qwen-code/pull/18071)、[#17689](https://github.com/QwenLM/qwen-code/pull/17689)

**入力履歴をデバイス間で共有できます。** パソコンで入力したプロンプトやコマンドを、スマホで同じワークスペースを開いて入力履歴から辿れます。スマホからパソコンへの共有も同じです。詳しくは PR [#18120](https://github.com/QwenLM/qwen-code/pull/18120)

**サイドバーで各会話の状態がわかります。** 目標付きの会話には目標マークが付き、色は Goals ページと同じです。実行中は青、あなたの対応待ちは琥珀色です。前回のターンが中断された会話には Continue バッジが付き、再起動後にどの会話を再開すべきか一目でわかります。詳しくは PR [#17515](https://github.com/QwenLM/qwen-code/pull/17515)、[#18044](https://github.com/QwenLM/qwen-code/pull/18044)

**スマホのフォローアップ提案をタップで選べます。** 提案は入力欄の上のタップ可能なチップになり、タップすると入力欄に入り、編集してから送信できます。詳しくは PR [#17918](https://github.com/QwenLM/qwen-code/pull/17918)

**その他の改善。** Generated UI カードのボタンからテキストを直接コピーしたり、小さなファイルをダウンロードしたりできます（[#18158](https://github.com/QwenLM/qwen-code/pull/18158)）。タッチスクリーンの編集バーはスマホと iPad で 1 行表示を維持します（[#18126](https://github.com/QwenLM/qwen-code/pull/18126)）。

## 📊 その他の新機能

**繁体字中国語の UI。** Web Shell と VS Code 拡張に繁体字中国語が加わりました。言語選択で「繁體中文 [zh-TW]」を選ぶだけです。詳しくは PR [#17421](https://github.com/QwenLM/qwen-code/pull/17421)

**返信の表示翻訳。** 設定で `general.displayLanguage` をオンにして簡体字中国語を選ぶと、モデルが英語で書いた返信と展開した思考が、ターミナルと Web Shell で中国語表示になります。アーカイブ、コピー、その後の会話には原文がそのまま使われます。デフォルトはオフで、ターミナルの `/settings` か Web Shell の設定ページでオンにできます。詳しくは PR [#18175](https://github.com/QwenLM/qwen-code/pull/18175)

**Microsoft Teams チャンネル拡張。** `@qwen-code/channel-msteams` 拡張を別途インストールし、Azure ボットを設定すると、Teams の個人チャットとグループでボットを @ メンションして作業を指示できます。話題ごとに会話が独立して進みます。詳しくは PR [#15620](https://github.com/QwenLM/qwen-code/pull/15620)

**CLI のスクリーンリーダーモード。** ターミナルにスクリーンリーダーモード（実験的）が加わりました。起動時に `--screen-reader` を付けると、返信の完了後に 1 回読み上げ、履歴はキーボードで辿れます。現在選択中の操作や承認待ちの操作も読み上げます。デフォルトのグラフィカル UI はそのままです。詳しくは PR [#17500](https://github.com/QwenLM/qwen-code/pull/17500)

## 👏 体験改善

**Web Shell がより速く開きます。** ターミナルは使うときに読み込み、大きな会話記録は圧縮してから転送します。履歴会話開いて内容が表示されるまでの実測時間は、約 1.3 秒から 0.8 秒に短縮されました。詳しくは PR [#17840](https://github.com/QwenLM/qwen-code/pull/17840)、[#11220](https://github.com/QwenLM/qwen-code/pull/11220)、[#18223](https://github.com/QwenLM/qwen-code/pull/18223)

**バックグラウンドタスクのバッジに「何をしているか」を聞けます。** 入力欄の上の各バッジに疑問符マークが増えました。クリックすると、AI がそのタスクの内容と起動理由をわかりやすい言葉で説明し、回答は隣の質問パネルに表示されます。現在の会話とタスクはそのまま進みます。詳しくは PR [#17398](https://github.com/QwenLM/qwen-code/pull/17398)

**コマンド実行中の追加メッセージにもその場で返答。** AI がコマンドを実行中にメッセージを追加すると、コマンドはバックグラウンドへ移って実行を続け、あなたのメッセージにはその場で返事が届きます。詳しくは PR [#17926](https://github.com/QwenLM/qwen-code/pull/17926)

**MCP 設定の変更は即時反映。** 設定で MCP サーバーを追加・削除すると、実行中の会話に自動で反映されます。再起動は不要です。詳しくは PR [#17743](https://github.com/QwenLM/qwen-code/pull/17743)

**フォローアップ提案がより速く生成されます。** 提案の生成時は会話の短い一部だけを参照します。詳しくは PR [#17532](https://github.com/QwenLM/qwen-code/pull/17532)

**Mods の書き換えが Web Shell にも反映。** Web Shell でも、返信と展開した思考がプラグインによる書き換え後のテキストで表示されます。履歴、コピー、検索、ブランチには原文がそのまま使われます。`experimental.mods` をオンにする必要があります。詳しくは PR [#17718](https://github.com/QwenLM/qwen-code/pull/17718)、[#17920](https://github.com/QwenLM/qwen-code/pull/17920)

**ワークフローの段階を一覧プレビュー。** ワークフローが通る段階は、開始時にすべて一覧表示されます。未実行の段階は先にマークされ、実行が進むと実際の進捗が表示され、全体がどこまで進んだか一目でわかります。ワークフローを使うには、先に環境変数 `QWEN_CODE_ENABLE_WORKFLOWS=1` で有効化する必要があります。詳しくは PR [#17782](https://github.com/QwenLM/qwen-code/pull/17782)

**Gemini 4 と Kimi K3 の思考の深さが自動対応。** この 2 つのモデルを接続すると、思考の深さの段階が自動で使えるようになります。詳しくは PR [#18039](https://github.com/QwenLM/qwen-code/pull/18039)、[#18095](https://github.com/QwenLM/qwen-code/pull/18095)

**フォールバックモデルへの切り替えがより速く。** `experimental.modelAvailabilityTracking` をオンにすると、このターンでキャパシティ不足により失敗したモデルはスキップし、次のフォールバックモデルを直接使います。失敗したモデルは次のターンで再試行します。デフォルトはオフです。詳しくは PR [#17377](https://github.com/QwenLM/qwen-code/pull/17377)
