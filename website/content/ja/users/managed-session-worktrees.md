# Managed Session ワークツリー


サポートされているローカル Managed デプロイメントでは、Session 作成時に Git プロジェクトを選択します。composer の下にあるワークスペースの横の Git branch ボタンを開き、**Worktree** を選択します。ピッカーが閉じます。最初のメッセージを送信すると、現在の HEAD から独自のブランチに隔離されたチェックアウトが自動的に作成されます。ブランチやディレクトリを入力するフォームはありません。未コミットのファイル、無視された設定、インストール済みの依存関係はソースディレクトリに残ります。

送信前に、**Current branch** を選択するか、Worktree チップをクリアして、ソースブランチで直接作業できます。チップには、隔離が選択されていない場合、**main** などの実際のソースブランチが表示されます。

Session は準備を報告し、同じストレージを使用する他のツールを待つことがあります。ファイル参照とワークスペースのアップロードは、ワークツリーの準備が整った後に利用可能になります。プロジェクトの指示はターゲットディレクトリから取得されます。Managed モデル、承認、Skills、MCP、Extensions の設定は Session ピンを保持します。

ホームチャットでは、セッションの詳細情報カードにワークツリーのステータス、ブランチ、ベースコミットが含まれます。準備が整ったワークツリーの詳細は会話の上部を占有しなくなりました。準備とエラーメッセージは、必要に応じて引き続き表示されます。

チャットを閉じる、アーカイブする、または削除しても、チェックアウトとブランチは保持されます。保持されているディレクトリを確認するには、同じワークスペースの新しいタスク composer ポップオーバーから **Session worktrees** を開きます。クリーンアップの前に、Session を閉じてバックグラウンド作業を完了させてください。最初に、追跡済み/未追跡/無視されたコンテンツをコミットまたは他の方法で保存してください。クリーンアップはクリーンなチェックアウトのみを削除し、すべてのブランチを保持します。変更をソースにマージすることはありません。

デプロイメントでは `qwen.managed-agent.runtime-broker.session-worktrees-enabled` を有効にします。デフォルトではオフです。`qwen serve --managed` は対象となるローカルホストを有効にします。このバージョンでは、ローカルの macOS/Linux ストレージ、Session 分離された永続的なローカルプロセスワーカー、および Git 2.40 以降がサポートされています。リポジトリとその Git 共通ディレクトリは、登録されたストレージルート内に存在する必要があります。Git メタデータが別の場所にある既存のリンクされたチェックアウトの場合は、元のチェックアウトを選択するか、管理者に両方を含むルートの登録を依頼してください。このバージョンでは SSH と CSI はサポートされていません。

準備が整った Session を再起動すると、元のチェックアウトが再利用されます。不足しているまたは置き換えられたディレクトリは実行をブロックします。Git がワークツリーを作成または削除している間にサーバーが強制終了され、未検証の元の Git プロセスが残っている場合、操作はブロックされたままになり、メンテナンスホールドも維持されます。再チェックでは強制的に回復されません。この場合の macOS の自動回復はこのバージョンの範囲外です。元の実行が調整されるまで、ディレクトリとブランチを保持してください。

パブリック Session 作成リクエストは `worktree: {"base_ref":"main"}` を追加します。`worktree: {}` は HEAD を選択し、省略すると現在のディレクトリが使用されます。明示的に認可された `workspace` を送信し、再試行時に同じ Idempotency-Key を保持してください。後続の入力を送信する前に、返された Session の `worktree.state` をクエリしてください。

この開発バージョンは共有 V1 スキーマベースラインを更新します。そのベースラインから再作成された開発カタログを使用してください。古いカタログのアップグレード移行は含まれていません。
