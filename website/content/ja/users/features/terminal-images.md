# ターミナルイメージ

Qwen Code は、アシスタントの応答や完了したツールの結果からのイメージパーツを、インタラクティブなターミナル UI に直接表示できます。この表示パスは Markdown レンダリングとは別であり、Markdown の `render` モードと `raw` モードの両方で同じように動作します。

## イメージが表示される場所

アシスタントの応答では、テキストとイメージは元の順序を保持します。ツール行には、成功、失敗、キャンセルの結果に関わらず、結果テキストに続いてイメージが表示されます。

ヘッドレス、ACP、デーモン/Web Shell、IDE 統合を含むその他の出力サーフェスでは、イメージパーツはレンダリングされません。WeChat（weixin）、WeCom、および DingTalk チャネルは、`[IMAGE: ...]` マーカーフローを通じてエージェント生成のイメージファイルを配信できます。その他の IM チャネルは現在アウトバウンドイメージを配信しません。

## ターミナルサポート

| 環境                                                          | イメージ表示                                                                             |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| tmux や SSH なしの直接 Kitty または Ghostty TTY                | ネイティブターミナルイメージ配置                                                          |
| `chafa` がインストールされたその他のターミナル                  | 256 色 ANSI プレビュー（iTerm2、Warp、tmux、SSH セッションを含む）                       |
| 互換性のあるレンダラーがない、またはスクリーンリーダーモード（インラインイメージパーツ） | ターミナルイメージシーケンスの代わりに `[image: 1024x768 png]` のような決定的なテキスト |

## 制限とフォールバック

インラインピクセルプレビューには、表示制限内の有効な PNG データが必要です。合計 64 メガピクセル、各辺最大 1,000,000 ピクセルです。他のイメージ形式、無効な PNG、およびこれらの制限を超えるインライン PNG は、テキストプレースホルルダーとして表示されます。

8 MiB を超えるインラインイメージペイロードはピクセルレンダリングされません。ほとんどの oversized ペイロードは TUI 履歴に入る前にドロップされますが、制限をわずかに超えるペイロードはテキストプレースホルダーとして残る場合があります。これは、admission がエンコードされたサイズに基づくためです。各アシスタントの応答またはツール行には最大 4 つのイメージが表示され、残りは `[+2 more images]` のようなマーカーで報告されます。

## セッション履歴とメモリ

ツールのイメージパーツは結果とともに保存され、セッション再開後に再構築できます。アシスタントイメージはライブでレンダリングされますが、現在永続化されていないため、`--continue` と `--resume` はそれらのイメージなしでアシスタントテキストを復元します。

長時間のセッションやイメージの多いセッションでメモリを制限するために、TUI は古い表示イメージを `[Old assistant image content cleared]` や `[Old tool result content cleared]` のようなマーカーに置き換える場合があります。これはライブビューにのみ影響します。ツールのイメージパーツはセッションレコードに保持され、再開後に表示されます。
