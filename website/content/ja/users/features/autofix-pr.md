# プルリクエストの自動修正

`/autofix-pr` はローカルの Qwen Code セッションからプルリクエストを 1 つ監視し、発生した問題（失敗した CI チェック、信頼する人からのレビューフィードバック、マージコンフリクト）を修正します。各修正は専用のワークツリーで作成・検証され、PR ブランチにプッシュされ、PR 上で回答されます。すべてあなたの git と `gh` の ID で行われます。PR がマージまたはクローズされると自動的に停止します。

```text
/autofix-pr [<pr-number>|<pr-url>] [--once] [--every <minutes>] [--no-reply] [--yes] [instructions...]
/autofix-pr status [<pr-number>]
/autofix-pr resume [<pr-number>]
/autofix-pr stop [<pr-number>]
```

- PR 引数がない場合: 現在のブランチのヘッドである PR。
- `--once`: 1 回だけチェックと修正を行い、スケジュールは設定せず、その後監視を終了します（後で `--once` を実行すると、PR の履歴から新しく開始されます）。このセッションで既に監視中の PR では、実行中の監視はそのまま維持されます。
- `--every <minutes>`: チェック間隔。1、2、5、10、15、30、60 のいずれか。デフォルトは 2。
- `--no-reply`: 修正をプッシュするが、PR には何も投稿しない。
- `--yes`: 開始確認をスキップする。ダイアログを表示できない環境で必要。
- フリーテキストは各修正に渡されます。例: `/autofix-pr 123 do not change the public API`。

## 開始前に

- `gh` がサインイン済みで、PR ブランチへのプッシュアクセスがあること: 同一リポジトリの PR への書き込みアクセス、または自分のフォーク、またはメンテナーからの編集を許可するフォーク。
- PR のリポジトリのクローンから、それに対する 1 つの git リモートを持つ状態で実行します。デーモンセッション（`qwen serve`、Web Shell）では、そのクローンがセッションの作業ディレクトリ内にある必要があります。デーモンは修正エージェントのコマンドをそこでのみ実行するため、`prepare` はクローンがそこにない PR を拒否します。そこでの監視はセッションに紐づいた永続的なスケジュールされたタスクです。デーモンはアイドルになってもそのセッションを回収せずに常駐させ続け、タスクは Scheduled tasks ページに表示されるため、ブラウザタブを閉じても監視は終了しません — 終了するには `/autofix-pr stop` を使います。タスクはデーモン再起動後に再ハイドレーションされます。再起動はゲートのプロセス内承認を削除するため、ゲートにはその後、無人で実行できる承認モードまたは保存済みルールが必要になり、最初にブロックされた実行で追加するルール名が示されます。1 つのデーモン会話につき 1 つのスケジュールされたタスクが運ばれるため、2 つ目の監視には別の会話が必要です。再起動はセッションが監視のために確認した内容も削除します。`/autofix-pr resume <n>` で再度確認するまで、ヘルパーも修正もシェルコマンドと同様に承認モードに従います。
- このスキルはヘルパーを `autofix_pr` ツール経由で実行します。このセッションで開始または再開した監視では、ラウンドのヘルパー（プッシュや返信を含む）は確認なしで実行されます。監視の開始・再開、スケジュール設定、および別のセッションからの引き継ぎ（`/autofix-pr stop <n>` で PR を指定することもこれに当たります）は毎回確認を求めます（[Auto Mode](./auto-mode.md) ではクラシファイアが判断しますが、開始は常にあなたが確認する必要があります）。`gh pr view` とスケジュールされたタスクの作成も同様です。シェルコマンドを拒否するルール（`Bash` や `Bash(qwen autofix-pr *)` など）はツールの呼び出しも拒否し、そのための ask ルールは呼び出しを確認のままにし、`AutofixPr(command:push)` を deny ルールに追加するとすべてのプッシュが停止します。シェルツールに設定した PreToolUse フックはこれらの呼び出しを見ません。`autofix_pr` に設定してください。プッシュや sync が実行する git フック（`pre-push`、`post-checkout`、`post-merge`、`reference-transaction`）を持つクローン — ワークツリー内のフックパス（husky など）、または PR 内のファイルに従って実行する pre-commit や lefthook などのフックマネージャー — では、修正が確認なしで実行されない限り（下記参照）、`sync` と `push` も確認を求めます。サブモジュールの git ディレクトリがクローン自体ではなくその内部にあるワークツリーのすべてのヘルパーも同様であり、シェルコマンドの ask ルールもここで同様に確認を求めます。このスキルは `.qwen/tmp/` 配下の独自ファイルの読み取り、修正ブリーフ・返信プラン・指示の書き込み、およびスケジュールされたタスクの一覧表示も許可します。これらのファイルはクローンのメインワークツリーに存在します。リンクされたワークツリーで開始したセッションからは、それらの読み書きにも確認が求められます。
- 開始の質問では **Start, fixes run without asking** も提供されます。このオプションを選ぶと、修正エージェントのコマンド（PR ワークツリーでのビルド、テスト、コミット）が、確認を追加で 1 回求められた後（そのダイアログを拒否すると開始がキャンセルされます。再度 `/autofix-pr <n>` を実行してください）、この監視では確認なしで実行されます。エージェントは [YOLO](./approval-mode.md) セッションの場合と同様に動作します。あなたの `git` と `gh` の認証情報を使用し、ワークツリー外のファイルにアクセスでき、ask ルールを通過します。deny ルールは引き続き適用されます。これは監視が停止されるまで、または plain な **Start**（または `--yes`）で再度開始されるまで、あるいはセッションが終了またはクリアされるまで続きます。`/autofix-pr resume` は再度確認を求めます。Plain な **Start** を選ぶと、デフォルトの[承認モード](./approval-mode.md)では各コマンドが最初に確認を求めます。これは目を届けておく監視に適しています。監視の引き継ぎと `/autofix-pr resume` も同じ選択肢を提供します。そのダイアログに回答するのはあなただけです。保存済みルール、[Auto Mode](./auto-mode.md) のクラシファイア、`--yes` は回答しません。また、信頼されないフォルダー内および stream-json 経由で Qwen Code を駆動するプログラムに対してはこの選択肢が拒否されます。そのような監視のスケジュールされたラウンドは修正エージェントをバックグラウンドで実行するため、セッションは作業中に使用可能なままです。YOLO セッション（そのような選択肢を記録しない）、`--once`、PR の移動によってターン内で再起動したラウンド、および破棄されたバックグラウンド修正をやり直すラウンドではフォアグラウンドのままです。ラウンドがプッシュする前に他人のプッシュをマージするエージェントは常にフォアグラウンドで実行されます。エージェントの完了通知が届くと、ラウンド（再実行、プッシュ、返信）が継続します。その間、PR のヘルパーはそれが終了してゲートが静かになるまで拒否します。`/autofix-pr status` は実行中の修正を表示します。このセッションでの `/autofix-pr stop <n>` はまずエージェントを停止しますが、別のセッションからの stop と resume はそれが終了するまで拒否されます（最大 45 分）。その修正が実行中の間は監視の再開も再開始も拒否されます。`/autofix-pr stop <n>` で停止します。その間、そのワークツリー（`.qwen/tmp/autofix-pr-<n>/`）内のファイルへのあなた自身の編集は、承認モードに関わらず最初に確認を求めます。修正エージェントがそこにあるものをビルド・実行し続けているためです。また、このセッションがそのワークツリー内から開始したエージェントも拒否されます。それを知っているのは修正を実行しているセッションだけです。同じクローン上の別のセッションのエージェントは拒否されないため、修正が実行中に 2 つ目のセッションからそのワークツリーで作業しないでください。ラウンドが継続しなかった修正（セッションが終了した、または開始から 40 分以内にクレームがなかった）は次のラウンドで破棄され、その項目はフォアグラウンドで再処理されます。`autofix_pr` ツールが利用できない場合（設定のツール許可リストに含まれない場合など）、ヘルパーはシェル経由で実行され、それぞれが最初に確認を求めます。
- 作成者がリポジトリにプッシュできない PR は、修正が検証される際に、あなたの `gh` と `git` の認証情報にアクセス可能な状態で他人のコードを実行します。このような PR は監視されません: その旨の確認（`--yes` ではスキップされない）の後、`--once` のみが提供されます。

開始時に、プッシュ先と PR への返信を行うこと、および修正がコマンドを確認なしで実行できるかどうかを 1 度だけ確認します。

## チェックの動作

監視は[スケジュールされたタスク](./scheduled-tasks.md)であり、そのゲートはモデル外で毎回 `qwen autofix-pr snapshot <n> --gate` を実行します。プローブは前回の実行以降に変更されたもののみを出力するため、変化のない PR ではモデルターンを消費しません。変更があった場合、ラウンドが実行されます:

1. マージまたはクローズされた PR は監視を終了します。他人のプッシュがまず取り込まれます。
2. 失敗したチェック、信頼された作成者による新しいコメント、およびマージコンフリクトは、PR ワークツリーで作業する 1 つの修正エージェントに送られます。失敗したチェックについてはジョブログを読み取ります。PR 外の失敗（ネットワーク、ランナー）は修正ではなく 1 回だけ再実行されます。
3. エージェントはリポジトリ独自のチェックで変更を検証し、パスした場合のみコミットします。
4. コミットは PR ヘッドのファストフォワードとしてプッシュされ、強制プッシュは行われません。その間に誰かがプッシュした場合、まずその作業がマージされます。
5. 対応した各レビュースレッドには返信（`Fixed in <sha>: …`、`Not changed: …`、`Needs a human decision: …`）が行われ、各プッシュには 1 つのサマリーコメントが付けられます。

ラウンドがあなたに何かを確認することはありません。人間の判断が必要なものは、PR 上で「Needs a human decision」として回答され、セッションで報告され、`/autofix-pr status` で一覧表示されます。

## 状態と再開

`/autofix-pr status` は、どのセッションが実行しているかに関わらず、クローンのすべての監視を一覧表示します。PR とそのブランチ、ヘッド、使用されたプッシュ、ゲートが最後にチェックした時刻と最後のラウンドが実行された時刻、このセッションが実行しているかどうか、および人間の判断を待っているものが表示されます。監視のファイルのみを読み取り、GitHub には問い合わせません。

監視は、それを実行していたセッションが終了すると終了します。デーモンセッションではタスクは永続的でそのセッションに紐づいているため、デーモンはそれを常駐させ続け、デーモンの再起動後も監視は生存します。スケジュールされたタスクはデフォルトで 7 日後に期限切れになります（`experimental.cronRecurringMaxAgeDays` 設定、または `QWEN_CODE_CRON_MAX_AGE_DAYS`）。状態ファイルは残ります。`/autofix-pr resume` は、このセッションが実行していないすべての監視（または指定した 1 つ）を、開始時の間隔、`--no-reply`、指示で現在のセッションで再度開始します。プッシュ、履歴、予算は保持されます。すべてに対して 1 度確認を求め、その後それぞれ 1 ラウンド実行して再スケジュールします。デーモンセッションでは 1 つの会話につき 1 つのスケジュールされたタスクが運ばれるため、他のものは 1 つずつ別の会話で再開してください。別のセッションがまだそのうちの 1 つを実行している場合、そのセッションのタスクは次の実行時に停止します。PR が指定されていない場合、`resume` は最近別のセッションがチェックした監視を除外し、その旨を表示します。PR がマージまたはクローズされた監視は、ラウンドによって削除されます。`--once` で開始された監視、または `stop` がワークツリーを保持したまま終了した監視は、`/autofix-pr <n>` で再度開始されます。

### Web Shell で

Web Shell も同じファイルから読み取られ、同じ状態を表示します。

- **PR watches** はサイドバーに、Web Shell がアクセスできるすべてのワークスペースの監視を一覧表示します。各監視について、PR（リンク）、監視の場所、プッシュ、ゲートが最後にチェックした時刻と最後のラウンドが実行された時刻、およびあなたを待っているものが表示されます。
  - 監視中
  - バックグラウンドで修正中、およびその経過時間
  - 置き去りにされたバックグラウンド修正（次のラウンドで再実行される）
  - 最近チェックされていない
  - PR がマージまたはクローズされた
  - 停止済み
- **Scheduled tasks** ページでは、監視のタスクのカードがタスクの下に同じ状態を表示します。
- **Open session** は監視を実行している会話に移動します。
- **Stop watch** はその会話に `/autofix-pr stop <n>` を送信します。そこにタイプした場合とまったく同じであり、そこと同じ確認を求めます。
- どちらのボタンも、この Web Shell の会話によって実行されている監視にのみ表示されます。ターミナルから実行されている監視はそのターミナルで停止します。どのセッションも実行していない監視は、そのワークスペースのセッションで `/autofix-pr stop <n>` または `/autofix-pr resume <n>` を使ってクリーンアップまたは再開始されます。

## どのフィードバックが反映されるか

コメントは、その作成者がリポジトリのオーナー、メンバー、コラボレーター、PR 作成者、またはボットである場合に処理されます（レビューとレビュースレッドのみ）。それ以外からのコメントは一覧表示されるだけで、処理も返信もされません。ボットは、スレッドを開始するコメントまたはレビュー内では聞かれますが、その返信（誰かへの応答）では聞かれません。GitHub が開始できなかったワークフロー（無効なワークフローファイルなど）には修正対象のログがなく、人間の判断が必要として回答されます。すべてのコメント、レビュー、CI ログはデータとして扱われます: どのフィードバックに対応するかは信頼された作成者が決定し、ツールが何をするかは決定しません。秘密の開示、テストまたは CI チェックの弱体化、強制プッシュ、無関係なコードの変更を求めるリクエストは「Needs a human decision」と回答されます。

## 決して行わないこと

- ワーキングツリーまたは現在のブランチに触れること: すべては `.qwen/tmp/autofix-pr-<n>/` で行われます。
- 強制プッシュ、PR の履歴の書き換え、またはデフォルトブランチへのプッシュ。
- 自身の返信（それぞれ `<!-- qwen-autofix-pr:v1 -->` で終わる）や信頼されない作成者への返信。
- レビュースレッドの解決、または PR タイトルや説明の編集。

## 制限

| 制限 | 値 | その後 |
| --- | --- | --- |
| 監視ごとのプッシュ | 10 | 監視が停止 |
| 1 つのヘッドでの失敗チェックの再実行 | 1 | 次の失敗は実際のもの |
| レビューコメントごとの試行 | 1 | 再提示されない |
| ラウンド内の他人によるプッシュ | 2 | 監視が停止 |
| バックグラウンド修正の実行時間（分） | 30 | エージェントが停止 |

## 停止とファイル

`/autofix-pr stop <n>` はスケジュールされたタスクを削除し、ワークツリー、そのブランチ、および状態ファイルを削除します。ゲートカーソルと PR の履歴は保持されるため、後の監視が同じコメントに再回答することはありません。プッシュされていない作業をまだ保持するワークツリーは保持され、レポートにその理由が示されます。`qwen autofix-pr cleanup <n> --force` でそれを破棄します。監視はすでに終了しています。`/autofix-pr stop <n>` は別のセッションが置き去りにした監視も停止します。裸の `/autofix-pr stop` は別のセッションがまだ実行している監視をそのままにし、その PR を指定すると終了します。タスクが期限切れになった監視、またはターミナルセッションが終了した監視はレポートなしに終了します。`/autofix-pr resume` で再度開始します（上記参照）。新しいセッションで `/autofix-pr <n>` を開始すると（または `/clear` または `/resume` の後）、監視の引き継ぎが提案され、プッシュと予算は保持されます。

ファイルはクローンのメインワークツリーの `.qwen/tmp/` 配下に存在します:

| ファイル | 内容 |
| --- | --- |
| `autofix-pr-<n>/` | PR ワークツリー |
| `autofix-pr-<n>-state.json` | 監視: 既知のヘッド、プッシュ、処理済み ID、スケジュールされたタスク |
| `autofix-pr-<n>-gate.json` | ゲートプローブのカーソル |
| `autofix-pr-<n>-gate.checked` | 監視のゲートが最後に PR をチェックした時刻 |
| `autofix-pr-<n>-snapshot.json` | ラウンドが読み取る、最新ラウンドの PR のスナップショット |
| `autofix-pr-<n>-replies.json` | GitHub による、どのボットコメントが他のコメントに応答しているか |
| `autofix-pr-<n>-history-*.json` | 以前の PR 監視が投稿・処理した内容。`stop` で保持 |
| `autofix-pr-<n>-instructions.txt` | 各ラウンドへのあなたの指示 |
| `autofix-pr-<n>-fix.json` | バックグラウンドで実行中の修正。実行中に更新される |
| `autofix-pr-<n>-fix-snapshot.json` | 最後のバックグラウンド修正が作業に使用したスナップショット |
| `autofix-pr-<n>-*.log`、`*.md`、`*.json` | CI ログ、修正ブリーフ、返信プラン |

設計は [`docs/design/2026-10-21-autofix-pr-command.md`](../../design/2026-10-21-autofix-pr-command.md) にあります。
