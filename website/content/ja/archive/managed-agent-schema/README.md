# アーカイブされた Managed Agent データベースマイグレーション


これらのファイルは、ソースコミット `18f80f56666a347a2b67b2ef98099cc58356b253` にある廃止された63テーブルのデータベースについて記述しています。これらは歴史的な参照情報であり、ランタイムおよびテストのクラスパス外にあります。アーカイブされた Java マイグレーションとアップグレード witness は、新しい環境では実行されません。

唯一のアクティブなベースラインは [`V1__managed_schema.sql`](../../../packages/managed-agent-server/src/main/resources/db/managed-schema/V1__managed_schema.sql) です。Managed Server と Runtime Broker は同じバージョン管理リソースを消費し、空のデータベースまたは構造的に検証された完全な32テーブルのベースラインを必要とします。レガシー、部分的、外部、または履歴のみのカタログは、初期化書き込み前に拒否されます。再初期化はカタログを検証しますが、バックフィルや修復は行いません。

古いデータのマイグレーションやインプレースアップグレードはありません。歴史的な読み取りのために古い環境とデータベースを保持し、切り替え前に新しい受け入れを停止して進行中の作業を完了させてから、新しい環境でのみ新しいセッションを作成してください。新しいデータが存在する状態でのロールバックは、新しいデータベースからそれらのレコードを保持して提供する必要があります。

アーカイブされたテストは、廃止されたマイグレーションアルゴリズムの証拠を保持しています。アクティブな置き換えは、新しい初期化、不変の既存行、型付きバリアント列、Hook の一意性とインデックス付き受け入れ、および古いカタログの拒否を検証します。重複していた Broker `schema.sql` は、別のスキーマ権限として保持されるのではなく、削除されました。

PR #13642 の retention V69 SQL と `RuntimeBrokerRetentionLegacyUpgradeTest.java` は、ヘッド `db4c37064b9f34d2aa879b23b0e894fbed0281e1` からの以前の retention-index/receipt アップグレードの証拠を保持しています。これらはアーカイブのみです：アクティブな32テーブルの V1 ベースラインが retention インデックスを提供し、その置き換えテストは、新しいカタログの同等性と繰り返し初期化時の不変の receipt を検証します。V69 はアクティブなマイグレーションでもバージョン予約でもありません。
