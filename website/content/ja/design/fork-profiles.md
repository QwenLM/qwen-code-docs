# フォークプロファイル

## Summary

#8066 で導入されたフォーク実行許可リストの上に、プロジェクトレベルの名前付き
プロファイルレイヤーを追加する。呼び出し元は `fork_tools` を繰り返す代わりに
`fork_profile: "<name>"` を渡せる。ランタイムは起動時に
`.qwen/fork-profiles/<name>.md` を 1 回だけ解決し、結果のツールリストを既存の
実行ゲートに渡す。

このフェーズでは新しい認可の仕組みは追加しない。解決されたプロファイルは、
等価なインラインの `fork_tools` 呼び出しとまったく同じ挙動をしなければ
ならない。

## File Format

プロファイルはアクティブなプロジェクトルートの下に置かれる:

```text
.qwen/fork-profiles/<name>.md
```

各ファイルには YAML のフロントマターが含まれる:

```markdown
---
name: ro-research
tools:
  - read_file
  - grep_search
  - glob
  - mcp__search__*
promptHint: |
  Work read-only. Prefer targeted searches and report evidence.
---
```

`name` と `tools` は必須である。`promptHint` は任意で、200 文字に制限される。
要求された名前、ファイル名、フロントマターの名前は一致しなければならない。
名前は 2〜50 文字で、文字、数字、ハイフン、アンダースコアのみを含み、先頭や
末尾に区切り文字は使えない。プロファイルファイルはフロントマターのみであり、
空白でない Markdown の本文は拒否されるため、ガイダンスがサイレントに破棄される
ことはない。プロファイルはプロジェクトのプロファイルディレクトリ内の通常の
ファイルに解決されなければならず、64 KiB を超えてはならない。

`tools` フィールドは、`fork_tools` の契約そのものを使用する。空のリストは引き
続きすべて拒否であり、裸の `*` は無効であり、MCP のワイルドカード構文は変更
されない。

このフェーズでは、プロジェクトスコープが唯一の検索スコープである。ユーザー
レベルのプロファイル、スコープの優先順位、組み込みプロファイル、プロファイル
の一覧表示、管理 UI は先送りされる。セーフモードと bare モードは、プロジェク
トプロファイルをローカルカスタマイズであるため拒否する。AUTO モードは
`.qwen/fork-profiles/` 配下への書き込みを自己変更として扱うため、通常の
ワークスペース内編集の高速パスを使用できない。

## Launch Resolution

`fork_profile` は `subagent_type: "fork"` とのみ有効であり、`fork_tools` や
名前付きチームメイトと組み合わせることはできない。エージェントの呼び出しは、
フォークランタイムの構築前にプロファイルを解決する:

1. ファイルシステムパスを構築する前に、要求された論理名を検証する。
2. 一致するプロジェクトプロファイルを読み取り、その YAML フロントマターを厳密
   に解析する。
3. ファイル名/フロントマターのアイデンティティとツールの許可リストを検証する。
4. 解析されたプロファイルを 1 つの起動スナップショットにバインドし、その有効
   なツールとプロンプトヒントを AUTO モードの分類に公開する。
5. クローンされたツールリストを `ToolConfig.executionAllowedTools` として渡す。
6. `promptHint` が存在する場合、親由来のキャッシュ可能なプレフィックスの後で、
   フォークタスクの指示に追加する。プロジェクトが制御するテキストはエスケープ
   され、指示の後のガイダンスとして枠付けされる一方、権威ある実行制限は最後に
   置かれたままである。

欠落または無効なプロファイルは、エージェントランタイム、フック、バックグラウンド
のレジストリエントリ、トランスクリプトのサイドカーが作成される前に、起動を
失敗させる。

## Runtime and Revival

既存の実行ゲートが引き続き権威を持つ。プロファイルの解決は、モデルに表示され
る宣言を変更することも、許可されたツールの通常の権限をバイパスすることもない。

プロファイル名やパスではなく、解決されたツールリストが起動時のポリシーである。
既存の `AgentMeta.executionAllowedTools` サイドカーは、空のすべて拒否リストを
含め、それを保存する。コールドリバイバルはそのスナップショットを現在のライブ
のツールサーフェスに再適用し、起動以降に変更された可能性のあるプロファイルを
再読み込みしない。

起動タスクのプロンプトはすでにフォークのトランスクリプトの一部であるため、
解決されたプロンプトヒントは、2 回目のプロファイル検索なしで、既存のトランス
クリプト/リバイバルパスに従う。

## Boundaries

このフェーズでは、シェルの引数パターン、オーバーレイファイルシステム、
`/btw` の統合、自動リフレクション/スワームオーケストレーション、ユーザー
レベルのプロファイル、プロファイルの CRUD UI は追加しない。

フォークプロファイルは、呼び出し元の利便性とプロジェクトが制御するプロンプト
レイヤーであり、管理者が強制するサンドボックスではない。親から継承された実行
可能なサーフェスを狭めることしかできない。
