# Java デーモン SDK 0.1.0-alpha

## Status

この文書は、既存の `com.alibaba:qwencode-sdk` アーティファクトにおける最初のデーモントランスポートを定義する。これは `com.alibaba.qwen.code.cli` 配下のレガシー stdio 実装から意図的に独立している。

## Goals

- 別の Maven アーティファクトを作らずに、`qwen serve` 向けの Java 11 API を追加する。
- ストリームのテキスト、thought、ツール、usage、permission、raw イベントをデーモンの順序で配送する。
- プロンプトテキストは、対応する信頼できる終端イベントの後のみ返す。
- 受け入れ（admission）の watermark からプロンプトストリームを再開し、リプレイのギャップやオブザーバーへの重複配送なしで行う。
- 曖昧なミューテーション結果と不完全なプロンプト結果を明示化する。
- クライアント所有のスレッド、ストリーム、セッション、detach 試行を制限されたままにする。

## Public surface

`DaemonClient` は HTTP とワーカーリソースを所有し、capability を読み取り、セッションを作成する。セッション作成のデフォルトは `sessionScope=thread` である。ブロッキングなプロンプト観測は、グローバルや無制限のエグゼキュータではなく、設定可能な上限付きワーカープールを使用する。
共有タイマーはウォッチドッグアクションのディスパッチのみを行う。ブロックする可能性がある SSE ストリームのクローズは、プロンプト並行上限に合わせたサイズの別の上限付きプールで実行されるため、1 件のストールしたクローズが他のセッションの期限やアイドルウォッチドッグを遅延させることはない。受け入れられた各プロンプトは、最終のクローズタスクが完了するまで、上限付きのストリームクリーンアップ容量を予約する。プロンプトは、そのプロンプトスロットが解放された時点で、自身のストリームがまだクローズ中でも終端を公開する。そのためこの容量はプロンプトスロットごとに 1 件の drain 中のクリーンアップを許容し、終端 continuation は並行上限に達していても次のプロンプトを開始できる。そのヘッドルームを超えてストールしたままのクローズは、後続の `startPrompt` 呼び出しを `DaemonClientCapacityException` で失敗させ得るが、期限トリガーのクローズをサイレントに破棄したり、クリーンアップ作業を無制限に増大させたりすることはできない。

`DaemonSessionClient` は 1 つのデーモンセッションを所有し、同時に最大 1 件のローカルプロンプトを受け入れる。`startPrompt` は直ちに `PromptCall` を返す。その受け入れと終端の future は独立しているため、呼び出し元は「デーモンがこのプロンプトを受け入れた」と「ターンが確実に終了した」を区別できる。
受け入れと終端 future の continuation は、クライアント所有の別個のエグゼキュータでディスパッチされるため、ユーザーの continuation が SSE 観測、そのローカルタイムアウト、プロンプトトランスポート容量を遅延させることはない。例外による完了も同じパスに従う。公開容量は `maximumConcurrentPrompts` に対して上限付きであり、ブロックしたままの continuation は、無制限のスレッドやキューイングされた作業を生む代わりに、後続の `startPrompt` 呼び出しを `DaemonClientCapacityException` で失敗させ得る。

不定の完了はセッション再利用の境界ではない。受け入れが不明になった後や、受け入れ済みプロンプトが不定に終了した後、セッションクライアントはローカルストリームのクリーンアップが成功しても後続のプロンプトを恒久的に拒否する。ローカル観測タイムアウトは、ストリームのクローズを無限に待たずに公開される。クリーンアップは非同期に継続し、完了するまで上限付きのクライアント容量を保持する。呼び出し元は影響するセッションを close または destroy する。

`PromptObserver` は型付きコールバックと raw イベントを受け取る。コールバックはクライアント所有のデーモンスレッドで直列に実行される。イベントカーソルは、該当するすべてのコールバックが正常に返った場合のみ進む。したがってコールバックは速やかに返る必要があり、同じ `PromptCall` を待ってはいけない。また、コールバックから同じセッションを close や destroy してはいけない。コールバックからの permission 応答はサポートされており、デーモンがリクエストの解決済みまたは保留解除を報告した場合、応答メソッドは `false` を返す。

`promptText` は `startPrompt` 上の簡易機能である。アシスタントのテキストのみを収集し、UTF-8 バイト上限を強制し、対応する `turn_complete` の場合のみ `PromptTextResult` を返す。`turn_error` は信頼できる終端のまま `PromptTurnException` として報告される。信頼できる終端のない結果は、利用可能な場合は明示的に不完全な部分テキストを添えた `PromptOutcomeIndeterminateException` として報告される。

Fastjson2 のエンコードと厳密な Jackson Core のデコードは実装の詳細である。デコードは非標準 JSON と重複オブジェクトキーを拒否する。公開される raw JSON 値は Java の `Map`、`List`、スカラー、null 値を使用する。

作成時のモデル選択は、この alpha では意図的に公開していない。デーモンは、`modelServiceId` が拒否された場合、デフォルトモデルで新規セッションを生存させ、拒否は create レスポンスより前に発行される SSE イベントでのみ報告する。プロンプトごとのサブスクリプションは後続の受け入れ watermark から始まるため、別のセッションイベントライフサイクルを追加しなければ、要求されたモデルが選択されたことを証明できない。

セッション作成前、SDK はデーモンに REST と `session_scope_override` の advertise を要求する。古いデーモンが要求されたスコープをサイレントに無視し得る場合、ミューテーションを拒否する。セッションが開いている間、SDK はデーモンが `client_heartbeat` を advertise している場合のみ、設定されたインターバル（デフォルト 1 分）ごとに 1 回、新しい heartbeat ミューテーションを送信し、detach または destroy で停止する。各 heartbeat は通常の有限リクエスト期限を持ち、リトライされない。インターバルをゼロに設定すると自動キープアライブが無効になる。
同様に、`deadlineMs` を持つプロンプトは、デーモンが `prompt_absolute_deadline` を advertise していなければ受け入れ前に拒否されるため、要求されたサーバー側の期限がサイレントに無視されることはない。ローカル観測タイムアウトは独立しており、常に SDK によって強制される。

## Wire flow

1. リトライなしの `POST /session/:id/prompt` を 1 回送信する。
2. `202` を要求し、`{promptId,lastEventId,eventEpoch?}` を検証する。
3. `Last-Event-ID` に watermark を設定し、デーモンが epoch を提供した場合は `X-Qwen-Event-Epoch` を設定して `GET /session/:id/events` を開く。
4. そのプロンプトに相関するイベントのみをリプレイして観測し、セッションレベルの障害フレームは致命的として扱う。
5. 対応する `turn_complete` または `turn_error` でのみ停止する。

このプロンプトごとのサブスクリプションは、`202` レスポンスがクライアントに到達する前に発行されたコンテンツイベントと終端イベントをカバーする。不明プロンプトのキャッシュや、長寿命のセッションポンプを必要としない。

## Transport contract

JDK の `HttpClient` は HTTP/1.1 を使用し、リダイレクトは決して辿らない。すべてのリクエストは JSON または event-stream の `Accept` ヘッダー、設定されている場合は bearer 認証、セッション作成後はデーモン発行の `X-Qwen-Client-Id` を送信する。SSE は加えて `Accept-Encoding: identity`、`Cache-Control: no-cache`、`Last-Event-ID` を送信する。利用可能な場合、`X-Qwen-Event-Epoch` がそのカーソルに同行する。クライアントはプロンプトの受け入れからこれを初期化し、互換性のために検証済みの SSE レスポンスヘッダーから学習し、レスポンスがヘッダーを省略した場合は既知の値を保持し、プロンプト観測中に値が変わった場合は fail closed（失敗時は拒否）となる。

有限の JSON とエラーボディは上限付きのサブスクライバーで消費され、`sendAsync` 経由でリクエスト期限と競争させられる。レスポンスヘッダーの受信ではその期限は終わらない。非成功の SSE ボディは、リクエスト予算とプロンプト観測予算の短い方によって別途制限される。

SSE パーサーは LF と CRLF のフレーミング、コメント、複数の `data:` 行を受け入れる。UTF-8 デコードは厳密である。フレーム、イベント名、エンベロープバージョン、数値 ID、SSE/エンベロープ ID の整合性は検証される。不正フレーム、ID ギャップ、`state_resync_required`、セッションの死、オブザーバー障害、アイドルタイムアウト、再接続枯渇は fail closed となる。

コミット済みカーソル以下の ID は重複であり、配送されない。次の数値イベントは厳密に `cursor + 1` でなければならない。ID なしの合成イベントは、デーモンが文書化した制御フレームのみ受け入れ、カーソルを進めない。ID なしのコンテンツまたは終端イベントは fail closed となる。実装は SSE GET のみを再接続し、上限付きの指数フルジッターバックオフ、ストリーム切断後の SSE `retry` 指示、リトライ可能な HTTP レスポンスでの `Retry-After` を使用する。ミューテーションは決して自動リトライされない。

## Ambiguous and terminal outcomes

ディスパッチ後に検証済み `202` なしでプロンプトトランスポートが失敗した場合、または HTTP 408 か 5xx を返した場合、受け入れ future は `PromptAdmissionUnknownException` で失敗する。SDK はプロンプトを再投稿しない。セッション作成も `SessionCreationOutcomeUnknownException` で同じ保守的な分類を適用する。permission、cancel、heartbeat、detach、delete は、中間者のレスポンスがデーモンのミューテーション拒否を証明しないため、同じ分類を適用する。detach はより具体的な `DetachOutcomeUnknownException` を使用する。すべてのミューテーションは、メソッド呼び出しごとに最大 1 回のみ試行される。

対応する `turn_complete` と `turn_error` のみが終端である。キューと `prompt_cancelled` イベントは参考情報である。ローカルタイムアウトは観測を停止するが、デーモンのターンを自動キャンセルしない。協調的なデーモンキャンセルは `stopReason=cancelled` の `turn_complete` として完了し、キャンセル中のエージェントまたはプロバイダー障害は `turn_error` を生成し得る。`promptText()` は完全な結果を返し、エラー終端を `PromptTurnException` として表面化させる。呼び出し元はどちらの場合も終端を待たなければならない。
キャンセル、期限、ティアダウン、エージェントの確定が競合する場合、デーモンの exactly-once ラッチが最初の正式な終端を公開し、後続の候補を抑制する。したがって SDK は、受信した終端を、最後に送信した制御ミューテーションから結果を導出するのではなく、権威として扱う。

`close()` はローカルでべき等であり、ローカル観測を停止し、最大 1 回 detach を試みる。失われた detach レスポンスはリトライされない。`destroySession()` は `DELETE /session/:id` を発行する唯一の API であり、detach 後も呼び出し可能である。

## Compatibility and non-goals

アーティファクト全体が Java 11 を要求するようになった。Java 8 ユーザーは `0.0.3-alpha` に留まる必要がある。stdio API はソース互換のままだが、Java 11 で動作し、`slf4j-api` 経由でロギングを取得する。Logback はテスト専用のため、アプリケーションは独自の SLF4J プロバイダーを選択する。

互換デーモンは、SDK と同じソースリビジョンからリリースされた qwen-code ビルドである。これには #7386 のクライアントごとの detach レジャー、#7400 の epoch ごとの終端保証、#7458 の再起動安全なイベントカーソル epoch、そして本リリースの承認付き受け入れキャンセルと FIFO cancel-drain フェンスが含まれる。#7400 コミット単独では、受け入れ済みプロンプトを停止せずにエージェントディスパッチ前にキャンセルを承認し得るし、未承認のセッションスコープキャンセルがキューの後継に到達し得る。
バンドルされた ACP 子は、デーモン内部のキャンセルリクエストを、承認付きの受け入れ対応ハンドシェイク 1 回で処理する。その拡張を実装しない、カスタムの標準準拠 ACP 子は、代わりに標準の `session/cancel` 通知を 1 回受け取る。デーモンは、同じ REST/SSE 機能セットでこれらの実装を区別する capability を advertise しないため、SDK はこの最小条件をランタイムにネゴシエートできず、正式な終端が存在しない場合は fail closed となる。

ハンドシェイクは、FIFO が後継をディスパッチする前に、対象のプロンプト呼び出しが確定するのを意図的に待つ。承認のみのタイムアウトを追加すると、遅延したセッションスコープキャンセルがその後継に到達し、順序保証を破壊する。したがって、`AbortSignal` を無期限に無視するプロバイダー、ツール、カスタム統合は、キャンセルミューテーションの結果を不明のままにし、セッションを使用不能にし得る。スタックした共有 ACP 子を兄弟セッションを終了させずに回収するには、より強いランタイム分離が必要であり、この alpha の範囲外である。

alpha は観測中のプロンプトにおけるイベント epoch の変更を検出して fail closed となるが、デーモン再起動をまたぐ exactly-once 実行、自動 epoch 復旧、スナップショット/再同期、永続カーソル、真のプロンプト ID 指定キャンセルは約束しない。また、デーモンが決定論的な結果を返せるようになるか、SDK が `Last-Event-ID: 0` からセッションイベントライフサイクルを所有するまで、作成時のモデル選択も公開しない。曖昧な create は、呼び出し元が識別も detach もできず、デーモン側の回収を待つしかないデーモンセッションを残し得る。これらのケースにはより強いデーモン契約が必要である。

## Verification

ユニットテストはプロセス内 HTTP サーバーを使用し、SSE フラグメンテーション、遅い単一行配送、リプレイ、重複、ギャップ、競合するプロンプト ID、不透明な未来のイベントデータ、watermark リプレイ、切断、圧縮レスポンス、ストールした有限ボディ、イベント epoch の伝播と不一致、再同期、オブザーバー障害、終端の不在、曖昧なミューテーションレスポンスを注入する。ライサイクルテストは、ローカル 1 プロンプトの受け入れ、受け入れ/クローズの直列化、期限終端に続くセッション再利用、キャンセルされた完了、ティアダウン終端の順序、上限付きテキスト、自動 heartbeat、べき等 close、detach クライアント識別、detach 1 回、明示的 destroy をカバーする。

CI は Linux の Java 11、17、21 でコンパイルとテストを行い、macOS と Windows では Java 21 のスモークカバレッジを行う。Linux CI と保護されたリリースワークフローは、一時ワークスペースとモデルスタブを使用した実 `qwen serve` プロセスに対する E2E を実行する。
