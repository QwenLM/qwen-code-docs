# Observed channel のグループ名

## 問題

#7109 で導入されたワークスペーススコープの observed-contact グラフは、完全なプラットフォームのグループ ID を保持しますが、現在すべての `groups[].label` はその ID にフォールバックしています。一部の受信チャネルコールバックはすでに人間が読めるグループ名を運んでいますが、アダプターは共有の観測境界の前にそれを破棄しています。

プロアクティブ配信のターゲットを選択するユーザーには、完全で安定したプラットフォーム ID と並べて、読める名前が必要です。名前は観測メタデータであり、ルーティングキーではありません。

## スコープ

共有の受信 envelope にオプションのグループ名を追加し、受け入れられた受信メッセージにすでに存在するメタデータからのみ設定します。

- DingTalk は Stream コールバックの `conversationTitle` をマップします。
- Telegram は、グループとスーパーグループについて受信チャットの `title` をマップします。
- Feishu は `im.message.receive_v1` がチャット表示名を含まないため、完全な `chat_id` フォールバックを保持します。
- 他のアダプターは、既存の受信ペイロードに文書化されたグループ名フィールドがない限り、ID フォールバックを保持します。

この変更は、プラットフォームのディレクトリ、グループ詳細、チャット情報 API の呼び出し、権限の追加、ルーティングやセッション identity の変更、権威あるメンバーシップの検出、ボット出力の観測、トピック名の追加を行いません。

## 契約

`Envelope` に 1 つのオプションフィールドが追加されます:

```ts
chatName?: string;
```

このフィールドは、そのメッセージで観測された `chatId` の表示名を記述します。ダイレクトメッセージでは無視されます。`chatId` が完全なプラットフォーム配信キーであり続け、セッション、重複排除、グラフの identity を決定し続けます。

共通の観測パスは、サニタイズされた非空の `chatName` をグループライベルとして使用します。欠落または使用不可能な値は、完全な `chatId` にフォールバックします。既存のレジストリストアは、永続化されるラベルをサロゲートペアを分割せずに 256 UTF-16 コード単位に制限します。

## 更新のセマンティクス

同じチャネル、ユーザー、グループに対して受け入れられた後続のメッセージは、観測を更新します。それが異なる使用可能な `chatName` を運ぶ場合、既存のストアの置き換えセマンティクスにより、別のグループノードを作成せずに派生したグループライベルが更新されます。鮮度は `lastObservedAt` のままです。名前は恒久的または権威あるものとしては扱われません。

後続のメッセージでグループ名を省略するプラットフォームは、その観測に対して ID フォールバックを提供します。グラフの派生はすでに最新の観測を選択するため、返されるラベルは隠れた長期間の名前キャッシュではなく、最新の受け入れられた証拠を表します。

## プラットフォームの証拠

- DingTalk の Stream ロボットメッセージの例は、受信コールバックに `conversationTitle` を含みます: [DingTalk Stream protocol](https://opensource.dingtalk.com/developerpedia/docs/learn/stream/protocol/#%E5%9B%9E%E8%B0%83%E6%8E%A8%E9%80%81)。
- Telegram は `Message.chat` を `Chat` として定義し、その `title` はグループチャットとスーパーグループで利用できます: [Telegram Bot API — Chat](https://core.telegram.org/bots/api/#chat)。
- Feishu のメッセージ受信イベントは `chat_id`、`chat_type`、`thread_id` を列挙しますが、チャット表示名はありません: [Feishu Open Platform — Receive message](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/events/receive)。

## テスト戦略

- base-channel テストは、使用可能なグループ名が伝播すること、使用不可能な名前が完全な ID にフォールバックすること、ダイレクトメッセージが `chatName` を無視すること、後続の観測がラベルを更新できることを証明します。
- DingTalk アダプターテストは、`conversationTitle` がコールバック処理を変更せずに envelope に入ることを証明します。
- Telegram アダプターテストは、グループとスーパーグループのタイトルが envelope に入り、プライベートチャットは変更されないことを証明します。
- 既存の Feishu テストは、API トラフィックなしで ID フォールバックパスを証明し続けます。
- フォーカスされたストアテストは、より新しいラベルによる置き換えをカバーします。永続化された観測はすでに `group.label` を含んでいるため、スキーママイグレーションは不要です。
