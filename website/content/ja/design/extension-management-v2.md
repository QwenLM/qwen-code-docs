# 拡張機能管理 V2

## Status

この設計は、付加的な `extension_management_v2` ケイパビリティの下で、デーモン
プロトコル `v1` を拡張する。すでに公開されている `workspace_extensions` ケイパ
ビリティと `/workspace/extensions/*` ルートは、プライマリワークスペースの互換性
アダプターとして引き続き利用可能である。

## Resource model

インストールされた拡張機能は、`QWEN_HOME/extensions` 内の 1 つのユーザーレベル
のアーティファクトである。アクティベーションはポリシーであり、そのアーティ
ファクトの 2 つ目のコピーではない:

1. 完全一致のワークスペースオーバーライド（`enabled` または `disabled`）。
2. レガシーのパスルールのマイグレーション中に作成される、内部的な完全一致の
   `inherit` マスク。
3. 順序付きの V1 パスルール。
4. グローバルデフォルト。

ワークスペースのアイデンティティは、デーモンの正規のワークスペースパスを使用
する。ワークスペースのルートは、まずワークスペース id で、次に正規の cwd で
既存のランタイムを選択する。信頼されていないランタイムでも読み取りは許可される。
アクティベーションの変更、リフレッシュ、ワークスペーススコープのインストール
には、信頼されたターゲットが必要である。グローバルのミューテーションは、リクエ
ストを開始したワークスペースの信頼状態ではなく、通常のデーモンミューテーション
の認証とインストールの同意を使用する。

## Store and transaction boundary

`ExtensionStore` は、最終的な拡張機能ディレクトリと V2 のアクティベーション
状態の唯一のライターである。`ExtensionManager` は引き続きワークスペース向けの
ファサードであるが、CLI、TUI、自動更新、デーモン、SDK を介した操作は、ミュー
テーションをストアに委譲する。

レイアウトは次のとおり:

```text
~/.qwen/
├── extensions/
└── extension-store/
    ├── lock
    ├── state.json
    ├── state.previous.json
    ├── staging/
    ├── rollback/
    └── transactions/
```

ストアとアーティファクトは同じファイルシステムを共有するため、アーティファクト
の入れ替えはディレクトリのリネームとなる。インプロセスの mutex と
`proper-lockfile` のロックが、V2 を認識するすべてのプロセス間でコミットを直列
化する。すべてのミューテーションは、ロックを保持しながら状態を再読み込みし、
単調な世代をインクリメントすることで、更新の消失を防ぐ。

インストール/更新の準備は、最終的なアーティファクトディレクトリの外で行われる。
コミットは `prepared` ジャーナルを書き込み、古いアーティファクトをロールバック
に移動し、ステージングを所定の位置に移動し、`state.json` をアトミックに書き
込む。その状態のリネームがコミットポイントである。それ以前は、リカバリが
ロールバックし、それ以降は、リカバリは投影とクリーンアップを完了させるのみ
である。コミットされたポリシーは、1 つのランタイムのリフレッシュが失敗した
だけでロールバックされることは決してない。コミット前の操作とそのロールバックの
両方が失敗した場合、呼び出し元は両方のエラーを受け取り、fail-closed のリカバリ
のためにジャーナルが残る。ストアは、曖昧なアーティファクト状態のまま書き込みを
続行しない。

ストアのファイルはオーナー専用の権限とアトミックな no-follow 書き込みを使用
する。拡張機能の id、直下の子のアーティファクトパス、トランザクションパス、
名前は検証される。失敗は、認証情報を秘匿化したソースとともに報告される。

## V1 migration and downgrade projection

最初に V2 を認識するプロセスは、登録済みワークスペースの現在の集合を完全一致の
オーバーライドとして具体化することなく、`extension-enablement.json` から順序
付きのルールをインポートする。V2 は各状態コミットの後に互換性のある投影を書き
込み、そのハッシュを `state.json` に保存する。

ハッシュが異なる場合、変更の順序がリカバリの方向を決定する。古い投影は権威の
ある V2 の状態から修復され、V2 の状態より後に変更された投影は、ダウングレード
されたバイナリによる逐次書き込みとして扱われ、新しい世代で再インポートされる。
1 つの `QWEN_HOME` を共有する V1 と V2 のライターの並行は、意図的にサポート
されない。

公開のワークスペースオーバーライドのクリアは、通常、完全一致のレコードを削除
する。その結果、古いパスルールが実効値を変更する場合、ストアは内部の `inherit`
マスクを書き込み、DELETE が引き続き「グローバルデフォルトを継承する」ことを
意味するようにする。

## Daemon API

グローバルのサーフェスは次のとおり:

```text
GET    /extensions
POST   /extensions/install
POST   /extensions/check-updates
POST   /extensions/:extensionId/update
DELETE /extensions/:extensionId
PUT    /extensions/:extensionId/activation
GET    /extensions/operations/:operationId
```

インストールには明示的な同意と初期アクティベーションが必要である:

```ts
type InitialActivation =
  | { scope: 'user' }
  | { scope: 'workspace'; workspaceId: string };
```

デーモンのインストールエンドポイントは、公開のネットワークポリシーの下で、
HTTPS の Git、GitHub Release、npm のソースを受け付ける。SSH とローカル/リンク
のソースは、引き続きローカル CLI の機能である。更新は、拡張機能の id、マニ
フェスト名、設定、アクティベーションポリシーを保持する。「すでに最新」は成功
の `updated: false` 結果である。アンインストールは冪等であり、アーティファクト
とポリシーの両方を削除する。

ワークスペースの投影は次のとおり:

```text
GET    /workspaces/:workspace/extensions
PUT    /workspaces/:workspace/extensions/:extensionId/activation
DELETE /workspaces/:workspace/extensions/:extensionId/activation
POST   /workspaces/:workspace/extensions/refresh
```

ワークスペースのアーティファクトに対するミューテーションルートは意図的に存在
しない。投影のエントリには、デフォルト、完全一致のワークスペース値、実効値、
ソースが含まれる。希望の世代とローカルで適用された世代は、トップレベルのレス
ポンスフィールドである。

遅くなる可能性のあるミューテーションは、`202`、`Location`、`Retry-After` を
返す。操作のレコードはデーモンローカルのメモリであり、ターミナルのレコードを
最大 100 件保持し、再起動時に消失する場合がある。カタログ/ストアのリカバリが
権威を持つ。SDK のポーリングタイムアウトはポーリングを停止させるのみで、受け
入れられた作業をキャンセルすることは決してない。

デーモンは、未完成の拡張機能操作を最大 10 件まで受け入れる。デーモン全体の
FIFO 準備キューは、ダウンロード、展開、変換、単一拡張機能の更新チェックを一度
に最大 2 つまで実行する。インストールと更新は、明示的な
`prepare -> commit/dispose` のライフサイクルを使用する。準備はステージング
ファイルとリビジョン付きの認証情報スナップショットを所有するが、ストア、
キャッシュ、ランタイム、またはインストール済みアーティファクトが選択した認証
情報は変更しない。準備が完了したミューテーションは、準備が完了した順序で、
個別の単一並行 FIFO コミットキューに入る。アクティベーションとアンインス
トールはコミットキューにのみ入り、更新チェックは準備キューにのみ入る。手動の
リフレッシュはコミットキューを通じて直列化される。その HTTP タイムアウトは
そのレーンを解放するため、停止したランタイムのリフレッシュが後続の拡張機能
ミューテーションを永久にブロックすることはない。すでに開始されたリフレッシュ
は、その後もし確定する場合がある。機密設定は、準備ごとのリビジョンの下で、
1 つのアトミックなシークレットバンドルとしてステージングされる。非シークレッ
トのセレクターが、そのリビジョンとセキュアストレージのバックエンドをステージ
ングされたアーティファクト内に記録するため、勝者となったアーティファクトの
コミットのみが完全なバンドルをアクティベーションする。したがって、ストアの
コミットが耐久性のポイントであり、コミットレーンを即座に解放する。拡張機能の
リロード、レガシーのキーごとの設定同期、マネージャーのランタイムリフレッシュ、
準備ファイルのクリーンアップ、デーモンランタイムの reconciliation は、その外側
で実行される。これらのコミット後のステップはどちらのスロットも占有しないため、
以前の世代が適用またはクリーンアップされている間も、後続のコミットが進行でき
る。

準備されたミューテーションの破棄はその未選択の認証情報スナップショットを削除
し、成功したコミットは、以前に選択されていたスナップショットをベストエフォー
トで削除する。破棄前のハードなプロセスクラッシュにより、到達不可能なエントリ
がセキュアバックエンドに残る場合がある。それを参照するアーティファクトのセレ
クターは存在しないため、それがアクティブになったり、コミットされた認証情報と
取り違えられたりすることはない。

準備の期限は、操作が待機している間ではなく、準備スロットを初めて獲得したとき
に開始される。中断（abort）は、ネットワーク操作とアクティブなアーカイブのス
キャンおよび展開ストリームに伝播される。開始されたタスクは、中断を無視しても、
基盤となる Promise が確定するまでスロットを占有し続ける。コミットはキャン
セルできない。準備された更新はターゲットのアーティファクト世代を運ぶ。無関係
な拡張機能やアクティベーションの変更は安全にリベースされ、同じアーティ
ファクトの古い更新は `extension_conflict` で失敗する。

リモートの npm メタデータは、10 MiB のレスポンス上限でストリーミングされる。
npm と GitHub のアーカイブには、それぞれ個別の 100 MiB のダウンロード上限、
リクエストの期限、リダイレクトの制限、展開前のアーカイブエントリの検証がある。

## Runtime reconciliation

成功したコミットは、ローカルのステータスを無効化し、影響を受けるランタイムを
リフレッシュする。グローバルのアーティファクト/デフォルトの変更は、このデーモン
内のすべてのランタイムを reconciliation し、完全一致のワークスペースオーバー
ライドはそのターゲットのみを reconciliation する。ランタイムの reconciliation
は、拡張機能とスキルのキャッシュ、拡張機能のツール、階層メモリ、アクティブな
チャットのシステム指示、利用可能なコマンドをリフレッシュする。失敗したコン
ポーネントが残りのリフレッシュコンポーネントをスキップさせることはない。
セッションの RPC は、すべてのコンポーネントが試行された後に、組み合わされた
失敗を報告する。ランタイム世代の reconciliation は、ミューテーションと世代
ポーラーが共有するデーモン全体の FIFO を使用する。ミューテーションは、耐久性
のあるコミットコールバックでその位置を予約するため、以前のコミット後の作業が
後で完了しても、後続の世代がランタイムを先にリフレッシュすることはできない。
ACP ブリッジは、各セッションのリフレッシュを 30 秒に制限する。集約されたリ
フレッシュが依然としてルートの期限を超える場合、コントローラーは基盤となる
RPC をキャンセルせずにコミットレーンを解放する。世代 N の適用は、それより古い
世代の待機者も満たすため、遅延した低世代のリフレッシュが適用された世代を後退
させることはできない。部分的なリフレッシュの失敗、またはコミット後のリロード/
クリーンアップの失敗は、アーティファクトをロールバックすることなく、ワーク
スペース固有またはコミットの診断情報を伴う `succeeded_with_warnings` を生成
する。

レガシーのワークスペースマイグレーションは、コミットされたアーティファクトを、
リロードできなかった場合にのみ失敗として扱う。設定の互換性同期、クリーン
アップ、ランタイムリフレッシュの警告は、すでに永続的にインストールされている
アーティファクトのリトライをトリガーしない。更新の呼び出し元は警告の詳細を
受け取る。互換性とクリーンアップの警告は、個別の `updated with warnings` 状態
を使用し、リロードまたはランタイムリフレッシュの失敗は引き続き
`updated, needs restart` となる。

拡張機能のファイルウォッチャーは、ポリシーの世代については
`extension-store/state.json` のみを観測し、コマンド、スキル、エージェント、
フック、MCP の変更については、引き続きインストール済み/リンクされた拡張機能の
内容を観測する。30 秒の世代ポーリングが、見逃したファイルシステムイベントを
修復し、ストアを共有する他のデーモンの収束を制限する。

## Compatibility

`workspace_extensions` は、引き続き既存の単数形サーフェスのためのケイパビリティ
である。そのハンドラーは同じマネージャー/コーディネーターを呼び出し、レスポン
スを適応させる。プロジェクトのアクティベーションはプライマリワークスペースの
オーバーライドとなり、ユーザーのアクティベーションはレガシーのルールクリアの
挙動を維持し、グローバルのミューテーションはすべてのローカルランタイムを
reconciliation する。レガシーの操作エンドポイントは、V2 の警告付き完了を、
公開済みのレガシーのリフレッシュエラーステータスにマッピングする。

クライアントは `extension_management_v2` をチェックしなければならない。
デーモンモードも、他のワークスペースケイパビリティも、この API を意味しない。
放棄された `workspace_qualified_extensions` の提案は、プロトコルの一部ではない。

## Non-goals

- ワークスペースごとのアーティファクトのコピー。
- デーモンのレジストリやリモートの確認プロトコル。
- 受け入れられた操作のユーザーによるキャンセル。
- 1 つの `QWEN_HOME` への、古いバイナリと V2 を認識する書き込みの並行。
- 将来のプロトコル v2 へのマイグレーション前の V1 アダプターの削除。
