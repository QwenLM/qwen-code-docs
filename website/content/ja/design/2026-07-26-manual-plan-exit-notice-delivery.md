# 手動プラン終了通知の配信

## 問題

プランモードは、モデルに紐づくユーザーターンで繰り返されるリマインダーによって補強されている。
承認モードが承認済みの `exit_plan_mode` フローの外側で変更された場合、そのリマインダーを
単に停止するだけでは、プランモードが終了したことの信頼できるシグナルにならない。

既存のワンショット通知は `GeminiClient` 内で UserQuery と Cron のターン向けに組み立てられる。
その境界は、ツール結果の継続、steering、フック、ACP/デーモン直接送信、インタラクティブな
エージェントなど、他のパスを通じて送信されるモデルリクエストを見逃す。`Config` の単一の
pending ブール値により、1 つの会話が、そのモードを共有するすべてのライブ会話向けの通知を
消費できてしまう。

## スコープ

この保証は、現在のプロセス内のライブ会話に適用される。通知をプロセス再起動をまたいで
永続化せず、承認チェック、プラン承認、ツール実行も変更しない。

通知が有効になる対象:

- `GeminiClient.startChat` が作成するメインチャット（TUI、非インタラクティブ、ACP、
  デーモン/Web UI、および圧縮後の置き換えチャットを含む）;
- `AgentCore.createChat` が `interactive: true` で作成するチャット。

fork/speculation、ヘッドレスエージェント、ワークフロー、メモリとコンパクションのサイド
クエリ、および明示的に有効化されないその他のすべての `GeminiChat` では引き続き無効。

## 状態と所有権

`Config` は 2 つの独立したインメモリ状態を保持する:

- モードイベント `{ version, kind }`。`kind` は `clear` または `manual-exit`;
- 会話カーソル `{ seenVersion }`。

イベントは承認モードとともに所有される。`Object.create(parent)` で作成された `Config` は、
親の承認モードと現在のイベントの両方を継承する。自身の承認モードを作成する最初の書き込みで、
現在のイベントをコピーし、その後、以降の親イベントから隔離される。

カーソルは常に、受信側の `Config` が遅延所有する。したがってメイン会話と各インタラクティブ
エージェントは、同じ継承イベントを独立してクレームできる。同じ `Config` でチャットを
再作成してもカーソルは保持され、イベントは再配信されない。

モード遷移は次のようにイベントを更新する:

- 非プランからプランへは version をインクリメントし `clear` を書き込む;
- プランから非プランへは version をインクリメントし `manual-exit` を書き込む。ただし
  承認済みの `exit_plan_mode` は `clear` を書き込む;
- 非プランから非プランへはイベントを作成しない。

プランへの突入は、未配信の古い終了通知をクリアする。配信は最新の承認モードを読み取るため、
後続の非プランから非プランへの切り替えは、別の通知を作成せずに pending 通知内のモード名を
変更する。

## 配信と失敗のセマンティクス

`GeminiChat` はべき等なオプトインを公開する。各送信で、非同期の圧縮とハードレスキュー
チェックを完了してから、ユーザーコンテンツを履歴にコミットする直前に同期で pending
イベントをクレームする。通知は最後のテキストパートとして追加され、その前にある
function response パートは保持される。

線形化ポイントは、通知を含む履歴コミットの成功である。プロバイダーのリトライと
フォールバックはそのコミット済みリクエストを再利用し、履歴に 2 回目の通知を追加しない。
同期の送信準備がスローして履歴 push をロールバックした場合、そのクレームは、同じ
manual-exit イベントがまだ現在であり、モードがまだ非プランであり、カーソルがまだその
version を指している場合にのみ復元される。後のモードイベントは古い復元を陳腐化させ、
無害にする。

実装は、失敗したトランスポートリクエストをプロバイダーが受信したかを判定できない。
トランスポートのリトライは同じリクエストを複数回送信しうるが、ライブのチャット履歴には
通知は最大 1 回しか含まれない。

コンテキストオーバーフローからの復旧は、元のリクエストを再利用する例外である: 反応的な
圧縮は、リトライペイロードを再構築する前にライブ履歴を置き換える。圧縮後の履歴に
コミット済みの通知が含まれなくなった場合、チャットはリトライ前にその正確なテキストを
再追加する。圧縮がすでにユーザーターンで終わっている場合、隣接するユーザーターンを
作るのではなく、その最後のパートとして通知を追加する。

## 通知

```text
<system-reminder>
The approval mode changed outside the approved exit_plan_mode flow.
The current approval mode is: ${currentMode}.
Plan mode is no longer active. This notice supersedes any earlier reminder that Plan mode is active. Do not call exit_plan_mode; no plan approval is pending. Continue under the current mode's permissions and confirmation requirements.
</system-reminder>
```

## 検証

ユニットテストは、遷移セマンティクス、継承イベントの所有権、独立した会話カーソル、
陳腐化した復元の挙動、オプトイン配信、パート順序、準備のロールバック、リトライ、
チャット再作成、チャット所有権をカバーする。E2E プランは PTY、ACP、インタラクティブ
エージェント、承認済みプラン終了をカバーする。
