# MCP ツール名のプロバイダー互換性

## Problem

Qwen Code は現在、Gemini の文字セットを使用して MCP ツール名を受け入れている。`literature.search_pubmed` のような名前は `mcp__server__literature.search_pubmed` になるが、これは Gemini は受け入れる一方で、より厳密な OpenAI 互換や Anthropic 互換のエンドポイントはツールを実行する前に拒否し得る。

同じ生名が、登録、権限の永続化、再接続時の検索、出力の切り詰め、復元された履歴において、独立して再構築される。そのため、プロバイダーリクエストのみを変更すると、モデルから見える名前がレジストリキーと食い違ってしまう。

## Design

MCP ツール名に 1 つの決定的なプロバイダー安全な正規化ルールを使用する:

- すでに `^[A-Za-z][A-Za-z0-9_-]*$` に一致し 63 文字以下の名前は保持する。
- サポートされない文字を置換し、先頭をアルファベットにし、正規化や切り詰めが必要な場合は安定した短いハッシュを付加する。
- 最終名を 63 文字以下に保つ。これは Gemini と、より厳密な OpenAI 互換・Anthropic 互換プロバイダーに受け入れられる。
- MCP 呼び出し中は、生のサーバー名とツール名から再構築するのではなく、登録済み名を使用する。
- 復元された OpenAI と Anthropic のリクエスト履歴内の MCP 名を正規化し、変更前に作成されたセッションも送信可能なままにする。
- 生のサーバー名とツール名から導出された、正規化前の正確なエイリアスを保持することで、レガシーの MCP 権限エントリと無効化ツールエントリのマッチングを継続する。これにより、ワイルドカードマッチングを広げることなく、以前の中間切り捨てアルゴリズムで切り詰められた名前も保持される。

プロバイダー固有のエイリアステーブルは導入しない。正当な既存名はバイト単位で変更されないため、Gemini の挙動と通常の組み込みツールは影響を受けない。

以前の中間切り捨てアルゴリズムが生成した復元名はすでにプロバイダー安全であり、履歴メッセージ内で変更されないままである。その除去された中間部分は確実に再構築できないため、コンバーターは新しいハッシュベースの名前を推測しない。正確な権限と無効化ツールの互換性は、代わりに MCP 登録時に利用可能な生名エイリアスを使用する。

## Verification

- 有効、無効、衝突、長名、安定、べき等な名前のユニットテスト。
- 登録、権限ルール、再接続時の検索、無効化ツールの MCP ツールテスト。
- ドット付き MCP 名を含む復元履歴の OpenAI と Anthropic のコンバーターテスト。
- Core パッケージのビルドと typecheck。
