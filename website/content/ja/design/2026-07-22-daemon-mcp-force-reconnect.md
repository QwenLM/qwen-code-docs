# デーモン MCP の強制再接続

## 問題

`POST /workspace/mcp/reload` は永続化された設定を再読み込みしますが、MCP 接続は増分的に reconciliation します。設定が変更されていないサーバーは既存のトランスポートを保持します。したがって、別の Qwen Code プロセスによって書き込まれた OAuth 認証情報は、そのトランスポートが再接続するまで読み取られません。

## 設計

オプションの `forceReconnectAll` および `forceReconnectWhich` フィールドを、両方のワークスペース MCP リロードルートとその SDK/ACP ブリッジメソッドに追加します。`forceReconnectAll` はデフォルトで `false` です。`forceReconnectWhich` は名前付きサーバーを選択します。これらのフィールドは相互に排他です。

いずれかの再接続オプションが指定されると、デーモンはまず通常の設定 reconciliation を実行します。その後、ワークスペース全体のすべての設定済み MCP サーバー、または `forceReconnectWhich` で選択された名前のみを再接続します:

- プールされたサーバーは、サーバー名ごとに 1 回、ワークスペースのトランスポートプールを通じて再起動し、その後ライブ設定のモデルツールスナップショットを更新します;
- プールエントリのないサーバーは、既存の設定ごとのディスカバリーパスを使用します。これは再ディスカバリーの前に切断して再接続します。

これは意図的に OAuth を開始しません。新しい接続を生じさせるだけで、デーモンのトークンストレージによって現在永続化されている認証情報を読み取ります。

## API

`POST /workspace/mcp/reload` および `POST /workspaces/:workspace/mcp/reload` は以下を受け付けます:

```json
{ "forceReconnectAll": true }
```

`forceReconnectWhich` は空でないサーバー名の配列を受け付けます。無効な値は 400 を返します。
作業はキューに入れられるため、レスポンスは `202 { "accepted": true }` のままです。

## 検証

- ルートテストは、デフォルトの転送、`true` の転送、無効な入力をカバーします。
- ACP テストは、各ライブ設定への伝播と強制再接続の動作をカバーします。
- E2E 計画は、OAuth トークンが外部で書き込まれたシナリオを文書化します。
