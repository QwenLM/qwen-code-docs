# デーモンのマルチワークスペース強化ベースライン

Status: イシュー [#6378](https://github.com/QwenLM/qwen-code/issues/6378) の
現在の実装ベースラインおよびレビュー契約。このドキュメントは強化フェーズを
締めくくるものであり、新しいデーモン機能を追加するためのロードマップではない。

## 所有権モデル

すべてのデーモンルートと下流の操作は、これらの所有権クラスの
ちょうど 1 つに属する：

| 所有権              | 意味                                                                                                                                                                                     |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| プロセスグローバル  | 認証、HTTP レート制限、接続制限、メトリクス、シャットダウンなど、すべてのランタイムで共有される 1 つのリスナー/プロセスリソース。                                                        |
| レガシープライマリ  | 契約が意図的にプライマリランタイムを対象とする互換ルート。ワークスペースセレクターの省略は、別の所有者を推測する許可ではない。                                                            |
| ワークスペース修飾  | ルートはまず明示的なワークスペース id を解決し、次にエンコードされた正規の絶対 cwd を解決し、選択されたそのランタイムにのみディスパッチする。                                              |
| ライブセッション所有者 | 単数形のライブセッションルートは、セッションを所有する一意のブリッジを登録済みランタイムからスキャンし、そこにのみディスパッチする。                                                       |
| 永続化ワークスペース | ルートは永続化されたセッションや organization ストレージを読み取る前にワークスペースを解決する。信頼されていないセカンダリに対し、ACP を開始せずに宣言済みの読み取り専用サーフェスを公開できる。 |

プライマリワークスペースは最初の起動ランタイムであり、そのフォールバックを
明示的に文書化したルートの互換デフォルトである。解決に失敗したときの
汎用的なフォールバックではない。

## 失敗時のセマンティクス

| 状態                         | 求められる挙動                                                                                                                                                                                                                                                                                  |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 未知のワークスペースまたはセッション | ルートの安定した mismatch/not-found レスポンスで fail closed（失敗時は拒否）する。プライマリに対するプローブや実行を行わない。                                                                                                                                                                  |
| 信頼されていないワークスペース | ランタイム backed の実行と変更を拒否する。信頼されていないセカンダリは、ACP の開始や修復状態の書き込みなしに、制限付きファイルシステムや永続化カタログ/トランスクリプトの読み取りを含む、明示的に文書化された読み取り専用サーフェスのみを使用できる。レガシープライマリのプリヒートはリクエストを認可しない。 |
| あいまいなライブセッション所有者 | ディスパッチを安全に行えないため、サーバーエラーを返す。どのブリッジでも実行しない。                                                                                                                                                                                                                |
| ブートストラップ中のランタイム | プロセスグローバルの liveness を応答性の高い状態に保つ。ランタイム backed の作業は、宣言された起動失敗を待つか報告する。集約が利用できない間、deep ヘルスは理由付きの `503` を返す。                                                                                                          |
| drain 中のランタイム | 安定した drain 中レスポンスで新しい作業を拒否する。強制でない削除は、アクティビティが存在する場合 `workspace_busy` でロールバックする。強制削除は終了とアクティブリソースの制限付きクリーンアップを要求する。ランタイムは削除が完了するまでデーモン全体の計算に残る。               |
| 削除されたランタイム | 未知として扱う。同じワークスペースを再追加する前に、ケイパビリティ、ルーティング、ヘルス集約から消えなければならない。永続化のコミットポイント後のクリーンアップはベストエフォートであり、失敗はログに記録され、ルーティングを復元しない。                                                    |

## 不変条件

- ワークスペースの解決は、未知、信頼なし、あいまい、drain 中、削除済みの
  結果の後にプライマリへフォールバックしない。
- ワークスペース id はエンコードされた cwd セレクターより優先される。
  cwd セレクターは絶対パスでなければならず、登録済みランタイムに正規化
  されなければならない。
- 各アクティブなワークスペースランタイムは、自身の環境スナップショット、
  ブリッジ、ワークスペースサービス、ファイルシステム/信頼境界、Voice 状態、
  ACP/MCP リソース境界を所有する。本番は互換性のためにプライマリーブブリッジの
  プリヒートを試み、プリヒート失敗後は最初の使用時にリトライする。
  信頼されたセカンダリは必要時に ACP 子プロセスを開始し、
  `mcp_workspace_pool` が有効な場合はその子プロセス内のプールを所有する。
  信頼されていないセカンダリはどちらも開始してはならない。プライマリの
  プリヒートはルートの信頼ゲートをバイパスしない。
  プロセスグローバルの Voice コーディネーターが、所有ランタイムごとの
  リースを追跡しつつ、共有の受け入れ上限を強制する。同名の環境キーは
  ランタイム間で交差してはならず、ワークスペースオーバーレイは親プロセスの
  環境を変更してはならない。
- 単一のデーモントークンがプロセスを認証する。これはワークスペースごとの
  ACL ではない。HTTP レート制限、リスナー上限、総セッション受け入れ、
  メトリクス、シャットダウン、プロセスの故障半径もデーモン全体である。
- `mcp_workspace_pool` が広告されている場合、MCP トランスポートと予算計算は
  1 つのワークスペースランタイム内のセッションで共有され、ランタイム間で
  共有されることは決してない。タグがない場合、クライアントはレガシーの
  セッションごとのマネージャーと `scope: 'session'` ステータスを
  受け入れなければならない。
- プライマリを含む明示的な起動/静的ランタイムは削除できない。
  動的または永続化されたセカンダリランタイムは、追加、drain、削除、
  再追加のライサイクリルールに従う。drain 中のランタイムは、論理的な
  削除が完了するまでデーモン全体のヘルスに表示され続ける。強制削除は
  アクティブリソースを中断し、制限付きのベストエフォートティアダウンを
  実行する。クリーンアップタイムアウトは、論理的な削除をロールバックする
  代わりにログに記録される。
- shallow `GET /health` は正確に `200 {"status":"ok"}` のままである。
  deep ヘルスはアクティブおよび drain 中のランタイムを集約し、
  ブートストラップまたは集約失敗時には理由付きの `503` を返し、
  ワークスペースパスを公開しない。
  [daemon-global deep health](./daemon-global-deep-health.md) を参照。
  [PR #6961](https://github.com/QwenLM/qwen-code/pull/6961) で実装された。

## レビュー契約

新規または変更されたすべてのデーモンルートについて、レビュアーは所有権
クラスを明示し、環境、ブリッジ、サービス、ファイルシステム、信頼、
失敗処理を通じてリクエストを追跡しなければならない。所有権解決の失敗後に
下流コンシューマがプライマリ状態を暗黙的に使用できる場合、そのルートは
不完全である。

レビューの発見事項は次のように分類される：

- 正確性、セキュリティ、データ損失、分離、または fail open（失敗時は許可）の
  リグレッションは強化に属し、影響する変更をブロックする。
- 意図的なプライマリ専用契約の新機能や移行は、別のイシューと設計を
  得る。この締めくくりを拡大しない。
- 具体的な欠陥のないリファクタリングは強化のスコープに入れない。

およそ 5 ラウンドのレビュー後は、正確性、セキュリティ、データ損失、
リグレッションの修正のみがアクティブな強化 PR を拡大すべきである。
その他の有効な提案はフォローアップとして記録し、アンブレラが
無期限に開いたままにならないようにする。

## 明示的な現在の制限

- `POST /session/:id/branch`、`POST /session/:id/fork`、
  `POST /session/:id/cd` は、セカンダリ所有のライブセッションに
  対してはレガシープライマリのままであり、
  `non_primary_session_route_not_supported` を返す。
- 名前付きのデーモン管理チャネルは所有ワークスペースごとにグループ化され、
  所有ランタイムごとに 1 つのワーカーを実行する。`--channel all` は
  意図的にプライマリ専用のままである。
- デーモンはワークスペースごとの認証、レート制限、プロセスの故障分離を
  提供しない。これらの境界が必要な場合は、別のデーモンをデプロイする。

## 終了ルール

このベースライン、その契約テスト、ルート/環境ガード、デーモン全体の
deep ヘルスが #6378 の固定された締めくくりである。Branch/fork ルーティングと
`cd` のセマンティクスは独立した機能作業のままである。締めくくり PR が
投入された後、将来のレビュー発見事項は、無制限の強化バケットを
再開するのではなく、焦点を絞ったイシューとして提出すべきである。
