# Auto-Skill Curator

## 問題

Qwen Code はツール中心の会話から再利用可能なプロジェクトスキルを抽出できるが、
承認された auto-skill は蓄積するだけである。既存のレビューエージェントは
`source: auto-skill` スキルの作成または更新はできるが、削除は明示的に禁止されている。
パスによるゲーティングと `skills.disabled` はプロンプトのノイズを減らすものの、
ディスク上のライブラリはメンテナンスされない。

## スコープ

プロジェクトの auto-skill 向けの小さく決定的なライフサイクルマネージャーを追加する:

- ディレクトリが `auto-skill-` で始まり、frontmatter に `source: auto-skill` を含む
  プロジェクトスキルの正常な呼び出しを追跡する。
- 30 日間アクティビティのない管理対象スキルを stale とマークする。
- 90 日間アクティビティのない場合、ディレクトリ全体を `.qwen/skills/` の外、
  `.qwen/archived-skills/` に移動してアーカイブする。
- 個々の管理対象スキルを自動遷移から除外する pin を許可する。
- Auto Skill が有効でワークスペースが信頼されている場合、設定初期化中に決定的パスを
  最大 7 日に 1 回実行する。
- インタラクティブ、非インタラクティブ、ACP のコマンドサーフェスに `/curator`、
  `/curator status`、`/curator run [--dry-run]`、
  `/curator pin|unpin|restore <directory>` を公開する。

この最初のバージョンは LLM を使用せず、重複するスキルの統合、personal/bundled/
extension/learned/手書きスキルの管理、いかなるものの恒久削除、設定可能な閾値の導入も
行わない。

## 所有権と永続化

curator は `Config.getProjectRoot()` からのみ解決される。その状態は
`<project>/.qwen/skill-curator.json` に置かれ、アーカイブされたパッケージは
`<project>/.qwen/archived-skills/` に置かれる。プロセスのプライマリワークスペース、
ホームディレクトリ、他のアクティブセッションへのフォールバックはない。これにより
デーモンとマルチワークスペースセッションは隔離される。

状態は auto-skill のディレクトリ名をキーとする。それがアーカイブへの移動および
アーカイブからの復元の単位だからである。各レコードは frontmatter のスキル名、初回観測時刻、
最後の正常使用、使用回数、ライフサイクル状態、pin 状態、任意のアーカイブ時刻を保存する。
書き込みはクロスプロセスロックでシリアライズされ、アトミックにコミットされる。

破損した状態はハードな非変更失敗である。curator は、永続化された証拠を読み取れない場合に、
使用記録の欠落から非アクティブを推論してはならない。

## 対象判定と安全性

ディレクトリが curator の管理対象となるのは、すべての条件が成り立つ場合のみ:

1. プロジェクトのスキルルート直下の、symlink でないディレクトリである。
2. 名前が `auto-skill-` で始まる。
3. 通常の symlink でない `SKILL.md` を含む。
4. 先頭の YAML frontmatter が正確に `source: auto-skill` を含む。

この二重のマーカーにより、curator が手書き、learned、extension、bundled、personal、
不正形式、または symlink されたコンテンツを移動するのを防ぐ。アーカイブと復元は
既存スキルを決して上書きしない。移動先の競合はそのパッケージのみをスキップし、
無関係なメンテナンスは続行できる。アーカイブされたディレクトリ名はレビュープロンプト内で
予約済みとして表示され、その書き込みパーミッションガードによって拒否される一方、
確認のステージングは引き続きアクティブなスキルのみをスナップショットする。
移動後に状態の永続化が失敗した場合、パスはエラーを表面化させる前にすべてのパッケージを
元に戻そうとする。

読み取り専用のステータスと dry-run プレビューは、セーフモードと信頼されていない
ワークスペースでも引き続き利用可能。メンテナンスパスの適用、pin、unpin、復元には、
セーフモード外の信頼されたワークスペースが必要。

## アクティビティと遷移

正常な Skill ツールまたは直接的なスキルスラッシュコマンドの呼び出しは、自動スキル生成が
無効な間でも、対象となる auto-skill のレコードをベストエフォートで更新する。これにより
観測されたアクティビティは、生成とスケジュールメンテナンスを制御するスイッチから独立する。
失敗した呼び出し、スキル無効、フックによるブロックはカウントされない。

ライブスキルにとって、アクティビティは以下のうち最新のもの:

- 永続化された最後の正常呼び出し;
- 永続化された初回観測時刻;
- 永続化された復元時刻;
- スキルマニフェストの変更時刻。

変更時刻を含めることで、最近改良されたスキルが、まだ再度呼び出されていないというだけの
理由でアーカイブされるのを防ぐ。

各対象スキルの初回観測は、古いファイルシステムタイムスタンプから非アクティブを推論する
のではなく `firstSeenAt = now` を種付けする。最初の自動観測は `lastRunAt` にも種付けし、
その後 7 日間の完全な間隔を待つ。明示的な `/curator run` は間隔をバイパスするが、
スキルごとの初回観測猶予は保持する; `--dry-run` は、ディレクトリの移動や状態変更なしで
同じ種付けと遷移候補を報告する。pin されたレコードは、明示的に unpin されるまで
stale とアーカイブの遷移をバイパスする。

## 統合ポイント

- `Config.initialize`: `SkillManager` がファイルシステムをスキャンする前に、期限の来た
  決定的パスを実行する。
- `SkillTool`: 管理対象スキルの正常な呼び出しを記録する。
- `SkillCommandLoader` とインタラクティブ/非インタラクティブのコマンドプロセッサー:
  直接的なスラッシュコマンドの正常な呼び出しを記録する; ACP は非インタラクティブ
  プロセッサーを再利用する。
- `SkillManager`: 手動のアーカイブまたは復元の後に既存のリフレッシュパスを使用し、
  モデルとスラッシュコマンドのサーフェスが即座にディスクと一致するようにする。
- `BuiltinCommandLoader`: 新しい `/curator` コマンドを公開する。

他のコンシューマーは curator の状態を書き込んだり、管理対象スキルパッケージを移動
したりすべきでない。

## 検証

ユニットテストは、対象判定、初回実行の種付け、stale/アーカイブ閾値、dry-run の非変更、
最近使用の保護、最近変更の保護、破損状態の fail closed（失敗時は拒否）挙動、競合処理、
復元、コマンドサーフェスをカバーする。既存の Skill ツールテストは、正常な読み込みのみが
使用を記録することを検証する。ビルドと typecheck はパッケージ間エクスポートとコマンド
登録をカバーする。
