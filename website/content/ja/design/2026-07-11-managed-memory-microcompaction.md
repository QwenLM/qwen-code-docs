# Managed Memory のマイクロコンパクションによる保持

## 問題

Managed memory のトピックファイルは `read_file` で遅延読み込みされます。マイクロコンパクションは現在、それらの結果を通常のツール出力と同様に扱い、古い内容を `[Old tool result content cleared]` に置き換えます。メモリのインデックスは引き続き利用可能であり、最近の修正により後続の `read_file` が実際のバイトを再び返すようになりましたが、アクティブなモデルがメモリの再読み込みが必要であることに気づくことは保証されません。

Issue #6487 は `/remember` 後の古いインデックスも報告していますが、その部分は PR #6497 がすでに対応しています。本設計は、マイクロコンパクションによって削除される managed memory の内容のみを扱います。

## 選択した設計

`MicrocompactOptions` に、成功した結果を保持しなければならない `read_file` パスを特定する狭いコールバックを追加します。マイクロコンパクションは、アイドル時、強制、サイズベースのクリアプランを構築する前に、各レスポンスをリクエスト側の `file_path` と対応付け、保護された結果をコンパクション対象セットから除外します。その他のツール、通常のファイル読み取り、エラー、およびパスを解決できないレスポンスは現在の動作を維持します。

本番のマイクロコンパクションのすべてのエントリポイントは、同一の述語を提供します:

- 送信前のアイドル時およびサイズベースのコンパクション
- `/compress-fast`
- メモリプレッシャーによる履歴コンパクション

この述語は、realpath を考慮した包含関係により、プロジェクト、ユーザー、チームの managed memory ルートを認識します。managed ルートの外側へ逃げるシンボリックリンクは保護されません。

## このレベルを選んだ理由

読み込まれたすべてのメモリ本体をシステム指示に注入すると、メモリが恒久的にコンテキストを消費するようになり、既存のインデックス＋遅延読み込みの設計を置き換えることになります。フルコンパクション後にすべてのメモリファイルを再アタッチするには、別途トークンバジェットと復元ポリシーが必要です。マイクロコンパクションからの managed memory の読み取りのみを保持すれば、再現されたクリア動作を限定的な変更で直接修正でき、フルコンパクションは既存のハードなコンテキスト削減の境界として残ります。

そのため、フルコンパクションは意図的にバイトを保持しません。そのサマリはコンパクション前のメモリ内容を参照し、`MEMORY.md` のインデックスはシステム指示に残り、モデルが正確なバイトを再読み込みできるようファイル読み取りキャッシュはクリアされます。本変更は、マイクロコンパクションをまたぐ保持のみを保証します。

## リスクとテスト

Managed memory ファイルの繰り返し読み取りは、フルコンパクションまで複数のコピーを保持し得ます。これは意図的なトレードオフです: それらのツール結果トークンの回収よりも、永続的なガイダンスの方が重要であり、フルコンパクションは引き続きハードキャップとして利用可能です。

テストは、プロジェクト、ユーザー、チームのルート、通常の読み取り、シンボリックリンクによる脱出、アイドル時、強制、サイズベースのパス、保護された結果とコンパクション可能な結果の混在、曖昧または欠落したレスポンス ID、および eviction メタデータをカバーします。
