# プランモードのターン途中ガイダンスとエントリー境界

## 問題

`enter_plan_mode` は、モデルのターンがまだ処理されている間に承認モードを変更します。この変更の前は、呼び出しの成功は短い 1 文のみを返していたため、モデルは後のターンまで完全なプランモードの制約を受け取りませんでした。同じモデルレスポンスからの兄弟ツール呼び出しは、モード遷移のどちら側でも実行される可能性がありました: エントリー前の呼び出しは以前のモードの下で実行され、エントリー後の呼び出しは、新しい境界に対して再スケジュールされることなく、プランモードがアクティブになった後に実行されました。

## 契約

成功、またはすでにアクティブな `enter_plan_mode` の呼び出しは、`getPlanModeSystemReminder()` が生成するのと同じ完全なリマインダーを返します。SDK セッションは SDK 固有のバリアントを受け取ります。要請のない YOLO 突入、遷移の失敗、サブエージェントや teammate による拒否は、プランモードの遷移が発生していないため、既存の結果を保ちます。

重複排除後の実行可能バッチが複数の呼び出しを含み、その 1 つが `enter_plan_mode` である場合、最初のエントリー呼び出しが実行境界です。その呼び出しのみが実行の対象となります。他のすべての実行可能な兄弟は、エントリーの前または後のどちらに現れたかに関係なく、新しい承認モードを観測した後の次のターンでリトライするようモデルに指示する、終端の `EXECUTION_DENIED` レスポンスを受け取ります。エントリーの失敗やべき等な成功は、兄弟を解放しません。

既存の終端決定が優先されます。ループ検出は引き続き最初にバッチ全体を拒否します。重複したプロバイダーレスポンスは元の位置で発行されますが、実行可能な兄弟ではありません。構造化出力モードでは、既存の構造化出力プレスキャンが終端のままであり、`enter_plan_mode` を他の非構造化呼び出しとともに抑制します。

`exit_plan_mode` はこの変更では実行境界ではありません。その明示的なユーザー承認と stale コンテキストの保護は独立しています。

## 統合

コアスケジューラーは、呼び出し ID の重複排除と正規名の解決の後、パーミッションチェック、レジストリ参照、フック、呼び出し構築の前に境界を適用します。したがって、スキップされた呼び出しはパーミッションを要求せず、ツールごとのフックを実行しません。それらは終端のバッチ結果のままなので、既存の完了コールバック、記録、テレメトリー、`PostToolBatch` 監査パスは、受け入れられたすべての呼び出し ID に対して完全なレスポンスを観測します。ランタイム固有のコンテンツジェネレータービューは、他の終端結果とともにクリーンアップされます。

ACP は、ループおよび重複プロバイダー処理の後、順次バッチや Agent バッチの実行の前に同じポリシーを適用します。重複レスポンスは順序を保ちます。ACP は `PostToolBatch` フックを導入しません。そのパスは意図的にそれをサポートしていないためです。

ヘッドレスモードは、重複および構造化出力のフィルタリング後にポリシーを適用します。スキップされた呼び出しは元の順序で発行され、拒否されたツール結果として返されますが、`--max-tool-calls` バジェットを消費しません。エントリー自体は通常のバジェットと中止の動作に従います。

## 出力の保持

リマインダーはライフサイクルポリシーであり、通常のツールペイロードではありません。`enter_plan_mode` はツールごとの無限の出力上限を宣言し、スケジューラーの永続化スピルゲートの適用外であり、集約バッチオフロードの候補ではありません。これら 3 つの保護により、ポリシーが切り詰められたり、ファイルポインターに置き換えられたり、次のモデルターンの前にプレビューに縮小されたりすることがなくなります。

## 検証

ユニットカバレッジは、正確な DEFAULT および SDK のリマインダー、成功およびべき等なエントリー、最初のエントリーの選択、両側での兄弟拒否、重複プロバイダーの順序、ヘッドレスのバジェット集計、意図的に小さな出力しきい値下での完全なリマインダーの保持、`PostToolBatch` の可視性、ランタイムビューのクリーンアップを検証します。既存のスケジューラー、ACP、ヘッドレスのスイートは、周辺のパーミッション、ループ、重複、構造化出力、中止の動作をカバーします。

管理対象ホストの検証では、ACP クライアントがすべてのツール呼び出しに対して 1 つの結果を受け取ること、および次のモデルリクエストが完全なリマインダーと兄弟拒否レスポンスを含むことを確認すべきです。この検証にはデプロイされたビルドとホストのセッション ID が必要です。この PR では本番ルーティングを変更してシミュレートするものではありません。
