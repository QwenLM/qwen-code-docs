# デーモンのワークスペース表示名

## ゴール

デーモンおよび TypeScript SDK のクライアントが、ワークスペースの identity やルーティングを変更せずに、オプションの人間が読める表示名を登録済みワークスペースに付与できるようにします。Web Shell のユーザーがワークスペースの追加時にその名前を設定し、ワークスペースリストで見られるようにします。API クライアントがアクティブなワークスペースの表示メタデータを更新またはクリアできるようにします。

## 契約

- `workspaces[]` エントリにオプションの `displayName` メタデータが追加されます。
- `POST /workspaces` は、セカンダリワークスペースの登録時または永続プロモーション時に、オプションの `displayName` を受け付けます。
- `PATCH /workspaces/:workspace` はワークスペース更新のエンドポイントです。現在のリクエスト形式は `{ displayName: string | null }` です。`null` は名前をクリアします。
- `POST /workspaces`、`PATCH /workspaces/:workspace`、および永続化登録の一覧表示は、存在する場合は実効の表示名を返します。
- `workspace_display_name` がこの契約を通知します。TypeScript SDK は登録オプションと `updateWorkspace()` を公開します。
- ケーパビリティが通知されている場合、Web Shell のワークスペース追加ダイアログはオプションの表示名を受け付け、ワークスペースラベルに使用します。

`id` と `cwd` が唯一のワークスペースセレクターであり続けます。表示名は検索に使われることはなく、一意である必要もありません。

## ランタイムと永続化

ランタイムが実効の表示名を所有します。アクティブなワークスペースの更新は、そのランタイムメタデータを変更します。ランタイムが一致する永続化登録 identity を持つ場合、同じ更新がそれらすべてにアトミックに書き込まれます。それ以外の場合、更新はプロセスローカルのままです。プロセスローカルのワークスペースは、デーモンが停止するとランタイムとその名前の両方を失い、表示名の更新のために登録ストアに依存することはありません。

既存のスキーマ v1 登録ファイルは `workspaces: string[]` の形式を保持し、既存の安定した登録 ID をキーとするオプションの `displayNames` オブジェクトを追加します。更新は、ストアの既存のロック、ロック下での再読み取り、アトミックな書き込みを再利用します。古いデーモンは追加されたフィールドを無視し、新しいデーモンはそれを含まないファイルの読み取りを継続します。登録を削除すると、その表示名エントリも削除されます。

## 検証と失敗

ワークスペースの表示名は、前後の空白をトリムした後で 256 文字に制限されます。内部の C0 および DEL 制御文字は拒否されます。空の結果は名前なしとして扱われます。無効な入力は、ファイルシステムやランタイムの作業が開始される前に `400 invalid_display_name` を返します。表示名の重複は許可されます。

プロセスローカルのワークスペースが初めて永続化されるとき、永続化された表示名がランタイムで公開される前に、登録ストアへの書き込みが完了します。同様に、PATCH は新しいランタイム値を公開する前に一致する永続レコードを更新するため、通常のストア失敗ではランタイムは変更されません。

## 互換性

ワイヤー上の変更はすべて、プロトコル v1 に対して追加的です。古い SDK は `displayName` を無視します。新しい SDK はそれをオプションとして型付けし、フィールドとケーパビリティタグの両方を省略する古いデーモンとも引き続き動作します。Web Shell はケーパビリティタグが存在しない場合、表示名のコントロールを非表示にします。

## 検証

- 登録ストアのテストは、レガシーファイル、初期の名前、バリデーション、アトミックなエイリアス更新、再起動後の復元、削除時のクリーンアップをカバーします。
- ワークスペース管理のテストは、プロセスローカルおよび永続の作成、更新/クリア、永続化エラー、べき等なプロモーションをカバーします。
- ケーパビリティ/ステータスおよび SDK のテストは、追加フィールド、リクエスト形式、`updateWorkspace()`、`workspace_display_name` の通知をカバーします。
- Web Shell のテストは、オプション入力、SDK オプションの転送、ラベルのフォールバックをカバーします。ブラウザのスクリーンショットで、実際のワークスペース追加フォームとその結果のサイドバーラベルを検証します。
- 手動のエンドツーエンド検証は、プロセスローカル登録と永続化の再起動復元をカバーします。
