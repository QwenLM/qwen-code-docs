# デーモンのワークスペースランタイム削除

## コンテキスト

ランタイムのワークスペース登録と永続化登録はすでに利用可能ですが、永続化登録を消去しても、ライブブリッジ、ACP マウント、セッション受け入れ状態、メモリレーンはアンロードされません。本設計では、既存の登録消去 API を維持しつつ、セカンダリランタイムの同期的なホット取り外しを追加します。

## スコープと不変条件

- 削除可能なのは、動的に登録されたセカンダリランタイムと、永続化から復元されたセカンダリランタイムのみです。プライマリおよびすべての `--workspace` ランタイムは静的です。
- `DELETE /workspaces/:workspace` はランタイムと既知のすべての永続エイリアスを削除します。ワークスペースのファイル、設定、トランスクリプト、アーカイブ、その他のプロジェクトデータを削除することはありません。
- 非強制削除は観測ベースです: フリーズされたランタイムにアクティビティがある場合、すべてのゲートがロールバックされ、リクエストは `409 workspace_busy` を返します。強制削除はそのアクティビティを終了させます。
- 破壊的なクリーンアップの前に永続化がコミットされます。ストアの失敗時はアクティブなランタイムを復元します。ストアのコミット後のクリーンアップ失敗は操作をロールバックできないため、フォールバックとして同期的なブリッジキルを使用します。
- 削除された cwd は、クリーンアップが完了するまで予約状態のままとなり、その後、新しいブリッジ、ACP ディスパッチャ、接続レジストリ、メモリレーンとともに再登録できます。

## プロトコル

本番デーモンは、削除コントローラーがインストールされている場合に `workspace_runtime_removal` を通知します。ケーパビリティのワークスペース行にはオプションの `removable` が追加されます。古いクライアントとデーモンは引き続き互換性を保ちます。

`DELETE /workspaces/:workspace` は既存の workspace-id-or-canonical-cwd セレクターを使用し、boolean の `force` を含むオプションの JSON ボディを受け付けます。成功時は、削除された identity、強制が要求されたかどうか、永続エイリアスが削除されたかどうか、および drain 後の最終的なアクティビティスナップショットを返します。すでに観測上ビジーな非強制リクエストは、ランタイムを短時間ゲートすることなく、drain 前のより早いスナップショットを返す場合があります。既存の `DELETE /workspace-registrations/:id` は引き続き消去のみを行います。

## ライフサイクル

レジストリは、active、draining、removed のランタイムを追跡します。パブリックな解決は active なランタイムのみを参照し、管理系の解決は競合レポートと cwd 予約のために draining 中のランタイムを保持します。

削除はまず高速なアクティビティスナップショットを取得します。次に同期的にレジストリを draining にマークし、ワークスペースごとのセッション受け入れをクローズし、ACP マウントとメモリレーンを drain します。最終スナップショットは、ライブブリッジのカウントの前に保留中のセッション予約を読み取るため、予約からセッションへの遷移がアイドルとして見えることはありません。ビジーな非強制リクエストはゲートを元に戻します。それ以外の場合は、既知のすべての登録 ID がアトミックに削除され、キューに入っていたメモリ作業が失敗処理され、サブセッションランチャーとブリッジが停止され、ACP マウントが破棄され、所有権インデックスがクリアされ、レジストリエントリが完了状態になります。

ランタイムのクリーンアップは cwd ではなくランタイムの identity 単位でメモ化されるため、同じパスに後から登録されたランタイムが古いクリーンアップ promise を再利用することはできません。デーモンのシャットダウンは管理系操作をシールし、それらの収束を待ち、ランチャーを停止した後、残りの管理対象ランタイムに対して同じブリッジの破棄パスを使用します。

## 永続化の identity

復元時は、正規化の前に各 raw 保存パスの ID を記録します。1 つのランタイムに解決される複数の raw エイリアスは、明示的な起動時ワークスペースに隠されたエイリアスを含め、1 つの ID セットとして保持されます。削除時は、スキーマを変更することなく、1 つのストアロックの下でそのセットと正規化された登録 ID をまとめて削除します。

## UI

Web Shell は、フィーチャータグと `removable: true` の両方が存在する場合にのみ削除を公開します。このアクションは信頼されていないワークスペースでも利用可能なままです。最初の確認は非強制リクエストを実行します。`workspace_busy` はアクティビティのカウントを描画し、強制削除を提案します。現在のセッションが対象のワークスペースに属している場合、強制は無効になります。成功時はケーパビリティとセッションリストを整合させ、必要に応じてプライマリワークスペースへフォールバックします。

## 失敗と互換性の分析

クライアントの切断や SDK のタイムアウトは、サーバー側のクリーンアップをキャンセルしません。並行する追加、永続化への昇格、削除操作は正規化された cwd ごとにシリアライズされます。シャットダウンは新しい管理系操作を `daemon_shutting_down` で拒否し、すでに開始された作業の完了を待ちます。古いクライアントはオプションのケーパビリティフィールドとフィーチャーを無視し、古いデーモンは存在しないルートに対して通常どおり `DaemonHttpError` を生成し続けます。

ワークスペーススコープのチャネルワーカーグループは、薄いアダプターを介してアクティビティと破棄を提供します。drain は対象ワークスペースの reload と webhook ルーティングをブロックします。コミットされた削除はそのワーカーのみを停止して登録解除するため、他のワークスペースに影響を与えることなく、デーモンのステータスと pidfile メタデータが収束します。

## 検証

ユニットカバレッジの対象は、レジストリの状態遷移とオーナークリーンアップ、受け入れ drain のロールバック、エイリアスの一括削除、busy/force/store-failure のルート動作、ブリッジ停止理由のべき等性、メモリレーンのキャンセル、SDK のリクエストエンコーディング、および Web Shell のフィーチャーと強制のガードです。E2E 計画は `.qwen/e2e-tests/workspace-runtime-removal.md` にあります。
