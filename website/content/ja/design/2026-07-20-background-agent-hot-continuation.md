# バックグラウンドエージェントのホットコンティニュエーション

## コンテキスト

完了したバックグラウンドサブエージェントは、現在そのインプロセスランタイムを失います。後続の `send_message` は JSONL トランスクリプトから新しい `AgentHeadless` を再構築します。これによりモデルに見える会話履歴のほとんどは保持されますが、チャット、ツールサーフェス、エージェントごとのレジストリ、プロバイダー側のキャッシュ状態は再作成されます。

起動パスはまた、通常のバックグラウンドエージェントを 2 回構築します: 1 回目は親のエミッターで、2 回目は専用のバックグラウンドエミッターです。最初のインスタンスは実行されることも破棄されることもありません。

この設計はセッション内のライフサイクルに対処します。親セッションの復元後の論理的な発見と継続は、バックグラウンドエージェントの roster 復元の設計で別途扱われます。

この区別は実装の詳細ではなく、動作上のものです。1 つのセッション内では、トランスクリプトの蘇生がすでにモデルに見える会話を保持しているため、ホットコンティニュエーションは主にランタイムの再構築を回避し、プロバイダー/ツールの状態を保持します。親セッションの復元をまたぐ場合、元のインメモリランタイムはプロセスの破棄を生き延びられません。したがって論理的な継続性は、タスク identity とトランスクリプトを新しいセッションに復元し、その後 1 回のコールド再構築を行うことから得られます。

## ゴール

- 新しい通常のバックグラウンドエージェントに対して 1 つのランタイムを作成する。
- 正常なターンの後、そのランタイムを常駐させ続ける。
- 同じチャットと準備済みのツールサーフェスで完了したタスクを継続する。
- 現在のタスク行、タスク ID、ターンごとの開始/完了イベント、終端通知を保持する。
- 互換性のある常駐ランタイムが存在しない場合のフォールバックとして、トランスクリプトの蘇生を保持する。
- 失敗、キャンセル、セッションのシャットダウン/リセット、終端エントリのエビクション、作業ディレクトリの変更、ブランチの切り替え、ACP セッションのクローズ/破棄時に、常駐リソースを解放する。
- 正常な完了を公開する前に、終了ウィンドウ内でキューに入れられた入力をアトミックに取得する。

## ノンゴール

- ライブランタイムをプロセスや親セッションの復元をまたいで永続化すること。
- 共有のタスクステータス union に `idle` の値を追加すること。
- アクティブに実行中のエージェントに送信されたメッセージがツールラウンド間で注入される方法の変更。
- フォークエージェントを永続化すること。
- 完了したターンをまたいで一時的なワークツリーの寿命を延長すること。
- エージェントがアイドル中に、グローバルに登録された frontmatter フックをインストールしたままにすることを安全にすること。

## 設計

### 再利用可能なヘッドレスランタイム

`AgentHeadless` は `GeminiChat` と準備済みのツール宣言をインスタンス状態として保持します。パブリックな `execute()` はターンごとの操作のままです:

- 同時に 1 つの呼び出しのみが実行可能;
- 最終テキストと終了モードは開始時にリセット; 統計は新しい親指示に対してリセットされますが、その指示の内部 stop-hook リトライ間では累積したまま;
- 最初の呼び出しがチャットを作成しツールを準備;
- 以降の呼び出しは同じチャットに新しいユーザーターンを追加し、外部メッセージイベントを発行することで、JSONL トランスクリプトが完全なままになります。

これにより、既存の `AgentHeadless` のフック、テレメトリー、外部メッセージの drain、終端結果の契約が保持されます。`AgentInteractive` は使用されません。そのキュー API は、バックグラウンドタスクが必要とするターンごとの完了結果と通知のセマンティクスを提供しないためです。

### 常駐コントローラー

`BackgroundTaskRegistry` は、タスク ID をキーとするインメモリのコントローラーテーブルを所有します。コントローラーは意図的に `AgentTask` と分離されています。`AgentTask` はシリアライズ可能な UI/ステータスレコードのままです。

コントローラーの機能:

- 完了した行からコンティニュエーションを開始;
- ランタイムを中止して破棄。

完了状態への `send_message` で、ツールはまずレジストリに常駐コンティニュエーションを問い合わせます。ヒットの場合、既存の行を同期的に `running` に戻し、通常のバックグラウンド実行スロットを確保し、前のターンが完全に確定した後で新しいターンスケジュールします。ミスの場合は既存のトランスクリプト蘇生サービスを使用します。

`completed` は引き続き「最新のターンが完了した」を意味します。ランタイムの常駐は内部実装の事実であるため、共有のタスクステータスや UI に新しい idle 状態が追加されることはありません。

### ターンごとおよび常駐のリソース

各コンティニュエーションは、新しいアボートコントローラー、SubagentStart/Stop フックのペア、トレース span、タスク開始イベント、完了通知、サイドカーのステータス遷移を受け取ります。子専用の AUTO 権限リースが必要になるランタイムは保持されません。これらのリースは並行するサブエージェント間で参照カウントされていないためです。

チャット、準備済みツール、JSONL ライター、イベントリスナー、エージェントスコープのツールレジストリ、エージェントごとの MCP リソースは、コントローラーが常駐している間生存し続けます。破棄はべき等です。

既存の終端エントリの保持上限は、常駐コントローラーにも上限を設けます。行のプルーニングはそのコントローラーを破棄します。レジストリのリセットとシャットダウンは、すでに完了したものを含め、すべてのコントローラーを破棄します。

### 互換性の除外

最初のバージョンは、以下の条件を満たす通常の命名バックグラウンドエージェントのみを保持します:

- 正常に完了した;
- `isolation: "worktree"` を使用しない;
- frontmatter フックを宣言しない;
- 子専用の AUTO 権限リースを必要としない。

一時的なワークツリーは現在各ターンの後に確定されるため、ランタイムを保持すると、その Config は削除されたディレクトリを指したままになります。frontmatter フックは現在、その存続期間中グローバルに登録されるため、アイドル中に保持すると無関係な作業に影響する可能性があります。子専用の AUTO リースは親のパーミッションマネージャーを変更し、並行するサブエージェント間で参照カウントされないため、ホットターンごとに再獲得するのは安全ではありません。フック付き、ワークツリー分離、子専用 AUTO のエージェントは、既存の JSONL 蘇生フローを通り続けます。再構築されたワークツリーエージェントは、その一時的な起動ワークツリーがすでに確定されているため、現在の親の作業ディレクトリから実行されます。

## レースと失敗処理

- 互換ランタイムが正常な完了を公開する直前、アクティブターンはレジストリキューを譲らずに drain します。入力を確保した場合、同じヘッドレスランタイムがその入力を実行し、タスクは running のままになります。キューが空の場合、トランスクリプトの永続化と running→completed の遷移が同期的に行われるため、後続の `send_message` は完了した行を観測し、誤解を招くキュー応答を受け取る代わりに常駐コンティニュエーションパスを使用します。ワークツリー分離のターンは、その後ランタイムが意図的に継続不能であるため、ティアダウン前に最終 drain を実行します。
- レジストリは、コンティニュエーションの promise がスケジュールされる前に、completed→running の遷移を同期的に実行します。したがって、2 番目の並行する `send_message` は `running` を観測し、既存のラウンド内メッセージキューを使用します。
- 次のターンは前のターンの promise の後にチェーンされ、完了通知が前の `finally` ブロックの完了前に発行されるウィンドウをカバーします。
- 失敗およびキャンセルされたターンは、常駐コントローラーを削除して破棄します。
- バックグラウンドスロットの確保に失敗した場合、行は completed のままで、呼び出し元は既存のコールド蘇生エラーパスを使用できます。
- アクティブターン中の破棄は、そのコントローラーを中止し、破壊的なリソースクリーンアップをターンの finalizer に延期します。

## 検証

ユニットテストが証明すべきこと:

- 新しいバックグラウンド起動が正確に 1 つの `AgentHeadless` を作成する;
- 2 つの連続するターンが 1 つの `GeminiChat` と 1 つの準備済みツールリストを使用する;
- 完了状態の `send_message` が常駐コントローラーを優先する;
- 常駐コントローラーがなくてもトランスクリプト蘇生が呼び出される;
- 2 番目のユーザー指示が JSONL に存在する;
- リセット、シャットダウン/キャンセル、終端プルーニングが正確に 1 回だけ破棄する;
- `/branch` が実行中のバックグラウンド作業を拒否し、ブランチが正常に初期化された後にのみ終端の常駐を破棄する;
- 作業ディレクトリの変更と ACP セッションの破棄が常駐ランタイムを解放する。

E2E シナリオは、2 つの完了フェーズで 1 つのタスク ID を使用し、2 番目のフェーズが最初のフェーズの nonce を覚えていることを検証します。物理的なランタイムの同一性は、ストリーム JSON がコンストラクタカウントを公開しないため、ユニットテストで検証されます。
