# 明示的なプラン終了の承認

## Problem

`exit_plan_mode` は、以前は承認と実行が混在していた。その確認コールバックは、
フックと実行が完了する前に `ApprovalMode` を変更し、AUTO/YOLO セッションは LLM
プラン承認ゲートを通じてユーザーをバイパスできる可能性があった。権限マネージャー
の許可ルール、権限フック、兄弟の自動承認も、実際のホスト/ユーザーのレスポンスなし
で `ask` の決定を満たす場合があった。これにより、モデル発のツール呼び出しが
ユーザーの決定なしにプランモードから離れようとする可能性が生じ、後続の実行が
失敗した場合に誤解を招くモード通知が作成されていた。

## Design

ツール呼び出しは `requiresUserInteraction()` を宣言できる。これは別の権限レベル
ではなく、本質的なインタラクション要件である。本質的な拒否や権限マネージャーの
拒否は引き続き優先し、許可ルールや自動承認モードはこれを満たすことができない。
メインセッションの `exit_plan_mode` はこの要件を宣言する。プラン必須のチーム
メイトはリーダー承認パスを維持し、通常のサブエージェントは既存のライフサイクル
ツールの拒否を維持する。

プランの確認コールバックは、4 つの決定のうち 1 つのみを記録する。プラン前の
モードへの復元、auto-edit への切り替え、default への切り替え、キャンセルの
いずれかである。モードを変更することは決してない。確認の作成により、プランの
テキスト、プラン前のモード、現在の承認モードのリビジョンが凍結される。
`execute()` は、承認が存在すること、シグナルがアクティブであること、セッション
がまだプランモードにいること、リビジョンがまだ一致していることを確認してから、
モード遷移を同期的に適用する。これにより、古い、再入力された、および並行した
終了は fail closed（失敗時は拒否）となる。プランの永続化は、遷移が成功した後に
のみベストエフォートで行われる。

`Config` は単調な承認モードのリビジョンを所有し、モードが実際に変更されたとき
のみインクリメントされる。承認モードのオーバーライドは独立したリビジョンを所有
する。既存の任意の `enteredByModel` セッター引数は、一時的に無視される互換性
パラメーターとして残る。モデルの発信源は承認に影響しない。

LLM プラン承認ゲートと、その AskUserQuestion メタデータとの結合は削除される。
`prePlanMode` は、ユーザーに表示される終了の選択肢であるため残る。
`originalRequest` と `researchSummary` は、プラン必須のチームメイトのリーダー
レビューのために残る。`resolutionSummary` は、ソース互換性のために非推奨の
TypeScript 入力プロパティとしてのみ残り、ランタイムのスキーマでは受け付けられ
なくなった。

## Host behavior

CLI と IDE の確認、ACP の `requestPermission`、stream-json の `can_use_tool` の
許可レスポンスは、明示的なインタラクションと見なされる。PermissionRequest の
許可フック、PM の許可ルール、YOLO/AUTO/AUTO_EDIT、兄弟の自動承認は見なされ
ない。フックの拒否決定は引き続き権威を持つ。承認可能なホストを持たない非イン
タラクティブな呼び出し元は、fail closed（失敗時は拒否）となる。

ACP は、権限が保留中の場合や、確認、フック、実行、遷移が失敗した場合には、
モードの更新を送信しない。プランのライフサイクル実行が成功し、実際にモードが
変更された後に、`Config` から読み取ったモードを使用して 1 回の更新を送信する。
レガシー通知の失敗は参考情報であり、正確な `legacyFrameSent` の値で拡張機能の
サイドチャネルも引き続き試行される。

## Failure behavior

- プランモードの外側からの呼び出しは、モードの変更を観測した境界のいずれかで、
  対処可能な状態のガイダンスとともに安全に失敗する。セッションがプランモードの
  外側にあり、承認のスナップショットが存在しない場合、`execute()` はガイダンス
  エラーを返す。`getConfirmationDetails()` は、プランモードの外側で呼び出された
  場合（例: PM の `ask` ルールや、権限評価と確認構築の間のプランから非プランへ
  の切り替えを介した場合）に同じガイダンスをスローする。デフォルトの権限は
  `allow` であり、これはセキュリティの問題ではなく状態の問題である。
- 無効な確認結果、キャンセル、中断、古いリビジョン、遷移の失敗は、プラン
  モードをアクティブなままにする。
- 同じリビジョンに対して承認された 2 つの終了が、両方とも成功することはできない。
- ACP ホストが `switch_mode` を提示できない場合、プランモードはアクティブな
  ままであり、エラーはユーザーをホストのモードセレクターまたは `/plan exit` に
  誘導する。
- すでに承認されたプランの保存はベストエフォートであり、成功したモード遷移を
  ロールバックしない。

## Compatibility and scope

この変更は、意図的にプランモードでの一般的なシェル実行を拡大せず、DataWorks
固有の読み取りツールも追加しない。それらは個別の権限/ツールの変更である。公開
の呼び出しメソッドはデフォルト `false` の任意であり、既存のツールと外部実装は
互換性が保たれる。
