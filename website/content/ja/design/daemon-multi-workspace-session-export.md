# ワークスペース修飾セッションエクスポート

## Summary

イシュー #6378 は、クライアントが明示的に選択した登録済みワークスペースから
永続化セッションをエクスポートすることを要求する。既存の
`GET /session/:id/export` ルートは意図的にプライマリワークスペースに
バインドされているため、セカンダリのセッションにこれを再利用すると、
`404` が返るか、同じセッション id が複数のワークスペースに存在する場合は
誤ったトランスクリプトを選択する可能性がある。

この変更は
`GET /workspaces/:workspace/session/:id/export?format=html|md|json|jsonl`、
`workspace_session_export` ケイパビリティ、対応する
`WorkspaceDaemonClient` メソッド、サポート文書を追加する。
レガシールートはプライマリにバインドされたままである。

## Contract

ワークスペースセレクターは既存の複数形ルートルールに従う：
まず正確な登録済みワークスペース id、次に正規化後の
URL エンコードされた絶対 cwd。選択されたランタイムは
信頼されていなければならない。解決と信頼のチェックは、
セッションやフォーマットの検証の前に行われる。

このルートは、選択されたワークスペースのアクティブな永続化 JSONL のみを
読み取る。別のワークスペースの検索、プライマリへのフォールバック、
ライブの所有者の解決、ACP の開始、クライアントのアタッチ、
ワークスペース設定の読み込みは行わない。アーカイブされたセッションは
利用できないままである。成功時は、レガシーのエクスポートルートと同じ
フォーマッター、ファイル名サニタイズ、MIME タイプ、キャッシュポリシー、
添付ファイルヘッダーを使用する。

エラーは既存のエクスポート/ストレージの形状を維持し、
`400 workspace_mismatch`、`403 untrusted_workspace`、
`400 invalid_export_format`、`404 session_not_found`、および既存の
`409 session_archived`、`session_archiving`、`session_conflict` の
契約を使用する。

## Capability and Compatibility

`workspace_session_export` は無条件の v1 ケイパビリティである。
複数形ルートは、id または cwd で選択された信頼された
シングルワークスペースのプライマリに対しても有用だからである。
信頼は引き続きリクエストごとに評価される。新しいタグは
`multi_workspace_sessions` とは独立しており、`session_export` や
`workspace_qualified_rest_core` から推論できない。リリース済みの
デーモンは古い両方のタグを広告するが、このルートは実装していない。

直接の SDK 呼び出し元は、新しいメソッドを古いデーモンに対して
呼び出した場合、通常の HTTP エラーを受け取る。Web Shell の統合は
この変更の範囲外であるため、その既存のプライマリ専用エクスポート
挙動は変更されない。

## Concurrency and Security

エクスポートは、セッション id をキーとする既存の共有
アーカイブコーディネーターロックを保持するため、アーカイブと削除は
リプレイ中にファイルを移動または削除できない。コーディネーターは
引き続き保守的にグローバルである：ファイルが独立していても、
異なるワークスペースの同一 id は直列化される場合がある。
アーカイブ/削除のロックキーすべてのリネームはこの変更の範囲外である。

制限付きの永続化トランスクリプトページャーとは異なり、完全な
エクスポートはトランスクリプト全体を実体化するため、信頼されていない
セカンダリワークスペースでは利用できない。既存の信頼された
エクスポートに新しいレスポンスサイズのバジェットはない。
ワークスペース固有の制限を追加すると、複数形とレガシーの
フォーマット契約が乖離してしまう。デーモンのベアラートークン認証、
デフォルトの GET 読み取りレートティア、リクエストごとの
ワークスペース信頼チェックは引き続き適用される。

ランタイム削除の競合は、リクエスト解決時に選択されたランタイムを
使用する。削除はトランスクリプトストレージを削除しないため、
エクスポートにはランタイムリースは不要であり、ACP 子プロセスを
生存させ続けることもない。

## SDK and Observability

`WorkspaceDaemonClient.exportSession` は既存のエクスポート結果と
フォーマットの型を再利用し、親クライアントが ACP トランスポートを
持つ場合も含め、常にネイティブ REST を使用する。共有のリクエスト
ヘルパーは、トークン、クライアント識別、タイムアウト、エラーパース、
コンテンツタイプ、添付ファイル名の挙動を維持する。

デーモンのテレメトリは新しいパスを
`GET /workspaces/:workspace/session/:id/export` として正規化し、
セッション id をデコードし、選択されたワークスペースハッシュには
ミドルウェアのワークスペース解決を使用する。

## Alternatives Rejected

- 単数形のエクスポートをライブの所有者でルーティングすると、
  非アクティブな永続化セッションでは失敗し、再起動後は
  所有権があいまいになる。
- レガシールートに `cwd` クエリを追加すると、プライマリ専用の
  互換契約が変わってしまい、既存の複数形ワークスペースルートとの
  一貫性も低い。
- ミス時にプライマリにフォールバックすると、id が衝突した場合に
  別のワークスペースのセッションをエクスポートしてしまう。
- 信頼なしの完全エクスポートを許可すると、永続化トランスクリプト
  ページャー用に設計された制限付き読み取りポリシーを
  バイパスしてしまう。

## Verification

テストは、ケイパビリティの広告、id/cwd セレクター、同じ id の分離、
すべてのフォーマット、レスポンスヘッダー、信頼とアーカイブの境界、
欠落/未知のターゲット、ブリッジ活動の不在、テレメトリの帰属、
SDK のトランスポートとエンコーディング、アーカイブ/削除の調整を
カバーする。エンドツーエンドの検証は、決定論的な永続化トランスクリプトを
持つ分離されたランタイムおよびワークスペースディレクトリを使用する。
