# 信頼されたデーモン呼び出しコンテキスト

## 目標

受け入れられた 1 つのルートプロンプトについて、デーモンが証明した識別情報を、Qwen が stdio 経由で起動する MCP サーバーに運ぶ。このコンテキストは相関のためのメタデータであり、認可のクレデンシャルではない。

完全な本番パスは次の通り:

```text
daemon prompt admission
  -> private ACP child
  -> root Session turn
  -> Qwen-launched stdio MCP tools/call request metadata
```

## ワイヤー契約

Qwen は `tools/call.params._meta["qwen-code/invocation"]` に次の値を追加する:

```ts
interface InvocationContextV1 {
  version: 1;
  sessionId: string;
  promptId: string;
  originatorClientId?: string;
}
```

- `sessionId` は、リクエストルートが選択したライブのデーモンセッションである。
- `promptId` は、デーモンがプロンプトを受け入れた時点で、セッションごとのキューで待機する前に確定する。ノンブロッキングの呼び出し元は、既存の終端イベントマッチングで使用される相関 ID を指定してもよい。それ以外の場合、デーモンが UUID を生成する。いずれの場合も、この値はプロンプト本文からコピーされたメタデータではなく、デーモンが実際に受け入れたプロンプトを識別する。
- `originatorClientId` は、存在する場合、そのセッションに登録されていることをデーモンが検証した後のリクエストヘッダー値である。
- 未知のフィールド、未知のバージョン、空白の識別子は無効である。

デーモンは、予約されたメタデータキーに対する呼び出し元提供の値を削除し、自身の状態からコンテキストを再構築する。この値は、プロセスごとのケーパビリティで起動・認証した ACP 子プロセスにのみ渡される。スタンドアロンの ACP 呼び出し元は、予約されたコンテキストを注入できない。

## ライフタイムと開示

ACP の Session は、コンテキストのセッションが実際のセッションと一致することを検証し、`AsyncLocalStorage` でルートプロンプトに結び付ける。プールされた MCP トランスポートを共有する場合を含め、並行するプロンプトは隔離されたままとなる。遅延された確認コールバックは、捕捉したコンテキストを明示的に復元する。

自動 cron ターン、バックグラウンド通知、再開されたバックグラウンドエージェント、サブエージェントの推論ループは、呼び出しコンテキストなしで実行される。コンテキストは、ルートターンが確定した後は永続化されない。

MCP の `command` 設定から Qwen が `StdioClientTransport` として作成したトランスポートインスタンスのみが対象としてマークされる。HTTP、SSE、WebSocket、reverse、SDK 提供、クライアントホストのトランスポートは、このメタデータを受け取らない。対象のマーカーは、ツールの検出、クローン、プーリング、再接続、リトライを追従し、公開の MCP 設定オプションにはならない。

## 非目標

- Browser Use、opencode、ローカル/リモートバックエンド、ページ、スキル固有の動作はなし。
- ingress の列挙や一般的な provenance グラフはなし。
- 新しい TypeScript SDK API や qwen-serve の MCP ライフサイクル動作はなし。
- `originatorClientId` に基づく認可の決定はなし。
