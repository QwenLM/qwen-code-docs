# 実験的なセッションのプラン & レビュー

## Goal

通常セッションのワークフロー可視化をオプトインにし、実行前に正確な Todo の依存
グラフをユーザーがレビューできるようにする。プランモード、Todo のスナップ
ショット、既存の権限ライフサイクルを再利用する。

## Rollout

`experimental.sessionWorkflow` はデフォルトで無効である。無効な場合、Web Shell
は既存の Todo リストとプランモードの挙動を維持するが、ワークフローの DAG を
描画せず、プランモードの名前も変更しない。この設定は表示のみを変更する。
ツールの登録、Todo のセマンティクスの変更、別の承認モードの作成は行わない。

有効にすると、既存の `plan` モードは **Plan & Review** として表示される。プラン
モードは引き続き実行のゲートである。読み取り専用の調査は許可され、変更を伴う
ツールはブロックされたままであり、`exit_plan_mode` を拒否するとプランモードに
留まり、承認するとプランモードを終了する。

## Delivery

### Phase 1: オプトインの表示

- 既存のデーモンワークスペース設定ルートを通じて、デフォルトでオフの設定を公開
  する。
- Web Shell のアクティブなワークスペースから有効な設定を読み取り、メイン
  チャット、分割ペイン、サイドタスクペインに一貫して適用する。
- ワークフロー DAG の入力をゲートする間、Todo リストの描画は変更しない。
- 設定が有効な間のみ、既存のプランのエントリ名を変更する。

### Phase 2: リビジョンに紐付いた承認

- Plan & Review では、承認前にノードが pending のままである構造化された Todo
  実行スナップショットを要求する。
- `exit_plan_mode` の承認リクエストに、Todo プランのアイデンティティとソースの
  ツール呼び出しのアイデンティティを付加する。
- 最新のアクティブな Todo リストではなく、そのアイデンティティから承認の DAG
  を解決する。
- 既存のプラン ID の系譜を再利用し、後続のスナップショットとエージェントの実行
  が、別のストアなしで同じワークフローの更新を続けられるようにする。
- 一致するスナップショットが利用できない場合は、既存のテキストのみの承認に
  フォールバックする。

## Boundaries

ワークフローは観測のままである。依存関係のスケジューリング、エージェントのリ
トライ、完了の伝播、ワークフローストアの追加は行わない。Plan & Review の外側の
セッションでは、`blockedBy` と `todo_id` は引き続き任意である。
