# レガシーセッションワークスペースのテレメトリ

## Context

デーモンのテレメトリミドルウェアは、Express のルートハンドラーが
実行される前に HTTP リクエストを分類する。レガシーの単数形セッション
ルートは任意の登録済みワークスペースに解決できるが、ミドルウェアは
URL だけでは選択されたランタイムを知ることができない。ミドルウェアと
ハンドラーの両方でライブの所有者を解決すると作業が重複し、
2 回のルックアップの間にレジストリが変更された場合は
食い違う可能性がある。

この設計は、すべての明示的なレガシー `/session`、`/sessions`、
`/permission` ルートに安定したリクエスト span を与えつつ、
動的ルートをハンドラーが選択したランタイムに帰属させる。

## Route inventory

ルートカタログは 48 の明示的なレガシールートをすべて含む。
各エントリは、HTTP メソッド、Express パステンプレート、正規の
ルートラベル、および 2 つの帰属モードのいずれかを宣言する：

- `handler_resolved`（41 ルート）：`POST /session`、load/resume、レガシーの
  トランスクリプトルート、およびライブの所有者を解決するすべての単数形
  セッションルート。ハンドラーが選択されたランタイムのワークスペースを
  テレメトリに公開する。
- `pre_resolved`（7 ルート）：レガシーエクスポート、A2UI アクション、
  レガシーの organization、3 つのグローバルな一括変更操作、および
  グローバルなパーミッション投票。これらのルートは引き続き
  プライマリワークスペースにバインドされる。

カタログマッチャーは関連する Express 5 のデフォルトに従う：
静的セグメントは大文字小文字を区別せず、末尾のスラッシュ 1 つは
許容され、パラメータセグメントは生のパス境界が捕捉された後にのみ
デコードされる。不正なセッション id は生の値のまま保持される。
パーミッションリクエスト id は、既存の長さと文字セットの検証の前に
デコードされる。出力される `http.route` は常に正規のカタログ
テンプレートを使用する。

## Deferred attribution

ハンドラー解決のリクエストは `qwen-code.workspace.hash` なしで開始される。
ミドルウェアは Express レスポンスにプライベートなコンテキストを保存する。
ルートコードは、一意のランタイムが選択された後に
`setDaemonTelemetryWorkspace(res, runtime.workspaceCwd)` を呼び出す。
このセッターはベストエフォートで first-selection-wins である：
同じ値の繰り返しは冪等であり、後から異なる値が来ても無視される。

公開の継ぎ目は 4 つである：

1. ライブ所有者ルートが共有する `requireSessionRuntime`。
2. ワークスペース選択後のセッション作成。
3. ターゲットランタイム選択後のセッション load/resume。
4. 一意のライブまたは永続化された所有者が見つかった後の
   レガシートランスクリプト解決。

公開は、後続の信頼チェック、未サポートのセカンダリ、競合、
リクエスト検証チェックより先に行われる。したがって、それらの失敗は
一意に選択されたランタイムを保持する。not-found、ambiguous、
workspace-mismatch のケースを含む、一意の選択前に失敗したリクエストは
ワークスペースハッシュを省略する。帰属には `runtime.workspaceCwd` を
使用し、セッションが要求した cwd や一時的な cwd は使用しない。

レスポンスの `finish` または `close` 時に、ミドルウェアは公開された
ワークスペースをハッシュし、span 属性を設定し、レスポンスを記録し、
span を終了する。解決、ハッシュ化、span の更新はベストエフォートであり、
リクエスト処理やメトリクス確定に影響を与えてはならない。
コンテキストは 1 回の確定後にクリアされる。

事前解決のリクエストは、span 開始時にミドルウェアが選択した
ワークスペースのハッシュ化を継続する。ミドルウェアのライブ所有者
コールバックを削除することで、ライブ所有者のリクエストごとの解決が
最大 1 回になることを保証する。

## Streaming and metrics

48 のカタログルートすべてがリクエスト span を作成する。
`GET /session/:id/events` の成功レスポンスは、SSE 接続が閉じると
span を終了するが、その長さが接続のライフタイムであるため、
通常の HTTP リクエスト数/時間および Web Shell ステータスメトリクスの
リングからは除外される。SSE ハンドシェイクの失敗は通常の短い
HTTP リクエストとして記録される。

`POST /session/:id/generate` は制限付きのリクエストスコープ SSE 操作である。
その接続は生成完了時に終了するため、時間は引き続き意味のある
リクエストレイテンシであり、通常の HTTP メトリクスに入り続ける。

heartbeat リクエストは OpenTelemetry HTTP メトリクスに残るが、
ステータスメトリクスのリングからは除外されたままである。
`GET /daemon/status` も引き続きそのリングからのみ除外される。
共有の確定ガードは、`finish` と `close` の両方が発生した場合の
重複記録を防ぐ。

HTTP メトリクスと Web Shell メトリクスリングは引き続きデーモン全体である。
ワークスペースのメトリクス次元を追加するには、別のカーディナリティと
ダッシュボード互換性のレビューが必要である。

## Compatibility and boundaries

この変更は、ルート、リクエストまたはレスポンスのスキーマ、SDK、
ケイパビリティ、永続化、認証、信頼の順序付け、アーカイブリース、
ブリッジエラーマッピング、セッション実行を変更しない。
公開テレメトリ属性の追加もしない。

テレメトリミドルウェアはベアラートークン認証、レート制限、JSON パースの
後にインストールされるため、それらの先行ゲートで拒否されたリクエストは
このリクエスト span のカバレッジの外に残る。暗黙の HEAD/OPTIONS、
アクセスログの挙動、レート制限のパス正規化、ワークスペースの
セッショングループレート、ワークスペース修飾付き organization、
ACP/WebSocket テレメトリ、セカンダリでの branch/fork/cd 実行の有効化は
スコープ外である。

## Verification

- ドリフトガードは Express に登録された明示的なレガシールートを
  カタログと比較し、48/41/7 のインベントリをアサートする。
- マッチャーのテストは、大文字小文字、末尾スラッシュ、エンコードされた
  スラッシュ、Unicode、不正なエンコーディング、パーミッション id の検証、
  メソッド/パスの不一致、正規ラベルをカバーする。
- ミドルウェアのテストは、遅延帰属、first-selection-wins、ハッシュ
  キャッシュ、テレメトリ失敗、一回限りの確定、SSE メトリクス、
  heartbeat、ステータスの除外をカバーする。
- ルートのテストは、プライマリ、セカンダリ、信頼なし、欠落、あいまい、
  競合のケースにおけるライブ所有者、作成、リストア、トランスクリプトの
  公開をカバーする。
- デュアルワークスペースの outfile テストは、生のワークスペースパスを
  公開せずに、セカンダリ、プライマリバインド、省略されたハッシュを
  検証する。
