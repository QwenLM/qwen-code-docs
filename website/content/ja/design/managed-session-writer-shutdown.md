# マネージドセッションライターのシャットダウン

## Problem

マネージドの `qwen serve` リプレースは、前の ACP 子がまだセッションライターのロックを所有している間に、新しいホスト名で起動し得る。外部ホストの v1 ロックは古いことを証明できないため、リプレースは正しく `session_writer_conflict` を返す。ホスト名や経過時間による回収は、2 つのライブ Pod が同じトランスクリプトを書き込むことを許してしまう。

## Scope

この P0 は、協調的なマネージドシャットダウンが親の SIGKILL 期限の前にライターロックを解放するようにする。シールされたハンドオフ記録、テイクオーバーのクレーム、TTL やホスト名の奪取、プラットフォームフェンシング、メンテナンスリース、SIGKILL / イベントループストール / ストレージ障害後の自動復旧は追加しない。過去の外部ホストロックには、依然として外部のライターフェンスと手動クリーンアップが必要である。

既存のプライベートな親 capability を検証した ACP 子のみがマネージドパスを使用する。スタンドアローン ACP は既存のシャットダウンとローカルの古い所有者の復旧挙動を維持する。マネージドの取得は、コンテナの PID 名前空間によりその証明が安全でなくなるため、PID の可視性から既存のロックを回収しない。

## Writer terminal

ライターのクローズはシングルフライトであり、公開の記録受け入れを同期的にクローズする。通常のクローズは、クローズ前にメタデータを確定し、受け入れ済みの作業を待つ。マネージドのファストクローズはアクティブなモデルターンを待たず、追加の確定レコードを追加しない。カットオフ前に受け入れられたレコーダー作業のみを drain する。

フラッシュ失敗はライターをシールし、exact-owner の解放試行の後にも報告され、既存のクローズ契約を維持する。所有権または解放の失敗は、解放がすでにコミット済みでない限り、プライマリロックを保持する。唯一の解放コミットは、プライマリロック `P` から所有者一意の退役パス `R` への同一ディレクトリ内リネームである。古い所有者は自身の正確な `R` のみをクリーンアップでき、プライマリのリネームを再試行したり、後継の `P` に触れたりしない。マネージドシャットダウンは、ライターの終端が失敗した場合、候補ロックパス付きでオペレーターに見える警告を発する。手動クリーンアップは、前のライターが稼働していないことを確認した後のみ安全である。

## Managed ACP shutdown

最初のシャットダウンアクションは、セッション作成とターン受け入れをクローズし、アクティブ、初期化中、遅延クリーンアップのライター対応 Config インスタンスをスナップショットする。すべてのライター終端は最初の await より前に開始し、並行して実行される。SessionEnd フックはライターフェーズの後、Config リソースがまだ利用可能な間に実行される。その後、残りの時間でリソースクリーンアップが実行される。

子はすべてのライター終端がクリーンな場合のみゼロで exit する。ロックが解放済みでも、後続のフックやリソースクリーンアップによりシャットダウン全体がアンクリーンになり得る。

### Config resource quiescence

ライターのシャットダウンと Config リソースのシャットダウンは別々の終端である。ライターのクローズは引き続き最初のマネージドシャットダウン await より前に開始する。リソースクリーンアップは、実行中の `Config.initialize()` に合流してからリソースを検査・停止するため、クリーンアップが返った後に初期化がウォッチャー、ツールレジストリ、MCP マネージャーを作成することはできない。

Config の初期化はシャットダウン開始時にシールされ、リソースクリーンアップはマネージドシャットダウンと並行するリクエスト失敗クリーンアップの間でシングルフライトである。writer と telemetry のオプションは呼び出しごとのままであるため、`shutdown(options)` 呼び出し全体はシングルフライトではない。

不完全に初期化された Config は、保留中のリースが公開され次第、初期化への合流前に exact-owner の解放を開始する。トランスクリプトのスナップショット読み取りは、チャンク間でその解放を観測し、遅延したレコーダーを公開せずに停止する。正常に初期化された Config は、通常の確定、フラッシュ、クローズの順序を保持する。初期化への合流にはローカルタイムアウトがない: 待機をタイムアウトさせると、基盤の初期化が実行中のままになり、遅延リソース作成が再導入される。デーモンプロセスの期限が引き続きハードな境界であり、保留中ライターの解放はすでに完了しているか、明示的に失敗している。

## Parent process lifecycle

各デーモンハンドルは、プライマリ、セカンダリ、動的ワークスペースのチャネルファクトリーで共有される 1 つのプロセスレジストリを所有する。spawn の予約とシャットダウンシールは同期的に競合する。成功した spawn は同じターン内でレジストリにアタッチされる。

PID なしの、Node の `spawn` イベントより前のエラーは `no_process` である。spawn 確定後は、生の `exit` のみが回収（reaping）を証明する。spawn 後のチャネル構築失敗は、未公開の子を直ちに SIGKILL し、構築エラーを返す前にチャネル終端に合流する。チャネルファクトリーが返った後、ブリッジは完全な ChannelInfo の構築や公開の前にチャネルを所有する。

デーモンシャットダウンは 1 つの単調なプロセスレジストリタイムラインを使用する: `t0` で SIGTERM、子が非ゼロまたはシグナルで exit した場合は安定したアンクリーンシャットダウン、`t0 + 5s` で SIGKILL、`t0 + 10s` で安定した `not_reaped` 失敗。ゼロ exit はマネージド子の協調的なライター終端承認であり、生の exit 単独は回収のみを証明する。レジストリの期限は決して再開せず、遅延した生の exit が失敗した終端を成功に変えることはない。デーモンは、後で回収可能になった独立マネージドチャネルワーカー向けの既存のリトライパスを保持する。そのようなリトライは、新しい ACP シャットダウンタイムラインを開始するのではなく、同じ確定済みの ACP プロセスレジストリ終端に合流する。

親の期限は、SessionEnd フック、Config 初期化、MCP クリーンアップの予算に合わせて意図的に拡張されない。プラットフォームの終了ウィンドウはそれより短く、デーモンの制御外であり得るためである。それらのライター後のフェーズはライター解放後の残り時間を使用し、中断され得る。その場合、解放済みライターロックを復元せずにアンクリーンなデーモン exit を生成する。未確認のチャネルワーカー exit のみが、デーモンを 2 回目のグレースフルシャットダウン試行のために生存させる。その他の ACP またはブリッジの失敗は、最初のシグナルで非ゼロ exit する。

## Compatibility and rollout

プライベート capability と公開の ACP/REST ペイロードは変更しない。カスタムの非同期 ChannelFactory は AcpChannel を解決した後のみカバーされる。デフォルトのマネージドファクトリーは spawn 予約以降カバーされる。

混在バージョンでのライター運用は引き続きサポートされない。デプロイとロールバックは、リプレースがセッションを受け入れる前に、古い ACP ライターを drain しなければならない。

## Verification

検証は次を区別しなければならない:

1. ロックが解放され、デーモンシャットダウン全体がクリーン。
2. ロックは解放されたが、後続のクリーンアップによりシャットダウンがアンクリーン。
3. ロックが保持され、後継が 409 を受け取り、手動復旧が引き続き必要。

必要な決定的カバレッジには、フラッシュ失敗、効果後のリネームエラー、後継の取得、通常からファストへのクローズ、すべてのカットオフ境界での取得、非同期の `ENOENT` spawn 失敗、spawn 後エラー、部分的なチャネル構築、バッファされた initialize レスポンスを持つ事前解決チャネルの exit、D1/D2 と生の exit の競合、遅延 exit、2 回のシグナル、マルチランタイムの並行シャットダウン、Config 初期化中のシャットダウン、並行 Config クリーンアップ、シャットダウン受け入れ後の初期化、スタンドアローン ACP、混在バージョンのロールアウトガードレールを含む。
