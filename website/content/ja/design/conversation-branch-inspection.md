# 会話ブランチの検査

## 動機

セッションの JSONL ファイルは、すでに `uuid` と `parentUuid` によってツリーを形成しているが、resume は現在、物理的に選択された 1 つの末尾のみを再構築する。したがって、複数の writer が同じセッションに追記した場合や、rewind が 2 つ目のブランチを作成した場合、再起動によって有効な兄弟履歴が隠されてしまう可能性がある。

この変更は、読み取り専用のトポロジーインスペクターを追加する。これはすべての意味論的な leaf を特定し、明示的な rewind レコードとの関係を記述し、小さな決定論的なサマリーを生成する。どのブランチがアクティブかを決定することはない。

## 境界

インスペクターはメモリ内の `ChatRecord` 値を受け取り、ファイルシステム、セッションサービス、モデル、writer への依存関係を持たない。既存の resume、fork、トランスクリプトのページネーション、デーモン、ACP、CLI の挙動は変更されない。

選択されたブランチの再構築は、引き続き明示的な `leafUuid` を指定した `buildOrderedUuidChain` を使用する。後続の書き込み側の変更では、排他的で安定したトランスクリプトのスナップショットを取得し、ユーザーまたは永続的なポリシーに報告された leaf のいずれかを選択させ、その選択を永続化し、resume された writer にシードしなければならない。これらの所有権に関する操作は、いずれもインスペクターには属さない。

Claude Code には、解析用の全 leaf トランスクリプトリーダーがあり、その一方で通常の resume パスは依然として最新の非 sidechain の leaf を選択している。Qwen はその選択ルールを安全に使用できない: 明示的な rewind は構造上の関係を証明するが、マルチ writer のトランスクリプトにおいては、すべての兄弟が意図的に放棄されたことを証明するものではないためである。

## 意味論的な leaf

UUID に対する最初の物理レコードがその親を定義し、これは既存のチェーンウォーカーと一致する。矛盾する重複した親は、推測するのではなく診断される。

生の終端レコードは、意図的に小さく保たれた中立末尾の許可リストを使って正規化される: `custom_title`、`session_artifact_event`、`session_artifact_snapshot` である。これらのレコードは、会話の末尾の横や後に、個別の復旧可能な会話を生むことなく追記されうる。これらの終端の連なりは、最も近い既知の非中立な祖先に収束される。そのような祖先が存在しない場合、メタデータのみの連なりは再構築可能な会話ブランチではないため、省略される。収束された候補は重複排除され、その後、他の候補の厳密な祖先である候補はすべて除外される。結果は、意味論的な leaf のアンチチェーンとなる。

他のすべてのシステムレコードは引き続き重要である。特に、rewind、圧縮、アトリビューション、ファイル履歴のレコードはリカバリー状態を保持しうるため、ユーザーに見えるテキストがないという理由だけで破棄してはならない。

親の欠落は、到達可能な末尾の島でチェーンを停止させる。親のサイクルは報告され、有界に保たれる。読み取り側は、欠落した履歴を再接続したり、ブランチをアクティブまたは放棄済みとラベル付けしたりすることは決してない。

## サマリーと rewind の関係

サマリーはローカルかつ決定論的である。これらには、最も近い分岐点、メッセージ数、タイムスタンプ、分岐点以降の最初の実際のユーザーテキスト、最新の実際のユーザーテキストと non-thought のアシスタントテキストが含まれる。通知、cron、ターン途中のユーザーレコードは、ユーザープロンプトとしては扱われない。テキストは空白が正規化され、切り詰められる。ツール引数とテキスト以外の部分は無視される。`updatedAt` は、意味論的な leaf に正規化された最後の物理終端のタイムスタンプを使用するため、中立なメタデータのアクティビティは失われない。

パスに rewind レコードが含まれる場合、そのブランチは rewind の子孫である。rewind レコードへのパスから分岐している場合、そのブランチは rewind の兄弟である。これらは構造上のラベルにすぎず、兄弟が時代遅れであることを示唆するものでは決してない。
