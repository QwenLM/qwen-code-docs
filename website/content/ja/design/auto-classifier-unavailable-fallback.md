# クラシファイア利用不可時のフォールバック

## 問題

Auto Mode は現在、クラシファイアのすべてのインフラ障害を実行拒否に変換している。そのため、ネットワークエラー、タイムアウト、無効な構造化レスポンス、高速モデルの利用不可、コンテキストオーバーフローが発生すると、標準の確認フローがユーザーにどうするかを尋ねる前に、保留中のツール呼び出しが失敗してしまう。

この挙動は 2 つの異なる結果を混同している:

- クラシファイアのポリシーブロックは安全性の判定であり、アクションを拒否し続けるべきである。
- クラシファイアの利用不可は判定が生成されなかったことを意味し、ユーザーに手動で決定させるべきである。

既存の連続利用不可フォールバックは、クラシファイア呼び出しが 2 回失敗した後に初めて確認を開くだけである。最初の失敗は依然としてツール呼び出しを終了させ、プロンプトはインフラの問題を説明せず、直接的な復旧パスも提示しない。

## ゴール

- クラシファイアの利用不可という最初の結果を、標準の手動確認フローへルーティングする。
- Auto Mode がアクションを分類できなかったことを確認画面で説明する。
- 現在のアクションを一度だけ承認し、セッションを Default Mode に切り替える明示的なオプションを提供する。
- CLI と ACP の権限挙動の整合性を保つ。
- ポリシーブロック、明示的な拒否ルール、決定論的な破壊的コマンドのガード、ユーザーキャンセルの挙動を維持する。

## 非ゴール

- Default Mode をユーザー設定やワークスペース設定に永続化すること。
- ユーザーの選択なしにモードを自動的に切り替えること。
- ポリシークラシファイアの許可／ブロックのルールを変更すること。
- 承認の手段を持たない非インタラクティブまたはバックグラウンドのセッションが、プロンプトを提示できるようにすること。

## 提案する挙動

クラシファイアが `unavailable: true` を返した場合、権限レイヤーは引き続き利用不可イベントを記録するが、ブロックされた結果ではなく手動フォールバックの結果を返す。保留中の呼び出しは、既存の PermissionRequest と確認のパスを通じて続行する。

生成される確認は Auto Mode のフォールバックメタデータを持ち、永続的な「常に許可」の選択肢を抑制する。確認はクラシファイアが利用不可であることを示し、障害が続く場合は Default Mode を推奨する。選択肢には以下が含まれる:

- 一度だけ許可。
- Default Mode に切り替えて一度許可。
- 拒否。

切り替えの選択肢は、意図的に明示的な一度きりの承認と組み合わせられている。モードのみのラベルでは、すでに保留中のアクションの処遇が曖昧になってしまう。

| クラシファイアの結果 | 現在の挙動          | 新しい挙動          |
| ----------------- | ------------------- | ------------------- |
| 許可               | 自動的に実行          | 変更なし            |
| ポリシーブロック    | ポリシー理由で拒否    | 変更なし            |
| 利用不可           | ツール呼び出しを拒否   | 手動承認を尋ねる     |

## コアの権限フロー

`applyAutoModeDecision` は利用不可カウンターを記録し、クラシファイアの利用不可専用のフォールバック理由を返す。結果はブロックされなくなるため、インフラ障害に対して PermissionDenied フックは発火しない。代わりに、プロンプトの前に通常の PermissionRequest フックが実行される。

利用不可カウンターは引き続き有用である。フォールバックの承認は連続カウンターをリセットし、拒否はそれを保持する。繰り返し障害が既存のしきい値に達した場合、後続のクラシファイア対象の呼び出しは、壊れていることがわかっているクラシファイアをバイパスし、直接手動確認に移行できる。

確認の詳細には、編集、実行、情報、MCP、その他の確認形態全体で共有される、任意の Auto Mode フォールバックメタデータが追加される。新しい承認結果として「一度続行して Default に切り替える」が表現される。CLI スケジューラーは、ツール固有の確認コールバックを呼び出す前、またはツールの決定を記録する前に、ランタイムセッションのモードを切り替え、その結果を通常の `ProceedOnce` に正規化する。

`Config.setApprovalMode` はすでに必要なセッション遷移を提供している: Auto Mode 開始時に一時的に削除されたルールを復元し、拒否カウンターをリセットし、承認モードのリビジョンをインクリメントする。設定ファイルは変更されない。

## CLI の表示

TUI の確認コンポーネントは、アクションの詳細の前にフォールバックの通知を描画し、拒否の前に切り替えオプションを追加する。フルとコンパクトの両方の確認レイアウトがこのオプションを表示する。高さの計算は、追加される警告とオプションのためにスペースを確保し、小さいターミナルでも引き続き実行可能な選択肢が表示されなければならない。

## ACP の表示

ACP の権限リクエストは、フォールバックの通知をテキストコンテンツとして含み、同じ「切り替えて一度許可」のオプションを公開する。選択されると、セッションはツールの承認を `ProceedOnce` に正規化し、ランタイムモードを Default に切り替え、既存の現在のモードの更新通知を発行する。

許可または拒否のみを選択する ACP クライアントは、引き続き既存のプロトコル挙動を使用する。

## 失敗の境界

- クラシファイアリクエストのユーザーキャンセルは引き続き中断であり、承認プロンプトにはならない。
- 明示的な権限拒否と決定論的な破壊的コマンドのブロックは引き続きエラーである。
- 権限トランスポートのない非インタラクティブな呼び出しや、プロンプトを出せないバックグラウンドエージェントは、引き続き既存の手動確認フォールバック処理を通じて拒否する。
- クラシファイアの Stage 2 におけるポリシーレビューの失敗は利用不可と見なされるため、ユーザーに尋ねる。完了した Stage 2 のポリシーブロックは引き続き拒否される。

## 影響を受けるファイル

- `packages/core/src/permissions/autoMode.ts` とテスト: 利用不可からフォールバックへのマッピング、メタデータ、フックのゲーティング。
- `packages/core/src/tools/tools.ts`: フォールバック確認のメタデータと切り替えの承認結果。
- `packages/core/src/core/coreToolScheduler.ts` とテスト: 確認の装飾、フォールバック解決の追跡、モードの切り替え、承認の正規化。
- `packages/core/src/telemetry/tool-call-decision.ts` とテスト: 新しい承認形式の結果の分類。
- `packages/cli/src/ui/components/messages/ToolConfirmationMessage.tsx` とテスト: 通知とオプションの描画。
- `packages/cli/src/acp-integration/session/permissionUtils.ts` とテスト: ACP のコンテンツとオプションのマッピング。
- `packages/cli/src/acp-integration/session/Session.ts` とテスト: ACP フォールバック、モード遷移、通知。
- `docs/users/features/auto-mode.md`: 即時の手動フォールバックと Default Mode の復旧オプションのドキュメント化。
