# TUI 画像表示ツール

## 目標

モデルから呼び出し可能な `display_image` ツールを追加し、インタラクティブなターミナル UI で既存の PNG をプレビューする。このツールは表示専用であり、モデルに画像のピクセルを提供せず、ヘッドレス、SDK、スクリーンリーダー、サブエージェントのいずれのレジストリでも利用できない。

## 設計

コアのツールは、絶対パスのワークスペースパス、通常ファイルであること、PNG のシグネチャ、8 MiB のサイズ上限を検証する。成功時は小さな構造化された表示値を返す:

```ts
{
  type: 'terminal_image',
  filePath: '/absolute/workspace/path/image.png',
  mimeType: 'image/png',
}
```

成功を返す前に、ツールは CLI が注入したプロバイダーに、現在のターミナルで利用可能なレンダラーがあるかを問い合わせる。ネイティブプロトコルは即座に通過する。フォールバックは、選択されたファイルをレンダリングすることなく、`chafa` が `PATH` 上で利用可能かをチェックする。利用可能なレンダラーがない場合、ツールは実行エラーを返し、TUI とモデルの両方が画像が表示されなかったことを把握できるようにする。`llmContent` は、画像を検査する必要がある場合は `read_file` を使用するようモデルに伝える。画像のバイトやターミナルのエスケープシーケンスは、モデルの履歴や永続化される表示値には決して入らない。

`ToolMessage` はこの構造化値を認識し、TUI コンポーネントに委譲する。コンポーネントは、読み取り前に現在のワークスペースに対してパスを再検証する。レンダリングはコンポーネントの初回レンダリング時に準備される。完了したツールの行は即座に Ink の追記専用の `Static` 領域に入るため、非同期の状態更新はそこで破棄されてしまうからである。Kitty 互換のターミナルは、Mermaid ダイアグラムですでに使用されている既存の仮想画像と Unicode プレースホルダーのアプローチを使用する。その他のターミナルはシンボル出力で `chafa` を試す。`chafa` は Mermaid レンダラーが使用するものと同じ許可リストの環境変数のみを受け取るため、API クレデンシャルは転送されない。どちらのパスも利用できない場合、TUI は画像名を示す制限付きのテキストフォールバックを表示する。

プレビューは 72 列 × 24 行が上限で、その後利用可能なターミナルのスペースに合わせてさらに縮小される。8×16 ピクセルのターミナルセル見積もりにより、小さな画像が意図的に拡大されないよう、保守的な自然サイズが得られる。ネイティブと `chafa` のレンダリングは、同じアスペクト比を維持する寸法を使用する。

このツールは、以下がすべて真の場合にのみ登録される:

- メインの設定がインタラクティブである
- SDK モードが無効である
- スクリーンリーダーモードが無効である
- レジストリがサブエージェント用に作成されているのではない

bare モードは既存の最小限のツールセットを維持する。

## 互換性

最初のバージョンは PNG のみをサポートする。Kitty と Ghostty はネイティブの画像配置を使用する。Warp は意図的に除外される。その Kitty サポートにはこのレンダラーが使用する Unicode プレースホルダー拡張が含まれておらず、直接配置はスクロールバックやターミナルのリフロー時に Ink のコンテンツからずれてしまうためである。iTerm2 の直接配置も除外される。そのインライン画像プロトコルはカーソル位置指定であり、既存の非同期な Ink パスはすでにそれを安全でないと扱っているためである。Warp、iTerm2、tmux、SSH、ネイティブパスのないターミナルも、`chafa` がインストールされていればそれを通じてレンダリングできる。

## セキュリティと永続化

ツールとレンダラーはどちらも `WorkspaceContext.isPathWithinWorkspace` を使用する。これはシンボリックリンクを解決し、登録されたワークスペースのルート外へのトラバースを防ぐ。レンダラーは復元された `resultDisplay` のデータを信頼されないものとして扱い、このチェックを繰り返す。永続化されたセッションにはパスと MIME タイプのみが含まれる。ファイルが存在しなくなった場合、復元はテキストの案内に縮退する。

生のターミナル出力は、信頼されたレンダラーによってのみ生成される。モデルが制御する文字列やファイルの内容は、ターミナルに直接書き込まれることは決してない。
