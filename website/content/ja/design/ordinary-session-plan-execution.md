# 通常セッションのプラン実行

## Goal

通常セッションの Todo プランを依存グラフとして表示し、各ノードをそれを実装する Agent 実行に接続する。既存の ACP プランストリーム、セッションタスクのスナップショット、サブエージェント詳細セッションを再利用する。

この機能は観察用である。作業のスケジューリング、リトライ、ブロック解除、完了は行わない。

## Data contract

`todo_write` はオプションの `blockedBy` Todo ID を受け入れる。ランタイムは、ID が一意であること、参照先が存在すること、依存関係が重複したり自己参照したりしないこと、グラフが非巡回であることを検証する。

Todo サイドカーは、ランタイムが生成した `planId` を現在のスナップショットと共に保存する。アクティブなプランが修正されている間、ID は安定したままになる。プランをクリアするか、前のプランが完了した後に空でない作業を開始すると、新しいプランが始まる。

Todo 結果の表示は `planId` を保持するため、ライブ ACP プロジェクションと通常のトランスクリプトリプレイパスが同じプランメタデータを保持する:

- プラン更新 `_meta.qwenTodoPlan.id`: 安定したプラン識別情報
- プラン更新 `_meta.qwenTranscript.planToolCallId`: 元の Todo ツール呼び出し
- プランエントリ `_meta.qwenTodo.id`: 元の Todo ID
- プランエントリ `_meta.qwenTodo.blockedBy`: 存在する場合の依存 ID

`_meta` を無視するクライアントは、引き続き標準の ACP プランエントリを受け取る。

Agent ツールはオプションの `todo_id` を受け入れる。これはランタイムのゲートではなくガイダンスである: アクティブな Todo グラフが存在する場合、トップレベルの Agent 呼び出しはそれを提供すべきである。既存の `AgentTask.toolUseId` が Agent ツール呼び出しをライブタスクステータスに結合するため、タスク API に追加フィールドは不要である。

## UI flow

アクティブな Todo ピルは引き続き既存のコンパクトリストを描画する。クリックすると既存の Tasks ダイアログが開く。プランメタデータが存在する場合、そのダイアログは既存のタスクツリーの上にネイティブ CSS のプラン実行セクションを追加する:

1. `blockedBy` からノードをトポロジカルに階層化する。
2. トップレベルの Agent ツール呼び出しを `args.todo_id` でグループ化する。
3. `task.toolUseId === tool.callId` でライブタスク行を結合する。
4. ネストした Agent 行は `parentAgentId` 経由でルート配下に保持する。
5. ワークフローノードを選択すると、グラフの下にその完全な Todo コンテンツ、ステータス、依存関係、リンクされた Agent 実行を検査できる。
6. リンクされた Agent 実行から既存のライブサブエージェント詳細パネルを開く。ストリームされる進捗、ツール呼び出し、最終出力のソースであり続ける。
7. `todo_id` の欠落や不明なバインドは Unassigned グループに置く。

グラフライブラリは追加しない。依存メタデータのないプランはリスト形式の表示を維持する。

## Plan Mode approval

Plan Mode は、作業開始前にワークフローをレビューしたいユーザー向けのオプトイン実行ゲートである。`exit_plan_mode` が権限を要求すると、Web Shell は既存の承認パネルに、権威ある ACP プラン本文に続けてアクティブな Todo ワークフローを表示する。Todo ビューはそのスナップショットが送信されたプランテキストと異なる可能性があるため、補足的なものである。依存関係を認識するワークフローは、Tasks ダイアログで使用されるのと同じ DAG として描画され、依存関係のないワークフローはリスト表示を維持する。

既存の権限ライフサイクルが引き続き権威である: 承認すると Plan Mode を抜けて実行が始まり、拒否するとセッションは Plan Mode のままとなる。アクティブな Todo スナップショットがない場合、承認は ACP が運ぶプラン本文を使用した既存のテキストのみ表示を維持する。Plan Mode に入らないセッションは変更されない。

## Status composition

Todo のステータスが引き続きビジネス上の信頼できるソースである。Agent の状態は実行のオーバーレイである:

1. リンクされた実行のいずれかが実行中: Running
2. それ以外で、リンクされた実行のいずれかが一時停止中: Paused
3. Todo 完了: Completed
4. 依存 Todo のいずれかが未完了: Blocked
5. Todo 進行中: In progress
6. それ以外: Ready

失敗またはキャンセルされた実行は、Todo のステータスを変更せずに Needs attention バッジを追加する。

## Compatibility and boundaries

- ID や依存関係のない古い Todo スナップショットも引き続き読み取り可能である。
- `todo_id` のない Agent 呼び出しも引き続き有効である。
- 空の Todo スナップショットは、アクティブ状態を即座にクリアしなければならない。
- サブエージェントの完全な結果は、3 秒のタスクポーリングレスポンスに入れない。
- Todo ノードはステップの出力を捏造しない。実行の詳細はリンクされた Agent ツール呼び出しと既存のサブエージェント詳細セッションに由来する。
- セッションレベルの存在チェックは古いプランを受け入れてしまう可能性があるため、すべてのセッションへの厳密なプラン優先の強制は引き続き範囲外である。
