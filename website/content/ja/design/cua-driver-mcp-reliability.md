# cua-driver MCP reliability hardening

## Problem

MCP プロキシはデーモンからの応答を最大 120 秒待つ。複数の macOS ツールパスは
同期的な OS 呼び出しの中でそれより長くブロックすることがある。その場合、
プロキシは汎用的な JSON-RPC `-32603` を出力する一方、放棄された操作と子プロセスは
実行を続けてしまう。また、capture scope はメモリとディスクの両方から読み取られるため、
`set_config` が成功を報告した後でも、1 つの MCP セッションが矛盾する値を
観測することがある。

## Design

### セッションごとに 1 つの有効な設定

`capture_scope` を既存のセッションスコープの画像サイズ上書きと同様に扱う。
MCP 呼び出しは呼び出し元の `_session_id` からこれを解決し、匿名の CLI 呼び出しは
グローバルに永続化されたデフォルトを使用する。`set_config`、`get_config`、
`get_desktop_state` はすべて同じ `ToolState` を通して解決しなければならない。
匿名時の永続化はメモリ内の値がコミットされる前に行われ、書き込み失敗は
呼び出し元へ返される。

### アプリ列挙からサブプロセスを排除する

稼働中のアプリには `NSWorkspace.runningApplications` を、インストール済みアプリには
Core Foundation のバンドルメタデータを使用する。これにより、インストール済みバンドルごとに
安全なタイムアウトを推測しようとするのではなく、`list_apps`、
`get_accessibility_tree`、`launch_app` の検出パスから `osascript` と `plutil` を
排除する。

### スクリーンショット取得を制限し終了させる

既存の `screencapture` バックエンドを維持しつつ、1 つの制限付きヘルパーを
経由して起動する。期限に達したら、ツールエラーを返す前にプロセスを kill して
回収する。取得ごとに一意の一時パス名と RAII クリーンアップガードを使用し、
並行呼び出し同士が衝突せず、失敗時にファイルが残らないようにする。

### AX とデーモンの作業をプロキシの期限より下に制限する

ツリー探索と要素アクションの前にネイティブ AX メッセージングタイムアウトを設定する。
最終的な安全網として、プロキシの 120 秒トランスポート期限より短い
デーモン側のツール期限を追加する。通常は内部の制限が先に効くべきであり、
デーモンの期限は予期しないツールの停滞が `-32603` ではなく
ツールレベルのエラーになることを保証する。

### フォークのデーモンエンドポイントを分離する

Qwen 固有のデフォルト Unix ソケットと PID ディレクトリを使用する。古いアップストリームの
デーモンはアップストリームのデフォルトで実行を続ける可能性があるが、Qwen プロキシは
もはやそれを暗黙的に再利用して、ユーザーが起動したバイナリとは異なる
実装／バージョンを実行することはない。明示的な `--socket` 上書きは
変更されない。

### ライフサイクル診断を保持する

セッションが tombstone 化された理由（明示的な終了、アイドル期限切れ、または接続終了）を
保持し、その理由を拒否テキストに含める。明示的な `start_session` による
復活は維持する。デフォルトのアイドル TTL を増やし、通常の長いエージェントターンが
わずか 5 分でセッションを失わないようにする。テストやデプロイ向けの
環境変数による上書きは引き続き利用可能である。

### E2E テストにフォークのバイナリを実行させる

共有テストキット内で `qwen-cua-driver` を解決する。フォークのバイナリが
実際の名前で存在する場合に、バイナリが見つからないことが
意図された E2E アサーションを 0 秒でパスするスキップに変えてはならない。

## Non-goals

- MCP JSON-RPC プロトコルの変更や、破壊的アクションのリトライ。
- Tokio が任意の外部ブロッキング呼び出しをキャンセルできるようにすること。
  OS サブプロセスは直接 kill され、AX にはネイティブのメッセージングタイムアウトが
  設定される。
- 座標正規化の挙動の変更。

## Verification

修正前の再現に使用したものと同じ分離されたプロキシ／デーモンのブラックボックスケースを
実行する。設定永続化の失敗、ハングしたアプリ列挙シム、ハングした
スクリーンショットシム、短いセッション TTL／復活である。2 つのハングケースは
120 秒のプロキシ期限より前に戻り、子プロセスを残さず、直後の
フォローアップ呼び出しが可能でなければならない。
