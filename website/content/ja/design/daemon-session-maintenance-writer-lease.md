# デーモンセッションメンテナンスのライターリース

## Problem

デーモンは、インプロセスの ACP オーナーがクローズされた後でも、永続化された
トランスクリプトの削除、アーカイブ、アーカイブ解除を行うことができる。別のデーモン
プロセスが同じトランスクリプトを所有している可能性があるため、インプロセスの
アーカイブコーディネーターだけでは、デーモンが外部のライターと競合することを
防げない。

トランスクリプトパスとライターロックパスもまた、同じワークスペースランタイムから
解決されなければならない。プライマリのデーモンランタイムへフォールバックすると、
別のワークスペースのロックを確認しながら一方のワークスペースを変更してしまう
可能性がある。

## Scope

この変更はデーモン所有のメンテナンスを対象とする:

- REST と ACP の削除、アーカイブ、アーカイブ解除リクエスト
- 切断および孤立（orphan）クリーンアップ
- スケジュールタスクのロールバックおよび keepalive クリーンアップ
- メンテナンスがすでに実行中のデーモンシャットダウン

リースの有効期限、heartbeat、ホスト名ベースのリカバリ、自動 steal、強制ロック解除、
ロックスキーマのマイグレーションは追加しない。リースプロトコルに参加しないライター
には、引き続きプラットフォームレベルのシングルライター fencing が必要である。

## Runtime storage binding

各 `WorkspaceRuntime` は、生成時に 1 つの絶対パスのセッションランタイムベース
ディレクトリを解決する。解決は既存の優先順位を維持する:

1. `QWEN_RUNTIME_DIR`
2. `advanced.runtimeOutputDir`。ワークスペースからの相対パスとして解決される
3. 通常の Qwen ランタイムディレクトリ

解決されたディレクトリはランタイムに保存され、すべてのマネージド ACP 子プロセスに
`QWEN_RUNTIME_DIR` として注入される。環境の再読み込みは他の値を更新する場合が
あるが、この固定された値は保持される。`runtimeOutputDir` の変更にはランタイムの
再起動が必要だからである。

セッションの一覧表示、読み取り、エクスポート、整理、メンテナンスを行うデーモンの
親操作は、選択されたランタイムのストレージコンテキスト内で実行される。ランタイム
解決の失敗はプライマリランタイムへフォールバックしない。

## Lease API

`SessionService.acquireSessionWriterLease()` は、サービスの固定 `Storage`
インスタンスからライターロックのルートとアクティブなトランスクリプトパスの両方を
導出する。呼び出し元はセッション ID、プロセス種別、バージョン、reclaim policy のみ
を提供する。無効なセッション ID は、ロックディレクトリに触れる前に拒否される。

デーモンのメンテナンスは常に `processKind: 'daemon'` と
`reclaimPolicy: 'never'` を使用する。既存のロックスキーマ、キー、オーナーレコード、
取得/解放プロトコルは変更されない。

## Maintenance protocol

すべてのセッションは独立して処理される:

1. デーモンのセッションごとの排他アーカイブコーディネーターに入る。
2. ローカルオーナーをクローズする。アーカイブにはエージェントのクローズが必要で
   あり、削除は通常の高速クローズを使用する。ローカルオーナーが存在しないことは
   許容される。
3. 永続化された状態を分類し、ロックを作成せずに既存の not-found および冪等な結果
   を保持する。
4. デーモンのライターリースを取得する。
5. リースを保持したまま再分類する。
6. 所有権とトランスクリプトのフィンガープリントを検証してから、1 回のミューテー
   ションを実行する。
7. オーナートークンの検証とともにリースを解放する。

バッチリクエストは独立したセッションを並行して処理してもよいが、ワーカーは最大で
1 つのクロスプロセスリースを保持し、複数のリースを保持したまま待機することは
決してない。

ミューテーションの失敗は、解放が成功した場合でも報告されるエラーのままとなる。
解放または所有権の失敗は、ミューテーションも失敗していたとしても、外部に対して
安全なエラーとなる。ログにはワークスペース、セッション、アクション、エラー種別、
およびトランスクリプトのミューテーションがディスクに到達したかが記録され、
オーナートークンやロックパスは決して含めない。スケジュールタスクの reconciliation
は、リースの解放がその後成功したかどうかではなく、実際のトランスクリプトの
ミューテーションに従う。

孤立（orphan）クリーンアップはまずローカルオーナーをクローズし、
`requireZeroAttaches` を尊重する。したがって、新しくアタッチされたオーナーは削除を
防ぐ。late-spawn クリーンアップは、リースを取得してトランスクリプトを削除する前に
クローズを待機する。

## Shutdown

`SessionArchiveCoordinator.sealMaintenanceAndWait()` は、新しい排他メンテナンスを
同期的に拒否し、すでに受け入れられた排他操作を待機する。共有のトランスクリプト
読み取りは対象に含まれないため、長いエクスポートが終了処理の予算を消費することは
ない。REST は `503 daemon_draining` を返し、ACP は `data.errorKind = daemon_draining`
を伴う JSON-RPC サーバーエラーを返す。

デーモンのシャットダウンは、子プロセス/プロセスのティアダウンの前にメンテナンスを
seal し、受け入れられたメンテナンスのリースがすべて解放された後にのみ完了する。

## Compatibility and rollout

バッチレスポンスの形状と、既存のアーカイブ/削除/アーカイブ解除の冪等性は変更され
ない。受け入れ（admission）前に `assertNotTransitioning` によって発生させられる
事前チェックのローカル `session_archiving` 競合は、引き続きリクエストレベルの
`409` として表面化する。受け入れゲートの内部で発生した競合は、アーカイブ、
アーカイブ解除、削除のいずれでも、`200` レスポンス本文（`errors[]`）内でセッション
ごとに報告される。バージョンが混在するライターは安全ではないため、デプロイと
ロールバックは、新バージョンを開始する前に古いデーモンとマネージド ACP プロセスを
drain しなければならない。

## Verification

テストは、ライターの競合とルートの分離のために実際の一時ランタイムルートを使用し、
初期分類とロック済み分類の間の状態変化をカバーし、クローズ、ミューテーション、
解放、スケジュールタスクの reconciliation、シャットダウンの順序を検証する。
ユニットテストはさらに、無効な ID、重複 ID、アクティブ/アーカイブの競合、リース
解放の失敗、孤立セッションの再アタッチ、ログの秘匿化もカバーする。マージ前には
関連パッケージのテスト、ビルド、typecheck が必須である。
