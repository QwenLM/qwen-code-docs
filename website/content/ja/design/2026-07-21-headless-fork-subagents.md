# ヘッドレスのコンテキスト継承サブエージェント

## 問題

明示的な `subagent_type: "fork"` リクエストは、現在 `Config.isInteractive()` が true の場合のみ受け入れられます。`qwen --prompt`、TypeScript SDK、CI ランナーなどのヘッドレス呼び出し元は、代わりに新しい `general-purpose` サブエージェントを暗黙のうちに実行します。そのため、要求されたコンテキストモードと実効のコンテキストモードが異なり、子は親の会話を受け取りません。

## 設計

フォークの利用可能性はプレゼンテーションサーフェスから独立しています。トップレベルのフォークリクエストは常に既存のフォーク構築パスを使用し、それは親の履歴とキャッシュセーフな生成設定をコピーします。

ヘッドレスのフォークは、`run_in_background` が省略された、または false の場合でも、既存のバックグラウンドエージェントレジストリを通じて実行されます。フォークは定義上デタッチされており、レジストリは非インタラクティブな呼び出し元に必要なライフサイクルを提供します:

- 単発のヘッドレス実行はフォークの完了を待つ;
- ストリーム利用側は `task_started` と終端のタスク通知を受け取る;
- 実効の `subagent_type: "fork"` はイベント、メタデータ、サブエージェントのテレメトリーに記録される;
- 非インタラクティブセッションでは表示できないパーミッションリクエストは、ハングする代わりに既存のバックグラウンドエージェントポリシーによって拒否される。

インタラクティブなフォークの動作は変更されません。

ネストされたサブエージェントからのフォークリクエストは引き続きサポートされませんが、新しい `general-purpose` サブエージェントを暗黙のうちに実行する代わりに、明示的なツールエラーで失敗するようになりました。

## スコープ

この変更は、現在の全履歴フォークの動作を再利用します。`fork_turns` のような部分履歴選択は追加しません。それは、正しいヘッドレス継承をブロックせずに別途導入できます。

## 検証

- コアのディスパッチテストは、インタラクティブなフォーク、ヘッドレスフォーク、強制バックグラウンドのライフサイクル、継承された履歴の構築、パーミッションの動作、明示的なネストフォークの拒否をカバーします。
- 非インタラクティブ CLI テストは、SDK 向けの `task_started` イベントをカバーし、それが `subagent_type: "fork"` を公開することを検証します。
- デスクトップ SDK アダプターテストは、ランタイムのバックグラウンド結果が、呼び出し元が指定した `run_in_background: false` に優先することを検証します。
- エンドツーエンドの `qwen --prompt --output-format stream-json` チェックは、フォークディレクティブには存在しない親マーカーを使用し、子が継承された履歴からそれを引き続き復元できることを検証します。
