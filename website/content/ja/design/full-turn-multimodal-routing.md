# ターン全体のマルチモーダルルーティング

## Scope

これは #6988 の Phase 1 のみを実装する。プライマリモデルがテキスト専用の場合に、明示的にエージェント対応のビジョンモデルが、画像を含むターン全体を処理できるというもの。

永続的なルート状態、セッションリカバリ、永続的なビジュアルサマリ、安定した画像参照、履歴メディアのクリーンアップ、後続の画像再検査は追加しない。

## Capability gate

ターン全体のルーティングには、画像とエージェントの両方の capability が必要である:

```json
{
  "id": "vision-agent",
  "capabilities": {
    "vision": true,
    "agent": true
  }
}
```

`agent` capability が欠落している、または false の場合は、既存の Vision Bridge による文字起こしの挙動が維持される。

## Routing

- プライマリが画像を受け付ける場合は、既存のプライマリモデルのパスを使用する。
- 選択されたビジョンモデルがエージェント対応でない場合は、Vision Bridge で文字起こしを行い、プライマリで回答する。
- 選択されたビジョンモデルがエージェント対応の場合は、元の画像パーツを保持し、ターンローカルな exact モデルセレクターを設定する。
- exact なプロバイダー、モデル、エンドポイントは、プロバイダーリトライ、ツール実行、ツール結果の continuation、ブロッキングな ACP Stop Hook の continuation で再利用される。
- ヘッドレスのツール実行は、選択された画像モデルと同じランタイムビューを受け取る。キューに入った通知や cron の drain は独立したターンのままであり、これを引き継がない。
- 設定されたフォールバックモデルは、そのターンでは無効になる。exact ルートの解決に失敗した場合は、生の画像データをプライマリに送信するのではなく、fail closed（失敗時は拒否）となる。
- 次の独立したユーザーターンでセレクターはクリアされ、プライマリに戻る。すべてのモデルリクエストは、サイドクエリを含め、その exact なターゲットがサポートするメディアモダリティのみを受け取る。

ターン全体のセレクターは、既存の `model\0baseUrl` 表現に末尾の NUL マーカーを追加する。チャットレイヤーはモデル解決の前にそのマーカーを除去する。これにより、通常のエンドポイント修飾付きモデル選択は既存の挙動のままである。

## Context limits

LLM ベースの自動チャット圧縮は、プライマリモデルのパスに残る。ターン全体のルートはその圧縮をスキップする。画像ターンを別のプロバイダーが所有している間にプライマリモデルの圧縮を実行すると、exact ルートの保証に違反するためである。既存のローカル履歴のマイクロコンパクションと画像ペイロードのスリム化は引き続き適用され、リクエスト/キャッシュのコピーはターゲットモデルがサポートするメディアモダリティのみを保持する。そのため、サイズ超過のターン全体のリクエストは選択されたモデルで失敗する。

## Entry points

Phase 1 は、インタラクティブ TUI、ACP、および非インタラクティブ CLI を対象とする。

テキストの `@` パスは、MIME 検出、ワークスペースチェック、ignore フィルタリング、ファイル読み取りの前に、正規ターゲットへ解決される。ユーザー指定のエイリアスと正規ターゲットの両方が ignore フィルタリングを通過する必要があるため、シンボリックリンクで ignore 対象ファイルや画像以外のターゲットを偽装することはできない。ハードリンクは `realpath` では解決されず、このチェックの対象外である。
