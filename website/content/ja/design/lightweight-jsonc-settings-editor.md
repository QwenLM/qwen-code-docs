# 軽量 JSONC 設定エディター

## Context

ACP ランタイムは、settings と trusted-folders のライターを静的に import している。両方のライターは現在 `comment-json` に依存しており、そのパーサークラスタは ACP の起動クロージャに 304,770 バイトを占める。これらのモジュールは、ほとんどの起動がどちらのファイルも書き込まないにもかかわらず、ACP 子が `initialize` に応答する前に解析・評価される。

Issue #7264 の候補 6 は、そのパーサーの遅延読み込み、またはより軽量なパーサーへの置き換えを提案している。書き込み API とその呼び出し元は同期であり、スタンドアローンの配布はバンドル外の任意の JavaScript 依存関係を同梱しないため、ランタイムの `require()` や動的 import は API の拡大か初回使用の破壊を招く。`jsonc-parser` はすでに開発依存関係グラフに存在し、バンドルフットプリントが小さく、同期の解析とパス編集 API を提供する。

## Goals

- ACP の静的起動クロージャから `comment-json` と `esprima` を削除する。
- 同期の settings および trusted-folders 書き込み API を維持する。
- 通常の更新において、既存ファイルのコメント、インデント、改行コード、末尾改行、UTF-8 BOM を保持する。
- マージ、同期、厳密なサブツリー置換の挙動を維持する。
- trusted-folders のロック、ディスク再読み込み、検証、権限、アトミック書き込み、通知、ロック解放の境界を変更しない。
- 不正な形式または非オブジェクトの JSONC を上書きせずに拒否する。

## Non-goals

- settings のマイグレーションや trusted-folder セマンティクスの変更。
- 設定書き込みの非同期化。
- すべての設定ファイルの再フォーマット。
- 個別の厳密な trusted-folders 読み込みパスの置き換え。
- 他のパッケージ向けの汎用 JSONC 抽象化の追加。

## Design

レガシーのキャメルケースユーティリティをケバブケースの JSONC エディターモジュールにリネームする。このモジュールは既存のファイルレベル更新 API と `applyUpdates` ヘルパーを保持し、2 つの同期インメモリ操作を追加する:

1. JSONC をトップレベルオブジェクトとして解析しつつ、すべてのパーサーエラーを収集して拒否する。先頭の UTF-8 BOM は解析前に一時的に除去する。
2. マージ、同期、または厳密なサブツリーの更新を解析済み値に適用し、変更されたオブジェクトパスを算出し、`jsonc-parser.modify()` でそれらのパスを元のテキストに適用する。

オブジェクトは再帰的に差分比較され、変更されていないコメントとレイアウトは手付かずのままになる。配列とスカラー値はアトミックに置換される。プロパティを削除する前に、同じ行のインラインコメントをそのプロパティと一緒に削除する。そうしないと `jsonc-parser` がコメントを前のプロパティに付与してしまう可能性がある。出力全体は、呼び出し元が書き込む前に再解析され、意図した値と比較される。

重複するオブジェクトキーは明示的な処理が必要である。`jsonc-parser` は最後の値を評価する一方、`modify()` は最初に一致するプロパティを対象とするためである。オブジェクトパスの更新を適用する前に、それらのパスに沿った先行する重複プロパティを削除し、実効的に最後のプロパティが残るようにする。削除された重複出現が所有するコメントは一緒に削除される。これにより、実効値が変更されないまま成功を返すことを回避する。

新規ファイルは引き続き 2 スペースの JSON を使用する。既存ファイルは検出されたタブまたはスペース、LF または CRLF、末尾改行の状態、先頭 BOM を保持する。

`trustedFolders` は、既存のロックを取得してファイルを再読み込みした後、インメモリのパーサーとエディターを再利用する。引き続きディスク状態と提案状態を検証し、モード `0o600`、`forceMode: true`、`noFollow: true` の `atomicWriteFileSync()` で書き込み、書き込み成功後にのみメモリを更新し、`finally` でロックを解放する。

`jsonc-parser` は CLI の直接の本番依存関係となり、`comment-json` は削除される。ソースの import は公開パッケージエントリを使用し、バンドルされていないコンパイル出力が Node で直接実行可能なままになる。esbuild 設定はそのエントリをパッケージの ESM ビルドにエイリアスする。Node 向けバンドルはそうでなければ UMD エントリを選択し、その相対 CommonJS require は分割された ESM バンドルを生き延びないためである。ファストパスのバンドルガードは、ACP 静的クロージャ内の `comment-json`、`esprima`、`jsonc-parser` UMD ビルドを禁止する。

## Failure handling

- パーサーエラーまたは非オブジェクトのルートは、書き込み前に中断する。
- JSON として表現できない値は、書き込み前に中断する。
- 編集済みドキュメントと意図した値の不一致は、書き込み前に中断する。
- settings の書き込みは、解析または検証失敗時に既存の `false` 返却と stderr 診断を維持する。
- trusted-folders の書き込みはスロー挙動を維持し、権威ある書き込みの失敗後に呼び出し元がメモリ内状態を更新することはない。
- ファイルシステム、ロック、権限、アトミック書き込みの失敗は既存の挙動を維持する。

## Alternatives considered

### 動的 `import('comment-json')`

公開の書き込みパスは同期であり、同期のマイグレーション、UI、ACP、デーモンの呼び出し元を持つため却下。呼び出しグラフの非同期化はこの最適化より広い。

### 遅延 `createRequire()`

esbuild は依存関係をバンドルの外に残し、スタンドアローンアーカイブは `lib/node_modules` に任意の JavaScript パッケージを含まないため却下。パッケージ化された初回書き込みがランタイムに失敗し得る。

### 常に `JSON.stringify()` で書き直す

通常の設定更新時にユーザーのコメントとフォーマットを破棄するため却下。

### カスタムトークナイザー

`jsonc-parser` が必要なパースツリーと編集プリミティブを、実質的に小さい保守済み実装で提供するため却下。

## Validation

- フォーカスしたユニットテストは、既存の挙動に加え、不正な形式の入力、非オブジェクトのルート、末尾カンマ、ネストおよびインラインコメント、削除プロパティのコメント、マージ/同期/置換セマンティクス、プロトタイプ汚染キー、重複キー、CRLF、タブ、末尾改行、BOM、無操作書き込み、出力検証をカバーする。
- trusted-folders のテストは、ロックされたディスクのマージ、無効な入出力、コメント保持、厳密な同期、権限を保持するアトミック書き込み、書き込み失敗、ロック解放をカバーする。
- バンドルガードテストと生成された esbuild metafile は、`comment-json` も `esprima` も ACP 静的クロージャにないことを証明する。
- CLI のビルド、typecheck、lint、フォーカステストが合格しなければならない。
- コントロールと候補のリリースバンドルは、確立された 2 vCPU ホストで、1 回の破棄ウォームアップ、交互のペアコールドスタート 30 回、交互のペアプリヒートスタート 30 回で実行された。候補はコールドの `channel.initialize` P50 を 35.39 ms、プロセスから最初のセッションまで P50 を 38.00 ms、プロセスから最初のセッション完了まで P50 を 48.51 ms 短縮した。各主要メトリクスで 30 コールドペア中 28 回勝利し、ペア平均の 95% ブートストラップ区間は完全にゼロ未満だった。
- すでにプリヒート済みのプロセスからセッション完了までのパスは統計的に中立だった。並行する最初のセッション、レガシー単一セッションモード、telemetry 有効、telemetry 無効のすべてが正常に完了し、期待される telemetry を生成し、残留プロセスはなかった。
- 候補のプロセストリーピーク RSS は初期化中に約 10.8 MiB 高かったが、別の 10 ペアのフォローアップが同じプロセスを 10 秒のアイドル期間後にサンプリングした。ペアの定常状態中央値差分は 0.55 MiB でブートストラップ区間はゼロを跨ぎ、ピーク差は持続的なフットプリント増加ではなく、一時的な初期化とガベージコレクションのタイミングだったことを示す。
- 厳密な ACP 静的クロージャは 12,449,869 バイトから 12,145,099 バイトへ、304,770 バイト（2.45%）減少し、`comment-json`、`esprima`、`jsonc-parser` UMD の入力はない。
