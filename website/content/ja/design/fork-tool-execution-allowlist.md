# フォークのツール実行許可リスト

## Summary

エージェントツールの既存の `subagent_type: "fork"` ランタイムに、任意の
`fork_tools` パラメーターを追加する。このパラメーターは、モデルに送信される
ツール宣言を変更せずに、フォークが実行できるツールを狭める。

これは #7625 の最初のフェーズである。名前付きプロファイルファイル、シェルの
引数パターン、オーバーレイファイルシステム、`/btw` の統合は対象外である。
起動プロンプトのヒントが、許可リストがどの可視ツールを許可するかをフォークに
伝える。

## Goals

- `fork_tools` が省略された場合は、フォークが決して実行してはならないインタ
  ラクションツールを除き、継承されたフォークの実行サーフェスを維持する。
- 空のリストは、既存の `tools: []` のワイルドカード挙動ではなく、すべて拒否
  として扱う。
- フォークの現在のモデル可視の宣言を変更しないままにし、実行制限の追加がその
  プロンプトキャッシュのプレフィックスを変えないようにする。
- 許可されていない呼び出しは、ツールの構築、ツールのフック、権限の分類、スケ
  ジューリング、承認の前に拒否する。
- バックグラウンドのフォークが永続化されたサイドカーからリバイバルされたとき
  も、制限を維持する。

## Parameter and Matching

`fork_tools` は、明示的な `subagent_type: "fork"` とのみ有効であり、名前付き
チームメイトと組み合わせることはできない。すべてのエントリは、前後に空白の
ない空でない文字列でなければならない。不明な完全一致の名前は許可リストに残り、
何にも一致しない。無効な空でないリストを省略された制限に変えると fail open
（失敗時は許可）になってしまうため、これらは取り除かれない。

組み込みツールは、モデル可視の宣言からの正確な正規の関数名を使用する。MCP の
エントリは、正確な正規名に加え、サーバーおよび末尾ワイルドカードパターンを
サポートする。パターンは、プロバイダーがサニタイズした名前だけでなく、登録
されたツールの生の MCP サーバー/ツールアイデンティティに対してマッチされる
ため、サニタイズすると同じプレフィックスになる別個のサーバー名がクロス
マッチすることはできない。裸の `*` は拒否される。省略すれば、すでに、それ
以外で実行可能なすべての継承ツールが許可される。
ワイルドカードエントリは、`mcp__*` または `mcp__github__read_*` のような末尾
の MCP ツールプレフィックスパターンに限定される。`mcp__*` は意図的に、組み
込みツールにはマッチせずにすべての MCP ツールにマッチする。

シェルの引数パターンはこのフェーズの一部ではない。`run_shell_command` を列挙
すると、ツール呼び出しは通常の権限パイプラインを通過し続けるが、そのコマンド
を事前承認するわけではない。

## Runtime Separation

`ToolConfig.tools` は、引き続き `AgentCore.prepareTools()` とすべてのモデル
リクエストの関数宣言のソースである。`AgentCore` が作成されるとき、別の
`executionAllowedTools` フィールドがスナップショットされる。完全一致のエントリ
と MCP のワイルドカードエントリは個別に事前計算されるため、ツールのミスが無関係
な組み込み名の割り当てや再スキャンを行うことはない。

`processFunctionCalls()` はまず、要求された名前が宣言セットに存在することを
検証する。その後、任意の実行許可リストを適用する。許可されていない呼び出しは、
元の呼び出し ID と名前を持つ 1 つの合成エラーレスポンスを生成し、同じバッチ
内の他の呼び出しはスケジューラーに進み続ける。このチェックはスケジューラーの
構築より前に行われるため、拒否された呼び出しが承認プロンプトを開いたり、
ツール前のフックを実行したりすることはできない。

許可リストは既存のサーフェスを狭めるだけである。サブエージェントの除外に
よって削除されたツールを再有効にすることも、許可されたツールの通常の権限を
バイパスすることも、宣言を追加することもできない。

すべてのフォークは、`fork_tools` が省略された場合でも、インメモリの実行許可
リストを受け取る。ランタイム所有の最低限の制限は、呼び出し元が提供したリスト
を適用した後に `ask_user_question` を削除するため、呼び出し元はそれを再有効
にできない。このツールは、プロンプトキャッシュの共有のために親由来の宣言
リストに残るが、呼び出しはスケジューリングや承認の前に拒否される。ブロック
されたフォークは、ユーザーと直接対話しようとするのではなく、入力の欠落を親に
報告する。

フォークは、継承されたキャッシュ可能なプレフィックスの後で、タスクプロンプト
内で制限の通知を受け取る。これにより、親由来のシステム指示、履歴プレフィックス、
ツール宣言を変更することなく、試行錯誤の呼び出しを回避する。

## Background Revival

バックグラウンドのフォークは、継承された履歴を `agent_bootstrap` トランス
クリプトレコードに、起動タスクのプロンプトを別のレコードに永続化する。システ
ム指示とツール宣言はケイパビリティであるため、コールドリバイバルは現在の親
ランタイムからそれらを再バインドし、現在のツール名をライブのレジストリを通じ
て解決する。

呼び出し元が提供した `executionAllowedTools` は、代わりに起動時のポリシーで
ある。制限されたフォークは、空のすべて拒否リストを含め、それを `AgentMeta`
のサイドカーに保存し、コールドリバイバルはそれをライブの `ToolConfig` に再
適用する。`fork_tools` なしで起動されたフォークは、導出されたリストを永続化
せず、リバイバルが現在の親のツールサーフェスからそれを再計算できるようにする。
結果として実行可能なサーフェスは、現在の親由来のツールサーフェスを、永続化
されたポリシーと必須のインタラクションツールの除外によって狭めたものである。

このフィールドは、互換性のために任意のままである。古いトランスクリプトや
`fork_tools` なしで起動されたフォークは、必須のインタラクションツールの除外
を引いた、現在の親由来のツールサーフェスで復元される。

## Boundary

`fork_tools` は、各エージェントツールの呼び出し時に、親モデルまたは呼び出し元
によって提供される。したがって、これは子に対するケイパビリティの制限であり、
ユーザーや管理者が強制するセキュリティサンドボックスではない。将来のプロ
ファイルレイヤーは、この実行メカニズムの上に、短い、プロジェクトが制御する
ポリシー名を提供できる。

この制限は別の子を通じてロンダリングすることはできない。フォークの実行は
フォークランタイムコンテキスト内で実行され、その権威あるエージェントツールの
ガードはすべてのサブエージェントの起動を拒否する。より一般的には、
`fork_tools` は、除外された、または宣言されていないツールを実行可能にする
ことはできない。
