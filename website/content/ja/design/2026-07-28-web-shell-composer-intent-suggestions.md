# Web Shell composer のインテントサジェスチョン

## サマリー

Web Shell の既存の新規トピック提案を拡張し、1 回のコンサバティブな分類で、`/btw` による
横道質問の提案と、新規セッションでの実体的な新トピック送信のどちらかを推奨できるようにする。

composer は引き続き最大 1 つの非ブロッキングアクションのみを表示する。有効な `none` の
判定は何もレンダリングしない。無効、失敗、キャンセルされた分類も何もレンダリングしない。

## 判定契約

```ts
type SuggestionKind = 'btw' | 'new_session' | 'none';

interface SuggestionDecision {
  suggestion: SuggestionKind;
  confidence: number;
}
```

既存の confidence 閾値以上の `btw` と `new_session` の判定のみがアクション可能になる。
アクション可能状態は、分類されたドラフトとソースセッションの正確な内容を記録し、
ユーザーのクリック時に両方を再チェックできるようにする。

## 挙動

- `btw` は、メインタスクを妨げるべきでない、素早く自己完結した横道質問向け。
- `new_session` は、明確に異なり実体的なタスクやトピック向け。
- `none` は継続、不確実、どちらのアクションにも当てはまらないドラフトをカバー。
- BTW の分類は、直前のユーザー/アシスタントの 1 往復の後から開始する。新規セッションの
  提案は既存のより厳格なコンテキスト閾値を維持する。
- フォローアップのような文言は BTW に分類されうるが、緩和された BTW 閾値を使って
  新規セッションアクションを表面化させることは決してできない。
- `btw` サジェスチョンのクリックは、既存のエディターパスを通じて `/btw <draft>` を
  送信し、コマンドの現在の履歴と composer クリアのセマンティクスを保持する。
- 画像または composer タグを含むドラフトは `btw` の対象にならない。
- `new_session` は既存のクリア、デタッチ、作成、自動送信のシーケンスを保持する
  （画像の保持とセッション競合のキャンセルを含む）。

## 安全性

分類器はコンサバティブかつ fail closed（失敗時は拒否）のまま:

- 不正形式の出力、未知のアクション、無効な confidence、エラー、キャンセルは
  アクションを生成しない;
- セッション変更は pending の分類を中断し、表示中のサジェスチョンを無効化;
- ドラフトまたは添付の変更は表示中のサジェスチョンを無効化;
- クリック処理は実行直前に現在のドラフト、ソースセッション、添付状態をチェック;
- ChatEditor がそうでないと報告するまで添付は存在するものとして扱うため、
  一時的な unknown 状態が `/btw` アクションを露出することはない。

## スコープ

変更は Web Shell 内にとどまる。既存のデーモンセッション生成、エディター送信、`/btw` の
挙動を再利用する。デーモンや SDK のルートを追加せず、スタイリングを変更せず、
汎用のサジェスチョンフレームワークも導入しない。

## composer のパフォーマンス

ドラフトの変更は安定したコールバックを通じて分類器に入る。分類器の refs、キャンセル状態、
デバウンスタイマーを更新するが、React の状態は更新しない。Web Shell アプリは、
アクション可能なサジェスチョンが出現するか、既存のサジェスチョンが無効化されたときにのみ
再レンダリングされる。

これにより、ドラフト変更時の即座のキャンセルを保持しつつ、インテント分類を composer の
レンダリングパスから外す。

## テスト戦略

- フックテストは、3 つの判定値、厳密なパース、confidence、添付ゲーティング、
  stale セッションの結果をカバー。
- アプリテストは、`/btw` の実行と composer クリア、stale なドラフト/セッションの拒否、
  添付の拒否、既存の新規セッション競合、分類 pending 中のアプリ再レンダリングの不在を
  カバー。
- ChatEditor テストは添付存在の報告をカバー。
