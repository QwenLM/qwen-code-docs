# Web Shell AskUserQuestion の送信リトライ

## 問題

`AskUserQuestion` は判定がクリックされると即座にロックされるが、そのコールバックは
非同期のパミッション結果を公開しない。したがってリクエストが失敗すると、見た目上有効な
パネルが残り、リトライをサイレントに無視する。送信パスは、パミッションペイロードに
`allow_once` オプションがない場合もサイレントに return する。

## 設計

- `AskUserQuestion` に、promise を返す確認コールバックと、所有するチャットサーフェスが
  提供するエラーレポーターを与える。
- リクエストの in-flight 中はアクションを無効化し、送信中のインジケーターを表示する。
- 正常に受け入れられた判定は、パミッションイベントがパネルを削除するまでロックを維持。
  これは記録済みだがまだ最終ではないコンセンサス投票もカバーする。
- 拒否または `false` の結果では、エラーを報告しアクションのロックを解除して
  ユーザーがリトライできるようにする。
- `allow_once` オプションの欠落は、サイレントに return せず即座に報告する。
