# デフォルトのバックグラウンドサブエージェント

## サマリー

トップレベルのワンショットサブエージェントは、デフォルトでバックグラウンドで実行されるべきです。インラインの結果が必要な呼び出し元は、`run_in_background: false` でオプトアウトできます。ネストされたサブエージェントの起動と、呼び出し元所有の `working_dir` に固定された起動は、現在のバックグラウンドライフサイクルがそれらの呼び出し元に安全に結果を返せないため、引き続きフォアグラウンドの操作です。フォークと名前付き Agent Teams のチームメイトは既存の動作を維持します。

## 動機

Agent ツールはすでに、インタラクティブ、ヘッドレス、SDK のコンシューマー間でバックグラウンド実行をサポートしていますが、呼び出し元は現在、`run_in_background: true` で要求するか、`background: true` で宣言されたエージェントを選択する必要があります。このため、親が独立した作業を継続できる場合でも、通常の委譲がデフォルトで親をブロックしてしまいます。バックグラウンド実行をトップレベルのデフォルトにすることは、結果に依存する作業のための明示的なフォアグラウンドのエスケープハッチを維持しつつ、ツールの並列委諾のガイダンスにより良く合致します。

## ゴール

- `run_in_background` が省略された場合、トップレベルのワンショットサブエージェントをバックグラウンドで実行する。
- `run_in_background: false` を明示的なフォアグラウンドのオプトアウトとして保持する。
- 既存の完了通知、キャンセル、並行性、パーミッション、トランスクリプト、ヘッドレスの保留パスを保持する。
- 安全でない、またはサポートされない起動形状は既存のフォアグラウンドパスに留める。
- インラインの結果が必要なスキルや呼び出し元に対する互換性の影響を文書化する。

## ノンゴール

- ネストされたサブエージェント起動のバックグラウンド実行。
- 呼び出し元所有の `working_dir` でのバックグラウンド実行。
- フォークのコンテキスト継承やフォークのライフサイクルの変更。
- 名前付き Agent Teams チームメイトの動作の変更。
- デフォルトのための新しいグローバル設定。
- バックグラウンド通知のルーティングやタスクの所有権の再設計。

## 動作

ランタイムは、ワンショットサブエージェントの実行をこの順序で解決します:

1. 名前付き Agent Teams チームメイトは既存のチームメイトパスを使用する。
2. 有効なトップレベルのフォークは既存のデタッチフォークパスを使用する。
3. ネストされた通常のサブエージェントは、バックグラウンドが要求された場合でもフォアグラウンドで実行され、その結果はネストされた呼び出し元に返る。
4. `working_dir` を持ち、設定されたバックグラウンドデフォルトのない通常のサブエージェントは、呼び出し元がそのワークツリーのライフサイクルを所有するため、フォアグラウンドで実行される。明示的または設定されたバックグラウンド要求は無効のまま。
5. その他のトップレベルの通常のサブエージェントについて:
   - `run_in_background: false` はフォアグラウンドで実行。
   - `run_in_background: true` はバックグラウンドで実行。
   - `run_in_background` の省略はバックグラウンドで実行。

既存のエージェントレベルの `background: true` フロントマターは、互換性のため引き続き受け付けられます。新しいトップレベルのデフォルトを得るために、もはや必要ではありません。明示的なツール呼び出しの値 `run_in_background: false` が優先され、フォアグラウンドパスを選択します。

## 実装

ディスパッチの決定は Agent ツール内に留まり、すべてのコンシューマーが同じ動作を受け取ります。バックグラウンドの決定は 3 つの概念を区別すべきです:

- 呼び出し元が明示的にオプトアウトしたか;
- 起動がトップレベルか;
- 起動形状が安全にデタッチできるか。

実装は、2 つ目の起動パスを追加するのではなく、既存のバックグラウンド分岐を再利用すべきです。ツールのスキーマテキストとモデル向けの使用ガイダンスは、バックグラウンドがデフォルトであることを説明し、結果がインラインで必要な場合は `run_in_background: false` を渡すよう呼び出し元に伝えるべきです。

`working_dir` の例外は、既存の非互換ガードの前に解決されなければなりません。バックグラウンドパラメータの省略が、以前は有効だった固定のレビュー起動をエラーに変えてはなりません。明示的な `run_in_background: true` や、`background: true` で設定されたエージェントは、引き続き `working_dir` と非互換であり、既存の安全性チェックを保持します。

## 結果フロー

デフォルトのバックグラウンド起動は、既存のバックグラウンド起動レスポンスを親に即座に返します。デタッチされたタスクは、既存のバックグラウンドタスクレジストリに登録されたままです。終了すると、レジストリは既存の完了、失敗、またはキャンセルの通知を発行し、親は後続のターンで結果を処理します。新しいメッセージ形式や SDK イベントは導入されません。

フォアグラウンドのオプトアウトは、既存の同期分岐を通じて継続し、サニタイズされたサブエージェントの結果をインラインで返します。

## ドキュメント

サブエージェントのユーザーガイドは、名前付きワンショットサブエージェントがトップレベルでデフォルトでバックグラウンドで実行されることを明記し、`run_in_background: false` を説明すべきです。フォークとの比較は、すべての名前付きサブエージェントが親をブロックすると主張するのではなく、コンテキストの継承と結果のセマンティクスに焦点を当てるべきです。

## テスト

ユニットカバレッジは以下を検証すべきです:

- フラグを省略した通常のトップレベルサブエージェントはバックグラウンドで起動する;
- `run_in_background: false` は結果をインラインで返す;
- `run_in_background: true` は既存のバックグラウンド動作を保持する;
- フラグを省略または true にしたネスト起動はフォアグラウンドのまま;
- フラグを省略した `working_dir` 起動はフォアグラウンドのまま;
- `working_dir` を伴う明示的なバックグラウンド要求は引き続き拒否される;
- フォークと名前付きチームメイトの動作は不変;
- ツールのスキーマと使用ガイダンスが新しいデフォルトとオプトアウトを宣伝する。

フォアグラウンド分岐を意図的に検証する既存のテストは、期待が明示的になるよう `run_in_background: false` を渡すべきです。フォーカスした Agent ツールのテストファイル、ビルド、typecheck は提出前に必要です。手動のインタラクティブ E2E チェックでは、通常の委諾が制御を即座に返し、後で完了通知を届けること、および明示的なフォアグラウンドの委諾がブロックして結果をインラインで返すことを確認すべきです。

## リスクと互換性

本変更は、フラグを省略し、Agent ツールのレスポンスにサブエージェントの結果が含まれると仮定するプロンプト、スキル、プログラマティックな呼び出し元にとって、動作上の破壊的変更です。それらの呼び出し元は `run_in_background: false` を渡す必要があります。

デフォルトのバックグラウンド実行は、並行する作業を増加させ得ます。既存のグローバル並行性制限とキューイングが、管理されたセーフガードのままです。パーミッション処理、シャットダウン、ヘッドレスの待機はすでに確立されたバックグラウンドタスクのライフサイクルを使用しており、本設計によって変更されません。
