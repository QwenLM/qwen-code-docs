# オーバーライド可能なデフォルト無効スキル

## 問題

`skills.disabled` は設定スコープ全体で大文字小文字を区別しない和集合です。これによりハードな拒否リストになります: プロジェクトは、ユーザー設定やシステム設定で無効化されたスキルを有効化できません。これはポリシーとしては正しいのですが、最初はオフにしておきつつプロジェクトのオプトインのために利用可能にしておくべきスキルを表現できません。

## 設定

`skills.disabled` を変更せずに、大文字小文字を区別しない 2 つの和集合リストを追加します:

| 設定                  | 意味                                                 |
| ------------------------ | ------------------------------------------------------- |
| `skills.disabled`        | ハードな無効化。常に優先され、既存のロックを保持します。 |
| `skills.defaultDisabled` | 明示的に有効化されない限り無効。                     |
| `skills.enabled`         | 明示的なオプトイン。`skills.disabled` をオーバーライドできません。     |

実効の無効化は `disabled + (defaultDisabled - enabled)` です。置き換えセマンティクスの代わりに明示的な `enabled` リストを使用することで、継承されたデフォルトの 1 つを有効化しても、無関係なデフォルトが置き換えられません。

## ランタイムと永続化

1 つの CLI ローカルリゾルバーが、実効の無効名と、各無効スキルが `hard` か `default` かを計算します。既存のランタイム利用側は、`Config.getDisabledSkillNames()` を通じて実効セットの読み取りを続けます。コアのスキル発見と実行の API は変更されません。

`/skills` ピッカーとデーモンのトグルは同じルールを適用します:

- 有効化は、ワークスペースのハードな無効化を削除し、必要な場合のみ正規名をワークスペースの `skills.enabled` に追加します;
- 無効化は、ワークスペースのオプトインを削除し、正規名をワークスペースの `skills.disabled` に追加します;
- より上位スコープの `skills.disabled` エントリはロックされたままです;
- 無関係なスキルおよび利用不能なスキルのエントリは保持されます。

ワークスペースのスキルステータスに無効化の理由とオプションのロックスコープが追加され、クライアントはハードロックとオーバーライド可能なデフォルトを区別できます。デーモンローカルと ACP のステータスパスは、両方とも同じ CLI ローカルリゾルバーを読み取ります。

## スコープ

- この変更では `defaultDisabled` にスキルは追加されません。
- `disable-model-invocation` と managed-skill の ACP 操作は変更されません。
- 既存の `skills.disabled` 設定は互換性が保たれます。
- 変更は、設定、既存の 2 つのトグルサーフェス、ワークスペースのスキルステータス、それらのワイヤー型、ドキュメント、フォーカスされたテストに限定されます。
