# デーモンの永続ワークスペース登録

## ゴール

Web Shell から追加されたワークスペースは、デーモンが同じプライマリワークスペースと `QWEN_HOME` で再起動された場合、`qwen serve` プロセスの再起動後も維持されます。

## ステータスの所有権

動的なワークスペース登録はユーザープライベートなデーモン設定であり、プロジェクト設定でも使い捨てのランタイム出力でもありません。登録は以下に保存されます:

```text
${QWEN_HOME:-~/.qwen}/daemon/workspaces/<primary-scope-sha256>.json
```

スコープハッシュは、正規化されたプライマリワークスペースパス（Windows では小文字化）の完全な SHA-256 です。ファイルにはプライマリパスが重複して記録されるため、不一致または破損したスコープは暗黙のうちに適用されるのではなく拒否されます。

```json
{
  "schemaVersion": 1,
  "primaryWorkspace": "/repo/main",
  "workspaces": ["/repo/service-a"]
}
```

保存されるのは正規化されたセカンダリパスのみです。トラスト、環境、ワークスペース ID、セッション、ランタイムエラーは、デーモンの起動ごとに再導出されます。

## ライフサイクル

本番デーモンは、プライマリワークスペースの解決と正規化を行った後、小さな登録ファイルを読み取ります。有効な保存済みパスは、明示的な `--workspace` 入力の後にマージされます。明示的な入力が優先されます: 不正な形式または利用できない明示的パスは引き続き起動エラーとなりますが、利用できない保存済みパスは警告付きでスキップされ、後日の再起動のためにディスク上に保持されます。

復元されたパスは、`WorkspaceRegistry` と Express/ACP サーフェスがアセンブルされる前に、通常のセカンダリランタイム構築ループに入ります。これにより、機能、ワークスペース修飾の ACP マウント、ステータス集約、デフォルトの合計セッション上限が、復元されたランタイムセットと一貫したままになります。

アプリのアセンブリ後のプロセスローカルな追加については、レジストリが存在する限りワークスペース修飾の ACP ルートはマウントされたままとなり、初回使用時に信頼されたセカンダリマウントを遅延して作成します。これにより、単一ワークスペースの起動スナップショットが原因で、後日の Web Shell 登録が再起動まで使用できなくなることを回避します。

`POST /workspaces` は `persist: true` を受け付けます。永続化リクエストが成功しても、登録ファイルの更新が正常に完了するまでは応答しません。すでにアクティブなワークスペースに対する永続化リクエストの繰り返しは、その保存済み登録を昇格または確認するもので、べき等に成功します。`persist` を省略する既存の呼び出し元は、現在のプロセスローカルな動作を維持します。

`GET /workspace-registrations` は管理用に保存された望ましいセットを公開します。`DELETE /workspace-registrations/:id` は保存済み登録を消去します。アクティブなランタイムは再起動までライブのままです。プライマリワークスペースは、このサーフェス経由で保存も消去もできません。

## 安全性と失敗時の動作

- ストアはセカンダリパス 24 件までに制限され、各パスはデーモンのワークスペースパス長制限を超えません。
- 読み取りは、シンボリックリンク、通常ファイル以外のファイル、サイズ超過ファイル、不正な形式の JSON、未知のスキーマバージョン、プライマリキャッシュの不一致を拒否します。
- 書き込みは、プロセス内ミューテックス、クロスプロセスロック、およびモード `0600` でシンボリックリンクをたどらない共用のアトミックファイル書き込みヘルパーを使用します。
- 破損したストアは、変更系パスによって空として扱われることがないため、後日の追加が復旧可能なデータを上書きすることを防ぎます。
- 永続化されたトラストは意図的に存在せず、復元されたワークスペースは現在の信頼済みフォルダー計算を通過します。
- 保存済みエントリのうち、欠落、アクセス不能、ネスト、またはアクティブ上限超過のものは、望ましいエントリを削除せずにスキップされます。重複エントリはストアを無効にし、暗黙に書き換えられることはありません。

## 互換性

追加的な `persistent_workspace_registration` ケーパビリティが新しい契約を通知します。SDK のリクエストオプションと `persisted` レスポンスフィールドは追加的です。`runQwenServe` が自動的な起動時復元を担当します。直接の `createServeApp` 埋め込みは、登録ストアが明示的に指定された場合のみ永続化管理ルートを獲得し、アプリ作成前に注入されたワークスペースレジストリを復元する責任は引き続き負います。

## フォローアップの境界

ホット取り外しは引き続き別扱いです: 登録の消去は次回の再起動に影響しますが、セッションを終了させたり、アクティブなワークスペースブリッジを破棄することはありません。
