# バックグラウンドエージェントの roster 復元

## コンテキスト

バックグラウンドエージェントのサイドカーと JSONL トランスクリプトは、論理的な identity と履歴を永続化し、`BackgroundTaskRegistry` は現在のセッションのアドレス可能なタスクのインデックスを作成します。レジュームローダーは現在、`running` 状態のままのサイドカーのみを復元します。そのため、完了したエージェントは、そのトランスクリプトが利用可能なままであっても、親セッションの復元後にレジストリから消えます。また、モデルにはレジストリを問い合わせるツールもありません。

## ゴール

- 最近の完了したバックグラウンドエージェントを、元のタスク ID とともに復元する。
- オンデマンドの発見のために、モデルが呼び出せる `list_agents` ツールを追加する。
- `send_message(task_id)` を継続操作として保持する。
- 復元後、モデルに一度だけ短いワンショットのリマインダーを与える。
- 同じ復元動作を TUI、ヘッドレス、ACP のエントリポイントに適用する。

## ノンゴール

- ライブの JavaScript ランタイムをプロセスの破棄をまたいで永続化すること。
- Agent Teams の `task_list` ツールを置き換えること。
- 失敗またはキャンセルされたエージェントを復元すること。
- 一時的なワークツリー分離を再構築すること。

## 設計

セッションディレクトリのスキャンは、`running` と `completed` の両方のサイドカーを受け入れます。running のエントリは paused になり、既存の中断された作業の動作を保持します。completed のエントリは completed のままで、通知済みとマークされ、`send_message` の蘇生に必要なトランスクリプトとメタデータのパスを保持します。

新しいサイドカーは、元の起動がバックグラウンドであったかどうかを永続化します。completed のエントリは、このマーカーが明示的に true の場合のみ復元されるため、フォアグラウンドおよびマーカーのないレガシーな completed サイドカーは、再利用可能なバックグラウンドエージェントとして公開されません。レガシーな running サイドカーは既存の復旧動作を保持します。

ローダーは、登録前にサイドカーのファイル名と親セッションのオーナーを検証します。トランスクリプトの欠落、トランスクリプト identity の不一致、互換性のない分離、競合する作業ディレクトリを持つ保持された行は、見えるままですが継続不能とマークされます。ワークツリー分離の行は、その一時的な所有コンテキストを安全に再構築できないため、同じように扱われます。保持された最新の completed エントリのみが復元されます。running のエントリはその上限の対象外です。

`list_agents` はライブのレジストリを読み取り、安定した `task_id`、説明、タイプ、ステータス、継続の可能性、ブロック理由を持つバックグラウンドエージェントを返します。ディスクをスキャンしません。このツールは呼び出し元所有であり、サブエージェントと teammate から除外されます。

復元後、次の通常のトップレベルユーザープロンプトは、`list_agents` を、そして `send_message` を呼び出す単一のシステムリマインダーを受け取ります。スラッシュコマンドと中断されたターンの継続は、このリマインダーを消費しません。Bare モードはこれを受け取りません。

セッションの切り替えは、新しい roster を読み込む前にインメモリのレジストリをクリアします。失敗したレジュームのロールバックは、古いセッションを復元する前に部分的に復元されたエントリをクリアし、バックグラウンド作業がまだアクティブな間はブランチがブロックされます。

## 検証

- running と completed のサイドカーが、安定した ID と正しい状態で復元される。
- フォアグラウンドおよびオーナー違いのサイドカーは除外される。
- 安全でない保持状態は見えるが、継続できない。
- 復元された completed エントリは重複した完了通知を発行しない。
- `send_message` は互換性のある復元済み completed エントリを蘇生できる。
- TUI、ヘッドレス、ACP が roster を復元し、リマインダーを一度だけ届ける。
- 新規、クリア、ブランチ、失敗したレジュームのパスは、以前の roster をリークしない。
