# マルチワークスペースのセッション organization 変更操作

## Summary

`PATCH /workspaces/:workspace/session/:id/organization` を、ワークスペース
修飾のセッション organization 変更操作として追加する。

このルートは、選択されたワークスペースが所有するセッション
organization ストアにピン、グループ、色の変更を適用する。
capabilities、リクエストまたはレスポンスのスキーマ、ACP、UI の挙動を
変更せずに、既存の複数形 REST サーフェスを拡張する。

## Problem

ワークスペース修飾のセッション読み取りは、すでに選択された
ワークスペースをターゲットにしている。
`GET /workspaces/:workspace/sessions` は、信頼された非プライマリ
ランタイムから永続化、アーカイブ、ライブのセッションを返し、
そのランタイムの organization ストアに対して organization ビューと
グループフィルターを適用できる。

現在唯一の organization 変更操作は
`PATCH /session/:id/organization` である。そのレガシールートは
プライマリワークスペース専用である。そのため、クライアントは
セカンダリワークスペースの organization 状態を読み取れるが、
対応するワークスペース修飾 REST サーフェスを通じて
それを更新することはできない。

## Decision

`PATCH /workspaces/:workspace/session/:id/organization` を、
他のワークスペース修飾セッションストレージルートの隣に登録する。

`:workspace` セレクターは既存の複数形ルートとまったく同じように
解決される：

1. 正確な登録済みワークスペース id にマッチする。
2. それ以外の場合は、絶対 cwd セレクターをデコードして正規化する。
3. どちらも解決できない場合は、既存の未知ワークスペースエラーを返す。

選択されたランタイムがその操作の完全なスコープである。セッションの
ルックアップ、グループの検証、organization の変更、永続化はすべて、
そのランタイムのワークスペース cwd とストアを使用する。ハンドラーは
プライマリランタイムへのフォールバックも、別の登録済みワークスペースの
検索も行わない。

## Data flow

1. リクエストはデーモンの通常のホスト、ベアラー、JSON ミドルウェアを
   通過する。
2. 複数形ルートは `:workspace` を 1 つの登録済みランタイムに解決する。
3. 複数形変更操作の信頼ゲートは、そのランタイムが信頼されていることを
   要求する。
4. ターゲットランタイムは、アクティブな永続化ストア、アーカイブされた
   永続化ストア、またはライブブリッジの中で `:id` をチェックする。
5. リクエストボディは既存の organization リクエスト検証を通過する。
6. `groupId` が存在し、null でない場合、ターゲットランタイムの
   グループストアがそのグループを検証する。
7. ターゲットランタイムの organization ストアが、既存のセマンティクスで
   `isPinned`、`groupId`、`color` を適用する。
8. ルートはレガシーの変更操作と同じ organization レスポンスを返す。

永続化されたアクティブセッション、永続化されたアーカイブセッション、
対応するライブのみのセッションが有効なターゲットである。
organization は引き続き sidecar 状態である：この変更操作は
トランスクリプト JSONL の書き換えも、トランスクリプトの変更時刻の
変更も行わない。

## Trust and error order

複数形ルートの慣例が観測可能な順序を決定する：

1. 未知のワークスペースセレクターは、既存の
   `400 { code: "workspace_mismatch" }` レスポンスを返す。
2. 既知だが信頼されていないワークスペースは、セッションやグループの
   存在が開示される前に `403 { code: "untrusted_workspace" }` を返す。
3. 選択されたランタイムのアクティブ、アーカイブ、ライブのセットの
   いずれにも存在しないセッションは、既存のセッション未検出
   `404` を返す。
4. 無効な organization 更新フィールドは、信頼されたターゲットセッションが
   見つかった後で、既存の organization 検証エラーを返す。
5. 選択されたランタイムのグループストアに存在しない null でない
   グループ id は `404 { code: "group_not_found" }` を返す。
6. 読み取り不能な organization sidecar は
   `500 { code: "session_organization_store_unreadable" }` を返す。

アーカイブと削除の競合は、既存のアーカイブコーディネーターエラーを
維持する。

どのエラーステージにもワークスペース間のフォールバックはない。
プライマリワークスペースにのみ存在するセッションやグループは、
セカンダリワークスペースが選択された場合は未知のままとなり、
その逆も同様である。

## Legacy compatibility

`PATCH /session/:id/organization` は、変更ゲート、検証、ルックアップ、
永続化、エラー形状、レスポンススキーマを含め、現在のプライマリ専用の
挙動を維持する。したがって、既存のクライアントは同じルーティングと
重複 id の挙動を維持する。

クライアントは、`session_organization` と
`workspace_qualified_rest_core` の両方が広告された後でのみ、
複数形の変更操作を使用する。新しいケイパビリティタグは導入されない。

## ACP behavior

ACP のディスパッチは変更されない。修飾されたディスパッチャーは
すでに `rt.bridge` と `rt.workspaceCwd` で動作しているため、
ワークスペース修飾の ACP セッションアクションはすでに
選択されたランタイムにバインドされている。この変更は、
複数形サーフェスから欠落していた REST の organization 変更操作に
限定される。

## Concurrency and store locks

`SessionOrganizationService` は、既存の sidecar ごとのロックを使用して、
同じ sidecar に対するグループとセッション organization の
read-modify-write 操作を直列化するのみである。既存のアーカイブ
コーディネーターは、organization の更新をアーカイブおよび削除の
遷移と調整する。このルートはデーモン全体のロックも、新しい
サービス間トランザクションやアトミック性の保証も追加しない。

## Testing and acceptance

自動化テストと実際の E2E アクセプタンス戦略を合わせて、
以下をカバーする：

- ワークスペース id と URL エンコードされた正規 cwd セレクターが
  同じランタイムに到達する。
- 信頼されたセカンダリワークスペースは、アクティブな永続化、
  アーカイブされた永続化、ライブのみのセッションの organization を
  変更できる。
- ピン留め、グループ化、グループ解除、サポートされる色または `null` の
  更新が、既存のレスポンス形状を返す。
- organization されたリストとピン/グループフィルターが
  変更操作を反映する。
- 永続化されたセッションについて、organization 状態が
  デーモンの再起動後も残る。
- セカンダリの変更操作は、プライマリワークスペースの organization 状態を
  変更しない。
- レガシールートはプライマリのみのままで、セカンダリワークスペースにのみ
  存在するセッションには `404` を返す。
- 既知の信頼されていないワークスペースは、セッションやグループの
  ルックアップの前に `403` を返す。
- 未知のセレクター、ターゲットスコープで未知のセッション、
  ターゲットスコープで未知のグループは、ワークスペース間の
  フォールバックなしに、既存のエラーを返す。

アクセプタンスにはさらに、ビルド、型チェック、フォーカスされた
ルートと SDK のテスト、および 2 つの信頼されたワークスペースと
信頼・セレクターのネガティブケースをカバーする E2E パスが含まれる。

## Explicit non-goals

この変更は、ケイパビリティタグやケイパビリティペイロードの変更、
リクエストまたはレスポンスのスキーマ変更、ACP の挙動変更、UI の変更を
導入しない。レガシールートをマルチワークスペース対応にすることも、
ワークスペース間のセッション発見を追加することも、アーカイブ、リスト、
グループ、トランスクリプトのセマンティクスを変更することもない。
