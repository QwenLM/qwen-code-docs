# デーモンチャネルのランタイム制御

## Summary

デーモン管理のチャネルワーカーに対するランタイムの desired-state 制御を追加する。
デーモンは `--channel` なしで起動でき、その後デーモンを再起動せずに
チャネル選択の有効化、置き換え、検査、リロード、停止を行える。ランタイムの変更は
永続化されない。次回のデーモン起動は引き続き `--channel` に従う。

制御層はワークスペースグループ化されたワーカー実装の上に位置する。
これはコミットされた選択を所有し、ライフサイクルの変更を直列化し、
serve 所有のチャネルサービスリースを保持し、順序付き選択が
変更されたワークスペースグループのみを reconciliation する。

## Public contract

`GET /workspace/channel` は、コミットされた選択、任意の保留中の選択、
現在の遷移、ワークスペースの注釈付きワーカースナップショットを返す。

`PUT /workspace/channel` は以下を受け付ける：

```json
{ "selection": { "mode": "names", "names": ["telegram", "feishu"] } }
```

または `{ "selection": { "mode": "all" } }`。名前付き選択はトリムされ、
ソートせずに重複排除される。空の選択は無効である。`all` は
マルチワークスペースモードでは引き続きプライマリワークスペース専用である。

`DELETE /workspace/channel` はランタイム選択を冪等に無効化する。
`POST /workspace/channel/reload` は引き続き利用可能であり、
コミットされた選択に対して設定を再読み込みする。変更操作には
厳格なベアラートークンゲートを使用する。

`channel_control` ケイパビリティがこのリソースを広告する。`channel_reload` は、
マネージャーがコミットされたリロード可能な選択を持っている間のみ
広告を続ける。

## Lifecycle

マネージャーは不変スナップショットを公開し、すべての変更を 1 つの
FIFO レーンを通して送る。選択の更新は、ワーカーを停止する前に
ワークスペースの所有権と信頼をプリフライトする。変更されていない
ワークスペースエントリは保持される。変更・削除されたエントリは、
デーモンがグローバルなチャネルサービスリースを保持したまま、
置き換えの開始前に停止する。

置き換えが失敗した場合、マネージャーは新たに開始されたエントリの停止と
以前のエントリの再起動を試みる。クリーンアップや復元も失敗しうるため、
クライアントは `rolledBack`、`rollbackError`、`state` を検査する。
SIGKILL 後に子の終了を観測できない場合はハードな停止失敗である：
スーパーバイザーは子の参照を保持し、マネージャーはサービスリースを保持し、
置き換えは起動されない。

ワーカーのコールバックは世代を伴う。置き換えられたエントリからの
コールバックはログに残る場合があるが、現在の pidfile や
ルーティング状態を更新することはできない。コミットが成功すると、
選択、webhook 設定、ワーカーマップがまとめて切り替えられ、
その後完全な pidfile スナップショットが書き込まれる。

アダプターの部分接続は既存の挙動を維持する：少なくとも 1 つの要求された
チャネルが接続すると、ワーカーは ready となる。制御結果は `partial` を報告し、
デーモンステータスは引き続き `channel_worker_partial_connect` を出力する。

## Compatibility

起動時の `--channel` は同じマネージャーを使用しつつ、listen 前の
リース予約と成功前の ready 挙動を維持する。`--channel` なしの場合、
デーモンは最初のランタイム変更までチャネルサービスの予約や
重いチャネルランタイムの読み込みを行わない。

レガシーの `runtime.channelWorker`、グループ化された `runtime.channelWorkers`、
pidfile フィールド、スタンドアロンの `qwen channel start`、`qwen channel reload` は
引き続き互換性がある。新しい CLI 制御は `qwen channel set` を通して公開され、
さらにチャネル停止とステータスのリモートバリアントが追加される。
