# Goal ループの入力制御

## Problem

アクティブな `/goal` はブロッキングな Stop フックとして実装されている。モデルの実行中、インタラクティブキューは通常、ストリームがアイドルになるまでスラッシュコマンドを延期する。goal ループはそのアイドル境界に到達しない可能性があるため、`/goal clear` や置き換えの `/goal` コマンドを反映できない。

Stop レスポンスは、goal フックを無関係な設定フックと集約する場合もある。goal のクリアは、別のフックが所有するブロッキング決定を破棄してはならない。

## Design

アクティブなターン中、メッセージキューはプレーンテキストの steering メッセージと一緒に `/goal` コマンドを drain する。その他のスラッシュコマンドは、通常のアイドル処理のためにキューに残る。

CLI は drain された goal コマンドを既存のスラッシュコマンドプロセッサ経由で実行する:

- clear コマンドは、モデル入力を生成せずに副作用を適用する。
- 置き換えコマンドは、保留中の goal 指示を置き換える。
- 複数の goal コマンドが一緒に drain された場合、最終的にアクティブな goal の指示のみが送信される。
- 生き残った指示は、プレーンテキストの steering メッセージに対する位置を保持する。
- 実行された goal コマンドは、後続の steering 準備がキャンセルされても復元されない。未実行のプレーンテキストメッセージは復元される。

Core は Stop フックの前と、ブロッキングな Stop フックが返った後に再度キューをサンプリングする。ブロッキングな goal 出力はその goal フック ID を運び、continuation 理由を通常のフック理由と分離して保持する。フックブリッジは、別の Stop 出力がブロック中かどうかも報告する。2 回目の境界で goal が変更された場合、core は古い goal の continuation のみを削除し、独立したブロッキング理由には引き続き従う。ノンブロッキングなフック出力は、追加の goal イテレーションを強制しない。

## Verification

- キューのテストは、アクティブターン中の goal drain とアイドル境界での延期をカバーする。
- CLI ストリームのテストは、clear、置き換え、バッチコマンド、順序、復元の挙動をカバーする。
- Core のテストは、Stop フック評価中の clear と置き換えをカバーし、集約された独立ブロッカーの場合も含む。
- ローカルの tmux セッションで、ビルド済みのインタラクティブ CLI に対して clear と置き換えを実施する。
