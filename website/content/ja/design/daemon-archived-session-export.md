# ワークスペース修飾付きアーカイブセッションエクスポート

## Summary

デーモンは、選択された登録済みワークスペースからアクティブな永続化セッションを
エクスポートできるが、アーカイブされたトランスクリプトは、アクティブストレージに
戻されるまでアクセスできないままである。この変更は、アクティブなエクスポートの挙動や
アーカイブの状態機械を変更せずに、読み取り専用のアーカイブエクスポートを追加する。

プロトコルには
`GET /workspaces/:workspace/session/:id/archive/export?format=html|md|json|jsonl`、
無条件の `workspace_archived_session_export` ケイパビリティ、および
`WorkspaceDaemonClient.exportArchivedSession` が追加される。このルートとケイパビリティは
アクティブなエクスポートとは別物であり、古いデーモンがアーカイブの意図を無視して
同じ id のアクティブなトランスクリプトを返すことはない。

## Contract

セレクターはまず正確な登録済みワークスペース id として解決され、次に
URL エンコードされた正規の絶対 cwd として解決される。選択されたランタイムは
信頼されていなければならない。セレクターと信頼のチェックは、セッションや
フォーマットの検証に先立つ。

対象となるのは選択されたワークスペースの `chats/archive/<id>.jsonl` のみである。
このルートはアクティブストレージや別のワークスペースをスキャンせず、プライマリへの
フォールバック、ライブの所有者の解決、ブリッジの呼び出し、ACP の開始、クライアントの
アタッチ、設定の読み込みも行わない。アクティブのみのセッションは `409 session_not_archived` を返し、
存在しないセッションは `404 session_not_found` を返し、アクティブとアーカイブのファイルが
同時に存在する場合は `409 session_conflict` を返し、遷移中は `409 session_archiving` を返す。

## Reuse and Concurrency

`SessionService.loadArchivedSession` が唯一の新しいコアのコンシューマサーフェスである。
これはアーカイブパスを読み取りつつ、`loadSession` と同じ私的な再構築ロジックに
委譲する。既存の load/resume の呼び出し元はアクティブ専用のままである。
デーモンは既存のエクスポートコレクター、フォーマッター、レスポンスヘッダー、
SDK 添付ファイルパーサーを再利用するため、アーカイブとアクティブのエクスポートは
同一のフォーマット挙動を持つ。再構築の前に、アーカイブ専用のローダーが既存の
256 MiB トランスクリプトインデックス作成制限を強制し、超過時には
`413 transcript_too_large` を返す。アクティブなエクスポートは出荷時の上限なしの
契約を維持する。

エクスポートは、場所のチェック、トランスクリプトの再構築、フォーマット操作の
全体にわたり、既存の共有 `SessionArchiveCoordinator` リースを保持する。
アーカイブ、アーカイブ解除、削除は排他リースを保持するため、遷移は
エクスポートより前に開始してそれを拒否するか、共有リースの解放後に開始するかの
いずれかである。コーディネーターは引き続きワークスペース間でセッション id をキーに
保守的に管理される。

## Compatibility and Verification

アクティブなワークスペースのエクスポートルート、`workspace_session_export` ケイパビリティ、
レガシーのプライマリエクスポート、アーカイブの変更操作、永続化レイアウトは変更されない。
新しいメソッドが古いデーモンを対象とした場合、直接の SDK 呼び出し元は
通常の HTTP エラーを受け取る。

テストは、ケイパビリティの広告、id と cwd のセレクター、すべてのフォーマット、
添付ファイルのメタデータ、アクティブ／欠落／競合／遷移の状態、信頼の優先順位、
同じ id のワークスペース間分離、ブリッジ活動の不在、両方向のロック、
コアのアーカイブ再構築、テレメトリの帰属、ネイティブ REST SDK トランスポートを
カバーする。サイズテストは正確なアーカイブ上限を受け入れ、トランスクリプトの
実体化の前にそれを 1 バイト上回るスパースファイルを拒否する。
