# pinned managed memory の保護

## 問題

managed の自動メモリは、既存のインデックス上限に従いつつ、プロジェクトおよびユーザーの
メモリルート配下で有効な markdown トピックを再帰的に探索する。自動抽出エージェントと
Dream 統合エージェントは許可されたメモリルート内のパスに書き込みや編集ができるため、
手作業で管理されたファイルが、自動生成されたメモリと同じように上書きまたは統合されうる。

再帰スキャナーはすでに `pinned/` 配下の有効なファイルを探索している; 欠けている挙動は、
自動メモリメンテナンス中の決定的な変更保護である。

## 選択した設計

managed memory ルート内のトップレベル `pinned/` ディレクトリを、自動抽出による変更から
保護し、Dream 統合から除外するものとして扱う:

- 有効な pinned ドキュメントは、通常のメモリ recall から読み取り可能のままにし、既存の
  インデクサーが通常の上限内で発見可能にする。
- リクエストされたパスが語彙的に `pinned/` 配下にある場合、自動抽出および fork された
  Dream の `write_file` と `edit` 操作を拒否する。
- 予約されたトップレベルディレクトリ名は大文字小文字を区別せずにマッチさせ、
  大文字小文字を区別しないファイルシステムで deny-list が fail open（失敗時は許可）に
  ならないようにする。
- symlink 経由で `pinned/` 内に解決されるエイリアスも拒否する。
- 既存の読み取り専用シェルゲートを保持する（すでに `rm` とその他のすべての変更系
  シェルコマンドを拒否している）。
- 自動抽出と Dream のプロンプトに、pinned ドキュメントを変更せず、通常のインデックス上限の
  範囲内で既存のインデックスエントリを意図的に削除しないことを学習させる。

パスチェックはリテラルパスと解決済みパスの両方を大文字小文字を区別せずに比較する。
リテラルの包含は、そのディレクトリ自体が symlink である場合でも `pinned/` を保護する。
解決済みの包含は、メモリ内の別の場所にある書き込み可能に見えるパスが symlink で
`pinned/` 内に戻ることを防ぐ。

保護は既存のメモリスコープエージェント設定の明示的なオプションであり、自動抽出および
fork された Dream のプランナーが有効にする。これによりセッション後の抽出、スケジュール
Dream、およびワークスペースメモリ Dream エンドポイントの呼び出し元をカバーする。
明示的な remember 操作は現在の挙動を保持する。

## スコープの境界

- スキャナーやインデクサーのプロダクション変更はなし: 再帰探索はすでに既存の
  frontmatter スキーマでプロジェクトとユーザーの `pinned/` ドキュメントを処理している。
- 新しい frontmatter フィールドの追加も、ディレクトリの自動作成もしない。
- `/memory` UI のインジケーターは追加しない。
- 明示的な `/forget` リクエストは現在の挙動を保持する。
- このパスベースの境界は、pinned ファイルへの既存のハードリンクエイリアスを検出しない。
  自動メモリワーカーは `write_file` や `edit` でそれらを作成できず、読み取り専用シェル
  ポリシーが `ln` をブロックする; より強い脅威モデルには inode ベースの別ポリシーが必要。
- 可視の `/dream` スラッシュコマンドのターンは共有のスキッププロンプトルールを受け取るが、
  この変更では決定的なツールゲートは得ない。スラッシュコマンドはメインの Agent で実行され、
  そこには既存のターンごとのパーミッションオーバーライドがない; それを追加するのは
  別のクロスサーフェスのパーミッション設計になる。
- fork された Dream は引き続きプロジェクトメモリ専用である（既存のスコープ設定が
  グローバルのユーザーメモリルートを除外しているため）。
- 自動抽出は引き続きプロジェクトとグローバルユーザーメモリの両ルートをカバーするため、
  両方のトップレベル `pinned/` ディレクトリが同じ保護を受ける。

## 未解決の論点

可視の `/dream` スラッシュコマンドが同じ決定的なゲートを受ける必要があるかは、
メンテナのスコープ判断のまま。必要な場合は、1 つの非同期ツールループのために
セッション全体のパーミッションマネージャーを変更するのではなく、一般的なターンごとの
パーミッションオーバーライドとして実装すべきである。
