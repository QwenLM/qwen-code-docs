# デーモンのワークスペース信頼ホットリロード

## ステータス

QwenLM/qwen-code#6378 向けに実装済み。

## 問題

デーモンは現在、`WorkspaceRuntime` の構築中にワークスペースの信頼を評価します。`GET /workspace/trust` はそのスナップショットを報告し、`POST /workspace/trust/request` は `trust_change_requested` を公開するだけです。`trustedFolders.json`、IDE の信頼、またはユーザー/システムのフォルダー信頼設定を変更してもランタイムは再構築されないため、デーモンが再起動されるまで、設定、環境、ファイルシステム、ACP セッション、MCP、拡張機能、チャネルワーカー、スケジュールされた作業はすべて古い信頼境界のままになります。

信頼はその場で更新できません。ファイルシステムファクトリー、ブリッジ、設定、環境、ACP マウント、およびいくつかのワークスペーススコープのマネージャーは、構築時にランタイムの入力を取り込みます。

## セキュリティ不変条件

1. 信頼の降格は、最初の非同期 drain ステップの前に、影響を受けるランタイム世代ガードをクローズします。その時点以降に新しい特権副作用を開始してはなりません。
2. クローズされた世代ガードが再度オープンされることはありません。後継は新しいガードと単調に増加する世代 ID を受け取ります。
3. 取り消し（revoke）の失敗は、以前の信頼済みランタイムを復元しません。
4. 不正な形式または読み取り不能なシステム/ユーザー設定は fail closed（失敗時は拒否）となります。不正な形式または読み取り不能な trusted-folders ファイルは、ファイル信頼が必要な場合には fail closed となりますが、フォルダー信頼が無効になっている場合や、IDE 信頼がすでにプライマリワークスペースを解決している場合は無関係です。
5. 遷移中、ブロック中、および stale なセッションオーナーは、プライマリランタイムにフォールバックしません。
6. すべてのランタイムアクティベーションパスは、公開の直前にポリシーリビジョンを検証します。

## 信頼ポリシー

デーモンは、システムオーバーライド、ユーザー設定、システムデフォルト、IDE 信頼、`trustedFolders.json` のみを読み取る、副作用のないポリシーローダーを使用します。ワークスペース設定とプロジェクト環境ファイルはポリシー評価から除外されます。既存の信頼ルールの優先順位とパス比較の動作は保持されます。

ローダーは不変のセマンティクスナップショットを生成します。ワークスペースはそのスナップショットを、運用上の信頼 boolean と許可ルートリストに具体化します。具体化の変更のみがランタイムを再構築します。ソースのみの変更は、再構築なしに適用済みポリシーリビジョンを進めます。

プライマリファイルシステムは、既存の信頼済み IDE マルチルートの動作を維持します。セカンダリルートがプライマリの許可ルートリストから削除されると、どちらかが drain される前に、セカンダリとプライマリの両方の世代がクローズされます。

モニターはポリシー入力を 1 秒に 1 回再読み取りし、セマンティックハッシュが変更した場合にのみ公開します。IDE と同一プロセスの trusted-folder 書き込みも、即時の読み取りをトリガーします。`/workspace/reload` と動的なワークスペース登録は、明示的に reconciliation を要求します。

Trusted-folder の書き込みは `proper-lockfile` を獲得し、ロック下で再読み取りし、コメントを保持し、シンボリックリンクをたどらずに通常の 0600 ファイルをアトミックに置き換えます。不正な形式のファイルは暗黙のうちに書き換えられません。

## ランタイムの所有

レジストリは安定した `WorkspaceEntry` オブジェクトを所有します。アクティブなエントリは 1 つの不変な `RuntimeGeneration` を参照し、それがランタイムとその世代ガードを所有します。ワークスペースの identity、永続化登録メタデータ、適用済みポリシー状態は、世代ではなくエントリに保持されます。ランタイムの構築とクリーンアップは、引き続きデーモンホストによって調整されます。

ワークスペース修飾されたデータプレインルートは、リクエスト時にランタイムを解決します。プロセス全体のパスを保持するプライマルートは、現在のランタイムへのライブデリゲートを使用します。特権 REST ミューテーションは世代ガードを取り込み、コミット境界でそれを再チェックします。ACP、Voice、チャネルワーカー、セッション受け入れは、既存の drain メカニズムを使用します。信頼ステータスとデーモンインベントリは、ランタイムを獲得せずに安定したエントリを読み取ります。

セッションオーナーインデックスは世代を認識します。セッションの作成と復元は所有権を明示的に登録し、ランタイムの置き換えは古い所有権を無効にします。既存のアクティブブリッジスキャンは、インデックス導入前のセッションに対する互換性修復パスとして残ります。

ランタイムのクリーンアップは、ブリッジと子チャネル、Voice の状態、サブセッション、ACP マウント、チャネルワーカー、スケジュールされた keepalive、および git の状態をシャットダウンします。後継ランタイムが所有するマネージャーは、新しい設定、環境、ファイルシステム、信頼、ポリシー、キャッシュの入力で再構築されます。共有パスロックとプロセステレメトリーは、ワークスペースのケーパビリティを持たないため、置き換え後も存続します。

## Reconciliation

信頼の reconciliation とランタイム公開は 1 つのデーモントポロジーゲートを共有します。ワークスペースの追加とリロードは、自身の操作の後、そのゲートを介して reconciliation を要求します。信頼スナップショットは統合されるため、呼び出し元が解放される前に、最後に観測されたリビジョンが適用されます。シャットダウンはモニターを停止し、クリーンアップスナップショットを取得する前にトポロジーゲートを待ちます。

信頼の降格の場合、コントローラーは最初の非同期 drain の前に影響を受けるすべての世代を同期的にクローズし、受け入れパスをクローズし、古いランタイムを破棄し、新しいランタイムを構築し、ポリシーリビジョンを再チェックし、新しいエントリ世代と ACP マウントをインストールします。既存のブリッジと ACP のシャットダウンパスが、有限または強制的なクリーンアップを提供します。stale な候補は破棄されて再構築されます。

許可（grant）も同じ破壊的な置き換えを使用します。失敗した場合、コントローラーは新しい非信頼ランタイムを試み、以降の reconciliation が成功するまで、設定されたリビジョンを失敗として報告します。ランタイムの封じ込めが確認できない場合、エントリはブロックされたままで、deep health は degradation 状態になります。他のワークスペースは引き続き利用可能です。

## プロトコル

リクエスト専用のエンドポイントはリクエスト専用のままです。信頼ステータス v1 はデフォルトの互換性ビューのままです。クライアントは `statusVersion=2` で v2 を要求できます。古いサーバーは v1 を返す場合があります。V2 は設定済みポリシーと実効ランタイム状態を分離し、`stable`、`applying`、または `failed`、opaque な revision、および安定したエラーコードを報告します。デーモンは、プライマリとセカンダリのルーティングが世代を認識した解決を使用するようになってから初めて `workspace_trust_hot_reload` を通知します。

信頼性の高い applied-event バスは導入されません。GET status が信頼できる情報源です。信頼変更リクエストは、既存のイベントを公開するためにアクティブな世代を必要とします。そうでない場合は、リトライ可能な 503 を返します。

## ノンゴール

- 直接のリモート信頼承認。
- ゼロダウンタイムのデュアルランタイムやセッションマイグレーション。
- 公開された世代識別子。
- 並列ランタイム再構築。
- Express アプリケーション全体の再構築。
- スタンドアロン CLI の信頼セマンティクスの変更。
