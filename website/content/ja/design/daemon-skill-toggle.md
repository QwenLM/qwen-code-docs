# デーモンのスキルトグル

## Goal

CLI の `/skills` パネルのワークスペース有効化/無効化の挙動を、デーモン REST と
TypeScript SDK を通じて公開する。これにはアクティブな ACP セッションの即時リ
フレッシュも含まれる。

## Public contract

- `POST /workspace/skills/:name/enable`
- `POST /workspaces/:workspace/skills/:name/enable`
- リクエスト本文: `{ "enabled": boolean }`
- SDK: `DaemonClient.setWorkspaceSkillEnabled` および
  `WorkspaceDaemonClient.setWorkspaceSkillEnabled`
- ケイパビリティ: `workspace_skill_toggle`

レスポンスには、正規のスキル名、要求された状態、永続化が変更されたか、アクティ
ベーション状態、セッションのリフレッシュ件数が含まれる。`applied` はすべての
アクティブセッションがリフレッシュされたことを意味し、`deferred` は実行中の ACP
子プロセスがなかったことを意味し、`partial` は永続化のコミット後に少なくとも
1 つのセッションのリフレッシュが失敗したことを意味する。

## Semantics

この API は、必要に応じてワークスペースの `skills.disabled` と `skills.enabled`
を変更する。スキルの検索は大文字小文字を区別しないが、永続化されるのは正規の
検出された名前である。デフォルトで無効なスキルを有効化すると、明示的なオプトイン
が書き込まれ、無効化するとオプトインが削除されてワークスペースのハードな無効化
が書き込まれる。1 つのターゲットの更新により、ターゲットの重複と大文字小文字の
バリアントは削除されるが、利用不可能なスキルの孤立エントリは削除されない。2 回
目の同一リクエストは何もしない。

このルートは、CLI パネルがトグルできない状態を拒否する:

- 不明なスキル: `404 skill_not_found`;
- `userInvocable === false`: `409 skill_not_toggleable`;
- 非アクティブな拡張機能由来のスキル: `409 skill_not_toggleable`;
- システムデフォルト、ユーザー、またはシステムスコープで無効化されている場合:
  ロックしているスコープを伴う `409 skill_not_toggleable`;
- 信頼されていないワークスペース: `403 untrusted_workspace`。

スコープロックのチェックとワークスペースのリード・モディファイ・ライトは、
デーモンのワークスペースごとの設定ロック内で行われる。書き込みの失敗は、リ
フレッシュとイベント公開の前に停止する。

## Skill availability versus `disable-model-invocation`

`skills.disabled` は、スコープ間でケースインセンシティブな和集合としてマージ
される、オペレーターによるハードな拒否リストである。`skills.defaultDisabled`
は上書き可能なデフォルトを提供し、`skills.enabled` は明示的なオプトインを提供
する。優先順位は `disabled > enabled > defaultDisabled` である。有効な無効化は、
一致するスキルのスラッシュコマンドとモデルに表示されるスキルエントリを削除し、
実行時の検証がそのスキルを拒否する。デーモンエンドポイントは `disabled` と
`enabled` のワークスペースメンバーを書き込む。

`disable-model-invocation` は SKILL.md のメタデータである。これは直接的な
ユーザー呼び出しを維持したまま、モデルからの呼び出しに対してスキルを隠す。
既存のマネージドスキル ACP 操作はそのメタデータを編集するが、この API は意図的
にそれを再利用しない。

## Activation flow

1. ワークスペースのステータススナップショットから、正規のトグル可能なスキルを
   解決する。
2. ワークスペース設定ロックの下で、すべてのスコープを再読み取りし、上位スコープ
   のロックを拒否し、正規のワークスペースリストをコミットする。
3. デーモンのキャッシュされたスキルステータスを無効化する。
4. ACP 子プロセスがライブであれば、`qwen/control/workspace/skills/refresh` を
   呼び出す。
5. 子プロセスはワークスペーススコープの設定を再読み込みし、ビジーなセッション
   を含め、すべてのアクティブセッションをリフレッシュする。
6. 各セッションは自身のワークスペース設定を再読み込みし、
   `available_commands_update` を再構築してプッシュし、SkillManager のコン
   シューマーに通知する。
7. 変更された各スキル設定キーについて、既存のワークスペース `settings_changed`
   イベントを公開する。

進行中のモデルリクエストを書き換えることはできない。後続のスキル実行チェック、
コマンドスナップショット、モデルコンテキストは新しい状態を読み取る。

## Downstream consumers

- 設定マージ: システムデフォルト、ユーザー、ワークスペース、システムのリストが、
  `disabled > enabled > defaultDisabled` の優先順位で有効な無効名の集合を構成
  する。
- ワークスペースステータス: ACP とデーモンローカルのスキルマッピングは、無効
  状態、無効化の理由、ロックスコープ、false のみの `userInvocable` を公開する。
- スラッシュコマンド: 利用可能なコマンドの構築は無効化されたスキルを削除し、
  更新されたコマンドメタデータをデーモンクライアントに送信する。
- モデルコンテキスト: SkillManager の変更リスナーが Skill ツールの説明と利用
  可能なスキルのコンテキストをリフレッシュする。
- 実行時の検証: Skill ツールは呼び出し前に無効名のプロバイダーを再読み取り
  するため、後続の呼び出しは即座に拒否される。
- 拡張機能の状態: 非アクティブな拡張機能のスキルは、設定で無効化されていなくて
  もトグル不可能なままである。
- デーモンキャッシュ: キャッシュされたライブ子プロセスのスキルスナップショット
  は永続化後に無効化されるため、後続の GET リクエストが古い状態をリプレイする
  ことはない。
- SDK コンシューマー: プライマリワークスペースとワークスペース修飾の両方の
  クライアントが、レスポンスとエラーの契約を共有する。
- イベント: 既存の `settings_changed` コンシューマーは、コミットされた各
  `skills.disabled` または `skills.enabled` の値を観測する。新しいイベント種別
  は存在しない。

## Failure behavior

- 永続化の失敗: HTTP リクエストは失敗し、ACP リフレッシュもイベントも行われない。
- 子プロセスなし: 永続化は `deferred` で成功し、次の子プロセスが起動時にその
  設定を読み込む。
- セッションごとのリフレッシュ失敗: 永続化はコミットされたままで、成功した
  セッションはリフレッシュされたままとなり、レスポンスは `partial` になる。
- 子プロセスのトランスポート競合: liveness チェックの後に子プロセスが消えた
  場合、レスポンスは `deferred` になり、その他のリフレッシュ失敗は `partial`
  として報告される。
