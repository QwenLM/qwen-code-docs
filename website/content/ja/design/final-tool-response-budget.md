# 最終ツールレスポンスのバジェット

## Problem

ツールの出力は、現在、複数の独立したレイヤーで短縮されている。シェル出力は
約 30K 文字付近で短縮されて切り詰め済みとマークされ、汎用ツール出力は約 2K 文字
付近で短縮され、コアのスケジューラーのバッチは、合計が設定されたバッチバジェット
を超えた場合に出力をオフロードする場合がある。これらのレイヤーは構造化された
状態を共有していない。

スケジューラーは、既存の切り詰めマーカーを、それ以上の作業が不要であることの
証拠として扱う。その結果、個別に短縮された複数のシェル結果が、合計バジェットを
超える場合がある。ヘッドレスモードは、ツール呼び出しごとに 1 つのスケジューラー
を作成し、それらのスケジューラーの外側でレスポンスを連結するため、このギャップ
を大きくする。インタラクティブモードも同様に、スケジューラーの最終化の後で、
重複した応答や合成された応答を追加する。ACP、エージェント、投機的実行には、
それぞれ独自の集約境界がある。

モデルリクエスト、再開可能なトランスクリプト、ツール結果の記録は、同じ上限付き
のレスポンスを含まなければならない。リッチなユーザー向けツール表示は意図的に
対象外であり、引き続き既存の結果表示を使用できる。

## Invariants

1. すべてのツールレスポンスのバッチは、モデルに送信される前に、最後の集約境界
   で最終化される。
2. そのバッチ内のシリアライズされたツール出力テキストは、バジェットが有限かつ
   正である場合、設定された合計文字バジェットを超えない。`enter_plan_mode` の
   ライフサイクルリマインダーはポリシー入力であり、ツール出力ではないため、
   このバジェットの外側でインラインのままとなる。
3. プロデューサーがすでに出力アーティファクトを永続化している場合、後続の
   レイヤーは、同じプロデューサー出力を再度書き込む代わりに、それらのパスを
   再利用する。
4. 合計の最終化は、構造化された内部メタデータを使用して、永続化されたアーティ
   ファクトを再利用できるかどうかを決定する。その決定を人間が読めるテキスト
   から推論することは決してない。プロデューサーローカルなセンチネルの処理は、
   既存の切り詰め機構の互換性の詳細として残る。
5. 最終化はレスポンスの順序と非テキスト部分を保持する。短縮できるのは、
   ツールレスポンスのバッチに属する `functionResponse.response.output`、
   `functionResponse.response.error`、トップレベルのテキスト部分のみである。
6. 最終化された部分は、リプレイと再開のために記録される部分でもある。
7. ツール表示はモデルレスポンスから独立したままである。

## Design

### Persistence metadata

`ToolResult` と `ToolCallResponseInfo` は、内部の任意フィールド
`persistedOutputFiles` を持つ。

- `undefined`: プロデューサーによる永続化の決定は行われていない。
- `[]`: 決定は行われたが、再利用可能なファイルはない。
- 空でない配列: プロデューサーが永続化した出力アーティファクトがそれらのパス
  で利用可能である。

このフィールドは、フックのシリアライズ、ACP ペイロード、JSON 出力、テレメトリ
属性、永続化された UI メタデータには含まれない。フックによって再構築された
レスポンスは、ランタイムによって明示的にコピーされない限り、メタデータを引き
継がない。

### Producer-level preview

プロデューサーの切り詰めは、通常のモデルプレビューを制御し、完全な出力を 1 回
だけ永続化する。

- シェルは現在の 30K のトリガーを維持するが、終了情報が表示されたままになる
  よう、約 4K の先頭と末尾のプレビューを返す。
- MCP は現在の大きな出力のトリガーを維持し、ユーザー向けの表示には変換後の完全
  な結果を保持し、約 2K のモデルプレビューを使用する。
- 汎用の永続化は、プライマリとフォールバックのライターの両方で、実際に書き込
  まれたパスを返す。

これらのプレビューは合計の強制ではない。すでに短縮されたレスポンスが、最終化
によって再び短縮される場合がある。

### Shared finalizer

1 つの共有ファイナライザーが、元の順序のレスポンスと設定された合計バジェットを
受け取る。すべての上限付きテキストフィールドを測定し、合計が収まるまでテキ
ストを削減する。既存の永続化済みパスは再利用される。再利用可能なパスがない
レスポンスは、パス参照がその短縮プレビューを置き換えるか添えられる前に、最大
1 回だけ永続化される。

削減は決定論的である。max-min のウォーターフィル配分が、モデル向けのテキスト
フィールド間でバジェットを共有しつつ、小さなフィールドは完全な内容を保持できる
ようにする。削減されたフィールドは小さな先頭と末尾のプレビューを保持し、配分が
許す場合は利用可能な永続化アーティファクトのパスを列挙する。Unicode のサロ
ゲートペアは決して分割されない。最終的なハードキャップのパスは I/O なしで
テキストを短縮するため、永続化の失敗がリクエストサイズの不変条件を破ることは
ない。

ファイナライザーは返された部分から `contentLength` を再計算する。無限または
無効なバジェットは何もしない。

`enter_plan_mode` は唯一のセマンティックな例外である。その成功したファンク
ションレスポンスの出力はアクティブなプランニングポリシーをインストールする
ため、それを切り詰めると、診断出力の短縮ではなく実行ルールの変更になってしまう。
ファイナライザーとラストチャンスの送信ガードは、その出力をツール名で識別して
配分から除外する。失敗テキストと同じバッチ内のすべての通常の出力は、上限付き
のままである。

### Runtime boundaries

- コアのスケジューラーは、`PostToolBatch` フックの前に最終化してフックの入力
  に上限を設け、フックの後にもう一度最終化してフックの出力に上限を設ける。
- インタラクティブモードは、実行可能、重複、合成のレスポンスを元の序数の順序で
  マージし、記録と送信の前に外側の最終化を実行する。
- ヘッドレスモードは、重複、スキップ、キャンセル、実行された呼び出しを含む
  ターン全体を収集し、記録と送信の前に一度だけ最終化する。
- ACP は完全なツール呼び出しターンを収集し、トランスクリプトの記録の前に最終
  化し、次のメッセージに対して同じ部分を返す。即時の ACP 表示イベントは変更
  されない。
- エージェントのランタイムと投機的なフォローアップは、モデル向けの結果の発行や
  履歴の追加の前に、その合計を最終化する。
- チャット送信の境界は、ツールレスポンスのフィールドに対してのみ、I/O なしの
  セーフティキャップを適用する。これは通常は何もしないべきであり、外側の集約
  境界を見逃す将来の呼び出し元を保護する。

## Failure handling

永続化の失敗は既存のログ記録を通じて報告され、最終的な切り詰めを妨げることは
決してない。返されるモデルレスポンスは引き続きバジェットに収まるが、完全な
出力の永続化に成功しなかった場合はファイル参照が省略される場合がある。メディア
部分は手つかずのままとなり、この文字バジェットにはカウントされない。

キャンセルとフック停止のレスポンスは、成功および失敗したツールレスポンスと
まったく同じように最終化される。空の出力とエラーフィールドは有効なままである。
バッチ全体のバジェットより大きな単一のレスポンスは、それ単独で削減される。
複数の大きなレスポンスは、残りのプレビュー容量を決定論的に共有する。

## Compatibility and non-goals

モデル向けの公開ファンクションレスポンススキーマは変更されない。既存の切り詰め
テキストは引き続き読めるが、合計の最終化はそれに依存しなくなる。既存のセッ
ションは引き続きリプレイ可能である。より厳密な不変条件を得るのは、新しく記録
されたツール結果のみである。

この変更は、ワイヤーバイトのハッシュ、正確なトークンの集計、メディアのバジェ
ット管理、ストレージのライフサイクル変更、トランスクリプトのマイグレーション、
新しい一時ファイルのレイアウトを追加しない。それらは独立したフォローアップ
である。
