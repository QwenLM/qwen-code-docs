Qwen Code 本周发布 v0.19.4，80+ 个 PR 合入，覆盖三个方向：

**`/loop` 离开也能跑。** 裸 `/loop` 启动自主模式——agent 在你离开时推进已确立的工作，不发明新活也不做不可逆操作。加上 `.qwen/loop.md` 任务文件，循环重读可编辑的清单，删除后循环发 no-op tick 保持存活。Claude Code 上周刚发了一篇[智能体循环入门指南](https://claude.com/blog/getting-started-with-loops)，讲的是 agent 按既定计划反复执行——`/loop` 的自主模式做的事类似，但多了一层：任务清单可以随时编辑，循环会自动感知变化。

**桌面端语音听写上线。** CLI 和 Web Shell 的语音听写已经有了，但桌面端一直缺。这个版本补齐了最后一个界面，三端体验统一。

**终端交互体验缩小差距。** `/settings` 从扁平列表变成标签式视图，搜索、状态、统计一屏搞定；Virtualized History 模式下菜单、补全、输入框支持鼠标点击和悬停了。

## ✨ 新增特性

### `/loop` 自主模式 + loop.md 任务文件

`/loop` 现在支持两种新模式：

**自主模式**：裸 `/loop`（无 prompt、无间隔）不再打印用法提示，而是启动一个自定步自主循环。agent 会在你离开时推进已确立的工作——维护在建 PR、续半截的活、兑现承诺——但只按 transcript 已确立的来做，不发明新活，未经明确授权不做不可逆动作（push/delete/send），安静了就停。自主 preamble 首发一次，之后每个 tick 只发短提醒，保持 token 成本低。

**loop.md 任务文件**：在项目根目录或 `~/.qwen/` 下创建 `.qwen/loop.md`，把 wakeup/cron 的 prompt 设为 sentinel（`<<loop.md-dynamic>>` 或 `<<loop.md>>`），循环每次 fire 时重读文件。首次投递全文，之后未变则发短提醒，编辑文件后重新全文投递。文件消失时循环发 no-op tick（agent 什么都不做，只 re-arm 保持循环存活），回到自主模式的基础行为。重建 loop.md 后，下一个 tick 自动检测变更，重新全文投递。

**频道循环**：`/loop` 不只限于终端——钉钉、飞书频道也能跑。在群里用 `/loop add "0 9 * * 1-5" 检查 CI 状态` 创建定时循环，`/loop list` 查看当前频道的所有循环，`/loop inspect <id>` 看运行次数和最近结果，`/loop cancel <id>` 停掉。循环通过 channel session router 执行，等当前活跃 turn 结束后再启动，结果经频道主动发送回写。一次性循环成功或失败后自动禁用。

你能用它做什么：

- 裸 `/loop` 让 agent 在你离开时盯着推进工作
- 用 `.qwen/loop.md` 维护一份持久、可编辑的任务清单，不用每个 tick 重述
- 删除 loop.md 后循环发 no-op tick 保持存活，重建后无缝接回
- 在钉钉/飞书群里用 `/loop add` 设定时循环，让 agent 定时推进工作

详见 PR [#5890](https://github.com/QwenLM/qwen-code/pull/5890)、[#5991](https://github.com/QwenLM/qwen-code/pull/5991)、[#6073](https://github.com/QwenLM/qwen-code/pull/6073)

### 桌面端语音听写：三端能力对齐

语音听写在 CLI 和 Web Shell 里已经有了，但桌面端缺失——用户配置好语音后一切到桌面端就失去这个能力。本版本补齐了最后一个界面。

composer 工具栏新增麦克风按钮，录音时工具栏变成录音条（点线引导 → 实时波形 → 计时），停止后转写结果插入输入框供复核。转写在服务端进行，复用 CLI 的语音管线（批量 `qwen3-asr-flash` 与实时 `*-realtime` 模型），provider 凭证不会进入 renderer。语音可在 Settings → Input 和 composer 模型下拉里开关并选择模型。

你能用它做什么：

- 点击麦克风说话，实时看到波形和计时
- 选择 realtime 模型（如 `qwen3-asr-flash-realtime`）边说边看 interim 文本
- 在平板或多显示器场景下解放双手输入

详见 PR [#5856](https://github.com/QwenLM/qwen-code/pull/5856)

### Mobile Sidebar Drawer + `qwen serve` 体验完善

之前手机浏览器访问 `qwen serve` 时，侧边栏（会话列表、搜索、新建会话）在 760px 以下直接 `display: none` 隐藏——你没有任何方式切换会话。现在用 overlay drawer 模式替代了直接隐藏：聊天面板头部出现菜单按钮，点击后侧边栏从左侧滑入，带半透明遮罩。选择会话、新建会话、点击遮罩均可关闭 drawer。桌面端布局完全不受影响。

这背后是一系列让 `qwen serve` 从“能用”变成“好用”的改动：

- **会话延迟创建**（[#6066](https://github.com/QwenLM/qwen-code/pull/6066)）：直到首次 prompt 才创建会话，减少空会话开销，Web Shell 启动更快
- **workspace remember**（[#5884](https://github.com/QwenLM/qwen-code/pull/5884)）：serve 模式记住工作区，重启后无需重新指定
- **session archive**（[#6058](https://github.com/QwenLM/qwen-code/pull/6058)）：daemon 支持会话归档，长期会话有管理了

你能用它做什么：

- 手机浏览器访问 `qwen serve`，点击菜单切换会话
- 在多个项目中切换时，serve 自动记住工作区
- 长期会话可以归档，不用删掉

详见 PR [#6003](https://github.com/QwenLM/qwen-code/pull/6003)

### TUI 鼠标点击与悬停

CLI 之前在 Virtualized History 模式下只支持鼠标滚轮和滚动条，不支持指针交互。现在开启了 Virtualized History（`ui.useTerminalBuffer`）后，三类交互可用：

- **选择菜单和对话框**（权限确认、`/model`、`/config`、主题等）：悬停高亮指针所在行，点击即选中
- **`/` 命令和 `@` 文件建议列表**：悬停高亮建议项，点击接受
- **输入框**：左键点击定位文本光标（支持多行换行、滚动偏移、宽字符）

你能用它做什么：

- 在 `/model` 对话框里直接用鼠标点选模型，不用按方向键
- 输入 `/` 后用鼠标点击补全项
- 在多行输入中点击重新定位光标

详见 PR [#6011](https://github.com/QwenLM/qwen-code/pull/6011)

![](https://gw.alicdn.com/imgextra/i3/O1CN01c0h5qw1vEdOGiDaqv_!!6000000006141-1-tps-1280-720.gif)

### Settings 标签式对话框：搜索、状态、统计一屏搞定

`/settings` 从扁平列表改造成了标签式视图，参照 Claude Code 的 `/config` 设计。顶部标签栏分 Settings / Status / Stats 三页，Settings 页新增搜索框，输入即筛选。

Status 页展示与 `/status` 相同的系统信息，Stats 页嵌入完整的 `/stats` 仪表盘（Session / Activity / Efficiency 子标签）。键盘焦点在标签栏 → 搜索框 → 设置列表间纵向移动，高亮只出现在真正持有焦点的区域。

你能用它做什么：

- `/settings` 打开后直接输入关键词筛选设置项
- 用 ←/→ 切换到 Status 页查看运行时信息，不用单独跑 `/status`
- 在 Stats 页按 Tab 切换 Session / Activity / Efficiency，Efficiency 表超出对话框高度时自动折叠为 "+N more"

详见 PR [#6044](https://github.com/QwenLM/qwen-code/pull/6044)

![](https://gw.alicdn.com/imgextra/i1/O1CN01X1ytLW1KtGkN6GEGW_!!6000000001221-1-tps-1280-720.gif)

### Chrome 扩展：浏览器里直接对话 + 操作页面

Chrome 扩展基于 daemon-direct 架构复活——扩展不再是 Native Messaging 宿主，而是本地 `qwen serve` daemon 的薄客户端。

侧边栏聊天通过 `DaemonSessionProvider` 直连 `qwen serve`（HTTP+SSE，和 web shell 同一条路径），连不上 daemon 时提示 " 运行 `qwen serve`"。浏览器工具（读页面、截图、控制台、导航、点击、填表）以客户端托管的 MCP server 形式经 daemon WebSocket 暴露给 agent，聊天和工具两条路径都去掉了 Native Messaging。

> [!caution]
> 
> 注意：反向工具通道目前通过 `QWEN_SERVE_CLIENT_MCP_OVER_WS` 环境变量开启，默认关闭——需要启动 `qwen serve` 时显式设置该标志。


你能用它做什么：

- 在 Chrome 侧边栏直接与 Qwen Code 对话，无需安装 OS 级原生宿主
- 让 agent 读取当前页面、截图、操作浏览器元素
- 复用 web shell 的共享 UI，体验一致

详见 PR [#5777](https://github.com/QwenLM/qwen-code/pull/5777)
