Qwen Code 本周发布 v0.19.6 ~ v0.19.8 共 3 个正式版本，150+ 个 PR 合入，覆盖四个方向：

**模型过载不再卡死。** 之前遇到 429/503/529，对话直接中断，你得手动换模型重发。现在 fallback 链在主模型重试预算耗尽后自动切到备选模型继续回复。加上 `/model --project` 让不同项目绑定不同模型，不用每次手动切。

**子代理可以派生子代理了。** 之前子代理是 " 叶子节点 "——接到任务只能自己干完，没法再分活。现在默认 5 层嵌套深度，子代理可以把子任务拆给下一层。TUI 和 Web Shell 都能看到树形结构，谁派生了谁一目了然。

**Web Shell 会话管理成体系了。** 归档/删除/命名分组/颜色标签/定时任务管理页/会话总览分屏——之前会话侧边栏只能切换，现在能整理、分类、监控、并行操作。7 个 PR 把会话从 " 平铺列表 " 变成可管理的资源。

**企业微信和权限控制补齐。** 企业微信智能机器人频道接入——Bot ID + Secret 两项配置就能用，不需要企业管理员权限开回调。PreToolUse hook 的 "ask" 现在真的会弹确认框了，之前这个选项等于静默拒绝。权限规则也支持 `Tool(param:value)` 语法，按参数值粒度控制。

## ✨ 新增特性

### 模型过载自动切换 + 项目级模型配置

模型 429/503/529 的时候，你的对话会直接卡住。这个版本加了 opt-in 的 fallback 链——主模型在同一个模型的重试预算耗尽后，自动切到 fallback 列表里的下一个模型继续回复。只有容量和限流问题才走 fallback 路径。认证、配额、配置、客户端错误会直接失败，因为这些不是 " 模型过载 "，是 " 你的配置有问题 "。

fallback 在向用户输出可见内容之前推进。如果 fallback 模型已经输出了部分内容然后挂了，剩余 fallback 不会继续尝试——你看到的是截断的回复。但下一个用户 turn 会重新从主模型开始，不会卡在 fallback 模型上。

配合 `/model --project`，你可以把不同模型绑定到不同项目。`--project` 写入项目 `.qwen/settings.json`，`--global` 写入用户 `~/.qwen/settings.json`。不带标志时保持当前行为。作用域标志也适用于 `--fast`、`--voice`、`--vision`。

你能用它做什么：

- 配置 fallback 模型列表，模型过载时自动切换，不用手动改模型
- 认证/配额错误不会被 fallback 掩盖，问题更早暴露
- `/model --project` 让不同项目用不同模型，配置跟项目走
- `/model --global` 设全局默认，新项目继承

详见 PR [#6273](https://github.com/QwenLM/qwen-code/pull/6273)、[#6060](https://github.com/QwenLM/qwen-code/pull/6060)

### 子代理嵌套派生 + 树形视图

子代理现在可以再派生子代理了。默认深度上限 5 层，通过 `model.maxSubagentDepth` 配置。设为 1 就回到老的行为——子代理不能派生子代理。

两层保护机制：schema 准备阶段，最深层的子代理不会看到 agent 工具（它根本不知道有这个工具可用）；运行时守卫，超过深度上限的派生请求会被拒绝。

TUI 和 Web Shell 都能看到嵌套树形结构。子代理显示在父代理下方，带 ↳ 标记和缩进。父代理离开后，子代理提升为根节点，标注 "from \<parent\>"。详情视图显示 "Level N · from \<parent type\>"。blocking 标签和停止确认也变成链路感知的——只有取消会导致 turn 结束时才弹出确认。

**这个能力默认开启**——升级后所有现有环境都获得嵌套派生能力。Fork 子进程、teammates、workflow agents 仍然排除在外。Arena 会话现在可以嵌套了。后台 agent 恢复时会恢复原始深度和启动时的 cap。

你能用它做什么：

- 让子代理处理复杂任务时，自己派生子代理分担子任务
- 在 TUI 和 Web Shell 里看到完整的代理树形结构
- 通过 `model.maxSubagentDepth` 调整嵌套深度上限

详见 PR [#6189](https://github.com/QwenLM/qwen-code/pull/6189)、[#6239](https://github.com/QwenLM/qwen-code/pull/6239)

### Web Shell 会话管理：归档、分组、定时任务、分屏

7 个 PR 把 Web Shell 的会话侧边栏从 " 平铺列表 " 改造成一个可以整理、分类、监控、并行操作的管理面板。

**归档与删除。** 每个会话行新增快捷操作和 "…" 溢出菜单（重命名/归档/删除）。归档后的会话收在可折叠的 "Archived" 区域，可以恢复或彻底删除。当前正在使用的会话不允许归档或删除，已归档的会话无法打开（409 `session_archived`），删除是硬删除，有二次确认。底层走 daemon 的 `archiveState` 和 `/sessions/archive`、`/sessions/unarchive` 端点。

**命名分组与颜色标签。** 可以创建、重命名、删除分组，把会话拖进去，给分组打颜色标签和置顶/归档状态。分组数据从 daemon 层贯穿到 UI——daemon 侧的项目级 sidecar 文件存储分组元数据，REST/ACP 路由提供 CRUD 操作，能力门控下按客户端支持情况暴露。

**会话总览与分屏。** 大屏下侧边栏出现会话总览面板，所有会话以实时卡片展示，按优先级排序：需要审批的排最前，然后是运行中的，最后是空闲的。每张卡片显示当前模型和客户端数量。多选后可以分屏查看——当前标签页内分屏，或者在新浏览器标签页打开（`?split=a,b` URL 参数）。N 个独立聊天面板并排显示，每个有自己的会话上下文，键盘焦点只作用于点击的面板。

你能用它做什么：

- 长期积累的会话归档整理，按项目分组、打颜色标签
- 可视化创建和管理定时任务，不用手写 cron 表达式
- 每个定时任务有独立会话，运行历史和转录随时可查
- 大屏下分屏并行查看多个会话的实时状态

详见 PR [#6293](https://github.com/QwenLM/qwen-code/pull/6293)、[#6350](https://github.com/QwenLM/qwen-code/pull/6350)、[#6305](https://github.com/QwenLM/qwen-code/pull/6305)、[#6348](https://github.com/QwenLM/qwen-code/pull/6348)、[#6389](https://github.com/QwenLM/qwen-code/pull/6389)、[#6453](https://github.com/QwenLM/qwen-code/pull/6453)、[#6400](https://github.com/QwenLM/qwen-code/pull/6400)

### 企业微信频道接入

通过 `@wecom/aibot-node-sdk` 接入企业微信智能机器人。配置只需要 Bot ID 和 Secret——不需要 Corp ID、Agent ID、回调 Token、EncodingAESKey，也不需要公网回调地址。

通过 WebSocket 长连接接收消息，支持文本、语音转写、图文混排、图片、文件、视频、引用内容。Assistant 回复以企业微信 markdown 格式发送。出站只支持本地图片标记（频道临时目录内），文件/视频/语音标记会被忽略。

配置方式：

```json
{
  "type": "wecom",
  "botId": "your-bot-id",
  "secret": "your-secret",
  "cwd": "/path/to/project"
}
```

启动命令：`qwen channel start my-wecom`

你能用它做什么：

- 用 Bot ID + Secret 两项配置接入企业微信，不需要企业管理员权限
- 接收文本、语音、图片、文件、视频、引用消息
- 在企业微信群里让 Qwen Code 回复 markdown 格式消息

详见 PR [#6436](https://github.com/QwenLM/qwen-code/pull/6436)

### PreToolUse hook 原生确认框

PreToolUse hook 返回 `permissionDecision: "ask"` 之前等同于 "deny"——确认框根本不会出现，hook 开发者以为用户会看到选择，实际上被静默拒绝了。

现在 "ask" 会弹出原生 TUI 确认框。选项是 "Yes, allow once" 和 "No, suggest changes"——没有 "always allow"，因为 hook 每次调用都会重新评估。批准后工具重新执行，拒绝则取消。

非交互式 CLI 和后台 agent 场景，"ask" 回退到 deny——不会挂起等待。复用现有的 awaiting_approval 机制，没有另起一条路径。"denied" 和 "stop" 行为不变，PermissionRequest hook 不受影响。

你能用它做什么：

- PreToolUse hook 里用 "ask" 让用户决定是否执行工具
- 不用担心非交互场景挂起
- 每次调用 hook 都重新评估，不会永久放行

详见 PR [#5629](https://github.com/QwenLM/qwen-code/pull/5629)

### 自动生成 Skills 预览审查

agent 自动生成 skill 时，之前只能看到文件名，确认后才知道里面写了什么。现在审查对话框内联预览完整内容——包括 frontmatter。

模型生成的内容会被消毒：ANSI/VT 控制序列变成无害转义，CRLF 变成普通换行。读取上限 64 KiB，显示上限 12 行（自动换行计算），超出部分标记 "lines hidden" / "truncated"。

按 `o` 可以在配置的编辑器里打开 skill 文件，不跳过当前 skill 审查。文件保存后自动刷新预览——配合 GUI 编辑器（macOS 默认行为）可以改完再看。

"Turn off auto-generated skills" 选项在列表最后，选中后立即生效（不需要重启），workspace 级持久化。当前批次会被搁置（不删除），从 `/memory` 重新开启后批次会回来。

你能用它做什么：

- 在确认前看到 skill 的完整内容，不用先接受再去翻文件
- 按 `o` 直接在编辑器里修改 skill 内容，保存后预览自动刷新
- 一键关闭自动生成 skills，当前批次不会被删，随时从 /memory 恢复

详见 PR [#6393](https://github.com/QwenLM/qwen-code/pull/6393)
