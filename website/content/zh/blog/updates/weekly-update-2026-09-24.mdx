Qwen Code 本周发布 v0.24.1 ~ v0.24.4 共 4 个正式版本，200 个 PR 合入。

**上下文满了，能查是哪个文件、哪个扩展吃掉的。** 知道该关掉哪一个，把地方腾回来。

**一条 SSH 地址就能改另一台电脑上的项目。** 代码在服务器、编译机或者同事的机器上，你坐在自己电脑前就能让它改那边的文件、跑那边的构建。

**工作流跑一半被打断，重启后能接着跑。** 跑完的部分直接沿用，几小时的长流程只要补失败那几处。

## ✨ 新增特性

### 上下文满了，能查是哪个文件、哪个扩展吃掉的

`/context` 把上下文按来源拆开列——系统提示、内置工具、MCP 工具、记忆文件、Skills、扩展带的文件，这周补上「启动上下文」和缓存前缀两行。`/context detail` 往下能看到具体文件，扩展带进来的标成 `Extension: 扩展名 · 文件名`，并给出各占多少。终端和 Web Shell 两边同步。

**占太多会提醒你一句。** 常驻上下文（`QWEN.md` 和自动记忆）加起来超过「窗口的 15%」和「1 万 token」里较小的那个数时，加载会提示一下。

**扩展带的规则可以只在碰到对应文件时才生效。** 命中你访问的那个文件才注入上下文，平时不占地方。

你能用它做什么：

- 上下文快满了，先看清是哪几个文件、哪个扩展在吃
- 装了扩展发现上下文涨了一截，用 `/context detail` 点出来是哪个
- 收到超量提示，知道该精简 `QWEN.md` 还是关掉自动记忆

详见 PR [#12119](https://github.com/QwenLM/qwen-code/pull/12119)、[#12318](https://github.com/QwenLM/qwen-code/pull/12318)、[#12034](https://github.com/QwenLM/qwen-code/pull/12034)

[📸 截图：`/context detail` 里标出扩展来源的那一屏]

### 一条 SSH 地址，直接改另一台电脑上的项目

项目放在服务器上、编译机里，或者同事的机器上，你想让 Qwen Code 去改。以前你得先在那台机器上把 Qwen Code 装上、把服务跑起来，再把地址填过来。现在 Web Shell 里添加工作区时，目录路径直接写一条 SSH 地址：

```text
ssh://user@host/absolute/project
```

那台机器上没装 Qwen Code 的，填这条地址注册进来；已经在跑 Qwen Code 服务的，存一次地址和令牌，之后添加工作区直接选中它。注册进来之后，读写那边的文件、在那边执行命令、看那边的 Git 状态，都在你本地这一条对话里完成。刚添加进来的工作区只能看，授权「信任」后才能改文档。

你能用它做什么：

- 代码和依赖都在编译机上，你在本地对话里让它改那边的文件、跑那边的构建
- 借别人机器上现成的环境验证一次
- 本机项目和远端项目同时挂着，一条对话里来回改

详见 PR [#12255](https://github.com/QwenLM/qwen-code/pull/12255)、[#12085](https://github.com/QwenLM/qwen-code/pull/12085)、[#12412](https://github.com/QwenLM/qwen-code/pull/12412)

[🎥 演示：Web Shell 里填 `ssh://` 地址注册远端工作区，让它改那边的文件]

### 工作流跑一半被打断，重启后能接着跑

一个流程跑到一半要下班，或者机器重启被打断，以前只能整个从头再来，现在每次运行都留了记录，下次能接着往下跑。

**重启之后会主动跟你说。** 打开 Qwen Code 时，启动提示里会列出哪一次运行被打断、停在第几步、有几个子代理已经跑完了，并让你去 `/workflows` 里看。这些运行也都进了历史列表。

**Web Shell 的历史运行卡片上有按钮。** 「重试失败路径」只重跑没成功的那部分，「全部重跑」从头再来。

你能用它做什么：

- 跑到一半要下班，明天开机先看看它停在哪一步
- 只有两个子代理失败的长流程，用「重试失败路径」补那两处
- 同一套流程想再从头验证一遍，点「全部重跑」

详见 PR [#12159](https://github.com/QwenLM/qwen-code/pull/12159)、[#12291](https://github.com/QwenLM/qwen-code/pull/12291)、[#12097](https://github.com/QwenLM/qwen-code/pull/12097)

[📸 截图：重启后的启动提示 + Web Shell 历史运行卡片上的两个按钮]

### Web Shell 多重更新

**批准改文件前，改动摊开给你看。** 需要你确认的文件修改，审批卡片里直接列出这次新增了哪些行、删了哪些行，覆盖改文件、写新文件、改 notebook 这三类。详见 PR [#12443](https://github.com/QwenLM/qwen-code/pull/12443)

**粘一大段日志会折成一张卡片。** 粘进来的内容超过 200 行或者 8000 字符时自动折起来，标题取开头一段，要点开就按「显示到输入框」放回输入框。以 `/` 或 `!` 开头的粘贴、短粘贴、替换选区里的内容都不会被折。详见 PR [#12084](https://github.com/QwenLM/qwen-code/pull/12084)

**右侧面板能加「轨迹」页签。** 跑完一轮觉得慢或者贵，打开它就能看出时间花在哪：每一轮用了多久、第一个字多久出来、吃掉多少 token，哪个工具调用最费时间。入口在右侧扩展区的「添加页签」里选「轨迹」。详见 PR [#12388](https://github.com/QwenLM/qwen-code/pull/12388)

**Git 历史更好找了。** Web Shell 的提交历史以分支线图显示，还能切换全部分支，并按提交信息、作者或哈希搜索。远程仓库地址也能在界面里加和删，不用开终端敲命令。入口都在输入框上方的分支标签里。详见 PR [#12152](https://github.com/QwenLM/qwen-code/pull/12152)、[#11163](https://github.com/QwenLM/qwen-code/pull/11163)

**其他改进。** 计划模式开关从输入框工具条收进「+」菜单，开着的时候输入框上方留一个可关掉的标签（[#12218](https://github.com/QwenLM/qwen-code/pull/12218)）；`/export` 导出的文件在对话里变成一张能预览、能下载的卡片（[#12050](https://github.com/QwenLM/qwen-code/pull/12050)）。

## 📊 更多新功能

**Web Shell 能装成电脑上的独立 App。** 地址栏右边出现安装入口，点一下就有自己的图标、开独立窗口，用起来跟商店装的应用一样。要求 Chrome / Edge 111 以上、Firefox 128 以上、Safari 16.4 以上，地址是本机地址（`127.0.0.1` 或 `localhost`）或者 HTTPS，用局域网 IP 访问时装不上。详见 PR [#11722](https://github.com/QwenLM/qwen-code/pull/11722)

**桌面版能调窗口里的字大小了。** 按 `Cmd` / `Ctrl` 加 `-` / `=` / `0`，或者两指在触控板上捏合，50% 到 300% 之间随意，下次打开还是你上回调好的比例。详见 PR [#12410](https://github.com/QwenLM/qwen-code/pull/12410)

**Goal 的额度显示在输入框上方。** 那条状态除了原有的 token 预算，现在还会显示轮数和时间上限，比如 `3 / 20 turns`、`12m 3s / 30m 0s`；没设上限的 Goal 保持原样。`/export` 导出的会话记录里也会带上 Goal 的完整过程。详见 PR [#12201](https://github.com/QwenLM/qwen-code/pull/12201)、[#12099](https://github.com/QwenLM/qwen-code/pull/12099)

**Goal 报完成，得看对话里的实际经过。** 用 `/goal` 让它带着目标跑几轮，它自己说「做完了」不作数——验收会回看最近这段对话真正发生了什么，对不上就判未完成。详见 PR [#12105](https://github.com/QwenLM/qwen-code/pull/12105)

**派出去的子代理，可以关在容器里干活。** 你让它扫整个仓库、跑一堆命令，不用担心它在 home 目录里翻到你的 SSH key 和凭证：它执行的每条命令、每次读写都关在一个 Docker 或 Podman 容器里，改得动的只有工作区。要这么跑就在启动前设 `QWEN_AGENT_EXECUTION_BACKEND=docker`，代价是工作流、Agent Team、MCP、LSP、skills 会一起停掉，Windows 也还不支持。详见 PR [#11711](https://github.com/QwenLM/qwen-code/pull/11711)

**一个服务商下能混着挂两种接口。** 想让某个模型走 OpenAI 的 Responses 协议，在这个模型条目上加一行 `"wireApi": "responses"` 就够，其余模型照旧走 Chat；`/auth` 配自定义服务商时也有「选择 API 格式」这一步可选。详见 PR [#11538](https://github.com/QwenLM/qwen-code/pull/11538)
## 👏 体验优化

**手机上用 Web Shell 更顺了。** 服务绑到对外地址时，Web Shell 的会话页右上角也能出配对码，手机扫一下就进当前会话，不用手动输令牌；进了手机页面，输入框也重新排过，十几个动作收进「添加到消息」抽屉。详见 PR [#12322](https://github.com/QwenLM/qwen-code/pull/12322)、[#12252](https://github.com/QwenLM/qwen-code/pull/12252)

**输入框这块清爽了些。** 会话还没建立时，工作区选择和 Git 分支标签从输入框工具条挪到下面单独一行；会话建立后，工作区只在顶部显示一个文件夹图标，鼠标悬停能看到完整路径。对话里链接类的产物卡片改成直接开新页面。详见 PR [#12299](https://github.com/QwenLM/qwen-code/pull/12299)、[#12317](https://github.com/QwenLM/qwen-code/pull/12317)

**压缩结果说中文了。** `/compress` 之后显示「上下文已压缩 X → Y」，没什么可压的时候说「无需压缩。」，重开会话之后上下文圆环上的数字也是新的。详见 PR [#12141](https://github.com/QwenLM/qwen-code/pull/12141)

**非主工作区的 Channel 自动连接会生效。** 一个 `qwen serve` 带多个工作区、各自挂不同 Channel 机器人时，服务启动现在会把每个受信任工作区自己的 Channel 都恢复起来，那几个「Qwen Code 启动时自动连接」开关点了保存之后是真的生效。详见 PR [#12385](https://github.com/QwenLM/qwen-code/pull/12385)

**Linux 沙箱改成只关工具执行。** 上一期那种把整个 Qwen Code 关进 bwrap 的配法，这版会直接报错并给出一句迁移提示，换成 `tools.executionSandbox` 之后，受约束的只剩命令行、读写文件这些工具执行，Qwen Code 本体、模型请求和你的登录状态都留在本机。详见 PR [#12267](https://github.com/QwenLM/qwen-code/pull/12267)

**脚本里一次性调用更快。** `qwen -p` 这种跑一句就退出的用法实测从 7.7 秒降到 5.1 秒，内存从 640 MiB 降到 421 MiB，少起一个进程。详见 PR [#12340](https://github.com/QwenLM/qwen-code/pull/12340)

**终端不出配对码时会说明原因。** 绑了对外地址想让手机扫码连上来，如果终端没出码，它会说明原因，并另给一张只含地址的码，扫开后在手机上输一次令牌就能连。要强行打出带令牌的码，用 `qwen serve --token-qr`。详见 PR [#12266](https://github.com/QwenLM/qwen-code/pull/12266)
