你让 Qwen Code 在电脑上接了个不算小的活——重构一个模块，顺带把测试补齐。它正在读文件、改代码、跑测试，干得有模有样。

这时候，会议室在催人，或者你只是单纯想离开那张椅子，去沙发上瘫一会儿。

通常你只有两个选择：盯着它跑完再走，或者把它丢在那儿、回来再看。两个都不太舒服。

但还有第三个：掏出手机，接着看它跑，该批准批准，该追问追问——就像你从来没离开过那张椅子。

这就是 `qwen serve` 想给你的东西。

## 它到底是什么

一句话：`qwen serve` 把你正在用的 Qwen Code，变成你这台机器上的一个本地服务。

你的终端、IDE 插件，还有任何浏览器——包括你手机上的那个——连到的都是**同一个 agent 会话**。同一份对话、同一批文件 diff、同一个权限确认。

它不是另起一个云端实例，也不是把你的项目同步到别处。它就是你电脑上那个 Qwen Code，只是多开了一扇门。

## 一条命令，门就开了

最爽的部分是启动——你甚至不用记任何参数。

跟 Qwen Code 说一句「启动远程访问」，或者触发你预先写好的 `serve` skill，它会自己把活儿干完。它背后做的事，大致是这样：

```bash
# 1. 查出你这台机器的局域网 IP
ipconfig getifaddr en0
# → 192.168.0.105

# 2. 在后台把服务起起来（带 token、允许你这个 IP 访问）
QWEN_SERVER_TOKEN=my-token qwen serve \
  --hostname 0.0.0.0 \
  --allow-origin "http://192.168.0.105:4170"
# → qwen serve listening on http://0.0.0.0:4170
#   (mode=http-bridge, workspace=/Users/you/your-project)
```

然后它把一个**带 token、点开就能用的链接**递到你面前：

```
http://192.168.0.105:4170?token=my-token
```

它替你包办了三件你懒得自己做的事：查出局域网 IP、在后台把服务起起来、把 token 直接拼进链接里。你要做的，只是复制那一个链接。

这才是「好用」该有的样子——把麻烦藏在一条命令背后，留给你的只是一个动作。

## 手机端，无敌好用

这是整件事的高光时刻。

手机连上和电脑同一个 Wi-Fi，浏览器里粘上那个地址，你看到的就是一个再熟悉不过的 Web Shell——和你电脑上是同一个。

它绝不是一个缩水版的聊天框。你在电脑上能看到的一切，手机上一项不少：

- 它读了哪个文件、改了哪几行，diff 清清楚楚
- 工具调用折叠在那儿，点开就看细节
- 它想动你的文件、跑一条命令之前，会弹一张权限卡片，等你点头

你在电脑上开了个头，现在躺在沙发上接着看它跑。它在屏幕那头「Converting coffee into code...」，你在这头看着它把活干完。

断线了也不怕。你进电梯、切到 5G、再切回 Wi-Fi，重新打开页面——它靠 SSE 的断线重连，把你漏掉的那一段补回来。不是刷新出一个空白页，而是严丝合缝地接着你离开的那一行。

## 为什么不是别的方案

你可能会想：这事我用别的不也能凑合吗？

**用 IM 机器人？**（Telegram、钉钉、飞书那些）

能，但你要把每一次对话、每一段代码上下文，都先送到第三方的 IM 服务器上转一圈。而且你在 IM 里看到的，是被压扁成纯文本的气泡——没有 diff 高亮，没有可折叠的工具调用，没有权限卡片。`qwen serve` 不经过任何中间商：浏览器直连你自己的机器，展示的是原生的、信息密度高得多的界面。

**用云端 remote control / 云 IDE？**

那意味着你得把整个开发环境搬到云上：代码、依赖、密钥、你精心配置的 git 和 shell。搬一次家，还得时刻担心两边对不上。`qwen serve` 什么都不搬——你的环境原封不动留在你自己的机器上，你只是换了块屏幕去看它。办公时间无缝切换，没有「云端环境还没配好」这种破事。

说到底，这三件事才是 `qwen serve` 真正想要的：

**克制。** 默认只监听 `127.0.0.1`，安安静静待在本机，外面什么都看不见。

**安全。** 一旦你要开到 `0.0.0.0` 让别人（或你的手机）访问，不带 token 它直接拒绝启动；CORS 默认把所有浏览器来源挡在门外；token 校验用的是常量时间比较，连侧信道都顺手堵上。

**隐私。** 你的代码、你的密钥、你的项目，从头到尾没有离开过你这台机器。信任的根，就是你这个用户本身。

## 几个值得知道的细节

- **多端共享一个会话**：电脑和手机连的是同一个会话。哪台设备先看到权限请求，哪台就能批——first-responder，不用抢。
- **手机语音输入**：想在手机上用语音给它下指令？加上 `--tls-cert` / `--tls-key` 走 HTTPS，浏览器 secure context 的限制就解开了。
- **一个 daemon，多个工作区**：`--workspace` 多写几次，一个服务能同时托管好几个项目。

## 一点诚实的现状

它现在最适合的，是**本地 / 局域网、单用户**的场景，主打文本聊天和编码。多人协作、容器化部署、公网暴露这些更重的用法，还在后续版本里逐步打磨。换句话说：拿它在你自己的机器上、用手机接着干活，现在就很香；想拿它当生产级多租户服务，再等等。

## 最后

真正好的工具是这样的：能力很强，但默认很安静；只在你需要的时候，恰到好处地出现。

`qwen serve` 就是这样。它没发明什么新东西，只是把「你的 agent 应该跟着你走」这件理所当然的事，做成了。

下次你让 Qwen Code 跑一个长任务的时候，试着站起来，掏出手机。

你会发现，它一直在那儿。
