编程开发不是只有写代码这一步。从想清楚要做什么，到确保代码质量，每一步都费时间。下面三个场景，Qwen Code 全程参与——帮你梳理需求、审查代码、补测试用例。

## 从模糊需求到可交互原型

脑子里有个想法，但还没想清楚细节？直接告诉 Qwen Code 你想做什么，它不会急着写代码，而是先像产品经理一样跟你聊——核心功能有哪些、交互方式怎么定、技术实现方式等。等你和 AI 都对需求满意了，它再动手把整个工具开发出来。从一句话到一个能跑的产品原型，全程不用你自己写一行代码。

### 操作步骤

1. **打磨需求** — 把你的想法告诉 Qwen Code，哪怕只是一句模糊的描述。AI 会主动问你一系列问题来补全细节——核心功能、交互方式、技术实现等，最后帮你生成一份完整的需求文档。
2. **确认需求方案** — AI 生成需求方案后，你可以逐条检查，看看有没有要改的或者要加的。确认没问题了，再进入下一步。
3. **进入开发** — 需求方案确认好了，直接让 Qwen Code 开始开发。它会按照需求文档一步步把整个工具搭建出来，全程自动完成。

<Callout>
    **提示**：需求阶段越具体，开发阶段越少返工。不要急着让 AI 写代码，先聊清楚。
</Callout>

## 9 个 AI 审查员，同时帮你看代码

写完代码提交前，跑一遍 `/review`，9 个审查 Agent 同时开工，从安全、性能、代码质量等维度并行扫描，发现问题直接帮你修好。同事提了 PR，一条命令审查，意见自动写到 GitHub 代码行上，跟真人 review 一样。

### 操作步骤

1. **项目代码审查** — 运行 `/review` 审查项目代码，9 个 Agent 并行扫描，自动发现硬编码密钥、SQL 注入等安全和性能问题。
2. **一键修复问题** — 选择自动修复，Qwen Code 直接修改代码并运行 linter 验证，确保修复不引入新问题。
3. **PR 审查并评论** — 运行 `/review <PR number> --comment` 审查远程 PR，切到 GitHub 查看行内批注，审查意见直接写在代码行上。

```bash
/review <PR number> --comment
```

## 给项目增加单元测试

让 Qwen Code 读懂项目规则，自动生成覆盖正常场景、边界场景和异常输入的单元测试，并运行验证、修复问题、补充测试覆盖。

### 操作步骤

1. **理解项目与测试目标** — Qwen Code 通读项目文件，理解业务规则、核心函数和测试目标，规划需要优先覆盖的测试场景。
2. **生成测试并运行验证** — 基于业务规则，为核心函数生成单元测试，覆盖正常场景、边界场景和异常输入，例如优惠券门槛、包邮临界值、空购物车和无效输入，并自动运行测试。
3. **修复问题并跑通测试** — 根据测试失败结果判断问题来源。如果源码实现与业务规则不一致，Qwen Code 会修改代码并重新运行测试，直到测试通过。
4. **补充测试覆盖** — 查看测试覆盖率报告，分析未覆盖的文件和分支，继续补充有价值的测试用例，提升关键逻辑的测试覆盖。

<Callout type="error">
    **注意**：AI 生成的测试用例需要你确认业务逻辑是否正确。AI 能帮你写测试，但不能替你判断什么是对的。
</Callout>
