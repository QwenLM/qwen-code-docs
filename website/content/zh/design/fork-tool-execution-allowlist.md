# Fork 工具执行允许名单

## 摘要

为 Agent 工具既有的 `subagent_type: "fork"` 运行时添加一个可选的
`fork_tools` 参数。该参数收窄 fork 可以执行的工具，而不改变发送给模型
的工具声明。

这是 #7625 的第一阶段。命名 profile 文件、shell 参数模式、overlay 文件
系统和 `/btw` 集成不在范围内。一个启动 prompt 提示告诉 fork 允许名单许
可哪些可见工具。

## 目标

- 当省略 `fork_tools` 时，保留继承的 fork 执行表面，但 fork 绝不能执行
  的交互工具除外。
- 把空列表视为拒绝一切，而不是既有的 `tools: []` 通配行为。
- 保持 fork 当前模型可见的声明不变，使添加执行限制不改变其 prompt-cache
  前缀。
- 在工具构建、工具 hooks、权限分类、调度或批准之前拒绝不允许的调用。
- 当后台 fork 从其持久化 sidecar 复活时保留该限制。

## 参数与匹配

`fork_tools` 仅与显式的 `subagent_type: "fork"` 一起有效，不能与命名
teammate 组合。每个条目必须是非空字符串且不带首尾空白。未知的精确名称
保留在允许名单中且不匹配任何工具；它们不会被过滤掉，因为把无效的非空列
表变成省略的限制会 fail-open（失败即放行）。

内建工具使用模型可见声明中的精确规范函数名。MCP 条目支持精确规范名称
加上服务器和尾部通配模式。模式针对已注册工具的原始 MCP server/tool 身
份匹配，而不只是其 provider 清洗后的名称，因此清洗为相同前缀的不同服务
器名不会交叉匹配。裸 `*` 被拒绝；省略已经允许所有其他可执行的继承工
具。通配条目限于 `mcp__*` 或尾部 MCP 工具前缀模式，例如
`mcp__github__read_*`。`mcp__*` 有意匹配所有 MCP 工具而不匹配内建工
具。

Shell 参数模式不属于本阶段。列出 `run_shell_command` 允许工具调用继续
走正常权限流水线，但不预先批准其命令。

## 运行时分离

`ToolConfig.tools` 仍是 `AgentCore.prepareTools()` 和每次模型请求的函
数声明的来源。一个单独的 `executionAllowedTools` 字段在 `AgentCore`
创建时被快照。精确条目和 MCP 通配条目分别预计算，使一次工具未命中不会
分配或重新扫描无关的内建名称。

`processFunctionCalls()` 首先验证请求的名称存在于声明集合中。然后应用
可选的执行允许名单。一个不允许的调用产生一个带原始调用 ID 和名称的合
成错误响应，而同一批次中的其他调用继续进入调度器。由于这个检查先于调度
器构建，被拒绝的调用无法开启批准提示或执行 pre-tool hook。

允许名单只收窄既有表面。它不能重新启用被子代理排除项移除的工具，不能为
允许的工具绕过正常权限，也不能添加声明。

每个 fork 都收到一个内存中的执行允许名单，即使省略了 `fork_tools`。运
行时拥有的底线在应用调用方提供的列表之后移除 `ask_user_question`，因此
调用方无法重新启用它。该工具保留在父级派生的声明列表中以共享
prompt-cache，但调用会在调度或批准之前被拒绝。被阻塞的 fork 向父级报
告缺失输入，而不是尝试直接与用户交互。

fork 在任务 prompt 中继承的可缓存前缀之后收到一条限制通知。这避免了试
错调用，而不改变父级派生的系统指令、历史前缀或工具声明。

## 后台复活

后台 fork 在 `agent_bootstrap` transcript 记录中持久化继承的历史，并在
单独的记录中持久化启动任务 prompt。系统指令和工具声明是能力，因此冷复
活从当前父运行时重新绑定它们，并通过活跃注册表解析当前工具名称。

调用方提供的 `executionAllowedTools` 则是启动时策略。受限的 fork 把它
存储在 `AgentMeta` sidecar 中，包括空的拒绝一切列表，冷复活把它重新
应用到活跃的 `ToolConfig`。没有 `fork_tools` 启动的 fork 不持久化派生
列表，允许复活从当前父工具表面重新计算它。得到的可执行表面是当前父级
派生的工具表面，按持久化策略和强制的交互工具排除项收窄。

该字段为兼容性保持可选。较旧的 transcript 和没有 `fork_tools` 启动的
fork 恢复时使用当前父级派生的工具表面，减去强制的交互工具排除项。

## 边界

`fork_tools` 由父模型或调用方在每次 Agent 工具调用时提供。因此它是子
级能力限制，不是用户或管理员强制的安全沙箱。未来的 profile 层可以在此
执行机制之上提供一个短的、项目控制的策略名称。

该限制无法通过另一个子级洗白：fork 执行在 fork 运行时上下文内运行，
其权威的 Agent-tool 守卫拒绝所有子代理生成。更一般地，`fork_tools`
无法使被排除或未声明的工具可执行。
