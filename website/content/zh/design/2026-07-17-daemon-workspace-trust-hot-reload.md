# Daemon 工作空间信任热重载

## 状态

已为 QwenLM/qwen-code#6378 实现。

## 问题

daemon 目前在构建 `WorkspaceRuntime` 时评估工作空间信任。`GET /workspace/trust` 只报告该快照，`POST /workspace/trust/request` 只发布 `trust_change_requested`。修改 `trustedFolders.json`、IDE 信任或用户/系统的文件夹信任设置并不会重建运行时，因此设置、环境、文件系统、ACP 会话、MCP、扩展、channel worker 以及定时工作都停留在旧的信任边界上，直到 daemon 重启。

信任无法原地更新。文件系统工厂、bridge、设置、环境、ACP 挂载以及若干工作空间作用域的管理器都在构建时捕获其运行时输入。

## 安全不变量

1. 信任降级会在第一个异步 drain 步骤之前关闭受影响运行时的 generation 守卫。自该时刻起不得有新的特权副作用开始。
2. 已关闭的 generation 守卫永不重新打开。替代者获得新的守卫和单调递增的 generation id。
3. 失败的撤销绝不恢复之前受信任的运行时。
4. 格式错误或不可读的系统/用户设置会 fail closed（失败即拒绝）。当需要文件信任时，格式错误或不可读的 trusted-folders 文件会 fail closed；但当文件夹信任被禁用或 IDE 信任已经解析出主工作空间时，该文件无关紧要。
5. 处于迁移中、被阻塞和过期的会话所有者绝不回退到主运行时。
6. 每个运行时激活路径都在发布前立即验证策略修订版本。

## 信任策略

daemon 使用一个无副作用的策略加载器，它只读取系统覆盖、用户设置、系统默认值、IDE 信任和 `trustedFolders.json`。工作空间设置和项目环境文件被排除在策略评估之外。现有的信任规则优先级和路径比较行为保持不变。

该加载器产出一个不可变的语义快照。一个工作空间将该快照物化为一个可操作的信任布尔值和一个允许根目录列表。只有物化结果的变化才会重建运行时。仅源文件的变化会推进已应用的策略修订版本，但不触发重建。

主文件系统保留现有的受信任 IDE 多根行为。当一个次级根目录从主允许根目录列表中移除时，次级和主两个 generation 都会在任一方被 drain 之前关闭。

monitor 每秒重新读取一次策略输入，仅当其语义哈希变化时才发布。IDE 和同进程的 trusted-folder 写入也会触发一次立即读取。`/workspace/reload` 和动态工作空间注册显式请求一次调和。

Trusted-folder 写入会获取 `proper-lockfile`，在锁内重新读取，保留注释，并原子地替换一个常规的 0600 文件，且不跟随符号链接。格式错误的文件不会被静默重写。

## 运行时所有权

注册表拥有稳定的 `WorkspaceEntry` 对象。一个活跃条目引用一个不可变的 `RuntimeGeneration`，后者拥有运行时及其 generation 守卫。工作空间身份、持久化注册元数据和已应用的策略状态位于条目上，而不是 generation 上。运行时的构建和清理仍由 daemon 宿主协调。

工作空间限定的数据面路由在请求时解析其运行时。保留进程级路径的主路由为当前运行时使用实时委托。特权 REST 变更捕获 generation 守卫，并在其提交边界重新检查。ACP、Voice、channel worker 和会话准入使用各自现有的 drain 机制。信任状态和 daemon 清单读取稳定条目而不获取运行时。

会话所有者索引是 generation 感知的。会话创建和恢复显式注册所有权，运行时替换会使旧的所有权失效。现有的活跃 bridge 扫描保留作为兼容修复路径，用于早于索引机制的会话。

运行时清理会关闭 bridge 和子 channel、Voice 状态、子会话、ACP 挂载、channel worker、定时 keepalive 和 git 状态。由替代运行时拥有的管理器会以全新的设置、环境、文件系统、信任、策略和缓存输入重建。共享路径锁和进程遥测在替换后存活，因为它们不携带任何工作空间能力。

## 调和

信任调和与运行时发布共享一个 daemon 拓扑闸门；工作空间添加和重载在完成自身操作后通过该闸门请求调和。信任快照会被合并，以便在调用方被释放之前应用最新观察到的修订版本。关闭流程会停止 monitor，并在获取其清理快照之前等待拓扑闸门。

对于信任降级，控制器会在第一个异步 drain 之前同步关闭所有受影响的 generation，关闭准入路径，销毁旧运行时，构建新的运行时，重新检查策略修订版本，并安装新的条目 generation 和 ACP 挂载。现有的 bridge 和 ACP 关闭路径提供有界的或强制的清理。过期的候选会被销毁并重建。

授权（grant）使用同样的破坏性替换。如果失败，控制器会尝试一个新的不受信任运行时，并将配置的修订版本报告为失败，直到后续调和成功。如果无法确认运行时遏制（containment），条目保持阻塞且深度健康降级；其他工作空间保持可用。

## 协议

仅请求的端点保持仅请求。信任状态 v1 保持为默认的兼容性视图。客户端以 `statusVersion=2` 请求 v2；旧服务器可能返回 v1。V2 将配置的策略与生效的运行时状态分离，并报告 `stable`、`applying` 或 `failed`、一个不透明的修订版本和一个稳定的错误码。daemon 仅在主路由和次级路由都使用 generation 感知的解析之后才宣告 `workspace_trust_hot_reload`。

不引入可靠的已应用事件总线。GET 状态是唯一事实来源。信任变更请求需要一个活跃的 generation 来发布现有事件；否则返回可重试的 503。

## 非目标

- 直接的远程信任批准。
- 零停机的双运行时或会话迁移。
- 公开的 generation 标识符。
- 并行的运行时重建。
- 重建完整的 Express 应用。
- 修改独立 CLI 的信任语义。
