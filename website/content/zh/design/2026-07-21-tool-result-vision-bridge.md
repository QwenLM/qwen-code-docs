# 工具结果 vision bridge

## 背景

现有的 vision bridge 转换从用户输入解析出的图像，而 `read_file` 会把普通图像排除在纯文本工具结果之外。其他工具可以以 `inlineData` 形式返回图像；`convertToFunctionResponse` 把这些图像存入 `functionResponse.parts`，请求瘦身器之后会用 MIME 占位符替换它们以适配纯文本模型。结果是，即使配置了视觉模型，模型发现的图像或内置、MCP 和扩展工具返回的图像也无法被纯文本主模型理解。

## 设计

`read_file` 仅在当前目标模型是纯文本且存在可用的 vision bridge 模型时保留普通图像。它自己不调用视觉模型；PDF 专用的转录保持不变。

一个共享的核心 helper 在规范化后的工具响应部分成为模型输入之前立即处理它们。当当前目标模型接受图像，或没有可用的 vision bridge 时，该 helper 原样返回响应。如果配置的视觉模型具备 agent 能力，且调用方可以切换本轮的剩余部分，该 helper 会限制内联图像大小、保留工具图像，并通过现有的整轮覆盖选择该模型。否则，对于每个包含内联图像的 `functionResponse`，它会以这些图像加上一个有界的焦点提示（包含工具名称、图像标签和现有的文本输出）调用现有的 vision bridge。

该 helper 把不可信的机器转录追加到现有的 `response.output` 或 `response.error`，保留函数名、调用 ID、其他响应字段和非图像媒体，并从 `functionResponse.parts` 中移除每一个原始内联图像。Bridge 失败和取消会用一条显式的不可用说明替换图像，而不是允许原始图像数据到达纯文本 provider。超出 bridge 计数或字节上限的图像同样被移除，并由转录块报告。

该共享 helper 被核心工具调度器和 ACP 的直接工具执行器使用。交互式调度器、非交互式运行器和活跃的 ACP 提示可以接受工具触发的整轮覆盖，因此下一个模型请求和后续的工具延续停留在具备 agent 能力的视觉模型上。在支持内联模型选择的表面上，显式选择保持优先。没有轮级覆盖通道的消费方保留转录回退，而不是把原始图像暴露给纯文本模型。推测性后续执行是例外：因为其输出可能被丢弃且只用于预热缓存，它会以一条显式的不可用说明移除工具结果图像，且从不把它们发送给视觉模型。内置工具、MCP 工具和扩展工具都经由这些路径之一进入。

每一次真实的工具结果 bridge 尝试都会在活跃表面上披露。转录使用现有的 vision bridge 格式化器报告所选的视觉模型和端点，而整轮接管报告会负责本轮剩余部分的模型。TUI 和 JSON 输出在该通知旁边保留工具的原始显示，ACP 把相同的通知作为 agent 消息发出。

只转换内联图像字节。图像 `fileData`、URL、仅路径的文本、音频和视频不在本变更范围内，因为解析它们会引入独立的文件系统、网络、认证和模态策略。

## 兼容性与失败行为

公共工具 schema 不变。现有的用户输入和 PDF vision bridge 行为保持原样。没有视觉模型的配置保留其当前不支持图像或 MIME 占位符的行为。成功的工具调用不会仅因为 bridge 失败而被转换为工具错误；模型收到原始文本加上一条脱敏的图像不可用说明。Provider 错误细节会被记录但从不插入函数响应。每轮次的图像预算在轮次内的所有 bridge 路径之间共享：运行计数以该轮次的中止信号为键，因此用户输入、PDF 和工具结果 bridge 从同一个上限中扣减，而不是各自获得一个新的上限。在配置了视觉模型但其不具备 agent 能力时，提前耗尽上限的轮次会使之后的工具图像被转录为预算耗尽；具备 agent 能力的接管不受影响，因为它保留原始图像而不是转录它们。

## 验证

专门的测试覆盖普通图像读取、嵌套工具图像、文本与图像混合的结果、多个函数响应、bridge 失败与取消、多模态目标的直通、整轮接管的接受与拒绝、用户可见的披露、推测性图像剥离，以及函数身份和非图像字段的保留。集成检查演练核心调度器、交互式与非交互式覆盖管线、ACP 执行器和推测性执行器的调用点。构建、类型检查、bundle 和本地 CLI 验证完成本变更。
