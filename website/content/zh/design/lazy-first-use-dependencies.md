# 编码、终端与 Git 依赖的惰性首次使用加载

## 背景

Issue #7264 跟踪那些存在于 ACP 子进程急切静态导入闭包中、但大多数会话
从不使用的依赖。候选 5 将三个具有不同首次使用边界的包归为一组：

| 包                       | 基线 ACP 闭包        | 首次使用                                                          |
| ------------------------ | -------------------: | ----------------------------------------------------------------- |
| `iconv-lite`             |        551,713 字节 | 读写不带 BOM 的非 UTF-8 文本                                       |
| `@xterm/headless`        |        213,071 字节 | 通过 PTY 路径启动 shell                                            |
| `simple-git`             |        146,526 字节 | 执行 worktree、清理或 GitHub 扩展的 Git 操作                       |
| **直接包合计**           |    **911,310 字节** |                                                                   |

直接合计约为 890 KiB。完整的 ACP 静态闭包还包含当这些包离开急切路径后变得
不可达的模块，因此实际测得的 bundle 级缩减可能更大。

## 目标

- 将这三个包全部从 ACP 子进程的静态导入闭包中移除。
- 保留当前同步的公共编码辅助函数。
- 每个包在真正首次使用时只加载一次，不引入新配置。
- 保留 shell 回退行为、Git 行为、文件编码元数据、BOM 处理和原子写入。
- 增加 bundle 守卫，使未来的导入不能把这些包静默恢复到急切闭包中。
- 使用与 #7264 中其他候选相同的 2-vCPU、4-GiB 验收规范验证该变更。

## 非目标

- 将公共编码 API 从同步改为异步。
- 替换 `iconv-lite`、`@xterm/headless` 或 `simple-git`。
- 更改 PTY 选择、worktree 语义、编码检测或错误策略。
- 优化在这些依赖已经加载之后运行的代码。

## 导入闭包发现

从 `febb43bc9266cc7a3363539df87d90d752ad782c` 构建的基线 bundle 的 ACP 静态
闭包为 13,405,027 字节，共 144 个输出。一次 esbuild metafile 遍历将
551,713 字节归因于 `iconv-lite`，213,071 字节归因于 `@xterm/headless`，
146,526 字节归因于 `simple-git`。

最初的包级惰性导入并不足够。CLI 包含对 Core 包根的生产命名空间动态导入。
在 esbuild 代码分割构建中，请求整个命名空间会使每个根导出保持可达，包括
同步编码兼容导出。因此该设计要求同时具备依赖本地加载器和窄的 CLI 运行时
入口模块，后者只重新导出每个延迟路径所消费的符号。

## 设计

### 共享加载器属性

每个包都有一个由模块作用域 promise 支撑的包本地加载器。并发的首次使用者
共享同一个 import，后续使用者复用已解析的模块。加载器归一化 Node 和
esbuild 发出的 CommonJS 互操作形态，并只暴露其消费者所需的运行时成员。

加载器刻意使用 `import()` 而不是 `createRequire()`。生产 bundle 是独立的，
绝不能依赖单独安装的 `node_modules` 树。动态导入让 esbuild 发出自包含的
chunk，同时让这些 chunk 留在 ACP 静态闭包之外。

### `@xterm/headless`

`ShellExecutionService.execute()` 已经是异步的。服务先获取 PTY 实现，然后
在进入 PTY 执行路径之前立即加载 `@xterm/headless`。它在异步导入之后重新
检查中止信号，并把解析出的 `Terminal` 构造函数传入现有的同步 PTY 和重放
辅助函数。

如果 terminal chunk 加载失败，错误保留在现有的 PTY 失败边界内，执行回退到
`child_process`，与当前回退策略一致。当 PTY 支持不可用或选择了子进程路径
时，不发生任何包加载。

### `simple-git`

被审计消费者中所有真实的 Git 操作都是异步的。`GitWorktreeService` 保持
构造无副作用，只在首次调用其 Git 方法时才解析每实例的 `SimpleGit` promise。
其他 Core 消费者直接使用同一个包本地加载器。

启动清理首先使用现有的轻量级仓库根发现。它只在真实仓库存在且需要检查过期
worktree 时才加载 `simple-git`。导入失败会在同一个异步边界拒绝该操作，
Git 初始化失败本来就在该边界上报。

### `iconv-lite`

这个包带有主要的兼容性约束：`decodeBufferWithEncodingInfo()` 和
`encodeTextFileContent()` 是公共同步 API。JavaScript 动态导入是异步的，
因此让这些函数直接惰性化会破坏 API。

同步 API 通过一个静态导入 `iconv-lite` 的兼容模块保持可用。只有 Core 根
重新导出边被标记为对 bundle 无副作用，使 esbuild 能在某个入口不使用这些
导出时丢弃兼容模块。该模块的其他导入保留正常的副作用处理。

内部异步文件服务路径使用惰性变体：

- 空文件、带 BOM 标记、有效 UTF-8、ASCII 和 UTF-8 写入无需加载
  `iconv-lite` 即可完成。
- 检测出的非 UTF-8 读取在解码前加载编解码器。
- 保留非 UTF-8 元数据的写入在编码前加载编解码器。
- 读取端加载或解码失败保留当前的警告和 UTF-8 替换回退。
- 写入端加载或编码失败会拒绝写入，而不是损坏字节。

CLI 的延迟 Core 命名空间导入被窄的本地运行时入口模块替代。这避免了保留
每个 Core 根导出，同时保持相同的捆绑 Core 实例和类身份。

## Bundle 守卫

ACP 快路径守卫将 `iconv-lite`、`@xterm/headless` 和 `simple-git` 视为
禁止的静态包。从 ACP 入口出发的静态路径会使检查失败；仅动态路径是允许的。
测试覆盖拒绝和允许的动态边界两者。

该守卫评估 metafile 导入图而不是 bundle 文本，因此重命名的 chunk 或被压缩
的符号无法绕过它。

## 兼容性与失败审计

| 领域                            | 保留的行为                                                       | 新边界                                                                  |
| ------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Shell 执行                      | PTY 输出处理、重放、中止、子进程回退                             | Terminal chunk 在 PTY 选择之后加载                                       |
| Worktree 与 GitHub 扩展         | 现有的 `simple-git` 选项和错误传播                               | Git 模块在首次异步 Git 操作时加载                                        |
| 文本读取                        | BOM 和 UTF-8 快路径、编码元数据、回退解码                        | 仅在检测出的非 UTF-8 回退时加载编解码器                                  |
| 文本写入                        | BOM 保留、非 UTF-8 编码、原子写入行为                            | 仅在非 UTF-8 元数据需要时加载编解码器                                    |
| 公共 Core API                   | 同步编码辅助函数的签名和行为                                     | 兼容导出可以从不使用它的入口中被 tree-shake 掉                           |

该设计不引入进程全局的可变配置。加载器 promise 是进程本地且幂等的。被拒绝
的导入保持拒绝，这是恰当的，因为缺失或损坏的捆绑 chunk 无法在同一进程生命
周期内恢复。

## 考虑过的替代方案

### 将同步编码 API 转换为 promise

被拒绝，因为它会破坏公共调用方，并把本属内部的启动优化扩散出去。

### 在首次使用时使用 `createRequire()`

被拒绝，因为它会使捆绑 CLI 依赖运行时的 `node_modules` 安装，并且不会产生
自包含的发布产物。

### 重新实现编码表或终端行为

被拒绝，风险远大于推迟加载现有包。

### 只落地 `@xterm/headless` 和 `simple-git`

这会更简单，但会把该组中最大的包留在急切路径上，无法满足候选 5。兼容门面
和窄运行时入口模块在不改变其公共 API 的情况下移除了 `iconv-lite`。

## 验证计划

1. 构建仅 CLI 的生产产物，并使用 esbuild 代码分割进行捆绑。
2. 遍历 ACP 入口的静态 metafile 闭包，要求三个包的归因字节全部为零。
3. 针对编码读写、shell 执行与回退、Git worktree 行为、清理、GitHub 扩展
   操作、每个加载器和 bundle 守卫运行聚焦的单元测试。
4. 运行受影响的 CLI 测试、构建和完整类型检查。
5. 在 2-vCPU、4-GiB 参考主机上，先运行一次成对冒烟测试，然后运行 30 组
   交替串行冷启动对和 30 组预热对。报告 `channel.initialize`、进程到首个
   会话延迟、进程树峰值 RSS、并发、遥测禁用行为、遗留单会话行为和残留
   进程。

## 实测 2C4G 结果

远端主机有 2 个 vCPU、3.5 GiB 总内存、无交换分区，Node.js 22.23.1。一次
单独的单对冒烟运行及其功能场景在正式运行前通过。正式运行随后完成 30 组
交替串行冷启动对和 30 组交替预热对，接着是另一组功能场景，没有失败的会话
或残留进程。

正式候选是复制的原型产物，SHA-256 为
`f0ac7edc7665752efac7b7bfbb4fb055ce2d8ef1a8ae5dd1af630305a2c84d28`，由测试
装置标记为 `febb43bc9266cc7a3363539df87d90d752ad782c+candidate5`。结果
适用于那个确切产物，不适用于未来的 commit SHA；如果 PR 的生产代码发生
变化，应保留产物哈希或重新运行门禁。

候选还通过了并发首会话、遥测禁用启动和遗留单会话启动。生产配置的首次使用

真实本地 `simple-git` 仓库初始化。远端主机没有 `git` 可执行文件，因此远端
的 `simple-git` 探针验证了模块加载和工厂构造，但无法执行真实 Git 命令；
完整的本地 Git 服务套件覆盖这些操作。

验收门禁满足：冷路径的胜出在全部 30 组延迟对中一致，在预热的 channel
初始化指标中仍然可见，并且没有用延迟换取更高内存。

## 风险与发布

主要风险是仅首次使用时才出现的失败，而急切导入过去会在启动时暴露它们。
聚焦测试演练首次使用路径，生产 bundle 守卫验证导入保持动态。远端冒烟和
验收运行演练真实捆绑的 ACP 会话并检查残留进程。

按照 #7264 的要求，该候选应保持为单独的 PR，使其回归面和性能影响保持可
归因。如果 2C4G 门禁没有显示可复现的启动收益，或出现有意义的首次使用
回归，则不应仅为减小 bundle 体积而落地该实现。
