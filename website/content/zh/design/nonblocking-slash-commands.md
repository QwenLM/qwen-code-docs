# 流式期间的非阻塞斜杠命令

## 问题

交互式输入路由器目前在模型响应流式输出期间会将除 `/btw` 之外的每个斜杠
命令排队。这使得本地 UI 控件即使其结果并不依赖该轮次，也要等待激活的会话
轮次。

## 设计

`SlashCommand` 新增一个可选启用的 `canRunDuringStreaming` 能力。默认仍为
false。当主模型正在响应时，输入路由器通过现有的斜杠命令树解析提交的命令。
启用了该能力的命令直接发送给斜杠命令处理器；所有其他斜杠命令继续使用现有
的串行化消息队列。

直接路径不经过 `submitQuery`。该函数拥有模型轮次生命周期，并有意拒绝并发
的顶层轮次。将本地命令置于其外，避免了与激活响应共享中止控制器、提交标志
或模型流计数器。

斜杠命令处理器和命令结果已经通过 React 状态更新 Ink。因此初始命令不会在
Ink 渲染期间直接写入终端 stdout。

## 初始命令集

- `/status`、`/about` 和 `/status paths`：读取本地运行时信息并追加一个
  Ink 历史项。
- `/settings`：打开设置对话框；保存的更改通过现有的 settings hook 应用，
  不会替换激活的会话轮次。
- `/help`：打开静态帮助对话框。

以下类别保持串行化：

- 提交或转换模型轮次的命令，例如 skill、`/summary`、`/compress`、
  `/model <model> <prompt>` 和 `/goal`。
- 替换、清除、回退、恢复、分支或以其他方式变更会话状态的命令。
- 调度工具或执行长时间外部工作的命令。
- 读取正被激活轮次变更的状态的命令，例如 `/context`、`/stats`、`/copy`、
  `/diff` 和 `/recap`。

`/btw` 保留其专门的并发模型请求路径。`/quit` 保留其现有的立即取消路径。
Ctrl+Q 继续强制任何提交等待空闲，包括原本启用了该能力的命令。

## 验证

单元覆盖验证启用该能力的命令在响应期间绕过 `submitQuery` 和消息队列，而
未标记的斜杠命令保持排队。命令测试固定初始的能力声明。交互式 E2E 检查应
启动一个可见的流式响应，打开每个启用的命令，关闭所有对话框，并确认原始
响应继续并完成。
