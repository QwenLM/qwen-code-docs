# MCP 工具名 Provider 兼容性

## 问题

Qwen Code 目前使用 Gemini 的字符集接受 MCP 工具名。诸如
`literature.search_pubmed` 这样的名称会变成
`mcp__server__literature.search_pubmed`，Gemini 接受该名称，但更严格的
OpenAI 兼容和 Anthropic 兼容端点可能在工具运行之前拒绝它。

同一个原始名称会在注册、权限持久化、重连查找、输出截断和恢复的历史中
被独立重建。因此，只更改 provider 请求会使模型可见的名称与注册表键不一致。

## 设计

对 MCP 工具名使用一条确定性的 provider 安全归一化规则：

- 保留已经匹配 `^[A-Za-z][A-Za-z0-9_-]*$` 且不超过 63 个字符的名称。
- 替换不支持的字符，确保首字符为字母，并在需要归一化或截断时追加一个
  稳定的短哈希。
- 将最终名称保持在 63 个字符以内，这被 Gemini 以及更严格的 OpenAI 兼容
  和 Anthropic 兼容 provider 接受。
- 在整个 MCP 调用过程中使用已注册的名称，而不是从原始服务器名和工具名
  重建。
- 归一化已恢复的 OpenAI 和 Anthropic 请求历史中的 MCP 名称，使变更之前
  创建的会话仍然可发送。
- 通过携带从原始服务器名和工具名派生的、归一化前的精确别名，继续匹配
  遗留的 MCP 权限和禁用工具条目。这也保留了被先前的中间截断算法截断的
  名称，而不会放宽通配符匹配。

不引入 provider 专属的别名表。合法的现有名称逐字节保持不变，因此 Gemini
行为和正常的内置工具不受影响。

由先前的中间截断算法产生的已恢复名称已经是 provider 安全的，并在历史消息
中保持不变。它们被移除的中间部分无法可靠重建，因此转换器不会猜测新的基于
哈希的名称；精确的权限和禁用工具兼容性改为使用 MCP 注册期间可用的原始名称
别名。

## 验证

- 针对有效、无效、冲突、超长、稳定和幂等名称的单元测试。
- 针对注册、权限规则、重连查找和禁用工具的 MCP 工具测试。
- 针对包含带点 MCP 名称的已恢复历史的 OpenAI 和 Anthropic 转换器测试。
- Core 包构建和类型检查。
