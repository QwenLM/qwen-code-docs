# 托管会话写入器关闭

## 问题

托管的 `qwen serve` 替换实例可能在新主机名上启动，而前一个 ACP 子进程
仍持有会话写入器锁。外部主机的 v1 锁无法被证明过期，因此替换实例正确地
返回 `session_writer_conflict`。按主机名或时长回收将允许两个存活 Pod 写入
同一份转录。

## 范围

本 P0 使协作式托管关闭在父进程的 SIGKILL 期限之前释放写入器锁。它不添加
密封交接记录、接管认领（claim）、TTL 或主机名抢占、平台围栏、维护租约，
或在 SIGKILL、事件循环卡死或存储故障之后的自动恢复。历史上的外部主机锁
仍然需要外部写入器围栏和手动清理。

只有校验了现有私有父进程能力的 ACP 子进程才使用托管路径。独立 ACP 保留其
现有的关闭和本地过期所有者恢复行为。托管获取绝不基于 PID 可见性回收现有
锁，因为容器 PID 命名空间使该证明不安全。

## 写入器终结

写入器关闭是单飞的，并同步关闭公共记录准入。正常关闭在关闭前敲定元数据
并等待已接受的工作。托管快速关闭不等待激活的模型轮次，也不追加额外的
finalize 记录；它只 drain 截止时间之前已被接受的记录器工作。

flush 失败会密封写入器，并且在精确所有者释放尝试之后仍会上报，保留先前
的关闭契约。所有权或释放失败会保留主锁，除非释放已经提交。唯一的释放
提交是从主锁 `P` 到所有者唯一退役路径 `R` 的同目录重命名。旧所有者只能
清理它自己确切的 `R`；它绝不重试主重命名，也不触碰后继者的 `P`。当写入器
终结失败时，托管关闭会发出运维者可见的警告，并附上候选锁路径。只有在
确认前一个写入器不再运行之后，手动清理才是安全的。

## 托管 ACP 关闭

第一个关闭动作关闭会话创建和轮次准入，并对激活、初始化和延迟清理的、
具备写入器能力的 Config 实例做快照。所有写入器终结在第一个 await 之前
启动并行运行。SessionEnd hook 在写入器阶段之后运行，此时 Config 资源
仍然可用。随后资源清理在剩余时间内运行。

只有当每个写入器终结都干净时，子进程才以零退出。锁可能已被释放，但后续
hook 或资源清理仍可能使整体关闭不干净。

### Config 资源静默

写入器关闭和 Config 资源关闭是独立的终结。写入器关闭仍在第一个托管关闭
await 之前启动。资源清理随后会先汇合任何进行中的 `Config.initialize()`，
再检查和停止资源，因此初始化无法在清理已经返回之后创建 watcher、工具
注册表或 MCP 管理器。

关闭一旦开始，Config 初始化即被密封，资源清理在托管关闭与并发请求失败
清理之间是单飞的。完整的 `shutdown(options)` 调用不是单飞的，因为写入器
和遥测选项仍然是调用专属的。

一个未完整初始化的 Config 会在其挂起租约暴露后立即开始精确所有者释放，
早于汇合初始化。转录快照读取会在块之间观察到该释放，并停止发布迟到的
记录器。成功初始化的 Config 保留正常的 finalize、flush 和关闭顺序。初始
化汇合没有本地超时：为等待设置超时会让底层初始化继续运行，并重新引入迟到
的资源创建。daemon 进程期限仍然是硬边界，此时挂起写入器释放已经完成或
已显式失败。

## 父进程生命周期

每个 daemon 句柄拥有一个由主、次级和动态工作空间 channel 工厂共享的进程
注册表。spawn 预留与关闭密封同步竞争。成功的 spawn 在同一轮次内附加到
注册表。

Node 的 `spawn` 事件之前、没有 PID 的错误是 `no_process`；spawn 确认后，
只有原始 `exit` 能证明已被收割（reaping）。spawn 后的 channel 构造失败
会立即 SIGKILL 未发布的子进程，并在返回构造错误之前汇合 channel 终结。
channel 工厂返回之后，桥在构造或发布其完整 ChannelInfo 之前拥有该
channel。

Daemon 关闭使用一条单调的进程注册表时间线：`t0` 时 SIGTERM，子进程非零
退出或被信号终止时稳定的不干净关闭，`t0 + 5s` 时 SIGKILL，`t0 + 10s` 时
稳定的 `not_reaped` 失败。零退出是托管子进程对写入器终结的协作确认；仅
原始 exit 只能证明已被收割。注册表期限绝不重启，迟到的原始 exit 不能把
已失败的终结改为成功。对于后来变得可收割的、独立托管的 channel worker，
daemon 保留其现有的重试路径；这样的重试会汇合到同一个已结算的 ACP 进程
注册表终结，而不是开启新的 ACP 关闭时间线。

父进程期限有意不扩大以匹配 SessionEnd hook、Config 初始化或 MCP 清理
预算，因为平台终止窗口可能更短且不在 daemon 控制之内。这些写入器之后的
阶段使用写入器释放后的剩余时间，可能被中断，产生不干净的 daemon 退出，
且不会恢复已释放的写入器锁。只有未确认的 channel-worker 退出会让 daemon
存活以进行第二次优雅关闭尝试；其他 ACP 或桥失败在第一个信号时即非零退出。

## 兼容性与发布

私有能力和公共 ACP/REST 负载不变。自定义异步 ChannelFactory 只在其解析
出 AcpChannel 之后被覆盖；默认托管工厂从 spawn 预留开始被覆盖。

混合版本的写入器运维仍然不受支持。部署和回滚必须在替换实例接受会话之前
drain 旧 ACP 写入器。

## 验证

验证必须区分：

1. 锁已释放且整个 daemon 关闭干净；
2. 锁已释放但后续清理使关闭不干净；以及
3. 锁保留、后继者收到 409、且仍需要手动恢复。

必需的确定性覆盖包括 flush 失败、效果后重命名错误、后继者获取、正常到
快速关闭、在每个截止边界的获取、异步 `ENOENT` spawn 失败、spawn 后错误、
部分 channel 构造、带缓冲 initialize 响应的预解析 channel 退出、D1/D2 与
原始 exit 竞争、迟到退出、两个信号、多运行时并行关闭、Config 初始化期间
关闭、并发 Config 清理、关闭准入后的初始化、独立 ACP，以及混合版本发布
护栏。
