# 后台代理状态与详情

## 问题

Agent 工具调用在后台代理启动后立即返回。因此它的转录块会有一个载荷为 `status: background` 的终结工具事件。Web Shell 有意把该启动结果映射回一个待处理工具卡片，但之后没有任何东西把该卡片与实时的后台任务注册表调和。页脚任务列表到达终态时，最初的 Agent 卡片仍显示为运行中。

前台代理已经在共享的子代理详情面板中打开。后台代理具有相同的 `toolUseId`、任务注册表条目、JSONL 转录和虚拟会话解析器，但这条路径缺少明确覆盖。

## 设计

保持启动投影不变：带 `status: background` 的启动结果保持待处理，直到权威的任务状态到达。守护进程已经会通过会话 SSE 流发出终结性的后台代理通知，携带任务 `status` 和 `toolUseId`。Web Shell 消费这些隐藏的通知元数据，并将其调和回投影出的 Agent 工具卡片。

- `completed` 和 `cancelled` 使卡片完成。
- `failed` 使卡片失败。
- 通知时间戳成为卡片结束时间。
- 没有 `toolUseId` 的通知、非代理通知和无关的工具调用不直接修改消息。

现有的子代理详情提供者仍是唯一的 UI 路径。后台 Agent 卡片在待处理期间和终态调和之后保持可点击。虚拟会话解析器继续流式读取任务 JSONL，并从任务注册表获取实时状态，不按前台/后台模式过滤。对于没有 `toolUseId` 的遗留任务，它把启动记录与持久化的边车文件匹配，并在原始后台启动结果仍显示 `running` 时保留边车文件中的终态状态。

当脱离的工作处于活动状态时，其主列表卡片使用专门的静态 `background task` 标签，而不是前台的 `running` 标签。该卡片不使用运行中的微光效果或滴答流逝计时器。终结通知会用正常的已完成、失败或已取消呈现替换该标签。

后台代理从底部状态栏中省略，因为其进度可以从可点击的卡片和详情面板获取。它们仍保留在完整的 Tasks 面板中。其他后台任务类型（包括 shell 命令）仍保留在底部状态栏并保留现有轮询。一个后台 Agent 本身不会激活底部栏的任务轮询。

持久化的通知记录并不总是保留 `toolUseId`。因此，当加载的转录包含活动的后台 Agent 卡片时，Web Shell 会在转录追赶之后通过现有的子代理端点解析每个待处理卡片。它在重连之后，以及任何终结性 Agent 通知到达时（即使该通知无法直接识别卡片）重复这一单次检查。它绝不启动定时器。输入焦点和普通流式输出不会改变待处理的 Agent 调用 ID 或终结通知键，因此不会触发另一次请求。

停靠的详情面板从右边缘展开，使聊天被连续向左推移，而不是先调整大小再单独做面板动作。减少动态效果偏好设置会禁用停靠动画。面板标签页保持固定宽度，截断长标题，并在标签列表超出可用空间时水平滚动。

## 范围

本次改动更新 Web Shell 投影和守护进程的虚拟子代理状态解析器。它不重写持久化的父转录、不改变任务生命周期、不为后台代理添加任务轮询、不从完整的 Tasks 面板移除代理，也不添加第二个子代理查看器。
