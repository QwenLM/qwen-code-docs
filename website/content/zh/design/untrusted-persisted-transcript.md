# 不可信持久化转录读取器

## 背景

daemon 已经为已注册的不可信次级工作区暴露仅持久化的会话和群组目录。转录
分页仍然不可用，因为传统的 `GET /session/:id/transcript` 路由通过实时桥
接状态解析会话 owner，并把重放委托给一个 ACP 子进程。该路径可能启动进
程、加载工作区设置和项目定义的能力，以及创建或修复持久化的游标签名密钥。

本设计添加一个独立的、按工作区限定的 REST 契约，只读取活动的持久化转
录。传统路由及其由 ACP 支撑的行为保持不变。

## 契约

daemon 宣告无条件的 `workspace_persisted_transcript` 能力，并提供：

`GET /workspaces/:workspace/session/:id/transcript?cursor=<opaque>&limit=<1..500>`

工作区选择器首先解析精确的已注册工作区 id，然后解析 URL 解码后的可携
带绝对 cwd。未知或未注册的选择器以 `workspace_mismatch` fail closed
（失败即拒绝）。受信任的主工作区和次级工作区，以及不可信的次级工作区，
都可以读取。不可信的主工作区保持被拒绝，以保留现有的复数路由安全模式
边界。

只读取活动的持久化 JSONL。已归档的会话返回 `session_archived`；
active/archive 冲突返回 `session_conflict`；缺失的会话返回 404。响应复
用 `DaemonSessionTranscriptPage`，包含由现有可见历史投影生成的无 id
`session_update` 帧。原始 JSONL 和隐藏的系统记录绝不会返回。

## 安全边界

该路由不得调用桥接方法、启动或预热 ACP、加载设置、解析 agent 或
skill、发现工具、运行外部命令、创建持久化游标密钥，或写入路由特定的
daemon/debug 日志。现有的 daemon 级 HTTP 访问日志和遥测保持在这条路由
特定的不写入保证之外。

直接的持久化转录读取在抑制 debug 会话日志的情况下运行。归档协调器在
位置检查、索引构建、记录读取、会话 id 校验和重放期间持有共享的会话锁。
每条返回的记录都必须携带所请求的会话 id；不匹配时以快照冲突 fail
closed（失败即拒绝）。

直接重放上下文只包含会话 id、更新接收器、可选的消息重写和可选的累计
用量。当不存在完整 `Config` 时，工具显示元数据回退到持久化的工具名称
和描述。不会查询任何项目控制的工具注册表。

## 游标生命周期

核心读取器接受显式的游标编解码器。现有调用者继续使用基于文件的编解码
器。daemon 为每个进程创建一个随机主密钥，从工作区 id 和规范化 cwd 派
生一个独立的 32 字节 HMAC 密钥，并为每个已注册的运行时缓存一个内存中
的编解码器。因此新路由的游标会在 daemon 重启时过期，并且不能跨工作区
重放。

游标冻结文件身份、字节大小、活动叶子、重放位置和重放状态。第一页之后
的追加不会改变快照。删除、归档、截断、替换、叶子变更或会话 id 不匹配
会返回 `transcript_snapshot_unavailable`。

## 失败与竞争处理

对于第一页，路由检查 active/archive 位置，但当位置未知时仍会尝试活动
读取器，使畸形的活动存储不会被静默地报告为缺失。对于游标页，它只校验
冻结的活动快照。遇到 `ENOENT` 时，游标页返回快照不可用；第一页会重新
检查位置，以在返回缺失之前检测归档竞争。

重放在协议边界上是页事务性的：在重放转换失败之前发出的更新会连同
`partial: true`、一个通用重放错误一起返回，并且没有 next 游标。挂起的
工具调用和累计用量只有在重放成功之后才会携带在签名游标中。

## 兼容性与限制

旧的单数路由、持久化游标密钥和 ACP 错误映射保持原样。新路由保持现有
的默认页大小 100、最大 500、256 MiB 快照上限、32 条目/64 MiB 索引缓
存和五分钟的缓存生命周期。按工作区限定的路由还额外将每页限制在 4 MiB
持久化源记录、32 MiB 序列化响应 JSON 和 64 KiB 游标状态之内。因此
`limit` 是记录数的上限，而不是承诺每个成功的页都包含那么多记录。单个
超出源预算的聚合记录返回 `transcript_page_too_large`；超大的重放游标
会使本来成功的页以 partial 终止，且不签发续接游标。首次索引扫描仍与冻
结快照的大小成线性关系。

TypeScript SDK 在 `WorkspaceDaemonClient` 上暴露该方法。它强制使用原
生 REST 传输，没有 ACP 路由映射。较旧的 daemon 可以通过新能力检测，
并继续对该路由返回 404。

## 延后工作

已归档转录读取、反向/尾部分页、实时跟随、自动全历史加载、worker 线程
索引、跨重启游标，以及 Web Shell 查看器，都是独立的后续工作。
