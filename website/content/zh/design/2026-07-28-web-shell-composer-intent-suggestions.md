# Web Shell Composer 意图建议

## 摘要

扩展 Web Shell 现有的新话题建议，使一次保守的分类可以推荐用 `/btw` 提一个
旁支问题，或者在新会话中发送一个实质性的新话题。

composer 继续至多显示一个非阻塞动作。有效的 `none` 决策不渲染任何内容。
无效、失败或被取消的分类也不渲染任何内容。

## 决策契约

```ts
type SuggestionKind = 'btw' | 'new_session' | 'none';

interface SuggestionDecision {
  suggestion: SuggestionKind;
  confidence: number;
}
```

只有达到或超过现有置信度阈值的 `btw` 和 `new_session` 决策才会变为可操作。
可操作状态记录被分类的确切草稿和源会话，以便在用户点击时两者都能被再次
检查。

## 行为

- `btw` 用于快速、自包含的旁支问题，不应打扰主任务。
- `new_session` 用于明显不同的、实质性的任务或话题。
- `none` 覆盖续写、不确定以及两个动作都不适合的草稿。
- BTW 分类在之前有一轮用户/助手交互后开始。新会话建议保持其更严格的现有
  上下文阈值。
- 类似跟进的措辞可以被分类为 BTW，但绝不能利用放宽的 BTW 阈值来浮现新会话
  动作。
- 点击 `btw` 建议会通过现有编辑器路径提交 `/btw <draft>`，这保留了该命令
  当前的历史和 composer 清空语义。
- 带图片或 composer 标签的草稿永远不符合 `btw` 资格。
- `new_session` 保留现有的清空、分离、创建和自动提交序列，包括图片保留和
  会话竞态取消。

## 安全性

分类器保持保守和 fail-closed：

- 格式错误的输出、未知动作、无效置信度、错误和取消都不产生动作；
- 会话切换会中止待处理的分类并使可见的建议失效；
- 草稿或附件变化会使可见的建议失效；
- 点击处理在执行前立即检查当前草稿、源会话和附件状态；
- 附件在 ChatEditor 报告相反情况之前被视为存在，因此瞬时的未知状态不会
  暴露 `/btw` 动作。

## 范围

变更保持在 Web Shell 内部。它复用现有的 daemon 会话生成、编辑器提交和
`/btw` 行为。它不添加 daemon 或 SDK 路由，不改变样式，也不引入通用的建议
框架。

## Composer 性能

草稿变化通过稳定的回调进入分类器。它们更新分类器的 ref、取消状态和防抖
计时器，但不更新 React 状态。Web Shell 应用只在可操作建议出现或现有建议
失效时才重新渲染。

这让意图分类离开 composer 的渲染路径，同时在草稿变化时保持立即取消。

## 测试策略

- Hook 测试覆盖三个决策值、严格解析、置信度、附件门控和过期会话结果。
- App 测试覆盖 `/btw` 执行和 composer 清空、过期草稿/会话拒绝、附件拒绝、
  现有的新会话竞态，以及分类待处理期间应用不重新渲染。
- ChatEditor 测试覆盖附件存在性报告。
