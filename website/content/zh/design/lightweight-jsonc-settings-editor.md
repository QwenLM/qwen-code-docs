# 轻量 JSONC settings 编辑器

## 背景

ACP 运行时静态导入 settings 和 trusted-folders 写入器。这两个写入器目前都
依赖 `comment-json`，其解析器簇为 ACP 启动闭包贡献了 304,770 字节。这些
模块在 ACP 子进程能够应答 `initialize` 之前就被解析和求值，尽管大多数启动
并不会写入这两个文件中的任何一个。

Issue #7264 候选 6 提议惰性加载该解析器，或用更轻的解析器替换它。写入 API
及其调用方都是同步的，而且独立发行版不在 bundle 之外附带任意 JavaScript
依赖，因此运行时的 `require()` 或动态导入要么扩大 API，要么破坏首次使用。
`jsonc-parser` 已经存在于开发依赖图中，bundle 占用小，并提供同步解析和
按路径编辑的 API。

## 目标

- 从 ACP 静态启动闭包中移除 `comment-json` 和 `esprima`。
- 保留同步的 settings 和 trusted-folders 写入 API。
- 在普通更新期间保留注释以及现有文件的缩进、换行符、末尾换行和 UTF-8 BOM。
- 保留合并、同步和精确子树替换行为。
- 保持 trusted-folders 的锁、磁盘重读、校验、权限、原子写入、通知和锁
  释放边界不变。
- 拒绝畸形或非对象的 JSONC，且不覆盖它。

## 非目标

- 更改 settings 迁移或 trusted-folder 语义。
- 使配置写入变为异步。
- 重新格式化所有配置文件。
- 替换独立的严格 trusted-folders 加载路径。
- 为其他包添加通用 JSONC 抽象。

## 设计

将遗留的驼峰命名工具重命名为 kebab-case 的 JSONC 编辑器模块。该模块保留
现有的文件级更新 API 和 `applyUpdates` 辅助函数，并新增两个同步的内存中
操作：

1. 将 JSONC 解析为顶层对象，同时收集并拒绝每一个解析器错误。前导 UTF-8
   BOM 在解析前被临时移除。
2. 对解析出的值应用合并、同步或精确子树更新，计算发生变化的对象路径，并
   使用 `jsonc-parser.modify()` 将这些路径应用到原始文本。

对象被递归 diff，使未改变的注释和布局保持不动。数组和标量值被原子替换。
在删除属性之前，同一行上的内联注释会随该属性一起被移除；否则
`jsonc-parser` 可能把注释挂到前一个属性上。完整输出会再次解析，并在任何
调用方写入之前与预期值比较。

重复的对象键需要显式处理，因为 `jsonc-parser` 取最后一个值，而 `modify()`
定位第一个匹配的属性。在应用对象路径更新之前，沿这些路径的较早重复属性会
被移除，使生效的最后一个属性保留下来。被移除的重复实例所拥有的注释随之
移除。这避免了返回成功但生效值未变的情况。

新文件继续使用两空格 JSON。现有文件保留检测到的制表符或空格、LF 或 CRLF、
末尾换行状态和前导 BOM。

`trustedFolders` 在获取其现有锁并重新读取文件之后，复用内存中的解析器和
编辑器。它仍然校验磁盘状态和提议状态，通过 `atomicWriteFileSync()` 写入，
使用模式 `0o600`、`forceMode: true` 和 `noFollow: true`，只在写入成功后
更新内存，并在 `finally` 中释放锁。

`jsonc-parser` 成为 CLI 的直接生产依赖，`comment-json` 被移除。源码导入
使用公共包入口，使未捆绑的编译产物仍可由 Node 直接运行。esbuild 配置将该
入口别名到包的 ESM 构建，因为面向 Node 的 bundle 否则会选其 UMD 入口，
而后者的相对 CommonJS require 无法在分割的 ESM bundle 中存活。快路径
bundle 守卫禁止 `comment-json`、`esprima` 和 `jsonc-parser` 的 UMD 构建
出现在 ACP 静态闭包中。

## 失败处理

- 解析器错误或非对象根在写入前中止。
- 无法表示为 JSON 的值在写入前中止。
- 编辑后的文档与预期值不一致在写入前中止。
- Settings 写入在解析或校验失败时保留现有的 `false` 返回和 stderr 诊断。
- Trusted-folders 写入保留其抛出行为，使调用方在权威的写入失败后绝不更新
  内存状态。
- 文件系统、锁、权限和原子写入失败保持其现有行为。

## 考虑过的替代方案

### 动态 `import('comment-json')`

被拒绝，因为公共写入路径是同步的，且有同步的迁移、UI、ACP 和 daemon
调用方。把调用图改为异步比这项优化的范围更大。

### 惰性 `createRequire()`

被拒绝，因为 esbuild 会把该依赖留在 bundle 之外，而独立发行包不包含
`lib/node_modules` 中的任意 JavaScript 包。打包后的首次写入可能在运行时
失败。

### 始终用 `JSON.stringify()` 重写

被拒绝，因为它会在正常的 settings 更新期间丢弃用户注释和格式。

### 自定义分词器

被拒绝，因为 `jsonc-parser` 已经以一个小得多且有人维护的实现提供了所需
的解析树和编辑原语。

## 验证

- 聚焦的单元测试覆盖现有行为以及畸形输入、非对象根、尾逗号、嵌套和内联
  注释、被删除属性的注释、合并/同步/替换语义、原型污染键、重复键、CRLF、
  制表符、末尾换行、BOM、无操作写入和输出校验。
- Trusted-folders 测试覆盖带锁的磁盘合并、无效输入和输出、注释保留、精确
  同步、保留权限的原子写入、失败写入和锁释放。
- bundle 守卫测试和生成的 esbuild metafile 证明 `comment-json` 和
  `esprima` 都不在 ACP 静态闭包中。
- CLI 构建、类型检查、lint 和聚焦测试必须通过。
- 对照和候选发布 bundle 在既定的 2-vCPU 主机上运行，一次丢弃的热身、30 组
  交替成对冷启动和 30 组交替成对预热启动。候选将冷启动
  `channel.initialize` P50 降低 35.39 ms，进程到首个会话 P50 降低
  38.00 ms，进程到首个会话完成 P50 降低 48.51 ms。每个主要指标在 30 组
  冷启动对中赢了 28 组，成对均值 95% bootstrap 区间完全低于零。
- 已经预热的进程到会话完成路径在统计上呈中性。并发首会话、遗留单会话
  模式、遥测启用和遥测禁用都成功完成，产生了预期的遥测，没有残留进程。
- 候选在初始化期间的进程树峰值 RSS 约高 10.8 MiB，但一次单独的 10 对
  后续测试在 10 秒空闲期后对相同进程采样。成对稳态中位数差为 0.55 MiB，
  bootstrap 区间跨越零，表明峰值差异是瞬时的初始化和垃圾回收时机，而不是
  持久的占用增长。
- 精确的 ACP 静态闭包从 12,449,869 字节降至 12,145,099 字节，减少
  304,770 字节（2.45%），没有 `comment-json`、`esprima` 或
  `jsonc-parser` UMD 输入。
