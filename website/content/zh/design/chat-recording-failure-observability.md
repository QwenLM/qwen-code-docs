# 聊天记录失败可观测性

## 背景

`ChatRecordingService` 在第一次异步 JSONL 写入失败后就永久停止接受写入。转录仍是有效的前缀，但如果没有单独的信号，用户和远端客户端可能错误地以为后续消息仍在被记录。

## 核心生命周期

`Config.onChatRecordingFailure()` 是进程本地的订阅边界。由某个 `Config` 创建的每个记录器会将其第一次异步写入失败转发给已注册监听器的一个快照。该事件携带失败记录的会话 ID 和一个归一化的 `Error`；监听器故障与写入者 promise 隔离。订阅在记录器被替换后仍存活，并由其释放者独立移除。`Config.shutdown()` 会让监听器在记录器终结和冲刷期间保持存活，然后再清除它们。

同步的会话文件创建失败不会发出该事件，因为记录器尚未进入永久失败状态，后续调用可能重试。失败的记录器只发出一次；被跳过的后代、后续追加和重复冲刷不会再次发出。

## 本地 CLI 界面

TUI 和文本输出渲染一条通用的可操作警告，不含文件系统路径、errno 值或底层错误。JSON、stream-json 和 dual-output 发出一条 `system/session_recording_degraded` 消息，其顶层和载荷中的会话 ID 都来自失败事件，而不是当前 `Config` 会话。

一次性结构化输出会终结记录器，并在发出最终结果前最多等待两秒让其完成冲刷。长生命周期的 stream-json 会话只订阅一次，在轮次之间冲刷但不终结，只在会话关闭时终结。超时保持响应性，且不取消底层写入。

## 守护进程协议与持久实时状态

ACP 子进程发送 `qwen/notify/session/recording-degraded`，带协议版本 1、受影响的会话 ID 和 `reason: "write_failed"`。桥接验证载荷、发布 `session_recording_degraded`，并把实时会话条目标记为降级。在条目注册之前到达的通知使用现有的有界早期事件缓冲；drain 该缓冲会同时更新重放环和条目状态。

`session_snapshot.recordingDegraded` 在实时事件离开重放环之后保留该状态。它仅是守护进程内存状态：守护进程重启会创建新的记录器并以健康状态开始。该事件在 `EVENT_SCHEMA_VERSION = 1` 下是增量式的；不需要能力变更。

## SDK 与 WebUI

SDK 验证实时事件和可选的快照字段。会话 reducer 把实时事件当作重同步安全的粘性更新。存在的快照字段是权威的，而缺失的字段为兼容旧版守护进程保留原状态。

UI 归一器把任一种降级表示映射为同一个可恢复的记录错误。WebUI 使用显式通知 ID `daemon.session_recording_degraded:<sessionId>`，使重放事件之后再来快照时保持幂等。关闭通知会移除当前实例；较后的快照可能再次呈现仍然活动的风险。

## 关闭边界

要求成功冲刷的严格关闭路径在冲刷失败时保持守护进程条目存活，使事件仍可投递。现有的尽力而为关闭顺序不变：如果在发现迟到的失败时其 EventBus 已经关闭，则只有调试日志保留该失败。

## 非目标

本设计不重试写入、不恢复降级的记录器、不改变 JSONL 内容或父链接、不添加 fsync、不暴露原始文件系统错误，也不在进程之间协调竞争的写入者。
