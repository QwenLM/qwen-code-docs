# MCP 连接丢失后的安全重放

## 问题

MCP 工具可能在其响应连接失败之前已经完成了一个副作用。因此，重新连接
并再次发送同一个 `tools/call` 可能会重复一次写入，而用户只看到第二次
结果。MCP 工具注解是可选的，且默认为非幂等行为，因此缺失的注解不能成为
自动重放的理由。

## 重放策略

Qwen Code 只在以下所有条件都为真时自动重放失败的调用：

- 该失败被现有的 MCP 连接检查归类为连接丢失。
- MCP 服务器具有 `trust: true`。
- 当前工作空间通过工作空间信任门禁。
- 工具声明了 `idempotentHint: true`，或声明了 `readOnlyHint: true` 且
  没有 `destructiveHint: true` 或 `idempotentHint: false`。

冲突的注解不被视为安全。特别地，一个声明自己只读、同时又声明破坏性或非
幂等行为的工具不会被重放。显式的幂等声明可以覆盖变更性操作，但它不能
覆盖相互矛盾的只读注解。

同一个决策应用于两条执行路径：用于感知进度调用的直接 MCP 客户端和可调用
回退。中止错误、非连接错误以及 MCP `isError: true` 协议结果保留其现有
行为。

重新连接后，Qwen Code 在发送重放之前对新发现的工具应用相同的信任和注解
检查。它不会把前一个服务器进程的信任或注解带入新的调用。

## 失败行为

当连接失败不安全到无法重放时，当前调用不会重新连接，也不会构造第二次
调用。它返回一个稳定的错误，说明该操作可能已经完成，不得自动重试。该
错误不包含工具参数或上游传输错误。

后续独立调用的连接恢复仍由现有的健康监视器、显式重连或正常的发现生命
周期负责。安全调用保留现有的有界重连行为。

## 兼容性

这是一个有意的保守变更。没有注解的工具不再获得透明的连接丢失重放，即使
较旧的 Qwen Code 版本曾重试它们。想要重放的服务器必须提供准确的注解，
管理员必须在受信任的工作空间中主动启用服务器信任。

MCP 注解是服务器提供的行为提示，不是授权边界。Qwen Code 只在服务器和
工作空间信任门禁都通过之后才将其用于重放。

## 验证

测试覆盖直接客户端和可调用回退、安全的幂等和只读声明、缺失和矛盾的注解、
两个信任门禁、失去信任或注解的重新发现工具、连接错误分类、中止、协议
错误、重连失败和重试上限。一个单独的本地 E2E 记录演练一个在断开响应连接
之前提交副作用的服务器，并验证不安全的调用只到达服务器一次。
