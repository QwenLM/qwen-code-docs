# Fork 子代理 `fork_turns`

## 摘要

为 Agent 工具现有的独立 `subagent_type: "fork"` 运行时添加一个可选的
`fork_turns` 参数。省略该参数时，fork 继续继承完整的父会话。调用者可以
显式使用：

- `all` 表示完整的父会话；或
- 正整数字符串，例如 `"3"`，表示最近三个真实用户轮次。

常规子代理和命名的 teammate 不接受 `fork_turns`，继续在没有父会话历史的
情况下启动。

## 目标

- 为省略该参数的 fork 调用保留现有的完整历史行为。
- 让调用者限定 fork 继承的历史范围，而不改变其系统提示词、工具、模型、
  审批模式、工作目录或独立生命周期。
- 计数真实用户轮次，而不是原始 API 消息。工具响应和纯系统提醒不消耗所
  请求的轮次数。
- 使所选的 fork 历史与可变的父消息部分隔离。

## 非目标

- 为常规专用子代理或 agent 团队 teammate 添加上下文继承。
- 添加无历史的 fork 模式。不想要父上下文的调用者应启动常规子代理。
- 改变 fork 的可用性、嵌套规则、后台执行、转录恢复，或对父系统提示词和
  工具声明的复用。

## 设计

### 参数与校验

`AgentParams.fork_turns` 是可选的。JSON schema 接受 `all` 或匹配
`^[1-9][0-9]*$` 的字符串。省略时归一化为 `all`，保留现有的 fork 行为。

对任何非 fork 的子代理类型、未显式指定子代理类型，或在启动命名 teammate
时提供 `fork_turns`，都会被拒绝。`none`、零、负数、小数、带空白的值以及
非字符串值都会被拒绝。

### 选择历史

`all` 使用与现有 fork 运行时相同的 curated 父历史。

对于数值，父聊天在 curated 会话历史之前会先移除其前导的启动上下文。这
可以防止 curation 将启动提醒与第一个真实用户 prompt 合并。原始的启动
前缀随后会被前置到所选窗口，使 fork 保留父的环境上下文。

真实用户轮次是包含除 function response、空文本或纯系统提醒之外内容的
user 角色消息。所选切片从倒数第 N 个真实用户轮次开始，并包括其后的模型
消息、工具调用、工具响应和提醒。如果真实轮次少于 N 个，则选择所有可用
的真实轮次。

压缩后的历史摘要是合成前缀，不包含在数值窗口中；当 fork 需要压缩摘要
时，调用者应使用 `all`。最终选定的历史会被深拷贝，使 fork 和父不共享
可变嵌套的消息部分。

现有的 fork 构造在发送指令之前仍会修复最终边界。它会丢弃未回答的尾部
用户消息，并在需要时用占位响应关闭打开的模型函数调用。

### 后台复活

所选的初始消息继续使用现有的 fork 引导记录。因此转录恢复会以与原始执行
相同的选择历史、启动时系统指令、工具和任务 prompt 复活一个有界历史的
fork。

## 兼容性与风险

现有的 fork 调用保持为完整历史的 fork，因为省略时默认为 `all`。现有的
常规子代理和 teammate 调用保持隔离。数值窗口可能省略较早的事实或压缩
摘要，因此指令必须重复 fork 仍需要的任何较早上下文。它还会缩短可复用的
会话历史缓存前缀，而父系统提示词、工具和启动上下文保持共享。
