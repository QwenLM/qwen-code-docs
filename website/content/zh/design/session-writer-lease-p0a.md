# 会话写入者租约 P0a

## 问题

当一个持久化会话的原始进程仍在生成并记录一个轮次时，目前第二个 Qwen 进程可以加载该会话。两个记录器缓存了相同的父 UUID。当它们独立追加时，JSONL 转录会从该父节点产生两个未标记的子节点。恢复（resume）沿物理尾部前进，因此可能隐藏第一个进程的完整回答。

生产事故正是这个顺序：原始进程记录了一个工具结果，daemon 全新加载了该会话，原始进程记录了剩余的工具工作和最终回答，随后 daemon 使用较早的工具结果作为父节点记录了一条用户消息。

## 范围

P0a 为每个 ACP/daemon 的 `(runtime base, session ID)` 建立一个跨进程写入者，并保护本事故所涉及的普通线性追加路径。它包括：

- 带死进程恢复能力的原子 owner-token 租约；
- 获取租约后的权威转录重载；
- 每次 JSONL 追加时的 owner、文件身份和字节长度围栏；
- 在用户、cron、通知和 teammate 工作开始之前的轮次准入；
- 在单个 daemon 内部复用已存活的会话；
- 用于实时转录重放和 Desktop 历史刷新的带 owner 围栏的读取；
- 确定性的 ACP/HTTP 冲突错误；以及
- 会话关闭和初始化失败时的租约 drain 与释放。

P0a 不会将会话切换、回退（rewind）、分支/fork、工作目录迁移、归档/删除/重命名维护或转录修复变为事务性操作。它也不引入一个把同一 daemon 内所有加载/恢复都对照关闭进行串行化的初始化中注册表条目；重复加载会在该 owner 注册之后复用它，而跨进程租约在初始化期间仍然拒绝第二个写入者。完整的加载/关闭结果合并属于 P0b。当某个 ACP Config 持有租约时，会话切换和持久化根迁移会 fail closed（失败即拒绝）。ACP 的逻辑工作目录变更仍然受支持，因为它使记录器和 SessionService 保持绑定到原始持久化根。同 owner 的回退加载在记录器写入围栏之下通过该 Config 固定的 SessionService 进行；重命名和分支保留其现有的记录器或复制前 flush 路径。daemon 的归档/删除以及对非存活会话的维护保留其现有语义。来自存活 owner 之外的并发维护仍然不受支持，属于 P0b 边界。交互式和 headless CLI 记录器保留其现有的无租约行为，使 `/clear`、`/resume`、`/branch` 和 `/cd` 不回退；在 P0b 扩展协议之前，它们不得与 ACP owner 并发写入同一会话。

该协议由 `experimental.sessionWriterLease` 门控，默认禁用。生效值在 ACP 子进程启动时从引导 Config 快照，并对该进程服务的每个会话保持固定；按会话的设置重载无法改变它。启用它需要重启进程。该设置只影响 ACP/daemon 记录器；即使启用了该设置，交互式和 headless 记录器仍继续使用传统路径。

## 不变量

1. 在一个 runtime base 之下，至多一个协作的 ACP 进程拥有会话写入者租约。
2. 已持有租约的 ACP 记录器在拥有租约并在持有期间重载转录之前处于非活动状态。
3. 租约之前加载的预览数据绝不会成为记录器的权威尾部。
4. 每次持有租约的 ACP 追加都会验证 owner token、硬转录状态和字节长度。仅时间戳漂移只有在稳定的内容验证之后才被接受。
5. 所有权或转录完整性失败会永久拒绝该持有租约的 ACP Config 中后续的顶层轮次。
6. daemon 绝不会为已在该 daemon 中存活的会话构造第二个可写 Config。
7. 存活条目只在其记录器 drain 并释放租约之后才被移除。
8. 运行时输出根按 Config 固定，使锁和转录不会通过不同的异步工作区上下文解析。

## 租约协议

锁存储在：

```text
<runtime base>/tmp/session-writer-locks/<encoded session id>.lock
```

其不可变记录包含一个随机 owner token、PID、主机、进程类型、获取时间、Qwen 版本以及（可用时）稳定的操作系统进程启动身份。Linux 使用内核 boot ID 加进程启动 ticks，因此墙钟校正不会使存活 owner 显得陈旧。Darwin 将进程启动探测归一化到 C locale 和 UTC，使两个环境不同的进程比较的是同一身份。当平台可靠地暴露该信息时，该身份能区分 PID 复用。外来主机的 owner 以及任何无法证明其安全性的状态都会 fail closed（失败即拒绝）。

获取操作会创建一个完整写入的临时记录，并原子地将其链接到锁名。有效的存活 owner 返回 `session_writer_conflict`。有效的已死亡本地 owner 可以被重命名、重新检查并回收。回收守卫构成有界的 owner 世代（generation），使回收者自身崩溃时另一个进程能够恢复。畸形、符号链接或非常规的锁会返回 `session_writer_unavailable`，而不是被猜测为陈旧。

租约会快照转录是否存在、其文件身份、安全元数据、字节长度以及内存中的增量 SHA-256 状态。存在性、长度、device/inode、mode、owner/group 和链接计数的变化会 fail closed（失败即拒绝）。创建、变更和修改时间戳是建议性的：仅时间戳漂移会触发通过一个文件句柄进行的稳定全内容检查，只有摘要未变时才被接受。不改变 mode 的扩展属性和 ACL 条目不会单独纳入指纹。当此类操作表现为时间戳漂移时，如果所有硬状态保持不变，则在同样的内容检查之后被接受；如果文件系统未暴露可观察到的时间戳差异，则该操作不会被检测到。`appendJsonLine` 在打开其追加句柄之后应用同样的检查，用已知字节推进候选摘要，并且只有在持久的追加成功、写后路径验证和最终 owner 检查之后才提交摘要和期望状态。新转录的创建使用独占创建。

获取一个已存在的转录会执行一次 O(n) 的流式读取以建立摘要基线，使用上限为 1 MiB 的缓冲区；普通追加保持增量。调和扫描要求时间戳从其读取前状态到读取后状态保持稳定，并且对仅时间戳的不稳定最多重试三次。这个稳定性区间是必要的，因为即使有非协作写入者在读取游标之后改变了已读取的偏移，顺序摘要仍可能与期望内容匹配。如果时间戳持续变化，租约会返回 `session_writer_unavailable`，而不是接受一个可能撕裂的快照。

增量摘要是存活进程的兼容性检查，而不是认证交接的持久化证明。非协作写入者仍然可以在追加期间覆盖一个等长前缀，而不在本进程的某次状态观察中留下可见的时间戳差异。封闭这个既有边界需要无条件的 O(n) 写后扫描，会使重复追加变成二次复杂度，超出 P0a 范围。

## 激活与关闭

当功能门控启用时，ACP 的 `Config.initialize()` 会在扩展、hook、工具、模型或调度器初始化之前获取租约。在持有租约期间，它会解析 active/archive 状态、在存在活动转录时重载它、验证转录在重载期间未发生变化、替换锁前的任何预览，并激活记录器。未选择启用的 ACP Config 和所有非 ACP Config 继续走传统记录器路径，不获取此 P0a 租约。

任何后续的初始化失败都会关闭记录器并释放租约。正常关闭和 ACP 会话关闭会定稿挂起的元数据、drain 记录器队列、释放 owner token，然后才移除存活会话条目。清理会进行身份检查，使失败的较旧初始化无法关闭较新的同 ID 条目。获取清理使用租约的单飞精确记录释放；终态失败会保留主锁，后续的释放调用会观察到同样的失败而不是尝试第二次重命名，另一个写入者保持被围栏状态，直到进程退出恢复。明确的子进程拒绝会使会话保持存活，以便可以重试关闭。关闭的 drain 是有界的；超时或传输失败的结果未知，因此桥接会终止共享的 ACP 通道，其进程拥有的租约随之可作为陈旧状态恢复。该通道上的其他会话也会被该恢复动作回收。

## 错误契约

| 类型                         | JSON-RPC | HTTP | 含义                                                    |
| ---------------------------- | -------: | ---: | ------------------------------------------------------- |
| `session_writer_conflict`    | `-32020` |  409 | 另一个存活进程拥有该会话。                              |
| `session_writer_lost`        | `-32021` |  409 | 该 Config 不再拥有其锁。                                |
| `session_transcript_changed` | `-32022` |  409 | JSONL 在期望的追加序列之外发生了变化。                  |
| `session_writer_unavailable` | `-32023` |  503 | 无法安全地验证所有权。                                  |

外部响应使用固定消息和 `errorKind`；它们不暴露 PID、主机、owner token、锁路径或转录路径。

没有先前常规文件基线的符号链接或非常规转录路径是 `session_writer_unavailable`。一旦租约建立了常规文件基线，将该路径替换为符号链接或其他非常规文件就是外部转录替换，归类为 `session_transcript_changed`。

## 兼容性与推广

该协议只协调启用了该功能的 ACP 写入者。部署和回滚必须在启用或禁用该设置之前 drain 旧的 ACP/daemon 写入者进程。混合版本或混合配置的 ACP 运行是不安全的，因为传统写入者会忽略锁。对同一持久化会话的并发交互式或 headless 访问仍然在 P0a 之外，在 P0b 之前不受支持。

运行时文件系统必须支持同目录硬链接且具备原子的 no-replace 行为。如果该前提不可用，获取会以 `session_writer_unavailable` fail closed（失败即拒绝）。

既有的分支转录不会被自动修复。P0a 在推广之后防止新的陈旧加载分支；修复和显式分支语义仍然是独立的工作。

## 验证

单元测试覆盖默认关闭和显式选择启用的门控、锁争用、死 owner 和崩溃回收者的恢复、畸形和非常规锁、并发 owner-token 释放、有界的释放预检查、终态清理失败、被截断和被外部修改的转录、仅时间戳的调和、等长就地替换与原子替换、安全元数据变化、UTF-8 字节计数、记录器激活/围栏/关闭、权威重载、初始化清理、运行时根固定、轮次准入、同 daemon 重放复用、禁用记录的兼容性、传统交互式记录器行为，以及错误净化。Darwin 覆盖还验证不同时区的进程推导出相同的 owner 身份。PID 复用处理已实现，但由于进程启动探测依赖平台，不作为测试证据声明。

在功能门控启用的情况下，一次真实的双进程回归重现了事故时序：进程 A 在工具结果尾部之后持有写入者，进程 B 在作为写入者加载之前被拒绝，A 追加其最终回答并关闭，然后 B 获取、重载该最终回答，并以最终回答为父节点追加下一条用户记录。

Desktop 覆盖验证写入者冲突会呈现给用户，而不是静默地用一个全新会话替换所请求的持久化会话。实时历史刷新通过 owner 的写入围栏和 Config 固定的 SessionService 提供，包括在逻辑 `/cd` 之后。
