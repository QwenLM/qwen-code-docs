# 整轮多模态路由

## 范围

本设计只实现 #6988 的 Phase 1：当主模型是纯文本时，一个显式具备
agent 能力的视觉模型可以处理完整的带图轮次。

它不添加持久路由状态、会话恢复、持久视觉摘要、稳定图片引用、历史媒体
清理或后续的图片复查。

## 能力闸门

整轮路由要求同时具备图片和 agent 能力：

```json
{
  "id": "vision-agent",
  "capabilities": {
    "vision": true,
    "agent": true
  }
}
```

`agent` 能力缺失或为 false 时保持既有的 vision bridge 转录行为。

## 路由

- 如果主模型接受图片，使用既有的主模型路径。
- 如果所选的视觉模型不具备 agent 能力，通过 vision bridge 转录并在主
  模型上回答。
- 如果所选的视觉模型具备 agent 能力，保留原始图片部分并设置一个轮次本
  地的精确模型选择器。
- 精确的 provider、模型和端点会被复用于 provider 重试、工具执行、工
  具结果续接和阻塞的 ACP Stop Hook 续接。
- 无头模式的工具执行收到与所选图片模型相同的运行时视图；排队的通知和
  cron drain 仍是独立轮次，不继承它。
- 该轮次禁用已配置的回退模型。无法解析精确路由会 fail closed（失败即
  拒绝），而不是把原始图片数据发给主模型。
- 下一个独立的用户轮次清除选择器并回到主模型。每次模型请求，包括旁路
  查询，都只收到其精确目标支持的媒体模态。

整轮选择器在既有的 `model\0baseUrl` 表示上添加一个尾部 NUL 标记。聊
天层在模型解析之前移除该标记。这使普通的端点限定模型选择保持既有行
为。

## 上下文限制

基于 LLM 的自动聊天压缩保持在主模型路径上。整轮路由跳过该压缩，因为
当图片轮次由另一个 provider 拥有时运行主模型压缩会违反精确路由保证。
既有的本地历史 microcompaction 和图片载荷瘦身仍然适用，请求/缓存副本
只保留其目标模型支持的媒体模态。因此一个超大的整轮请求会在所选模型上
失败。

## 入口点

Phase 1 覆盖交互式 TUI、ACP 和非交互式 CLI。

文本 `@` 路径在 MIME 检测、工作空间检查、ignore 过滤和文件读取之前被
解析到其规范目标。用户提供的别名和规范目标都必须通过 ignore 过滤，因
此符号链接无法伪装被忽略的文件或非图片目标。硬链接不由 `realpath` 解
析，不在该检查覆盖范围内。
