# 后台 npm 更新

## 问题

已发布的 CLI 被代码分割为按内容哈希的 JavaScript chunk。在一个激活会话
中运行 `npm install -g` 会就地替换这些 chunk，因此旧进程中后续动态导入
可能以 `ERR_MODULE_NOT_FOUND` 失败。将安装推迟到会话退出可以避免损坏，
但这会把后台更新变成退出时的延迟，并且用户在离开会话之前得不到任何收益。

## 设计

对于可写的全局 npm 安装，渲染后更新检查会将精确解析出的版本安装到一个由
全局启动器派生的目录下：

```text
~/.qwen/updates/npm/<launcher-id>/versions/<version>/
```

版本检查在全局上下文中运行 npm，暂存安装使用隔离的 prefix。暂存命令显式
保留原始的全局 npm 配置，因此更改 prefix 不会在发现和安装之间切换 registry
或认证设置。

启动器在选择版本之前从相同的家目录作用域 `.env` 文件解析 `QWEN_HOME`。
这使得引导路径与 CLI 存储保持一致，尽管完整的环境加载器稍后才运行。

安装和激活在分离的 worker 中运行，因此退出 TUI 不会中断已在进行中的更新。
在 npm 成功退出后，worker 校验包名、版本、bundle 和启动器，然后在该启动器
的版本旁原子地写入一个 `active.json` 指针。全局 npm 包不被修改。已在运行
的进程及其启动的任何子命令保持钉在原始构建上。下一次调用时，稳定的启动器
读取指针并启动已校验的版本目录。

每个全局 npm 启动器都有自己的指针和版本负载，因此不同 npm 或 nvm prefix
下的安装可以共享 `~/.qwen` 而互不覆盖、也不共享依赖。较慢的并发更新无法
替换较新的激活版本。

不完整的安装绝不改变激活指针。在激活之前，worker 会校验已安装的 manifest
并运行启动器冒烟测试。缺失、畸形或与启动器不匹配的指针会被忽略，原始 npm
包仍然是回退。指针还记录基础包和启动器身份，因此之后显式的全局 npm 安装
会取代托管版本。由于启动器不会被托管更新替换，现有的 `active.json` 字段
构成兼容性契约：未来的变更可以增加字段，但不得移除或重新解释它们。

版本目录会被保留，因为较旧的存活会话可能仍从它们加载。清理有意推迟，直到
磁盘用量表明需要基于租约的收集器。

## 范围

这只改变 npm 安装的自动更新。其他包管理器和独立发行包在拥有等价的不可变
版本安装布局之前，保持现有的退出安全行为。
