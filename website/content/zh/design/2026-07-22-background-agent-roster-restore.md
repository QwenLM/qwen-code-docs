# 后台代理名册恢复

## 背景

后台代理的 sidecar 和 JSONL transcript 持久化逻辑身份与历史，而 `BackgroundTaskRegistry` 索引当前会话可寻址的任务。恢复加载器目前只恢复停留在 `running` 状态的 sidecar。因此已完成的代理在其父会话恢复后会从注册表中消失，即使它们的 transcript 仍然可用。模型也没有查询注册表的工具。

## 目标

- 以原始任务 ID 恢复最近已完成的后台代理。
- 新增一个模型可调用的 `list_agents` 工具，用于按需发现。
- 保持 `send_message(task_id)` 作为续接操作。
- 在恢复后给模型一条简短的一次性提醒。
- 对 TUI、无头模式和 ACP 入口应用相同的恢复行为。

## 非目标

- 跨进程销毁持久化一个活跃的 JavaScript 运行时。
- 替换 Agent Teams 的 `task_list` 工具。
- 恢复失败或被取消的代理。
- 重建临时 worktree 隔离。

## 设计

会话目录扫描同时接受 `running` 和 `completed` 的 sidecar。运行中的条目变为已暂停，保留现有的中断工作行为。已完成的条目保持已完成，被标记为已通知，并保留 `send_message` 复活所需的 transcript 和元数据路径。

新的 sidecar 会持久化原始启动是否为后台运行。只有当该标记显式为 true 时才恢复已完成条目，因此前台的和旧版未标记的已完成 sidecar 不会作为可复用的后台代理暴露。旧版运行中的 sidecar 保留现有的恢复行为。

加载器在注册之前验证 sidecar 文件名和父会话所有者。一个被保留但 transcript 缺失、transcript 身份不匹配、隔离不兼容或工作目录冲突的行仍然可见，但被标记为不可续接。worktree 隔离的行以同样方式处理，因为其临时所有权上下文无法被安全地重建。只有最新的被保留已完成条目会被恢复；运行中的条目不受该上限约束。

`list_agents` 读取实时注册表并返回后台代理，包含稳定的 `task_id`、描述、类型、状态、续接能力和任何阻塞原因。它不扫描磁盘。该工具由调用方拥有，并对 subagent 和 teammate 排除。

恢复之后，下一个普通的顶层用户提示会收到一条系统提醒，调用 `list_agents` 然后调用 `send_message`。斜杠命令和被中断轮次的延续不消费这条提醒。Bare 模式不会收到它。

会话切换会在加载新名册之前清空内存中的注册表。失败的恢复回滚会在恢复旧会话之前清空部分恢复的条目，并且在后台工作仍然活跃时阻止分支切换。

## 验证

- 运行中和已完成的 sidecar 以稳定 ID 和正确状态恢复。
- 前台的和所有者的 sidecar 被排除。
- 不安全的被保留状态可见但无法续接。
- 恢复的已完成条目不发出重复的完成通知。
- `send_message` 可以复活一个兼容的已恢复已完成条目。
- TUI、无头模式和 ACP 恢复名册并只投递一次提醒。
- 新建、清空、分支和失败恢复路径不会泄漏先前的名册。
