# 默认后台子代理

## 总结

顶层一次性子代理应默认在后台运行。需要内联结果的调用方可以用 `run_in_background: false` 退出。嵌套的子代理启动和固定到调用方拥有的 `working_dir` 的启动保持前台操作，因为当前的后台生命周期无法安全地把结果返回给这些调用方。Fork 和具名的 Agent Teams 队友保持其现有行为。

## 动机

Agent 工具已经支持跨交互式、无头模式和 SDK 消费者的后台执行，但调用方目前必须用 `run_in_background: true` 来请求，或选择一个声明了 `background: true` 的代理。这使得普通委派即使在父级可以继续独立工作时也默认阻塞父级。把后台执行作为顶层默认值更符合该工具的并行委派指引，同时为依赖结果的工作保留显式的前台逃生通道。

## 目标

- 当省略 `run_in_background` 时，顶层一次性子代理在后台运行。
- 保留 `run_in_background: false` 作为显式的前台退出。
- 保留现有的完成通知、取消、并发、权限、transcript 和无头模式保留路径。
- 让不安全或不支持的启动形态保持在其现有的前台路径上。
- 记录对需要内联结果的 skill 和调用方的兼容性影响。

## 非目标

- 嵌套子代理启动的后台执行。
- 调用方拥有的 `working_dir` 中的后台执行。
- fork 上下文继承或 fork 生命周期的变更。
- 具名 Agent Teams 队友行为的变更。
- 用于该默认值的新全局设置。
- 重新设计后台通知路由或任务归属。

## 行为

运行时按以下顺序解析一次性子代理的执行：

1. 具名的 Agent Teams 队友使用现有的队友路径。
2. 有效的顶层 fork 使用现有的分离 fork 路径。
3. 嵌套的普通子代理在前台运行，即使请求了后台，使其结果返回给嵌套调用方。
4. 带 `working_dir` 且未配置后台默认值的普通子代理在前台运行，因为调用方拥有该 worktree 的生命周期。显式或配置的后台请求保持无效。
5. 对于任何其他顶层普通子代理：
   - `run_in_background: false` 在前台运行。
   - `run_in_background: true` 在后台运行。
   - 省略 `run_in_background` 在后台运行。

现有的代理级 `background: true` frontmatter 为兼容而继续被接受。要获得新的顶层默认值已不再需要它。显式的工具调用值 `run_in_background: false` 优先，并选择前台路径。

## 实现

分发决策保留在 Agent 工具中，使每个消费者获得相同的行为。后台决策应区分三个概念：

- 调用方是否显式退出；
- 启动是否是顶层的；
- 启动形态是否可以安全分离。

实现应复用现有的后台分支，而不是添加第二条启动路径。工具 schema 文本和面向模型的使用指引应把后台描述为默认值，并告诉调用方在需要内联结果时传入 `run_in_background: false`。

`working_dir` 例外必须在现有的不兼容守卫之前解析。省略的后台参数不得把之前有效的固定评审启动变成错误。显式的 `run_in_background: true` 或配置了 `background: true` 的代理仍与 `working_dir` 不兼容，保留现有的安全检查。

## 结果流

默认后台启动立即向父级返回现有的后台启动响应。分离的任务继续注册在现有的后台任务注册表中。当它终止时，注册表发出现有的完成、失败或取消通知，父级在之后的轮次中处理结果。不引入新的消息格式或 SDK 事件。

前台退出继续走现有的同步分支，并内联返回净化后的子代理结果。

## 文档

子代理用户指南应说明具名一次性子代理在顶层默认在后台运行，并解释 `run_in_background: false`。Fork 对比应聚焦上下文继承和结果语义，而不是声称所有具名子代理都阻塞父级。

## 测试

单元测试覆盖应验证：

- 省略标志的普通顶层子代理在后台启动；
- `run_in_background: false` 内联返回结果；
- `run_in_background: true` 保留现有后台行为；
- 省略标志或标志为 true 的嵌套启动保持前台；
- 省略标志的 `working_dir` 启动保持前台；
- 带 `working_dir` 的显式后台请求保持被拒绝；
- fork 和具名队友行为保持不变；
- 工具 schema 和使用指引宣告新的默认值和退出方式。

有意演练前台分支的现有测试应传入 `run_in_background: false`，使其期望显式化。聚焦的 Agent 工具测试文件、build 和 typecheck 在提交前是必需的。一次手动的交互式 E2E 检查应确认：普通委派立即交还控制权并在之后投递完成通知，而显式前台委派阻塞并内联返回其结果。

## 风险与兼容性

对于省略标志并假设 Agent 工具响应包含子代理结果的 prompt、skill 和程序化调用方，该变更在行为上是破坏性的。这些调用方必须传入 `run_in_background: false`。

默认后台执行还可能增加并发工作。现有的全局并发上限和排队仍是控制性保障。权限处理、关闭和无头模式等待已经使用既定的后台任务生命周期，本设计不改变它们。
