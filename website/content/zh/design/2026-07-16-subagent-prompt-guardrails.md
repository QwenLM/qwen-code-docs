# 子代理 Prompt 护栏

## 动机

Agent 工具目前鼓励宽泛的并行委派，并表示子代理输出通常应被信任。内置 prompt 也缺少一些执行和验证方面的期望，而 Explore 和 fork 的 prompt 包含不安全或自相矛盾的指引。

## 设计

- 告诉父代理只委派有界的、独立的工作，把即时的关键路径工作留在本地，避免重复工作，并给并行编写代码的代理不相交的写入范围。
- 要求父代理在集成或转达子代理结果之前审查其声明和代码变更。
- 简化通用 prompt，并添加范围、保留、验证、不确定性和结构化报告的期望。
- 通过从 Explore 的允许列表中移除 task、memory 和 user question 工具来收窄其有状态工具面。允许 shell 管道，同时继续在其 prompt 中禁止写入。
- 除非指令显式要求提交，否则不再要求 fork 代理提交变更。

上下文继承和默认后台执行行为不在此变更范围内。

## 验证

聚焦的单元测试断言父代理指引、内置 prompt 内容、Explore 的工具允许列表和 fork 报告规则。core 包的 build 和 typecheck 提供更广泛的编译时检查。
