# cua-driver MCP 可靠性加固

## 问题

MCP 代理最多等待 120 秒的 daemon 响应。多条 macOS 工具路径可能在同步 OS 调用中阻塞超过这个时间。代理随后发出通用的 JSON-RPC `-32603`，而被放弃的操作和子进程继续运行。另外，捕获范围会同时从内存和磁盘读取，因此一个 MCP 会话在 `set_config` 报告成功后仍可能观察到互相矛盾的值。

## 设计

### 每个会话一份有效配置

把 `capture_scope` 当作现有的会话级图像尺寸覆盖来处理。MCP 调用从调用方的 `_session_id` 解析它；匿名 CLI 调用使用全局持久化的默认值。`set_config`、`get_config` 和 `get_desktop_state` 必须都通过同一个 `ToolState` 解析。匿名持久化发生在内存值提交之前，写入失败会返回给调用方。

### 从应用枚举中移除子进程

活跃应用使用 `NSWorkspace.runningApplications`，已安装应用使用 Core Foundation bundle 元数据。这从 `list_apps`、`get_accessibility_tree` 和 `launch_app` 的发现路径中移除了 `osascript` 和 `plutil`，而不是试图为每个已安装的 bundle 猜一个安全的超时。

### 为截图捕获设置上限并终止

保留现有的 `screencapture` 后端，但通过一个有上限的 helper 来 spawn 它。到达截止时间时，先杀掉并回收该进程，再返回工具错误。每次捕获使用唯一的临时路径名，并加上 RAII 清理守卫，使并发调用不会互相冲突、失败也不会留下残留文件。

### 把 AX 与 daemon 工作限定在代理截止时间之下

在树遍历和元素操作之前设置原生 AX 消息超时。增加一个短于代理 120 秒传输截止时间的 daemon 侧工具截止时间，作为最终的兜底。内部上限通常应先触发；daemon 截止时间确保未预料到的工具卡死变成工具级错误，而不是 `-32603`。

### 隔离 fork 的 daemon 端点

使用 Qwen 特有的默认 Unix socket 和 PID 目录。旧的上游 daemon 可以继续在上游默认值上运行，但 Qwen 代理不会再悄悄复用它，从而执行与用户启动的二进制不同的实现/版本。显式的 `--socket` 覆盖保持不变。

### 保留生命周期诊断

记录会话被墓碑化的原因（显式结束、空闲过期或连接结束），并在拒绝文案中包含该原因。保留显式的 `start_session` 复活。调高默认空闲 TTL，使一个正常的长 agent 轮次不会在五分钟后就失去会话；环境覆盖仍然可用于测试和部署。

### 让 E2E 测试执行 fork 二进制

在共享 testkit 中解析 `qwen-cua-driver`。当 fork 的二进制以其真实名称存在时，缺失二进制不得再把预期的 E2E 断言变成零秒通过的跳过。

## 非目标

- 修改 MCP JSON-RPC 协议或重试破坏性操作。
- 让 Tokio 能够取消任意的外部阻塞调用；OS 子进程直接杀掉，AX 接收其原生消息超时。
- 修改坐标归一化行为。

## 验证

运行与修复前复现所用的同一套隔离 proxy/daemon 黑盒用例：配置持久化失败、应用枚举 shim 卡死、截图 shim 卡死，以及短会话 TTL/复活。两个卡死用例必须在代理 120 秒截止时间之前返回，不留下子进程，并允许立即发起后续调用。
