# Shell 安全性分类

## 背景与范围

Issue [#6949](https://github.com/QwenLM/qwen-code/issues/6949) 要求 Plan 模式区分已被证明为只读的命令与无法静态确定其行为的命令。布尔值无法保留这种区分，因此本改动在 `shellAstParser.ts` 中引入了一个三态事实层，而不改变权限路由。

本改动不修改 Shell、Monitor、PermissionManager、speculation、内存作用域代理、ACP、Plan 模式提示词或 Plan 退出行为中的路由或调用点逻辑。在分类器被加固的地方，现有的布尔消费者可以变得更保守。后续改动可以利用新的事实地将 `unknown` 命令路由到一次性审批，而无需修改本分类器。

## 契约

`classifyShellCommandSafety(command)` 是一个内部模块 API，其结果如下：

| 结果        | 含义                                                                                                                             |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `read-only` | 每条可执行路径都由当前规则证明不会修改持久或外部状态。                                                                           |
| `write`     | 语法中包含文件、Git、进程或其他状态变更的正面证据。该命令最终是否成功并不重要。                                                 |
| `unknown`   | 该命令无法由受支持的静态规则证明为安全或会变更。                                                                                 |

对于有效的 AST，结果按 `write > unknown > read-only` 的顺序合并。包含 `ERROR` 的树会在评估部分语法之前被归类为 `unknown`。命令替换和进程替换在其可执行内容被扫描期间施加 `unknown` 下限，因此嵌套的已知写入者会将结果提升为 `write`。重定向分析负责重定向节点内部的替换，而命令和语句评估器将这些节点排除在其替换扫描之外，防止对嵌套替换的重复遍历。控制流使用相同的 unknown 下限并扫描可能的分支。函数定义不是执行，因此保持 `unknown`，而不会将其函数体归类为已执行的写入。

独立的纯赋值和 `cd` 保留现有的兼容行为。为命令加前缀的赋值，或与另一语句共享复合序列的赋值，会施加 `unknown` 下限，因为诸如 `LD_PRELOAD`、`PATH`、`PAGER` 或工具特定配置之类的变量可以改变行为；显式的写入证据仍然获胜。子 shell 和命令组聚合其已执行的内容。该 API 只分析提供的源码字符串；它不解开 `sudo` 或解释器，不解析 PATH 或别名，也不加载 shell 配置。

## 解析器故障与兼容 API

私有分类器在加载或运行 tree-sitter 时可能抛出异常。公共的三态 API 将这些故障映射为 `unknown`，并且绝不用正则表达式来替代确定性判断。在解析过程中抛出异常的解析器会被丢弃，并从已加载的 Bash 语言重建，因为失败的实例可能已被污染；这不会重新加载运行时或语言。现有的 `isShellCommandReadOnlyAST()` 兼容 API 仅在结果为 `read-only` 时返回 `true`，但当 tree-sitter 无法加载或在运行时抛出异常时保留现有的正则回退。语法无效的树是正常的 `unknown` 结果，而不是解析器故障，因此永远不会进入该回退。每个成功返回的树都会在 `finally` 块中释放一次。

这种不对称是有意的：新消费者需要诚实的不确定性事实，而现有的布尔消费者保持其解析器可用性行为，直到它们显式迁移。

## 受支持的证据

分类器识别一个有界的、大小写敏感的直接文件系统写入者、进程信号命令、输出重定向、Git 变更族集合，以及 `find`、`sed`、`awk`、`sort`、`tree`、`uniq`、`tee` 和 `dd` 中的显式写入模式。Sed 和 AWK 使用共享的线性扫描器来区分内联程序与选项值和文件参数，因此转义的、畸形的或高度重复的输入无法触发正则回溯，也无法从文件名伪造写入证据。`diff`、`log` 和 `show` 的 Git 输出文件是写入。有状态的 `printf -v` 形式是 unknown。显式的 Git 辅助功能和签名验证——包括 pager/config 环境选项、diff/text-conversion 辅助功能、grep 的外部 pager 和签名占位符——是 unknown；不受支持的 Git 全局选项和子命令 help 路径也会 fail closed（失败即拒绝），因为 help 可能启动外部查看器。动态执行、外部脚本、模糊的输出目标、解释器和包装器、`sort --compress-program`、ripgrep 预处理器、主机名辅助功能以及归档搜索（`--pre`、`--hostname-bin`、`--search-zip` 和 `-z`），还有普通的 pager 命令，都保持 `unknown`。选项终止符和受支持选项的值元数会被解释，因此字面上名为 `--help` 的文件名或消息不会被误认为 help 调用。大小写不同的命令名、未列出的包管理器、服务和自定义可执行文件也保持 `unknown`；分类器不是沙箱。

已弃用的同步检查器镜像了同步调度所需的每个新拒绝模式。它用哨兵保留参数展开，而不是允许 `shell-quote` 擦除它们；拒绝畸形的尾部管道和带赋值的复合结构；并从原始命令评估包装器。它有意保持布尔语义，且比 AST 分类器更保守：`printf`、选项繁多的 `sort`、`tree`、`uniq`、`rg` 和 `ripgrep` 命令，以及超出最简单列表模式的 Git 分支形式，都会顺序执行。

## 消费者与迁移边界

当前的布尔消费者是 Shell、Monitor、PermissionManager、speculation 门控和内存作用域代理配置；它们的调用点在本次重构中不变。同步检查器还被核心工具调度器和传统的 shell 权限工具使用。调度器现在将原始命令传递给检查器，使包装器保持 unknown，而不是被解开成一个看似只读的命令。`extractCommandRules()` 保持独立于安全性分类。

后续的 `fix(core): Route unknown Plan shell commands to one-off approval` 应当只在 Plan 权限边界处消费 `classifyShellCommandSafety()`。它必须单独定义审批的 provenance、生命周期、ACP 行为，以及与 Plan 退出的交互；这些策略不属于事实层。

## Claude Code 参考

Claude Code 的 Bash 分析可作为两个设计原则的证据：解析不确定性必须被显式表示，并且当解析不可用或过于复杂时，权限决策必须 fail closed（失败即拒绝）。它更大的 Bash 解析器和策略引擎不会被复制，因为 Qwen Code 在当前边界只需要一个小型分类器。

## 验证

单元测试覆盖使用表驱动矩阵验证所有三种状态、复合优先级、替换、语法错误、解析器初始化和运行时故障、对对抗性嵌套和转义输入的有界行为，以及兼容单调性。同步检查器和调度器测试防止新知的不安全命令加入并发的 Shell 批次。
