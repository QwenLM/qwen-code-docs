# 实时日志截断恢复

## 背景

daemon 为未完成的轮次维护一个有界的内存中实时日志（live journal）。当日志
超过 10,000 个事件或 8 MiB 时，它会丢弃最旧的重放事件，并在开头添加一个
`history_truncated` 标记。持久化的转录（transcript）和轮次边界压缩仍然是
权威的，因此在正式终结事件之后，完整的轮次会再次变得可用。

该标记之前没有 prompt 归属，SDK 渲染一条通用消息，WebUI 要么把标记藏在
历史分页之后，要么让保留的尾部永久可见。本设计保留现有的资源限制和逐出
策略，同时使丢失信息精确化，并在不发起另一次模型请求的情况下修复可见的
尾部。

## 协议与 SDK

对于 `session/load` 返回的实时日志标记，桥将会话权威的 `activePromptId`
复制到标记 envelope 上，作为可选的 `promptId`。持久化事件和事件 schema
版本不变。没有该字段的较旧 daemon 只有在保留的实时事件恰好有一个 prompt
ID 时才可修复。

`DaemonHistoryTruncatedData` 暴露现有的可选 `scope` 和 `maxEvents` 字段。
校验拒绝畸形的可选值。归一化的状态数据保留完整的 daemon 负载。文本区分
重放历史截断和实时轮次截断，说明保留了最新事件并丢弃了较旧的重放事件，
并且仅在 `fullTranscriptAvailable` 为 true 时承诺终结后恢复。

## WebUI 恢复段

在快照重放期间，一个可恢复的实时标记会在该标记紧前方创建一个检查点。该
检查点复用不可变的转录块，并保留会话 ID、目标 prompt ID、快照事件水位线、
标记块 ID 和确定性的段签名。在标记激活期间，较旧的历史页和 provider
本地状态块会被镜像到检查点中。

只有匹配的 `turn_complete` 或 `turn_error` 才会使恢复就绪。取消由带取消
停止原因的正式终结事件表示，并走相同的路径。在尝试恢复之前，缓冲的转录
事件会被刷出，prompt 状态会被结算。进行中的会话加载、历史页请求、导航或
本地 prompt 会将尝试推迟到下一个空闲点。

恢复执行一次同会话的 `session/load`，使用内存中重放，不使用配置的历史
页大小。在校验成功之前，当前转录保持附加和可见。新快照必须未降级，且
必须同时包含目标 prompt 的用户输入和匹配的正式终结。校验失败或可重试的
传输失败会拒绝替换，从其 SSE 游标恢复前一个会话句柄，保留转录，并发出
一条可恢复的 `daemon.live_journal_repair.failed` 通知。认证失败和会话
缺失同样保留转录并发出通知，但保留 provider 现有的断开或重新认证状态，
因为该 SSE 流无法安全恢复。

成功后，WebUI 从最早的匹配用户输入到新快照尾部重建目标后缀。当标记块仍
被保留时，它从检查点开始；否则重建一个有界的完整快照。重放的事件重建
转录状态（包括 `assistant.done`），但等于或低于段水位线的事件不会重复
通知、工作空间信号、挂起 prompt 发布、后续发布或其他副作用。更新的事件 ID
保留其正常效果。

最终状态通过一次 store 重置提交。当完整后缀容纳在检查点的 `maxBlocks`
之内时，保留的历史块 ID、分页游标、已加载深度和容量状态保持稳定。如果
超出该限制，现有的 store 策略可以修剪最旧的已加载块，而不是为修复创建
一个无界的例外。以另一个可恢复实时标记结尾的新后缀会为那个 prompt 创建
一个单独的段。

## 并发与生命周期

一个段至多自动尝试一次。配置的重新加载、会话切换、页面卸载或显式会话
清除会中止并移除它。修复性重新加载会保留它直到成功或失败。重新加载会
暂停旧的 SSE 订阅，但不解除其会话注册。被拒绝的候选会被解除附加，前一个
句柄从其现有游标恢复；校验通过的候选成为新的订阅所有者。

检查点继承当前转录 store 的有效 `maxBlocks`，而经标记修剪的回退使用配置
的 `maxBlocks`。这保留了现有的超大初始重放行为，而不为修复创建新的例外。
块是共享的而不是复制文本负载，并且不引入无界日志或第二份转录缓存。

## 兼容性

- 标记的 `promptId`、`scope` 和 `maxEvents` 字段是可选的。
- 旧客户端忽略标记 envelope 扩展。
- 新客户端接受旧负载，并安全地拒绝模糊的自动修复。
- 默认的 `reloadSession` 行为保持配置的重放；只有内部修复路径请求内存
  重放。
- Daemon 持久化、转录 API、日志限制和最旧优先逐出不变。

## 验证

单元覆盖演练标记归属、终结后压缩、负载校验、精确的状态文本、prompt 匹配、
重放校验、原子后缀替换、重复副作用抑制、历史保留、失败回退和重新加载
来源传播。Daemon 集成测试使用确定性 mock ACP agent 和三事件日志，从第二
个客户端观察实时标记，验证终结后完整的压缩轮次，并挂载真实的 WebUI
provider 以证明恢复只增加一次加载而不产生模型请求。
