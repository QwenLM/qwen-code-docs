# 后台代理热续接

## 背景

一个已完成的后台 subagent 目前会失去其进程内运行时。之后的 `send_message` 会从 JSONL transcript 重建一个新的 `AgentHeadless`。这保留了大部分可见的会话历史，但会重建 chat、工具表面、每个代理的注册表以及 provider 侧的缓存状态。

启动路径还会把普通后台代理构造两次：一次使用父级 emitter，另一次使用专用的后台 emitter。第一个实例从不被执行或销毁。

本设计处理会话内生命周期。父会话恢复后的逻辑发现与续接由后台代理名册恢复设计单独处理。

这一区分是行为上的，而不仅仅是实现细节。在单个会话内，transcript 复活已经保留了模型可见的会话，因此热续接主要是避免运行时重建，并保留 provider/工具状态。跨越一次父会话恢复，原始的内存中运行时无法在进程销毁后存活。因此逻辑上的连续性来自把任务身份和 transcript 恢复到新会话中，随后进行一次冷重建。

## 目标

- 为一个全新的普通后台代理只创建一个运行时。
- 在成功的轮次之后让该运行时保持常驻。
- 在同一个 chat 和准备好的工具表面上继续一个已完成的任务。
- 保留当前的任务行、任务 ID、每轮次的开始/完成事件和终态通知。
- 当不存在兼容的常驻运行时，保留 transcript 复活作为回退。
- 在失败、取消、会话关闭/重置、终态条目逐出、工作目录变更、分支切换以及 ACP 会话关闭/销毁时释放常驻资源。
- 在发布成功完成之前，原子地认领在收尾窗口中排队的输入。

## 非目标

- 跨进程或跨父会话恢复持久化一个活跃的运行时。
- 向共享的任务状态联合类型添加 `idle` 值。
- 修改消息如何在工具轮次之间注入给正在活跃运行的代理。
- 让 fork 代理持久化。
- 跨已完成的轮次延长临时 worktree 的寿命。
- 让全局注册的 frontmatter hook 在代理空闲时保留安装也是安全的。

## 设计

### 可复用的无头运行时

`AgentHeadless` 把其 `GeminiChat` 和准备好的工具声明作为实例状态保留。其公共的 `execute()` 仍然是每轮次的操作：

- 同一时间只能运行一个调用；
- 最终文本和终止模式在开始时重置；统计数据为新的父级指令重置，但在该指令的内部 stop-hook 重试之间保持累计；
- 第一次调用创建 chat 并准备工具；
- 之后的调用向同一个 chat 追加一个新的用户轮次，并发出外部消息事件，使 JSONL transcript 保持完整。

这保留了现有的 `AgentHeadless` hook、遥测、外部消息 drain 和终态结果契约。不使用 `AgentInteractive`，因为它的队列 API 不提供后台任务所需的每轮次完成结果和通知语义。

### 常驻控制器

`BackgroundTaskRegistry` 拥有一个以任务 ID 为键的内存控制器表。控制器有意与 `AgentTask` 分离，后者仍然是可序列化的 UI/状态记录。

控制器可以：

- 从一个已完成的行开始续接；
- 中止并销毁其运行时。

对于已完成的 `send_message`，该工具首先向注册表请求一次常驻续接。命中会同步地把现有行改回 `running`，认领一个普通的后台执行槽，并在前一轮次完全落定之后调度新轮次。未命中则使用现有的 transcript 复活服务。

`completed` 继续表示“最近的轮次已完成”。运行时常驻是一个内部实现事实，因此共享的任务状态和 UI 不新增空闲状态。

### 每轮次与常驻资源

每次续接都会获得新的中止控制器、SubagentStart/Stop hook 对、trace span、任务开始事件、完成通知和 sidecar 状态转换。需要仅子代理的 AUTO 权限租约的运行时不会被保留，因为这些租约在并发 subagent 之间没有引用计数。

当控制器常驻时，chat、准备好的工具、JSONL 写入器、事件监听器、代理作用域的工具注册表以及每个代理的 MCP 资源保持存活。销毁是幂等的。

现有的终态条目保留上限也约束常驻控制器。修剪一行会销毁其控制器。注册表重置和关闭会销毁所有控制器，包括已完成的。

### 兼容性排除

第一个版本只保留满足以下条件的普通具名后台代理：

- 正常完成；
- 不使用 `isolation: "worktree"`；
- 不声明 frontmatter hook；
- 不需要仅子代理的 AUTO 权限租约。

临时 worktree 目前在每个轮次后终结，因此保留运行时会使其 Config 指向一个已被移除的目录。Frontmatter hook 目前在其生命周期内全局注册，因此在空闲时保留它们可能影响无关的工作。仅子代理的 AUTO 租约会修改父级权限管理器，且在并发 subagent 之间没有引用计数，因此在每个热轮次重新获取它们是不安全的。带 hook 的、worktree 隔离的和仅子代理 AUTO 的代理继续走现有的 JSONL 复活流程。重建的 worktree 代理从当前父级工作目录运行，因为其临时启动 worktree 已经被终结。

## 竞争与失败处理

- 在兼容运行时发布成功完成之前，活跃轮次不让出地 drain 注册表队列。如果它认领了输入，同一个无头运行时执行该输入，任务保持运行。如果队列为空，transcript 持久化和运行到完成的转换同步发生，因此之后的 `send_message` 观察到已完成的行并使用常驻续接路径，而不是收到一个误导性的排队确认。worktree 隔离的轮次在拆除之前执行其最终 drain，因为其运行时在之后有意不可续接。
- 注册表在续接 promise 被调度之前同步执行完成到运行的转换。因此第二个并发的 `send_message` 观察到 `running` 并使用现有的轮内消息队列。
- 下一个轮次链接在前一轮次的 promise 之后，覆盖了完成通知在前一轮次 `finally` 块完成之前发出的窗口。
- 失败和被取消的轮次移除并销毁常驻控制器。
- 如果认领后台槽失败，该行保持已完成，调用方可以使用现有的冷复活错误路径。
- 活跃轮次期间的销毁会中止其控制器，并把破坏性的资源清理推迟到该轮次的终结器。

## 验证

单元测试必须证明：

- 一次全新的后台启动恰好创建一个 `AgentHeadless`；
- 两个顺序轮次使用一个 `GeminiChat` 和一个准备好的工具列表；
- 已完成的 `send_message` 优先使用常驻控制器；
- 没有常驻控制器时仍然调用 transcript 复活；
- 第二条用户指令存在于 JSONL 中；
- 重置、关闭/取消和终态修剪恰好销毁一次；
- `/branch` 拒绝正在运行的后台工作，并且只在分支成功初始化之后才销毁终态常驻者；
- 工作目录变更和 ACP 会话销毁会释放常驻运行时。

E2E 场景使用一个任务 ID 运行两个已完成阶段，并验证第二阶段记得第一阶段的一个 nonce。物理运行时身份由单元测试验证，因为 stream JSON 不暴露构造计数。
