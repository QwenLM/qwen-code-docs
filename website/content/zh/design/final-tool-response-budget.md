# 最终工具响应预算

## 问题

工具输出目前在多个独立的层被缩短。Shell 输出在接近 30K 字符时被缩短
并标记为截断，通用工具输出在接近 2K 字符时被缩短，而当聚合量超过配置
的批次预算时，Core 调度器批次可以卸载输出。这些层不共享结构化状态。

调度器把既有的截断标记当作无需更多工作的证明。因此，多个各自被缩短的
Shell 结果仍可能超过聚合预算。无头模式使缺口更大，因为它为每个工具调
用创建一个调度器，并在这些调度器之外拼接它们的响应。交互模式同样在调
度器定稿之后追加重复和合成的响应。ACP、agent 和 speculation 执行有各自
的聚合边界。

模型请求、可恢复的 transcript 和工具结果记录必须包含相同的有界响应。
面向用户的富工具显示有意不在范围内，可以继续使用既有的结果显示。

## 不变量

1. 每个工具响应批次在发送给模型之前，于最后一个聚合边界处定稿。
2. 当预算有限且为正时，该批次中序列化的工具输出文本不超过配置的聚合
   字符预算。`enter_plan_mode` 生命周期提醒是策略输入，不是工具输出，
   保持内联在此预算之外。
3. 如果生产者已经持久化了输出 artifact，后续层复用这些路径，而不是再
   次写入相同的生产者输出。
4. 聚合定稿使用结构化内部元数据来决定是否可以复用已持久化的
   artifact；它绝不从人类可读文本推断该决定。生产者本地的哨兵处理仍是
   既有截断器的兼容性细节。
5. 定稿保留响应顺序和非文本部分。它只能缩短属于工具响应批次的
   `functionResponse.response.output`、`functionResponse.response.error`
   和顶层文本部分。
6. 定稿的部分也是为重放和恢复而记录的部分。
7. 工具显示保持独立于模型响应。

## 设计

### 持久化元数据

`ToolResult` 和 `ToolCallResponseInfo` 携带一个内部可选的
`persistedOutputFiles` 字段。

- `undefined`：生产者未做出持久化决定。
- `[]`：已做出决定，且没有可复用的文件。
- 非空数组：生产者持久化的输出 artifact 可在这些路径获得。

该字段不包含在 hook 序列化、ACP 载荷、JSON 输出、遥测属性或持久化的
UI 元数据中。由 hook 重建的响应不继承元数据，除非运行时显式复制。

### 生产者级预览

生产者截断控制正常的模型预览，并只持久化一次完整输出。

- Shell 保持当前的 30K 触发器，但返回约 4K 的首尾预览，使退出信息保
  持可见。
- MCP 保持当前的大输出触发器，为面向用户的显示保留完整的转换结果，并
  使用约 2K 的模型预览。
- 通用持久化为主写入器和回退写入器都返回实际写入的路径。

这些预览不是聚合强制。一个已被缩短的响应可能被定稿再次缩短。

### 共享定稿器

一个共享定稿器按原始顺序接受响应以及配置的聚合预算。它衡量所有有界
文本字段，然后缩减文本直到聚合量适配。既有的已持久化路径被复用。没有
可复用路径的响应最多被持久化一次，然后由路径引用替换或伴随其缩短的预
览。

缩减是确定性的。一个最大-最小水位分配在面向模型的文本字段之间共享预
算，同时允许小字段保留完整内容。被缩减的字段保留一个小的首尾预览，并
在分配允许时列出可用的已持久化 artifact 路径。Unicode 代理对绝不被拆
分。最终的硬上限通道在没有 I/O 的情况下缩短文本，因此持久化失败不会
违反请求大小不变量。

定稿器从返回的部分重新计算 `contentLength`。无限或禁用的预算是
no-op。

`enter_plan_mode` 是唯一的语义例外。它的成功函数响应输出安装活跃的规
划策略，因此截断它会改变执行规则，而不是缩短诊断输出。定稿器和最后关
头发送守卫按工具名识别该输出，并把它排除在分配之外；失败文本和同一批
次中的所有普通输出保持有界。

### 运行时边界

- Core 调度器在 `PostToolBatch` hook 之前定稿以限定 hook 输入，并在
  hook 之后再次定稿以限定 hook 输出。
- 交互模式按原始序号顺序合并可执行、重复和合成的响应，然后在记录和提
  交之前执行外层定稿。
- 无头模式收集整个轮次，包括重复、跳过、取消和已执行的调用，然后在记
  录和提交之前定稿一次。
- ACP 收集完整的工具调用轮次，在 transcript 记录之前定稿，并为下一条
  消息返回相同的部分。即时 ACP 显示事件保持不变。
- Agent 运行时和 speculation 后续在发出面向模型的结果或追加历史之前，
  对其聚合量定稿。
- 聊天发送边界仅对工具响应字段应用无 I/O 的安全上限。它通常应是
  no-op，并保护错过外层聚合边界的未来调用方。

## 失败处理

持久化失败通过既有日志报告，绝不阻止最终截断。返回的模型响应仍适配
预算，但如果没有完整输出被成功持久化，可能省略文件引用。媒体部分保持
不变，不计入此字符预算。

取消和 hook-stop 响应与成功和失败的工具响应完全相同地定稿。空输出和
错误字段仍有效。单个大于整个批次预算的响应被单独缩减；多个大响应确定
性地共享剩余的预览容量。

## 兼容性与非目标

面向模型的公开函数响应 schema 不变。既有的截断文本保持可读，但聚合
定稿不再依赖它。既有会话仍可重放；只有新记录的工具结果获得更严格的
不变量。

本变更不添加 wire 字节哈希、精确 token 核算、媒体预算、存储生命周期
变更、transcript 迁移或新的临时文件布局。那些是独立的后续工作。
