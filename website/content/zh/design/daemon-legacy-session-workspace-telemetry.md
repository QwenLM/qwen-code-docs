# 旧式会话工作空间遥测

## 背景

daemon 遥测中间件在 Express 路由处理器运行之前对 HTTP 请求分类。旧式单数会话路由可以解析到任何已注册的工作空间，但中间件无法仅从 URL 得知所选运行时。在中间件和处理器中都解析活跃 owner 会重复工作，并且如果 registry 在两次查找之间发生变化，两者还可能不一致。

本设计为每个显式旧式 `/session`、`/sessions` 和 `/permission` 路由提供一个稳定的请求 span，同时把动态路由归因到处理器所选的运行时。

## 路由清单

路由目录包含全部 48 条显式旧式路由。每个条目声明其 HTTP 方法、Express 路径模板、规范路由标签，以及两种归因模式之一：

- `handler_resolved`（41 条路由）：`POST /session`、load/resume、旧式 transcript 路由，以及每一条解析活跃 owner 的单数会话路由。处理器把所选运行时的工作空间发布给遥测。
- `pre_resolved`（7 条路由）：旧式导出、A2UI 操作、旧式组织操作、三个全局批量变更操作，以及全局权限投票。这些路由保持绑定到主工作空间。

目录匹配器遵循相关的 Express 5 默认行为：静态段大小写不敏感，接受一个结尾斜杠，参数段只在其原始路径边界被捕获之后才解码。格式错误的会话 id 保留为其原始值。权限请求 id 在现有的长度和字符集校验之前解码。发出的 `http.route` 总是使用规范的目录模板。

## 延迟归因

处理器解析的请求在没有 `qwen-code.workspace.hash` 的情况下开始。中间件在 Express 响应上存储一个私有上下文。路由代码在唯一运行时被选定之后调用 `setDaemonTelemetryWorkspace(res, runtime.workspaceCwd)`。该 setter 是尽力而为且先选优先：重复的相同值是幂等的，之后的不同值被忽略。

四个发布接缝是：

1. `requireSessionRuntime`，由活跃 owner 路由共享。
2. 工作空间选定之后的会话创建。
3. 目标运行时选定之后的会话 load/resume。
4. 找到唯一的活跃或持久化 owner 之后的旧式 transcript 解析。

发布先于其后的信任、不支持次级、冲突和请求校验检查。因此这些失败保留被唯一选定的运行时。在唯一选定之前失败的请求，包括 not-found、歧义和工作空间不匹配的情况，省略工作空间哈希。归因使用 `runtime.workspaceCwd`，而不是会话请求的或临时的 cwd。

在响应 `finish` 或 `close` 时，中间件对已发布的工作空间做哈希，设置 span 属性，记录响应，并结束 span。解析、哈希和 span 更新都是尽力而为，不能影响请求处理或指标结算。上下文在一次结算后被清除。

预解析请求继续在 span 开始时对中间件所选工作空间做哈希。移除中间件的活跃 owner 回调，确保每个请求至多解析一次活跃 owner。

## 流式与指标

全部 48 条目录路由都创建请求 span。成功的 `GET /session/:id/events` 响应在 SSE 连接关闭时结束其 span，但被排除在常规 HTTP 请求计数/时长和 Web Shell 状态指标环之外，因为其时长就是连接生命周期。SSE 握手失败被记录为普通的短 HTTP 请求。

`POST /session/:id/generate` 是一个有界的请求作用域 SSE 操作。其连接在 generation 完成时结束，因此其时长仍然是有意义的请求延迟，并继续进入常规 HTTP 指标。

心跳请求保留在 OpenTelemetry HTTP 指标中，但仍被排除在状态指标环之外。`GET /daemon/status` 也仍然只被排除在该环之外。一个共享的结算守卫防止 `finish` 和 `close` 都触发时的重复记录。

HTTP 指标和 Web Shell 指标环保持为 daemon 全局。增加工作空间指标维度需要单独的基数和 dashboard 兼容性评审。

## 兼容性与边界

本变更不改变路由、请求或响应 schema、SDK、能力、持久化、认证、信任顺序、归档租约、bridge 错误映射或会话执行。它不新增公开遥测属性。

遥测中间件安装在 bearer 认证、限流和 JSON 解析之后，因此被这些更早闸门拒绝的请求仍然在本请求 span 覆盖之外。隐式 HEAD/OPTIONS、访问日志行为、限流路径归一化、工作空间会话组路由、工作空间限定的组织操作、ACP/WebSocket 遥测，以及启用次级 branch/fork/cd 执行，都不在范围内。

## 验证

- 一个漂移守卫把注册到 Express 的显式旧式路由与目录比较，并断言 48/41/7 清单。
- 匹配器测试覆盖大小写、结尾斜杠、编码斜杠、Unicode、格式错误的编码、权限 id 校验、方法/路径不匹配和规范标签。
- 中间件测试覆盖延迟归因、先选优先、哈希缓存、遥测失败、一次性结算、SSE 指标、心跳和 status 排除。
- 路由测试覆盖主、次级、不受信任、缺失、歧义和冲突情况下的活跃 owner、创建、恢复和 transcript 发布。
- 一个双工作空间 outfile 测试验证次级、主绑定和省略的哈希，且不暴露原始工作空间路径。
