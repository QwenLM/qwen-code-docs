# TUI 图片显示工具

## 目标

添加一个模型可调用的 `display_image` 工具，在交互式终端 UI 中预览已有的
PNG。该工具仅用于显示：它不向模型提供图像像素，并且在 headless 模式、
SDK、读屏器和子代理的工具注册表中不可用。

## 设计

核心工具会校验绝对工作区路径、常规文件状态、PNG 签名以及 8 MiB 的大小
限制。成功时返回一个小型的结构化显示值：

```ts
{
  type: 'terminal_image',
  filePath: '/absolute/workspace/path/image.png',
  mimeType: 'image/png',
}
```

在返回成功之前，工具会询问一个由 CLI 注入的提供者：当前终端是否有可用
的渲染器。原生协议立即通过；回退路径检查 `PATH` 上是否有可用的 `chafa`，
但不会渲染所选文件。如果没有可用的渲染器，工具返回执行错误，使 TUI 和模
型都知道图像未被显示。`llmContent` 告诉模型：如果需要检查图像，请使用
`read_file`。图像字节和终端转义序列绝不会进入模型历史或持久化的显示值。

`ToolMessage` 识别该结构化值并将其委托给一个 TUI 组件。该组件在读取路径
之前，会针对当前工作区重新校验路径。渲染在组件首次渲染时准备，因为已完
成的工具行会立即进入 Ink 的只追加 `Static` 区域；在那里异步的状态更新
会被丢弃。Kitty 兼容的终端使用既有的虚拟图像和 Unicode 占位符方案，与
Mermaid 图表所用的相同。其他终端尝试带符号输出的 `chafa`。`chafa` 只接
收与 Mermaid 渲染器相同的白名单环境，因此 API 凭证不会被转发。如果两条
路径都不可用，TUI 显示一个有界的文本回退，其中标明图像名称。

预览上限为 72 列 24 行，然后进一步缩小以适应可用的终端空间。按
8×16 像素的终端单元格估算提供一个保守的自然尺寸，使小图像不会被刻意放
大。原生渲染和 `chafa` 渲染都使用相同的保持宽高比尺寸。

仅当以下所有条件都为真时才注册该工具：

- 主配置是交互式的；
- SDK 模式已禁用；
- 读屏器模式已禁用；
- 注册表不是为子代理创建的。

Bare 模式保持其现有的最小工具集。

## 兼容性

第一个版本仅支持 PNG。Kitty 和 Ghostty 使用原生图像放置。Warp 被有意排
除，因为它的 Kitty 支持不包含本渲染器所使用的 Unicode 占位符扩展，而直
接放置会在回滚和终端回流期间偏离 Ink 内容。iTerm2 的直接放置也被排除，
因为其内联图像协议基于光标定位，且现有的异步 Ink 路径已经将其视为不安
全。Warp、iTerm2、tmux、SSH 以及没有原生路径的终端，在安装了 `chafa`
时仍可通过它渲染。

## 安全与持久化

工具和渲染器都使用 `WorkspaceContext.isPathWithinWorkspace`，它会解析
符号链接并防止遍历到已注册工作区根之外。渲染器把恢复的 `resultDisplay`
数据视为不可信，并重复此检查。持久化的会话只包含路径和 MIME 类型；如
果文件已不存在，恢复会降级为文本提示。

原始终端输出只由受信任的渲染器生成。模型可控的字符串和文件内容绝不会
被直接写入终端。
