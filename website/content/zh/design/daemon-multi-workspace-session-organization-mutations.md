# 多工作空间会话组织变更操作

## 摘要

新增 `PATCH /workspaces/:workspace/session/:id/organization`，作为工作空间限定的会话组织变更操作。

该路由把置顶、分组和颜色变更应用到所选工作空间拥有的会话组织存储。它扩展现有的复数 REST 面，不改变能力、请求或响应 schema、ACP 或 UI 行为。

## 问题

工作空间限定的会话读取已经指向所选工作空间。`GET /workspaces/:workspace/sessions` 可以从受信任的非主运行时返回持久化、已归档和活跃的会话，并可以对该运行时的组织存储应用已组织视图和分组过滤。

目前唯一的组织变更操作是 `PATCH /session/:id/organization`。该旧式路由仅限主工作空间。因此，客户端可以读取次级工作空间的组织状态，却无法通过匹配的工作空间限定 REST 面更新它。

## 决策

在其他工作空间限定的会话存储路由旁注册 `PATCH /workspaces/:workspace/session/:id/organization`。

`:workspace` 选择器的解析与现有复数路由完全一致：

1. 匹配精确的已注册工作空间 id。
2. 否则解码并规范化一个绝对 cwd 选择器。
3. 两者都无法解析时返回现有的未知工作空间错误。

所选运行时是该操作的完整作用域。会话查找、分组校验、组织变更和持久化都使用该运行时的工作空间 cwd 和存储。处理器绝不回退到主运行时，也不搜索其他已注册工作空间。

## 数据流

1. 请求通过 daemon 正常的 host、bearer 和 JSON 中间件。
2. 复数路由把 `:workspace` 解析到一个已注册运行时。
3. 复数变更信任闸门要求该运行时受信任。
4. 目标运行时在其活跃持久化存储、已归档持久化存储或活跃 bridge 中查找 `:id`。
5. 请求体通过现有的组织请求校验。
6. 如果 `groupId` 存在且非 null，目标运行时的分组存储校验该分组。
7. 目标运行时的组织存储以现有语义应用 `isPinned`、`groupId` 和 `color`。
8. 路由返回与旧式变更操作相同的组织响应。

持久化的活跃会话、持久化的已归档会话，以及匹配的仅活跃会话，都是有效目标。组织保持为 sidecar 状态：该变更不重写 transcript JSONL，也不改变 transcript 的修改时间。

## 信任与错误顺序

复数路由约定决定可观测的顺序：

1. 未知的工作空间选择器返回现有的 `400 { code: "workspace_mismatch" }` 响应。
2. 已知但不受信任的工作空间在披露会话或分组是否存在之前返回 `403 { code: "untrusted_workspace" }`。
3. 在所选运行时的活跃、已归档和活跃集合中都不存在的会话，返回现有的会话未找到 `404`。
4. 无效的组织更新字段在找到受信任的目标会话之后返回现有的组织校验错误。
5. 非 null 但不在所选运行时分组存储中的分组 id 返回 `404 { code: "group_not_found" }`。
6. 不可读的组织 sidecar 返回 `500 { code: "session_organization_store_unreadable" }`。

归档和删除冲突保留现有的归档 coordinator 错误。

任何错误阶段都没有跨工作空间回退。只存在于主工作空间的会话或分组，在选定次级工作空间时保持未知，反之亦然。

## 旧式兼容

`PATCH /session/:id/organization` 保留其当前仅主工作空间的行为，包括其变更闸门、校验、查找、持久化、错误形状和响应 schema。因此现有客户端保持相同的路由和重复 id 行为。

客户端只在 `session_organization` 和 `workspace_qualified_rest_core` 都通告之后才使用复数变更操作。不引入新的能力标签。

## ACP 行为

ACP 分发不变。限定 dispatcher 已经操作 `rt.bridge` 和 `rt.workspaceCwd`，因此工作空间限定的 ACP 会话操作已经绑定到所选运行时。本变更仅限于复数面缺失的 REST 组织变更操作。

## 并发与存储锁

`SessionOrganizationService` 只使用其现有的每 sidecar 锁，来串行化针对同一 sidecar 的分组和会话组织读改写操作。现有的归档 coordinator 协调组织更新与归档/删除转换。本路由不添加 daemon 范围的锁，也不添加新的跨服务事务或原子性保证。

## 测试与验收

自动化测试和真实 E2E 验收策略共同覆盖：

- 工作空间 id 和 URL 编码的规范 cwd 选择器到达同一运行时。
- 受信任的次级工作空间可以对活跃持久化、已归档持久化和仅活跃会话变更组织。
- 置顶、分组、取消分组，以及支持的颜色或 `null` 更新，返回现有的响应形状。
- 已组织列表和置顶/分组过滤反映该变更。
- 持久化会话的组织状态在 daemon 重启后幸存。
- 次级变更不修改主工作空间的组织状态。
- 旧式路由保持仅主工作空间，对只存在于次级工作空间的会话返回 `404`。
- 已知不受信任的工作空间在会话或分组查找之前返回 `403`。
- 未知选择器、未知的目标作用域会话和未知的目标作用域分组，返回其现有错误，无跨工作空间回退。

验收还包括 build、typecheck、聚焦的路由和 SDK 测试，以及覆盖两个受信任工作空间加负向信任和选择器场景的 E2E 通过。

## 显式非目标

本变更不引入能力标签或能力载荷变更，不改变请求或响应 schema，不改变 ACP 行为，也不改变 UI。它不让旧式路由具备多工作空间感知，不添加跨工作空间会话发现，也不改变归档、列表、分组或 transcript 语义。
