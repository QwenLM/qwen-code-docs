# Daemon 多工作空间加固基线

状态：issue [#6378](https://github.com/QwenLM/qwen-code/issues/6378) 的当前实现基线与评审契约。本文档收束加固阶段；它不是新增 daemon 功能的路线图。

## 所有权模型

每条 daemon 路由和下游操作都恰好属于以下所有权类别之一：

| 所有权           | 含义                                                                                                                                                                                  |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 进程全局      | 每个运行时共享的一个监听器/进程资源，例如认证、HTTP 限流、连接限制、指标和关闭。                                               |
| 旧式主工作空间      | 契约刻意指向主运行时的兼容路由。省略工作空间选择器不是猜测其他 owner 的许可。                                  |
| 工作空间限定 | 路由先解析显式的工作空间 id，再解析编码的规范绝对 cwd，并且只分发到所选运行时。                                                   |
| 活跃会话 owner  | 单数活跃会话路由扫描已注册运行时，找到拥有该会话的唯一 bridge，并且只在那里分发。                                                           |
| 持久化工作空间 | 路由在读取持久化的会话或组织存储之前先解析工作空间；它可以在不启动 ACP 的情况下为不受信任的次级暴露一个声明的只读面。 |

主工作空间是第一个启动的运行时，也是显式记录了该回退的路由的兼容默认值。它不是解析失败时的通用回退。

## 失败语义

| 状态                        | 要求的行为                                                                                                                                                                                                                                                                                  |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 未知的工作空间或会话 | fail closed（失败即拒绝），返回该路由稳定的 mismatch/not-found 响应。不得对主工作空间探测或执行。                                                                                                                                                                                          |
| 不受信任的工作空间          | 拒绝运行时支撑的执行和变更。不受信任的次级只能使用显式记录的只读面，包括有界的文件系统和持久化目录/transcript 读取，且不启动 ACP 或写入修复状态。旧式主预热不授权请求。 |
| 歧义的活跃会话 owner | 返回服务端错误，因为无法安全分发。不在任何 bridge 上执行。                                                                                                                                                                                                                |
| 引导中的运行时        | 保持进程全局存活探测的响应；运行时支撑的工作等待或报告声明的启动失败。聚合不可用时，深度健康返回带原因的 `503`。                                                                                                          |
| drain 中的运行时             | 以稳定的 draining 响应拒绝新工作。非强制移除在活动存在时以 `workspace_busy` 回滚；强制移除请求终止并对活跃资源做有界清理。该运行时在移除完成之前保留在 daemon 全局核算中。               |
| 已移除的运行时              | 视为未知。在同一工作空间可以被重新添加之前，它必须从能力、路由和健康聚合中消失。持久化提交点之后的清理是尽力而为；失败会被记录，且不会恢复路由。                                                    |

## 不变量

- 工作空间解析在未知、不受信任、歧义、draining 或已移除的结果之后绝不回退到主工作空间。
- 工作空间 id 优先于编码的 cwd 选择器。cwd 选择器必须是绝对的，并规范化到一个已注册的运行时。
- 每个活跃工作空间运行时拥有其环境快照、bridge、工作空间服务、文件系统/信任边界、Voice 状态和 ACP/MCP 资源边界。生产会为兼容性预热主 bridge，并在预热失败后于首次使用时重试。受信任的次级按需启动其 ACP 子进程，并且当启用 `mcp_workspace_pool` 时，在该子进程内拥有池；不受信任的次级两者都不能启动。主预热不绕过路由信任闸门。一个进程全局的 Voice coordinator 强制执行共享准入上限，同时按所属运行时跟踪租约。同名环境键不得跨运行时，工作空间覆盖层不得修改父进程环境。
- 一个 daemon token 认证整个进程；它不是每工作空间的 ACL。HTTP 限流、监听器上限、总会话准入、指标、关闭和进程故障半径也是 daemon 全局的。
- 当通告 `mcp_workspace_pool` 时，MCP 传输和预算核算在一个工作空间运行时内的会话之间共享，绝不跨运行时。没有该标签时，客户端必须接受旧式的每会话 manager 和 `scope: 'session'` 状态。
- 显式的启动/静态运行时（包括主运行时）不可移除。动态或持久化的次级运行时遵循添加、drain、移除和重新添加的生命周期规则。draining 运行时在逻辑移除完成之前对 daemon 全局健康保持可见。强制移中止活跃资源并执行有界的尽力拆除；清理超时会被记录，而不是回滚逻辑移除。
- 浅层 `GET /health` 保持恰好为 `200 {"status":"ok"}`。深度健康聚合并活跃和 draining 的运行时，对引导或聚合失败返回带原因的 `503`，且绝不暴露工作空间路径。参见 [daemon 全局深度健康检查](./daemon-global-deep-health.md)，由 [PR #6961](https://github.com/QwenLM/qwen-code/pull/6961) 实现。

## 评审契约

对于每条新增或变更的 daemon 路由，评审者必须指明所有权类别，并跟踪请求经过环境、bridge、服务、文件系统、信任和失败处理。如果任何下游消费者可以在所有权解析失败后悄悄使用主状态，该路由就是不完整的。

评审发现按如下分类：

- 正确性、安全性、数据丢失、隔离或 fail-open 回归属于加固范围，并阻塞受影响的变更。
- 新能力或对刻意的仅主工作空间契约的迁移，单独立 issue 和设计；它不扩大本收束。
- 没有具体缺陷的重构不进入加固范围。

大约五轮评审之后，只有正确性、安全性、数据丢失和回归修复才应扩大一个活跃的加固 PR。其他有效建议记录为后续工作，使伞 issue 不会无限期保持开放。

## 显式的当前限制

- `POST /session/:id/branch`、`POST /session/:id/fork` 和 `POST /session/:id/cd` 对次级拥有的活跃会话保持旧式主工作空间行为，并返回 `non_primary_session_route_not_supported`。
- 命名的 daemon 管理 channel 按所属工作空间分组，每个所属运行时运行一个 worker。`--channel all` 刻意保持仅限主工作空间。
- daemon 不提供每工作空间的认证、限流或进程故障隔离。需要这些边界时部署独立的 daemon。

## 退出规则

本基线、其契约测试、路由/环境守卫和 daemon 范围深度健康检查是 #6378 的固定收束。Branch/fork 路由和 `cd` 语义保持为独立的功能工作。收束 PR 落地之后，未来的评审发现应作为聚焦的 issue 提交，而不是重新打开一个无界的加固桶。
