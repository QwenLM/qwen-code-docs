# 认证会话写入者交接

## 问题

协作式托管关闭目前会在 ACP 子进程退出之前释放每个会话写入者锁。这修复了普通的替换路径，但它无法区分一个故意停止记录的写入者和一个未释放活动锁就消失的外部宿主写入者。把主机名、PID 可见性、锁龄或转录不活动当作死亡证明，将允许两个存活的 Pod 向同一份转录追加。

## 范围

本改动为托管 ACP 写入者添加一个受完整性保护的交接状态。在关闭准入并持久地 drain 已接受的记录器工作之后，一个受信任的托管子进程可以将其活动锁替换为一条封存记录。一个受信任的托管替换者只有在针对新 Config 所请求的精确转录验证该记录之后，才能取得所有权。

转录路径必须不存在，或解析为证明时打开的同一个普通文件。悬空符号链接不被视为缺失的转录。

该协议仍由 `experimental.sessionWriterLease` 门控，默认禁用，并在 ACP 进程启动时做快照。独立 ACP、交互式和 headless 记录器不获得认证接管。正常的按会话关闭仍会释放其锁，而不是留下封存记录。

本改动不回收由 SIGKILL、事件循环停滞、未处理崩溃或封存完成前的存储故障遗留的活动锁。它不添加 TTL、心跳、主机名抢占、Kubernetes API 查询、运维强抢端点、维护租约或混合版本支持。这些活动锁场景仍需要权威的外部写入者围栏和显式恢复。

## 锁记录

新所有者写入 schema v2 记录。活动记录保留现有的不可变所有者诊断信息，并新增：

```json
{
  "schema_version": 2,
  "state": "active"
}
```

封存记录保留前所有者的诊断信息，并新增：

```json
{
  "schema_version": 2,
  "state": "sealed",
  "sealed_at": "2026-07-28T00:00:00.000Z",
  "transcript": {
    "relative_path": "<runtime-relative transcript key>",
    "exists": true,
    "byte_length": 1234,
    "sha256": "<lowercase hex digest>"
  }
}
```

相对键必须解析为新 Config 已经提供的转录路径。它绝不用于选择任意的文件系统路径。Schema v1 记录在回滚期间仍是有效的活动记录，但它们绝不会被解释为封存。

## 固定 claim

固定的 claim 路径是：

```text
<primary lock path>.claim
```

它串行化两种临时移除主路径的转换：active-to-sealed 和 sealed-to-active。claim 用现有的写入-同步-硬链接原语创建。含糊的链接错误会在转换继续或清理之前，对照精确的 claim 字节进行调和。claim 绝不按 PID、主机名或龄期回收。任何已存在的 claim 都返回 `session_writer_unavailable`；只有在权威的外部写入者围栏之后才允许手动清理。

普通获取在安装缺失的主锁之前每次都检查 claim。安装之后再次检查，如果并发转换已取得 claim，则只移除自己精确的候选。这保留了当前的活动锁快路径和本地陈旧所有者回收，同时让两条路径都尊重交接转换。混合版本的写入者仍不受支持，因为较旧的写入者不知道固定 claim。

获取者可能在转换创建 claim 之前一刻通过了第一次 claim 检查，然后在转换的主路径空档期间安装其活动候选。转换把该同会话的 schema-v2 活动记录识别为知晓 claim 的候选，保留已退役的前任，并等待该候选强制性的第二次检查将其移除后再重试硬链接。该等待有界；如果候选在第二次检查之前停滞或退出，转换以 unavailable 失败，同时保留其 claim 和已退役的前任。未知的、畸形的或跨会话的继任者绝不被移除或覆盖。

## 封存

托管关闭同步停止会话和记录器准入，然后并行启动所有写入者终结器。写入者终结器：

1. drain 在截止点之前接受的每一个记录器操作；
2. 不跟随符号链接地打开预期转录，验证现有所有者和转录快照，并通过那个保持打开的文件描述符对字节做哈希；
3. 写入并同步一个所有者唯一的封存候选；
4. 获取固定 claim，并重新验证活动所有者以及保持打开的转录标识和元数据；
5. 把精确的活动主路径重命名为所有者唯一的退役路径；
6. 不做替换地把封存候选硬链接到现在缺失的主路径上；以及
7. 只移除其精确的退役、候选和 claim 记录。

对协作的写入者来说，主路径转换在逻辑上是原子的，因为每次安装都尊重固定 claim，且最终的硬链接不会覆盖另一个进程创建的锁。生效后的错误会从精确的记录字节进行调和。旧所有者绝不删除或覆盖未知的主路径。

托管 flush 或证明失败会保留活动锁。正常的按会话关闭保留现有的释放行为，包括精确所有者清理。如果一次正常释放与托管关闭竞争并先提交，缺失的主路径已经是一次安全的交接，替换者执行普通获取。

失败清理只有在证明精确的转换前主路径已被恢复之后才移除固定 claim。如果回滚无法恢复或验证该记录，即使出现了另一个主路径，claim 仍会保留，因为该路径可能是一个失败的普通获取候选，它会在观察到 claim 之后自行移除。回滚本身只在固定 claim 仍包含本次转换的精确记录时才尝试；claim 缺失或被替换意味着当前主路径绝不能被改动。恢复随后需要与任何其他残留 claim 相同的权威外部写入者围栏。

主路径转换开始之前的失败则不同：声明者尚未创建主路径空档，也未移动前任，因此即使另一个认证竞争者已经替换了观察到的封存主路径，它也只释放自己精确的 claim。这防止了一个迟到的失败竞争者在获胜者变为活动之后搁置一个 claim。

## 认证接管

只有在受信任的托管父进程下创建的 Config 才启用认证接管。当获取观察到一条封存记录时，它：

1. 验证该记录的相对键与 Config 预期的转录匹配；
2. 在固定 claim 之外打开该转录并做哈希，保留文件描述符及其标识；
3. 获取固定 claim；
4. 重新读取精确的封存主路径，并重新验证保持打开的描述符、路径标识、元数据、字节长度和摘要；
5. 把封存主路径重命名为候选唯一的退役路径；
6. 不做替换地把已同步的活动候选从 claim 硬链接到主路径上；以及
7. 只移除精确的退役记录和它自己的 claim。

随后租约在记录器激活之前执行现有的权威会话重载和转录围栏。两个竞争同一封存记录的替换者最多产生一个活动所有者。失败者会收到冲突或 unavailable 结果，取决于它观察到的是获胜者的活动主路径，还是进行中/残留的 claim。

## 失败契约

| 条件                                                                          | 结果                             |
| ---------------------------------------------------------------------------------- | ---------------------------------- |
| 有效的活动所有者，包括外部宿主或托管的死 PID 记录            | `session_writer_conflict` / 409    |
| 封存证明与预期转录不匹配                                | `session_transcript_changed` / 409 |
| 畸形记录、非普通路径、残留 claim 或不确定的文件系统结果 | `session_writer_unavailable` / 503 |
| 当前写入者不再拥有其精确的活动记录                              | `session_writer_lost` / 409        |

公开错误保持清洗。成功的封存和接管日志包含会话 ID、前主机名/PID 和封存时间，但绝不包含所有者令牌或转录路径。

## 兼容性与推广

在混合版本推广期间，该功能门必须保持禁用。启用或禁用它需要 drain 旧的 ACP 进程。schema v2 读取器仍接受 schema v1 活动记录，但较旧的读取器不理解 schema v2。因此回滚需要 drain 所有新写入者，并确认本协议没有遗留任何活动、封存或 claim 记录。

一个未获取租约的写入者——例如普通的 `qwen --resume` 会话，因为独立、交互式和 headless 记录器运行在本协议之外——仍可以向托管写入者已封存的转录追加。该追加会使封存证明失效，因此同一会话后续的认证接管会以 `session_transcript_changed` fail closed（失败即拒绝），守护进程保持围栏状态，直到权威的外部写入者围栏清除残留记录。因此推广必须让非租约写入者远离任何参与认证交接的转录。

哈希有意在封存和接管时执行，而不是给每次追加都加增量摘要。这让首个实现保持小巧，并使证明独立于进程内存。非常大的转录可能导致托管封存超出父进程截止期限；那会 fail closed 并保留活动锁，可观察为一次不干净的关闭。

## 验证

单元测试和多进程覆盖必须证明：

- schema v1 和 v2 活动锁保持现有的存活/陈旧行为；
- 托管获取绝不回收活动的死 PID 或外部宿主锁；
- 成功的封存记录精确的相对键、存在性、字节长度和 SHA-256 摘要；
- 认证替换者重新加载封存转录并变为活动；
- 两个竞争一条封存记录的替换者恰好选出一个所有者；
- 转录修改、替换、截断、证明损坏、畸形封存记录和残留 claim 都 fail closed；
- 每次主路径转换前后的失败绝不覆盖或删除未知继任者；
- 托管 flush 失败保留活动主路径；
- 正常记录器关闭是释放而不是封存；以及
- 默认关闭和独立 ACP 路径保持不变。
