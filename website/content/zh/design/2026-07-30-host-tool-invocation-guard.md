# 宿主工具调用守卫

## 状态

针对 issue [#8102](https://github.com/QwenLM/qwen-code/issues/8102) 和
PR [#8032](https://github.com/QwenLM/qwen-code/pull/8032) 的草案设计。

## 问题

进程内嵌入宿主可以通过现有的权限和 hook 来评估模型提出的工具调用，但这些
检查可能在 Qwen Code 解析出规范工具名或构建最终调用参数之前运行。因此，执行
组织策略的宿主无法证明它评估的就是到达 `invocation.execute()` 的那个调用。

缺失的原语是对生效工具调用的最终执行边界决策。产品特定的任务状态、审批工作
流、策略存储和审计传输不属于 Qwen Code。

## 目标

- 让进程内宿主通过 `ConfigParameters` 提供一个允许/拒绝函数。
- 在执行之前立即评估规范工具名和克隆的最终调用参数。
- 覆盖核心调度器、ACP 会话运行时和 speculation 执行路径。
- 当配置的守卫拒绝、抛错、返回格式错误的决策或无法接收克隆参数时，fail
  closed（失败即拒绝）。
- 未配置守卫时保留现有执行路径。
- 如果在等待守卫之前或期间发生取消，阻止执行。

## 非目标

- 没有 CLI 标志、设置键、环境变量、daemon 路由、网络客户端或外部策略传输。
- 没有任务、plan、授权、业务授权或审计 schema。
- 不改变权限、hook、沙箱或审批模式语义。
- 不声称模型规划或工具实现变得确定性。
- 没有结果回调或并行工具结果协议。
- 不拦截在 Config 拥有的运行时之外手动调用 `ToolInvocation.execute()` 或
  `Tool.buildAndExecute()` 的 SDK 消费方。

## 契约

宿主在 `ConfigParameters` 中提供一个 `ToolInvocationGuard`。守卫接收：

- 运行时接受的工具调用关联标识符；
- 规范工具名；
- 最终调用参数的结构化克隆；以及
- 调用的中止信号。

决策要么是 `{ allowed: true }`，要么是 `{ allowed: false, reason? }`。缺失或
空白的拒绝理由使用一个稳定的通用消息。异常、格式错误的决策和克隆失败使用
另一个稳定的失败消息并拒绝执行。提供的拒绝理由是用户可见的，可能进入现有
的工具结果和遥测面，因此不得包含密钥或原始 provider 错误。

克隆的参数防止守卫改动 Qwen Code 将要执行的调用。该契约不把任意工具参数变
为机密；嵌入宿主必须把它们当作敏感应用数据对待。

工具调用标识符可能源自模型响应。它对于把守卫决策与现有生命周期事件关联有
用，但它不是经过认证的主体，也不是独立的幂等键。需要强身份的托管宿主必须把
它绑定到宿主拥有的会话和 prompt 身份。

## 执行位置

核心调度器在工具构建、权限处理、路径归一化和 `PreToolUse` 之后评估守卫，但
在调用变为 `executing` 之前、在 `invocation.execute()` 之前。

ACP 会话在工具构建、权限处理和 `PreToolUse` 之后评估相同的契约，但在其直接
的 `invocation.execute()` 路径之前。

实验性的 speculation 引擎也直接执行调用，而不使用核心调度器。它在构建调用
之后评估相同的守卫，并把拒绝或取消转换为零执行器调用的 speculation 边界。
未来的托管外部 provider 模式必须禁用 speculation 的 apply，因为把 overlay
复制到真实文件系统是 `invocation.execute()` 之外的单独效果边界。

三条路径都使用构建好的调用参数，而不是模型提供的草稿参数。在核心和 ACP 路径
中，拒绝产生零执行器调用和一个结构化的 `execution_denied` 工具结果。

任何未来直接执行 `ToolInvocation` 的 Config 拥有的运行时，都必须评估相同的
守卫或路由经过已有守卫的调度器。这是代码评审不变量，不是声称可以拦截任意
外部调用方。

两个代理分发调用点——`/fork` 斜杠命令和 ACP agent fork 处理器——直接构建并
执行代理工具调用而不咨询守卫。被 spawn 的子代理共享调用方的 `Config`，因此
子代理自己调用的每个工具都被守卫；只有分发调用本身未被守卫。未来的变更可以
把守卫扩展到这些调用点。

## 默认关闭的兼容性

Qwen Code 不在其 CLI 或 daemon 引导中填充 `toolInvocationGuard`。该字段仅是
进程内嵌入 API。

每个执行路径读取可选回调，只在回调存在时才进入异步求值器。不存在时，Qwen
Code 不进行守卫 promise 分配、参数克隆、provider 调用、能力通告或额外的异步
让出。因此现有的 CLI 和 daemon 部署保留其先前的执行路径。

仓库内刻意缺席的生产 setter 意味着本变更在合并前需要维护者对公开嵌入接缝
达成一致。未来的外部 provider 变更必须保持单独的 PR，不能被假定为包含在本
PR 的批准中。

## 取消与失败语义

求值器在调用守卫之前和其 promise 落定之后都检查取消。每个执行路径也在
await 之后、任何执行器调用之前立即检查其活跃信号。

- 评估前取消：不调用守卫或执行器；
- 等待守卫期间取消：记录取消且不调用执行器；
- 显式拒绝：记录 `execution_denied` 且不调用执行器；
- 守卫异常、格式错误的响应或克隆失败：fail closed 且不调用执行器。

没有自动重试。守卫回调拥有任何 provider 特定的重试策略，但嵌入宿主不得通过
该 API 重试或执行模糊的副作用。

## 证据

单元测试和集成测试覆盖：

- 配置的允许和拒绝决策；
- 默认拒绝理由；
- 守卫异常、格式错误的响应和克隆失败；
- 参数变更隔离；
- 守卫评估之前和期间的取消；
- 核心和 ACP 路径中的最终归一化参数；
- speculation 执行在拒绝时停在边界；
- 拒绝和取消时零执行器调用；
- 核心与 ACP 工具结果记录之间的 `execution_denied` 对等；以及
- 通过外围调度器和 ACP 套件的现有未配置执行。

本 PR 不需要 E2E 计划，因为它不添加 CLI、设置、daemon 路由或其他用户可激活
的行为。跨平台 CI 在合并前仍然必需。

## 后续边界

未来的外部策略 provider 可以用受信任的运行时拥有的会话和 prompt 身份扩展上
下文，并跨 `qwen serve` 到 ACP 子进程的边界适配进程内回调。该后续工作必须默
认关闭、独立评审，并证明未配置的 CLI 和 daemon 不会初始化 provider 或改变其
子进程环境。

结果观察应复用现有的结构化工具生命周期事件，除非有单独的 issue 证明具体的
关联缺口。产品特定的编排和策略保持在 Qwen Code 之外。
