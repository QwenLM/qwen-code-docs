# 不可信工作空间只读会话目录

## 摘要

多工作空间 daemon 为启动时信任状态为 `false` 的已注册非主工作空间暴露
一个窄的只读目录。该目录包含持久化的会话摘要和会话组织 sidecar。它不
附加到会话、不启动 ACP 子进程、不合并实时运行时状态，也不解释工作空间
控制的 capability 定义。

这是一个路由允许名单，不是工作空间 ACL。持有 daemon bearer token 的客户
端可以读取每个已注册工作空间的允许数据。信任继续作为执行和变更的闸门；
它不创建单独的认证主体。

## 安全不变量

每个新允许的不可信工作空间读取路径必须满足以下所有条件：

- 不调用 `loadSettings()` 或任何设置迁移/修复路径。
- 不创建、修复、重写或以其他方式修改存储。
- 在目录读取器活跃期间抑制基于文件的调试日志，使格式错误的记录不能以
  读取副作用的形式创建或追加调试日志。
- 不调用 `ensureChannel()` 或任何其他 ACP 子进程启动路径。
- 不查询或合并不可信运行时的实时桥接状态。
- 不执行外部命令。
- 不发现或解析工作空间 agents、skills、hooks、MCP 配置或其他项目控制的
  capability 定义。

该实现对所有会话列表形态（default、organized 和 `parentSessionId` 过滤）
使用内部 `mergeLive: false` 读取策略来强制实时状态边界。同一个异步读取
边界只为不可信目录读取抑制基于文件的调试日志；trusted 请求和该边界之外
的日志保持不变。存储缺失会产生空目录，格式错误的条目遵循既有的尽力而为
读取行为，不修复文件。

## 路由矩阵

除非另有说明，下表描述的是不可信的次级工作空间。

| 表面                                        | 结果              | 数据来源与约束                                                                        |
| ------------------------------------------- | ----------------- | ------------------------------------------------------------------------------------- |
| `GET /workspace/:id/sessions`               | 200               | 仅持久化会话文件；id 或编码的规范 cwd 选择器                                        |
| `GET /workspaces/:workspace/sessions`       | 200               | 同样的仅持久化目录                                                                    |
| `GET /workspace/:id/session-groups`         | 200               | 仅组织 sidecar；任何已注册 id 或编码的 cwd                                            |
| `GET /workspaces/:workspace/session-groups` | 200               | 仅组织 sidecar                                                                        |
| 文件读取、bytes、stat、list、glob           | 既有行为          | 既有的文件系统读取策略不变                                                            |
| 工作空间信任 GET/request                    | 既有行为          | 既有的信任配置语义不变                                                                |
| `/capabilities`、`/daemon/status`           | 既有行为          | 既有的 daemon 诊断不变                                                                |
| 复数会话/组变更                             | 403               | 变更信任闸门保持不变                                                                  |
| 单数组变更                                  | 既有行为          | 保持仅主工作空间；次级选择器 fail closed（失败即拒绝）                                |
| 设置、权限、providers                       | 403               | 设置加载可能迁移、备份或修复文件                                                      |
| 内存                                        | 403               | 当前响应包含全局内存路径，而不是仅工作空间的投影                                      |
| Env                                         | 403               | 暴露凭据存在性和代理/宿主诊断                                                         |
| Preflight                                   | 403               | 可能执行 git、npm、ripgrep 或其他探测                                                 |
| MCP、工具、hooks                            | 403               | 与实时桥接状态或项目配置耦合                                                          |
| Skills、agents                              | 403               | 发现并解析项目控制的定义                                                              |
| Transcript                                  | 403               | 当前路径可能启动 ACP，且游标初始化可能写入 HMAC 密钥                                  |
| Export、会话 status/context/tasks           | 403               | 没有按工作空间限定的仅持久化实现                                                      |
| ACP HTTP/WebSocket、语音、channels          | 拒绝              | 执行、进程或长生命周期运行时能力                                                      |

未知的绝对、嵌套或未注册的工作空间选择器继续以既有的
`400 workspace_mismatch` 响应 fail closed。格式错误的旧式单数选择器保留
其既有的 `400` 校验消息。两种情况都不会回退到主工作空间。复数路由对不可
信的主工作空间继续返回 `403 untrusted_workspace`。单数主路由保留其既有
的兼容行为。

## 会话目录语义

仅持久化模式保留既有的 `archiveState`、`view=organized`、`group`、
`parentSessionId`、游标和页大小行为。它从不从实时运行时填充 pending
交互、轮次错误或客户端状态；既有的持久化摘要默认值如 `clientCount: 0`
和 `hasActivePrompt: false` 保持 wire 兼容。它从不调用
`bridge.listWorkspaceSessions()`。

Trusted 次级和主工作空间保留既有的持久化/实时合并。不新增任何路由、wire
字段、schema 或 capability 标签：较旧的客户端继续处理 `403`，而随 daemon
一起发布的捆绑 Web Shell 消费新的 `200` 响应。

## Web Shell 行为

不可信的次级工作空间保持可展开，并同时标记为 `untrusted` 和
`read-only`。展开它执行一次目录读取。`reloadToken` 变更执行另一次读取，
但通常的十秒轮询被禁用，因为该 daemon 不能在该工作空间创建会话。

展开不会选择或激活工作空间。持久化会话渲染为带 `role="note"` 的非交互
行，其可访问名称包含会话名、日期，以及工作空间必须先被信任才能打开会话
的说明。该行不绑定鼠标或键盘激活，也不接收活跃会话样式。Trusted 工作
空间行为不变。不可信的主工作空间保持禁用，等待单独的 primary safe-mode
设计。

## 失败与兼容行为

- 会话或组织存储缺失时返回空目录。
- 无法解析和非对象的 JSONL 记录由既有的会话读取器跳过。本变更不为结构
  无效的对象记录增加 schema 校验。
- 不可读的组织 sidecar 返回既有的空读取视图和警告；读取不修复它。
- Web Shell 请求失败保留既有的空状态和控制台警告。
- 信任 GET 继续观察当前磁盘上的信任配置，并告知调用方运行时变更需要
  重启。本变更不把它转换为启动快照。

## 延迟工作

- 无副作用的设置和信任快照加载器。
- 仅工作空间的内存投影。
- 脱敏的环境和配置检查。
- 不解析项目定义的 skills 和 agents 清单。
- 既不启动 ACP 也不初始化游标 HMAC 密钥的 daemon 本地 transcript 读取
  器，以及真正只读的会话查看器。
- 动态信任应用、运行时重建，以及工作空间移除/drain。
