# 参与 Qwen Code 开发

从可复现的问题或范围明确的改动开始，说明当前行为、预期行为和验证方法。行为修复中避免夹带无关格式化与重构。

## 源码结构

| 目录 | 职责 |
| --- | --- |
| `packages/cli` | 终端界面、CLI 入口、命令与登录集成 |
| `packages/core` | Agent 执行、模型访问、工具、权限、Hooks 与会话 |
| `packages/resource` | 设置和 Skills 等可复用资源 |
| `schemas` | 生成的配置 Schema |
| `scripts` | 构建、打包与维护工具 |

修改代码前阅读对应包的 `AGENTS.md`。运行时版本以当前源码为准：Node.js 参考 `.nvmrc`，Bun 参考 `.bun-version`。包清单声明 Node.js 最低支持版本；排查构建问题时不要随意替换为其他全局运行时。

## 构建流程

源码定义的开发流程如下：

```sh
npm ci
npm run build
npm start
```

**Preview 前置条件：**公开依赖安装仍待发布验证。这些是源码中的开发脚本，不代表所有依赖已经可以从公开源获取。安装失败时，记录失败包和脱敏错误；不要向 Issue 提交私有源凭证，也不要为绕过原因不明的失败而提交源地址覆盖。

构建会应用依赖补丁。修改依赖清单时保持锁文件一致。修改设置定义后，执行 `npm run schema:settings` 重新生成配置 Schema，并检查生成差异。

## 定向验证

在所属包目录中运行受影响的测试：

```sh
cd packages/core
npx vitest run path/to/affected.test.ts
```

将示例路径替换为验证当前行为的实际测试。CLI 界面测试应直接用 `npx vitest run` 指定文件。根目录测试命令只负责阻止错误调用，不会运行测试。慢测试可能需要按包配置设置 `QODER_RUN_SLOW_TESTS=1`；这是源码开发中保留的兼容环境变量。

PR 描述应说明执行了什么、能证明什么。类型检查不能验证终端渲染，打包成功不能验证安装，静态审查不能验证真实模型请求。依赖问题导致测试未运行时，不应写成测试通过。

## 提交审阅前

- 说明具体触发条件和改动后的行为，覆盖相关失败路径。
- 行为改动需要时补充或更新定向回归测试。
- 用户行为变化时同步修改英文指南和中文翻译。
- 检查命令语法、配置示例、相对链接及功能前置条件。
- 不提交令牌、私有地址、本地数据或构建产物。

遵循仓库现有的许可证和安全报告流程。敏感漏洞应走安全报告渠道，避免在公开 Issue 中发布利用细节。
