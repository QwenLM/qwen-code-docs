# 终端图像

Qwen Code 可以在交互式终端 UI 中直接显示助手响应和工具完成结果中的图像部分。此显示路径独立于 Markdown 渲染，在 Markdown 的 `render` 和 `raw` 模式下行为一致。

## 图像出现的位置

在助手响应中，文本和图像保持原始顺序。工具行显示结果文本，后跟成功、失败和已取消结果的图像。

其他输出表面（包括无头模式、ACP、daemon/Web Shell 和 IDE 集成）不渲染图像部分。微信（weixin）、企业微信和钉钉 channel 仍可通过其 `[IMAGE: ...]` 标记流传递 agent 生成的图像文件；其他 IM channel 目前不传递外发图像。

## 终端支持

| 环境                                                           | 图像显示                                                                                    |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 直接使用 Kitty 或 Ghostty TTY，不经过 tmux 或 SSH              | 原生终端图像放置                                                                            |
| 安装了 `chafa` 的其他终端                                      | 256 色 ANSI 预览，包括 iTerm2、Warp、tmux 和 SSH 会话                                       |
| 无兼容渲染器，或屏幕阅读器模式（内联图像部分）                  | 确定性文本，如 `[image: 1024x768 png]`，代替终端图像序列                                     |

## 限制与回退

内联像素预览目前需要有效的 PNG 数据，且在显示限制内：总计 6400 万像素，每边最多 1,000,000 像素。其他图像格式、无效 PNG 以及超出这些限制的内联 PNG 仍以文本占位符的形式可见。

大于 8 MiB 的内联图像载荷不会被像素渲染。大多数超大载荷在进入 TUI 历史之前会被丢弃，而略超限制的载荷可能仍以文本占位符形式保留，因为准入基于编码大小。每个助手响应或工具行最多显示四张图像，其余部分用 `[+2 more images]` 等标记报告。

## 会话历史与内存

工具图像部分会与其结果一起保存，并可在会话恢复后重建。助手图像实时渲染但目前不会持久化，因此 `--continue` 和 `--resume` 会恢复助手文本但不包含这些图像。

为了在长时间或图像密集的会话中限制内存占用，TUI 可能会用 `[Old assistant image content cleared]` 或 `[Old tool result content cleared]` 等标记替换较旧的已显示图像。这只影响实时视图。工具图像部分仍保留在会话记录中，并在恢复后重新出现。
