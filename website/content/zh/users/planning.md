# 计划与持续目标

需要先研究方案再实施时，使用计划模式；需要会话跨轮次持续推进明确结果时，使用目标。两者可以配合，但都不会取消工具权限，也不保证任务一定成功。

## 先制定计划

`/plan` 切换计划模式。进入时也可以提供任务：

```text
/plan 设计保持现有 API 兼容的迁移方案
```

实施前检查计划和其中的假设。再次运行 `/plan` 会退出计划模式。计划模式是独立的会话状态，某些权限模式不允许进入，此时命令会说明原因。它不是文件系统沙箱，也不代表任意 Shell 命令都没有副作用。

| 命令 | 用途 |
| --- | --- |
| `/plan` | 进入或退出计划模式 |
| `/plan copy` | 将已批准的计划复制到剪贴板 |
| `/plan open` | 在编辑器中打开已批准计划，或当前会话的计划文件 |

`/plan copy` 需要已有已批准计划。`/plan open` 依次使用 `EDITOR`、`VISUAL`，最后回退到 `vi`，并等待编辑器关闭后重新读取文件。没有计划文件或编辑器无法启动时会报告错误。编辑计划文件本身不等于批准文件中列出的所有操作。

## 设置目标

说明希望达成的结果，并按需修改轮数上限：

```text
/goal 完成分页功能并验证相关测试 --turns 20
```

命令注册目标并立即开始工作。轮数限制用于控制目标轮次，不是 Token、费用或实际耗时上限。状态中显示已使用轮数和累计时间。不带 `--turns` 时，默认上限为 100 轮。正整数设置其他上限，`--turns -1` 明确表示不限轮数。有限轮数耗尽后，目标会自动暂停。

| 命令 | 用途 |
| --- | --- |
| `/goal` 或 `/goal status` | 查看目标、状态、轮数和耗时 |
| `/goal pause` | 暂停正在进行的目标 |
| `/goal resume` | 恢复暂停或阻塞的目标，或在中断后重新触发活跃目标执行 |
| `/goal clear` | 移除当前目标 |

轮数已耗尽的目标在恢复时会获得新的一组轮数。如果需要控制执行长度，恢复前请检查状态。清除目标只移除跟踪状态，不会撤销已经执行的文件修改、命令或外部操作。旧的 `/goal set` 写法已弃用，应直接在 `/goal` 后写目标。

## 推荐流程

1. 范围不清晰或存在重要设计选择时，先用 `/plan`。
2. 检查计划涉及的文件、假设与验证步骤。
3. 准备好后退出计划模式，设置有明确完成条件和轮数限制的目标。
4. 使用 `/goal status` 和 `/tasks` 查看进展，需要调整方案时暂停。
5. 接受结果前检查 diff 和实际测试结果。

命令不可用时，查看 `/help` 和当前功能设置。目标功能需要已初始化的会话；请根据错误提示区分初始化尚未完成和当前没有目标。
