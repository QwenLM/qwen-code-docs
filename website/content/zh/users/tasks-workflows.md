# 后台任务与工作流

后台工作允许主会话在其他操作执行时继续交互。应给任务明确的范围和交付结果，在依赖结果之前检查完成状态。

## 发起继承上下文的子任务

第一轮对话完成后，运行：

```text
/subtask 检查解析器测试并报告缺失的边界用例，不要编辑文件。
```

命令启动后台 fork 工作者，继承父会话的完整上下文及已渲染的系统指令。工作者执行指定任务，完成后向当前会话回报；其状态也可在 `/tasks` 中查看。

命令要求会话已初始化且已有系统提示，因此不能在第一轮对话之前执行，也不能在另一个 fork 工作者内部发起。Agent sessions 被禁用时，命令会说明不可用。Agent sessions 默认开启；在默认品牌构建启动前设置 `QWEN_ENABLE_AGENT_SESSIONS=0` 可将其禁用。它与其他实验性 Agent 设置分别控制。

复制上下文不代表工作文件自动隔离。并行工作者应负责独立范围，需要文件系统分离时明确使用 worktree 隔离。“不要编辑文件”是一条指令，不能替代工具权限限制。

## 查看任务

`/tasks` 打开统一后台任务面板，`/bg` 和 `/background` 是别名。可在面板查看当前状态与输出，并按所选任务显示的操作提示管理任务。不同任务类型可能提供不同控制。继续依赖任务之前，请检查完成、失败或中断状态及对应结果。

保存的任务记录用于历史和诊断，不保证 CLI 进程退出后任务继续执行。下次启动时，遗留的运行中记录可能被校正为已中断。后台结果没有出现时，应先查看 `/tasks` 和错误信息，避免直接启动重复操作。

## 工作流任务

`/workflows`（别名 `/workflow-tasks`）打开当前会话的工作流任务浏览器，它本身不定义或启动工作流。

可用工作流命令来自可展示的 workflow Skill，包括已启用插件的资源。命令名和参数要求取决于实际安装的定义。请通过 `/help`、命令补全和 Skill 说明查找真实入口；不存在所有安装环境都可用的统一工作流名称。

使用已安装资源提供的工作流：

1. 在 `/skills` 或 `/plugins` 中检查资源已启用且可见。
2. 阅读工作流描述、输入要求和预期产物。
3. 使用界面显示的斜杠命令，按说明传入参数。
4. 在 `/workflows` 跟进执行，接受结果前检查任务输出。

工作流命令未出现时，检查资源是否可用、工作区是否可信，以及 Skills 是否被管理配置禁用。定义存在于磁盘，不代表已加载或可以运行。单个专门角色见[子 Agent](/zh/users/subagents/)，跨轮次推进目标见[计划与目标](/zh/users/planning/)。
