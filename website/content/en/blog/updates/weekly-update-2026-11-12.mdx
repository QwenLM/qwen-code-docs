Qwen Code shipped five stable releases this week — v0.26.8 through v0.27.2.

**Sign in with your Qwen subscription and get straight to work.** CLI, VS Code, and the desktop app all sign in with a Plus/Pro subscription, and chat and web search run on the models it includes.

**WeChat, QQ, and email all set up in Web Shell.** WeChat and QQ sign in by scanning a QR code on the page; email connects once you fill in the server address and account info.

**GitHub channels filter events by repository.** A whitelist takes only the listed repositories; a blacklist excludes them.

## ✨ New Features

### Sign In with Your Qwen Subscription

If your Qwen account already has a Plus or Pro subscription, sign in with it from the terminal, VS Code, or the desktop app. Run `/auth` in the terminal, choose **Qwen Account with Subscription**, and finish authorization in the browser. Once signed in, the client loads the models your subscription covers, and the built-in web search works too.

What you can do:

- Work directly with the models in your subscription — usage bills to the subscription
- Sign in with the same account on terminal, VS Code, and desktop — the models match everywhere
- Skip the API setup: subscribe to Qwen and use it in Qwen Code right away

See PR [#16378](https://github.com/QwenLM/qwen-code/pull/16378)

![Account and model list after signing in with a Qwen subscription](https://img.alicdn.com/imgextra/i2/O1CN01yN4UdkxBF2G7nW9B_!!6000000007738-2-tps-3841-2160.png)

### Set Up WeChat, QQ, and Email Channels in Web Shell

Channel management in Web Shell now covers three more platforms: WeChat, QQ, and email. WeChat and QQ show a QR code right on the page — scan it with your phone to sign in. For email, fill in the server address and account info. Every major chat platform except Telegram can now be configured in Web Shell.

What you can do:

- Scan the QR code in Web Shell with your phone to connect a personal WeChat DM or bind QQ
- Add or edit email channels in channel management, and choose which senders can start a session by email
- Revoke a channel pairing in Web Shell with one click

See PR [#16736](https://github.com/QwenLM/qwen-code/pull/16736), [#16724](https://github.com/QwenLM/qwen-code/pull/16724), [#16746](https://github.com/QwenLM/qwen-code/pull/16746)

![WeChat channel QR sign-in page in Web Shell](https://img.alicdn.com/imgextra/i1/O1CN01ldag0pIAw9J4s7XG_!!6000000004740-2-tps-2400-1626.png)

### Filter GitHub Channel Events by Repository

A GitHub channel feeds repository events into sessions automatically: someone opens a PR, leaves a comment, CI finishes — the agent picks it up and acts. Now you choose the scope: a whitelist takes only the listed repositories, a blacklist takes everything except the listed ones. Excluded events are skipped outright — they never enter a session and never get processed.

What you can do:

- Your organization has hundreds of repositories — list the two you own, and only their events come in
- Blacklist a repository you're not tracking right now, and add it back when you take it over
- PRs from unrelated repositories stop queuing for the agent, so the repositories you care about get handled faster

See PR [#16493](https://github.com/QwenLM/qwen-code/pull/16493)

![Repository filter settings in the channel editor](https://img.alicdn.com/imgextra/i4/O1CN01NAru06FwyBE7o1Mj_!!6000000003227-2-tps-3845-2160.png)

### Web Shell: Q&A and Usage at a Glance, Sessions Organized in Bulk

**A heatmap for your Q&A.** A long task can run for days. Click the heatmap button and a calendar lays out day by day — darker colors mean more Q&A that day. Click any day to jump straight to its first question and answer. See PR [#16037](https://github.com/QwenLM/qwen-code/pull/16037)

**A usage bar under the input box.** A row of numbers sits below the input box: turn count, output speed, total tokens, and cache hit rate. See PR [#16815](https://github.com/QwenLM/qwen-code/pull/16815)

**Pin and archive sessions in bulk.** A multi-select toggle in the sidebar lets you check several sessions and pin or archive them in one click. See PR [#16702](https://github.com/QwenLM/qwen-code/pull/16702)

**Ask what an option means.** When the AI presents a choice, the question panel has an "Ask for details" button. It opens a side task that explains what each option means, how they differ, what they affect, and which one it recommends. See PR [#16458](https://github.com/QwenLM/qwen-code/pull/16458)

**Other improvements.** Collapse or expand all workspaces with one click, and drag a workspace by its title to reorder it ([#16197](https://github.com/QwenLM/qwen-code/pull/16197)). When a background task waits for your approval, a desktop notification or terminal bell tells you, even if you've switched to another window ([#16800](https://github.com/QwenLM/qwen-code/pull/16800)). Tool cards like MCP calls expand to show parameters and the full result ([#15435](https://github.com/QwenLM/qwen-code/pull/15435)). The skills page takes a ZIP upload to install a skill ([#16424](https://github.com/QwenLM/qwen-code/pull/16424)).

## 📊 More New Features

**Scheduled tasks can choose a delivery channel.** When you create a scheduled task in Web Shell, pick which channel receives the results. See PR [#16524](https://github.com/QwenLM/qwen-code/pull/16524)

**QQ groups get proactive messages.** Results from scheduled tasks, webhooks, and background tasks can now go into a QQ group as proactive messages. An optional `forwardBotMessages` switch also forwards messages from other bots in the group to the session. See PR [#15635](https://github.com/QwenLM/qwen-code/pull/15635), [#15904](https://github.com/QwenLM/qwen-code/pull/15904)

**File change hooks.** Local sessions gain a `FileChanged` hook: it fires when a watched file or directory is created, modified, or deleted — including changes made by other programs. See PR [#13969](https://github.com/QwenLM/qwen-code/pull/13969)

**Three new capabilities for Mods plugins.** `$.store` keeps plugin data across sessions; `ui.render` rewrites the reply text shown in the terminal while stored and copied text stays unchanged; `$.model.complete` runs a one-shot text completion. See PR [#16791](https://github.com/QwenLM/qwen-code/pull/16791), [#16794](https://github.com/QwenLM/qwen-code/pull/16794), [#16737](https://github.com/QwenLM/qwen-code/pull/16737)

**PR comments flow into bound sessions.** Once a session is bound to a PR, new comments on that PR arrive in the session automatically — regular comments and inline review comments alike, no @ needed. See PR [#16602](https://github.com/QwenLM/qwen-code/pull/16602)

## 👏 Experience Improvements

**/btw side questions take follow-ups and run several at once.** A new side question carries the earlier answered ones along, so a follow-up can build on a previous answer. Ask several in a row and each gets its own answer without interrupting the others. See PR [#16408](https://github.com/QwenLM/qwen-code/pull/16408)

**The AI knows which shell you're using at startup.** The session opens by stating which shell commands will run in (bash, cmd.exe, and so on), so the AI writes syntax for your actual shell instead of guessing from the OS — fewer wrong commands on Windows. See PR [#16491](https://github.com/QwenLM/qwen-code/pull/16491)

**Auto session titles follow the conversation language.** A conversation in Chinese gets a title in Chinese — each language gets its own. See PR [#16806](https://github.com/QwenLM/qwen-code/pull/16806)

**Goal check reasons follow the session language.** The reason a check passes or rejects shows in the session's output language. See PR [#15806](https://github.com/QwenLM/qwen-code/pull/15806)

**Follow-up suggestions stay in Thai, Lao, Khmer, and Burmese.** Chat in one of these languages and the follow-up suggestions come back in the same language. See PR [#16341](https://github.com/QwenLM/qwen-code/pull/16341)

**Experimental code intelligence (LSP) turns on in settings.** Set `tools.lspEnabled` to true in your user-level settings — no CLI flag needed, so clients that can't pass flags, like the desktop app, get go-to-definition, find references, and diagnostics too. It ships off by default. See PR [#14613](https://github.com/QwenLM/qwen-code/pull/14613)

**Choose whether subagents run in the foreground or background by default.** Set `agents.defaultBackground` to false and subagents run in the foreground, returning results in the current turn — a fit for channels and bots that need the result within one round. Takes effect after a restart. See PR [#15178](https://github.com/QwenLM/qwen-code/pull/15178)

**Managed sessions hold several questions at once.** Multiple questions from a managed session can stay open together, and you can answer them in any order. See PR [#16484](https://github.com/QwenLM/qwen-code/pull/16484)

**Channel events link into their sessions.** Click an entry in the channel event timeline and jump straight to its session. See PR [#16375](https://github.com/QwenLM/qwen-code/pull/16375)
