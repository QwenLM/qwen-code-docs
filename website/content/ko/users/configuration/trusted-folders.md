
# 신뢰 폴더

신뢰 폴더 기능은 Qwen Code의 전체 기능을 사용할 수 있는 프로젝트를 제어할 수 있는 보안 설정입니다. CLI가 프로젝트별 구성을 로드하기 전에 폴더를 승인하도록 요청하여 잠재적으로 악성 코드가 실행되는 것을 방지합니다.

## 기능 활성화

신뢰 폴더 기능은 **기본적으로 비활성화**되어 있습니다. 사용하려면 먼저 설정에서 활성화해야 합니다.

사용자 `settings.json` 파일에 다음을 추가하세요:

```json
{
  "security": {
    "folderTrust": {
      "enabled": true
    }
  }
}
```

## 작동 방식: 신뢰 대화상자

기능이 활성화되면 폴더에서 처음 Qwen Code를 실행할 때 대화상자가 자동으로 나타나 선택을 요청합니다:

- **Trust folder**: 현재 폴더(예: `my-project`)에 대한 전체 신뢰를 부여합니다.
- **Trust parent folder**: 상위 디렉토리(예: `safe-projects`)에 신뢰를 부여하며, 모든 하위 디렉토리도 자동으로 신뢰합니다. 안전한 프로젝트를 한 곳에 모아두는 경우 유용합니다.
- **Don't trust**: 폴더를 신뢰할 수 없음으로 표시합니다. CLI는 제한된 "안전 모드"로 작동합니다.

선택 사항은 중앙 파일(`~/.qwen/trustedFolders.json`)에 저장되므로 폴더당 한 번만 질문받습니다.

이 기능은 실패 시 안전하게 작동합니다: 선택을 내릴 때까지 폴더는 기본적으로 신뢰됨이 아닌 **신뢰할 수 없음**으로 간주됩니다. 해당 파일이 없는 경우(새 컴퓨터, 복원된 홈 디렉토리, 동기화된 dotfiles 설정) 더 높은 우선순위 시그널이 결정하지 않는 모든 폴더(아래 "신뢰 확인 프로세스(고급)" 참조)는 이전에 신뢰한 폴더를 포함하여 신뢰할 수 없는 상태로 시작합니다. 신뢰 확인이 파일 규칙에 도달했을 때 읽을 수 없는 파일, 잘못된 JSONC 구문, 또는 객체가 아닌 문서는 심각한 구성 오류입니다. 캐시된 로드 실패 시 CLI가 "Please fix the configuration file and try again." 메시지와 함께 중지되고 데몬의 v1 신뢰 확인은 `500 trusted_folders_invalid`로 응답합니다. 이전 IDE 신뢰 결정은 이러한 파일 기반 확인을 우회할 수 있습니다. 부여 작성자는 규칙을 저장하기 전에 여전히 파일을 검증합니다. 파일을 수동으로 복구하거나 제거한 후 데몬을 재시작하여 실패한 로드를 해제합니다. 주석과 후행 쉼표는 허용됩니다. 잘못된 신뢰 수준 값은 부여 작성자와 v2 정책 리더에서 감지되지만 레거시 v1 리더에서는 검증되지 않습니다. v2는 정책 오류를 `configured.state: "error"`와 함께 `200`으로 보고합니다. 캐시된 로드 후에 파일이 무효화되면 부여 쓰기 중에 `500 internal_error`로 실패하거나 쓰기 후 정책 검증 중에 `409 trust_grant_ineffective`로 실패할 수 있습니다.

## 신뢰가 중요한 이유: 신뢰할 수 없는 워크스페이스의 영향

폴더가 **신뢰할 수 없음**으로 표시되면 Qwen Code는 사용자를 보호하기 위해 제한된 "안전 모드"로 실행됩니다. 이 모드에서는 다음 기능이 비활성화됩니다:

1.  **워크스페이스 설정 무시**: CLI는 프로젝트에서 `.qwen/settings.json` 파일을 로드**하지 않습니다**. 이는 사용자 정의 도구 및 기타 잠재적으로 위험한 구성이 로드되는 것을 방지합니다.

2.  **환경 변수 무시**: CLI는 프로젝트에서 `.env` 파일을 로드**하지 않습니다**.

3.  **확장 관리 제한**: 확장을 **설치, 업데이트 또는 제거할 수 없습니다**.

4.  **도구 자동 수락 비활성화**: 전역적으로 자동 수락이 활성화되어 있더라도 도구가 실행되기 전에 항상 프롬프트가 표시됩니다.

5.  **자동 메모리 로딩 비활성화**: CLI는 로컬 설정에서 지정된 디렉토리에서 컨텍스트로 파일을 자동으로 로드하지 않습니다.

폴더에 신뢰를 부여하면 해당 워크스페이스에서 Qwen Code의 전체 기능이 잠금 해제됩니다.

## 신뢰 설정 관리

결정을 변경하거나 모든 설정을 확인해야 하는 경우 몇 가지 옵션이 있습니다:

- **현재 폴더의 신뢰 변경**: CLI 내에서 `/permissions` 명령어를 실행하세요. 동일한 대화형 대화상자가 표시되어 현재 폴더의 신뢰 수준을 변경할 수 있습니다.

- **웹 셸에서 워크스페이스 신뢰**: 워크스페이스 개요를 열고 신뢰할 수 없는 워크스페이스에서 **Trust** 작업을 사용하세요. 이는 터미널 없이도 동일한 결정을 기록하며, 규칙이 결정한 워크스페이스가 없어 모든 워크스페이스가 신뢰할 수 없는 상태로 나타났을 때 복구 방법입니다. 이 작업은 연결된 데몬이 `workspace_trust_grant`를 광고할 때만 나타납니다. 이는 신뢰 핫 리로드가 실행 중인 런타임에 결정을 적용하는 경우에만 해당됩니다. 핫 리로드 없이 부여 라우트를 제공하는 데몬은 이 작업을 숨깁니다. 해당 데몬의 자체 API를 통해 기록된 부여는 신뢰 파일과 v1 신뢰 상태를 즉시 업데이트하지만 시작 시점 런타임 게이트는 재시작이 필요합니다. 별도의 터미널 프로세스나 파일 편집으로 기록된 결정은 데몬의 캐시된 v1 상태에 즉시 표시되지 않습니다. 데몬을 재시작하여 로드하세요. 작업을 사용할 수 있는 경우 데몬이 런타임을 재구성하면 워크스페이스 신뢰가 완료되며, 이 과정에는 잠시 시간이 걸립니다.

- **모든 신뢰 규칙 보기**: 신뢰 및 신뢰할 수 없는 폴더 규칙의 전체 목록을 보려면 홈 디렉토리의 `~/.qwen/trustedFolders.json` 파일 내용을 확인하면 됩니다.

## 신뢰 확인 프로세스(고급)

고급 사용자의 경우 신뢰가 결정되는 정확한 작업 순서를 알아두면 유용합니다:

1.  **IDE 신뢰 시그널**: [IDE 통합](../ide-integration/ide-integration)을 사용하는 경우 CLI는 먼저 IDE에 워크스페이스가 신뢰되는지 묻습니다. IDE의 응답이 가장 높은 우선순위를 가집니다.

2.  **로컬 신뢰 파일**: IDE가 연결되지 않은 경우 CLI는 중앙 `~/.qwen/trustedFolders.json` 파일을 확인합니다.
