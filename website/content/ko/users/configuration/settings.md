
# Qwen Code 설정

> [!tip]
>
> **인증 / API 키:** 인증(API Key, Alibaba Cloud Coding Plan) 및 인증 관련 환경 변수(`OPENAI_API_KEY` 등)는 **[Authentication](../configuration/auth)**에 문서화되어 있습니다.

> [!note]
>
> **새 설정 형식 안내**: `settings.json` 파일의 형식이 더 체계적인 새 구조로 업데이트되었습니다. 기존 형식은 자동으로 마이그레이션됩니다.
> Qwen Code는 환경 변수, 커맨드라인 인자, 설정 파일 등 다양한 방법으로 동작을 구성할 수 있습니다. 이 문서에서는 각 설정 방법과 사용 가능한 설정을 설명합니다.

## 설정 레이어

설정은 다음 우선순위 순서로 적용됩니다(낮은 번호가 높은 번호에 의해 재정의됨):

| 단계 | 설정 소스             | 설명                                                                                      |
| ---- | --------------------- | ----------------------------------------------------------------------------------------- |
| 1    | 기본값                | 애플리케이션 내에 하드코딩된 기본값                                                       |
| 2    | 시스템 기본값 파일    | 다른 설정 파일에 의해 재정의될 수 있는 시스템 전반의 기본 설정                             |
| 3    | 사용자 설정 파일      | 현재 사용자의 전역 설정                                                                   |
| 4    | 프로젝트 설정 파일    | 프로젝트별 설정                                                                           |
| 5    | 시스템 설정 파일      | 다른 모든 설정 파일을 재정의하는 시스템 전반의 설정                                        |
| 6    | 환경 변수             | 시스템 전반 또는 세션별 변수, `.env` 파일에서 로드될 수 있음                               |
| 7    | 커맨드라인 인자       | CLI 시작 시 전달되는 값                                                                   |

## 설정 파일

Qwen Code는 영구 구성에 JSON 설정 파일을 사용합니다. 파일 위치는 네 곳입니다:

| 파일 유형             | 위치                                                                                                                                                                                                                                                                                     | 범위                                                                                                                                                                                                                                          |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 시스템 기본값 파일    | Linux: `/etc/qwen-code/system-defaults.json`<br>Windows: `C:\ProgramData\qwen-code\system-defaults.json`<br>macOS: `/Library/Application Support/QwenCode/system-defaults.json` <br>`QWEN_CODE_SYSTEM_DEFAULTS_PATH` 환경 변수로 경로를 재정의할 수 있습니다.                                | 시스템 전반 기본 설정의 기본 레이어를 제공합니다. 이 설정은 가장 낮은 우선순위를 가지며, 사용자, 프로젝트 또는 시스템 재정의 설정에 의해 재정의되도록 의도되었습니다.                                                                            |
| 사용자 설정 파일      | `~/.qwen/settings.json`(`~`는 홈 디렉토리).                                                                                                                                                                                                                                               | 현재 사용자의 모든 Qwen Code 세션에 적용됩니다.                                                                                                                                                                                               |
| 프로젝트 설정 파일    | 프로젝트 루트 디렉토리 내의 `.qwen/settings.json`.                                                                                                                                                                                                                                         | 해당 특정 프로젝트에서 Qwen Code를 실행할 때만 적용됩니다. 프로젝트 설정은 사용자 설정을 재정의합니다.                                                                                                                                         |
| 시스템 설정 파일      | Linux: `/etc/qwen-code/settings.json` <br>Windows: `C:\ProgramData\qwen-code\settings.json` <br>macOS: `/Library/Application Support/QwenCode/settings.json`<br>`QWEN_CODE_SYSTEM_SETTINGS_PATH` 환경 변수로 경로를 재정의할 수 있습니다.                                                    | 시스템의 모든 사용자에 대한 모든 Qwen Code 세션에 적용됩니다. 시스템 설정은 사용자 및 프로젝트 설정을 재정의합니다. 기업에서 시스템 관리자가 사용자의 Qwen Code 설정을 제어하는 데 유용할 수 있습니다.                                           |

> [!note]
>
> **설정의 환경 변수 참고:** `settings.json` 파일 내의 문자열 값은 `$VAR_NAME` 또는 `${VAR_NAME}` 구문을 사용하여 환경 변수를 참조할 수 있습니다. 이 변수는 설정이 로드될 때 자동으로 해석됩니다. 예를 들어, `MY_API_TOKEN` 환경 변수가 있는 경우 `settings.json`에서 다음과 같이 사용할 수 있습니다: `"apiKey": "$MY_API_TOKEN"`.

### 프로젝트의 `.qwen` 디렉토리

프로젝트 설정 파일 외에도, 프로젝트의 `.qwen` 디렉토리에는 Qwen Code의 작동과 관련된 기타 프로젝트별 파일을 포함할 수 있습니다:

- [사용자 정의 샌드박스 프로파일](../features/sandbox)(예: `.qwen/sandbox-macos-custom.sb`, `.qwen/sandbox.Dockerfile`).
- `.qwen/skills/` 아래의 [Agent Skill](../features/skills)(각 Skill은 `SKILL.md`를 포함하는 디렉토리).

### 설정 마이그레이션

Qwen Code는 레거시 설정을 새 형식으로 자동 마이그레이션합니다. 이전 설정 파일은 마이그레이션 전에 백업됩니다. 다음 설정은 부정(`disable*`)에서 긍정(`enable*`) 명칭으로 변경되었습니다:

| 이전 설정                                | 새 설정                                     | 비고                               |
| ---------------------------------------- | ------------------------------------------- | ---------------------------------- |
| `disableAutoUpdate` + `disableUpdateNag` | `general.enableAutoUpdate`                  | 단일 설정으로 통합                 |
| `disableLoadingPhrases`                  | `ui.accessibility.enableLoadingPhrases`     |                                  |
| `disableFuzzySearch`                     | `context.fileFiltering.enableFuzzySearch`   |                                  |
| `disableCacheControl`                    | `model.generationConfig.enableCacheControl` |                                  |

> [!note]
>
> **불리언 값 반전:** 마이그레이션 시 불리언 값이 반전됩니다(예: `disableAutoUpdate: true`는 `enableAutoUpdate: false`가 됨).

#### `disableAutoUpdate`와 `disableUpdateNag`의 통합 정책

두 레거시 설정이 서로 다른 값으로 존재할 때, 마이그레이션은 다음 정책을 따릅니다: **`disableAutoUpdate`** 또는 **`disableUpdateNag`** 중 하나라도 `true`이면 `enableAutoUpdate`는 `false`가 됩니다:

| `disableAutoUpdate` | `disableUpdateNag` | 마이그레이션된 `enableAutoUpdate` |
| ------------------- | ------------------ | --------------------------------- |
| `false`             | `false`            | `true`                            |
| `false`             | `true`             | `false`                           |
| `true`              | `false`            | `false`                           |
| `true`              | `true`             | `false`                           |

#### review

| 설정                 | 유형    | 설명                                                                                                                                                                                                                                                                                                                                                                                          | 기본값   |
| -------------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| `review.attribution` | boolean | `/review`가 게시하는 리뷰 본문과 인라인 댓글에 모델과 CLI 버전을 명시하는 기여 푸터를 추가합니다(예: `_— qwen3-coder via Qwen Code /review (v0.21.2)_`). AI 기여 표시 없이 리뷰를 게시하려면 비활성화하세요: 푸터가 생략되고 게시된 댓글과 본문 목록에서 `**[Critical]**`/`**[Suggestion]**` 마커가 제거됩니다. 게시물은 원본 소스에서 여전히 식별 가능합니다: 각 댓글에는 보이지 않는 심각도 마커(`<!-- qwen-review critical -->`)가 있으며 리뷰 본문에는 레저 마커(`<!-- qwen-review-ledger ... -->`)가 포함되어, 댓글 본문을 읽는 모든 것(GitHub API 자동화, 이 설정이 연결되는 워크플로)이 여전히 `/review` 아티팩트를 인식하고, 제출 전 중복 감지는 심각도 마커로 리뷰 계정의 이전 게시물을 인식합니다(다른 계정의 비속성 게시물은 제외). 또 다른 결과: qwen-autofix의 Critical-only 모드(5라운드 후 또는 카운팅 창의 diff 성장 예산이 초과되면 더 일찍 활성화)가 더 이상 게시된 발견을 Critical로 인식하지 못하고 지연합니다. 비활성화하면 리뷰 본문에 임베드된 모델이 머신 레저 마커에서도 제거되므로, 새 환경(CI, 다른 클론 — 리뷰 캐시가 없는 곳)에서 마지막 게시 리뷰에서 복구된 증분 앵커가 동일 모델 검사에 실패하고 재리뷰가 전체 범위로 폴백합니다. | `true` |

```json

  "model": {
    "generationConfig": {
      "timeout": 60000,
      "streamIdleTimeoutMs": 300000,
      "contextWindowSize": 128000,
      "modalities": {
        "image": true
      },
      "enableCacheControl": true,
      "toolResultContentFormat": "parts",
      "customHeaders": {
        "X-Client-Request-ID": "req-123"
      },
      "extra_body": {
        "enable_thinking": true
      },
      "samplingParams": {
        "temperature": 0.2,
        "top_p": 0.8,
        "max_tokens": 1024
      }
    }

```

**timeout (요청 타임아웃):**

`timeout`은 밀리초 단위의 요청별 타임아웃(기본값 `120000`)입니다. `0`으로 설정하면 요청 타임아웃을 비활성화합니다 — `QWEN_STREAM_IDLE_TIMEOUT_MS=0` 규칙과 일치 — 요청을 중단하지 않습니다. `QWEN_CODE_API_TIMEOUT_MS` 환경 변수로도 설정할 수 있습니다. 이는 아래의 두 스트림 가드와 구별됩니다.

**스트림 가드 (OpenAI 호환 제공자 전용):**

두 가드가 스트리밍 응답을 제한하며, 각각 `0`을 받아 비활성화합니다. Anthropic/Gemini 생성기는 구현하지 않으며, 아래의 drip-fed 형태를 제한 없이 둡니다.

- `streamIdleTimeoutMs`(기본값 `240000`)는 스트리밍 청크 _사이_의 비활성 시간을 제한합니다: 이 시간 동안 침묵하는 스트림은 재시도 가능한 `ETIMEDOUT`으로 중단됩니다. 제공자 지원 모델의 경우 일치하는 `modelProviders[providerId][].generationConfig` 아래에 설정하고, 런타임 모델의 경우 `model.generationConfig`를 사용하세요. 명시적 모델 값은 `QWEN_STREAM_IDLE_TIMEOUT_MS`보다 우선하며, `0`은 유휴 가드를 비활성화합니다.
- `QWEN_STREAM_MAX_LIFETIME_MS`(기본값 `900000`)는 청크 흐름과 무관하게 하나의 스트리밍 응답의 _전체_ 업스트림 대기 시간을 제한합니다 — 완료되지 않는 drip-fed 스트림이 리셋할 수 없는 바운드.

`streamMaxLifetimeMs`는 `QWEN_STREAM_MAX_LIFETIME_MS`를 통해서만 또는 임베더의 경우 `ContentGeneratorConfig.streamMaxLifetimeMs`를 통해서만 사용 가능하며, `settings.json`에 작성해도 효과가 없습니다. 15분 수명 캡은 유휴 타임아웃을 그 이상으로 올린 스트림도 제한합니다. 더 긴 창에 의존한다면 수명 환경 변수도 동일하게 올리거나 `0`으로 설정하세요. `streamIdleTimeoutMs`만 비활성화한다고 이 수명 캡이 비활성화되지 않습니다.

**max_tokens (출력 토큰 제한):**

`samplingParams.max_tokens`과 `QWEN_CODE_MAX_OUTPUT_TOKENS`가 모두 설정되지 않으면 Qwen Code는 일반적으로 선택된 모델의 선언된 출력 제한을 요청의 기본 출력 제한으로 사용합니다. 응답이 여전히 해당 제한에 도달하면 Qwen Code는 상향된 제한(64K 바닥)으로 재시도하고 연속 턴에 걸쳐 복구할 수 있습니다.

OpenAI 호환 제공자의 경우 `samplingParams`는 와이어 형태 이스케이프 해치이기도 합니다: 설정되면 키가 그대로 전달되며 Qwen Code는 `max_tokens` 기본값을 합성하지 않습니다. `max_completion_tokens` 같은 제공자별 파라미터에 사용하세요.

고정 출력 제한을 강제하려면 설정에서 `samplingParams.max_tokens`을 설정하거나 `QWEN_CODE_MAX_OUTPUT_TOKENS` 환경 변수를 사용하세요. 명시적 제한은 자동 출력 토큰 상향을 비활성화합니다.

**toolResultContentFormat:**

OpenAI 호환 요청에서 텍스트 전용 도구 결과의 직렬화 방식을 제어합니다. 기본값 `"parts"`는 표준 콘텐츠 파트 배열 형태를 유지합니다. `"string"`은 도구 템플리트가 텍스트 콘텐츠 파트를 무시하는 레거시 OpenAI 호환 런타임(예: 오래된 GLM-5.1 vLLM/SGLang 템플리트)에만 설정하세요. 도구 반환 미디어는 여전히 `splitToolMedia`의 영향을 받습니다.

**contextWindowSize:**

선택된 모델의 기본 컨텍스트 창 크기를 재정의합니다. Qwen Code는 모델 이름 패턴 매칭을 기반으로 내장 기본값을 사용하여 컨텍스트 창을 결정하며, 상수 폴백 값이 있습니다. 제공자의 유효 컨텍스트 제한이 Qwen Code의 기본값과 다를 때 이 설정을 사용하세요. 이 값은 모델의 가정된 최대 컨텍스트 용량을 정의하며, 요청별 토큰 제한이 아닙니다.

선택된 모델이 `modelProviders`에 정의되어 있으면 최상위 `model.generationConfig` 대신 해당 제공자 항목의 `generationConfig`에서 `contextWindowSize`를 설정하세요. 제공자 모델 항목은 봉인되어 있으므로 최상위 생성 설정이 누락된 제공자 필드를 채우지 않습니다.

**modalities:**

선택된 모델의 자동 감지된 입력 모달리티를 재정의합니다. Qwen Code는 모델 이름 패턴 매칭을 기반으로 지원되는 모달리티(image, PDF, audio, video)를 자동으로 감지합니다. 자동 감지가 올바르지 않을 때 이 설정을 사용하세요 — 예를 들어 지원하지만 인식되지 않는 모델에 대해 `pdf`를 활성화합니다. 형식: `{ "image": true, "pdf": true, "audio": true, "video": true }`. 지원되지 않는 유형은 키를 생략하거나 `false`로 설정하세요.

**customHeaders:**

모든 API 요청에 사용자 정의 HTTP 헤더를 추가할 수 있습니다. 요청 추적, 모니터링, API 게이트웨이 라우팅 또는 다른 모델이 다른 헤더를 요구할 때 유용합니다. 제공자 모델의 경우 `modelProviders[].generationConfig.customHeaders`에 `customHeaders`를 정의하세요. 일치하는 제공자 항목이 없는 런타임 모델의 경우 `model.generationConfig.customHeaders`에 정의하세요. 두 수준 간 병합은 발생하지 않습니다.

`extra_body` 필드는 API로 전송되는 요청 body에 사용자 정의 파라미터를 추가할 수 있습니다. 표준 구성 필드에서 다루지 않는 제공자별 옵션에 유용합니다. **참고: 이 필드는 OpenAI 호환 제공자(`openai`, `qwen-oauth`)에서만 지원됩니다. Anthropic과 Gemini 제공자에서는 무시됩니다.** 제공자 모델의 경우 `modelProviders[].generationConfig.extra_body`에 `extra_body`를 정의하세요. 일치하는 제공자 항목이 없는 런타임 모델의 경우 `model.generationConfig.extra_body`에 정의하세요.

**model.openAILoggingDir 예시:**

- `"~/qwen-logs"` - `~/qwen-logs` 디렉토리에 로깅
- `"./custom-logs"` - 현재 디렉토리 기준 `./custom-logs`에 로깅
- `"/tmp/openai-logs"` - 절대 경로 `/tmp/openai-logs`에 로깅

#### 파일 검색 성능 문제 해결

파일 검색(예: `@` 완성)에서 성능 문제가 발생하면, 특히 파일 수가 매우 많은 프로젝트에서 다음 방법을 순서대로 시도해 보세요:

1. **ignore 파일 사용:** 프로젝트 루트에 `.qwenignore` 또는 구성된 사용자 정의 ignore 파일을 생성하여 참조할 필요가 없는 대량 파일이 포함된 디렉토리(예: 빌드 아티팩트, 로그, `node_modules`)를 제외하세요. 크롤링되는 총 파일 수를 줄이는 것이 성능을 개선하는 가장 효과적인 방법입니다.
2. **퍼지 검색 비활성화:** 파일 무시만으로는 부족하면 `settings.json`에서 `enableFuzzySearch`를 `false`로 설정하여 퍼지 검색을 비활성화할 수 있습니다. 더 단순한 비퍼지 매칭 알고리즘을 사용하여 더 빠를 수 있습니다.
3. **재귀 파일 검색 비활성화:** 마지막 수단으로 `enableRecursiveFileSearch`를 `false`로 설정하여 재귀 파일 검색을 완전히 비활성화할 수 있습니다. 프로젝트의 재귀 크롤을 피하므로 가장 빠른 옵션입니다. 단, `@` 완성 사용 시 파일의 전체 경로를 입력해야 합니다.

#### permissions

권한 시스템은 어떤 도구를 실행할 수 있는지, 어떤 도구가 확인이 필요한지, 어떤 도구가 차단되는지에 대한 세밀한 제어를 제공합니다.

**결정 우선순위(높은 순): `deny` > `ask` > `allow` > _(기본값/대화형 모드)_**

첫 번째로 일치하는 규칙이 승리합니다. 규칙은 `"ToolName"` 또는 `"ToolName(specifier)"` 형식을 사용합니다.

| 설정              | 유형             | 설명                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | 기본값      |
| ----------------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| `permissions.allow` | array of strings | 자동 승인된 도구 호출에 대한 규칙(확인 불필요). 모든 범위(사용자 + 프로젝트 + 시스템)에서 병합됩니다. 레지스트리 수준 허용 목록으로도 작동합니다: 유효한 allow 규칙이 하나 이상 구성되어 있으면(잘못된 항목은 계산되지 않으며, `--allowed-tools` CLI 플래그와 같은 자동 승인 전용 소스는 활성화하지 않음), allow 또는 ask 규칙으로 커버되지 않는 내장 도구가 지연 도구로 강등됩니다 — 등록된 상태로 유지되며(`/tools`에 나열되고 `tool_search` 도구를 통해 필요 시 로드 가능), 하지만 스키마가 즉시 모델 요청에 전송되지 않으며, 호출 시 여전히 일반 승인 흐름을 거칩니다. 이렇게 하면 커버되지 않은 스키마가 모델 요청에서 제외되면서 도구가 조용히 제거되지 않습니다. MCP 도구, `--json-schema` `structured_output` 계약, plan 모드 수명 주기 도구 `exit_plan_mode` / `enter_plan_mode` / `ask_user_question`, `task_stop`, `tool_search` 및 지연 `computer_use__*` 패밀리는 면제되며 즉시 사용 가능한 상태로 유지됩니다. 세션 중간에 규칙을 제거하면 자동 승인이 즉시 취소되지만 레지스트리 구성 변경은 재시작 시 적용됩니다. 예외: AUTO 승인 모드에서는 위험한 allow 규칙이 활성 대신 보관되므로 세션 중간 제거가 보관에 영향을 줄 수 없습니다 — AUTO 모드를 종료하면 보관된 규칙이 복원되어 세션 재시작까지 다시 자동 승인합니다. 재시작이 필요합니다. | `undefined` |
| `permissions.ask`   | array of strings | 항상 사용자 확인이 필요한 도구 호출에 대한 규칙. `allow`보다 우선합니다. Ask 규칙도 레지스트리 허용 목록에 포함됩니다: ask 규칙으로 커버되는 도구는 허용 목록이 활성 상태에서도 등록된 상태로 유지되므로 "항상 확인 필요"가 조용히 "도구 사용 불가"로 변하지 않습니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | `undefined` |
| `permissions.deny`  | array of strings | 차단된 도구 호출에 대한 규칙. 최고 우선순위 — `allow`와 `ask` 모두를 재정의합니다. 전체 도구 deny 규칙(specifier 없음)은 내장 도구와 `tools.discoveryCommand`를 통해 발견된 도구를 레지스트리에서도 제거합니다. MCP 도구는 면제입니다(등록 경로가 `disabledTools`만 존중함): 서버별 `excludeTools` / `tools.disabled` 필터로 숨기세요. Deny 규칙은 여전히 런타임에 MCP 도구 호출을 차단합니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | `undefined` |

**도구 이름 별칭(규칙에서 모두 작동):**

| 별칭                | 표준 도구           | 비고                      |
| ------------------- | ------------------- | ------------------------- |
| `Bash`, `Shell`     | `run_shell_command` |                           |
| `Read`, `ReadFile`  | `read_file`         | 메타 범주 — 아래 참조     |
| `Edit`, `EditFile`  | `edit`              | 메타 범주 — 아래 참조     |
| `Write`, `WriteFile` | `write_file`       |                           |
| `NotebookEdit`      | `notebook_edit`     |                           |
| `NotebookEditTool`  | `notebook_edit`     |                           |
| `Grep`, `SearchFiles` | `grep_search`     |                           |
| `Glob`, `FindFiles` | `glob`              |                           |
| `ListFiles`         | `list_directory`    |                           |
| `WebFetch`          | `web_fetch`         |                           |
| `Agent`             | `task`              |                           |
| `Skill`             | `skill`             |                           |

**메타 범주:**

일부 규칙 이름은 자동으로 여러 도구를 포함합니다:

| 규칙 이름 | 포함되는 도구                                  |
| --------- | ---------------------------------------------- |
| `Read`    | `read_file`, `grep_search`, `glob`, `list_directory` |
| `Edit`    | `edit`, `write_file`, `notebook_edit`          |

> [!important]
> `Read(/path/**)`는 **네 가지** 읽기 도구(파일 읽기, grep, glob, 디렉토리 목록)를 모두 포함합니다.
> 파일 읽기만 제한하려면 `ReadFile(/path/**)` 또는 `read_file(/path/**)`를 사용하세요.

**규칙 구문 예시:**

| 규칙                        | 의미                                                          |
| --------------------------- | ------------------------------------------------------------- |
| `"Bash"`                    | 모든 셸 명령                                                   |
| `"Bash(git *)"`             | `git`으로 시작하는 셸 명령(단어 경계: `gitk`는 아님)           |
| `"Bash(git push *)"`        | `git push origin main` 같은 셸 명령                            |
| `"Bash(npm run *)"`         | 모든 `npm run` 스크립트                                        |
| `"Read"`                    | 모든 파일 읽기 작업(읽기, grep, glob, 목록)                    |
| `"Read(./secrets/**)"`      | `./secrets/` 아래의 모든 파일을 재귀적으로 읽기                |
| `"Edit(/src/**/*.ts)"`      | 프로젝트 루트 `/src/` 아래의 TypeScript 파일 편집              |
| `"WebFetch(api.example.com)"` | `api.example.com`과 모든 하위 도메인에서 가져오기            |
| `"mcp__puppeteer"`          | puppeteer MCP 서버의 모든 도구                                 |

**경로 패턴 접두사:**

| 접두사  | 의미                               | 예시                |
| ------- | ---------------------------------- | ------------------- |
| `//`    | 파일 시스템 루트의 절대 경로       | `//etc/passwd`      |
| `~/`    | 홈 디렉토리 기준 상대 경로         | `~/Documents/*.pdf` |
| `/`     | 프로젝트 루트 기준 상대 경로       | `/src/**/*.ts`      |
| `./`    | 현재 작업 디렉토리 기준 상대 경로  | `./secrets/**`      |
| (없음)  | `./`와 동일                        | `secrets/**`        |

**셸 명령 우회 방지:**

`Read`, `Edit`, `WebFetch`의 권한 규칙은 에이전트가 동등한 셸 명령을 실행할 때도 적용됩니다. 예를 들어, `Read(./.env)`가 `deny`에 있으면 에이전트는 셸 명령에서 `cat .env`로 우회할 수 없습니다. 지원되는 셸 명령에는 `cat`, `grep`, `curl`, `wget`, `cp`, `mv`, `rm`, `chmod` 등이 포함됩니다. 알려지지 않은/안전한 명령(예: `git`)은 파일/네트워크 규칙의 영향을 받지 않습니다.

**레거시 설정에서 마이그레이션:**

| 레거시 설정   | 해당 `permissions` 규칙     | 비고                                                         |
| ------------- | --------------------------- | ------------------------------------------------------------ |
| `tools.allowed` | `permissions.allow`       | 첫 로드 시 자동 마이그레이션                                 |
| `tools.exclude` | `permissions.deny`        | 첫 로드 시 자동 마이그레이션                                 |
| `tools.core`    | `permissions.allow`(허용 목록) | 자동 마이그레이션; 목록에 없는 도구는 지연 도구로 강등 — 등록되고 `tool_search`를 통해 로드 가능하지만 스키마가 즉시 모델 요청에서 제외됨 |

**설정 예시:**

```json
{
  "permissions": {
    "allow": ["Bash(git *)", "Bash(npm run *)", "Read(//Users/alice/code/**)"],
    "ask": ["Bash(git push *)", "Edit"],
    "deny": ["Bash(rm -rf *)", "Read(.env)", "WebFetch(malicious.com)"]
  }
}
```

> [!tip]
> 인터랙티브 CLI에서 `/permissions`를 사용하면 `settings.json`을 직접 편집하지 않고도 규칙을 보고, 추가하고, 제거할 수 있습니다.

#### slashCommands

CLI에서 사용 가능한 슬래시 명령어를 제어합니다. 멀티테넌트 또는 기업 배포에서 명령어 표면을 제한하는 데 유용합니다.

| 설정                   | 유형             | 설명                                                                                                                                                                                                                                                                                                                 | 기본값      |
| ---------------------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| `slashCommands.disabled` | array of strings | 숨기고 실행을 거부할 슬래시 명령어 이름. 최종 명령어 이름에 대해 대소문자 구분 없이 매칭됩니다(확장 명령어의 경우 명확화된 형식, 예: `myext.deploy`). **범위를 가로질러 합집합으로 병합**되므로 워크스페이스 설정은 사용자 또는 시스템 설정에서 정의된 항목을 추가할 수 있지만 제거할 수는 없습니다.                     | `undefined` |

동일한 거부 목록은 `--disabled-slash-commands` CLI 플래그(쉼표로 구분 또는 반복)와 `QWEN_DISABLED_SLASH_COMMANDS` 환경 변수를 통해서도 제공될 수 있으며, 세 출처의 값이 모두 합집합됩니다.

**예시 — 샌드박스 배포를 위한 내장 명령어 잠금:**

```json
{
  "slashCommands": {
    "disabled": ["auth", "mcp", "extensions", "ide", "quit"]
  }
}
```

시스템 수준 `settings.json`(`/etc/qwen-code/settings.json` 또는 `QWEN_CODE_SYSTEM_SETTINGS_PATH`)에 이러한 값이 있으면 사용자는 자체 범위에서 거부 목록을 축소할 수 없으며 비활성화된 명령어는 자동 완성에서 나타나지 않고 입력 시 실행되지 않습니다.

> [!note]
> 이 설정은 슬래시 명령어(예: `/auth`, `/mcp`)만 게이트합니다. 도구 권한에는 영향을 주지 않습니다 — 해당 내용은 `permissions.deny`를 참조하세요. `Ctrl+C` 또는 `Esc` 같은 키보드 단축키도 가로채지 않습니다.

#### skills

모델에 노출되는 [Skill](../features/skills)을 제어합니다.

| 설정                   | 유형             | 설명                                                                                                                                                                                                                                                                                                                                      | 기본값      |
| ---------------------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| `skills.disabledLevels`  | array of strings | 완전히 건너뛸 skill 발견 레벨. 지원되는 값은 `project`, `user`, `extension`, `bundled`입니다. 설정 범위를 가로질러 합집합으로 병합됩니다. `["bundled"]`를 사용하면 호스트 제공 skill을 유지하면서 모든 번들 skill을 숨깁니다. 참고: `skills.directories` 항목은 `user` 레벨에서 발견되므로 `["user"]`는 이것들도 숨깁니다.             | `undefined` |
| `skills.disabled`        | array of strings | 하드 비활성화된 skill 이름. 대소문자 구분 없이 매칭되며 설정 범위를 가로질러 **합집합으로 병합**되므로 프로젝트 설정이 사용자 또는 시스템 항목을 재정의할 수 없습니다. 숨겨진 skill은 `<available_skills>` 또는 `/<name>` 슬래시 명령어로 나타나지 않습니다.                                                                               | `undefined` |
| `skills.defaultDisabled` | array of strings | 기본적으로 비활성화되지만 `skills.enabled`를 통해 옵트인할 수 있는 skill 이름. 대소문자 구분 없이 매칭되며 설정 범위를 가로질러 합집합으로 병합됩니다.                                                                                                                                                                                    | `undefined` |
| `skills.enabled`         | array of strings | 일치하는 `skills.defaultDisabled` 항목을 재정의하는 명시적 옵트인. 대소문자 구분 없이 매칭되며 설정 범위를 가로질러 합집합으로 병합됩니다. 이 설정은 `skills.disabled`를 재정의하거나 `skills.disabledLevels`에서 제외된 레벨의 skill을 다시 활성화할 수 없습니다.                                                                         | `undefined` |

우선순위는 `skills.disabled` > `skills.enabled` > `skills.defaultDisabled`입니다. 예를 들어 사용자는 skill을 `defaultDisabled`에 넣을 수 있고 프로젝트는 동일한 이름을 `enabled`에 추가할 수 있습니다. 어느 범위의 하드 `disabled` 항목이 여전히 승리합니다.

#### lsp

> [!warning]
> **실험적 기능**: LSP 지원은 현재 실험적이며 기본적으로 비활성화되어 있습니다. `--experimental-lsp` 커맨드라인 플래그를 사용하여 활성화하세요.

Language Server Protocol(LSP)은 go-to-definition, 참조 찾기, 진단과 같은 코드 인텔리전스 기능을 제공합니다.

LSP 서버 구성은 `settings.json`이 아닌 프로젝트 루트 디렉토리의 `.lsp.json` 파일을 통해 수행됩니다. 구성 세부 정보와 예시는 [LSP 문서](../features/lsp)를 참조하세요.

#### serve

[`qwen serve`](../qwen-serve)의 영구 서브 세션 동시성 설정. 변경 사항은 데몬을 재시작해야 합니다. 양수가 아니거나 정수가 아닌 동시성 제한은 경고를 생성하고 내장 기본값으로 폴백합니다.

#### mcpServers

사용자 정의 도구를 발견하고 사용하기 위해 하나 이상의 모델 컨텍스트 프로토콜(MCP) 서버에 대한 연결을 구성합니다. Qwen Code는 구성된 각 MCP 서버에 연결하여 사용 가능한 도구를 발견하려고 시도합니다. 여러 MCP 서버가 동일한 이름의 도구를 노출하면 도구 이름에 구성에서 정의한 서버 별칭이 접두사로 추가됩니다(예: `serverAlias__actualToolName`). 시스템이 호환성을 위해 MCP 도구 정의에서 특정 스키마 속성을 제거할 수 있습니다. `command`, `url`, `httpUrl` 중 최소 하나를 제공해야 합니다. 여러 개가 지정되면 우선순위 순서는 `httpUrl`, 그다음 `url`, 그다음 `command`입니다.

| 속성                                  | 유형             | 설명                                                                                                                                                                                                                                                         | 선택 사항 |
| ------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------- |
| `mcpServers.<SERVER_NAME>.command`    | string           | 표준 I/O를 통해 MCP 서버를 시작하기 위해 실행할 명령.                                                                                                                                                                                                         | 예        |
| `mcpServers.<SERVER_NAME>.args`       | array of strings | 명령에 전달할 인자.                                                                                                                                                                                                                                           | 예        |
| `mcpServers.<SERVER_NAME>.env`        | object           | 서버 프로세스에 설정할 환경 변수.                                                                                                                                                                                                                              | 예        |
| `mcpServers.<SERVER_NAME>.cwd`        | string           | 서버를 시작할 작업 디렉토리.                                                                                                                                                                                                                                  | 예        |
| `mcpServers.<SERVER_NAME>.url`        | string           | Server-Sent Events(SSE)를 통신에 사용하는 MCP 서버의 URL.                                                                                                                                                                                                     | 예        |
| `mcpServers.<SERVER_NAME>.httpUrl`    | string           | 스트리밍 가능한 HTTP를 통신에 사용하는 MCP 서버의 URL.                                                                                                                                                                                                         | 예        |
| `mcpServers.<SERVER_NAME>.headers`    | object           | `url` 또는 `httpUrl`로의 요청과 함께 전송할 HTTP 헤더 맵.                                                                                                                                                                                                     | 예        |
| `mcpServers.<SERVER_NAME>.timeout`    | number           | 이 MCP 서버로의 요청에 대한 타임아웃(밀리초).                                                                                                                                                                                                                 | 예        |
| `mcpServers.<SERVER_NAME>.trust`      | boolean          | 신뢰할 수 있는 워크스페이스에서 이 서버를 신뢰하고 도구 호출 확인을 우회합니다.                                                                                                                                                                                 | 예        |
| `mcpServers.<SERVER_NAME>.description` | string          | 표시 목적으로 사용될 수 있는 서버의 간단한 설명.                                                                                                                                                                                                               | 예        |
| `mcpServers.<SERVER_NAME>.includeTools` | array of strings | 이 MCP 서버에서 포함할 도구 이름 목록. 지정되면 여기에 나열된 도구만 이 서버에서 사용 가능합니다(허용 목록 동작). 지정하지 않으면 서버의 모든 도구가 기본적으로 활성화됩니다.                                                                                   | 예        |
| `mcpServers.<SERVER_NAME>.excludeTools` | array of strings | 이 MCP 서버에서 제외할 도구 이름 목록. 여기에 나열된 도구는 서버에서 노출되더라도 모델이 사용할 수 없습니다. **참고:** `excludeTools`는 `includeTools`보다 우선합니다 — 도구가 두 목록 모두에 있으면 제외됩니다.                                                 | 예        |

## 셸 기록

CLI는 실행한 셸 명령의 기록을 유지합니다. 다른 프로젝트 간의 충돌을 피하기 위해 이 기록은 사용자 홈 폴더 내의 프로젝트별 디렉토리에 저장됩니다.

- **위치:** `~/.qwen/tmp/<project_hash>/shell_history`
  - `<project_hash>`는 프로젝트의 루트 경로에서 생성된 고유 식별자입니다.
  - 기록은 `shell_history`라는 파일에 저장됩니다.

## 환경 변수 및 `.env` 파일

환경 변수는 애플리케이션을 구성하는 일반적인 방법이며, 특히 민감한 정보(토큰 등)나 환경 간에 변경될 수 있는 설정에 사용됩니다.

Qwen Code는 `.env` 파일에서 환경 변수를 자동으로 로드할 수 있습니다.
인증 관련 변수(`OPENAI_*` 등)와 권장 `.qwen/.env` 접근 방식은 **[Authentication](../configuration/auth)**을 참조하세요.

> [!tip]
>
> **환경 변수 제외:** 일부 환경 변수(`DEBUG`, `DEBUG_MODE` 등)는 CLI 동작에 간섭하는 것을 방지하기 위해 프로젝트 `.env` 파일에서 기본적으로 자동으로 제외됩니다. `.qwen/.env` 파일의 변수는 절대 제외되지 않습니다. `settings.json`의 `advanced.excludedEnvVars` 설정을 사용하여 이 동작을 사용자 정의할 수 있습니다.

> [!warning]
>
> **로더 영향 변수는 항상 거부됩니다:** 생성된 Node.js 프로세스나 OS 로더가 공격자가 선택한 파일을 실행하도록 만드는 변수 — `NODE_OPTIONS`, `npm_config_node_options`(및 npm의 구성 파일 리디렉션 `npm_config_userconfig`, `npm_config_globalconfig`, `npm_config_script_shell`, `npm_config_prefix`), `NODE_PATH`, `OPENSSL_CONF`(시작 시 공격자 OpenSSL 엔진을 dlopen), `NODE_REPL_EXTERNAL_MODULE`, `npm_config_node_gyp`, `npm_config_init_module`, `LD_PRELOAD`, `LD_AUDIT`, `DYLD_INSERT_LIBRARIES`, `BASH_ENV`, `ZDOTDIR` 및 내보낸 bash 함수 정의(`BASH_FUNC_*`) — 는 `.env` 파일(`.qwen/.env` 및 사용자 수준 파일을 포함한 모든 범위)이나 최상위 `settings.json` `env` 섹션에서 절대 로드되지 않습니다(어떤 scope에서도). 워크스페이스가 제어하는 값이 있으면 Qwen Code가 생성하는 모든 서브프로세스의 모듈 해석을 탈취할 수 있으므로, Qwen Code는 이러한 키를 거부할 때 경고를 출력합니다(프로세스당 한 번, 키 및 소스별 — 다중 워크스페이스 데몬에서는 각 워크스페이스의 거부가 별도로 보고됨). 이러한 변수 중 하나를 사용하려면 Qwen Code를 시작하는 환경에서 내보내세요; `qwen serve` 데몬이 호스팅하는 세션은 의도적으로 이를 상속하지 않지만, 직접 편집기(ACP) 세션과 일반 CLI는 내보낸 값을 유지합니다. 라이브러리 _검색_ 경로(`LD_LIBRARY_PATH`, `DYLD_LIBRARY_PATH`) 및 대화형 셸 전용 `ENV`는 의도적으로 이 목록에 없습니다 — 이를 거부하면 주류 도구 체인이 깨집니다(`ENV=production`, conda/CUDA 라이브러리 디렉토리) — 하지만 프로젝트 `.env`는 여전히 리로드 시 이를 적용할 수 없습니다. 이 거부는 최상위 `env` 섹션에만 적용됩니다: 서버별 `mcpServers[].env`와 hook별 `hooks[].env`는 의도적으로 해당 서버나 hook으로 범위가 지정되며 여전히 적용됩니다(두 표면 모두 워크스페이스 제공 구성에 대해 폴더 신뢰로 게이트됨). 별도로, 프로젝트 `.env`는 `QWEN_CLI_ENTRY`(데몬의 세션 프로세스 엔트리포인트), `QWEN_CDP_MCP_COMMAND`(데몬이 브라우저 자동화 MCP 어댑터로 생성하는 명령), `QWEN_SERVE_CDP_TUNNEL_OVER_WS`(해당 터널 표면을 전환), `DEV`(개발 하네스 시작 마커), TLS 신뢰 앵커 변수(`NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE`, `SSL_CERT_DIR`, `CURL_CA_BUNDLE`, `REQUESTS_CA_BUNDLE`, `GIT_SSL_CAINFO`, `GIT_SSL_CAPATH`, `npm_config_cafile`, `npm_config_ca`, `npm_config_strict_ssl`, `PIP_CERT` — 여기에 공격자 CA가 있거나 `npm_config_strict_ssl=false`이면 세션의 `git`/`npm`/`pip`/`curl` 호출이 만드는 토큰 포함 트래픽에 대한 MITM이 가능해짐), git 명령 실행 변수(`GIT_SSH_COMMAND`, `GIT_SSH`, `GIT_EXEC_PATH`, `GIT_TEMPLATE_DIR`, `GIT_ASKPASS`, `GIT_PROXY_COMMAND`, `GIT_EDITOR`, `GIT_SEQUENCE_EDITOR`, `GIT_EXTERNAL_DIFF`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`, `GIT_CONFIG_COUNT`, `GIT_CONFIG_PARAMETERS` 및 번호가 매겨진 `GIT_CONFIG_KEY_<n>`/`GIT_CONFIG_VALUE_<n>` 쌍 — git이 세션 `git` 호출마다 실행 — 그리고 `XDG_CONFIG_HOME`(`$XDG_CONFIG_HOME/git/config`를 리디렉션하며 git이 `~/.gitconfig`와 병합), curl/wget rc 파일 리디렉션(`CURL_HOME`, `WGETRC` — rc 파일이 공격자 프록시나 CA를 설치할 수 있음), `PIP_CONFIG_FILE`(pip의 모든 구성을 리디렉션 — 공격자 파일의 `index-url`, `trusted-host`, 프록시 또는 cert 설정이 세션 pip 트래픽이나 자격 증명을 공격자 인프라로 전송), `SSH_ASKPASS`(git/ssh가 인증 챌린지에서 폴백 암호 프롬프트 프로그램으로 실행), `LESSOPEN` 및 `LESSCLOSE`(`less`가 세션이 보는 모든 파일의 입력 전처리기로 실행), node-gyp 인터프리터 선택 변수(`NODE_GYP_FORCE_PYTHON`, `npm_config_python`, `PYTHON` — 네이티브 애드온 설치 중 빌드 Python으로 실행 — 및 `npm_config_git`, npm의 git 바이너리로 실행), 편집기 및 시작 hook(`VISUAL`, `EDITOR` — git의 편집기 폴백 체인, CLI 자체의 외부 편집기 흐름에서도 생성 — 및 `PYTHONSTARTUP`, CPython이 대화형 시작 시 실행), 또는 `BROWSER`(CLI가 보안 브라우저 런처를 통해 실행)를 설정할 수 없습니다. 이들은 셸 환경이나 사용자 수준 `.env`에서 설정 가능합니다; 위의 로더 목록과 달리 프로젝트 파일에서만 거부되므로 직접 내보낸 값은 보존됩니다. 또한 부팅 시 사용자 수준 `.env`에서 고정되므로: 설정 리로드는 여기에 대한 편집이나 제거를 적용하지 않으며 프로세스 재시작까지 적용되지 않습니다. 업그레이드 참고: 이 거부 목록이 존재하기 전에는 일부 키가 `.env` 파일이나 `settings.json` `env`에서 일부 경로에서 로드될 수 있었습니다; 이제 모든 곳에서 경고와 함께 거부되며, `qwen serve` 데몬은 더 이상 세션 서브프로세스에 상속된 값을 전달하지 않습니다.

## 컨텍스트 파일(계층적 지시 컨텍스트)

CLI의 _동작_에 대한 엄격한 구성은 아니지만, 컨텍스트 파일(기본적으로 `QWEN.md`이지만 `context.fileName` 설정으로 구성 가능)은 _지시 컨텍스트_("메모리"라고도 함)를 구성하는 데 중요합니다. 이 강력한 기능을 사용하면 프로젝트별 지시, 코딩 스타일 가이드 또는 관련 배경 정보를 AI에게 제공하여 응답을 사용자의 요구에 더 맞고 정확하게 만들 수 있습니다. CLI는 로드된 컨텍스트 파일 수를 나타내는 footer 표시기와 같은 UI 요소를 통해 활성 컨텍스트에 대한 정보를 제공합니다.

- **목적:** 이 Markdown 파일에는 Qwen 모델이 응답을 생성할 때 참조할 지시, 가이드라인 또는 컨텍스트가 포함됩니다. 시스템은 이러한 지시 컨텍스트를 계층적으로 관리하도록 설계되었습니다.
- **위치:** 컨텍스트 파일은 프로젝트 루트 또는 그 상위 디렉토리에 배치할 수 있습니다.

### 컨텍스트 파일 내용 예시(예: `QWEN.md`)

TypeScript 프로젝트 루트에 있는 컨텍스트 파일의 개념적 예시:

```
# Project: My Awesome TypeScript Library

## General Instructions:
- When generating new TypeScript code, please follow the existing coding style.
- Ensure all new functions and classes have JSDoc comments.
- Prefer functional programming paradigms where appropriate.
- All code should be compatible with TypeScript 5.0 and Node.js 22+.

## Coding Style:
- Use 2 spaces for indentation.
- Interface names should be prefixed with `I` (e.g., `IUserService`).
- Private class members should be prefixed with an underscore (`_`).
- Always use strict equality (`===` and `!==`).

## Specific Component: `src/api/client.ts`
- This file handles all outbound API requests.
- When adding new API call functions, ensure they include robust error handling and logging.
- Use the existing `fetchWithRetry` utility for all GET requests.

## Regarding Dependencies:
- Avoid introducing new external dependencies unless absolutely necessary.
- If a new dependency is required, please state the reason.
```

이 예시는 일반 프로젝트 컨텍스트, 특정 코딩 규칙, 특정 파일이나 컴포넌트에 대한 노트를 제공하는 방법을 보여줍니다. 컨텍스트 파일이 관련성이 있고 정확할수록 AI가 더 잘 도울 수 있습니다. 프로젝트별 컨텍스트 파일을 사용하여 규칙과 컨텍스트를 설정하는 것을 강력히 권장합니다.

- **계층적 로딩 및 우선순위:** CLI는 여러 위치에서 컨텍스트 파일(예: `QWEN.md`)을 로드하여 계층적 메모리 시스템을 구현합니다. 이 목록의 아래(더 구체적)에 있는 파일의 내용은 위(더 일반적)에 있는 파일의 내용을 일반적으로 재정의하거나 보완합니다. 정확한 연결 순서와 최종 컨텍스트는 `/memory` 대화상자에서 확인할 수 있습니다. 일반적인 로딩 순서는 다음과 같습니다:
  1. **전역 컨텍스트 파일:**
     - 위치: `~/.qwen/<configured-context-filename>`(예: 사용자 홈 디렉토리의 `~/.qwen/QWEN.md`).
     - 범위: 모든 프로젝트에 대한 기본 지시를 제공합니다.
  2. **프로젝트 루트 및 상위 컨텍스트 파일:**
     - 위치: CLI는 현재 작업 디렉토리에서 구성된 컨텍스트 파일을 검색한 다음 프로젝트 루트(`.git` 폴더로 식별) 또는 홈 디렉토리까지 각 상위 디렉토리에서 검색합니다.
     - 범위: 전체 프로젝트 또는 그 상당 부분과 관련된 컨텍스트를 제공합니다.
- **연결 및 UI 표시:** 발견된 모든 컨텍스트 파일의 내용은 구분 기호와 함께 연결(출처와 경로를 표시)되어 시스템 프롬프트의 일부로 제공됩니다. CLI footer는 로드된 컨텍스트 파일 수를 표시하여 활성 지시 컨텍스트에 대한 빠른 시각적 단서를 제공합니다.
- **내용 가져오기:** `@path/to/file.md` 구문을 사용하여 다른 Markdown 파일을 가져옴으로써 컨텍스트 파일을 모듈화할 수 있습니다. 자세한 내용은 [Memory 문서](../features/memory.md)를 참조하세요.
- **메모리 관리 명령어:**
  - `/memory`를 사용하여 메모리 관리 대화상자를 엽니다.
  - 대화상자에서 메모리를 새로 고쳐 모든 구성된 위치에서 컨텍스트 파일을 다시 검색하고 로드합니다.
  - `/memory` 명령어에 대한 자세한 내용은 [Commands 문서](../features/commands.md)를 참조하세요.

구성 레이어와 컨텍스트 파일의 계층적 특성을 이해하고 활용함으로써 AI의 메모리를 효과적으로 관리하고 Qwen Code의 응답을 특정 요구와 프로젝트에 맞게 조정할 수 있습니다.

## 샌드박스

Qwen Code는 시스템을 보호하기 위해 샌드박스 환경에서 잠재적으로 안전하지 않은 작업(셸 명령 및 파일 수정 등)을 실행할 수 있습니다.

[샌드박스](../features/sandbox)는 기본적으로 비활성화되어 있지만 다음 방법으로 활성화할 수 있습니다:

- `--sandbox` 또는 `-s` 플래그 사용.
- `QWEN_SANDBOX` 환경 변수 설정.
- 설정에서 `tools.sandbox` 설정.

> ⚠️ **`--yolo`는 샌드박스를 자동으로 활성화하지 _않습니다_.** YOLO 모드는 도구 호출만 자동 승인합니다. 샌드박싱은 `--sandbox`, `QWEN_SANDBOX` 또는 `tools.sandbox`를 통해 별도로 옵트인해야 합니다. `--yolo`(또는 `--approval-mode=yolo`)와 샌드박스 없이 헤드리스/비대화형 실행에서 모델은 현재 프로세스의 권한 수준에서 셸, 쓰기 및 편집 도구를 실행할 수 있습니다 — Qwen Code는 이 경우 stderr에 경고를 출력합니다. 트레이드오프를 검토한 후 `QWEN_CODE_SUPPRESS_YOLO_WARNING=1`로 억제하세요.

기본적으로 미리 빌드된 `qwen-code-sandbox` Docker 이미지를 사용합니다.

프로젝트별 샌드박싱이 필요한 경우 프로젝트 루트 디렉토리의 `.qwen/sandbox.Dockerfile`에 사용자 정의 Dockerfile을 생성할 수 있습니다. 이 Dockerfile은 기본 샌드박스 이미지를 기반으로 할 수 있습니다:

```
FROM qwen-code-sandbox
# 여기에 사용자 정의 종속성이나 구성을 추가하세요
# 예:
# RUN apt-get update && apt-get install -y some-package
# COPY ./my-config /app/my-config
```

`.qwen/sandbox.Dockerfile`이 존재하면 Qwen Code를 실행할 때 `BUILD_SANDBOX` 환경 변수를 사용하여 사용자 정의 샌드박스 이미지를 자동으로 빌드할 수 있습니다:

```
BUILD_SANDBOX=1 qwen -s
```

## 사용 통계

Qwen Code를 개선하기 위해 익명화된 사용 통계를 수집합니다. 이 데이터는 CLI가 어떻게 사용되는지 이해하고, 일반적인 문제를 식별하고, 새 기능의 우선순위를 정하는 데 도움이 됩니다.

**수집하는 항목:**

- **도구 호출:** 호출된 도구의 이름과 범주(네이티브 또는 MCP), 종료 상태(성공, 오류 또는 취소), 실행에 걸린 시간을 기록합니다. 도구에 전달된 인자나 반환된 데이터는 수집하지 않습니다.
- **API 요청:** 각 요청에 사용된 모델, 요청 지속 시간, 성공 여부를 기록합니다. 프롬프트나 응답의 내용은 수집하지 않습니다.
- **세션 정보:** 활성화된 도구 및 승인 모드와 같은 CLI 구성에 대한 정보를 수집합니다.

**수집하지 않는 항목:**

- **개인 식별 정보(PII):** 이름, 이메일 주소 또는 API 키와 같은 개인 정보를 수집하지 않습니다.
- **프롬프트 및 응답 내용:** 프롬프트 내용이나 모델의 응답을 기록하지 않습니다.
- **파일 내용:** CLI가 읽거나 쓴 파일의 내용을 기록하지 않습니다.

**옵트아웃 방법:**

`settings.json` 파일의 `privacy` 범주에서 `usageStatisticsEnabled` 속성을 `false`로 설정하여 언제든지 사용 통계 수집을 옵트아웃할 수 있습니다:

```
{
  "privacy": {
    "usageStatisticsEnabled": false
  }
}
```

또는 환경에서 `QWEN_USAGE_STATISTICS_ENABLED=false`(또는 `0`)를 설정하세요. 환경 변수가 설정보다 우선합니다. 두 값 중 하나를 변경한 후 Qwen Code를 재시작하세요.

> [!note]
>
> 사용 통계가 활성화되면 이벤트가 Alibaba Cloud RUM 수집 엔드포인트로 전송됩니다.
