# 터미널 이미지

Qwen Code는 어시스턴트 응답과 완료된 도구 결과의 이미지 파트를 인터랙티브 터미널 UI에 직접 표시할 수 있습니다. 이 표시 경로는 Markdown 렌더링과 분리되며 Markdown `render`와 `raw` 모드에서 동일하게 동작합니다.

## 이미지가 표시되는 위치

어시스턴트 응답에서 텍스트와 이미지는 원래 순서를 유지합니다. 도구 행은 성공, 실패 및 취소된 결과에 대해 결과 텍스트 뒤에 이미지를 표시합니다.

헤드리스, ACP, daemon/Web Shell 및 IDE 통합을 포함한 다른 출력 표면은 이미지 파트를 렌더링하지 않습니다. WeChat(weixin), WeCom 및 DingTalk 채널은 `[IMAGE: ...]` 마커 플로우를 통해 에이전트가 생성한 이미지 파일을 계속 전달할 수 있습니다. 다른 IM 채널은 현재 아웃바운드 이미지를 전달하지 않습니다.

## 터미널 지원

| 환경                                                                 | 이미지 표시                                                                               |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| tmux나 SSH 없는 직접 Kitty 또는 Ghostty TTY                          | 네이티브 터미널 이미지 배치                                                               |
| `chafa`가 설치된 다른 터미널                                         | iTerm2, Warp, tmux 및 SSH 세션을 포함한 256색 ANSI 미리보기                               |
| 호환 렌더러 없음, 또는 스크린 리더 모드(인라인 이미지 파트)           | 터미널 이미지 시퀀스 대신 `[image: 1024x768 png]`와 같은 결정적 텍스트                     |

## 제한 및 폴백

인라인 픽셀 미리보기는 현재 표시 제한 내의 유효한 PNG 데이터가 필요합니다: 총 64메가픽셀이고 각 변당 최대 1,000,000픽셀입니다. 다른 이미지 형식, 유효하지 않은 PNG 및 해당 제한을 초과하는 인라인 PNG는 텍스트 플레이스홀더로 표시됩니다.

8 MiB보다 큰 인라인 이미지 페이로드는 픽셀 렌더링되지 않습니다. 대부분의 초과 페이로드는 TUI 기록에 들어가기 전에 삭제되며, 제한을 약간 초과하는 페이로드는 인코딩 크기를 기반으로 허가가 결정되므로 텍스트 플레이스홀더로 남을 수 있습니다. 각 어시스턴트 응답 또는 도구 행은 최대 4개의 이미지를 표시하고 나머지는 `[+2 more images]`와 같은 마커로 보고합니다.

## 세션 기록 및 메모리

도구 이미지 파트는 결과와 함께 저장되며 세션 재개 후 재구성할 수 있습니다. 어시스턴트 이미지는 실시간으로 렌더링되지만 현재 영속화되지 않으므로 `--continue`와 `--resume`은 해당 이미지 없이 어시스턴트 텍스트를 복원합니다.

길거나 이미지가 많은 세션에서 메모리를 제한하기 위해 TUI는 오래된 표시 이미지를 `[Old assistant image content cleared]` 또는 `[Old tool result content cleared]`와 같은 마커로 대체할 수 있습니다. 이는 라이브 뷰에만 영향을 미칩니다. 도구 이미지 파트는 세션 기록에 남아 있으며 재개 후 다시 나타납니다.
