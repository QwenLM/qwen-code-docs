# 출력 스타일

출력 스타일은 Qwen Code가 응답을 작성하는 방식 — 톤, 서술의 정도, 설명의 양 — 을 바꾸지만, 할 수 있는 일은 바꾸지 않습니다. 스타일은 내장 시스템 프롬프트 위에 겹쳐지는 이름 붙은 명령어 블록이며, 모델은 매 턴마다 활성 스타일을 상기받으므로 긴 세션 동안에도 일관성을 유지합니다.

## 내장 스타일

| 스타일            | 설명                                                                                                                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **default**       | 추가 스타일 없음 — 표준 프롬프트.                                                                                                                                                           |
| **Concise**       | 서론, 서술, 마무리 요약 없이 답변부터 제시. 작업 자체는 여전히 철저하며, 오류 보고서와 안전 확인은 전체 내용을 유지.                                                                         |
| **Proactive**     | 즉시 작업을 시작하고, 낮은 위험의 결정에서는 질문보다 명시된 가정을 우선. 허용 범위는 바뀌지 않음: 승인 모드와 확인 규칙이 그대로 적용.                                                     |
| **Explanatory**   | 작업과 함께 코드베이스와 구현 선택에 대한 짧은 교육용 "Insight" 노트를 추가.                                                                                                                |
| **Learning**      | 함께 배우는 실습 방식: 작고 의미 있는 코드 조각을 `TODO(human)`으로 표시해 건네주고 기다림. 헤드리스 모드에서는 대기할 수 없으므로 건너뜀.                                                  |

## 스타일 선택

`/output-style`을 실행해 선택기를 열거나, 직접 설정:

```
/output-style Concise
/output-style default   # 스타일 없음으로 복귀
```

변경은 실행 중인 세션에 즉시 적용 — 시스템 프롬프트가 제자리에서 다시 빌드되므로 다음 턴부터 새 스타일로 응답 — 되고, 이후 세션에도 유지. 신뢰된 프로젝트 설정이 현재 `general.outputStyle`을 소유하고 있으면 해당 프로젝트 설정을 업데이트하고, 그렇지 않으면 사용자 설정을 업데이트. 스타일 이름은 대소문자를 구분하지 않음.

명령어 없이도 스타일을 설정 가능:

- **설정**: `settings.json`의 `"general": { "outputStyle": "Concise" }` (사용자 또는 프로젝트 범위). 값은 내장 또는 [사용자 정의](#custom-styles) 스타일 이름. 수동 편집은 다음 시작 시 적용.
- **단일 실행**: `qwen -p "..." --output-style Concise`는 해당 실행에 대해 설정을 재정의. [Headless Mode](./headless) 참조.

## 사용자 정의 스타일

사용자 정의 스타일은 본문이 스타일의 명령어인 Markdown 파일. 두 디렉토리 중 하나에 배치:

| 위치                                 | 범위                                                          |
| ------------------------------------ | ------------------------------------------------------------- |
| `~/.qwen/output-styles/<name>.md`    | 모든 프로젝트에서 사용 가능한 사용자 스타일                   |
| `<project>/.qwen/output-styles/*.md` | 프로젝트 스타일, 워크스페이스가 신뢰될 때만 읽힘              |

신뢰 확인은 파일을 읽을 때가 아니라 스타일이 사용될 때마다 이루어지므로, 세션 도중 신뢰를 취소하면 프로젝트 스타일이 대화에 영향을 미치는 것이 중단됨.

```markdown
---
name: Reviewer
description: Reviews code and reports findings without editing anything
keep-coding-instructions: false
---

You are reviewing, not implementing. Read the code the user points you at, list concrete findings ordered by severity, and never edit files unless the user asks for a fix.
```

프론트매터는 선택 사항. 각 필드에는 기본값이 있음:

- `name` — 스타일의 이름, `/output-style <name>` 및 `general.outputStyle`에서 사용. 기본값은 `.md`를 제외한 파일 이름. `default`는 예약됨.
- `description` — 선택기에 표시되는 한 줄 요약. 기본값은 본문의 첫 줄.
- `keep-coding-instructions` — `true`는 내장 소프트웨어 엔지니어링 워크플로우 안내를 스타일과 함께 프롬프트에 유지; `false`는 해당 섹션을 제거하여 코딩이 아닌 작업용 스타일로 만듦. 아무것도 명시하지 않으면 재정의하는 내장 스타일의 값을 상속하므로 `concise.md`를 다시 써도 안내가 유지됨; 내장 대응 항목이 없는 파일은 기본값 `false`. 내장 프롬프트의 나머지 부분 — 정체성, 안전 규칙, 도구 안내 — 은 모든 스타일에서 그대로 유지.

사용자 정의 스타일은 선택기에서 내장 스타일 뒤에 표시되며 출처가 레이블로 붙고, 선택기가 열리거나 이름이 지정될 때마다 다시 읽히므로 새 파일도 재시작이 필요 없음. 이름은 대소문자를 구분하지 않으며 고유해야 함: 프로젝트 스타일이 같은 이름의 사용자 스타일을 재정의하고, 둘 다 해당 이름의 내장 스타일을 재정의. 로드할 수 없는 파일은 건너뛰어져 디버그 로그에 보고되며 다른 파일은 계속 로드 — 빈 본문, 유효하지 않은 이름, 25kB 초과 파일(스타일은 문서가 아닌 프롬프트), UTF-8 텍스트가 아닌 파일, 또는 전체 본문이 HTML 주석인 파일. HTML 주석은 본문에서 제거되므로 동료를 위한 메모는 모델에 전송되지 않음.

스타일 파일은 자기 자신만 읽을 수 있음: 심볼릭 링크인 프로젝트 파일은 건너뛰어지고, 사용자 파일은 자신의 홈으로의 심볼릭 링크(dotfiles 설정)일 수 있지만 그 바깥으로는 불가, 하드 링크는 어느 쪽에서도 거부됨.

사용자 정의 스타일은 `--bare` 및 `--safe-mode`에서 무시되며, 내장 스타일만 유지됨.

## 범위 및 상호작용

- 스타일은 내장 프롬프트 위에 겹쳐짐. `--system-prompt` 또는 `QWEN_SYSTEM_MD`가 프롬프트 전체를 대체하면 스타일(및 턴별 알림)은 적용되지 않음.
- 스타일은 메인 대화에만 적용. 서브에이전트는 자체 시스템 프롬프트를 실행하며, 아레나 피어는 해당 스타일이 코딩 안내를 유지하는 경우에만 세션의 스타일을 상속 — 피어는 생성하는 diff로 평가되므로 소프트웨어 엔지니어링 안내가 제거된 상태로 실행되지 않음.
- `--bare` 및 `--safe-mode`는 설정을 무시하고 `/output-style` 변경을 허용하지 않음.
- 세션 도중 스타일을 변경하면 캐시된 프롬프트 접두사가 한 번 무효화; 그 후에는 캐싱이 평소대로 동작.

스타일은 톤과 워크플로우를 조정하며, 지식이나 권한을 조정하지 않음. 모델이 항상 알아야 할 프로젝트 컨벤션은 컨텍스트 파일(`QWEN.md`)을 사용하고, 프롬프트에 일회성 추가를 원하면 `--append-system-prompt`를 사용.
