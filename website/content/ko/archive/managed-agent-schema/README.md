# 보관된 Managed Agent 데이터베이스 마이그레이션


이 파일들은 소스 커밋 `18f80f56666a347a2b67b2ef98099cc58356b253`에서 사용 중단된 63개 테이블 데이터베이스를 설명합니다. 이는 역사적 참고 자료이며 런타임 및 테스트 클래스패스 외부에 있습니다. 보관된 Java 마이그레이션과 업그레이드 증인은 새 환경에서 실행되지 않습니다.

유일한 활성 베이스라인은 [`V1__managed_schema.sql`](../../../packages/managed-agent-server/src/main/resources/db/managed-schema/V1__managed_schema.sql)입니다. Managed Server와 Runtime Broker는 동일한 버전 관리 리소스를 사용하며 빈 데이터베이스 또는 구조적으로 검증된 완전한 32개 테이블 베이스라인이 필요합니다. 레거시, 부분적, 외부 또는 기록 전용 카탈로그는 초기화 쓰기 전에 거부됩니다. 재초기화는 카탈로그를 검증하며 백필이나 복구를 수행하지 않습니다.

이전 데이터 마이그레이션이나 제자리 업그레이드는 없습니다. 역사적 읽기를 위해 이전 환경과 데이터베이스를 유지하고, 전환 전에 새 승인을 중지하고 진행 중인 작업을 완료한 후 새 환경에서만 새 세션을 생성하십시오. 새 데이터가 존재하는 상태에서 롤백은 새 데이터베이스에서 해당 레코드를 보존하고 제공해야 합니다.

보관된 테스트는 사용 중단된 마이그레이션 알고리즘의 증거를 보존합니다. 활성 대체물은 새 초기화, 변경 불가능한 기존 행, 타입화된 변형 열, Hook 고유성 및 인덱싱된 승인, 그리고 오래된 카탈로그 거부를 검증합니다. 중복된 Broker `schema.sql`은 또 다른 스키마 권한으로 유지되는 대신 제거되었습니다.

PR #13642 보존 V69 SQL과 `RuntimeBrokerRetentionLegacyUpgradeTest.java`는 헤드 `db4c37064b9f34d2aa879b23b0e894fbed0281e1`의 이전 보존 인덱스/영수증 업그레이드 증거를 보존합니다. 이들은 보관된 것일 뿐입니다. 활성 32개 테이블 V1 베이스라인은 보존 인덱스를 제공하며 대체 테스트는 새 카탈로그 동등성과 반복 초기화 시 변경 불가능한 영수증을 검증합니다. V69는 활성 마이그레이션이나 버전 예약이 아닙니다.
