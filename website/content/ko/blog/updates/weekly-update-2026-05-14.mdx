Claude Code가 `/goal`을 내놨습니다 — 목표를 정해 주고 Agent가 끝까지 달리게 하는 기능이죠. [Cursor는 완전히 새 Agent 경험을 발표](https://www.cursor.com/blog/agents)했고, [Karpathy는](https://x.com/berryxia/status/2054339265103065156) 대부분 사람이 불필요한 컨텍스트를 보내 Token을 낭비하고 있다고 말했습니다. 코딩 Agent 경쟁이 유난히 뜨거웠던 한 주였습니다.

Qwen Code는 이번 주에 4개 버전(v0.15.8 ~ v0.15.11)을 냈습니다. 두 갈래입니다. **상호작용 제어** — 서브 Agent 실행 과정을 전부 투명하게 드러내고, `/branch`로 여러 갈래를 동시에 탐색. **Token 관리** — ToolSearch로 필요할 때만 로드하고, 넘치는 상황은 반응형 압축으로 대비.

## ✨ 새로운 기능

### 서브 Agent 시각화: LiveAgentPanel + 상태 Pill

Agent가 서브 Agent를 부릴 때, 이전에는 커서 깜빡임만 바라보고 있었습니다. 뭘 하고 있지? 얼마나 돌았지? Token은 얼마를 썼지? 전부 블랙박스였습니다.

이제 하단에 상태 패널이 상주하면서 서브 Agent의 실행 상태, 소요 시간, Token 소모를 실시간으로 보여 줍니다. 포그라운드 서브 Agent는 pill 형태로 뜨고, 펼치면 사고 과정과 도구 호출 내역이 전부 보입니다.

**이렇게 쓸 수 있습니다:**
- 서브 Agent가 얼마나 돌고 Token을 얼마 썼는지 한눈에
- pill을 펼쳐 추론 과정을 확인하고, 새는 걸 바로 잡아 중단
- 서브 Agent 여러 개가 병렬로 돌아도 각자 상태를 따로 표시

관련 PR [#3909](https://github.com/QwenLM/qwen-code/pull/3909), [#3768](https://github.com/QwenLM/qwen-code/pull/3768)

### ToolSearch: 도구 필요할 때만 로드해 Token 절약

[Karpathy가 지적했듯](https://x.com/berryxia/status/2054339265103065156), AI 프로그래밍 비용의 상당 부분은 불필요한 컨텍스트를 보내는 데 새 나갑니다 — 파일을 과도하게 로드하고, 모든 도구 정의를 기본으로 붙이는 식이죠.

ToolSearch는 저빈도 도구(ApplyDiff, NotebookEdit, CreateDirectory 등)를 초기 prompt에서 빼고, Agent가 필요할 때 검색해 로드합니다. prompt가 가벼워니 prefix caching 적중률이 오르고 첫 응답도 빨라집니다.

**이렇게 쓸 수 있습니다:**
- 기본 활성화, 설정 필요 없음. Agent가 도구를 필요로 하면 스스로 찾아 로드합니다
- prefix caching을 지원하는 Claude 같은 모델에서는 대화마다 수십 K Token을 덜 씁니다
- `tools.toolSearch.enabled`로 끌 수 있습니다

관련 PR [#3589](https://github.com/QwenLM/qwen-code/pull/3589), [#4022](https://github.com/QwenLM/qwen-code/pull/4022), [#4069](https://github.com/QwenLM/qwen-code/pull/4069)

### /export HTML 라이트 테마

대화를 동료가 보라고 내보냈는데, 상대는 밝은 시스템 테마를 쓴다면 — 어두운 HTML은 밝은 환경에서 눈이 아픕니다.

`/export html`에 이제 테마 전환이 내장됩니다. 우측 상단 토글 하나면 밝고 어둡게 마음대로 전환되고, 선택은 localStorage에 저장됩니다.

**이렇게 쓸 수 있습니다:**
- 밝은 테마를 쓰는 동료에게 공유해도 읽는 경험이 정상
- 테마 선호가 저장돼 매번 전환할 필요 없음
- `/export`가 HTML 형식 기본값 — 명령 한 번이면 끝

관련 PR [#3908](https://github.com/QwenLM/qwen-code/pull/3908)

### /branch: 세션 갈라치기

대화가 중간쯤 갔을 때 다른 방안을 시험해 보고 싶어 집니다. 이전에는 새 세션을 열어 처음부터 하는 수밖에 없었습니다.

`/branch`는 현재 대화에서 새 세션을 갈라 내되, 컨텍스트는 그대로 유지합니다. 두 경로를 병렬로 탐색하면서 서로 간섭하지 않습니다. 원래 경로로 돌아가고 싶으면 `/resume`에서 원본 세션을 찾아 이어가면 됩니다.

**이렇게 쓸 수 있습니다:**

- 리팩터링 중간에 방안을 바꾸고 싶을 때 → `/branch`로 갈라 양쪽 모두 시도
- 갈라낸 세션은 독립 저장 — 각자 별도의 기록을 가짐
- `/resume`과 함께 쓰면 여러 갈래를 빠르게 오감

관련 PR [#3539](https://github.com/QwenLM/qwen-code/pull/3539)

### /diff: 세션 변경 통계

긴 대화 하나를 끝내면 Agent가 파일을 잔뜩 고칩니다. 뭘 바꿨는지 빨리 알고 싶은데, 빠져나와 `git diff --stat`을 돌리기는 귀찮습니다.

`/diff`를 입력하면 현재 세션의 모든 파일 변경 통계가 터미널에 바로 표시됩니다. 어느 파일이 새로 생기고 어느 파일이 수정됐으며 몇 줄이 늘고 줄었는지, 한눈에 보입니다.

**이렇게 쓸 수 있습니다:**

- 대규모 리팩터링 후 영향 범위를 빠르게 확인
- Agent가 건드리면 안 될 파일을 고쳤을 때 즉시 포착
- 각 갈래에서 `/diff`를 돌려 두 방안의 변경량 비교

관련 PR [#3491](https://github.com/QwenLM/qwen-code/pull/3491)

### 검색되는 /resume

세션이 쌓이면 `/resume` 목록이 벽이 됩니다. 특히 `/branch`를 함께 쓰면 갈래가 늘수록 목록도 길어지죠.

이제 `/resume`에 실시간 검색 필터가 지원됩니다. 키워드를 입력하면 목록에 일치하는 세션만 남습니다. 검색과 브랜치 필터는 겹쳐 쓸 수 있습니다.

**이렇게 쓸 수 있습니다:**

- 수십 개 과거 세션에서 키워드를 치면 금방 찾아냄
- `/branch`와 조합 — 여러 갈래를 이름으로 빠르게 전환
- 검색 + 브랜치 필터를 겹쳐 되살릴 컨텍스트를 정확하게 지정

관련 PR [#3880](https://github.com/QwenLM/qwen-code/pull/3880)

![](https://gw.alicdn.com/imgextra/i3/O1CN01R7xO7b1jJsWgE6fyQ_!!6000000004528-1-tps-1280-720.gif)

<Callout type="tips">

    `/branch`, `/diff`, `/resume`은 각각 써도 쓸모가 있지만, 진짜 힘은 조합에 있습니다:

    Agent와 큰 리팩터링을 하다가, 다른 방안이 더 나을 것 같은 지점에 이르렀다고 해 봅시다.

    1.`/branch`로 새 갈래를 나눠 양쪽을 각자 진행시킵니다. 각 갈래가 끝나면

    2.`/diff`로 변경 통계를 봅니다 — 어느 방안이 덜 고치고 영향 범위가 작은지 한눈에 보입니다. 갈래가 많아 어느 것이 무엇인지 모를 때

    3.`/resume`에서 키워드를 쳐 검색해 곧바로 찾습니다. 검색과 브랜치 필터를 겹칠 수도 있고요.

    전체 과정에서 터미널을 새로 열 필요도, 손으로 `git stash`할 필요도 없습니다. 대화 컨텍스트는 처음부터 끝까지 유지됩니다. AI 프로그래밍 세션에 Git 브랜치 능력을 붙여 준 셈입니다.
</Callout>

### 반응형 컨텍스트 압축

대화가 context window를 넘으면 이전에는 그대로 에러가 나고 멈췄습니다. 이제는 자동으로 압축합니다 — 최근 작업과 핵심 컨텍스트는 남기고 초기 중복을 정리해 대화가 계속됩니다. 서브 Agent도 같은 혜택을 받아, 긴 대화에서 넘쳐서 크래시하지 않습니다.

**이렇게 쓸 수 있습니다:**
- 긴 대화가 token 초과로 끊기지 않으니 `/compact`를 손으로 돌릴 필요 없음
- 압축 과정을 느끼지 못한 채 대화가 자연히 이어짐
- 복잡한 다단계 작업 (대규모 리팩터링) 완료율이 올라감

관련 PR [#3879](https://github.com/QwenLM/qwen-code/pull/3879), [#3985](https://github.com/QwenLM/qwen-code/pull/3985)
