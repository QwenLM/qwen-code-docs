코딩 Agent 분야는 이번 주 큰일이 두 개 있었습니다. Anthropic이 [Claude Opus 4.8](https://www.anthropic.com/news/claude-opus-4-8)을 발표해 Computer Use 능력을 계속 강화하고 fast mode 비용을 이전의 3분의 1로 낮췄지만, Opus급 가격 문턱은 그대로입니다. 한편 Google은 [Gemini CLI 무료판을 6월 18일에 종료](https://news.ycombinator.com/item?id=48196867)한다고 발표했고 Antigravity CLI가 대체합니다 — 작년 오픈소스로 Star 5만 개와 커뮤니티 기여 6,000건 이상을 받아 놓고 지금은 기업 사용자 쪽으로 회수하니 커뮤니티 반응이 꽤 큽니다.

Qwen Code는 이번 주 **v0.17.0**과 **v0.17.1**을 내놓고 PR 60개 이상을 병합했습니다. 네 방향을 다뤘습니다:

**Computer Use가 내장 기능이 됐습니다.** 이전에는 extension을 설치하고, MCP를 설정하고, 권한을 부여하고, 재시작해야 했습니다. 대부분 이 절차를 끝까지 가지 못합니다. 이제는 데스크톱 자동화 도구 9개가 deferred 내장으로 등록되고, 모델이 처음 호출할 때 확인 창 한 번만 뜨면 나머지는 전부 자동입니다 (binary 다운로드, macOS 권한 안내, server 생명주기). Anthropic은 Opus 4.8에서 Computer Use를 더 강화했지만 자사 모델에 묶었습니다. Qwen Code는 당신이 고른 모델로 돌리고, 비용도 당신이 정합니다.

**Feishu도 쓸 수 있습니다.** Qwen Code는 이미 WeChat 연동을 지원했고, 이번 주 Feishu(Lark)를 붙였습니다. WebSocket과 Webhook 두 가지 연결 방식이고, Agent 응답은 Feishu 인터랙티브 카드로 스트리밍 출력돼 실시간 갱신되고 중지 버튼까지 달려 있습니다. Feishu 채팅방에서 @만 붙이면 Agent를 부를 수 있고, 도구를 옮겨 다닐 필요가 없습니다.

**긴 작업의 압축이 더 이상 컨텍스트를 잃지 않습니다.** 기존 압축은 문자 수로 70/30을 잘랐습니다. 한 turn짜리 긴 작업 (대표적으로 computer-use 워크플로)은 사용자 메시지가 한 개뿐이라, 분할 로직이 split point를 못 찾으면 스크린샷과 사용자의 원본 prompt를 통째로 버렸습니다. 새 엔진은 전체 이력 summary + 선택적 복원 방식입니다. 9개 섹션의 구조화된 요약이 서사의 연속성을 지키고, 최근 파일 5개와 이미지 3장이 상태의 연속성을 되살립니다. Computer Use를 돌리다가 압축이 걸려도 Agent가 더 이상 '장님'이 되지 않습니다.

**CJK 사용자, 드디어 참지 않아도 됩니다.** 중일한 입력법의 후보 창이 늘 터미널 왼쪽 아래 구석으로 날아가, 실제로 글자를 치는 자리와는 화면 전체만큼 떨어져 있었습니다. 이번 주 yoga 트리 순회로 물리 커서를 시각 커서 자리로 옮겨 후보 창이 드디어 커서를 따라옵니다.

## ✨ 새로운 기능

### Computer Use 제로 설정 내장: 데스크톱 자동화, 확인 한 번이면 됩니다

Qwen Code는 Computer Use를 설정 없는 내장 기능으로 만들었습니다. `computer_use__list_apps`, `computer_use__get_app_state`, `computer_use__click` 등 도구 9개가 deferred 내장 도구로 등록됩니다. 모델이 그중 하나를 처음 호출할 때 표준 tool-permission 대화상자가 뜨고, 한 번 Approve하면 이후는 전부 자동입니다 — `npx -y open-computer-use mcp`로 upstream binary를 가져오고(약 50MB), macOS에서는 Accessibility와 Screen Recording 권한을 자동으로 안내하며, MCP server 생명주기도 자동으로 관리됩니다.

기본으로 켜져 있고(`tools.computerUse.enabled: true`), 원치 않으면 설정 하나로 끕니다. 직접 고른 모델로 돌리며, 특정 provider에 묶이지 않습니다.

**이걸로 할 수 있는 일:**

- Agent에게 "Stocks 앱 열고 첫 번째 종목 눌러"라고 시키세요 — Agent가 스크린샷을 보고 UI 요소를 인식하고 직접 클릭합니다
- 처음 쓸 때 확인 한 번만 하면 이후 호출은 바로 통과합니다
- 모델이 `select:computer_use__list_apps,computer_use__get_app_state,computer_use__click`처럼 보내면 schema를 한 번에 여러 개 불러옵니다
- macOS 권한 안내가 전부 자동입니다: Accessibility → Screen Recording → 재시작 후 자동 재연결
- `tools.computerUse.enabled: false`로 끄거나, `QWEN_COMPUTER_USE_PACKAGE`로 upstream binary 버전을 덮어쓸 수 있습니다

### Feishu Channel: Feishu 안에서 바로 Qwen Code

Qwen Code는 이미 WeChat 연동을 지원했고 이번 주 Feishu(Lark)를 붙였습니다. Feishu(Lark) channel adapter가 새로 생겼고 WebSocket과 Webhook 두 연결 방식을 지원합니다. Agent 응답은 Feishu의 인터랙티브 카드로 스트리밍 출력돼 실시간으로 갱신되고 중지 버튼도 있습니다. 인용/답장 컨텍스트도 올바르게 가져옵니다 — 텍스트 메시지와 카드 메시지 모두 됩니다.

메시지마다 상태가 따로 격리돼 여러 사람이 동시에 써도 뒤섞이지 않습니다.

**이걸로 할 수 있는 일:**

- Feishu 개인 채팅이나 단체 채팅방에서 Qwen Code를 @로 불러 바로 질문하거나 작업을 시키세요
- 스트리밍 카드로 Agent의 사고와 출력 과정을 실시간으로 보고, 중지 버튼을 눌러 언제든 끊을 수 있습니다
- 특정 메시지를 인용해 질문하면 Agent가 인용된 원문을 봅니다
- 이미지와 파일 첨부도 지원합니다

### 압축 재작성: 긴 작업이 더 이상 컨텍스트를 잃지 않습니다

지난주 자동 압축을 3단 계단으로 설계했습니다. 이번 주 한 층 더 들어갑니다. 압축 엔진 자체를 다시 만들었습니다.

기존 방식은 문자 수대로 이력을 앞 70%(summary로 압축)와 뒤 30%(원문 그대로 보존)으로 갈랐습니다. 문제는 computer-use 같은 한 turn짜리 긴 작업에서 터집니다. 사용자는 "Safari 열고 검색 결과 누르고 스크린샷 찍어"라고 한 마디만 했고, 그 뒤 Agent가 도구 호출을 수십 라운드 돌렸습니다. 분할 로직은 split point를 잡으려면 사용자 메시지가 최소 두 개는 있어야 하는데, 한 turn은 영원히 못 찾습니다. 그래서 fallback이 **스크린샷 전부와 사용자 원본 prompt를 텍스트 요약 한 덩어리로 바꿔 버렸습니다.** Agent는 '장님'이 됩니다 — 시각 컨텍스트도, 원문 그대로의 사용자 의도도 사라집니다.

새 엔진은 summary + selective restoration입니다:

- **9개 섹션 구조화 summary**: 그중 6번째 섹션은 사용자 메시지를 하나하나 원문 그대로 인용하도록 강제합니다. 압축 뒤에도 사용자 의도가 살아남습니다
- **최근 파일 5개 복원**: 크기에 맞게 조절됩니다 — 작은 파일은 디스크에서 새로 읽은 전체 내용을 넣고, 큰 파일은 경로 참조만 남깁니다
- **최근 이미지 3장 복원**: 각 이미지에 metadata header(turn index + origem 도구명 + args)를 붙여 보냅니다. 모델이 시각 상태와 그것을 만든 작업을 대응시킬 수 있습니다

**이걸로 할 수 있는 일:**

- Computer Use 긴 작업을 압축해도 Agent는 최근 스크린샷과 당신의 원본 지시를 계속 봅니다
- `/compress`에 focus 지시가 새로 생겼습니다: `/compress focus on the auth bug` — 요약이 당신이 신경 쓰는 지점에 집중하도록 이끕니다 (최대 2,000자)
- Plan mode와 백그라운드 subagent 상태가 압축 뒤에 자동 복원돼 소리 소문 없이 사라지지 않습니다

### 승인 모드 이름 변경: Default → Ask Permissions

이전까지 승인 모드의 기본 단계 이름은 'Default'였습니다. 이 이름은 '이게 기본값이다'만 알려주고, 그 모드가 실제로 어떤 권한을 주는지는 말해주지 않습니다. 다른 모드(Plan, Auto-Edit, Auto, YOLO)는 전부 동작을 그대로 서술하는데 Default만 예외였습니다.

**Ask Permissions**로 바꾸면 "이 모드에서 Agent가 나한테 물어보나?"에 바로 답이 됩니다. Claude Code의 같은 역할 모드 이름과도 맞춰, 도구를 옮겨 다니는 인지 비용을 낮췄습니다.

내부 열거값 `ApprovalMode.DEFAULT`, settings.json의 `"default"`, CLI 명령 `/approval-mode default`는 전부 그대로입니다. 기존 설정은 마이그레이션이 0입니다. 9개 locale 번역도 함께 갱신했습니다.

**이걸로 할 수 있는 일:**

- Settings 대화상자의 `Tool Approval Mode` 줄에 `Ask permissions`로 표시됩니다 — 이 모드가 동의를 구한다는 사실을 한눈에 압니다
- `/approval-mode` 선택지에서 의미 없는 'Default'가 아니라 동작 설명을 보게 됩니다
- 이미 쓰고 있던 settings.json과 CLI 명령이 완전히 호환되니 아무것도 바꿀 필요가 없습니다

### IME 후보 창 위치: CJK 입력법이 드디어 쓸 만해집니다

Qwen Code는 시각 커서를 반전 색상 문자로 렌더링하고, 물리 커서는 숨긴 채 터미널 왼쪽 아래 구석에 둡니다. 중일한 입력법 사용자의 후보 창은 물리 커서를 따라갑니다 — 실제로 글자를 치는 자리와 화면 하나만큼 떨어져 있죠. Hermes와 OpenClaude도 같은 문제고, 양쪽 답은 Ink 소스를 fork하는 것이었습니다.

Qwen Code는 접근을 바꿨습니다. `addLayoutListener`(yoga `calculateLayout()` 뒤에 발동해 흔들림이 0)로 yoga 트리를 순회해 입력 컴포넌트의 절대 위치를 구하고, 물리 커서를 시각 커서 자리로 옮깁니다. `patch-package`로 `ink/dom`과 `ink/components/CursorContext` 두 내부 모듈만 노출하니 Ink 전체를 fork하지 않아도 됩니다.

**이걸로 할 수 있는 일:**

- Sogou, Apple Pinyin 같은 CJK 입력법으로 바꿔도 후보 창이 커서 옆에 뜹니다. 왼쪽 아래 구석으로 날아가지 않습니다
- 방향키로 커서를 움직이면 후보 창이 따라옵니다
- 일반 대화, 여러 줄 입력, 이력 스크롤은 영향 없습니다

관련 PR: [#4652](https://github.com/QwenLM/qwen-code/pull/4652)
