Qwen Code는 이번 주에 v0.23.1, v0.23.2 두 개의 정식 버전을 출시하고 PR 210개 이상을 병합했습니다.

**워크플로 전용 관리 페이지가 생겼습니다.** Web Shell에서 실행마다 어디까지 진행됐고, Agent를 몇 개 파견했으며, token을 얼마나 소비했는지 볼 수 있습니다.

**Web Shell이 세 군데 편해졌습니다.** 컨텍스트가 무엇에 가득 찼는지 클릭 한 번으로 확인하고, 이전 대화를 넘길 때 내비게이션 바가 생겼으며, Plan과 YOLO를 동시에 켤 수 있습니다.

**Channel 작업에 이름을 붙일 수 있습니다.** DingTalk에서 여러 일을 동시에 진행하면서 작업마다 이름을 붙이고 언제든 전환할 수 있고, 각자 독립된 워크스페이스로 파일을 수정합니다.

## ✨ 새로운 기능

### 워크플로 전용 관리 페이지가 생겼습니다

지난주에 워크플로는 일시 중지, 재개, 취소를 지원했지만 터미널에서 명령을 입력해야 했습니다. 이번 주에는 Web Shell에 전용 페이지가 생겼습니다.

사이드바에서 Workflows를 클릭하거나 대화에 `/workflows`를 입력하면 됩니다. 페이지는 저장됨, 실행 중, 기록 세 개의 탭으로 나뉘고, 실행마다 단계 진행 상황, 파견한 Agent, 대기 중인 승인, 소비한 token이 모두 표시됩니다. 저장된 워크플로를 열면 설명, 적용 시나리오, 스크립트 경로와 소스 코드를 바로 볼 수 있습니다.

이렇게 활용할 수 있습니다:

- 페이지에서 워크플로가 어디까지 진행됐고 Agent를 몇 개 파견했는지 확인
- 중간에 멈추고 싶으면 멈추고, 다시 하고 싶으면 재실행
- 저장된 워크플로를 열어 스크립트와 설명 확인

관련 PR: [#10594](https://github.com/QwenLM/qwen-code/pull/10594)

### Web Shell: 컨텍스트 사용량 확인, Plan과 YOLO도 함께 켜기

**컨텍스트가 무엇에 가득 찼는지 클릭 한 번으로 봅니다.** 대화 헤더에 아이콘이 하나 추가됐고, 누르면 컨텍스트 사용량 탭이 열립니다. 창을 얼마나 사용했고 얼마가 남았는지, 여기에 시스템 프롬프트, 내장 도구, MCP 도구, 메모리 파일, 스킬, 메시지가 각각 얼마나 차지하는지 알 수 있고, 각 항목을 펼쳐 구체적 내용까지 볼 수 있습니다.

**이전 대화를 넘길 내비게이션 바가 생겼습니다.** 대화 영역 왼쪽에 눈금 내비게이션이 추가됐습니다. 눈금에 마우스를 올리면 해당 라운드의 질문이 표시되고, 클릭하면 바로 이동합니다.

**Plan과 실행 권한이 분리됐습니다.** Plan을 권한 메뉴에서 꺼내 독립된 토글로 만들었습니다. Default, Auto Edit, Auto, YOLO와 자유롭게 조합할 수 있고, 이전에는 Plan을 고르면 YOLO를 함께 쓸 수 없었습니다. 계획 승인이 끝나면 자동으로 꺼집니다. `/plan` 계열 명령을 모두 지원합니다.

**작업이 끝나면 브라우저로 알림을 받을 수 있습니다.** 설정의 UI 항목에 '브라우저 작업 알림' 토글이 추가됐습니다. 켜고 권한을 허용하면, 페이지가 백그라운드에 있거나 포커스가 벗어난 상태에서 지켜보던 대화가 끝나거나 실패할 때 브라우저 알림이 뜹니다. 기본은 꺼져 있고, 알림에는 대화 내용과 디렉터리 경로가 포함되지 않습니다.

**백그라운드 Agent가 아직 도는지 알 수 있습니다.** 백그라운드 Agent 카드의 아이콘에 은은한 맥동 표시가 붙고, 포그라운드 Agent의 접힌 행에는 얼마나 실행 중인지와 지금 어떤 하위 도구를 돌리는지 표시됩니다.

이렇게 활용할 수 있습니다:

- 대화 헤더의 아이콘을 클릭해 컨텍스트가 무엇에 가득 찼는지 확인
- 왼쪽 눈금 바를 클릭해 이전 대화의 아무 라운드로든 이동
- Plan과 YOLO를 동시에 켤 수 있음

### Channel: 한 그룹에서 여러 작업 병행, 워크스페이스도 각자 사용

Channel 봇은 QR 코드를 스캔해 DingTalk, Feishu 등 채팅 도구에 붙여 쓰는 Qwen Code 봇입니다. 이전에는 한 그룹의 봇이 동시에 한 가지만 할 수 있었습니다. PR을 보게 하면서 김에 새 기능도 만들라고 하고 싶은데, 두 일은 같은 대화에 몰려 서로 방해만 했습니다. 이제 Channel에 이름 지정 작업이 생겨 여러 일을 동시에 진행할 수 있습니다.

**한 그룹 채팅에서 여러 작업을 엽니다.** `/session new <이름>`으로 작업을 만들고, 한 사람이 한 그룹에서 최대 8개까지 만들 수 있으며, 각자 세션과 기록을 따로 가집니다. `/session use <이름>`으로 언제든 전환하고, 작업이 도는 중에도 다른 작업을 만들거나 전환할 수 있습니다. `/session cancel <이름>`으로 지정한 작업만 멈춥니다. 모든 응답에 출처 표시가 붙고, 개별 채팅에서는 작업 이름, 그룹 채팅에서는 '누구 · 어느 작업'으로 표시됩니다. 중간에 무관한 질문을 하고 싶으면 `/btw <질문>`을 보내면 되고, 주 작업은 그대로 진행됩니다.

**작업마다 구획을 나눠 일합니다.** 작업을 만들 때 `--worktree`를 붙이면 그 작업은 자기 디렉터리와 브랜치에서 일하므로, 여러 일이 동시에 파일을 수정해도 각자 따로 됩니다. `/clear`, `/new`, `/reset`은 새로운 대화로 갈아탈 뿐이고, 만들어 놓은 파일과 브랜치는 그대로 남으며, 봇을 재시작해도 작업은 유지됩니다. 세션 전체를 삭제하면 그 작업이 만든 워크스페이스와 브랜치까지 함께 정리되고, 커밋되지 않은 변경 사항이 남아 있으면 그대로 보존됩니다.

쓰기 전에 설정에서 해당 Channel의 `sessionScope: "user"`와 `multiSession: true` 두 항목을 켜 주세요.

이렇게 활용할 수 있습니다:

- PR 검토와 새 기능 작성을 동시에 돌리고, 기록은 각자 따로
- `--worktree`를 붙여 파일 수정을 각자 따로 진행
- 작업이 도는 중에 다른 질문을 끼워도 주 작업은 그대로 진행

### DingTalk: 권한 확인은 카드로, 작업 진행 상황은 상태 이모지로

**도구 권한 확인이 카드가 됐습니다.** AI가 승인이 필요한 작업을 실행하려 하면 DingTalk에 네이티브 인터랙션 카드가 오고, 버튼만 누르면 됩니다: 한 번 허용, 거부, 항상 허용.

**작업 진행 상황에 상태 이모지가 붙습니다.** AI가 일하는 동안, 보낸 메시지에 👀 외에도 현재 단계에 따라 상태 태그가 바뀝니다: 🤔 생각 중, 📖 읽는 중, 🔎 검색 중, 🖥️ 실행 중, 🛠️ 편집 중, 🗑️ 삭제 중, 🌐 가져오는 중 등이며, 끝나면 최종 상태 이모지 하나만 남습니다.

**백그라운드 Agent의 말에 이름이 붙습니다.** 여러 백그라운드 Agent가 병렬로 돌면 각 응답 앞에 `Agent · 이름`이 표시되어 누가 말하고 있는지 구분됩니다. 메시지가 많다면 `aggregateBackgroundAgentResponses`를 켜서 라운드마다 한 건으로 합칠 수 있습니다.

이렇게 활용할 수 있습니다:

- AI가 권한을 요구하면 카드를 클릭
- 메시지를 보낸 뒤 이모지만으로 AI가 어디까지 왔는지 확인
- 여러 Agent가 동시에 말해도 각각 누가 말하는지 표시

### 클라우드에 돌린 Qwen Code가 내 컴퓨터의 프로젝트를 수정합니다

Qwen Code를 클라우드 서버에 설치해 돌리고, 사람은 자기 컴퓨터 앞에서 브라우저로 지시하는 사용 방식이 이제 꽤 흔합니다. 문제는 AI가 클라우드 서버의 파일만 본다는 점입니다. 노트북 안의 프로젝트는 손이 닿지 않아서, 예전에는 파일을 올려 놓고 고친 뒤 다시 내려받아야 했습니다.

이제 브라우저에서 자기 컴퓨터의 폴더 하나를 골라 현재 세션에 맡길 수 있습니다. 고르고 나면 그 세션이 폴더 안의 파일을 나열, 읽기, 검색, 쓰기 하고, 모든 경로는 고른 폴더를 기준으로 계산됩니다. 사이드바 하단에는 현재 어떤 폴더가 연결됐고 도구를 몇 개 제공하는지 표시됩니다.

이 폴더는 연결한 바로 그 세션에만 열립니다. 탭을 닫거나 연결이 끊기거나 세션이 끝나면 바로 회수됩니다.

이렇게 활용할 수 있습니다:

- 서버는 클라우드에 둔 채로 내 컴퓨터의 프로젝트를 직접 수정하게 함
- 폴더 하나를 맡기고 파일 업로드와 결과 다운로드 없이 진행
- 이번엔 A 프로젝트, 다음엔 B 프로젝트로 넘겨도 AI는 지금 맡긴 것만 봅니다

## 📊 그 외 새로운 기능

**출력 스타일을 직접 만들 수 있습니다.** 지난주에는 내장 출력 스타일 네 가지를 고를 수 있었다면, 이번 주에는 직접 정의합니다. `~/.qwen/output-styles/`에 Markdown 파일을 두면 전역 스타일, 프로젝트의 `.qwen/output-styles/`에 두면 프로젝트 스타일이고, 파일 본문이 그 스타일의 프롬프트입니다. 관련 PR: [#10761](https://github.com/QwenLM/qwen-code/pull/10761)

**내장 웹 검색이 자동으로 켜집니다.** Bailian의 Standard API Key나 Token Plan을 쓰면 `web_search`가 자동으로 사용 가능해지고, 비용은 현재 사용 중인 계정에 청구됩니다. Coding Plan은 Bailian 서비스 제공자 설정을 직접 지정해야 합니다. 관련 PR: [#11348](https://github.com/QwenLM/qwen-code/pull/11348), [#11450](https://github.com/QwenLM/qwen-code/pull/11450)

**대화를 HTML로 내보냅니다.** CLI, Web, VS Code의 `/export html`이 같은 파이프라인을 사용하며, 내보낸 파일에서 전문 검색, 선택, 복사, 인쇄가 됩니다. 내보낸 파일을 열려면 네트워크 연결이 필요합니다. 관련 PR: [#10076](https://github.com/QwenLM/qwen-code/pull/10076)

**Goal이 얼마를 썼는지 보입니다.** Goal에는 token 예산이 있어 다 쓰면 멈추고 돌려주는데, 이전에는 사용량을 볼 수 없었습니다. 이제 터미널 하단, 상태 카드, Web Shell 모두에서 사용량과 상한이 표시되고, 멈춘 뒤에도 숫자가 남습니다. Goal이 3 라운드 연속 판단할 만한 성과를 내지 못하면 스스로 일시 중지하고, 메시지를 보내 중단한 것은 공회전으로 치지 않습니다. 관련 PR: [#11248](https://github.com/QwenLM/qwen-code/pull/11248), [#11254](https://github.com/QwenLM/qwen-code/pull/11254), [#11239](https://github.com/QwenLM/qwen-code/pull/11239), [#11257](https://github.com/QwenLM/qwen-code/pull/11257)

**Channel 설정 항목이 두 개 늘었습니다.** 그룹 채팅 메시지가 뒤섞여 있으면 Channel에 `messagePrefix`를 지정할 수 있습니다. 이 접두사로 시작하는 메시지만 봇을 트리거합니다. `instructions`는 특정 Channel에 상시 요구 사항을 고정으로 두는 설정으로, 응답 말투나 특정 유형 문제를 누구에게 넘길지 같은 것을 적고, 모든 Channel 유형에서 쓸 수 있습니다. 관련 PR: [#10817](https://github.com/QwenLM/qwen-code/pull/10817), [#11082](https://github.com/QwenLM/qwen-code/pull/11082)

**사고 강도를 설정할 수 있는 모델이 늘었습니다.** GPT-6 Astra는 low부터 max까지 5단계를 지원하고 기본은 medium입니다. GPT-5 계열은 각자 지원하는 단계에 맞춥니다. deepseek-v4-pro도 연결됐고 high와 max를 지원합니다. 관련 PR: [#11295](https://github.com/QwenLM/qwen-code/pull/11295), [#10999](https://github.com/QwenLM/qwen-code/pull/10999)

**리뷰에 두 관점이 추가됐습니다.** 변경 사항에 `SKILL.md`, `QWEN.md` 같은 지시 파일이 포함되면, 한 Agent가 수정된 지시를 실제로 돌려 본 뒤 글이 약속한 내용과 어긋난 곳을 찾습니다. 다른 관점은 PR 설명에서 짚은 주제를 일부러 피하면서 변경 사항 전체를 독립적으로 봅니다. 관련 PR: [#10221](https://github.com/QwenLM/qwen-code/pull/10221)

**로컬 코드 검색 도구를 바로 설치합니다.** 'zvec-grep 설치해 줘'라고 말하거나 `/zvec-grep-install`를 입력하면 zvec-grep를 설치하고 Qwen Code에 연결해 줍니다. 키워드 검색과 시맨틱 검색을 합친 로컬 코드 검색 도구입니다. 관련 PR: [#10723](https://github.com/QwenLM/qwen-code/pull/10723)

**할 일 목록 도구는 직접 켜야 합니다.** AI가 여러 단계의 작업을 할 때 스스로 작업 목록을 만들고 하나씩 체크하는데, 화면에 보이는 그 목록이 `todo_write` 도구입니다. 기본 도구 목록에서 빠졌으니 필요하면 설정에서 `tools.todoWrite.enabled`를 `true`로 바꾸고 재시작하세요. 관련 PR: [#10645](https://github.com/QwenLM/qwen-code/pull/10645)

**접속 주소를 직접 지정해도 명령 한 줄로 QR 코드가 나옵니다.** 이전에 `--hostname`을 수동으로 바인딩하려면 토큰과 허용 출처를 직접 설정해야 했고, 다 채우지 못하면 서비스가 시작을 거부했습니다. 이제 `qwen serve --hostname 0.0.0.0`이면 충분하고, 스마트폰으로 터미널의 QR 코드를 스캔하면 로그인된 Web Shell로 바로 들어갑니다. 관련 PR: [#11172](https://github.com/QwenLM/qwen-code/pull/11172)

**서비스 인스턴스를 여러 개 동시에 돌립니다.** 같은 컴퓨터에서 여러 Qwen Code 서비스 인스턴스를 동시에 실행할 수 있고, 충돌하면 Web Shell이 재시도 안내를 표시합니다. 관련 PR: [#10924](https://github.com/QwenLM/qwen-code/pull/10924), [#11207](https://github.com/QwenLM/qwen-code/pull/11207)

**Mem0 메모리에 쓰고 지울 수 있습니다.** Mem0를 연결하면 메모리를 Qwen Code가 작성하고 삭제할 수 있습니다. 관리자가 배포한 Mem0에는 자동 회상도 켤 수 있어서, 질문마다 가장 관련 높은 기록 몇 건을 자동으로 데려옵니다. 관련 PR: [#11311](https://github.com/QwenLM/qwen-code/pull/11311), [#11337](https://github.com/QwenLM/qwen-code/pull/11337), [#11246](https://github.com/QwenLM/qwen-code/pull/11246), [#11397](https://github.com/QwenLM/qwen-code/pull/11397)
