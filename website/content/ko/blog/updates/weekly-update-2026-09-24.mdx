Qwen Code는 이번 주에 v0.24.1 ~ v0.24.4 네 개의 정식 버전을 출시하고 PR 200개를 병합했습니다.

**컨텍스트가 찼다면 어떤 파일과 확장이 먹었는지 확인할 수 있습니다.** 어느 것을 줄일지 알면 자리를 되돌릴 수 있습니다.

**SSH 주소 하나로 다른 컴퓨터의 프로젝트를 수정할 수 있습니다.** 코드가 서버나 빌드 머신, 동료의 컴퓨터에 있어도 내 컴퓨터에 앉아 그곳의 파일을 고치고 빌드를 돌릴 수 있습니다.

**워크플로가 중간에 끊겨도 재시작 후 이어서 실행할 수 있습니다.** 이미 끝난 부분은 그대로 쓰고, 몇 시간짜리 긴 흐름도 실패한 곳만 채우면 됩니다.

## ✨ 새로운 기능

### 컨텍스트가 차면 어떤 파일·확장이 먹었는지 확인

`/context`는 컨텍스트를 출처별로 나누어 보여 줍니다. 시스템 프롬프트, 내장 도구, MCP 도구, 메모리 파일, 스킬, 확장이 가져온 파일에 더해 이번 주에는 '시작 컨텍스트'와 '캐시 접두사' 두 줄이 추가됐습니다. `/context detail`로 들어가면 개별 파일까지 확인할 수 있고, 확장이 가져온 항목은 `Extension: 확장자명 · 파일명`으로 표시되며 각각의 차지 비중도 함께 나옵니다. 터미널과 Web Shell 양쪽에 동일하게 반영됩니다.

**용량을 초과하면 알려 줍니다.** 상주 컨텍스트(`QWEN.md`와 자동 메모리)의 합이 '창의 15%'와 '1만 token' 중 작은 값을 넘으면 로딩 때 안내가 뜹니다.

**확장이 가져온 규칙은 해당 파일을 다룰 때만 적용할 수 있습니다.** 접근하는 파일에 걸릴 때만 컨텍스트를 주입하고, 평소에는 자리를 차지하지 않습니다.

이렇게 활용할 수 있습니다:

- 컨텍스트가 곧 차면 어떤 파일과 확장이 먹는지 먼저 확인
- 확장 설치 후 컨텍스트가 늘었다면 `/context detail`로 원인 짚어 냄
- 초과 안내를 받으면 `QWEN.md`를 정리할지 자동 메모리를 끌지 판단

관련 PR: [#12119](https://github.com/QwenLM/qwen-code/pull/12119), [#12318](https://github.com/QwenLM/qwen-code/pull/12318), [#12034](https://github.com/QwenLM/qwen-code/pull/12034)

### SSH 주소 하나로 다른 컴퓨터의 프로젝트를 바로 수정

프로젝트가 서버나 빌드 머신, 동료의 컴퓨터에 있어서 Qwen Code가 거기를 수정하길 원할 수 있습니다. 예전에는 그 컴퓨터에 Qwen Code를 먼저 설치하고 서비스를 띄운 뒤 주소를 옮겨 적어야 했습니다. 이제 Web Shell에서 워크스페이스를 추가할 때 디렉터리 경로에 SSH 주소를 바로 적으면 됩니다:

```text
ssh://user@host/absolute/project
```

그 컴퓨터에 Qwen Code가 없다면 이 주소를 적어 등록하고, 이미 Qwen Code 서비스를 돌리고 있다면 주소와 토큰을 한 번만 저장해 두면 이후 워크스페이스를 추가할 때 바로 고를 수 있습니다. 등록 후에는 그곳의 파일을 읽고 쓰고, 그곳에서 명령을 실행하고, 그곳의 Git 상태를 보는 일이 모두 내 로컬의 이 대화 하나에서 끝납니다. 방금 추가한 워크스페이스는 읽기 전용이며, '신뢰'를 승인해야 파일을 수정할 수 있습니다.

이렇게 활용할 수 있습니다:

- 코드와 의존성이 모두 빌드 머신에 있으면 로컬 대화에서 그곳 파일을 고치고 빌드 실행
- 다른 컴퓨터의 갖춰진 환경을 빌려 한 번 검증
- 로컬과 원격 프로젝트를 동시에 띄우고 한 대화에서 오가며 수정

관련 PR: [#12255](https://github.com/QwenLM/qwen-code/pull/12255), [#12085](https://github.com/QwenLM/qwen-code/pull/12085), [#12412](https://github.com/QwenLM/qwen-code/pull/12412)

[🎥 시연: Web Shell에서 `ssh://` 주소를 적어 원격 워크스페이스를 등록하고 그곳 파일을 수정하는 모습]

### 워크플로가 중간에 끊겨도 재시작 후 이어서 실행

한 흐름을 돌리다가 퇴근하거나 컴퓨터 재시작으로 중단되면 예전에는 처음부터 다시 해야 했습니다. 이제는 매 실행마다 기록이 남아 다음에 이어서 돌릴 수 있습니다.

**재시작 후 스스로 알려 줍니다.** Qwen Code를 열면 시작 안내에 어느 실행이 끊겼고 몇 단계에서 멈췄으며 서브 Agent가 몇 개 끝났는지 목록으로 뜨고, `/workflows`에서 확인하도록 안내합니다. 이 실행들은 모두 기록 목록에도 들어갑니다.

**Web Shell의 실행 기록 카드에 버튼이 있습니다.** '실패 경로 재시도'는 성공하지 못한 부분만 다시 돌리고, '전체 재실행'은 처음부터 다시 합니다.

이렇게 활용할 수 있습니다:

- 중간에 퇴근하면 다음 날 켰을 때 어디서 멈췄는지 먼저 확인
- 서브 Agent 두 개만 실패한 긴 흐름은 '실패 경로 재시도'로 그 두 곳만 채움
- 같은 흐름을 처음부터 다시 검증하려면 '전체 재실행' 선택

관련 PR: [#12159](https://github.com/QwenLM/qwen-code/pull/12159), [#12291](https://github.com/QwenLM/qwen-code/pull/12291), [#12097](https://github.com/QwenLM/qwen-code/pull/12097)

[📸 스크린샷: 재시작 후 시작 안내 + Web Shell 실행 기록 카드의 두 버튼]

### Web Shell에 여러 업데이트가 몰렸습니다

**파일 수정을 승인하기 전에 변경 사항을 펼쳐 보여 줍니다.** 확인이 필요한 파일 수정은 승인 카드에 이번 라운드에 추가된 줄과 삭제된 줄을 바로 나열하며, 파일 수정·새 파일 작성·notebook 변경 세 유형을 모두 다룹니다. 관련 PR: [#12443](https://github.com/QwenLM/qwen-code/pull/12443)

**긴 로그를 붙여 넣으면 카드로 접힙니다.** 붙여 넣은 내용이 200줄이나 8000자를 넘으면 자동으로 접히고, 제목은 앞부분을 따르며, 펼치려면 '입력창에 표시'를 눌러 입력창에 되돌립니다. `/`나 `!`로 시작하는 붙여 넣기, 짧은 붙여 넣기, 선택 영역을 바꾸는 내용은 접히지 않습니다. 관련 PR: [#12084](https://github.com/QwenLM/qwen-code/pull/12084)

**오른쪽 패널에 Trajectory 탭을 추가할 수 있습니다.** 한 라운드를 돌고 나서 느리거나 비싸다고 느꼈다면, 이 탭을 열면 시간이 어디에 쓰였는지 보입니다 — 라운드별 소요 시간, 첫 글자가 나오는 데 걸린 시간, 소비한 token 양, 가장 오래 걸린 도구 호출. 진입점은 오른쪽 확장 영역의 '탭 추가'에서 Trajectory를 고르는 것입니다. 관련 PR: [#12388](https://github.com/QwenLM/qwen-code/pull/12388)

**Git 이력이 훨씬 찾기 쉬워졌습니다.** Web Shell의 커밋 기록이 브랜치 그래프로 표시되고, 모든 브랜치를 전환할 수 있으며 커밋 메시지·작성자·해시로 검색도 됩니다. 원격 저장소 주소도 터미널에서 명령을 치지 않고 화면에서 추가하고 삭제할 수 있습니다. 진입점은 모두 입력창 위 브랜치 탭에 있습니다. 관련 PR: [#12152](https://github.com/QwenLM/qwen-code/pull/12152), [#11163](https://github.com/QwenLM/qwen-code/pull/11163)

**그 외 개선.** 계획 모드 토글이 입력창 도구줄에서 '+' 메뉴로 들어갔고, 켜 두면 입력창 위에 끌 수 있는 탭이 남습니다 ([#12218](https://github.com/QwenLM/qwen-code/pull/12218)); `/export`로 내보낸 파일이 대화 안에서 미리보기와 다운로드가 가능한 카드로 바뀝니다 ([#12050](https://github.com/QwenLM/qwen-code/pull/12050)).

## 📊 그 외 새로운 기능

**Web Shell을 컴퓨터에 독립 앱으로 설치할 수 있습니다.** 주소창 오른쪽에 설치 진입점이 뜨고, 한 번 누르면 자체 아이콘과 독립 창을 갖춰 스토어에서 설치한 앱처럼 쓰입니다. Chrome / Edge 111 이상, Firefox 128 이상, Safari 16.4 이상이 필요하고, 주소가 로컬 주소(`127.0.0.1` 또는 `localhost`)나 HTTPS여야 합니다. LAN IP로 접근하면 설치되지 않습니다. 관련 PR: [#11722](https://github.com/QwenLM/qwen-code/pull/11722)

**데스크톱에서 창 글자 크기를 조절할 수 있습니다.** `Cmd` / `Ctrl`에 `-` / `=` / `0`을 누르거나 트랙패드에서 두 손가락으로 확대·축소하면 50%부터 300%까지 자유롭게 조절되고, 다음에 열어도 이번에 맞춘 배율이 유지됩니다. 관련 PR: [#12410](https://github.com/QwenLM/qwen-code/pull/12410)

**Goal 잔여 한도가 입력창 위에 표시됩니다.** 해당 상태에 기존 token 예산에 더해 라운드수와 시간 상한도 나타나며, 예를 들어 `3 / 20 turns`, `12m 3s / 30m 0s`처럼 표시됩니다. 상한을 두지 않은 Goal은 그대로입니다. `/export`로 내보낸 세션 기록에는 Goal의 전체 과정도 함께 담깁니다. 관련 PR: [#12201](https://github.com/QwenLM/qwen-code/pull/12201), [#12099](https://github.com/QwenLM/qwen-code/pull/12099)

**Goal 종료를 판단할 때는 대화의 실제 경과를 봅니다.** `/goal`으로 목표를 들고 몇 라운드를 돌리면, 스스로 '완료'라고 말하는 것은 인정되지 않습니다 — 검수가 최근 대화를 되돌아보며 실제로 무엇이 일어났는지 확인하고, 맞지 않으면 미완으로 판정합니다. 관련 PR: [#12105](https://github.com/QwenLM/qwen-code/pull/12105)

**파견한 서브 Agent를 컨테이너 안에 가둬 작동시킬 수 있습니다.** 저장소 전체를 훑거나 수많은 명령을 실행시켜도 home 디렉터리에서 SSH key와 자격 증명을 건드릴까 걱정할 필요가 없습니다 — 실행하는 모든 명령과 읽기·쓰기가 Docker나 Podman 컨테이너 안에 갇히고, 건드릴 수 있는 것은 워크스페이스뿐입니다. 이렇게 돌리려면 시작 전에 `QWEN_AGENT_EXECUTION_BACKEND=docker`를 설정하면 되는데, 대가로 워크플로, Agent Team, MCP, LSP, 스킬이 함께 꺼지고 Windows는 아직 지원되지 않습니다. 관련 PR: [#11711](https://github.com/QwenLM/qwen-code/pull/11711)

**한 서비스 제공자 아래 두 가지 인터페이스를 섞어 걸 수 있습니다.** 어떤 모델을 OpenAI의 Responses 프로토콜로 쓰려면 해당 모델 항목에 `"wireApi": "responses"` 한 줄을 추가하면 되고, 나머지 모델은 그대로 Chat을 사용합니다. `/auth`로 사용자 지정 서비스 제공자를 설정할 때도 'API 형식 선택' 단계를 고를 수 있습니다. 관련 PR: [#11538](https://github.com/QwenLM/qwen-code/pull/11538)

## 👏 사용성 개선

**스마트폰에서 Web Shell이 더 매끄러워졌습니다.** 서비스를 외부 주소에 바인딩하면 Web Shell 세션 화면 오른쪽 위에도 페어링 코드가 뜨고, 스마트폰으로 스캔하면 현재 세션에 바로 들어가 수동으로 토큰을 입력할 필요가 없습니다. 스마트폰 화면에 들어오면 입력창도 다시 배치되어 열몇 가지 동작이 '메시지에 추가' 서랍으로 들어갔습니다. 관련 PR: [#12322](https://github.com/QwenLM/qwen-code/pull/12322), [#12252](https://github.com/QwenLM/qwen-code/pull/12252)

**입력창 주변이 단정해졌습니다.** 세션이 아직 만들어지기 전에는 워크스페이스 선택과 Git 브랜치 탭이 입력창 도구줄에서 아래 별도 한 줄로 옮겨지고, 세션이 만들어진 후에는 워크스페이스가 상단에 폴더 아이콘 하나로만 표시되며 마우스를 올리면 전체 경로를 볼 수 있습니다. 대화 안의 링크형 산출물 카드는 새 페이지를 바로 열도록 바뀌었습니다. 관련 PR: [#12299](https://github.com/QwenLM/qwen-code/pull/12299), [#12317](https://github.com/QwenLM/qwen-code/pull/12317)

**압축 결과가 문장으로 표시됩니다.** `/compress` 이후 '컨텍스트를 X → Y로 압축했습니다'라고 표시되고, 압축할 것이 없으면 '압축 불필요.'라고 전합니다. 세션을 다시 열면 컨텍스트 링의 숫자도 새로고침됩니다. 관련 PR: [#12141](https://github.com/QwenLM/qwen-code/pull/12141)

**주 워크스페이스가 아닌 워크스페이스의 Channel 자동 연결도 적용됩니다.** `qwen serve` 하나로 여러 워크스페이스를 들고 각각 다른 Channel 봇을 연결하면, 서비스 시작 시 신뢰되는 각 워크스페이스의 Channel을 되살립니다. 'Qwen Code 시작 시 자동 연결' 토글을 켜고 저장하면 실제로 적용됩니다. 관련 PR: [#12385](https://github.com/QwenLM/qwen-code/pull/12385)

**Linux 샌드박스는 도구 실행만 가두도록 바뀌었습니다.** 지난 주처럼 Qwen Code 전체를 bwrap에 가두는 설정은 이번 버전에서 즉시 오류가 나고 한 줄의 마이그레이션 안내를 제공합니다. `tools.executionSandbox`로 바꾸면 남는 제약은 명령줄, 파일 읽기·쓰기 같은 도구 실행뿐이고, Qwen Code 본체와 모델 요청, 로그인 상태는 모두 로컬에 남습니다. 관련 PR: [#12267](https://github.com/QwenLM/qwen-code/pull/12267)

**스크립트의 일회성 호출이 빨라졌습니다.** `qwen -p`처럼 한 문장 돌리고 끝나는 용법은 실측 7.7초에서 5.1초로, 메모리는 640 MiB에서 421 MiB로 줄었고 프로세스를 하나 덜 띄웁니다. 관련 PR: [#12340](https://github.com/QwenLM/qwen-code/pull/12340)

**터미널에 페어링 코드가 안 뜨면 이유를 설명합니다.** 외부 주소에 바인딩해 스마트폰으로 스캔해 연결하려 하는데 터미널에 코드가 뜨지 않으면, 그 이유를 설명하고 주소만 담은 코드를 따로 제공합니다. 스캔한 뒤 스마트폰에서 토큰을 한 번 입력하면 연결됩니다. 토큰을 포함한 코드를 강제로 띄우려면 `qwen serve --token-qr`을 사용하십시오. 관련 PR: [#12266](https://github.com/QwenLM/qwen-code/pull/12266)
