Qwen Code는 이번 주 **v0.18.0-preview**(preview.0 / preview.1 / preview.2)를 내놓고 PR 50개 이상을 병합했습니다. 세 방향을 다뤘습니다:

**Agent가 드디어 병렬로 일합니다.** `/fork` 명령으로 대화 도중에 백그라운드 Agent를 다른 일에 보내면 됩니다. 컨텍스트, 도구, 모델 설정을 그대로 상속받고, 당신은 메인 대화에서 계속 작업합니다. fork가 끝나면 백그라운드 작업 패널이 알려줍니다.

**스킬 관리에 패널이 생겼습니다.** 이전까지 Qwen Code의 skill 시스템에는 공용 진입점이 없었습니다. 스킬 이름을 외워야만 쓸 수 있었죠. 이제 `/skills`를 입력하면 picker 대화상자가 열려 탐색, 검색, 활성화/비활성화, 원클릭 실행이 되고, 워크스페이스 단위로 어떤 스킬을 모델에게 보여줄지 관리할 수도 있습니다.

**메모리가 프로젝트를 넘습니다.** 이전까지 auto-memory는 현재 프로젝트 디렉터리 안에서만 쌓여서, 저장소를 바꾸면 Agent는 기억을 잃었습니다. 이번 주 `~/.qwen/memories/` 사용자 레벨 메모리 디렉터리가 추가됐고, 취향·작업 스타일·프로젝트를 넘는 피드백은 자동으로 사용자 레벨로 라우팅됩니다. 프로젝트의 deadline과 이벤트는 프로젝트 디렉터리에 남습니다. 이미 있는 네 가지 메모리 분류를 라우팅에 썼으므로 새 설정은 없습니다.

## ✨ 새로운 기능

### /fork: 대화 도중 백그라운드 Agent를 파견하고, 메인 대화는 기다리지 않습니다

`/fork`로 한 세션 안에서 여러 일을 동시에 돌립니다. 새 터미널을 열 필요도, 세션을 옮길 필요도 없습니다.

`/fork <지시문>`을 입력하면 백그라운드 Agent가 즉시 시작됩니다. 현재 대화의 전체 컨텍스트(system prompt, 이력, 도구, 모델, prompt cache)를 상속받고 백그라운드에서 지시를 독립적으로 실행합니다. 메인 대화는 막히지 않으니 당신은 계속 작업하면 됩니다. fork가 끝나면 백그라운드 작업 패널로 알리고, 결과는 JSONL transcript에 기록됩니다.

`/branch`와 역할이 다릅니다. `/branch`는 현재 대화를 새 세션으로 복사해 다른 방향을 탐색하는 것이고, `/fork`는 현재 세션 안에 백그라운드 일꾼을 하나 내보내는 것입니다.

**이걸로 할 수 있는 일:**

- 코딩 도중 `/fork 이 모듈 테스트를 채워 주세요` — 테스트는 백그라운드에서 돌고 당신은 다음 모듈을 씁니다
- 백그라운드 작업 패널에서 fork 진행 상황(`main` / `○ fork: …`)을 실시간으로 보고, 끝나면 터미널 알림을 받습니다
- 여러 fork를 병렬로 돌릴 수 있고, 동시성 상한 안에서 관리됩니다
- 지시문이 비어 있거나, 설정이 없거나, 스트리밍 출력 중인 경우 명확한 오류 메시지를 보여줘 소리 소문 없이 실패하지 않습니다

### /skills: 스킬 관리에 드디어 패널이 생겼습니다

이전까지 Qwen Code의 skill은 이름을 기억해 `/<스킬명>`을 직접 쳐야 했습니다. 탐색도, 검색도, 켜고 끄는 것도 없었습니다. 시끄러운 스킬 하나 끄고 싶으면 settings.json을 손으로 고쳐야 했죠.

이제 `/skills`를 입력하면 picker 대화상자가 열립니다. 등록된 스킬이 한눈에 보입니다: 이름, 설명, 출처(프로젝트 레벨 / 사용자 레벨 / 내장). 키보드로 검색해 빠르게 찾고, Space로 활성화/비활성화를 전환하고, Enter로 고른 스킬의 명령을 입력창에 바로 채웁니다. 비활성화 상태는 워크스페이스 레벨 `skills.disabled` 설정에 기록돼 현재 세션에 즉시 반영됩니다 — 모델의 `<available_skills>` 목록과 slash 자동 완성이 함께 갱신되니 재시작이 필요 없습니다.

scope를 넘어가는 설정도 처리했습니다. 어떤 스킬이 사용자 레벨 settings에서 꺼져 있으면, 워크스페이스 레벨 picker에는 `[locked: User]`로 표시되고 워크스페이스 레벨에서 덮어쓸 수 없습니다.

**이걸로 할 수 있는 일:**

- `/skills`로 패널을 열어 사용 가능한 스킬과 설명을 모두 탐색
- 키보드로 키워드를 입력해 스킬 검색
- Space로 스킬 활성화/비활성화, Esc로 저장하고 종료
- Enter로 고른 스킬을 입력창에 채워 바로 실행
- 끈 스킬은 모델 가용 스킬 목록과 slash 자동 완성에서 사라집니다

### 사용자 레벨 크로스 프로젝트 메모리: 저장소를 바꿔도 기억을 잃지 않습니다

이전까지 auto-memory는 현재 프로젝트 디렉터리 안에서만 쌓여, 저장소를 바꾸면 Agent는 기억을 잃었습니다. 이번 주 `~/.qwen/memories/` 사용자 레벨 메모리 디렉터리가 프로젝트 레벨 `.qwen/memories/`와 나란히 추가됐습니다. 이미 있는 네 가지 분류(user / feedback / project / reference)를 라우팅에 쓰므로 새 설정 항목은 없습니다.

라우팅 규칙은 하드코딩이 아니라 메모리 추출 Agent의 prompt에서 결정됩니다:

- **user 유형**: 항상 사용자 레벨로 갑니다 (당신이라는 사람에 관한 정보이므로)
- **feedback 유형**: 기본은 사용자 레벨입니다 (대부분 피드백은 개인 스타일). 다만 프로젝트 레벨 규약(테스트 전략, 빌드 규범)이 명확하면 프로젝트 레벨로 보냅니다
- **project 유형**: 항상 프로젝트 레벨입니다 (deadline, 이벤트, 진행 중인 작업)
- **reference 유형**: 기본은 프로젝트 레벨입니다 (이 프로젝트의 Linear, Grafana). 회사 전체 공통 리소스는 사용자 레벨로 보냅니다

system prompt에는 두 scope의 인덱스가 모두 렌더링됩니다 — 사용자 레벨이 먼저(배경 정보), 프로젝트 레벨이 나중(더 구체적이니 자연스럽게 덮어씁니다). 사용자 레벨 `MEMORY.md`가 비어 있어도 자리표시자는 렌더링됩니다. Agent가 그 디렉터리의 존재를 알고 무엇을 써 넣을 수 있는지 알아야 하기 때문입니다.

**이걸로 할 수 있는 일:**

- Agent가 당신의 취향("pnpm을 선호한다", "테스트는 jest 말고 vitest를 쓴다")을 배우면, 어떤 새 프로젝트로 가도 기억합니다
- 모든 저장소의 `.qwen/QWEN.md`에 개인 취향을 다시 옮겨 적지 않아도 됩니다
- `memory.enableManagedAutoMemory` 스위치가 기존 설정을 그대로 재사용하니 추가 설정이 필요 없습니다

### /stats 인터랙티브 통계 패널: token 사용량 한눈에

이전까지 `/stats`는 현재 세션의 token 수만 텍스트 한 덩어리로 보여 주고 말았습니다. 이제 세 탭이 있는 인터랙티브 패널로 바뀌었습니다: **Session**(현재 세션 실시간 지표), **Activity**(세션을 넘는 사용 추이), **Efficiency**(성능과 도구 분석).

사용 데이터는 자동으로 `~/.qwen/usage_record.jsonl`에 영속화되며, 세션 종료와 `/clear` 때 기록합니다. Tab / Shift+Tab으로 탭을 바꾸고, `r`로 시간 범위를 전환하고(All → Month → Week → Today), 방향키로 월별 추이 그래프를 넘겨봅니다.

Activity 탭은 GitHub 스타일 기여 히트맵, braille 꺾은선 그래프로 그린 token 추이, top-5 프로젝트 순위를 보여줍니다. Efficiency 탭은 캐시 적중률, 도구 성공률, 평균 지연, 모델 비교 표를 보여줍니다.

**이걸로 할 수 있는 일:**

- `/stats`를 열어 현재 세션의 token 사용량과 비용을 한눈에 확인
- Activity 탭으로 세션을 넘는 사용 추이와 코딩 히트맵 확인
- Efficiency 탭으로 성공률이 낮은 도구, 지연이 큰 모델 확인
- 시간 범위로 걸러 단계별 사용 패턴을 비교

### 시스템 잠자기 방지: 긴 작업 도중에 끊기지 않습니다

오래 걸리는 prompt나 도구 실행 중에 시스템이 자동으로 잠들면 진행 중인 작업이 끊깁니다. 이번 주 실행 중 잠자기 억제기가 추가됐습니다. 모델이 스트리밍 응답하거나 도구가 실행되는 동안 시스템이 잠드는 것을 자동으로 막습니다. macOS는 `caffeinate`, Linux는 `systemd-inhibit`, Windows는 `SetThreadExecutionState`를 사용합니다.

기본으로 켜져 있고(`general.preventSystemSleep: true`), 원치 않으면 설정 하나로 끕니다. 참조 개수로 관리돼 병렬 작업 여러 개가 억제 락을 하나 공유하고, 전부 끝나면 자동으로 해제됩니다. ACP 세션도 동일하게 적용됩니다.

**이걸로 할 수 있는 일:**

- 긴 Agent 작업(computer-use, 대규모 리팩터링)이 시스템 잠자리 때문에 중단되지 않습니다
- 기본 활성화라 설정이 필요 없습니다
- `general.preventSystemSleep: false`로 끄면 됩니다

### Vim 모드 대수선: Esc는 얌전해지고, Enter는 보내지고, 명령어는 자동 완성

Vim 사용자는 Qwen Code에서 세 가지 문제를 오래 참았습니다. INSERT 모드에서 Esc를 누르면 AppContainer의 핸들러까지 함께 발동해 'Press Esc again to clear' 안내가 뜨고 입력 버퍼까지 비워졌습니다. NORMAL 모드에서 Enter를 눌러도 아무 일이 일어나지 않았습니다. 모드 전환 시 하단 표시기가 눈에 띄게 느리게 갱신됐습니다.

이번 주 한꺼번에 고쳤습니다. Esc는 INSERT 모드에서 모드 전환만 하고 다른 핸들러로 새지 않습니다. NORMAL 모드에서 Enter로 메시지를 정상 제출합니다. VimModeContext를 State와 Actions 두 context로 나누고 `useMemo`와 함께 써서, consumer 6개가 모드 전환 하나에 전부 다시 렌더링되지 않습니다. 하단에 `-- NORMAL --` 표시기가 새로 생기고 전환과 동시에 갱신됩니다.

NORMAL 모드 명령도 대거 채웠습니다: undo, replace, 대소문자 전환, 줄 합치기, indent/unindent, WORD 이동, find/till 이동, yank/paste(시스템 클립보드), operator-pending 조합.

**이걸로 할 수 있는 일:**

- INSERT → NORMAL(Esc)에서 입력이 비워지지 않고, 모델의 스트리밍 출력도 끊기지 않습니다
- NORMAL 모드 Enter로 메시지 제출 — Vim을 안 쓸 때와 동작이 같습니다
- `-- NORMAL --` / `-- INSERT --` 표시기가 지연 없이 즉시 전환
- `u`(undo), `r`(replace), `~`(대소문자 전환), `J`(join) 같은 표준 명령 사용 가능

### 독립 설치 자동 업데이트: npm 없이도 원클릭 업그레이드

이전까지 설치 스크립트(`curl ... | bash`)로 독립 설치한 Qwen Code는 업데이트할 때 npm global install fallback을 탔습니다. EACCES 오류가 나거나(npm prefix에 root 권한이 필요), 독립 binary와 다른 위치에 설치됐습니다.

이번 주 독립 설치에 네이티브 자동 업데이트가 붙었습니다.전 과정에 sudo도, 패키지 관리자도 필요 없습니다.

**이걸로 할 수 있는 일:**

- 독립 설치 사용자는 업데이트 안내를 보면 자동 다운로드, 검증, 교체를 거치고 재시작하면 반영됩니다
- 업데이트가 실패하면 이전 버전으로 자동 롤백됩니다
- 터미널 여러 개가 동시에 시작해도 충돌하지 않습니다(lock 파일 보호)
- `~/.local/bin`이 shell rc 파일에 자동 기록돼 PATH 우선순위가 지켜집니다

관련 PR: [#4629](https://github.com/QwenLM/qwen-code/pull/4629)
