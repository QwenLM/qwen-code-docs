Qwen Code는 이번 주에 v0.21.0과 v0.21.1 두 개의 정식 버전을 출시하고 PR 290개 이상을 병합했습니다.

**세션과 Agent 생명주기에서 비어 있던 두 곳을 채웠습니다.** 예전 대화의 컨텍스트를 다시 쓰려면 resume이나 fork뿐이었고, 그러려면 현재 대화가 끊겼습니다. 이제 `@`를 입력하면 자동 완성 목록에 이 프로젝트의 과거 세션이 뜨고, 하나를 고르면 읽기 전용 요약이 주입되는 동안 현재 대화는 그대로 유지됩니다. 백그라운드 Agent도 실행이 끝나면 바로 폐기되던 탓에 한 가지를 더 물으려면 처음부터 다시 만들어야 했습니다. 이제는 완료된 Agent 런타임이 상위 세션에 그대로 상주하고, `send_message`로 대화를 이어 가면 됩니다. 프로세스를 종료했다가 돌아와도 roster까지 복원됩니다.

**스킬 시스템이 '수동' 단계에서 한 걸음 나아갔습니다.** `/learn`은 이전까지 텍스트, 문서, 웹 페이지만 다뤘고, 교육 영상은 직접 본 뒤 스킬을 손으로 적어야 했습니다. 이제는 MP4 파일을 그대로 던지면 Agent가 영상을 보고 재사용 가능한 Skill로 뽑아 냅니다. 스킬 디렉터리를 여러 벌 복사할 필요도 없습니다. settings에 경로만 지정하면 Claude Code, Codex, Qwen Code가 같은 스킬 라이브러리를 공유합니다.

**관측성과 연동도 뒤따라 채워지고 있습니다.** `/stats`에 드디어 TTFT, 생성 소요 시간, TPS가 생겼습니다. 모델을 바꿔 가며 스트리밍 성능을 비교할 때 감에 의존하지 않아도 됩니다. GitHub Channel 어댑터가 가동을 시작해, Issue나 PR에서 봇을 멘션하면 Agent가 댓글로 답합니다. Web Shell은 이번 주 PR이 40개 이상 병합됐습니다. Git 브랜치 선택기, commit 대화창, PR 생성 흐름, Channel 관리 페이지, 파일 렌더링 미리보기, 음성 입력 — 한 번에 다 들어갔습니다.

## ✨ 새로운 기능

### /learn이 영상 입력을 지원: 교육 영상 하나면 재사용 가능한 스킬이 됩니다

이전까지 `/learn`은 텍스트, 문서, 디렉터리, 웹 페이지를 다뤘지만 영상은 안 됐습니다. 15분짜리 작업 화면 녹화가 있어서 Agent가 쓸 수 있는 스킬로 만들고 싶다면, 직접 끝까지 보고 SKILL.md를 손으로 작성해야 했습니다.

이제 `/learn`은 로컬 MP4, WebM, MOV, M4V 파일과 HTTP(S) 영상 직링크를 지원합니다. 명령을 실행하면 현재 모델이 영상 입력을 지원하는지 먼저 확인하고, 통과하면 영상을 Agent에게 넘겨 정리시킵니다. 결과는 `learned-skill-*` 디렉터리로 나오고, 여기에 `SKILL.md`와 타임스탬프가 붙은 `references/source.md` 출처 기록이 담깁니다. YouTube 페이지 URL은 인식되어 거부되고, 먼저 로컬 영상으로 다운로드하라고 안내합니다. 영상이 아닌 입력은 기존 동작 그대로입니다.

이렇게 쓸 수 있습니다:

- 동료의 작업 화면 녹화를 팀에서 재사용하는 스킬로 바로 바꿉니다
- 교육 영상을 보고 `/learn tutorial.mp4` 한 번으로 작업 단계를 추출합니다
- 출처 기록에 "source-grounded, not execution-verified"라고 표시되어 '보고 얻은 것'과 '직접 검증한 것'이 갈립니다

### @로 과거 세션 참조: 복원도 fork도 없이 현재 대화에서 과거 컨텍스트를 부릅니다

예전에는 과거 세션의 컨텍스트를 재사용하려면 resume이나 fork뿐이었습니다. resume은 현재 대화를 떠나야 하고, fork는 새 브랜치를 만듭니다. '이전 결론을 잠깐 인용하고 싶은' 정도의 가벼운 요구에는 둘 다 무거웠죠.

이제 입력창에 `@`를 치면 자동 완성 드롭다운이 전체·파일·세션·MCP·확장 분류로 결과를 나눠 보여 주고, 좌우 방향키로 분류를 전환합니다. 과거 세션을 고르면 Qwen Code가 결정적으로 생성한 읽기 전용 요약을 주입합니다. 사용자와 어시스턴트에게 보이던 텍스트는 그대로 두고, 도구 결과는 한 줄 상태로 압축하며, 전체를 8k token 예산 안에 맞추되 최신 내용을 우선합니다. 현재 대화는 전혀 건드리지 않고, 과거 세션도 복원하거나 분기하지 않습니다.

이렇게 쓸 수 있습니다:

- 현재 작업에서 앞서 디버그한 세션의 결론을 옮겨 다니지 않고 인용합니다
- 지난번 코드 리뷰 피드백을 컨텍스트로 새 작업에 넘겨줍니다
- 세션을 넘어 프로젝트 지식을 쌓고, 매번 배경을 다시 설명하지 않습니다

관련 PR: [#7302](https://github.com/QwenLM/qwen-code/pull/7302)

### 백그라운드 Agent 상주와 세션 간 복구: 완료 후 재구축 없이 한 마디로 이어 가기

이전에는 백그라운드 Agent가 끝나면 런타임이 폐기됐습니다. 한 가지를 더 물으려면 JSONL transcript에서 chat, 도구, registry, provider 캐시를 전부 다시 만들어야 했습니다 — 느릴 뿐 아니라 프로세스 안에 있던 상태가 모두 사라집니다. 더 나쁜 경우는 프로세스를 종료하고 상위 세션을 복원하면, 완료된 Agent가 그대로 `Task not found`가 되어 버리는 것이었습니다.

이번 주 두 PR이 이 문제를 같이 정리했습니다. 첫째, 완료된 백그라운드 Agent 런타임이 상위 세션에 바로 상주합니다. 같은 `task_id`로 `send_message`를 보내면 살아 있는 chat, 이미 준비된 도구, provider 캐시, 시작 때의 모델을 그대로 재사용하고 transcript에서 다시 만들지 않습니다. 둘째, 프로세스를 종료했다가 상위 세션을 복원하면 중단된 Agent는 `paused`로, 완료된 Agent는 `completed` 상태로 돌아오고 작업 ID는 그대로입니다. 새로 추가된 `list_agents` 도구로 현재 세션에서 참조 가능한 백그라운드 Agent를 모두 볼 수 있습니다.

이렇게 쓸 수 있습니다:

- 백그라운드 Agent가 코드 리뷰를 끝내면 '세 번째 제안 좀 더 펼쳐 줘'라고 추가 질문합니다. 재구축은 없습니다
- 터미널을 끄고 다음 날 돌아와 `list_agents`를 보면 어제 Agent가 그대로 있고, 바로 이어서 일합니다
- 수정을 반복하는 동안 Agent는 시작 때 모델을 유지하고, 상위 세션에서 모델을 바꿔도 영향받지 않습니다

관련 PR: [#7426](https://github.com/QwenLM/qwen-code/pull/7426), [#7459](https://github.com/QwenLM/qwen-code/pull/7459)

### 커스텀 스킬 디렉터리: 스킬 한 벌을 여러 Agent가 함께 씁니다

이전에는 스킬을 `~/.qwen/skills/` 아래에만 둘 수 있었습니다. Claude Code와 Qwen Code를 같이 쓰면 같은 스킬을 두 벌 복사해야 했고, 하나를 고치고 다른 하나를 잊는 게 다반사였습니다.

이제 settings.json에 `skills.directories` 배열을 추가해 스킬을 더 탐색할 경로를 지정하면 됩니다. 경로는 `~` 확장을 지원하고 SKILL.md 파일을 재귀적으로 훑습니다. 기본 디렉터리 우선순위가 더 높아, 이름이 겹치는 스킬은 기본 디렉터리 것을 따릅니다.

이렇게 쓸 수 있습니다:

- `~/.agent/skills`에 스킬을 모아 두고 Claude Code, Codex, Qwen Code가 함께 씁니다
- 팀 공용 스킬 라이브러리를 `/shared/team-skills`에 두고 전원 자동으로 동기화합니다
- 한 디렉터리에 몰아 넣지 않고 프로젝트별로 스킬을 정리합니다

### /stats에 생성 성능 지표: TTFT와 TPS를 한눈에

이전 `/stats`는 세션 진행 시간, 요청 총량, 도구 호출, 파일 변경만 보여 줬습니다. 두 모델의 스트리밍 응답 속도를 비교하고 싶어도 TTFT가 없고 TPS도 없어서 오직 감에 의존해야 했습니다.

이제 `/stats`와 Session 탭에 Generation Metrics 영역이 추가됐습니다. 최근 요청의 모델명, TTFT(첫 Token 지연), 생성 소요 시간, 출력 Token 수와 TPS, 그리고 세션 단위 타이밍 요청 수·평균 TTFT·가중 Session TPS를 볼 수 있습니다. 생성 소요 시간은 `api_duration - ttft`로 계산하고, TPS의 분모는 첫 가시 Token부터 생성 완료까지의 구간입니다. 내부 보조 prompt는 집계하지 않으며, 일별/월별 사용량 기록은 그대로입니다.

이렇게 쓸 수 있습니다:

- 모델을 바꾼 뒤 `/stats`를 한 번 돌려 TTFT와 TPS 차이를 바로 봅니다
- 로컬 백엔드와 클라우드 API의 스트리밍 성능을 비교합니다
- 세션 단위 가중 TPS로 대화 전체의 실제 처리량을 파악합니다

관련 PR: [#7677](https://github.com/QwenLM/qwen-code/pull/7677)

### GitHub Channel 어댑터: Issue와 PR에서 봇을 멘션하면 Agent가 바로 움직입니다

이전 Qwen Code의 Channel은 Feishu, WeChat, QQ, Telegram을 지원했지만 GitHub은 안 됐습니다. Issue에서 봇을 멘션해 문제를 좀 봐 달라고 하고 싶어도 방법이 없었습니다.

이제 GitHub Channel 어댑터가 가동을 시작했습니다. classic PAT를 설정하고 Channel을 켜면 GitHub 알림 API를 폴링합니다. Issue나 PR 댓글에서 봇을 멘션하면 Agent가 댓글 내용을 읽고 같은 스레드에 답합니다. 새 Issue를 만들 때 body에서 봇을 멘션해도(첫 접촉) 동작합니다. 중복 제거는 GitHub의 비동기 `markNotificationsAsRead`가 아니라 cursor 기반 댓글 창으로 판단하고, 봇 자신의 댓글은 걸러내 루프를 막습니다. GitHub Enterprise(`baseUrl` 설정)와 프록시도 지원합니다.

이렇게 쓸 수 있습니다:

- Issue에서 봇을 멘션해 '이 오류 좀 봐 줘'라고 하면 Agent가 바로 댓글로 답합니다
- PR 리뷰 중에 봇을 멘션해 컨텍스트를 보탭니다. 터미널로 옮겨갈 필요가 없습니다
- 폴링 간격을 설정(기본 60s)해 응답 속도를 필요에 맞게 조정합니다

관련 PR: [#7632](https://github.com/QwenLM/qwen-code/pull/7632)

### Web Shell 대대적 업데이트: Git 조작, Channel 관리, 파일 미리보기, 음성 입력을 한 번에

Web Shell에는 이번 주 PR이 40개 이상 병합됐습니다. Git 워크플로부터 Channel 관리, 입력 경험까지 손대지 않은 곳이 없습니다.

**Git 조작이 한 바퀴 돌아갑니다.** 이전 Web Shell에서는 브랜치를 볼 주기만 할 뿐 전환도, commit도, PR 생성도 안 됐습니다. 이제 새 세션을 만들 때 Git 모드 선택기가 생기고([#7471](https://github.com/QwenLM/qwen-code/pull/7471)), 세션 안에서 브랜치를 전환하고 commit 대화창을 열고 PR을 바로 만들 수 있습니다([#7731](https://github.com/QwenLM/qwen-code/pull/7731)). Worktree 세션에서도 Changes와 History 대화창을 열 수 있습니다([#7695](https://github.com/QwenLM/qwen-code/pull/7695)). 사이드바에는 읽기 전용 GitHub PR 패널([#7683](https://github.com/QwenLM/qwen-code/pull/7683))이 추가돼, 브라우저로 넘어가지 않고도 PR 상태를 볼 수 있습니다.

**Channel을 관리하는 페이지가 생겼습니다.** 이전에는 Channel을 설정하려면 settings.json을 직접 고쳐야 했습니다. 이제 Web Shell에 완전한 Channel 관리 페이지([#7793](https://github.com/QwenLM/qwen-code/pull/7793))가 있고, 설정 진행 흐름([#7893](https://github.com/QwenLM/qwen-code/pull/7893))과 페어링 요청 관리([#7909](https://github.com/QwenLM/qwen-code/pull/7909))도 지원합니다.

**파일 미리보기와 Agent 관리.** 파일 목록이 렌더링 미리보기를 지원하게 되면서([#7467](https://github.com/QwenLM/qwen-code/pull/7467)) 원문을 열지 않고도 내용을 볼 수 있습니다. 서브 Agent 세션이 상세 패널에 표시되고([#7380](https://github.com/QwenLM/qwen-code/pull/7380)), 백그라운드 Agent 상태가 실시간으로 동기화됩니다([#7561](https://github.com/QwenLM/qwen-code/pull/7561)). Workspace 선택기([#7390](https://github.com/QwenLM/qwen-code/pull/7390))와 네이티브 폴더 선택기([#7849](https://github.com/QwenLM/qwen-code/pull/7849))로 여러 프로젝트를 오가는 게 한결 수월해졌습니다.

**입력 경험.** 음성 입력은 현재 composer 워크스페이스로 범위가 한정되고([#7754](https://github.com/QwenLM/qwen-code/pull/7754)), 누르고 말하기 모드를 지원([#7839](https://github.com/QwenLM/qwen-code/pull/7839))하며, 모바일 안정성 문제도 고쳤습니다([#7806](https://github.com/QwenLM/qwen-code/pull/7806)). 터치 기기에서는 plain textarea composer로 되돌아갑니다([#7587](https://github.com/QwenLM/qwen-code/pull/7587)). 붙여넣은 내용이 사라지는 일도 없어졌습니다([#7824](https://github.com/QwenLM/qwen-code/pull/7824)). 터미널은 256색과 truecolor SGR 시퀀스 해석을 지원합니다([#7620](https://github.com/QwenLM/qwen-code/pull/7620)).

**그 외 개선.** 사이드바를 창 폭의 절반까지 늘릴 수 있고([#7778](https://github.com/QwenLM/qwen-code/pull/7778)), 세션 이름에 마우스를 올리면 전체 이름이 표시되며([#7662](https://github.com/QwenLM/qwen-code/pull/7662)), Monitor 작업에 상세 패널이 생겼고([#7817](https://github.com/QwenLM/qwen-code/pull/7817)), 긴 세션의 렌더링 성능을 개선했습니다([#7408](https://github.com/QwenLM/qwen-code/pull/7408)). Shadow DOM 격리로 호스트 CSS가 컴포넌트 스타일을 오염시키지 않습니다([#7551](https://github.com/QwenLM/qwen-code/pull/7551)). 입력창에 'BTW'를 치면 보조 질문을 하나 열어 보라고 제안합니다([#7935](https://github.com/QwenLM/qwen-code/pull/7935)).

## 📊 그 외 새로운 기능

**이미지 줌 도구.** 큰 이미지는 모델에 보내기 전에 축소되기 때문에 작은 글자나 그래프 라벨이 자주 뭉개집니다. 이제 이미지 입력을 지원하는 모델은 `zoom_image` 도구로 원본 전체 해상도 파일에서 지정한 영역만 잘라, 확대한 JPEG 뷰를 받을 수 있습니다. PNG, JPEG, WebP를 지원하고 EXIF 회전도 자동으로 처리합니다. 관련 PR: [#7809](https://github.com/QwenLM/qwen-code/pull/7809)

**Subagent 모델 등급.** 작업마다 비용이 다른 모델을 써야 하지만, 호출하는 쪽이 구체적인 모델 ID를 만지면 안 됩니다. 이제 settings에서 `small`, `high` 같은 시맨틱 등급을 모델 selector에 매핑할 수 있고, Agent 도구 스키마에는 등급 이름만 노출됩니다. Fork와 지명 teammate는 이 파라미터를 받지 않습니다. 관련 PR: [#7702](https://github.com/QwenLM/qwen-code/pull/7702)

**이미지 생성 모델을 설정으로 지정.** 이미지 생성이 더 이상 기본 모델에 묶이지 않고, 설정에서 지정할 수 있습니다. 관련 PR: [#7607](https://github.com/QwenLM/qwen-code/pull/7607)

**외부 코퍼스 검색 도구.** `context_search` MCP 도구가 새로 추가되어, 외부 지식 베이스나 RAG 서비스에서 필요할 때 컨텍스트를 가져옵니다. 읽기 전용이며 자동 회수도 기록도 없고, 서비스 제공자와 코퍼스는 관리자가 설정해 고정합니다. Mem0 어댑터와 범용 HTTP 어댑터 두 가지를 함께 제공합니다. 관련 PR: [#7586](https://github.com/QwenLM/qwen-code/pull/7586)

**시스템 신원 덮어쓰기.** 환경 변수 `QWEN_SYSTEM_IDENTITY_MD`로 핵심 신원 프롬프트를 덮어쓸 수 있습니다. 관련 PR: [#7478](https://github.com/QwenLM/qwen-code/pull/7478)

**MCP 강제 재연결.** `qwen serve`가 MCP 서버 강제 재연결을 지원해, 프로세스 전체를 다시 시작하지 않아도 됩니다. 관련 PR: [#7488](https://github.com/QwenLM/qwen-code/pull/7488)

**Workspace trust 핫 리로드.** workspace trust 설정을 바꾸면 실행 중인 daemon이 새 정책을 즉시 적용합니다. 재시작이 필요 없습니다. 관련 PR: [#7268](https://github.com/QwenLM/qwen-code/pull/7268)

**Skill 기본 비활성 상태.** 스킬을 기본은 꺼 두되 명시적으로 켤 수 있게(soft default) 설정할 수 있고, 하드 비활성으로 설정하면 덮어쓸 수 없습니다. 관련 PR: [#7357](https://github.com/QwenLM/qwen-code/pull/7357)

**Session-scoped 런타임 MCP.** ACP 세션이 세션 단위 런타임 MCP 설정을 지원합니다. 관련 PR: [#7847](https://github.com/QwenLM/qwen-code/pull/7847)

**DingTalk 이미지 전송.** DingTalk Channel이 이미지 메시지 전송을 지원합니다. 관련 PR: [#7698](https://github.com/QwenLM/qwen-code/pull/7698)

**Telegram forum topic 라우팅.** Telegram Channel의 답장이 forum topic으로 올바르게 라우팅됩니다. 관련 PR: [#7612](https://github.com/QwenLM/qwen-code/pull/7612)

**Review 이중 언어 댓글.** PR 설명이 중국어로 작성되면 `/review`가 등록하는 리뷰 댓글이 자동으로 중국어·영어 이중 언어로 나갑니다. 관련 PR: [#7564](https://github.com/QwenLM/qwen-code/pull/7564)

**OAuth 로그인 링크 개선.** OAuth 로그인 URL이 OSC 8 하이퍼링크 형식으로 출력되어, 터미널에서 바로 클릭해 이동할 수 있습니다. 관련 PR: [#7255](https://github.com/QwenLM/qwen-code/pull/7255)

**VP 모드 선택 복사 시 시맨틱 텍스트 유지.** VP 모드에서 텍스트를 선택해 복사할 때 렌더링 형식이 아니라 시맨틱 텍스트가 유지됩니다. 관련 PR: [#7286](https://github.com/QwenLM/qwen-code/pull/7286)

## 👏 사용성 개선

**Shift+Enter로 드디어 줄바꿈이 됩니다.** Kitty 프로토콜이 켜지지 않은 Ghostty 같은 터미널에서는 Shift+Enter가 Escape로 오판되어 대화 되돌림 안내가 떴습니다. CSI-u 해석을 바로잡아 Shift/Ctrl/Alt+Enter가 VP 모드와 일반 모드 모두에서 정상적으로 줄바꿈됩니다. 스트리밍 Thinking 블록의 높이 흔들림도 없어졌습니다 — 창은 늘어나기만 하고 줄지 않으며, 터미널 높이를 따라 흔들리지 않습니다. 관련 PR: [#7397](https://github.com/QwenLM/qwen-code/pull/7397)

**큰 붙여넣기도 멈추지 않습니다.** 이전에는 260K 문자를 붙여넣으면 문자마다 keypress 이벤트가 떠서 260K 번 발생하고 약 1.7초 동안 막혔습니다. 이제 stdin 단계에서 bracketed paste 표시를 가로채 한 덩어리로 처리하면서 약 8ms로 떨어졌습니다. 붙여넣는 동안 Footer에 진행 바(`Pasting… ████████░░░░░░░░ 42% (128 KB)`)가 표시되고 Ctrl+C로 중단할 수 있습니다. 관련 PR: [#6506](https://github.com/QwenLM/qwen-code/pull/6506)

**스트리밍 재시도 지연을 설정합니다.** `retryInitialDelayMs`와 `retryMaxDelayMs` 설정이 추가되어, 특정 서비스 제공자의 쿼터 창에 맞춰 SSE 스트리밍 재시도 지연을 조절할 수 있습니다. 관련 PR: [#7674](https://github.com/QwenLM/qwen-code/pull/7674), [#7666](https://github.com/QwenLM/qwen-code/pull/7666)

**TUI 아이콘 열 정렬.** 모든 TUI 아이콘 열 폭을 2문자로 통일해 더 이상 들쭉날쭉하지 않습니다. 관련 PR: [#7633](https://github.com/QwenLM/qwen-code/pull/7633)

**대기열 메시지 표시 수정.** 대기열에 있는 메시지의 표시 형식과 순서를 바로잡아 더 이상 어긋나지 않습니다. 관련 PR: [#7381](https://github.com/QwenLM/qwen-code/pull/7381)

**/copy 명령 수정.** 인덱스만 주는 `/copy`와 `/copy <message> <index>`로 코드 블록을 고르는 방식 모두 정상 동작합니다. 관련 PR: [#7789](https://github.com/QwenLM/qwen-code/pull/7789), [#7883](https://github.com/QwenLM/qwen-code/pull/7883)

**업데이트 확인을 npm view로.** 버전 업데이트 확인을 update-notifier에서 `npm view`로 바꿔 더 신뢰할 수 있습니다. 관련 PR: [#7528](https://github.com/QwenLM/qwen-code/pull/7528)

**IME 커서 정렬.** Footer가 갱신된 뒤에도 입력기 커서가 어긋나지 않습니다. 관련 PR: [#7711](https://github.com/QwenLM/qwen-code/pull/7711)
