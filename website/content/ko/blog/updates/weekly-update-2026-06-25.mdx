Qwen Code는 이번 주 v0.18.4~v0.19.2 다섯 개의 정식 버전을 내놓고(메이저 버전은 v0.19.0으로 올라갔습니다) PR 140개 이상을 병합했습니다. 세 방향을 다뤘습니다:

**음성 입력을 지원해 타이핑할 필요가 없습니다.** 이전에는 모든 입력을 손으로 쳤습니다 — 긴 명령, 복잡한 파라미터, 중영 혼용은 느리고 오타도 많습니다. 이번 주 `/voice` 음성 입력은 마이크에 말하기만 하면 됩니다. 말끝에 fast model이 추임새와 오탈자를 자동으로 정리해, 당신이 보는 시점에는 이미 다듬어진 깨끗한 텍스트입니다. Web Shell도 지원합니다.

**워크플로를 저장하고 재사용할 수 있습니다.** 이전에는 워크플로가 끝나면 사라졌습니다. 다음에는 prompt를 처음부터 다시 써서 손으로 돌려야 했죠. 이번 주 Dynamic Workflows가 마지막 조각을 맞췄습니다: 돌린 뒤 원클릭으로 slash 명령에 저장하면, 다음에는 `/<name>`만 입력해 호출할 수 있고, 같은 session 안에서 이전에 중단된 실행을 resume할 수도 있습니다.

**UI 전면 슬림화.** 이전에는 터미널에서 도구 그룹의 둥근 테두리가 쌓여 상자가 되었고, thinking 블록은 접은 뒤 전용 펼침 키가 없었으며, extension과 MCP server 관리는 설정 파일을 손으로 고쳐야 했습니다. 이번 주 테두리는 사라지고, 완료된 도구는 한 줄로 접히고, Alt+T가 thinking을 전담하고, `/extensions`가 인터랙티브 관리자가 되고, MCP Resources를 탐색하고 `@`로 자동 완성할 수 있습니다.

### 음성 입력: 마이크에 말하기만 하면 됩니다

이전에는 모든 입력을 손으로 쳤습니다. 긴 명령, 복잡한 파라미터, 중영 혼용은 느리고 오타도 많습니다.

이번 주 `/voice` 음성 입력이 새로 생겼습니다. 모드는 두 가지입니다. hold 모드는 Space를 누른 채 말하고 놓는 순간 멈추고, tap 모드는 한 번 눌러 시작하면 다시 누르거나 무음이 되면 자동으로 종료해 제출합니다. 오디오는 네이티브 마이크 백엔드로 잡습니다(`@qwen-code/audio-capture` N-API addon). Linux에서는 arecord/SoX로 자동 fallback하고, macOS에서는 마이크 권한을 자동으로 요청합니다.

전사에는 두 경로가 있습니다. batch 모드(`qwen3-asr-flash`)는 OpenAI 호환 chat/completions + input_audio API를 쓰고, realtime 모드(`qwen3-asr-flash-realtime`, `fun-asr-realtime`)는 WebSocket으로 PCM을 스트리밍하면서 화면에 부분 전사 텍스트를 실시간 표시합니다. 말끝에 fast model이 추임새("um", "어")와 오탈자를 정리합니다 — 원문 표현은 살리고 고쳐 쓰지는 않습니다. 타임아웃이거나 실패하면 원시 전사 텍스트를 그대로 씁니다. 음성 입력은 반드시 텍스트로 나옵니다.

`/model --voice`로 전사 모델을 고르고, `general.voice.{enabled,mode,language}`로 동작을 설정합니다.

**이걸로 할 수 있는 일:**

- `/voice hold`로 Space를 누르고 말하고, 놓으면 전사가 멈춥니다
- `/voice tap`으로 한 번 눌러 시작하고, 한 마디 더하거나 무음이면 멈춥니다
- `/model --voice qwen3-asr-flash-realtime`로 실시간 스트리밍 전사 모델을 선택
- `/voice status`로 현재 음성 설정 확인
- Web Shell에서도 마이크 버튼을 누르면 음성 입력이 됩니다(브라우저에서 녹음, daemon 쪽에서 전사)

### Dynamic Workflows: 워크플로를 돌린 뒤 원클릭 저장, 다음에는 바로 호출

이전에는 워크플로가 끝나면 사라졌습니다. 같은 작업을 다시 하려면 prompt를 처음부터 다시 써서 손으로 트리거해야 했고, 같은 session 안에서 중단된 뒤에는 이어갈 방법도 없었습니다.

이번 주 Dynamic Workflows가 이 구멍을 메웠습니다. 워크플로를 하나 돌린 뒤 `s`를 누르면 스크립트가 `.qwen/workflows/<name>.js`에 저장되고, 저장되는 순간 slash 명령이 됩니다 — 다음에는 `/<name>`만 입력하면 돌고, prompt를 다시 쓸 필요가 없습니다. 저장할 때 project 레벨(현재 프로젝트에서만 사용)이나 user 레벨(모든 프로젝트에서 사용)을 고를 수 있고, 같은 이름의 스크립트가 이미 있으면 덮어쓰기 확인을 띄웁니다.

같은 session 안에서도 이미 돌린 워크플로를 resume할 수 있습니다: `resumeFromRunId`는 JSONL 로그를 재생해 가장 긴 불변 접두어에서 캐시로 이어받고, 첫 번째로 갈리는 지점에서 실행을 계속합니다. 완료된 terminal run은 매번 `<projectDir>/workflows/<runId>.json`에 자동 저장되고, `/workflows` 패널에서 이력을 볼 수 있습니다(재시작해도 남고, 가장 오래된 것부터 자동 정리).

보조 기능도 몇 가지 있습니다. agent stall 워치독(하위 agent가 타임아웃으로 침묵하면 자동 3회 재시도), 중첩 호출(workflow 안에서 `workflow('<name>')`로 다른 workflow를 부름), 입력에 "workflow" 키워드가 있으면 workflow tool로 부드럽게 유도(`ui.disableWorkflowKeywordTrigger`로 끄기), 완료/실패 시 터미널 bell 알림.

**이걸로 할 수 있는 일:**

- 워크플로를 돌린 뒤 `s`를 눌러 `/<name>` slash 명령으로 저장하고, 다음에 바로 호출
- `/workflows` 패널에서 과거 실행 기록 확인, 재시작해도 그대로
- 같은 session 안에서 이전에 중단된 워크플로 resume
- project 레벨 또는 user 레벨로 저장해 공개 범위를 택할 수 있음

관련 PR: [#5600](https://github.com/QwenLM/qwen-code/pull/5600)

### 사용성 전면 개선

이번 주 터미널과 Web Shell UI를 몰아서 슬림화했습니다 — 시각적 소음 정리부터 상호작용 효율, 관리 능력까지 네 덩어리를 한꺼번에 개선했습니다.

**TUI 테두리 제거 + 완료된 도구 접기.** 이전에는 도구 호출마다 둥근 테두리로 쌓여, 여러 도구를 병렬로 돌리면 화면이 상자 더미가 됐습니다. 이번 주 테두리를 전부 없앴고, compact 모드에서 완료된 도구는 한 줄로 접힙니다(상태 아이콘 + 도구명 + 소요 시간). 실행 중이거나 오류난 것만 펼쳐집니다. compact 모드가 아니면 그대로입니다.

**Thinking Alt+T + 전체 화면 뷰어.** 지난주 Thinking은 접을 수 있게 됐지만 전용 펼침 키가 없어 Ctrl+O의 compactMode 전환과 같은 키를 공유해야 했습니다. 이번 주 Alt+T가 모든 thinking 블록의 펼침/접기를 전담합니다. 접힌 thinking 줄을 클릭하면 AlternateScreen 전체 화면으로 펼쳐 볼 수도 있습니다 — 키보드 탐색(↑↓, PgUp/PgDn) + 마우스 휠.

**`/extensions`가 인터랙티브 관리자가 됐습니다.** 이전에는 읽기 전용의 납작한 목록이라 설치나 설정을 하려면 settings를 손으로 고쳐야 했습니다. 이번 주 인터랙티브 다중 탭 관리자로 바뀌었습니다: Installed 탭은 레벨별 그룹화 + 확장 프로그램마다 조작 메뉴(활성화/비활성화/즐겨찾기/scope 변경/업데이트/제거), Discover 탭은 marketplace에서 검색 후 원클릭 설치, Sources 탭은 새 marketplace 추가(GitHub repo, Claude marketplace, npm 패키지, 로컬 경로 지원). CLI에도 `qwen extensions sources add/list/update/remove` 명령군이 생겼습니다.

**MCP Resources 탐색과 `@` 자동 완성.** 이전에는 MCP server의 resources에 발견 수단이 없어서 어떤 데이터를 쓸 수 있는지 알 수 없었습니다. 이번 주 `/mcp` 대화상자에 View resources 조작이 추가돼, resource URI 목록을 열어 세부 사항을 볼 수 있습니다. `@server:`를 입력하면 해당 server의 모든 resource URI가 자동 완성되고, `@`만 입력하면 모든 server의 resources를 검색합니다. prompts도 과도하게 엄격한 capability gating에 걸러지지 않습니다.

**이걸로 할 수 있는 일:**

- compact 모드에서 완료된 도구는 한 줄로 접히고, Alt+T는 thinking만 전담
- `/extensions` 관리자를 열어 확장 프로그램을 검색 설치, 설정, 제거
- `/mcp` → View resources로 MCP server 데이터를 탐색하고, `@server:`로 resource 자동 완성
- `/extensions`의 Sources 탭에서 Claude marketplace나 GitHub repo 추가

### Artifact: 모델이 인터랙티브 웹 페이지를 만들어 줍니다

이전에는 모델에 아키텍처 다이어그램을 그려 달거나 인터랙티브 대시보드를 만들어 달하면 터미널에 텍스트와 표로만 출력했습니다. 눈에 보이는 것은 정리된 글자 덩어리이지 진짜 그래프가 아니라서 클릭도 드래그도 안 됐습니다.

이번 주 Artifact 도구가 새로 생겼습니다(실험적, 수동 활성화). 켜면 모델이 만든 내용을 웹 페이지로 바로 열 수 있습니다 — 아키텍처 다이어그램은 노드를 클릭해 세부 사항을 펼치고, 데이터 표는 정렬과 필터가 되고, 코드 walkthrough는 링크로 이동합니다. 디자이너에게 프로토타입을 맡기고 브라우저를 열었을 때의 그 느낌입니다.

모든 내용은 로컬 파일로 씁니다(`~/.qwen/artifacts/`). 여는 주소는 `file://`이고 네트워크로 나가지 않습니다. 같은 파일에 다시 돌리면 이전 버전을 덮어쓰고, 다른 파일이면 새 페이지를 만듭니다. 모델이 만든 내용은 완전히 자기 완결적이어야 합니다 — 외부 CSS나 JS를 참조할 수 없어 통제 밖의 자산 로딩을 막습니다. 페이지 하나당 최대 16 MB입니다.

켜는 방법: settings에 `experimental.artifact`를 설정하거나, 환경변수 `QWEN_CODE_ENABLE_ARTIFACT=1`을 지정합니다. non-interactive와 SDK 모드에서는 기본 사용 불가입니다.

**이걸로 할 수 있는 일:**

- 모델에 인터랙티브 아키텍처 다이어그램을 만들게 하고, 노드를 클릭해 세부 사항 확인
- 데이터 대시보드를 만들어 정렬과 필터를 직접 조작
- 코드 walkthrough 페이지를 만들어 클릭해 이동
- settings에서 `experimental.artifact`를 켜거나 `QWEN_CODE_ENABLE_ARTIFACT=1` 설정

### Vision Bridge: 텍스트 전용 모델도 이미지를 봅니다

이전에는 텍스트 전용 모델(예: DeepSeek V4)을 쓰면 `@`로 이미지를 참조해도 'unsupported-image' 안내로 바뀌어, 모델은 이미지 내용을 하나도 보지 못했습니다.

이번 주 Vision Bridge 자동 호환 경로가 새로 생겼습니다. 사용자가 `@`로 이미지를 참조하고, primary 모델이 텍스트 전용으로 알려져 있고, 같은 provider에 이미지를 처리하는 모델이 있으면, Qwen Code가 vision 모델을 빌려 이미지 내용을 텍스트로 전사한 뒤 그 텍스트를 primary 모델에 보냅니다. 사용자 설정이 필요 없습니다 — 조건이 전부 맞아떨어지면 자동 발동합니다: primary가 텍스트 전용 + 같은 provider에 vision 모델 있음 + 사용자 turn에 image parts 포함. primary가 이미 이미지를 지원하면 bridge를 타지 않고 바로 보냅니다. primary의 modalities가 알려지지 않았거나 같은 provider에 쓸 만한 vision 모델이 없으면 bridge는 발동하지 않고 기존 동작을 유지합니다.

Bridge는 같은 provider 안에서만 모델을 빌립니다 — provider를 넘어 라우팅하지 않고, 자격 증명을 제3자에게 새지 않습니다.

**이걸로 할 수 있는 일:**

- DeepSeek V4 같은 텍스트 전용 모델에서 `@`로 스크린샷을 참조하면 자동으로 텍스트 설명으로 전사됩니다
- 설정이 전혀 필요 없습니다 — 자동 감지 조건이 맞아떨어지면 발동
- 같은 provider 안에서만 vision 모델을 빌리므로 provider를 넘지 않습니다

### /stats: 소모한 token이 한눈에

이전에는 token을 얼마나 썼고 얼마가 들었는지 감으로만 알 수 있었습니다. 오래 작업하면 자기도 모르게 수만 token을 태울 때가 있는데, `/stats`는 session 단위 통계만 보여 줘서 일별, 월별, 모델별 분해를 볼 수 없었습니다.

이번 주 `/stats`에 영속화 token 회계가 추가됐습니다. `/stats daily`는 오늘 하루의 총 token, 요청 수, input/output/cached/thought 분해를 모델과 auth type별로 그룹 지어 보여 주고, `/stats monthly`는 한 달 전체 집계를 보여 줍니다. `/stats export daily YYYY-MM-DD --format csv`나 `/stats export monthly YYYY-MM --format json --output <path>`로 파일을 내보낼 수도 있습니다. 내보내는 데이터는 집계만 포함하고 prompt/response 텍스트나 프로젝트 경로는 넣지 않습니다. 내보내기 경로는 프로젝트 작업 디렉터리 안으로 제한되고, 경로 순회와 심볼릭 링크, Windows alternate-data-stream 경로는 거부됩니다.

데이터는 `~/.qwen/stats/` 디렉터리에 영속화돼 재시작해도 그대로입니다.

**이걸로 할 수 있는 일:**

- `/stats daily`로 오늘 token을 얼마나 썼는지, 모델별로 확인
- `/stats monthly`로 한 달 소비 집계 확인
- `/stats export`로 CSV/JSON 내보내기 — 집계만 있고 개인정보는 없음
- 재시작 후에도 데이터가 남아 있음
