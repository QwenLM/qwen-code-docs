Qwen Code는 이번 주에 v0.19.6부터 v0.19.8까지 3개의 정식 버전을 출시하고 PR 150개 이상을 병합했습니다. 방향은 네 가지입니다.

**모델이 과부하돼도 대화가 끊기지 않습니다.** 이전에는 429/503/529를 만나면 대화가 그대로 중단돼서, 모델을 직접 바꿔 다시 보내야 했습니다. 이제 fallback 체인이 주 모델의 재시도 예산이 다 쓰이면 순서상 다음 모델로 자동 전환해 답변을 이어갑니다. `/model --project`로 프로젝트마다 다른 모델을 묶어 두면 손으로 바꿀 일이 아예 없습니다.

**서브 Agent가 이제 하위를 파생합니다.** 이전까지 서브 Agent는 마지막 가지였습니다. 받은 일을 자기 손으로 끝내야 했고, 더 나눌 방법이 없었습니다. 지금은 기본 중첩 깊이가 5단계라 서브 Agent가 서브 태스크를 아래 층으로 넘길 수 있습니다. TUI와 Web Shell 모두 트리 구조로 보여주니 누가 누구를 파생했는지 바로 보입니다.

**Web Shell 세션 관리가 체계를 갖췄습니다.** 아카이브/삭제/이름 붙인 그룹/색상 라벨/예약 작업 관리 페이지/세션 요약 분할 화면까지, 이전에는 세션 사이드바에서 세션을 바꿔 보는 것만 가능했습니다. 지금은 정리하고, 분류하고, 감시하고, 병렬로 다룰 수 있습니다. PR 7개로 세션을 단순 나열 목록에서 관리 가능한 자원으로 바꿨습니다.

**WeCom과 권한 제어가 채워졌습니다.** WeCom 스마트 봇 채널을 연동했습니다. Bot ID와 Secret 두 항목이면 끝나고, 기업 관리자 권한으로 콜백을 열 필요도 없습니다. PreToolUse hook의 "ask"는 이제 실제로 확인창을 띄웁니다. 이전에는 이 선택지가 조용히 거부하는 것과 같았습니다. 권한 규칙도 `Tool(param:value)` 문법을 지원해 파라미터 값 단위로 제어할 수 있습니다.

## ✨ 새로운 기능

### 모델 과부하 자동 전환 + 프로젝트별 모델 설정

모델이 429/503/529를 반환하면 대화가 그 자리에서 멈춥니다. 이번 버전에는 직접 켜는 방식의 fallback 체인이 들어갔습니다. 주 모델이 같은 모델에서 재시도 예산을 모두 쓰면 fallback 목록의 다음 모델로 넘어가 답변을 이어갑니다. fallback을 타는 원인은 용량과 속도 제한뿐입니다. 인증, 쿼터, 설정, 클라이언트 오류는 바로 실패로 돌려보냅니다. 모델이 과부하인 경우가 아니라 설정이 잘못된 경우이기 때문입니다.

전환은 사용자에게 내용이 보이기 전에 일어납니다. fallback 모델이 일부를 출력한 뒤 죽으면 남은 목록은 시도하지 않으니, 잘린 답변만 보입니다. 그래도 다음 사용자 turn은 다시 주 모델부터 시작하므로 fallback 모델에 붙박이로 남지 않습니다.

`/model --project`를 쓰면 프로젝트마다 다른 모델을 묶어 둘 수 있습니다. `--project`는 프로젝트의 `.qwen/settings.json`에, `--global`은 사용자 `~/.qwen/settings.json`에 기록됩니다. 플래그를 붙이지 않으면 기존 동작 그대로입니다. 이 범위 지정 플래그는 `--fast`, `--voice`, `--vision`에도 함께 쓸 수 있습니다.

이렇게 쓸 수 있습니다:

- fallback 모델 목록을 정해 두면 모델이 과부하일 때 자동 전환되므로 직접 모델을 갈아탈 필요가 없습니다
- 인증/쿼터 오류는 fallback에 가려지지 않아 문제가 더 일찍 드러납니다
- `/model --project`로 프로젝트마다 다른 모델을 쓰면 설정이 프로젝트를 따라다닙니다
- `/model --global`로 전역 기본값을 정해 두면 새 프로젝트가 이어받습니다

관련 PR: [#6273](https://github.com/QwenLM/qwen-code/pull/6273), [#6060](https://github.com/QwenLM/qwen-code/pull/6060)

### 서브 Agent 중첩 파생 + 트리 뷰

이제 서브 Agent가 자기 밑의 서브 Agent를 다시 파생할 수 있습니다. 기본 깊이 상한은 5단계이고 `model.maxSubagentDepth`로 조정합니다. 1로 두면 서브 Agent가 하위를 만들지 못하는 예전 동작으로 돌아갑니다.

방어선은 두 겹입니다. 스키마를 준비할 때 가장 깊은 단계의 서브 Agent는 agent 도구 자체를 보지 못합니다. 쓸 수 있다는 사실도 모릅니다. 여기에 런타임 가드가 있어 깊이 상한을 넘는 파생 요청은 거부됩니다.

TUI와 Web Shell 모두 중첩 트리 구조를 보여줍니다. 서브 Agent는 부모 아래에 ↳ 표시와 들여쓰기로 놓입니다. 부모가 끝나면 서브 Agent는 루트 노드로 올라가고 "from \<parent\>"라고 표시됩니다. 상세 뷰에는 "Level N · from \<parent type\>"이 나옵니다. blocking 태그와 중지 확인도 파생 경로를 따르게 바뀌어, 취소를 해도 turn이 끝나는 경우가 아니라면 확인창이 뜨지 않습니다.

**이 기능은 기본적으로 켜져 있습니다.** 업그레이드하면 기존 모든 환경에 중첩 파생이 적용됩니다. Fork 하위 프로세스, teammates, workflow agents은 여전히 제외됩니다. Arena 세션도 이제 중첩할 수 있습니다. 백그라운드 agent는 복구할 때 원래 깊이와 시작 당시 상한을 함께 되찾습니다.

이렇게 쓸 수 있습니다:

- 서브 Agent가 복잡한 일을 받으면 스스로 하위를 파생해 서브 태스크를 나눕니다
- TUI와 Web Shell에서 전체 Agent 트리 구조를 볼 수 있습니다
- `model.maxSubagentDepth`로 중첩 깊이 상한을 조정합니다

관련 PR: [#6189](https://github.com/QwenLM/qwen-code/pull/6189), [#6239](https://github.com/QwenLM/qwen-code/pull/6239)

### Web Shell 세션 관리: 아카이브, 그룹, 예약 작업, 분할 화면

PR 7개로 Web Shell의 세션 사이드바를 그저 나열만 되던 목록에서 정리·분류·감시·병렬 작업이 가능한 관리 패널로 바꿨습니다.

**아카이브와 삭제.** 세션 행마다 바로 실행 버튼과 "…" 메뉴(이름 변경/아카이브/삭제)가 생겼습니다. 아카이브한 세션은 접히는 "Archived" 영역으로 모이고, 여기서 복원하거나 완전히 삭제할 수 있습니다. 지금 사용 중인 세션은 아카이브도 삭제도 되지 않습니다. 아카이브된 세션은 열 수 없고 409 `session_archived`가 돌아옵니다. 삭제는 되돌릴 수 없는 완전 삭제이며 확인 단계를 한 번 더 거칩니다. 동작은 daemon의 `archiveState`와 `/sessions/archive`, `/sessions/unarchive` 엔드포인트로 처리됩니다.

**이름 붙인 그룹과 색상 라벨.** 그룹을 만들고 이름을 바꾸거나 지울 수 있고, 세션을 끌어다 넣을 수 있으며, 그룹에 색상 라벨과 상단 고정/아카이브 상태를 붙일 수 있습니다. 그룹 데이터는 daemon 계층에서 UI까지 그대로 이어집니다. daemon 쪽에서는 프로젝트 단위 sidecar 파일에 그룹 메타데이터를 저장하고, REST/ACP 라우트가 CRUD를 제공하며, capability gate 아래에서 클라이언트 지원 여부에 따라 노출 범위를 정합니다.

**세션 요약과 분할 화면.** 넓은 화면에서는 사이드바에 세션 요약 패널이 나타납니다. 모든 세션이 실시간 카드로 보이고 순서는 승인 대기 → 실행 중 → 유휴입니다. 카드마다 현재 모델과 클라이언트 수가 표시됩니다. 여럿 고르면 분할 화면으로 열 수 있습니다. 같은 탭 안에서 나누거나 새 브라우저 탭에 여는 방식(`?split=a,b` URL 파라미터)입니다. 독립 채팅 패널 N개가 나란히 열리고 각각 세션 컨텍스트를 따로 가지며, 키보드 포커스는 클릭한 패널에만 걸립니다.

이렇게 쓸 수 있습니다:

- 오래 쌓인 세션을 아카이브로 정리하고 프로젝트별로 그룹 지어 색상 라벨을 붙입니다
- 예약 작업을 화면에서 직접 만들고 관리합니다. cron 표현식을 손으로 적지 않아도 됩니다
- 예약 작업마다 독립 세션이 생기고, 실행 이력과 트랜스크립트를 언제든 볼 수 있습니다
- 넓은 화면에서 여러 세션의 실시간 상태를 분할 화면으로 나란히 확인합니다

### WeCom 채널 연동

`@wecom/aibot-node-sdk`로 WeCom 스마트 봇을 연결했습니다. 설정은 Bot ID와 Secret 두 개면 됩니다. Corp ID, Agent ID, 콜백 Token, EncodingAESKey가 필요 없고, 공개 네트워크 콜백 주소도 필요 없습니다.

메시지는 WebSocket 상시 연결로 받습니다. 텍스트, 음성 전사, 텍스트+이미지 혼합, 이미지, 파일, 영상, 인용 콘텐츠를 모두 지원합니다. 어시스턴트 답변은 WeCom markdown 형식으로 전송됩니다. 발송 쪽은 로컬 이미지 태그(채널 임시 디렉터리 안)만 지원하고, 파일/영상/음성 태그는 무시됩니다.

설정 방법:

```json
{
  "type": "wecom",
  "botId": "your-bot-id",
  "secret": "your-secret",
  "cwd": "/path/to/project"
}
```

실행 명령: `qwen channel start my-wecom`

이렇게 쓸 수 있습니다:

- Bot ID + Secret 두 항목으로 WeCom을 연결합니다. 기업 관리자 권한이 필요 없습니다
- 텍스트, 음성, 이미지, 파일, 영상, 인용 메시지를 받습니다
- WeCom 그룹 채팅에서 Qwen Code가 markdown 형식으로 답하게 합니다

관련 PR: [#6436](https://github.com/QwenLM/qwen-code/pull/6436)

### PreToolUse hook에 네이티브 확인창

이전에는 PreToolUse hook이 `permissionDecision: "ask"`를 돌려주면 "deny"와 같았습니다. 확인창은 아예 뜨지 않았습니다. hook 개발자는 사용자가 선택지를 보길 기대했지만, 실제로는 조용히 거부되고 있었습니다.

이제 "ask"는 TUI 네이티브 확인창을 띄웁니다. 선택지는 "Yes, allow once"와 "No, suggest changes" 두 개입니다. hook이 호출마다 다시 판단하기 때문에 "always allow"는 없습니다. 승인하면 도구가 다시 실행되고, 거부하면 취소됩니다.

비대화형 CLI와 백그라운드 agent에서는 "ask"가 deny로 처리되어 응답을 기다리면서 멈추지 않습니다. 기존 awaiting_approval 메커니즘을 그대로 써서 경로를 하나 더 만들지 않았습니다. "denied"와 "stop" 동작은 그대로이고 PermissionRequest hook도 영향받지 않습니다.

이렇게 쓸 수 있습니다:

- PreToolUse hook에서 "ask"를 써서 도구 실행 여부를 사용자가 결정하게 합니다
- 비대화형 환경에서 기다림에 묶일 걱정이 없습니다
- hook이 호출마다 다시 판단해 영구적으로 통과시키지 않습니다

관련 PR: [#5629](https://github.com/QwenLM/qwen-code/pull/5629)

### 자동 생성 Skills 미리보기 검토

agent가 skill을 자동 생성하면 예전에는 파일 이름만 보이고, 승인한 뒤에야 내용을 알 수 있었습니다. 이제는 검토 대화창 안에서 frontmatter까지 전문을 미리봅니다.

모델이 만든 내용은 걸러서 보여줍니다. ANSI/VT 제어 순서대는 무해한 이스케이프로 바꾸고, CRLF는 일반 줄바꿈으로 바꿉니다. 읽기 상한은 64 KiB, 표시 상한은 12줄(자동 줄바꿈까지 계산)이며, 넘치는 부분은 "lines hidden" / "truncated"로 표시합니다.

`o`를 누르면 설정해 둔 편집기에서 skill 파일이 열립니다. 지금 보고 있는 skill 검토는 건너뛰지 않습니다. 파일을 저장하면 미리보기가 자동 갱신되니 GUI 편집기(macOS 기본 동작)와 함께 쓰면 고쳐 본 뒤 결정할 수 있습니다.

"Turn off auto-generated skills" 항목은 목록 마지막에 있습니다. 고르면 재시작 없이 즉시 적용되고, 워크스페이스 단위로 저장됩니다. 지금 배치는 삭제하지 않고 잠시 접어 두며, `/memory`에서 다시 켜면 배치가 돌아옵니다.

이렇게 쓸 수 있습니다:

- 승인하기 전에 skill 전문을 봅니다. 일단 받아들인 뒤 파일을 뒤져 보는 수고가 없습니다
- `o`를 눌러 편집기에서 skill 내용을 바로 고치고, 저장하면 미리보기가 갱신됩니다
- 자동 생성 skills을 한 번에 끌 수 있고, 지금 배치는 삭제되지 않으니 `/memory`에서 언제든 되돌립니다
