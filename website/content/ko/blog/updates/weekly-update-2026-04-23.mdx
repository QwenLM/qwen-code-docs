이번 주에 **v0.15.0**을 릴리스했습니다.

이번 업데이트는 네 가지에 집중했습니다. AI가 세션을 넘어 스스로 기억하고 지난 기억은 정리합니다. 세션 목록이 제목을 자동 생성하고, 이름 바꾸기나 삭제도 지원합니다. `/batch` 명령어 하나로 여러 파일 수정을 동시에 끝낼 수 있습니다. Hook 시스템 확장과 subagent 백그라운드 실행으로 자동화와 사내 연동이 더 자유로워졌습니다.

## ✨ 새로운 기능

### AI의 세션 간 능동 기억

이전에는 기억 기능을 손으로 계속 관리해야 했습니다. 이제 Qwen Code에 자동 기억(auto-memory)과 자동 정리(auto-dream) 시스템이 들어왔습니다. AI가 대화 중에 중요한 정보를 기억으로 뽑아 내고, 주기적으로 갈고닦아 세션을 넘어 이어지는 경험이 매끄러워집니다.

**이렇게 쓸 수 있습니다:**

- 다시 말해 주지 않아도 됩니다 — 한번 말한 기술 스택, 코드 스타일, 프로젝트 구조를 새 세션에서 AI가 저절로 기억합니다
- 자동 정리와 병합 — 백그라운드에서 기억을 훑어 중복 항목을 합치고 지난 기억을 갱신하며 인덱스를 정기 보수합니다. 책장을 정기적으로 정리하는 것과 같습니다
- 손 관리 비용이 줄어듭니다 — 전에 QWEN.md나 규칙 파일에 직접 적어 넣던 내용을 이제 AI가 알아서 처리합니다

### 세션 제목 자동 생성, 이름 바꾸기와 삭제 지원

이전에는 세션 제목이 사용자의 첫 질문 그대로였습니다. 길어서 찾기조차 어려웠죠. 이제 AI가 대화 내용을 보고 제목을 자동 지어 주고, 원하면 언제든 제목을 직접 고치거나 필요 없는 세션을 지울 수 있습니다.

**이렇게 쓸 수 있습니다:**

- AI가 제목을 자동 생성 — 직접 짓지 않아도 대화 내용을 보고 세션 제목을 만듭니다
- 프로젝트별로 세션 이름 변경 — AI가 지은 제목이 영 마땅치 않으면 언제든 손으로 고침
- 무의미한 세션 정리 — 테스트하거나 내용 없는 대화를 지워 목록에 쓸모있는 것만 남김

### /batch로 여러 파일 한꺼번에 처리

이전에는 여러 파일을 고치려면 작업을 하나씩 돌려야 했습니다. 이제는 `/batch` 명령어 하나로 동시에 병렬 처리합니다. 같은 종류의 문제를 일괄 수정하거나, 여러 문서를 함께 갱신하거나, 코드를 리팩터링할 때 잘 맞습니다.

**이렇게 쓸 수 있습니다:**

- 같은 종류 문제 일괄 수정 — 여러 파일에 퍼진 동일한 lint 오류를 하나씩 하지 않고 한 번에 처리
- 여러 문서 동시 갱신 — 문서 여러 개에 같은 장을 추가하거나 버전 번호를 고칠 때 명령 한 번
- 코드 리팩터링 일괄 실행 — 여러 파일의 변수 이름 변경·함수 추출을 한꺼번에 병렬로 완료

### Hook 확장: AI가 일하는 김에 추가 동작까지

이전에는 Qwen Code가 시킨 작업 하나만 실행했습니다. 이제는 Hook으로 '자동 실행 동작'을 붙일 수 있습니다. Hook 사용법 세 가지가 새로 추가됐습니다. HTTP Hook으로 외부 서비스(Feishu, DingTalk 같은)에 알림을 자동 발송, Function Hook으로 코드 조각을 자동 실행, 시간이 오래 걸리는 작업은 Async Hook을 태워 백그라운드에서 돌리면 현재 대화가 막히지 않습니다. VSCode 플러그인에서도 이 Hook들을 설정할 수 있게 됐습니다.

**이렇게 쓸 수 있습니다:**

- 팀 알림 — AI가 핵심 파일을 고치면 Feishu나 DingTalk에 자동으로 메시지가 나가니 동료를 일일이 @ 하지 않아도 됩니다
- 사내 컴플라이언스 감사 — AI가 뭘 할 때마다 회사 감사 시스템에 자동 기록돼, 수기 등록 없이 규정 요구를 맞춥니다
- 자체 도구 심층 연동 — SDK로 직접 등록한 코드를 대화 중 이벤트에 자동 실행할 수 있어, 새 창에서 손으로 돌릴 필요가 없습니다

### subagent 백그라운드 실행

이전에는 subagent가 반드시 전면 화면에서 돌아갔습니다. 이제 백그라운드 headless 실행을 지원하고, SDK도 완전히 지원해 CI/CD 파이프라인과 자동화 스크립트에 넣기 좋습니다.

**이렇게 쓸 수 있습니다:**

- 백그라운드 병렬 처리 — subagent 여러 개를 동시에 돌려 서로 다른 작업을 처리시키고, 메인 화면은 건드리지 않고 계속 일할 수 있음
- SDK로 자체 도구 연동 — SDK API로 subagent 기능을 호출해 개발 도구 체인에 직접 삽입
- CI/CD 자동 리뷰 — PR 파이프라인에서 subagent를 띄워 코드를 자동 검토. 터미널 화면을 열 필요가 없습니다

### 디렉터리마다 다른 규칙 자동 적용

이전에는 모든 디렉터리가 규칙 하나를 공유했습니다. 이제는 파일 경로에 맞춰 특정 컨텍스트 규칙을 자동 주입합니다. `.qwen/rules/` 디렉터리에서 읽어 오니, 디렉터리별로 AI 행동이 더 정밀해집니다.

**이렇게 쓸 수 있습니다:**

- 모듈마다 다른 규범 — 프론트엔드 디렉터리는 React 규범, 백엔드 디렉터리는 Node.js 규범을 자동 인식
- 프로젝트 맞춤 규칙 — 하위 디렉터리별 특수 코드 스타일 요구사항을 `.qwen/rules/`에 넣으면 자동 적용
- 수동 설정 감소 — 대화마다 규칙을 지정하지 않아도 경로가 맞으면 저절로 적용

### /doctor로 환경 문제 원터치 점검

이전에는 문제가 생기면 설정과 환경을 하나씩 손으로 확인해야 했습니다. 이제는 `/doctor`만 돌리면 환경, 설정, 네트워크 등 흔한 문제를 자동 진단하고 수정 제안까지 알려 줍니다.

**이렇게 쓸 수 있습니다:**

- 환경 문제 빠른 진단 — MCP 서버 연결 실패, 모델 로드 실패 같은 걸 원터치로 검사
- 설정 정상 여부 확인 — 설정 파일 문법과 API Key 유효성을 자동 검증
- 자동화에 친화적 — 비대화 JSON 출력을 지원해 스크립트나 CI/CD 흐름에 넣기 좋음

### PDF 바로 읽기와 Jupyter Notebook 분석

이전에는 텍스트 모델이 PDF를 만나면 바로 에러를 냈습니다. 이제는 시스템 도구를 자동 호출해 순수 텍스트로 추출하고, 페이지 범위 지정 읽기까지 지원합니다. Jupyter Notebook 파일도 원본 JSON을 그대로 던져 주지 않고, 셀 단위로 코드와 출력 결과를 구조화해 보여 줍니다.

**이렇게 쓸 수 있습니다:**

- PDF 문서 분석 — AI가 PDF 보고서, 논문, 기술 문서를 직접 읽으니 텍스트로 변환할 필요 없음
- 페이지 지정 정독 — 불러올 페이지 범위를 정할 수 있어, 큰 파일 전체를 로드하지 않아도 됨
- Notebook 검토 — `.ipynb` 파일을 AI가 분석해 코드와 출력이 질서 정연하게 보입니다. 중첩 JSON 더미가 아닙니다
