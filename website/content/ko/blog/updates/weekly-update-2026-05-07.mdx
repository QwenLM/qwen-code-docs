이번 주에 주요 기능 버전 v0.15.7과 후속 버전 6개(v0.15.1–v0.15.6)를 릴리스했습니다.

DeepSeek V4는 이번 주 AI 커뮤니티에서 가장 뜨거운 주제 중 하나였습니다. HN에서 antirez의 로컬 추론 엔진 이야기부터 각 회사의 발 빠른 지원까지, 저희도 즉시 전체 대응을 끝냈습니다. 1M 컨텍스트 창, 384K 출력 상한, reasoning effort의 "max" 등급을 지원하고, thinking blocks 호환 문제까지 수정했습니다.

Agent 멀티태스킹은 업계 전반의 방향입니다 (OpenAI Codex, Google AlphaEvolve 모두 이쪽으로 가고 있습니다). 백그라운드 Agent 시스템을 기반 코드부터 완성된 작업 패널까지 올렸습니다. 백그라운드 작업은 한곳에서 상태를 확인하고 언제든 취소할 수 있고, 중단되면 자동 일시정지했다가 이어서 복구할 수도 있습니다. GitHub에서 Agent PR 검토 가이드가 나온 직후라, `qwen review`에도 하위 명령어와 agent를 여럿 추가해 터미널에서 바로 코드 검토를 끝낼 수 있게 했습니다.

여기에 대화 상호작용과 효율도 계속 다듬었습니다. 대화가 딴길로 새면 Esc를 두 번 눌러 예전 라운드로 돌아가 다시 시작할 수 있고, 긴 작업이 끝나거나 권한 확인이 필요하면 터미널과 VS Code가 먼저 알려 줍니다. `/stats`는 가격을 설정해 두면 비용을 바로 추정하고, 모델 전환도 더 단순해졌습니다.

## ✨ 새로운 기능

### DeepSeek V4 심층 지원

DeepSeek V4가 공개되자마자 Qwen Code가 바로 전체 대응을 마쳤습니다. 컨텍스트 창은 1M, 출력 상한은 384K입니다. Agent가 대형 코드 저장소를 한 번에 읽고 아주 긴 출력까지 만들어 낼 수 있다는 뜻입니다. reasoning effort의 "max" 등급도 지원해 DeepSeek이 복잡한 추론 작업에 모든 힘을 쓰게 할 수 있습니다. thinking blocks 관련 호환 문제 여러 개도 함께 고쳐, 어떤 사용 환경에서든 DeepSeek의 사고 과정이 끝까지 표시됩니다.

**이렇게 쓸 수 있습니다:**

- DeepSeek V4로 초대형 파일과 저장소 전체를 다룹니다. 1M 컨텍스트라 잘릴까 걱정하지 않습니다
- reasoning effort를 "max"로 설정해 복잡한 아키텍처 설계나 긴 사슬 추론에 온 힘을 다하게 함
- 세션 복구, 대화 되돌리기, 컨텍스트 압축을 해도 DeepSeek의 추론 사슬이 그대로 보존됨
- anthropic 호환 모드에서도 thinking blocks가 제대로 주입돼, 서드파티 배포(sglang/vllm) 환경에서 정상 사용 가능

### 백그라운드 작업 한곳에서 보고, 취소하고, 복구하기

이전에는 백그라운드 shell 명령이 시스템에 의해 뒤로 밀려 나면, 아직 도는지, 출력은 어디 있는지, 어떻게 멈추는지 알기 어려웠습니다. 이제는 background agent와 백그라운드 shell이 모두 하나의 백그라운드 작업 화면에 모입니다. 상태, 출력, 상세를 한곳에서 확인하고, 작업이 중단되면 자동으로 일시정지되니 복구하거나 취소하면 됩니다.

**이렇게 쓸 수 있습니다:**

- 긴 작업을 돌려도 대화가 안 멈춤: `npm run dev`, 테스트, 파일 감시 같은 명령은 백그라운드로 돌리고 현재 대화는 계속 진행
- 작업 상태를 언제든 보고 제어: `/tasks`나 작업 패널에서 백그라운드 shell, background agent의 실행 상태와 출력 경로를 확인하고, 돌고 있는 작업을 취소할 수도 있음
- 중단된 작업도 안전하게 복구: 백그라운드 작업이 뜻밖에 멈춰도 사라지지 않으니 이어서 복구하거나 그만두면 됩니다

### 이전 라운드로 되돌려 다시 시작하는 대화

이전에는 대화 방향이 어긋나면 계속 고쳐 가거나 새 세션을 여는 수밖에 없었습니다. 이제는 `Esc`를 두 번 누르거나 `/rewind`를 실행해 앞선 사용자 라운드를 고르면, 대화 기록을 그 시점으로 되돌리고 원래 질문에서 다시 이어갈 수 있습니다.

**이렇게 쓸 수 있습니다:**

- 잘못된 방향 되감기: AI가 새고 나면 핵심 질문으로 돌아가 요구를 바꿔 다시 실행
- 컨텍스트를 유지한 채 재도전: 새 세션을 열 필요도, 앞선 배경 정보를 복사해 붙일 필요도 없음
- 탐색형 개발에 더 잘 맞음: 구현 방안을 여러 개 시도할 때 갈라진 지점으로 돌아가 다시 밀 수 있음

### `/review` 코드 검토 흐름 업그레이드

`/review`를 이번 주에 통째로 손봤습니다. agent를 5개에서 9개로 늘리고, prompt 여기저기 흩어져 있던 검토 단계를 6개 크로스플랫폼 CLI 하위 명령어로 정리했으며, 출력도 구조화된 JSON으로 바꿨습니다. 사용자는 `/review <PR 링크 또는 번호>`만 입력하면 됩니다. AI가 코드 가져오기, 프로젝트 규칙 로드, lint 실행, 9개 역할 병렬 검토, 자동 중복 제거, CI 상태 확인, 인라인 댓글 게시까지 전부 처리합니다.

**이렇게 쓸 수 있습니다:**

- PR 원터치 검토: `/review https://github.com/xxx/pull/123`을 입력하면 코드 가져오기부터 댓글 작성까지 자동 완료
- 9개 역할 동시 검토: 정확성과 보안 외에 '공격자, 심야 온콜, 유지보수자' 같은 관점을 추가해 사각지대를 남기지 않음
- CI 통과 못 하면 approve하지 않음: CI 상태와 본인 PR 여부를 자동 감지해, 통과하지 못하면 자동으로 comment로 격하
- 애매한 제안은 PR에 남기지 않음: 신뢰도가 낮은 문제는 터미널에만 표시하고 PR에는 댓글을 달지 않음
- 기존 댓글 자동 중복 제거: 이미 있는 Qwen 댓글을 알아보고 같은 제안을 반복 게시하지 않음

### 작업 끝나거나 확인 필요할 때 먼저 알려 줍니다

이전에는 터미널 알림이 눈에 잘 안 띄는 terminal bell에 주로 의존했고, VS Code 플러그인에는 눈에 띄는 상태 표시가 부족했습니다. 이제는 iTerm2, Kitty, Ghostty 터미널에서 작업이 끝나면 데스크톱 알림이 자동으로 뜨고, VS Code도 탭의 점, 알림 버블, 소리로 알려 줍니다.

**이렇게 쓸 수 있습니다:**

- 긴 작업을 계속 지켜보지 않아도 됨: 다른 일을 하다가도 작업이 끝나면 시스템이 알림과 소리로 불러 줍니다
- 권한 확인을 제때 캐치: AI가 도구 호출 승인이나 질문 답변을 기다릴 때 훨씬 눈에 잘 띕니다
- VS Code에서 탭 여러 개 써도 놓치지 않음: 다른 파일로 옮겨 가도 채팅 탭에 상태 표시가 남습니다

### `/stats`에 모델 비용 추정 표시

`/stats` 명령어에 비용 추정이 추가됐습니다. `settings.json`에 `modelPricing`만 설정하면 (모델별 입력/출력 100만 Token 가격을 적어 두면), `/stats`가 Token 사용량을 보고 대략적인 비용을 자동 계산합니다. 직접 계산할 필요가 없습니다. 설정하지 않으면 이전처럼 Token 수만 표시됩니다.

**이렇게 쓸 수 있습니다:**

- 자주 쓰는 모델 가격 등록: `settings.json`에 가격을 한 번 적어 두면 이후 `/stats`가 알아서 계산
- 모델별 지출 비교: 모델을 바꿔 가며 비용 차이를 봐서 가성비 좋은 조합을 찾음
- 장기 실행 비용 통제: 자동화 흐름에서 비용을 주기 점검해 초과를 방지

### `/model` 빠른 모델 전환

이전에는 모델을 바꾸려면 `/model`로 선택기를 연 뒤 목록을 뒤져야 했습니다. 이제는 `/model 모델명`을 바로 치면 전환됩니다.

**이렇게 쓸 수 있습니다:**

- 선택기를 뒤지지 않음: `/model qwen3.6-plus`처럼 모델명을 입력하면 바로 전환 — 목록 탐색이 사라짐
- 모델 비교가 빨라짐: `/model A`로 한 번 묻고 `/model B`로 다시 물어, 여러 모델의 응답을 견줌
- 최신 모델을 즉시 사용: base URL만 설정돼 로컬에 등록되지 않은 모델로도 바로 전환 가능

## 📊 최적화 및 개선

- **OpenRouter 연결을 브라우저 원터치 승인 방식으로**: 이전에는 API Key와 모델 목록을 손으로 설정해야 했습니다. 이제는 `/auth` 브라우저 승인 흐름을 타서 Key가 자동 저장되고 모델 디렉터리도 가져옵니다. `/manage-models`가 새로 추가돼 검색, 필터, 모델 활성화할 수 있습니다 ([#3576](https://github.com/QwenLM/qwen-code/pull/3576))
- **Todo 목록 상시 고정**: 최신 작업 목록이 입력창 위에 고정되고 상태가 바뀌면 함께 갱신됩니다. 진행 상황을 확인한다고 기록을 위로 스크롤하지 않아도 됩니다 ([#3507](https://github.com/QwenLM/qwen-code/pull/3507), [#3647](https://github.com/QwenLM/qwen-code/pull/3647))
- **파일 읽기가 빨라지고 중복도 없음**: 파일 읽기 캐시(FileReadCache)가 추가돼 같은 내용을 다시 읽지 않습니다. 멀티 라운드 대화와 도구 호출의 응답이 더 안정적입니다 ([#3717](https://github.com/QwenLM/qwen-code/pull/3717))
- **웹 검색을 MCP 경유로 전환**: 내장 `web_search` provider를 MCP 기반 방식으로 옮겼습니다. Bailian, Tavily, GLM WebSearch Prime 같은 검색 서비스를 필요에 맞게 붙이면 됩니다 ([#3502](https://github.com/QwenLM/qwen-code/pull/3502))
- **첫 모델 요청이 더 빨라짐**: 시작할 때 기본 API 엔드포인트를 미리 연결해, 첫 요청에서 TCP·TLS 연결/setup 시간이 줄어듭니다 ([#3318](https://github.com/QwenLM/qwen-code/pull/3318))
- **도구 일괄 호출을 읽기 쉽게**: 여러 도구가 병렬로 끝나면 짧은 의미 태그가 붙습니다. 도구 개수만 기계적으로 뜨던 것과 달리 AI가 이번 묶음에서 뭘 했는지 금방 파악됩니다 ([#3538](https://github.com/QwenLM/qwen-code/pull/3538))
- **도구 호출 핫패스 경량화**: 런타임 동기 I/O를 줄여 도구 호출 경로가 가벼워졌습니다. 긴 작업과 다수 도구 호출에서 응답이 더 안정적입니다 ([#3581](https://github.com/QwenLM/qwen-code/pull/3581))
- **세션 제목 수동 재생성**: 자동 제목에 `/rename --auto`가 추가돼, 제목이 영 아니하면 fast model이 다시 지리게 할 수 있습니다 ([#3540](https://github.com/QwenLM/qwen-code/pull/3540))
- **포그라운드 Subagent도 통합 작업 패널로**: 이전에는 백그라운드 작업만 보이던 것이, 이제 포그라운드 subagent도 /tasks 패널에서 함께 관리됩니다 ([#3768](https://github.com/QwenLM/qwen-code/pull/3768))
- **Skill 로딩 가속과 경로 조건부 활성화**: 여러 skill을 병렬 로드해 시작이 빨라지고, 디렉터리 조건에 맞춰 자동 활성화되니 매번 손으로 지정하지 않아도 됩니다 ([#3604](https://github.com/QwenLM/qwen-code/pull/3604))
- **하단 상태 바에 MCP 서비스 건강 상태 표시**: MCP server가 살아 있는지 한눈에 보이고, 연결 이상도 더 쉽게 찾습니다 ([#3741](https://github.com/QwenLM/qwen-code/pull/3741))
