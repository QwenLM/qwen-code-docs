Qwen Code는 이번 주 v0.18.0~v0.18.3 네 개의 정식 버전을 내놓고 PR 100개 이상을 병합했습니다. 네 가지 방향을 다뤘습니다:

**여러 Agent가 병렬로 협업합니다.** 이전에는 `/fork`로 백그라운드 Agent를 돌리면 각 Agent가 서로 소통하지 않아서 결과를 당신이 직접 합쳐야 했습니다. Agent Team 모드는 모델이 이름을 가진 팀을 만들고 팀원을 여러 명 파견해 병렬로 일하면서 서로 메시지를 주고받고 공유 작업 목록을 쓰다, 그리고 마지막에 leader가 보고서 하나로 정리합니다. 팀원은 오래 남아 있습니다. 작업을 하나 끝내면 다음 작업을 받을 수 있고, 끝나면 사라지는 일회성 subagent가 아닙니다.

**예약 작업이 재시작을 견딥니다.** 이전에는 `/loop`로 잡아 둔 예약 작업이 세션과 함께 사라졌습니다 — 재시작하면 소리 소문 없이 없어졌죠. Durable /loop은 영속화할 예약 작업 파일을 저장하고, 다음 시작할 때 자동으로 복원하며, 놓친 주기 작업은 한 번 보정으로 실행합니다.

**세션 안에서 디렉터리를 바꾸고, 재시작하지 않습니다.** `/cd <path>`로 CLI를 종료하지 않고 현재 세션의 작업 디렉터리를 바꿉니다. session 파일은 새 워크스페이스로 자동 이동하고, system/directory context는 자동 갱신됩니다. 이전에는 프로젝트 디렉터리를 바꿔 돌리려면 재시작뿐이었습니다.

## ✨ 새로운 기능

### Agent Team: 여러 Agent가 병렬로 협업하고, 서로 메시지를 주고받고, 작업을 공유합니다

이전까지 Qwen Code의 `/fork`는 백그라운드 Agent를 돌릴 수 있었지만, Agent마다 고립돼 있었습니다. Agent 셋에 코드 검토를 동시에 시켜도 서로 통신할 통로가 없어서, 마지막에는 당신이 그 결과 세 개를 합쳐야 했습니다.

이번 주 Agent Team 모드가 추가됐습니다(실험적, opt-in). 켜면 모델이 이름을 가진 팀을 만들고 팀원을 여러 명 파견해 병렬로 작업시킵니다. 팀원끼리, 그리고 leader와 메시지를 주고받고 공유 작업 목록을 쓰며, 마지막에 leader가 보고서 하나로 통일해 정리합니다. 팀원은 오래 남아 있습니다. 일회성 subagent가 아니라, 작업을 하나 끝내면 다음 작업을 받을 때까지 기다립니다.

기본은 꺼져 있습니다(`experimental.agentTeam` 설정 또는 `QWEN_CODE_ENABLE_AGENT_TEAM=1` 환경변수로 켬). 켜면 모델은 팀 협업 도구(팀 생성/삭제, 팀원에게 메시지 보내기, 공유 작업 생성/갱신/목록)를 얻고, Agent 도구에는 `name` 파라미터가 추가돼 일회성 서브 Agent가 아니라 오래 사는 이름 있는 팀원을 파생합니다.

**이걸로 할 수 있는 일:**

- reviewer 셋에 이 코드를 병렬로 보게 하세요 — 하나는 오류 처리, 하나는 경합 조건, 하나는 예외 케이스 — 그리고 정리된 보고서를 받습니다
- 팀을 꾸려 작은 북마크 앱을 만들도록 조율합니다
- 팀원은 작업이 끝나면 leader에게 자동 보고하고, leader는 당신에게 정리된 요약 하나를 줍니다

### Durable /loop: 예약 작업이 재시작을 견딥니다

이전까지 모든 `/loop`는 세션과 함께 사라졌습니다. "30분마다 내 PR 확인해 줘"라고 해 놓고 Qwen Code를 재시작하면 루프는 흔적도 없이 사라졌죠. 이번 주 `/loop` 작업은 재시작을 견딥니다.

요청이 영속화를 암시하면("1시간마다 내 PR 확인") 작업은 프로젝트별로 `~/.qwen/tmp/<project-hash>/scheduled_tasks.json`에 저장됩니다(워크스페이스 밖이라 `git status`에 잡히지 않음), 다음 시작할 때 자동으로 복원됩니다. 기본은 여전히 session-only이고, 임시 알림은 파일을 만들지 않습니다.

종료 중에 만료된 일회성 알림은 재시작 시 모델이 확인을 먼저 받고 실행하며, 절대 몰래 실행하지 않습니다. 놓친 주기 작업은 시작 후 한 번 보정으로 돌고 나서 정상 리듬으로 돌아옵니다. 같은 프로젝트에 세션이 여러 개면 하나만 영속 작업을 트리거하고, 그걸 들고 있던 세션이 죽으면 다른 세션이 몇 초 안에 이어받습니다. 주기 작업은 7일 뒤 자동 만료됩니다(마지막 트리거 뒤에 삭제).

**이걸로 할 수 있는 일:**

- "1시간마다 내 PR 확인" → 재시작해도 계속 돌고, 다시 예약하지 않아도 됩니다
- 놓친 주기 작업은 재시작 후 자동으로 한 번 보정 실행됩니다
- 임시 알림 `/loop 5m remind me`는 여전히 세션과 함께 사라지고 파일을 만들지 않습니다

### /cd: CLI를 재시작하지 않고 디렉터리 전환

이전까지 Agent를 다른 프로젝트 디렉터리에서 작업시키려면 종료하고 다시 시작해야 했습니다. 다중 저장소나 부모-자식 workspace 사이를 오갈 때 매우 불편했고, 세션 도중 active tool context를 옮길 진입점도 없었습니다.

이번 주 `/cd <path>` slash 명령이 새로 생겼습니다. 대상 디렉터리를 검증하고, 신뢰 확인을 처리하고, workspace roots와 cwd 서비스를 갱신하고, 현재 세션의 transcript/runtime/worktree 파일을 새 workspace 세션 디렉터리로 이동하고, system/directory context를 갱신합니다. 경로 자동 완성은 그대로 쓸 수 있습니다.

**이걸로 할 수 있는 일:**

- `/cd ../another-project`로 인접 프로젝트로 전환 — 세션 파일은 자동 이동합니다
- `/cd /path/to/parent-repo`로 세션 안에서 위아래로 이동 — 재시작이 필요 없습니다
- 신뢰하지 않은 경로에서는 확인 창이 뜹니다 — 첫 시작할 때의 신뢰 절차와 같습니다

### Thinking 접기: 추론 과정이 더 이상 화면을 차지하지 않습니다

이전까지 모델의 thinking 블록은 항상 펼쳐진 채 전체 추론 텍스트를 보여줘 화면을 크게 잡아먹었습니다. 이번 주 삼태 표시로 바뀌었습니다:

- **스트리밍 단계**: 4줄 고정 높이 롤링 창으로 추론 내용을 실시간 표시 + 타이머("∴ Thinking… 8s")
- **완료 후 접힘**(기본): 한 줄에 총 소요 시간만 표시("∴ Thought for 15s")
- **펼쳐 보기**: 앞으로 thinking 블록에 전용 단축키를 배정할 예정입니다. 지금은 Ctrl+O가 compactMode 전환이라 thinking 펼치기와 같은 키를 씁니다 — 전용 펼치기/접기 단축키는 이후 PR에서 분리됩니다

`thinkingDisplayMode` 설정은 제거되고 단일 접기 모드로 통일됐습니다. thinking 블록은 UI history 전용이고 API로 전송되지 않으며, session resume 동작은 그대로입니다.

**이걸로 할 수 있는 일:**

- 복잡한 추론 중에도 thinking은 한 줄로 접혀 거슬리지 않습니다
- Ctrl+O로 언제든 펼쳐 모델의 전체 추론 과정을 볼 수 있습니다
- 스트리밍 단계에 타이머가 있어 모델이 얼마나 고민했는지 알 수 있습니다

### MCP 승인 게이팅: 프로젝트 레벨 MCP 설정이 자동으로 연결되지 않습니다

이전까지 프로젝트 `.mcp.json`이나 워크스페이스 `.qwen/settings.json`에 선언된 MCP server는 자동으로 연결됐습니다. 악의적인 `.mcp.json`을 담은 저장소를 열면, 당신이 검토하기도 전에 server가 떠버릴 수 있었습니다.

이번 주 승인 게이팅이 붙었습니다. project `.mcp.json`과 workspace scope의 MCP server는 승인을 거쳐야만 연결됩니다. 승인 결정은 `<QWEN_HOME>/mcpApprovals.json`에 영속화되고, 프로젝트 root + server name으로 색인되며, 설정 hash에 묶입니다. server의 command/args/URL/environment/headers를 바꾸면 hash가 달라져 다시 pending으로 돌아갑니다 — 이전 승인을 조용히 이어받지 않습니다.

MCP server 우선순위 모델: user/default settings < project `.mcp.json` < workspace/system settings < session(ACP/IDE) < `--mcp-config`. 프로젝트 설정은 사용자 설정을 덮을 수 있지만, 기업의 system 설정은 덮을 수 없습니다.

**이걸로 할 수 있는 일:**

- 새 저장소를 열면 프로젝트 레벨 MCP server는 "Pending approval"로 표시되고 자동 연결되지 않습니다
- `qwen mcp approve <name>` 또는 `qwen mcp approve --all`로 일괄 승인
- server 설정을 바꾸면 자동으로 승인을 다시 요구합니다(hash 묶음)
- `qwen mcp list`로 모든 server의 승인 상태 확인

### 백그라운드 Agent 권한 버블링: 백그라운드 작업이 확인을 자동 거절하지 않습니다

이전까지 백그라운드 Agent가 권한 확인이 필요한 도구 호출(`git push`, `rm` 등)을 하면 자동 거절됐습니다. "background agents cannot prompt for confirmation"이라는 오류와 함께 부모 세션이 foreground에서 다시 실행됐죠 — 백그라운드는 헛돌았고 결국 앞에서 다시 돌렸습니다.

이번 주 `approvalMode: bubble`이 추가됐습니다. subagent 설정에 `approvalMode: bubble`을 넣으면, 백그라운드 Agent가 확인이 필요한 도구 호출을 만나도 요청이 부모 세션의 Background tasks UI로 올라갑니다. footer pill에서 세부 사항을 열어 승인하면 됩니다. 승인하면 Agent가 이어서 실행하고, 거절하면 정상 종료합니다. `bubble`은 subagent 전용 approvalMode 값이고 session 단위 옵션은 아닙니다. headless/ACP/SDK 환경에는 UI가 답할 수 없으므로 여전히 자동 거절됩니다.

**이걸로 할 수 있는 일:**

- 커스텀 subagent에 `approvalMode: bubble`을 선언하면 백그라운드 작업이 자동 거절되지 않습니다
- footer pill에 "⚠ needs approval"로 표시되고, ↓를 눌러 세부 사항을 열어 승인합니다(단회 승인만 지원, '항상 허용' 옵션은 없음)
- 승인 후 Agent가 이어서 실행하고 결과를 돌려주니, foreground로 돌아와 다시 돌릴 필요가 없습니다

관련 PR: [#4955](https://github.com/QwenLM/qwen-code/pull/4955)

### /compress-fast: LLM을 부르지 않고 즉시 컨텍스트 압축

이전까지 `/compress`는 LLM 보조 질의로 요약을 만들었습니다(약 2~5초, 약 30K token 소모). 로컬 모델로 돌리거나 공간만 빠르게 되돌리고 싶은 사용자에게는 너무 느립니다.

이번 주 `/compress-fast`가 새로 생겼고 순수 규칙 기반입니다. microcompaction을 강제해 오래된 도구 결과와 미디어 콘텐츠를 정리하고(최근 N개는 보존), 모든 모델 응답에서 thinking 부분을 제거합니다. API 호출 0, token 비용 0, 즉시 응답입니다. JSONL에 `chat_compression` checkpoint를 쓰므로 `--resume` 동작은 `/compress`와 완전히 같습니다.

**이걸로 할 수 있는 일:**

- `/compress-fast` 하나로 즉시 token 수천 개를 되돌립니다 — 지연도 비용도 없습니다
- 긴 세션에서 도구 호출을 잔뜩 돌린 뒤 공간을 빠르게 회수하고 싶을 때 적합합니다
- `/compress`는 그대로 쓸 수 있습니다 — 요약의 의미 품질이 필요하면 이쪽입니다
- `/compress-fast`를 두 번 연속하면 두 번째는 "No compression needed"라고 안내합니다
