O Qwen Code lançou a v0.19.4 esta semana, com mais de 80 PRs mesclados em três direções:

**`/loop` funciona mesmo quando você sai.** Um `/loop` simples (sem prompt) ativa o modo autônomo — o agent continua avançando o trabalho já estabelecido enquanto você está ausente, sem inventar novas tarefas nem executar operações irreversíveis. Com um arquivo de tarefas `.qwen/loop.md`, o loop relê a lista editável a cada tick; se o arquivo for deletado, o loop emite ticks no-op apenas para se manter vivo. O Claude Code publicou na semana passada um [guia introdutório sobre loops de agentes](https://claude.com/blog/getting-started-with-loops), descrevendo agents executando um plano predefinido repetidamente — o modo autônomo do `/loop` faz algo semelhante, mas com uma camada extra: a lista de tarefas pode ser editada a qualquer momento e o loop detecta as mudanças automaticamente.

**Ditado por voz chega ao desktop.** O ditado por voz já existia no CLI e no Web Shell, mas o desktop ainda não tinha. Esta versão preenche a última lacuna, unificando a experiência nas três interfaces.

**Interação no terminal mais refinada.** `/settings` deixou de ser uma lista plana e virou uma visualização por abas — pesquisa, status e estatísticas em uma única tela; no modo Virtualized History, menus, sugestões e campo de entrada agora aceitam cliques e hover do mouse.

## ✨ Novos Recursos

### Modo autônomo `/loop` + arquivo de tarefas loop.md

`/loop` agora suporta dois novos modos:

**Modo autônomo**: Um `/loop` simples (sem prompt, sem intervalo) não exibe mais a mensagem de uso — em vez disso, inicia um ciclo autônomo com passos definidos pelo próprio agent. O agent avança o trabalho já estabelecido enquanto você está ausente — mantém PRs em andamento, continua tarefas incompletas, cumpre promessas feitas — mas só executa o que já está confirmado no transcript, sem inventar novas tarefas e sem realizar ações irreversíveis (push/delete/send) sem autorização explícita. Para quando fica quieto. O preamble autônomo é enviado apenas uma vez; a cada tick seguinte, apenas um lembrete curto é enviado, mantendo o custo de tokens baixo.

**Arquivo de tarefas loop.md**: Crie `.qwen/loop.md` na raiz do projeto ou em `~/.qwen/`, defina o prompt do wakeup/cron como sentinel (`<<loop.md-dynamic>>` ou `<<loop.md>>`), e o loop relê o arquivo a cada execução. Na primeira vez, o conteúdo completo é entregue; nas seguintes, se nada mudou, apenas um lembrete curto é enviado; se o arquivo foi editado, o conteúdo completo é reenviado. Quando o arquivo desaparece, o loop emite ticks no-op (o agent não faz nada, apenas re-arma o ciclo para mantê-lo vivo), voltando ao comportamento base do modo autônomo. Ao recriar o loop.md, o próximo tick detecta a mudança automaticamente e reenvia o conteúdo completo.

**Loops em canais**: `/loop` não se limita ao terminal — também funciona em canais do DingTalk e Feishu. No grupo, use `/loop add "0 9 * * 1-5" verificar status do CI` para criar um loop agendado, `/loop list` para ver todos os loops do canal atual, `/loop inspect <id>` para ver contagem de execuções e resultados recentes, `/loop cancel <id>` para parar. Os loops são executados via channel session router, aguardando o turno ativo terminar antes de iniciar, e os resultados são enviados de volta ao canal. Loops de execução única são desativados automaticamente após sucesso ou falha.

**O que você pode fazer com isso:**

- Use `/loop` simples para o agent continuar avançando o trabalho enquanto você está ausente
- Mantenha uma lista de tarefas persistente e editável com `.qwen/loop.md`, sem precisar repetir instruções a cada tick
- Delete o loop.md e o loop emite ticks no-op para se manter vivo; recrie e ele retoma normalmente
- Em grupos DingTalk/Feishu, use `/loop add` para agendar loops que avançam o trabalho periodicamente

### Ditado por Voz no Desktop: Alinhamento entre as Três Interfaces

O ditado por voz já existia no CLI e no Web Shell, mas o desktop não tinha — usuários que configuravam voz perdiam essa capacidade ao alternar para o desktop. Esta versão preenche a última lacuna.

A barra de ferramentas do composer agora tem um botão de microfone. Durante a gravação, a barra se transforma em uma barra de gravação (linha pontilhada → forma de onda em tempo real → cronômetro). Ao parar, o resultado da transcrição é inserido no campo de entrada para revisão. A transcrição é feita no servidor, reutilizando o pipeline de voz do CLI (batch `qwen3-asr-flash` e modelos em tempo real `*-realtime`); as credenciais do provider não entram no renderer. A voz pode ser ativada e o modelo selecionado em Settings → Input e no dropdown de modelos do composer.

**O que você pode fazer com isso:**

- Clique no microfone e fale, vendo a forma de onda e o cronômetro em tempo real
- Escolha um modelo realtime (como `qwen3-asr-flash-realtime`) para ver o texto provisório enquanto fala
- Libere as mãos para entrada por voz em tablets ou cenários com múltiplos monitores

### Mobile Sidebar Drawer + Aprimoramentos em `qwen serve`

Anteriormente, ao acessar `qwen serve` pelo navegador móvel, a sidebar (lista de sessões, pesquisa, nova sessão) era simplesmente ocultada com `display: none` abaixo de 760px — não havia nenhuma forma de alternar sessões. Agora, um overlay drawer substitui o ocultamento direto: um botão de menu aparece no cabeçalho do painel de chat e, ao clicar, a sidebar desliza da esquerda com uma máscara semitransparente. Selecionar uma sessão, criar uma nova sessão ou clicar na máscara fecha o drawer. O layout desktop não é afetado.

Por trás disso, há uma série de mudanças que transformam o `qwen serve` de "funcional" em "agradável de usar":

- **Criação lazy de sessão** ([#6066](https://github.com/QwenLM/qwen-code/pull/6066)): a sessão só é criada no primeiro prompt, reduzindo overhead de sessões vazias e acelerando o início do Web Shell
- **workspace remember** ([#5884](https://github.com/QwenLM/qwen-code/pull/5884)): o modo serve lembra o workspace, sem necessidade de reespecificar após reiniciar
- **session archive** ([#6058](https://github.com/QwenLM/qwen-code/pull/6058)): o daemon suporta arquivamento de sessões, permitindo gerenciar sessões de longa duração

**O que você pode fazer com isso:**

- Acesse `qwen serve` pelo navegador móvel e use o menu para alternar entre sessões
- Ao alternar entre vários projetos, o serve lembra o workspace automaticamente
- Sessões de longa duração podem ser arquivadas em vez de deletadas

Veja PR [#6003](https://github.com/QwenLM/qwen-code/pull/6003)

### Cliques e Hover do Mouse no TUI

Anteriormente, no modo Virtualized History, o CLI suportava apenas scroll do mouse e barra de rolagem, sem interação por ponteiro. Agora, com o Virtualized History habilitado (`ui.useTerminalBuffer`), três tipos de interação estão disponíveis:

- **Menus de seleção e caixas de diálogo** (confirmação de permissão, `/model`, `/config`, temas etc.): hover destaca a linha sob o ponteiro, clique seleciona
- **Listas de sugestões de comandos `/` e arquivos `@`**: hover destaca a sugestão, clique aceita
- **Campo de entrada**: clique esquerdo posiciona o cursor de texto (suporta múltiplas linhas, offset de scroll, caracteres largos)

**O que você pode fazer com isso:**

- No diálogo `/model`, selecione o modelo diretamente com o mouse, sem usar as teclas de direção
- Após digitar `/`, clique na sugestão de autocompletar
- Em entradas multilinha, clique para reposicionar o cursor

### Settings em Abas: Pesquisa, Status e Estatísticas em Uma Tela

`/settings` foi redesenhado de uma lista plana para uma visualização por abas, inspirada no design do `/config` do Claude Code. A barra de abas no topo divide em três páginas — Settings / Status / Stats — e a página Settings tem uma caixa de pesquisa que filtra ao digitar.

A página Status exibe as mesmas informações do sistema que `/status`; a página Stats incorpora o painel completo de `/stats` (com sub-abas Session / Activity / Efficiency). O foco do teclado se move verticalmente entre barra de abas → campo de pesquisa → lista de configurações, e o destaque só aparece na área que realmente possui o foco.

**O que você pode fazer com isso:**

- Abra `/settings` e digite uma palavra-chave para filtrar configurações
- Use ←/→ para alternar até a página Status e ver informações de runtime, sem precisar executar `/status` separadamente
- Na página Stats, use Tab para alternar entre Session / Activity / Efficiency; quando a tabela Efficiency exceder a altura do diálogo, ela se recolhe automaticamente em "+N more"

### Extensão Chrome: Converse e Opere Páginas Diretamente no Navegador

A extensão Chrome foi ressuscitada com base na arquitetura daemon-direct — a extensão deixa de ser o host de Native Messaging e passa a ser um cliente fino do daemon local `qwen serve`.

O chat na sidebar conecta-se diretamente ao `qwen serve` via `DaemonSessionProvider` (HTTP+SSE, o mesmo caminho do web shell); quando não consegue conectar ao daemon, exibe a mensagem "execute `qwen serve`". As ferramentas de navegador (ler página, captura de tela, console, navegação, clique, preenchimento de formulários) são expostas ao agent como um MCP server gerenciado pelo cliente via daemon WebSocket. Tanto o chat quanto as ferramentas eliminaram o Native Messaging.

> [!caution]
>
> Atenção: o canal reverso de ferramentas é habilitado via variável de ambiente `QWEN_SERVE_CLIENT_MCP_OVER_WS`, desativado por padrão — é necessário definir essa flag explicitamente ao iniciar o `qwen serve`.

**O que você pode fazer com isso:**

- Converse com o Qwen Code diretamente na sidebar do Chrome, sem precisar instalar um host nativo no sistema operacional
- Peça ao agent para ler a página atual, fazer capturas de tela e operar elementos do navegador
- Reutilize a UI compartilhada do web shell, com experiência consistente
