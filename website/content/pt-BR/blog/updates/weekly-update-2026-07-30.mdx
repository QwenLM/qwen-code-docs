Esta semana o Qwen Code lançou duas versões oficiais: v0.21.0 e v0.21.1, com 290+ PRs integrados.

**O ciclo de vida de sessões e Agents ganhou dois reforços importantes.** Antes, para reutilizar contexto de conversas anteriores, só era possível fazer resume ou fork — a conversa atual era interrompida. Agora, ao digitar `@` você vê as sessões históricas do projeto na lista de autocompletar; ao selecionar uma, um resumo somente leitura é injetado e a conversa atual permanece independente. Do lado do Agent em segundo plano, antes ele era destruído ao concluir — para fazer uma pergunta de acompanhamento era preciso reconstruir tudo do zero. Agora o runtime do Agent concluído permanece residente na sessão pai, `send_message` continua a conversa de onde parou, e mesmo após sair do processo e voltar, o roster restaura tudo.

**O sistema de skills deu um passo além do "modo manual".** O `/learn` antes só processava texto, documentos e páginas web — vídeos de tutorial exigiam que você assistisse e escrevesse a skill manualmente. Agora é só jogar um MP4 e o Agent assiste e destila automaticamente em uma Skill reutilizável. E os diretórios de skills não precisam mais ser duplicados — configure o caminho no settings e Claude Code, Codex e Qwen Code compartilham a mesma biblioteca de skills.

**Observabilidade e integrações também estão avançando.** O `/stats` finalmente tem TTFT, duração de geração e TPS — para comparar performance de streaming entre modelos não é mais preciso confiar na intuição. O adaptador de GitHub Channel está disponível: mencione o bot com @ em uma Issue ou PR e o Agent responde com um comentário. O Web Shell recebeu 40+ PRs esta semana: seletor de branch Git, diálogo de commit, fluxo de criação de PR, página de gerenciamento de Channels, preview de renderização de arquivos, entrada por voz — tudo de uma vez.

## ✨ Novidades

### /learn suporta entrada de vídeo: assista um tutorial e transforme em skill reutilizável

Antes o `/learn` processava texto, documentos, diretórios e páginas web, mas não vídeos. Você tem uma gravação de tela de 15 minutos e quer transformá-la em uma skill que o Agent possa usar? Tinha que assistir inteiro e escrever o SKILL.md manualmente.

Agora o `/learn` suporta arquivos MP4, WebM, MOV e M4V locais, além de links diretos HTTP(S) para vídeos. O comando primeiro verifica se o modelo atual suporta entrada de vídeo; se sim, entrega o vídeo ao Agent para destilação, gerando um diretório `learned-skill-*` com `SKILL.md` e um registro de origem `references/source.md` com timestamps. URLs de páginas do YouTube são identificadas e rejeitadas, com orientação para baixar como vídeo local primeiro. Entradas que não são vídeo mantêm o comportamento original.

O que você pode fazer com isso:

- Transformar gravações de tela de colegas em skills reutilizáveis para a equipe
- Assistir um tutorial em vídeo e extrair os passos com `/learn tutorial.mp4`
- O registro de origem marca "source-grounded, not execution-verified", diferenciando "o que foi visto" de "o que foi validado"

Veja o PR [#7497](https://github.com/QwenLM/qwen-code/pull/7497)

### @ referência a sessões históricas: use contexto anterior sem restore ou fork

Antes, para reutilizar contexto de sessões anteriores, só era possível fazer resume ou fork. O resume sai da conversa atual, o fork cria um novo branch — para a necessidade leve de "só quero referenciar uma conclusão anterior", os dois são pesados demais.

Agora, ao digitar `@` no campo de entrada, o dropdown de autocompletar exibe resultados categorizados por todos, arquivos, sessões, MCP e extensões, com as setas esquerda/direita alternando entre categorias. Ao selecionar uma sessão histórica, o Qwen Code injeta um resumo somente leitura gerado deterministicamente: preserva o texto visível do usuário e do assistente, comprime resultados de ferramentas em uma linha de status, controla o orçamento total em 8k tokens com prioridade para o conteúdo mais recente. A conversa atual não é afetada, e a sessão antiga não é restaurada nem bifurcada.

O que você pode fazer com isso:

- Referenciar conclusões de uma sessão de debugging anterior na tarefa atual, sem ficar alternando
- Passar o feedback de uma revisão de código anterior como contexto para uma nova tarefa
- Acumular conhecimento do projeto entre sessões, sem precisar reexplicar o contexto toda vez

### Agent em segundo plano residente e restauração entre sessões: sem reconstruir após concluir

Antes, o Agent em segundo plano era destruído ao concluir. Quer fazer uma pergunta de acompanhamento? Era preciso reconstruir chat, ferramentas, registry e cache de provider a partir do transcript JSONL — lento, e todo o estado em processo era perdido. Pior ainda: ao sair do processo e restaurar a sessão pai, os Agents concluídos viravam `Task not found`.

Esta semana, dois PRs resolveram isso juntos. Primeiro, o runtime do Agent em segundo plano concluído permanece residente na sessão pai — `send_message` para o mesmo `task_id` reutiliza o chat ativo, as ferramentas preparadas, o cache de provider e o modelo de inicialização, sem reconstruir a partir do transcript. Segundo, ao sair do processo e restaurar a sessão pai, Agents interrompidos voltam com status `paused` e concluídos voltam com status `completed`, com o mesmo task ID. A nova ferramenta `list_agents` permite visualizar todos os Agents em segundo plano endereçáveis da sessão atual.

O que você pode fazer com isso:

- O Agent em segundo plano termina uma revisão de código, você pergunta "explica a terceira sugestão em mais detalhes" — sem reconstruir
- Sai do terminal e volta no dia seguinte, `list_agents` mostra que os Agents de ontem ainda estão lá — continua de onde parou
- Durante iterações, o Agent mantém o modelo de inicialização, sem ser afetado por trocas de modelo na sessão pai

Veja os PRs [#7426](https://github.com/QwenLM/qwen-code/pull/7426), [#7459](https://github.com/QwenLM/qwen-code/pull/7459)

### Diretórios de skills personalizados: um conjunto de skills compartilhado entre múltiplos Agents

Antes, skills só podiam ficar em `~/.qwen/skills/`. Se você usa Claude Code e Qwen Code ao mesmo tempo, o mesmo conjunto de skills precisa ser duplicado — e esquecer de atualizar um dos dois é rotina.

Agora, adicione um array `skills.directories` no settings.json especificando caminhos adicionais para scan de skills. Os caminhos suportam expansão de `~` e fazem scan recursivo de arquivos SKILL.md. O diretório padrão tem prioridade mais alta — skills com o mesmo nome usam a versão do diretório padrão.

O que você pode fazer com isso:

- Coloque um conjunto de skills em `~/.agent/skills` e compartilhe entre Claude Code, Codex e Qwen Code
- Biblioteca de skills da equipe em `/shared/team-skills`, todos sincronizam automaticamente
- Organize skills por projeto, sem precisar colocar tudo em um único diretório

Veja o PR [#7395](https://github.com/QwenLM/qwen-code/pull/7395)

### /stats métricas de performance de geração: TTFT e TPS de relance

Antes o `/stats` exibia duração de sessão, total de requisições, chamadas de ferramentas e alterações de arquivos. Quer comparar a velocidade de streaming entre dois modelos? Sem TTFT, sem TPS — só na intuição.

Agora o `/stats` e a aba Session têm uma nova seção Generation Metrics: nome do modelo da última requisição, TTFT (latência do primeiro Token), duração de geração, número de Tokens de saída e TPS, além de métricas a nível de sessão como número de requisições cronometradas, TTFT médio e TPS ponderado da sessão. A duração de geração é calculada por `api_duration - ttft`, e o denominador do TPS é o intervalo entre o primeiro Token visível e o fim da geração. Prompts auxiliares internos não são contabilizados, e os registros de uso diário/mensal permanecem inalterados.

O que você pode fazer com isso:

- Trocou de modelo? Rode `/stats` e veja a diferença de TTFT e TPS diretamente
- Compare a performance de streaming entre backend local e API na nuvem
- O TPS ponderado a nível de sessão reflete o throughput real da conversa inteira

Veja o PR [#7677](https://github.com/QwenLM/qwen-code/pull/7677)

### Adaptador de GitHub Channel: mencione o bot com @ em Issues e PRs para acionar o Agent

Antes, os Channels do Qwen Code suportavam Feishu, WeChat, QQ e Telegram, mas não GitHub. Quer mencionar o bot com @ em uma Issue para ele ajudar a investigar um problema? Impossível.

Agora o adaptador de GitHub Channel está disponível. Configure um classic PAT, inicie o Channel e ele faz polling na API de notificações do GitHub. Mencione o bot com @ em um comentário de Issue ou PR e o Agent lê o conteúdo e responde no mesmo thread. Ao criar uma Issue nova, mencionar o bot com @ no body também aciona (primeiro contato). A deduplicação é baseada na janela de cursor de comentários, não no `markNotificationsAsRead` assíncrono do GitHub, e auto-comentários do bot são filtrados para evitar loops. Suporta GitHub Enterprise (via configuração `baseUrl`) e proxy.

O que você pode fazer com isso:

- Em uma Issue, mencione o bot: "me ajuda a investigar esse erro" — o Agent responde com um comentário diretamente
- Durante revisão de PR, mencione o bot para adicionar contexto, sem precisar ir ao terminal
- Intervalo de polling configurável (padrão 60s), ajuste a velocidade de resposta conforme necessário

Veja o PR [#7632](https://github.com/QwenLM/qwen-code/pull/7632)

### Web Shell completamente atualizado: operações Git, gerenciamento de Channels, preview de arquivos e entrada por voz de uma vez

O Web Shell recebeu 40+ PRs esta semana — do workflow Git ao gerenciamento de Channels à experiência de entrada, praticamente cada canto foi tocado.

**O ciclo de operações Git está completo.** Antes, no Web Shell só era possível ver branches — sem alternar, sem commit, sem criar PR. Agora, ao criar uma nova sessão há um seletor de modo Git ([#7471](https://github.com/QwenLM/qwen-code/pull/7471)), dentro da sessão é possível alternar branches, abrir o diálogo de commit e criar PR diretamente ([#7731](https://github.com/QwenLM/qwen-code/pull/7731)). Sessões de Worktree também podem abrir os diálogos de Changes e History ([#7695](https://github.com/QwenLM/qwen-code/pull/7695)). A barra lateral ganhou um painel somente leitura de PRs do GitHub ([#7683](https://github.com/QwenLM/qwen-code/pull/7683)) — veja o status do PR sem sair para o navegador.

**Gerenciamento de Channels com página dedicada.** Antes, configurar Channels exigia editar o settings.json manualmente. Agora o Web Shell tem uma página completa de gerenciamento de Channels ([#7793](https://github.com/QwenLM/qwen-code/pull/7793)), com fluxo de configuração ([#7893](https://github.com/QwenLM/qwen-code/pull/7893)) e gerenciamento de requisições de pareamento ([#7909](https://github.com/QwenLM/qwen-code/pull/7909)).

**Preview de arquivos e gerenciamento de Agents.** A lista de arquivos agora suporta preview de renderização ([#7467](https://github.com/QwenLM/qwen-code/pull/7467)) — sem precisar abrir para ver o conteúdo bruto. Sessões de sub-Agents são visíveis no painel de detalhes ([#7380](https://github.com/QwenLM/qwen-code/pull/7380)), e o status de Agents em segundo plano sincroniza em tempo real ([#7561](https://github.com/QwenLM/qwen-code/pull/7561)). O seletor de Workspace ([#7390](https://github.com/QwenLM/qwen-code/pull/7390)) e o seletor de pastas nativo ([#7849](https://github.com/QwenLM/qwen-code/pull/7849)) tornam a alternância entre projetos mais fluida.

**Experiência de entrada.** A entrada por voz é restrita ao composer workspace atual ([#7754](https://github.com/QwenLM/qwen-code/pull/7754)), suporta modo push-to-talk ([#7839](https://github.com/QwenLM/qwen-code/pull/7839)), e a estabilidade no mobile foi corrigida ([#7806](https://github.com/QwenLM/qwen-code/pull/7806)). Dispositivos touchscreen fazem fallback para composer textarea puro ([#7587](https://github.com/QwenLM/qwen-code/pull/7587)). Conteúdo colado não se perde mais ([#7824](https://github.com/QwenLM/qwen-code/pull/7824)). O terminal suporta parsing de sequências SGR de 256 cores e truecolor ([#7620](https://github.com/QwenLM/qwen-code/pull/7620)).

**Outras melhorias.** A barra lateral pode ser expandida até metade da janela ([#7778](https://github.com/QwenLM/qwen-code/pull/7778)), nomes de sessão mostram o nome completo no hover ([#7662](https://github.com/QwenLM/qwen-code/pull/7662)), tarefas de Monitor têm painel de detalhes ([#7817](https://github.com/QwenLM/qwen-code/pull/7817)), e a performance de renderização de sessões longas foi otimizada ([#7408](https://github.com/QwenLM/qwen-code/pull/7408)). Isolamento via Shadow DOM impede que CSS do host contamine estilos de componentes ([#7551](https://github.com/QwenLM/qwen-code/pull/7551)). Digitar "BTW" sugere abrir uma pergunta lateral ([#7935](https://github.com/QwenLM/qwen-code/pull/7935)).

## 📊 Mais funcionalidades

**Ferramenta de zoom em imagens.** Imagens grandes são reduzidas antes de serem enviadas ao modelo, e textos pequenos e labels de gráficos frequentemente ficam ilegíveis. Agora, modelos que suportam entrada de imagem podem usar a ferramenta `zoom_image` para recortar uma região específica do arquivo original em resolução completa, retornando uma visualização JPEG ampliada. Suporta PNG, JPEG e WebP, com tratamento automático de orientação EXIF. Veja o PR [#7809](https://github.com/QwenLM/qwen-code/pull/7809)

**Níveis de modelo para Subagents.** Tarefas diferentes precisam de modelos com custos diferentes, mas quem chama não deveria lidar com IDs de modelo específicos. Agora é possível mapear níveis semânticos como `small` e `high` para seletores de modelo no settings — o schema da ferramenta Agent expõe apenas o nome do nível. Forks e teammates nomeados não aceitam esse parâmetro. Veja o PR [#7702](https://github.com/QwenLM/qwen-code/pull/7702)

**Modelo de geração de imagens configurável.** A geração de imagens não fica mais atrelada ao modelo padrão — é possível especificar na configuração. Veja o PR [#7607](https://github.com/QwenLM/qwen-code/pull/7607)

**Ferramenta de recuperação de corpus externo.** Nova ferramenta MCP `context_search` para recuperar contexto sob demanda de bases de conhecimento externas ou serviços RAG. Somente leitura, sem recall automático, sem escrita — Provider e corpus são fixados pelo administrador. Inclui adaptadores para Mem0 e HTTP genérico. Veja o PR [#7586](https://github.com/QwenLM/qwen-code/pull/7586)

**Override de identidade do sistema.** A variável de ambiente `QWEN_SYSTEM_IDENTITY_MD` permite sobrescrever o prompt de identidade central. Veja o PR [#7478](https://github.com/QwenLM/qwen-code/pull/7478)

**Reconexão forçada de MCP.** O `qwen serve` suporta reconexão forçada de servidores MCP sem reiniciar o processo inteiro. Veja o PR [#7488](https://github.com/QwenLM/qwen-code/pull/7488)

**Hot-reload de Workspace trust.** Após alterar a configuração de workspace trust, o daemon em execução aplica a nova política imediatamente, sem reinício. Veja o PR [#7268](https://github.com/QwenLM/qwen-code/pull/7268)

**Estado desativado por padrão para Skills.** Skills podem ser configuradas como desativadas por padrão, mas com ativação explícita permitida (soft default); desativação rígida não pode ser sobrescrita. Veja o PR [#7357](https://github.com/QwenLM/qwen-code/pull/7357)

**MCP runtime por sessão.** Sessões ACP suportam configuração de MCP runtime a nível de sessão. Veja o PR [#7847](https://github.com/QwenLM/qwen-code/pull/7847)

**Envio de imagens no DingTalk.** O Channel do DingTalk suporta envio de mensagens com imagens. Veja o PR [#7698](https://github.com/QwenLM/qwen-code/pull/7698)

**Roteamento de forum topic no Telegram.** Respostas do Channel do Telegram agora são roteadas corretamente para o forum topic. Veja o PR [#7612](https://github.com/QwenLM/qwen-code/pull/7612)

**Comentários bilíngues no Review.** Quando a descrição do PR está em chinês, os comentários de revisão publicados pelo `/review` usam automaticamente chinês e inglês. Veja o PR [#7564](https://github.com/QwenLM/qwen-code/pull/7564)

**Link de login OAuth otimizado.** A URL de login OAuth agora é exibida como hyperlink OSC 8 — clique diretamente no terminal para abrir. Veja o PR [#7255](https://github.com/QwenLM/qwen-code/pull/7255)

**Cópia preserva texto semântico no VP mode.** Ao selecionar e copiar texto no VP mode, o texto semântico é preservado em vez do formato renderizado. Veja o PR [#7286](https://github.com/QwenLM/qwen-code/pull/7286)

## 👏 Melhorias de experiência

**Shift+Enter finalmente faz quebra de linha.** Terminais como Ghostty, quando o protocolo Kitty não está habilitado, interpretavam Shift+Enter erroneamente como Escape, acionando o prompt de rollback de conversa. Agora o parsing de CSI-u foi corrigido — Shift/Ctrl/Alt+Enter fazem quebra de linha corretamente tanto no VP mode quanto fora dele. A altura dos blocos de Thinking em streaming também não oscila mais — a janela só cresce, sem acompanhar a deriva de altura do terminal. Veja o PR [#7397](https://github.com/QwenLM/qwen-code/pull/7397)

**Colar textos grandes não trava mais.** Antes, colar 260K caracteres disparava 260K eventos de keypress caractere a caractere, bloqueando por ~1,7 segundos. Agora os marcadores de bracketed paste são interceptados na camada stdin e processados em bloco, caindo para ~8ms. Durante a colagem, o Footer exibe uma barra de progresso (`Pasting… ████████░░░░░░░░ 42% (128 KB)`), com suporte a Ctrl+C para interromper. Veja o PR [#6506](https://github.com/QwenLM/qwen-code/pull/6506)

**Delay de retry em streaming configurável.** Novas configurações `retryInitialDelayMs` e `retryMaxDelayMs` permitem ajustar o delay de retry de streaming SSE para janelas de quota de providers específicos. Veja os PRs [#7674](https://github.com/QwenLM/qwen-code/pull/7674), [#7666](https://github.com/QwenLM/qwen-code/pull/7666)

**Alinhamento de ícones na TUI.** Todas as colunas de ícones da TUI foram unificadas para 2 caracteres de largura — sem mais desalinhamento. Veja o PR [#7633](https://github.com/QwenLM/qwen-code/pull/7633)

**Exibição de mensagens em fila corrigida.** O estilo e a ordenação de mensagens em fila foram corrigidos — sem mais desalinhamento. Veja o PR [#7381](https://github.com/QwenLM/qwen-code/pull/7381)

**Correção do comando /copy.** `/copy` com índice simples e `/copy <message> <index>` para selecionar blocos de código agora funcionam corretamente. Veja os PRs [#7789](https://github.com/QwenLM/qwen-code/pull/7789), [#7883](https://github.com/QwenLM/qwen-code/pull/7883)

**Verificação de atualização usa npm view.** A verificação de atualização de versão migrou do update-notifier para `npm view` — mais confiável. Veja o PR [#7528](https://github.com/QwenLM/qwen-code/pull/7528)

**Alinhamento de cursor IME.** O cursor do método de entrada não fica mais desalinhado após atualização do Footer. Veja o PR [#7711](https://github.com/QwenLM/qwen-code/pull/7711)
