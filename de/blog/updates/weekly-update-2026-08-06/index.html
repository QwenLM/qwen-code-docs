Qwen Code Wochenbericht: Desktop-App offiziell veröffentlicht, Session Workflow macht den Aufgabenfluss sichtbar, Sub-Agenten bekommen Berechtigungen passend zur Aufgabe

Qwen Team
2026-08-06

Qwen Code hat diese Woche fünf stabile Versionen veröffentlicht (v0.21.2 bis v0.21.6), mit über 300 gemergten PRs. Dazu kommt ein großer Schritt: Qwen Code Desktop v0.1.0 ist offiziell erschienen.

Die Desktop-App ist da! Letzte Woche bekam die Web Shell ein großes Update — diese Woche ist daraus eine eigenständige Desktop-App geworden: Qwen Code Desktop v0.1.0. Für macOS, Windows und Linux gibt es native Installationspakete, direkt zum Download auf GitHub Releases.

Die Aufgabenausführung wird sichtbar. Die neue Session-Workflow-Ansicht zeichnet Aufgabenplan und Fortschritt als Flussdiagramm: wie viele Schritte der Plan hat, welcher gerade läuft, welcher wartet und welche Teilaufgabe welchem Agenten zugewiesen ist — alles auf einen Blick. Bevor der Agent loslegt, zeigt er dir das Diagramm zur Freigabe; erst wenn du nickst, beginnt er.

Auch Terminal-Erfahrung und Berechtigungssteuerung werden ausgebaut. Vom Agenten erzeugte Bilder erscheinen jetzt direkt im Terminal — kein manuelles Öffnen mehr. Sub-Agenten bekommen Berechtigungen passend zur Aufgabe: Nur-Lesen-Aufgaben erhalten nur Lesezugriff, häufig genutzte Berechtigungskombinationen lassen sich als Vorlage speichern. Für die Komprimierung langer Sitzungen kann ein eigenes günstiges Modell festgelegt werden — die Kosten bleiben besser im Griff.

✨ Neue Features

Qwen Code Desktop offiziell veröffentlicht: Native Apps für alle drei großen Betriebssysteme

Bisher verteilte sich das Desktop-Erlebnis von Qwen Code auf zwei Orte: die Electron-App und die Web Shell im Browser. Diese Woche sind beide verschmolzen: Qwen Code Desktop v0.1.0 ist offiziell veröffentlicht — mit der Oberfläche der letzte Woche groß aktualisierten Web Shell. Installationspakete für macOS, Windows und Linux sind online und stehen auf GitHub Releases  zum Download bereit.

macOS-Nutzer der alten Electron-Version müssen nicht manuell migrieren: Die neue Version bringt eine einmalige Migrationsanleitung mit, und künftige Updates kommen danach automatisch.

Was du damit machen kannst:

  • Qwen Code Desktop kann alles, was auch die Terminal-Version kann
  • Einheitliches Erlebnis auf allen drei großen Betriebssystemen
  • Automatische Update-Prüfung — neue Versionen ohne manuelle Neuinstallation

Siehe PRs #8132 , #8392 , #8511 , #8518 

Session Workflow: Plan, Teilaufgaben und Fortschritt als ein Diagramm

Wenn eine komplexe Aufgabe lief, musste man bisher den Gesprächsverlauf durchsuchen, um herauszufinden, wie weit der Plan ist und welche Teilaufgabe gerade was macht.

Die neue Session-Workflow-Ansicht zeichnet all das als Flussdiagramm: Jeder Schritt des Plans wird zu einem Kasten, Linien zeigen die Reihenfolge, und in Echtzeit sieht man, welcher Schritt läuft und welcher hängt. Auch die verteilten Teilaufgaben hängen am Diagramm — ein Klick zeigt, was sie konkret gemacht haben. Bevor der Agent loslegt, zeigt er dir das Diagramm zur Freigabe: abgelehnt heißt zurück zur Planung. Auch nach Abschluss der Aufgabe lässt sich das Diagramm wieder öffnen — für jeden Schritt ist festgehalten, wer ihn ausgeführt hat und was passiert ist.

Das Feature ist standardmäßig deaktiviert — in den Settings experimental.sessionWorkflow auf true setzen genügt. Zwei Extras sind dabei: Braucht eine Teilaufgabe eine Bestätigung, etwa zum Ausführen eines Befehls oder Ändern einer Datei, erscheint die Anfrage direkt in der Hauptansicht — kein Hineinwühlen in die Teilaufgabe. Sehr lange Aufgaben lassen sich in den Hintergrund schicken, während der Hauptchat weiterläuft; bei Fertigstellung gibt es eine Benachrichtigung.

Was du damit machen kannst:

  • Den Fortschritt komplexer Aufgaben auf einen Blick verfolgen — das Diagramm zeigt sofort, wo es hakt
  • Erst den Plan freigeben, dann startet die Arbeit — ohne Überraschungen
  • Lange Aufgaben in den Hintergrund legen und im Hauptchat weiterarbeiten

Siehe PRs #7580 , #8391 , #8240 , #8303 

display_image: Vom Agenten erzeugte Bilder erscheinen direkt im Terminal

Bisher bekam man nach der Bildgenerierung nur einen Dateipfad und musste die Datei selbst öffnen. Jetzt zeigt der Agent das Bild direkt im Terminal — fertig generiert, sofort sichtbar. So wurde auch das Cover dieses Wochenberichts ausgewählt: Der Agent erzeugte mehrere Kandidaten, die direkt im Terminal erschienen — vergleichen und auswählen, ohne jede Datei einzeln zu öffnen. Und wenn das Terminal keine Bilder anzeigen kann, gibt es einen klaren Hinweis.

Was du damit machen kannst:

  • Erzeugte Bilder sofort nach der Generierung sehen — kein manuelles Öffnen
  • Auch Diagramme aus Daten oder Screenshots fertiger Webseiten erscheinen direkt
  • Vorhandene Design-Entwürfe und Screenshots aus dem Repo direkt vom Agenten anzeigen lassen

Siehe PR #8217 

Berechtigungen für Sub-Agenten: Schlüssel nach Auftrag, parallele Aufgaben bleiben isoliert

Wenn du Qwen Code eine große Aufgabe gibst, schickt es manchmal mehrere Sub-Agenten parallel los — einer liest Code, einer führt Tests aus. Bisher hatte jeder Sub-Agent dieselben vollen Rechte wie der Hauptagent: Dateien lesen, Dateien ändern, Befehle ausführen. Wolltest du nur „schau dir den Code an und schreib eine Zusammenfassung”, konnte er nebenbei trotzdem Dateien ändern — kein gutes Gefühl.

Jetzt lassen sich Berechtigungen pro Aufgabe vergeben:

  • Schlüssel nach Auftrag: Beim Delegieren lässt sich einschränken, welche Tools der Sub-Agent nutzen darf — ein Satz genügt, etwa „diese Aufgabe ist nur lesen”, und die Einschränkung gilt: Änderungsversuche werden sofort abgewiesen
  • Berechtigungsvorlagen: Häufig genutzte Kombinationen werden als Vorlage im .qwen/fork-profiles/-Verzeichnis des Projekts gespeichert und beim nächsten Mal mit einem Parameter wiederverwendet — kein Neukonfigurieren jedes Mal
  • Abgeschirmte Aufträge: Eine Lücke ist geschlossen — bisher konnten parallel laufende Sub-Agenten die Anweisungen der anderen sehen. Jetzt sieht jeder nur seinen eigenen Auftrag

Was du damit machen kannst:

  • Nur-Lesen-Aufgaben bekommen nur Lesezugriff — kein nebenbei Dateien ändern
  • Häufige Berechtigungskombinationen als Vorlage speichern und mit einer Zeile wiederverwenden
  • Parallele Sub-Agenten arbeiten isoliert, ohne sich gegenseitig in die Quere zu kommen

Siehe PRs #8066 , #8148 , #8344 

Komprimierungskosten im Griff: eigenes günstiges Modell für die Komprimierung

Wenn eine lange Sitzung die automatische Komprimierung auslöste, musste bisher das Hauptmodell den gesamten Kontext durchlaufen — teuer und langsam.

Diese Woche gibt es drei Verbesserungen. Erstens: /model --compaction weist der Komprimierung ein eigenes Modell zu — ein günstiges Modell fasst die lange Konversation zusammen, während der Hauptchat weiter das gute Modell nutzt; die Qualität leidet nicht. Zweitens: Komprimiert das Hauptmodell, werden bereits gecachte Inhalte wiederverwendet — schnellere Antworten, auch bei Verläufen mit Bildern. Drittens: Mit Claude-Modellen lässt sich generationConfig.cacheRetention auf "1h" setzen — die Cache-Haltedauer steigt von den Standard-5-Minuten auf 1 Stunde, sodass lange Pausen zwischen Gesprächen nicht mehr jedes Mal den Cache verfallen lassen.

Was du damit machen kannst:

  • Komprimierung an ein günstiges Modell delegieren — lange Sitzungen werden günstiger
  • Komprimierung mit dem Hauptmodell nutzt den Cache wieder — schnellere Antworten
  • Selten genutzte Sitzungen verlieren nicht mehr bei jeder Nachricht den Cache

Siehe PRs #7818 , #8339 , #8419 , #8048 

Channel-Ökosystem: GitLab-Anbindung, DingTalk-Interaktionskarten, Pairing-Verwaltung

Letzte Woche kam der GitHub-Channel, diese Woche wächst das Channel-Ökosystem weiter.

GitLab ist da. GitLab-Todos und @Bot-Erwähnungen in Kommentaren werden zu eingehenden Nachrichten. Welche Aktionen der Agent übernimmt, ist konfigurierbar — bereits Verarbeitetes wird nicht doppelt bearbeitet. Siehe PR #7862 

DingTalk bekommt Interaktionskarten. Der DingTalk-Channel unterstützt interaktive Karten: Der Ausführungsstatus des Agenten wird live auf der Karte aktualisiert, und wenn eine Eingabe nötig ist, erscheint eine strukturierte Frage — statt eines langen Textblocks. Andere Plattformen bleiben unberührt. Siehe PR #6930 

Die Liste „wer darf den Agenten rufen” ist einseh- und widerrufbar. Beim Anbinden von Chat-Plattformen kann man aus Sicherheitsgründen den Pairing-Modus aktivieren: Wenn eine fremde Person den Bot zum ersten Mal @erwähnt, braucht sie deine Freigabe. Bisher gab es nach der Freigabe keine Liste mehr und keinen Widerruf — wer versehentlich freigegeben wurde oder das Team verlassen hat, konnte den Agenten weiter nutzen. Jetzt zeigt der Channel-Editor, wer freigegeben ist, einzelne Personen lassen sich widerrufen — jeder Workspace verwaltet seine eigene Liste. Siehe PR #8045 , #8081 

GitHub-/GitLab-Channels ohne Handkonfiguration. Bisher musste man für die Anbindung die Konfigurationsdatei settings.json selbst bearbeiten: Zugangsdaten, Geltungsbereiche, berechtigte Personen — ein falsches Zeichen und nichts funktionierte. Jetzt gibt es in der Web Shell eine eigene Verwaltungsseite: alles im Formular ausfüllen und per Klick auswählen, Speichern genügt — die Konfigurationsdatei bleibt unberührt. Siehe PR #8310 

Feinschliff am GitHub-Channel. Wer lokal mit gh angemeldet ist, kann diese Anmeldung direkt für den GitHub-Channel nutzen — kein separates Token nötig. Auch das Antwortverhalten ist disziplinierter: pro Ereignis höchstens ein endgültiger Kommentar; während der Bearbeitung hängt am Originalkommentar ein temporäres 👀-Emoji, das danach automatisch verschwindet. Unterbrochene Aufgaben lassen sich nach dem Neustart fortsetzen. Siehe PR #8461 , #8033 , #8061 , #8306 

📊 Weitere neue Funktionen

Auto Recall: automatische Kontextsuche. Die externe Korpus-Suche letzte Woche war „der Agent sucht auf Abruf” — Auto Recall sucht bei jeder Frage automatisch: Die Treffer werden dem Agenten als Referenz angehängt, gängige sensible Informationen werden automatisch gefiltert. Schließt sich mit dem Abruf-Modus aus und wird vom Administrator eingerichtet. Siehe PR #7877 

Schwellenwert für Tool-Vorabladung. Neue Einstellung tools.toolSearch.threshold: Bei wenigen Tools werden alle direkt beim Sitzungsstart deklariert — keine nachträgliche Suche, schnellere Antworten. Auf 0 gesetzt gilt das bisherige Verhalten. Siehe PR #7922 

/autofix unterstützt den lokalen Workspace. Bisher lief /autofix nur in GitHub Actions — jetzt prüft und repariert es direkt lokale Änderungen: Probleme finden, minimale Fixes anwenden, Checks laufen lassen, erneut prüfen — bis alles sauber ist oder feststeht, dass es nicht automatisch zu beheben ist. Vor dem Lauf kommt der Hinweis, dass die Prüfung in einer Sandbox stattfindet, und die Bestätigung, dass du dem Repo vertraust. Siehe PR #8121 

Strukturierte Review-Ansicht in der Web Shell. Nach einem /review-Lauf gibt es in der Web Shell eine eigene Ansicht: wie viele Probleme, wo, wie zu beheben, mit welcher Evidenz — filterbar nach Schweregrad, inklusive Link zum vollständigen Bericht. Siehe PR #8402 

Reasoning Effort für Qwen 3.8 wirkt. Mit qwen3.8-max-Modellen steuern die fünf Stufen von /effort jetzt tatsächlich die Denktiefe des Modells — nicht mehr nur eine einzige Stufe. Siehe PR #8472 

Goal v3 im CLI. /goal und der interaktive Modus nutzen jetzt dieselbe Runtime — Statuskarten und Lebenszyklus-Befehle sind auf beiden Seiten angeglichen, das Erlebnis ist einheitlich. Siehe PR #8005 , #8324 

Skills nach Ebene ausblenden. Die neue Einstellung skills.disabledLevels blendet ganze Skill-Ebenen nach Herkunft aus — hilfreich, wenn zu viele Skills unübersichtlich werden. Siehe PR #8057 

Lebenszyklus für automatisch erzeugte Skills. Von /learn und Co. erzeugte Skills werden jetzt nachverfolgt: 30 Tage ungenutzt heißt als abgelaufen markiert, nach 90 Tagen automatisch archiviert — die Sammlung wächst nicht mehr ins Unendliche. Siehe PR #7846 

memory.agentMaxTurns. Einheitliche Obergrenze für die Runden des Memory-Agenten — 0 bedeutet unbegrenzt. Siehe PR #8171 

/summary mit eigenem Pfad. /summary akzeptiert jetzt einen Pfadparameter und speichert die Projektzusammenfassung am gewünschten Ort — übergeordnete Verzeichnisse werden automatisch angelegt. Siehe PR #8116 

Daemon-Kapazität und -Status. Das Sitzungslimit pro Workspace steigt von 20 auf 32 — parallele Sitzungen stoßen seltener an die Grenze. /daemon/status zeigt den Speicherverbrauch und wie viel Puffer noch bleibt; auch das Parallelitätslimit für Sub-Sitzungen ist jetzt konfigurierbar. Siehe PR #8235 , #8245 , #8341 

Chrome-Erweiterung in Alpha. Die Alpha der Chrome-Erweiterung bekommt einen Einrichtungsassistenten, Laufzeitdiagnose und automatisierte Abnahmetests in einer echten Chrome-Umgebung. Siehe PR #6739 

👏 Erlebnisverbesserungen

Statusabfrage auch während des Streamings. Während das Modell noch ausgibt, laufen Nur-Lesen-Befehle wie /status, /settings und /help sofort — ohne auf das Rundenende zu warten. In der Web Shell gelten /stats, /about und /context ebenfalls mitten in der Runde; vorher wurden diese Befehle still verschluckt. Siehe PR #8130 , #8496 

Kein Abschneiden langer Tool-Ausgaben mehr. Befehlsausgaben und lange Thinking-Inhalte wurden bisher ab 500 Zeichen hart abgeschnitten — jetzt gibt es eine standardmäßig eingeklappte, aufklappbare Vollansicht. Auch in exportierten Sitzungen ist der volle Text sichtbar. Siehe PR #8251 

Runden bleiben geöffnet, solange Hintergrund-Agenten laufen. Sobald der Hauptagent idle war, klappte die Web Shell die Runde als abgeschlossen ein — selbst wenn noch Sub-Agenten im Hintergrund liefen und später neue Updates auftauchten; der Zustand sprang hin und her. Jetzt bleibt die Runde geöffnet, solange noch aktive Sub-Agenten laufen. Siehe PR #8413 

Thinking-Blöcke flackern nicht mehr, Transcript wird inline. Die Höhe von Streaming-Thinking-Blöcken ist jetzt stabil — kein Springen mehr. Das Vollbild-Transcript-Overlay weicht einem Inline-Schalter per Strg+O. Siehe PR #8077 

Neue Tastenkürzel. Auf macOS fügt Option+V Zwischenablage-Bilder ein; zum Wechseln der Kategorien in der @-Vervollständigung gibt es Strg+Tab / Strg+Shift+Tab — ohne mit den Kürzeln des Terminals zu kollidieren. Siehe PR #8120 , #8074 

Suche schneller und zuverlässiger. Die Dateisuche ist schneller; schlägt eine Suche fehl, wird automatisch wiederholt — „nicht fertig durchsucht” wird nicht mehr als „keine Treffer” gemeldet. Siehe PR #8253 , #7888 

Tabellen- und Dialogdetails. Beim Schließen des Zellen-Dialogs in erweiterten Markdown-Tabellen springt die Seite nicht mehr; Mausrad-Ereignisse im Moment des Dialogöffnens scrollen nicht mehr fälschlich den Hintergrund. Siehe PR #8407 , #8089 

Strg+Shift+C kopiert wieder. Bisher löste Strg+Shift+C Beenden oder Bildschirmleeren aus — jetzt tut das Kürzel wieder das, was man im Terminal erwartet: kopieren. Siehe PR #8011 

Sitzungsdetails-Menü. In schmalen Layouts läuft das Sitzungsdetails-Menü nicht mehr über; neu hinzugekommen ist die per Tastatur erreichbare Aktion „Vollständige Sitzungs-ID kopieren”. Siehe PR #8127
