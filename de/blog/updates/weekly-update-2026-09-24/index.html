Qwen Code Weekly: Sehen, welche Dateien den Kontext belegen, Projekte per SSH-Adresse auf anderen Rechnern bearbeiten, unterbrochene Workflows machen weiter

Qwen Team
2026-09-24

Qwen Code hat diese Woche vier Stable-Releases ausgeliefert — v0.24.1 bis v0.24.4 — mit 200 gemergten PRs.

Ist der Kontext voll, siehst du, wer ihn belegt. Welche Datei und welche Extension Tokens kostet, steht jetzt da — du weißt, was du abschalten kannst, und machst Platz frei.

Eine SSH-Adresse genügt, um ein Projekt auf einem anderen Rechner zu bearbeiten. Der Code liegt auf einem Server, einer Build-Maschine oder dem Rechner einer Kollegin: Du sitzt an deinem Rechner und lässt dort Dateien ändern und Builds laufen. Auf der Gegenseite muss kein Qwen Code installiert sein.

Ein abgebrochener Workflow läuft weiter. Was fertig ist, bleibt erhalten; bei einem Ablauf über mehrere Stunden holst du nur die paar fehlgeschlagenen Stellen nach.

✨ Neue Features

Sehen, welche Dateien und Extensions den Kontext belegen

/context listet den Kontext nach Quelle auf — System-Prompt, eingebaute Tools, MCP-Tools, Memory-Dateien, Skills und die Dateien aus Extensions. Diese Woche kommen Start-Kontext und Cache-Präfix als zwei Zeilen dazu. Mit /context detail gehst du eine Ebene tiefer bis zu einzelnen Dateien; was eine Extension mitbringt, steht dort als Extension: Erweiterungsname · Dateiname, inklusive Anteil. Terminal und Web Shell ziehen gleich.

Ein Hinweis, wenn es zu viel wird. Überschießen die ständigen Inhalte (QWEN.md und automatisches Memory) zusammen den kleineren der beiden Werte — 15 % des Fensters oder 10.000 Tokens —, sagt das beim Laden Bescheid.

Regeln aus Extensions greifen nur bei den passenden Dateien. Der Kontext kommt erst dazu, wenn du die zugehörige Datei öffnest; sonst belegt er nichts.

Was du damit machen kannst:

  • Der Kontext läuft voll — zuerst sehen, welche Dateien und Extensions ihn fressen
  • Nach der Installation einer Extension den Zuwachs mit /context detail einer Quelle zuordnen
  • Bei der Meldung wissen, ob QWEN.md schlanker muss oder das automatische Memory weg kann

Siehe PRs #12119 , #12318 , #12034 

Eine SSH-Adresse, und das Projekt auf dem anderen Rechner ist dran

Das Projekt liegt auf einem Server, in einer Build-Maschine oder auf dem Rechner einer Kollegin, und Qwen Code soll dort arbeiten. Bisher war die Reihenfolge: dort Qwen Code installieren, den Dienst starten, die Adresse eintragen. Jetzt schreibst du beim Hinzufügen eines Workspaces in der Web Shell einfach eine SSH-Adresse ins Pfadfeld:

ssh://user@host/absolute/project

Läuft auf dem Rechner kein Qwen Code, registrierst du ihn über diese Adresse. Läuft der Dienst schon, speicherst du Adresse und Token einmal und wählst den Rechner künftig direkt aus. Danach läuft alles in deinem lokalen Gespräch: Dateien dort lesen und schreiben, Befehle dort ausführen, den Git-Status dort sehen. Ein frisch hinzugekommener Workspace ist erst einmal nur zum Anschauen da; geändert wird, nachdem du ihn als vertrauenswürdig markiert hast.

Was du damit machen kannst:

  • Code und Abhängigkeiten liegen auf der Build-Maschine — du lässt im lokalen Gespräch dort Dateien ändern und Builds laufen
  • Eine fertige Umgebung auf einem fremden Rechner für einen Test leihen
  • Lokales und entferntes Projekt gleichzeitig offen, in einem Gespräch hin- und herwechseln

Siehe PRs #12255 , #12085 , #12412 

Ein Workflow, der mitten drin abbricht, macht nach dem Neustart weiter

Bricht ein Ablauf ab — Feierabend, Reboot, egal was — fing er bisher komplett von vorn an. Jetzt bleibt von jedem Lauf eine Aufzeichnung erhalten, und der nächste setzt dort auf.

Der Neustart meldet sich von sich aus. Beim Start von Qwen Code steht in der Begrüßung, welcher Lauf unterbrochen wurde, bei welchem Schritt er stand und wie viele Subagents fertig sind, mit dem Hinweis, in /workflows nachzusehen. Alle diese Läufe stehen außerdem in der Historienliste.

Auf den Historienkarten der Web Shell sitzen Buttons. „Fehlgeschlagenes erneut versuchen” läuft nur die Teile nach, die nicht durchgekommen sind; „Alles neu ausführen” beginnt von vorn.

Was du damit machen kannst:

  • Halb fertig ausgeschaltet — morgens zuerst sehen, wo der Lauf stehen geblieben ist
  • Ein langer Ablauf, in dem genau zwei Subagents fehlgeschlagen sind: Mit „Fehlgeschlagenes erneut versuchen” holst du diese beiden nach
  • Denselben Ablauf einmal komplett neu durchtesten — Button „Alles neu ausführen”

Siehe PRs #12159 , #12291 , #12097 

Web Shell: mehrere Verbesserungen

Änderungen sichtbar vor der Genehmigung. Wenn eine Dateiänderung deine Zustimmung braucht, listet die Genehmigungskarte direkt, welche Zeilen dazukommen und welche wegfallen — bei Änderungen an bestehenden Dateien, bei neuen Dateien und bei notebook-Bearbeitungen. Siehe PR #12443 

Lange Pastes werden zu einer Karte. Mehr als 200 Zeilen oder 8.000 Zeichen faltet die Web Shell automatisch zusammen; der Titel kommt aus den ersten Zeilen, und „In das Eingabefeld einfügen” holt den Text zurück. Pastes, die mit / oder ! beginnen, kurze Pastes und Ersetzen einer Auswahl bleiben entfaltet. Siehe PR #12084 

Trajectory-Tab im rechten Panel. Kommt dir eine Runde zu langsam oder zu teuer vor, zeigt der Tab, wo die Zeit hingeht: wie lange jede Runde brauchte, wann das erste Zeichen kam, wie viele Tokens flossen und welcher Tool-Call am teuersten war. Du fügst ihn im rechten Erweiterungsbereich über „Tab hinzufügen” mit der Wahl Trajectory ein. Siehe PR #12388 

Git-Historie finden statt suchen. Die Commit-Historie der Web Shell steht als Branch-Graph da, schaltet zwischen allen Branches um und sucht nach Commit-Message, Autor oder Hash. Remote-Adressen trägst du ebenfalls im Interface ein und entfernst sie dort, ohne das Terminal zu bemühen. Beides sitzt am Branch-Label über dem Eingabefeld. Siehe PRs #12152 , #11163 

Weitere Verbesserungen. Der Schalter für den Plan-Modus wandert aus der Werkzeugleiste in das „+“-Menü; ist er an, bleibt ein abschaltbares Label über dem Eingabefeld (#12218 ). Dateien aus /export erscheinen im Gespräch als Karte mit Vorschau und Download (#12050 ).

📊 Weitere neue Features

Die Web Shell wird zur App auf dem Rechner. Rechts in der Adressleiste taucht der Installationsknopf auf: eigenes Icon, eigenes Fenster, benutzt sich wie eine installierte App. Voraussetzung ist Chrome / Edge 111 oder neuer, Firefox 128 oder neuer, Safari 16.4 oder neuer — und die Adresse muss eine lokale Adresse (127.0.0.1 oder localhost) oder HTTPS sein. Über eine LAN-IP klappt die Installation nicht. Siehe PR #11722 

Der Desktop-Build kann zoomen. Cmd / Ctrl mit -, = oder 0, oder zwei Finger auf dem Trackpad — zwischen 50 % und 300 %, und die nächste Sitzung öffnet sich wieder mit deiner Einstellung. Siehe PR #12410 

Die Goal-Budgets stehen über dem Eingabefeld. Die Statuskarte zeigt neben dem Token-Budget jetzt auch Runden- und Zeitgrenze, etwa 3 / 20 turns und 12m 3s / 30m 0s; Goals ohne Grenze bleiben, wie sie sind. Der mit /export gespeicherte Session-Verlauf enthält auch den kompletten Goal-Verlauf. Siehe PRs #12201 , #12099 

Abgeschlossen heißt: im Gespräch nachprüfbar. Wenn du /goal mehrere Runden laufen lässt, reicht die Meldung „fertig” des Modells nicht mehr — die Abnahme schaut, was in diesem Gespräch tatsächlich passiert ist, und urteilt bei Lücken auf nicht abgeschlossen. Siehe PR #12105 

Subagents dürfen in einem Container arbeiten. Lässt du sie das ganze Repository durchsuchen und viele Befehle ausführen, sollen sie nicht an deine SSH-Keys und Credentials im Home-Verzeichnis kommen: Jeder Befehl und jeder Lese- und Schreibzugriff läuft in einem Docker- oder Podman-Container, schreibbar ist nur der Workspace. Dafür setzt du vor dem Start QWEN_AGENT_EXECUTION_BACKEND=docker. Der Preis: Workflows, Agent Team, MCP, LSP und Skills sind dann abgeschaltet, und Windows wird noch nicht unterstützt. Siehe PR #11711 

Ein Provider, zwei API-Formate. Soll ein bestimmtes Modell über das OpenAI Responses-Protokoll laufen, setzt du in seinen Eintrag "wireApi": "responses" — die anderen Modelle bleiben bei Chat. Wenn du mit /auth einen eigenen Provider konfigurierst, gibt es denselben Schritt jetzt optional. Siehe PR #11538 

👏 Verbesserte Erfahrungen

Die Web Shell auf dem Handy ist brauchbarer. Bindest du den Dienst an eine externe Adresse, erscheint der Pairing-Code jetzt auch oben rechts auf der Session-Seite: Kamera drauf, direkt im aktuellen Gespräch, ohne Token abzutippen. Auch das Eingabefeld ist neu sortiert — gut ein Dutzend Aktionen stecken im Drawer „Zur Nachricht hinzufügen”. Siehe PRs #12322 , #12252 

Weniger los im Eingabebereich. Solange die Session noch steht, wandern Workspace-Wahl und Git-Branch-Label aus der Werkzeugleiste in eine eigene Zeile darunter. Ist die Session angelegt, zeigt oben nur ein Ordnersymbol den Workspace an, und die Hover-Karte nennt den kompletten Pfad. Karten für Links im Gespräch öffnen jetzt direkt eine neue Seite. Siehe PRs #12299 , #12317 

/compress meldet in Klartext. Danach steht dort „Kontext komprimiert: X → Y”, und gibt es nichts zu komprimieren, „Nichts zu komprimieren.” Nach dem erneuten Öffnen einer Session zeigt auch der Kontext-Ring wieder aktuelle Zahlen. Siehe PR #12141 

Automatisches Channel-Verbinden klappt jetzt auch in anderen Workspaces. Betreut ein qwen serve mehrere Workspaces mit jeweils eigenen Channel-Bots, stellt der Start die Channels jedes vertrauenswürdigen Workspaces wieder her. Der Schalter „Beim Start von Qwen Code automatisch verbinden” wirkt also, nachdem du gespeichert hast. Siehe PR #12385 

Linux: nur noch die Tool-Ausführung in der Sandbox. Die Konfiguration aus der letzten Woche, die ganz Qwen Code in bwrap gesteckt hat, gibt jetzt einen Fehler mit einem Migrationshinweis. Umgestellt auf tools.executionSandbox gelten die Grenzen nur noch für Befehle und Datei-Zugriffe — Qwen Code selbst, Modell-Requests und dein Login bleiben auf dem Rechner. Siehe PR #12267 

Einmal-Aufrufe in Skripten sind schneller. qwen -p — einmal Text rein, Ergebnis raus — braucht gemessen nicht mehr 7,7 Sekunden, sondern 5,1 Sekunden, und statt 640 MiB nur noch 421 MiB, weil ein Prozess weniger startet. Siehe PR #12340 

Steht kein Pairing-Code im Terminal, steht der Grund da. Bindest du den Dienst an eine externe Adresse, damit das Handy scannt, und der Code fehlt, erklärt Qwen Code warum und legt einen zusätzlichen Code nur mit der Adresse dazu: scannen, auf dem Handy einmal das Token eintragen, verbunden. Wer den Code mit Token erzwingen will, nimmt qwen serve --token-qr. Siehe PR #12266
