Qwen Code: автоматическое переключение при перегрузке модели, вложенные субагенты, интеграция с WeCom

Qwen Team
2026-07-09

На этой неделе Qwen Code выпустил 3 стабильные версии v0.19.6–v0.19.8, принято более 150 PR. Работа велась по четырём направлениям:

Перегрузка модели больше не блокирует работу. Раньше при ошибках 429/503/529 диалог прерывался, и приходилось вручную переключать модель и отправлять сообщение заново. Теперь fallback-цепочка автоматически переключается на резервную модель, когда лимит повторов основной модели исчерпан. А /model --project позволяет привязать разные модели к разным проектам, чтобы не переключать их каждый раз.

Субагенты могут порождать субагентов. Раньше субагент был «листовым узлом» — получив задачу, он выполнял её сам и не мог делегировать дальше. Теперь по умолчанию поддерживается вложенность до 5 уровней, и субагент может разбивать подзадачи между следующим уровнем. И TUI, и Web Shell отображают древовидную структуру, где сразу видно, кто кого породил.

Управление сессиями Web Shell стало полноценным. Архивация, удаление, именованные группы, цветовые метки, планировщик задач, обзор сессий на разделённом экране — раньше боковая панель позволяла только переключаться между сессиями, а теперь можно организовать, классифицировать, мониторить и работать параллельно. 7 PR превратили сессии из «плоского списка» в управляемый ресурс.

WeCom и контроль доступа доведены до ума. Интеграция с ботом WeCom через интеллектуальный SDK — достаточно указать Bot ID и Secret, права администратора предприятия не нужны. PreToolUse hook с параметром “ask” теперь действительно показывает диалог подтверждения, а раньше молча отклонял запрос. Правила доступа поддерживают синтаксис Tool(param:value) для контроля на уровне значений параметров.

✨ Новые возможности

Автоматическое переключение при перегрузке модели + настройка моделей на уровне проекта

При ошибках 429/503/529 диалог зависал. В этой версии добавлена opt-in fallback-цепочка: когда лимит повторов основной модели исчерпан, система автоматически переключается на следующую модель из списка fallback. Fallback срабатывает только при проблемах с пропускной способностью и ограничениями. Ошибки аутентификации, квот, конфигурации и клиентские ошибки приводят к немедленному сбою, потому что это не «перегрузка модели», а «проблема в вашей конфигурации».

Fallback продвигается до того, как пользователь увидит какой-либо вывод. Если fallback-модель уже успела вывести часть текста и затем упала, оставшиеся fallback-модели не будут вызваны — вы получите усечённый ответ. Но следующее сообщение пользователя начнётся снова с основной модели, система не застрянет на fallback-модели.

С помощью /model --project можно привязать разные модели к разным проектам. --project записывает настройку в .qwen/settings.json проекта, --global — в пользовательский ~/.qwen/settings.json. Без флага поведение остаётся прежним. Флаги области действия также работают для --fast, --voice, --vision.

Что это даёт:

  • Настройте список fallback-моделей — при перегрузке переключение происходит автоматически, без ручной смены модели
  • Ошибки аутентификации и квот не маскируются fallback, проблемы проявляются раньше
  • /model --project позволяет разным проектам использовать разные модели, конфигурация привязана к проекту
  • /model --global задаёт глобальные настройки по умолчанию, новые проекты наследуют их

Вложенные субагенты + древовидное представление

Субагенты теперь могут порождать собственных субагентов. Лимит глубины по умолчанию — 5 уровней, настраивается через model.maxSubagentDepth. Установите 1, чтобы вернуться к старому поведению — субагенты не смогут порождать потомков.

Два защитных механизма: на этапе подготовки схемы самый глубокий субагент не видит инструмент agent (он просто не знает о его существовании); на этапе выполнения запросы на порождение сверх лимита отклоняются.

И TUI, и Web Shell отображают вложенную древовидную структуру. Субагенты показываются под родительским агентом с маркером ↳ и отступом. Когда родительский агент завершает работу, субагент становится корневым узлом с пометкой «from <parent>». В детальном виде отображается «Level N · from <parent type>». Метки блокировки и подтверждения остановки тоже учитывают цепочку — подтверждение появляется только если отмена приведёт к завершению хода.

Эта функция включена по умолчанию — после обновления все существующие окружения получают возможность вложенного порождения. Fork-подпроцессы, teammates и workflow agents по-прежнему исключены. Arena-сессии теперь поддерживают вложенность. При восстановлении фоновых агентов восстанавливается исходная глубина и лимит на момент запуска.

Что это даёт:

  • Субагент, обрабатывая сложную задачу, может сам порождать субагентов для подзадач
  • Полное древовидное представление агентов в TUI и Web Shell
  • Настройка лимита глубины вложенности через model.maxSubagentDepth

Управление сессиями Web Shell: архивация, группировка, планировщик, разделённый экран

7 PR превратили боковую панель сессий Web Shell из «плоского списка» в полноценную панель управления с возможностями организации, классификации, мониторинга и параллельной работы.

Архивация и удаление. Каждая строка сессии получила быстрые действия и меню «…» (переименовать/архивировать/удалить). Архивированные сессии собираются в сворачиваемой области «Archived», их можно восстановить или окончательно удалить. Текущую активную сессию архивировать или удалить нельзя, архивированную сессию открыть невозможно (409 session_archived), удаление — жёсткое, с повторным подтверждением. Под капотом используются archiveState демона и эндпоинты /sessions/archive, /sessions/unarchive.

Именованные группы и цветовые метки. Можно создавать, переименовывать, удалять группы, перетаскивать в них сессии, назначать группам цветовые метки и статусы закрепления/архивации. Данные групп проходят от уровня демона до UI — на стороне демона метаданные групп хранятся в sidecar-файлах уровня проекта, REST/ACP маршруты предоставляют CRUD-операции, доступность контролируется через capability gates.

Обзор сессий и разделённый экран. На больших экранах в боковой панели появляется панель обзора сессий — все сессии отображаются в виде карточек в реальном времени, отсортированных по приоритету: сначала требующие подтверждения, затем активные, затем простаивающие. Каждая карточка показывает текущую модель и количество клиентов. После множественного выбора можно разделить экран для просмотра — в рамках текущей вкладки или в новой вкладке браузера (URL-параметр ?split=a,b). N независимых чат-панелей отображаются рядом, каждая со своим контекстом сессии, фокус клавиатуры действует только на ту панель, по которой кликнули.

Что это даёт:

  • Архивация и организация накопившихся сессий, группировка по проектам с цветовыми метками
  • Визуальное создание и управление запланированными задачами, без ручного написания cron-выражений
  • Каждая запланированная задача имеет собственную сессию, историю запусков и транскрипты доступны в любой момент
  • Разделённый экран для параллельного мониторинга нескольких сессий в реальном времени на больших дисплеях

Интеграция с WeCom

Подключение интеллектуального бота WeCom через @wecom/aibot-node-sdk. Для настройки нужны только Bot ID и Secret — не требуются Corp ID, Agent ID, callback Token, EncodingAESKey или публичный callback-адрес.

Приём сообщений через WebSocket-соединение, поддерживаются текст, транскрипция голоса, смешанные текстово-графические сообщения, изображения, файлы, видео и цитаты. Ответы Assistant отправляются в формате WeCom markdown. Исходящие сообщения поддерживают только локальные изображения (из временного каталога канала), метки файлов/видео/голоса игнорируются.

Конфигурация:

{
  "type": "wecom",
  "botId": "your-bot-id",
  "secret": "your-secret",
  "cwd": "/path/to/project"
}

Команда запуска: qwen channel start my-wecom

Что это даёт:

  • Подключение WeCom через Bot ID + Secret, без прав администратора предприятия
  • Приём текстовых, голосовых сообщений, изображений, файлов, видео и цитат
  • Qwen Code отвечает в группах WeCom сообщениями в формате markdown

Нативный диалог подтверждения для PreToolUse hook

Раньше PreToolUse hook с возвратом permissionDecision: "ask" был равносилен “deny” — диалог подтверждения вообще не появлялся, разработчик hook думал, что пользователь увидит выбор, а на самом деле запрос молча отклонялся.

Теперь “ask” показывает нативный TUI-диалог подтверждения. Варианты: «Yes, allow once» и «No, suggest changes» — без «always allow», потому что hook переоценивается при каждом вызове. При одобрении инструмент выполняется заново, при отказе — отменяется.

В неинтерактивном CLI и фоновых агентах “ask” откатывается к deny — система не зависает в ожидании. Используется существующий механизм awaiting_approval, отдельный путь не создавался. Поведение “denied” и “stop” не изменилось, PermissionRequest hook не затронут.

Что это даёт:

  • Используйте “ask” в PreToolUse hook, чтобы пользователь решал, выполнять инструмент или нет
  • Нет риска зависания в неинтерактивных сценариях
  • Hook переоценивается при каждом вызове, не даёт постоянного разрешения

Предварительный просмотр автоматически сгенерированных Skills

Раньше при автоматической генерации skill агентом было видно только имя файла, а содержимое становилось доступным лишь после подтверждения. Теперь в диалоге проверки отображается полное содержимое, включая frontmatter.

Сгенерированный моделью контент санитизируется: управляющие последовательности ANSI/VT превращаются в безопасные экранированные символы, CRLF — в обычные переносы строк. Лимит чтения — 64 КиБ, лимит отображения — 12 строк (с учётом автоматического переноса), остаток помечается как «lines hidden» / «truncated».

Нажатие o открывает файл skill в настроенном редакторе, не пропуская текущую проверку. После сохранения файла предпросмотр автоматически обновляется — в связке с GUI-редактором (поведение macOS по умолчанию) можно отредактировать и сразу увидеть результат.

Опция «Turn off auto-generated skills» находится в конце списка, вступает в силу немедленно (перезапуск не требуется), сохраняется на уровне workspace. Текущая партия откладывается (не удаляется), после повторного включения через /memory партия возвращается.

Что это даёт:

  • Просмотр полного содержимого skill перед подтверждением — не нужно сначала принимать, а потом искать файл
  • Нажатие o открывает skill в редакторе для правки, предпросмотр обновляется после сохранения
  • Одной кнопкой отключить автогенерацию skills, текущая партия не удаляется и восстанавливается через /memory в любой момент
