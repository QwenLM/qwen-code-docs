블로그기능 업데이트지난 업데이트07-16 제품 업데이트

Qwen Code 주간 업데이트: /learn로 지식을 스킬로 바꾸고, Code Review 품질 검증 대폭 강화, Web Shell 화면 대대적 개편

Qwen Team
2026-07-16

Qwen Code는 이번 주에 v0.19.9, v0.19.10, v0.19.11 세 개의 정식 버전을 출시하고 PR 160개 이상을 병합했습니다.

/learn 명령이 생겼습니다. 이번에는 사용자가 직접 스킬을 만듭니다. 디렉터리, URL, 대화, 직접 쓴 텍스트 중 어떤 형태든 지식 원본을 던져 주면 Qwen Code가 SKILL.md로 정리해 주고, 다음부터는 그대로 불러 씁니다.

Code Review, ‘되는 정도’에서 ‘잘 쓰는 정도’로. 제안 항목이 PR 인라인 댓글로 바로 게시되고, 검토 절차에 절차적 정확성 검사, 게시 전 검증, Step 4 verifier와 Step 5 reverse-audit가 추가됐습니다.

Web Shell을 크게 손봤습니다. shadcn 컴포넌트 라이브러리를 기반으로 깔고 Artifact 검토 패널, extension 관리 페이지, Mermaid 확대·이동을 더했습니다. 여러 워크스페이스 지원이 끝까지 연결됐고, 분할 화면은 워크스페이스별로 색을 구분합니다.

Voice Bridge로 ACP에 음성을 연결했습니다. 메인 모델이 텍스트 전용이어도 음성 prompt를 다룰 수 있습니다. 음성을 먼저 텍스트로 바꿔 모델에 넘기고, 음성을 지원하는 모델은 원본을 그대로 통과시킵니다.

스캔 PDF에 Agent가 멈추지 않습니다. 텍스트 추출이 한도를 넘으면 페이지를 자동으로 이미지로 렌더링하고, 비전 모델이 그림을 보고 바로 답합니다.

CLI 작업 흐름을 채웠습니다. /update로 한 번의 명령에 업그레이드, Ctrl+O로 대화 고정, Ctrl+S로 prompt 임시 저장, Explore의 메인 모델 상속, Alt+T로 사고 과정 전체 보기까지 가능합니다.

✨ 새로운 기능

/learn: 지식을 재사용 가능한 스킬로

/learn은 지식 원본에서 재사용 가능한 스킬을 만드는 새 슬래시 명령어입니다. 원본은 로컬 디렉터리, URL, 대화 기록, 직접 쓴 텍스트 중 아무 형태나 상관없습니다. 메인 모델이 지식을 모아서 SKILL.md로 자동 정리한 뒤 .qwen/skills/learned-skill-<name>/에 저장하고, source: learned 표시를 붙입니다. 그래서 손으로 작성한 스킬, 자동 생성된 스킬과 서로 간섭하지 않습니다.

이렇게 쓸 수 있습니다:

  • /learn Deploy process: ...처럼 배포 절차를 스킬로 만들어 두면, 다음 배포 때 바로 호출합니다
  • 문서 디렉터리를 던져 주면 프로젝트의 개발 규약을 학습해서, 이후 코딩할 때 자동으로 따릅니다
  • 대화에서 지식을 뽑아 재사용 가능한 명령 템플릿으로 남겨 둡니다

관련 PR: #6440 

Code Review 품질 검증 대폭 강화

이번 주 Code Review는 여러 방향에서 품질 검증을 끌어올렸습니다. 인라인 댓글에서 검토 결과 검증까지 전반을 다뤘습니다.

/review는 이제 제안(Suggestion) 유형으로 나온 발견 항목을 PR 인라인 댓글로 바로 게시합니다 — 검토 출력에서 제안 내용을 복사해 PR에 붙여 넣을 필요가 없습니다. 검토 자체에도 절차적 정확성 검사기(procedural correctness finders)와 조절 가능한 effort 단계가 추가됐고, 댓글을 올리기 전에 guardrail이 각 발견 항목이 실제로 성립하는지 한 번 더 확인합니다.

큰 diff도 대충 나누지 않습니다 — diff의 모든 줄에 담당 reviewer가 명확히 붙어 검토 커버리지를 확보합니다. Review chunk agent에는 프롬프트가 빈틈없이 조립되어 전달되므로, 텅 빈 컨텍스트로 도는 일이 없습니다. PR triage 댓글에는 신뢰도 점수, 시퀀스 다이어그램, 파일 개요, 검토 footer가 추가돼 reviewer가 더 많은 맥락을 안고 볼 수 있습니다. 자동화 검토의 기본 타임아웃은 180분으로 늘리고 최대 240분까지 override를 허용해, 큰 PR이 시간 초과로 중단되는 일이 없습니다.

이렇게 쓸 수 있습니다:

  • /review가 PR에 인라인 제안 댓글을 자동으로 달아 줘서, 직접 댓글을 옮길 필요가 없습니다
  • effort 단계를 조절해 검토 규모에 맞춥니다
  • PR triage의 신뢰도 점수로 어떤 PR을 깊이 봐야 할지 가늠할 수 있습니다

v0.19.11에서는 Step 4 verifier와 Step 5 reverse-audit이 더해졌습니다. 검토 흐름이 ‘문제 발견 → 댓글 게시’에서 ‘문제 발견 → 발견이 실제로 성립하는지 검증 → 역방향 감사로 빠진 게 없는지 확인’하는 완결된 사슬로 바뀝니다. findings 목록은 verify/reverse-audit 프롬프트 안에 접혀 들어가 프롬프트 용량을 줄입니다. Agent 7의 build/test 범위도 diff가 실제로 건드린 워크스페이스로 좁아져, 큰 저장소에서 통째로 다시 빌드하지 않습니다.

관련 PR: #6593 , #6711 , #6612 , #6789 , #6771 , #6840 , #6942 , #6965 , #6892 , #6955 

Web Shell UI 대대적 개편

이번 주 Web Shell에는 PR 15개 이상이 몰렸습니다. 기반 UI 컴포넌트 라이브러리부터 사이드바, 설정 페이지, 모델 선택기까지 전부 새로 만들었습니다.

UI 기반 컴포넌트 라이브러리로 shadcn을 들여와 디자인 token과 컴포넌트 규약을 통일했습니다. 여러 워크스페이스 사이드바를 다시 설계해 배치가 한결 깔끔해졌습니다. 설정 페이지도 현대적인 컴포넌트 라이브러리로 바뀌어, 사용자 단위 설정을 패널에서 바로 고치고 모델 관리까지 설정 패널 안에 들어 있습니다. 모델 선택기 역시 다시 설계해 모델 메타데이터가 또렷하고 전환도 빨라집니다. 관련 PR: #6760 , #6804 , #6817 , #6758 

여러 워크스페이스 지원이 끝까지 연결됐습니다. Daemon ACP 엔드포인트가 워크스페이스 범위를 인정하고, 채널 worker는 워크스페이스별로 묶여 바인딩되며, 분할 화면은 워크스페이스를 넘는 세션과 워크스페이스 탭을 지원합니다. 동적으로 추가한 워크스페이스 등록도 저장되므로 daemon을 재시작한 뒤 설정을 다시 할 필요가 없습니다. 워크스페이스는 서버를 재시작하지 않고도 실행 중에 뺄 수 있습니다. 관련 PR: #6621 , #6635 , #6746 , #6716 , #6745

Voice Bridge: 음성 입력을 ACP에 연결

이전에는 ACP(Agent Communication Protocol)로 음성 prompt를 보내도 메인 모델이 텍스트 전용이면 음성을 처리할 방법이 없었습니다. 이번에 voice bridge가 들어갔습니다. 음성이 설정해 둔 voice model에서 먼저 전사되어 텍스트가 된 뒤 메인 모델에 전달됩니다. 반대로 메인 모델이 원래 음성을 지원한다면 전사를 거치지 않고 원본 음성을 그대로 통과시킵니다. 전사를 쓸 수 없거나 실패한 경우에도 메인 모델에는 안전한 ‘음성 사용 불가’ 안내만 전달되고, 음성 데이터 원본을 그대로 넘기지는 않습니다.

이렇게 쓸 수 있습니다:

  • ACP 클라이언트로 음성 지시를 보내면 텍스트 전용 모델도 내용을 알아듣습니다
  • 음성을 지원하는 메인 모델(멀티모달 모델 등)은 원본 음성을 그대로 받아 음성 정보가 손상되지 않습니다
  • 전사에 실패해도 안전하게 대체 처리되므로 음성 문제 하나로 대화가 끊기지 않습니다

관련 PR: #6576 

PDF 자동 이미지 변환: 스캔본에 Agent가 멈추지 않습니다

이전에는 스캔본이나 글자가 빽빽한 PDF를 만나면 텍스트 추출이 12000 token 예산을 넘기면서 FILE_TOO_LARGE 무한 루프에 빠졌습니다. Agent가 페이지 범위를 계속 줄여 다시 시도해도 매번 같은 실패가 반복되고, 컨텍스트가 터진 끝에 세션이 무너졌습니다. 이제 페이지→이미지 렌더링 대체 경로가 생겼습니다. 텍스트 추출이 한도를 넘거나 실패하면 pdftoppm으로 페이지를 자동으로 JPEG 이미지로 바꿔 비전 모델에 넘깁니다. 페이지당 token 비용이 고정이라 글자가 얼마나 빽빽하든 상관이 없습니다. 텍스트 추출이 기본 경로는 그대로입니다(grep 가능, 정확한 텍스트 추출). 렌더링은 한도를 넘거나 실패했을 때만 발동됩니다. 비전 모델이 설정된 텍스트 전용 메인 모델의 경우, @로 첨부한 스캔본은 몇 장의 페이지로 렌더링된 뒤 vision bridge에 넘겨 전사합니다.

이렇게 쓸 수 있습니다:

  • 스캔 PDF에서 더 이상 FILE_TOO_LARGE가 뜨지 않고, 비전 모델이 그림을 보고 바로 답합니다
  • token 예산을 넘는 빽빽한 PDF는 자동으로 이미지로 처리돼 컨텍스트가 터지지 않습니다
  • 텍스트 기반 PDF는 계속 텍스트 추출을 쓰니 정밀도가 떨어지지 않습니다

관련 PR: #6585 

CLI 작업 흐름 업그레이드: 한 번의 명령으로 업그레이드, 대화도 보존

이전에는 Qwen Code를 업그레이드할 때 설치 방식을 직접 기억하고 있어야 했습니다. npm으로 설치했으면 npm install을 돌리고, standalone으로 설치했으면 설치 파일을 다시 내려받아야 했죠. 이번 주에 qwen update CLI 명령과 /update 슬래시 명령이 추가돼 설치 유형을 자동 감지해 업그레이드를 진행합니다. standalone 설치는 npm registry에서 최신 버전을 바로 가져오고 SHA256 검증 + Ed25519 서명 확인(선택) + smoke test(새 바이너리가 --version을 통과해야 함) + 원자적 교체를 거치며, 실패하면 자동으로 되돌립니다. npm으로 설치한 경우에는 알맞은 npm install -g 명령을 보여 줍니다. i18n은 9개 언어를 지원합니다. 관련 PR: #5780 

Ctrl+O로 트랜스크립트 고정 화면을 엽니다. 누르면 대체 화면이 열리면서 모든 도구 출력을 펼친 채 전체 대화 기록을 보여 주고, 위아래로 스크롤할 수 있습니다. Esc/q/Ctrl+C/Ctrl+O로 빠져나오면 메인 화면으로 돌아옵니다. 이와 함께 도구 출력 렌더링을 다시 짰습니다. read/search/list 계열 도구의 결과는 한 줄 요약으로 접히고, 상태를 바꾸는 도구의 출력은 펼쳐진 상태로 남습니다. 기존의 compactMode 설정은 조용히 무시됩니다. 관련 PR: #5666 

Ctrl+S로 prompt를 임시 저장할 수 있습니다. 입력창에 내용이 있을 때 Ctrl+S를 누르면 프로젝트 단위의 임시 저장 파일에 prompt가 담기고, 같은 프로젝트에서 다음에 시작할 때 자동으로 복구됩니다. 전송이 끝나면 임시 저장은 지워집니다. 길게 붙여 넣은 내용도 저장 전에 자리 표시자가 풀린 상태로 저장되니, 복구하면 원본을 그대로 얻습니다. 서로 다른 프로젝트끼리는 섞이지 않습니다. 관련 PR: #6709 

Shell 명령 타임아웃을 설정할 수 있습니다. tools.shell.defaultTimeoutMs 설정이 새로 생겨, 프로젝트 또는 세션 단위에서 포그라운드 명령의 기본 타임아웃을 조정할 수 있습니다. 매번 명령 인자에 따로 적지 않아도 됩니다. 기본값은 기존대로 120초이고, 0으로 두면 타임아웃이 꺼집니다. 관련 PR: #6628 

Explore 서브 Agent가 기본으로 메인 모델을 상속합니다. 내장 Explore 서브 Agent가 더 이상 fastModel을 자동 선택하지 않고 메인 세션의 모델을 따릅니다. 메인 모델을 Claude Opus로 쓰면 Explore도 Claude Opus를 쓰므로 추론 성능이 떨어지지 않습니다. 여전히 빠른 쪽을 쓰고 싶다면 agents.builtin.exploreModel을 fast나 구체적인 모델 ID로 설정하면 됩니다. 관련 PR: #6807 

Alt+T로 사고 과정을 전부 펼칩니다. 스트리밍 출력 중 Alt+T를 누르면 thinking block이 열리고, 추론 내용이 처음부터 끝까지 실시간 스트리밍되는 모습을 볼 수 있습니다. 기존처럼 하단 4줄만 하드코딩으로 미리 보여 주지 않습니다. 사고 흐름을 따라가는 모델의 생각 줄기를 드디어 따라갈 수 있게 됐습니다. 매우 긴 추론은 뷰포트 높이만큼만 보여 주고 무한히 펼쳐지지는 않습니다. 관련 PR: #6678
